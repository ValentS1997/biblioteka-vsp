# Шпаргалка главы 6 — Словари

## Symptom / problem framing

Типовые задачи:

- получить значение по ключу;
- добавить или изменить атрибут;
- удалить ненужную пару;
- не падать при отсутствующем ключе;
- перебрать пары, ключи или значения;
- убрать повторяющиеся значения;
- смоделировать вложенные связанные данные.

## Baseline / context

~~~python
alien_0 = {'color': 'green', 'points': 5}
~~~

Словарь хранит пары `ключ: значение`.

Доступ:

~~~python
print(alien_0['color'])
~~~

## Read-only checks

### Ожидаемый ключ

~~~python
value = alien_0['color']
~~~

### Ключ может отсутствовать

~~~python
value = alien_0.get('points', 'No point value assigned.')
~~~

### Перебор

~~~python
for key, value in user_0.items():
    print(key, value)

for key in user_0.keys():
    print(key)

for value in user_0.values():
    print(value)
~~~

### Уникальные значения

~~~python
for language in set(favorite_languages.values()):
    print(language)
~~~

## Interpretation

- `dict[key]` + отсутствующий ключ → `KeyError`.
- `get(key, default)` → default при отсутствии ключа.
- `get(key)` без default → источник указывает `None`.
- `items()` используется для перебора ключа и значения одновременно.
- простой `for key in dictionary:` по source example эквивалентен перебору ключей.
- `sorted(dictionary.keys())` меняет порядок перебора представления, а не сам словарь в показанном примере.
- `set(values)` оставляет уникальные значения.

## Next action

1. Определить, что является ключом и что значением.
2. Решить, гарантирован ли ключ.
3. Если гарантирован → `dict[key]`.
4. Если может отсутствовать → рассмотреть source-supported `get()`.
5. Для изменения явно определить добавление, замену или удаление.
6. Для обхода выбрать pairs / keys / values.
7. При сложной модели выбрать вид вложения.

## Modifying action

~~~python
alien_0['x_position'] = 0
alien_0['color'] = 'yellow'
del alien_0['points']
~~~

- присваивание новому ключу добавляет пару;
- присваивание существующему ключу меняет значение;
- `del` полностью удаляет пару.

Risk: source прямо говорит, что удаление пары через `del` отменить нельзя.

## Verification / acceptance checks

- после add/change вывести словарь или значение ключа;
- после `del` проверить отсутствие ключа;
- для `get()` проверить существующий и отсутствующий ключ;
- для `items()` убедиться, что обрабатываются пары;
- для `keys()` и `values()` сверить нужный компонент;
- после `set(values)` проверить отсутствие повторов;
- для nested structure вывести несколько вложенных значений/объектов.

## Rollback

- `del`: источник прямо утверждает, что отменить удаление пары не удастся. Rollback отсутствует.
- add/change: отдельная rollback-процедура не описана; если предыдущее значение известно, его можно присвоить обратно, но как source procedure это `[Needs confirmation]`.
- read-only access/iteration: `[Not applicable]`.

## Nesting boundary

Источник рекомендует избегать чрезмерно глубокой вложенности: если структура становится существенно глубже приведённых примеров, вероятно, существует более простое решение.
