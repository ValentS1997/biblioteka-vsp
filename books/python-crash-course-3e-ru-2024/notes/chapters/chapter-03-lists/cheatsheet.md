# Шпаргалка главы 3 — Списки

## Symptom / problem framing

Основная задача главы — выбрать правильную операцию над упорядоченным списком и понимать, меняет ли она исходный список.

Типовые проблемы:

- запрошен неверный индекс;
- перепутана человеческая позиция и индекс Python;
- элемент удалён, хотя его значение ещё требовалось;
- сортировка необратимо изменила исходный порядок;
- ожидалось удаление всех одинаковых значений, но `remove()` убрал только первое;
- `[-1]` применён к пустому списку.

## Baseline / context

- Список записывается в `[]`, элементы разделяются запятыми.
- Список упорядочен.
- Первый элемент имеет индекс `0`.
- Последний элемент непустого списка доступен как `[-1]`.
- Элемент списка можно использовать как обычное значение, включая методы строк и f-строки.
- `len(list)` возвращает количество элементов.

## Read-only checks

### Посмотреть список

~~~python
bicycles = ['trek', 'cannondale', 'redline', 'specialized']
print(bicycles)
~~~

### Проверить элемент по индексу

~~~python
print(bicycles[0])
print(bicycles[-1])
~~~

### Проверить длину

~~~python
print(len(bicycles))
~~~

### Временно отсортировать без изменения исходного списка

~~~python
cars = ['bmw', 'audi', 'toyota', 'subaru']
print(sorted(cars))
print(cars)
~~~

Второй вывод используется для проверки, что исходный порядок сохранился.

## Interpretation

- `IndexError: list index out of range` → запрошенного индекса нет в текущем списке.
- Для третьего элемента используется индекс `2`, а не `3`.
- `-1` указывает на последний элемент только если список не пуст.
- `sorted()` не меняет исходный список.
- `sort()` меняет сам список.
- `reverse()` обращает текущий порядок, а не выполняет обратную алфавитную сортировку.
- `remove(value)` удаляет первое вхождение значения.
- `pop()` нужен, когда удалённое значение требуется использовать дальше.

## Next action

Выберите операцию по намерению:

1. Только прочитать элемент → индекс.
2. Заменить существующий элемент → присваивание по индексу.
3. Добавить в конец → `append()`.
4. Добавить в конкретную позицию → `insert()`.
5. Удалить по индексу без дальнейшего использования → `del`.
6. Удалить и сохранить значение → `pop()` / `pop(index)`.
7. Удалить по известному значению → `remove(value)`.
8. Временно показать сортировку → `sorted()`.
9. Изменить порядок списка сортировкой → `sort()`.
10. Обратить текущий порядок → `reverse()`.
11. Узнать число элементов → `len()`.

## Modifying action

Следующие операции изменяют список:

~~~python
motorcycles[0] = 'ducati'
motorcycles.append('ducati')
motorcycles.insert(0, 'ducati')
del motorcycles[0]
motorcycles.pop()
motorcycles.pop(0)
motorcycles.remove('ducati')
cars.sort()
cars.sort(reverse=True)
cars.reverse()
~~~

Перед изменением полезно вывести исходный список, если его состояние важно для проверки.

## Verification / acceptance checks

После state-changing операции:

1. вывести список;
2. проверить ожидаемое наличие/отсутствие элемента;
3. при изменении размера проверить `len()`;
4. после `pop()` дополнительно проверить возвращённое значение;
5. после `sorted()` повторно вывести исходный список и убедиться, что он не изменился;
6. после `reverse()` проверить фактическую последовательность.

## Rollback

- `reverse()`: источник прямо указывает, что второй вызов `reverse()` возвращает исходный порядок.
- `sort()`: источник говорит, что после постоянной сортировки вернуться к исходному порядку уже нельзя; rollback: `[Needs confirmation]`.
- Присваивание по индексу, `append()`, `insert()`, `del`, `pop()`, `remove()`: отдельная rollback-процедура в главе не задана — `[Needs confirmation]`.

## Диагностика IndexError

Source workflow:

`traceback → проверить индекс → уменьшить индекс на 1 при off-by-one → повторить запуск`.

Если причина неясна:

~~~python
print(motorcycles)
print(len(motorcycles))
~~~

Фактический список и его длина помогают проверить предположение о доступных индексах.
