# Шпаргалка главы 5 — Оператор if

## Symptom / problem framing

Типовые вопросы главы:

- почему условие возвращает `False`;
- нужно выполнить одно из двух действий;
- нужно выбрать один вариант из нескольких;
- нужно выполнить несколько независимых действий;
- нужно проверить наличие/отсутствие значения в списке;
- нужно отдельно обработать пустой список;
- значение списка требует специальной обработки.

## Baseline / context

Условная проверка возвращает `True` или `False`.

~~~python
car = 'bmw'
print(car == 'bmw')
~~~

`=` присваивает значение; `==` сравнивает.

## Read-only checks

### Равенство / неравенство

~~~python
car == 'bmw'
requested_topping != 'anchovies'
~~~

### Без учёта регистра

~~~python
car.lower() == 'audi'
~~~

Источник показывает, что `lower()` в такой проверке не меняет значение `car`.

### Числа

~~~python
age < 21
age <= 21
age > 21
age >= 21
~~~

### Несколько условий

~~~python
age_0 >= 21 and age_1 >= 21
age_0 >= 21 or age_1 >= 21
~~~

### Список

~~~python
'mushrooms' in requested_toppings
user not in banned_users
~~~

## Interpretation

- `and` → всё выражение истинно только если истинны обе проверки.
- `or` → достаточно одной истинной проверки.
- `in` → значение присутствует.
- `not in` → значение отсутствует.
- непустой список в `if list_name:` даёт истинный результат; пустой — ложный.
- `if-elif-else` выполняет только первый истинный блок.
- серия независимых `if` позволяет выполнить несколько блоков.

## Next action

1. Сформулировать условие.
2. Проверить его отдельно и понять ожидаемый Boolean result.
3. Определить, сколько блоков может быть выполнено:
   - один условный блок → `if`;
   - один из двух → `if-else`;
   - один из многих → `if-elif-else`;
   - несколько одновременно → отдельные `if`.
4. После выполнения сверить фактический вывод.

## Modifying action

Условные конструкции могут менять program state, если внутри блока есть присваивание:

~~~python
if age < 4:
    price = 0
elif age < 18:
    price = 25
else:
    price = 40
~~~

Effect: значение `price` выбирается по первому истинному условию.

Risk: неверный порядок условий может направить выполнение не в тот блок.

Verification: вывести `price` для representative input values.

Rollback: универсальная процедура в главе не задана — `[Needs confirmation]`.

## Verification / acceptance checks

- Проверить как минимум один True и один False case.
- Для `and` проверить случай, где одна часть ложна.
- Для `or` проверить случай, где обе части ложны.
- Для `if-elif-else` подтвердить, что выполняется только один блок.
- Для независимых `if` подтвердить выполнение всех подходящих блоков.
- Для пустого списка проверить `else`.
- Для проверок пользовательского значения по whitelist/list of available values проверить и допустимый, и недопустимый вариант.

## Formatting check

Source recommendation: ставить один пробел до и после операторов сравнения, например:

~~~python
if age < 4:
~~~

а не `if age<4:`.
