# Шпаргалка — приложение В

## Symptom / problem framing

Когда «ничего не работает», source требует сначала превратить неопределенную проблему в конкретную диагностическую запись.

Ответить на три вопроса:

1. Что именно я пытаюсь сделать?
2. Что уже сделал?
3. Что именно получил?

## Baseline / context

Полезные исходные данные:
- OS/environment;
- exact command/action;
- exact error message;
- minimal relevant code;
- что уже пробовали.

## Read-only checks

Source не задает конкретных shell checks как универсальный список. Главная read-only операция — собрать и прочитать фактический output/error, не меняя систему.

## Interpretation

Если формулировка проблемы стала ясной, возможны три исхода:
- ошибка находится самостоятельно;
- проблему можно воспроизвести и исправить повторным проходом;
- становится возможен качественный search/help request.

## Next action

Порядок source:
- попробовать заново;
- при длительном тупике сделать перерыв;
- посмотреть companion resources;
- искать в Интернете по конкретным словам/точному error;
- использовать официальную документацию;
- при необходимости задать вопрос со small reproducible example.

## Modifying action

[Not applicable] — приложение в основном описывает диагностический и коммуникационный процесс.

## Verification / acceptance checks

Хороший help request:
- содержит конкретную цель;
- перечисляет уже выполненные действия;
- приводит точный result/error;
- включает минимальный пример кода;
- не требует от другого человека исследовать огромный проект без контекста.
