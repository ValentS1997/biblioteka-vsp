# Cheatsheet — глава 5 «Создаем слаженную команду»

## Symptom / problem framing

Признаки несбалансированной команды:

- сильным сотрудникам скучно;
- младшие сотрудники тонут без наставничества;
- все критичные знания находятся у одного человека;
- команда состоит почти только из новичков;
- команда состоит почти только из «звезд», которые постоянно конкурируют;
- onboarding новых людей снижает скорость сильнее, чем ожидалось;
- команда растет быстрее, чем успевает формироваться рабочая структура;
- конфликтный сотрудник разрушает доверие;
- вся команда постоянно работает в режиме срочности;
- у людей слишком много одновременно активных задач;
- взаимодействие существует только в формальных рабочих каналах.

## Baseline / context

Сбалансированная команда в логике главы должна одновременно:

- закрывать все необходимые части проекта;
- иметь задачи подходящей сложности для каждого;
- давать людям пространство для развития;
- переживать временное отсутствие отдельных сотрудников;
- не тратить чрезмерные ресурсы на onboarding;
- сохранять приемлемый уровень конфликтов;
- работать без постоянного давления и авралов;
- иметь достаточные человеческие связи внутри коллектива.

## Read-only checks

### Сложность задач
1. Какие задачи для каждого сотрудника являются рутиной?
2. Какие попадают в его «серую зону»?
3. Есть ли сотрудники, у которых почти вся работа слишком легкая?
4. Есть ли сотрудники, у которых почти вся работа слишком сложная?

### Состав команды
1. Сколько младших, средних и старших специалистов?
2. Кто реально способен наставлять новичков?
3. Нет ли перегруза наставников?
4. Нет ли нескольких сильных сотрудников, претендующих на одну и ту же зону влияния?
5. Достаточно ли задач разной сложности?

### Стажеры
1. Есть ли запас времени на временное падение производительности?
2. Есть ли безопасные задачи для обучения?
3. Есть ли наставник?
4. Может ли стажировка помочь потенциальному будущему руководителю получить практику управления?

### Bus factor
1. Какая часть проекта остановится при временном отсутствии ключевого сотрудника?
2. Есть ли дублер для каждой критичной области?
3. Документируются ли критичные знания?
4. Есть ли review или групповые обсуждения, распространяющие контекст?
5. Не платит ли команда слишком большую цену за попытку сделать всех универсалами?

### Рост команды
1. Сколько людей можно реально onboard одновременно?
2. Успеют ли наставники продолжать основную работу?
3. Достаточно ли задач для новых сотрудников?
4. Можно ли разделить найм на этапы?

### Конфликты и «звезды»
1. Человек конфликтует со всеми или с определенной группой?
2. Как его поведение влияет на остальных?
3. Сколько времени руководитель тратит на устранение конфликтов?
4. Компенсирует ли реальная ценность специалиста организационные издержки?
5. Можно ли уменьшить конфликтность через изменение состава или зоны ответственности?

### Нагрузка
1. Каждая задача объявляется срочной?
2. Кто определяет сроки?
3. Сколько задач сотрудник держит в голове одновременно?
4. Есть ли возможность ограничить WIP и внешнее давление?

### Командные связи
1. Есть ли у людей пространство для неформального общения?
2. Есть ли регулярные совместные обеды / чаты / встречи?
3. Тимбилдинг связан с реальными интересами команды или навязан извне?

## Interpretation

- **Скука у сильного сотрудника** → возможно, задача слишком проста и не содержит зоны роста.
- **Новичок постоянно ошибается** → проверить не только человека, но и наличие наставничества и подходящих задач.
- **После найма команда стала медленнее** → это может быть нормальным onboarding effect.
- **Все могут делать всё, но никто не владеет областью глубоко** → универсализация могла зайти слишком далеко.
- **Один эксперт держит критичный контекст** → bus factor требует внимания.
- **Много сильных людей постоянно спорят** → пересекаются амбиции и зоны ответственности.
- **Конфликтная «звезда» съедает время всей команды** → оценивать нужно не индивидуальную продуктивность, а общий эффект.
- **Все время дедлайн «вчера»** → экстренный режим стал постоянной операционной моделью.
- **Люди знают друг друга только по task tracker** → команде может не хватать неформальных связей.

## Next action

1. Составить список ключевых типов задач проекта.
2. Для каждого сотрудника отметить:
   - рутинную область;
   - «серую зону»;
   - критичную специализацию;
   - возможного дублера.
3. Выявить перекос состава:
   - слишком много новичков;
   - слишком много конкурирующих сильных специалистов;
   - нехватка наставников;
   - критичные single points of knowledge.
4. Скорректировать распределение задач.
5. Если идет найм — проверить реальную onboarding capacity и по возможности разбить рост на этапы.
6. Ограничить количество одновременно активных задач.
7. Проверить, не превращены ли все сроки в экстренные.
8. Разобрать текущие конфликты через влияние на команду, а не только через индивидуальную результативность.
9. Создать простой канал неформального общения.
10. Для командного мероприятия выбирать формат, связанный с реальной общей работой или общим успехом.

## Modifying action

Источник поддерживает такие изменения:

- менять сложность задач под уровень сотрудника;
- разводить зоны ответственности сильных специалистов;
- при избытке новичков выращивать заместителя/наставника;
- нанимать стажеров только при наличии onboarding capacity;
- повышать bus factor через review, документацию, групповые обсуждения и дублеров;
- сохранять специализацию там, где она дает глубокую экспертизу;
- наращивать команду постепенно, если это возможно;
- расставаться с хронически конфликтными сотрудниками, если общий вред превышает пользу;
- адаптировать условия под действительно сильных специалистов, если trade-off оправдан;
- ограничивать WIP и постоянный deadline pressure;
- защищать команду от внешних авралов;
- поддерживать неформальное общение;
- выбирать тимбилдинги, связанные с работой и естественными интересами команды.

## Verification / acceptance checks

- у каждого сотрудника есть подходящая по сложности работа;
- ни один наставник не перегружен новичками сверх рабочей емкости;
- критичные области имеют хотя бы минимальное резервирование знаний;
- специализация не превращается в полную незаменимость;
- универсализм не уничтожает глубину экспертизы;
- новый найм не превышает способность команды к onboarding;
- зоны ответственности сильных сотрудников не создают постоянной войны;
- конфликтный сотрудник не снижает общую эффективность команды сильнее своей индивидуальной пользы;
- срочные режимы остаются исключением;
- число одновременно активных задач ограничено;
- в команде есть реальные неформальные связи.
