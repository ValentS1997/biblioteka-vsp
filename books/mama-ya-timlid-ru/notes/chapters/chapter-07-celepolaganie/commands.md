## Source-supported managerial tools / practices

| Прием | Тип | Эффект | Риск / ограничение | Проверка | Rollback |
|---|---|---|---|---|---|
| Явно сформулировать цель этапа | planning | Синхронизирует усилия команды | Слишком абстрактная цель бесполезна | Участники могут повторить цель своими словами | Переформулировать |
| Определить критерий готовности | planning | Снижает риск сделать вовремя, но непригодно | Источник не задает формальный DoD | Есть понятная граница «готово / не готово» | Уточнить критерий |
| Регулярно повторять цель | communication | Возвращает фокус | Избыточное повторение может стать шумом | Активные задачи остаются связанными с целью | Изменить частоту |
| Показывать пользовательскую проблему | read-only context | Связывает работу с реальной пользой | Пересылать лучше конструктивную обратную связь | Команда понимает эффект своей работы | Сменить источник контекста |
| Короткая презентация раз в 1–2 недели | communication ritual | Сохраняет общий контекст | Частота зависит от проекта | Команда знает изменения и приоритеты | Изменить cadence |
| Отдельная рассылка/страница для важных новостей | communication channel | Уменьшает потерю информации | Нужно поддерживать актуальность | Ключевые новости можно найти вне чата | Закрыть неэффективный канал |
| Демо-встреча | review ritual | Дает заказчикам видимость, команде — промежуточный результат | Не превращать в длинный отчет о мелочах | Показан реальный результат | Изменить формат/частоту |
| Короткий письменный итог | documentation | Оставляет общий контекст отсутствующим | Лишняя детализация снижает читаемость | Итог читается за несколько минут | Сократить формат |
| Совместное обсуждение разных ролей | collaboration | Повышает вовлеченность и качество решений | Не каждый проект выдерживает частые встречи | Участники реально влияют на решение | Перейти к async-формату |
| Общение с удаленными коллегами о целях | communication | Снижает ощущение «внешнего исполнителя» | Требует времени | Удаленная команда понимает общую картину | Использовать письменный формат |

## Goal-focus audit

```text
цель этапа:
  сформулирована?
  понятна каждому?
  есть критерий готовности?
  определена требуемая планка качества?

для каждой активной задачи:
  влияет на цель?
    yes -> оставить
    no  -> обосновать / отложить

коммуникация:
  есть надежный канал?
  есть регулярный повтор контекста?
  заказчики видят промежуточный результат?
  после синхронизации остается короткий итог?
```

## Safety boundary

Источник описывает управленческие практики коммуникации и вовлечения. Он не задает формальных OKR/KPI/SMART-процессов, требований к отчетности или обязательной cadence для всех команд.
