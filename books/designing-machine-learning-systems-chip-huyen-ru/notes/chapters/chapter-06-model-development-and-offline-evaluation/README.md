## Центральная идея

Выбор ML-модели — это **инженерное решение**, а не соревнование с целью получить максимальную автономную метрику. Надо учитывать назначение задачи, базовые решения, бюджет вычислений, скорость, объяснимость, изменчивость данных и последствия ошибок. **Автономная оценка не доказывает производственную пригодность**: устойчивость, калибровка, достоверность отдельных прогнозов и качество по критическим срезам рассматриваются отдельно. [p0163-c01–p0168-c01; p0189-c01–p0199-c01]

## Карта главы

1. **Выбор алгоритма и шесть советов (PDF 163–169).** Не гоняться за самым новым; начинать с простого; избегать предубеждений в сравнении архитектур; смотреть на перспективу с ростом данных; анализировать trade-offs; понимать предположения моделей (IID, независимость, линейность и др.). [p0163-c01–p0169-c01]
2. **Ансамбли (169–174).** Мажоритарное голосование, бэггинг/бутстреп, бустинг/перевзвешивание трудных примеров, стекинг/метаучащийся. Повышение качества сопровождается затратами на поддержку и развёртывание. [p0169-c01–p0174-c01]
3. **Experiment tracking, versioning и debugging (174–179).** Отслеживать кривые потерь, показатели, данные прогнозов/эталонные метки, скорость, CPU/GPU и меняющиеся гиперпараметры. Версионировать не только код, но и данные и среду; воспроизводимость без детерминизма оборудования не гарантирована. Начинать отладку с простой модели, переобучать маленький пакет, контролировать случайность. [p0174-c01–p0180-c01]
4. **Распределённое обучение (180–183).** Нехватка памяти, gradient checkpointing, data parallelism и синхронные/асинхронные градиенты, model parallelism и pipeline parallelism. [p0180-c01–p0183-c01]
5. **AutoML (183–186).** Поиск гиперпараметров (random/grid/байесовский), архитектурный поиск, обучаемые оптимизаторы. Тестовые данные **не использовать** для настройки гиперпараметров. [p0184-c01–p0187-c01]
6. **Четыре этапа разработки (186–188).** Без ML → простая ML-модель → её оптимизация → сложная архитектура после исчерпания простых. [p0187-c01–p0189-c01]
7. **Автономная оценка (188–198).** Базовые конфигурации/случайный прогноз и простые правила, существующие решения, человек; perturbation/invariance/expectation tests; калибровка, порог уверенности и срезы данных, включая парадокс Симпсона. [p0189-c01–p0198-c01]
8. **Итоги** (PDF 199 / печатная 198): оригинальный RAG-текст в [summary.md](summary.md), источник `p0199-c01`.
