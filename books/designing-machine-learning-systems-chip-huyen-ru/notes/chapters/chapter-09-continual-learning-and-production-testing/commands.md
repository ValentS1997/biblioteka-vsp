# Commands and tools — глава 9

Источник: канонический RAG PDF p.269–296, SHA256 `0bcacadb4e1dc2235cb58f975111e1633527217127c5871edb894fe2b8f4c80c`. **Глава не предоставляет готовый исполняемый runbook для переобучения, A/B, Canary или Bandits.** Не добавлять привычные CLI-команды из памяти.

| Класс | Упоминание RAG | Эффект и ограничения |
| --- | --- | --- |
| Read-only / measurement | Сравнение статичного test с recent non-overlapping backtest | Выяснить качество модели на старом и свежем распределениях; метки/срезы/конкретная метрика отсутствуют [p0285-c01–p0286-c01] |
| Workload-generating | Продолжение обучения от контрольной точки на микропакете | Stateful training, new model artifact; checkpoint path, optimizer state, dataset не заданы [p0270-c01–p0272-c01] |
| Workload / state-changing | Stateless retraining с нуля | Новый candidate, выполнение full training pipeline [p0271-c01; p0279-c01–p0281-c01] |
| Workload | Kafka, Confluent, Materialize, Snorkel | Возможные технологии потоков, логирования событий и ускорения маркировки; скриптов и конфигурации нет [p0275-c01–p0277-c01] |
| Workload / state-changing | Airflow, Argo, scheduler, model storage | Оркестрация извлечения данных, меток, train, eval и release; конкретные DAG/CLI отсутствуют [p0281-c01] |
| Workload | `StandartScaler` и `partiai_fit` (как в текстовом RAG) | В p0279-c01 повреждена форма названия метода incremental statistics; **не применять как рабочий API** [p0279-c01] |
| Read-only / workload | Shadow deployment candidate | Производит дополнительные прогнозы на реальном трафике, не должен воздействовать на пользователей, может увеличить вычислительную стоимость [p0286-c01–p0287-c01] |
| State-changing | A/B traffic routing | Деление трафика и сравнение с действующей моделью; вмешательство вариантов и sample-size — риски [p0287-c01–p0288-c01] |

| State-changing | Interleaving rankings, multi-armed/contextual bandits, Thompson sampling, UCB | Смешение результатов ранжирования или адаптивный выбор модели; влияет на пользовательский опыт, требует reward and attribution [p0289-c01–p0293-c01] |

## Alert / trigger параметры — не конфигурации

`p0283-c01` иллюстрирует четыре сигнала обновления: **время**, **ухудшение качества**, **объём новых размеченных данных** и **изменение распределения данных**. Значения (каждые 5 минут и изменение объёма на 5%) — примеры автора, **не production SLO/частота/команда**. Актуальная policy: **[Needs confirmation]**.

## Проверки до любого запуска

Подтвердить источник/доступность свежих данных и согласованные метки; независимый holdout, champion vs challenger, обновляемую контрольную точку, оценку и правила отбора; budget вычислений и трафика, риск/ответственность, обратимость решения. Для изменяющих состояние действий source-supported эффект — создание новой версии или перераспределение трафика; точные параметры, мониторинговые пороги и rollback API — **[Needs confirmation]**.

## Provenance issues

В p0279-c01 имена методов повреждены. В p0288-c01 формулировки статистической значимости и порог `p < 0,5` внутренне конфликтуют с соседним `p = 0,05`; в p0292-c01 приведено `ε = 0,9` вместе с 90% exploitation. Ничего не исправлять по памяти; подробности в `source-findings.md`.
