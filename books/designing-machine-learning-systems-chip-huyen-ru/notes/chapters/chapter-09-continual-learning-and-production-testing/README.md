## Основной принцип

Непрерывное обучение отвечает на проблему дрейфа и старения ML в производстве, но **обновлять живую модель напрямую нельзя**. Источник различает обслуживающую модель-чемпиона и её обновлённую копию-претендента, которую проверяют до замены; полезность свежих данных, стоимость обновления и проверка на production обязательны. Непрерывное обучение прежде всего требует инфраструктуры, связи stream данных, меток и автоматизированной оценки. [p0269-c01–p0273-c01; p0275-c01–p0278-c01; p0294-c01–p0295-c01]

## Карта главы

1. **Что такое непрерывное обучение** (269–273): обновление микропакетами, champion/challenger, catastrophic forgetting, stateless retraining против stateful continuation, неоднозначная терминология. [p0269-c01–p0273-c01]
2. **Почему и что мешает** (273–279): быстрые изменения, холодный старт, свежие данные/естественные метки, задержка оценки, ограничение части алгоритмов, online statistics. [p0273-c01–p0279-c01]
3. **Четыре этапа** (279–283): manual stateless → automated stateless → automated stateful → trigger-driven continual learning; автоматизация обработки данных, признаков, меток, обучения, оценки и деплоя. [p0279-c01–p0283-c01]
4. **Когда обновлять** (283–285): ценность свежести данных, обучение на разных исторических интервалах против свежего тестового периода, trade-off data iteration vs model iteration. [p0283-c01–p0285-c01]
5. **Тестирование в производстве** (285–294): статичные тесты плюс бэктестирование, shadow deployment, A/B, canary, interleaving, multi-armed и contextual bandits. Тестовые конвейеры должны иметь определённые стадии, пороги и ответственность. [p0285-c01–p0294-c01]
6. **Исходные «Итоги»** (294–295): явно маркированный RAG-grounded пересказ в [summary.md](summary.md), не дословное издательское воспроизведение.
