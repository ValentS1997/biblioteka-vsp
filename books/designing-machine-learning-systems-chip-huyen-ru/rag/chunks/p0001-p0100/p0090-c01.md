Основы проектирования баз данных           |  89

Режимы потока данных

В этой главе мы уже рассмотрели форматы и модели данных, а также их хранение
и обработку, задействованные в рамках одного процесса. Но чаще всего на произ
водстве у нас не один, а несколько процессов. Возникает вопрос: как передавать
данные между различными процессами, не использующими общую память?

Когда данные передаются из одного процесса в другой, мы называем это потоком
данных между двумя процессами. Существуют три основных режима потока данных:

♦ передача данных через базы данных;

♦  передача данных через сервисы, использующие запросы по типу тех, что пре
   доставляются REST и RPC API (например, запросы POST/GET);

♦  передача данных через транспортировку в реальном времени по типу Apache
   Kafka и Amazon Kinesis.

Рассмотрим каждый из этих пунктов по отдельности.

Передача данных через базы данных

Самый простой способ передачи данных между процессами — через базы данных,
о которых мы уже говорили в разд. «Хранение и обработка данных». Например,
для передачи данных из процесса А в процесс Б процесс А может записать данные
в базу, а процесс Б считать их из этой же базы.

Но этот режим не всегда работает, и на то есть две причины. Во-первых, это требу
ет, чтобы у двух процессов был доступ к одной и той же базе данных. Это может
быть неосуществимо, особенно если сами процессы выполняются разными компа
ниями.

Во-вторых, для этого требуется, чтобы к обеим базам имели доступ оба процесса, а
чтение/запись из баз данных могут быть медленными. Это делает вариант неподхо
дящим для приложений к строгим требованиям по задержке— например, почти
для всех приложений, ориентированных на потребителей.

Передача данных через сервисы

Еще одним способом передачи данных между двумя процессами является отправ
ка данных через сеть, соединяющую эти процессы. Чтобы передать данные из про
цесса А в процесс Б, процессу А сначала нужно отправить запрос с указанием не
обходимых данных в процесс Б. Через ту же сеть процесс Б передает данные в про
цесс  А.  Поскольку  процессы  взаимодействуют  через  запросы, мы  говорим,
происходит управление запросами (request-driven).
