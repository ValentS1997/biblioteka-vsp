  В контексте обучения без примеров (zero-shot learning или, иногда, zero-data
   learning, https://oreil.ly/ZshSg) система генерирует прогнозы для задачи, не бу
  дучи обученной на данных конкретно для этой задачи. При этом ML-система
   ранее обучалась на данных для других задач, часто связанных с рассматривае
  мой темой. Поэтому, даже несмотря на то, что системе не требуются данные для
   прогнозов, ей все равно нужны данные для обучения.

  Впрочем, возможно также запустить ML-систему вообще без данных. Например,
   в контексте непрерывного обучения модели можно развернуть ее без предвари
   тельного обучения на каких-либо данных— при этом она будет обучаться на
  входящих данных в ходе работы (мы рассмотрим тему онлайн-обучения в гла
   ве 9). Как бы там ни было, предоставление пользователям плохо подготовлен
  ных моделей сопряжено с определенными рисками — в том числе и снижением
   качества обслуживания клиентов.

   Без данных и постоянного обучения многие компании придерживаются принци
   па «притворяйся, пока это не станет правдой». Они запускают продукт с прогно
   зами, созданными людьми вместо ML-моделей, в надежде использовать сгене
  рированные данные для последующего обучения ML-моделей.

4. Предсказания: это ошибка прогнозирования.

  ML-модели делают прогнозы, поэтому способны решать только те проблемы,
   что требуют прогностических ответов. ML также может быть особо привлека
  тельным, если вы планируете извлечь выгоду из большого количества дешевых,
   но приблизительных прогнозов. В этом случае под «предсказанием» восприни
   мается «оценка значения в будущем». Например, какая погода будет завтра? Кто
   выиграет Суперкубок в этом году? Какой фильм зрители захотят посмотреть
  следующим?

  По мере повышения эффективности прогнозирующих машин (например, ML-
   моделей) все больше и больше проблем переосмысливаются в прогностические
   задачи. Какой бы у вас ни появился вопрос, вы всегда сможете сформулировать
   его так: «Каким был бы ответ на этот вопрос?» — вне зависимости от того, каса
   ется ли конкретный вопрос чего-либо в будущем, настоящем или даже в про
   шлом.

  Требующие больших вычислительных ресурсов задачи — один из классов задач,
   весьма успешно переосмысленных в прогностические. Вместо вычисления точ
   ного результата процесса, который к тому же может быть затратнее ML с точки
   зрения вычислений и отнимать больше времени, вы можете сформулировать
   проблему так: «Как будет выглядеть результат этого процесса?» и приблизить
   его к реальности с использованием ML. Результат будет близким к точному,
   но зачастую этого недостаточно. Много подобных примеров можно увидеть при
   рендеринге графики — например, для шумоподавлении или затемнения эк
   рана4.
