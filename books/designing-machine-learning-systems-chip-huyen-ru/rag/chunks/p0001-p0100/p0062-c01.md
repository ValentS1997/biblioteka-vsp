Введение в проектирование ML-систем          |   61

В аналогичном случае для ранжирования постов по вовлеченности сначала нужно
спрогнозировать количество кликов, которые получит каждый пост. В нашем слу
чае вы хотите свести к минимуму engagementlost — разницу между прогнозируе
мым и реальным количеством кликов на каждом посте.

Один из подходов заключается в объединении этих двух потерь в одну и обучении
модели минимизировать ее:

    loss = a quality loss + 0 engagement loss

Вы можете случайным образом протестировать значения а и 0 и найти те, что рабо
тают лучше всего. Если вы хотите подойти более системно, можете ознакомиться
с оптимизацией по Парето: «область принятия решений по множеству критериев,
связанная с задачами математической оптимизации, включающими более одной
целевой функции, которые должны быть оптимизированы одновременно»9.

         Возможно, вам также захочется прочесть замечательную статью Джина (Yaochu
            Jin) и Сендхоффа (Bernhard Sendhoff) о применении оптимизации по Парето в ML.
         В ней авторы утверждают, что «по своей сути машинное обучение является муль-
         тиобъективной задачей»10.S
Проблема с оптимизацией по Парето заключается в том, что при каждой настройке
а и 0 — например, если качество новостных лент повышается, но вовлеченность
снижается, вы можете захотеть уменьшить значение а и увеличить значение  0.
В таком случае вам придется переучивать свою модель.

Еще один подход заключается в обучении двух разных моделей, оптимизирован
ных под свои потери. Итак, у вас есть две модели:

♦  quality model — минимизация quality loss и вывод прогноза качества для каждо
   го поста;

♦ engagemet model— минимизация engagement loss и вывод прогнозируемого
   количества кликов на каждом посте;

и вы можете комбинировать выходные данные моделей и ранжировать публикации
по их суммарному рейтингу:

   a quality score + 0 engagement score

Так что теперь у вас есть возможность настраивать значения а и 0 без переучивания
своей модели!

В общем, если есть несколько целей, было бы неплохо для начала разделить их,
поскольку это упрощает разработку и обслуживание модели. Упрощает— потому
что легче настроить вашу систему без переучивания модели, как уже говорилось
ранее. Облегчает техобслуживание— потому что для разных целей может быть
применен разный режим обслуживания. Поскольку методы рассылки спама совер
шенствуются гораздо быстрее оценки качества постов, системы для фильтрации
спама должны обновляться чаще, чем системы ранжирования качества.
