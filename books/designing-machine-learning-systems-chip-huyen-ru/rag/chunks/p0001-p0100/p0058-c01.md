Введение в проектирование ML-систем           |  57

Когда количество классов становится слишком большим, может оказаться полез
ной иерархическая классификация, при которой классы сначала с помощью одного
классификатора распределяются по большим группам, а затем другой классифика
тор распределяет классы уже по подгруппам. Например, для классификации това
ров можно сначала распределить позиции по одной из четырех основных катего
рий: электроника, товары для дома и кухни, мода и товары для животных. После
попадания товара в одну из этих категорий вы можете задействовать другой клас
сификатор, помещающий товар в одну из подгрупп: обувь, рубашки, джинсы или
аксессуары.

Мультиклассовая или многометочная классификация?

В бинарной и мультиклассовой классификациях каждый пример может относиться
только к одному классу. Если пример относится к нескольким классам, то встает
задача мулыпиметочной классификации с несколькими метками. Например, при
создании модели для классификации статей по четырем темам: технологии, развле
чения, финансы и политика— статья может определяться как техническая и
финансовая одновременно.

Есть два основных подхода для задач с многометочной классификацией. Первый —
относиться к задаче как к мультиклассовой классификации, где есть четыре основ
ных класса: [технологии, развлечения, финансы и политика] и метка — например,
развлечения. Вы отражаете эту метку в векторе так:  [0,  1, 0, 0]. В классификации
с несколькими метками, если пример имеет сразу две метки: развлечения и финан
сы — метка уже будет представлена так: [0, 1, 1,0].

Второй подход состоит в том, чтобы превратить примеры в набор задач бинарной
классификации. Для задачи классификации упомянутых статей у вас может быть
четыре модели, соответствующие четырем темам, где каждая модель выводит ин
формацию о том, находится ли статья в этой теме или нет.

Судя по моему опыту, из всех типов задач у компаний возникает больше всего про
блем с многометочной классификацией. Этот тип означает, что количество классов,
присутствующих у примера, может меняться. Во-первых, это усложняет аннотацию
меток, т. к. усугубляет проблему множественности меток, о которой мы поговорим
в главе 4. Например, аннотатор может считать, что один и тот же пример соответ
ствует только одному классу, и эти разногласия бывает сложно разрешить.

Во-вторых, меняющееся число классов затрудняет получение прогнозов из необра
ботанных вероятностей. Возьмем ту же задачу классификации статей по четырем
темам. В зависимости от статьи ваша модель выдает распределение необработан
ных вероятностей: [0.45, 0.2, 0.02, 0.33]. В мультиклассовом режиме, когда вы знае
те, что текст может относиться только к одной категории, вы просто выбираете
класс с наибольшей вероятностью. В рассматриваемом случае это 0.45. В многоме
точной классификации, когда вы не знаете, к скольким классам может относиться
пример, вы можете выбрать две категории (0.45 и 0.33) или три категории с наи
большей вероятностью (0.45, 0.2 и 0.33).
