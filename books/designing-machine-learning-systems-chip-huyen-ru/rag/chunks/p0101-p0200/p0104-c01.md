А это значит, что вам заранее неизвестна вероятность, по которой должен быть
выбран твит. Но вы хотите убедиться, что:

♦ каждый твит выбирается с одинаковой вероятностью;

♦ вы можете остановить алгоритм в любое время, и твиты будут выбраны с верной
   вероятностью.

Одно из решений для этих проблем — резервуарное семплирование. Его алгоритм
предусматривает как бы резервуар, который может быть массивом, и состоит из
трех шагов:

 1. Первые к элементов помещаются в резервуар.

2. Для каждого поступающего и-го элемента генерируется случайный номер   z,
   причем  1 < i < п.

3. Если   1 <  i < к. элемент под номером  i заменяется в резервуаре на элемент под
   номером п, в противном случае ничего не происходит.

Это значит, что каждый входящий и-й элемент имеет вероятность к/п попасть
в резервуар. К тому же можно доказать, что каждый элемент, находящийся в резер
вуаре, имеет вероятность к/п быть там. То есть все образцы имеют равные шансы
быть отобранными. Если мы остановим алгоритм в любой момент, то увидим, что
все образцы в резервуаре были отобраны с правильной вероятностью. На рис. 4.2
приведен пример, показывающий, как работает резервуарное семплирование.

Семплирование по важности

Семплирование по важности — один из самых серьезных методов семплирования,
причем не только в сфере ML. Оно позволяет собирать данные из распределения,
когда у нас есть доступ только к другому распределению.
