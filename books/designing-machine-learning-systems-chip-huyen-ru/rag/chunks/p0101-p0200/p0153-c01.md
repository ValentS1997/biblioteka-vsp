152           |  Гпава 5

Для предотвращения будущих утечек информации в тренировочный процесс, а
также, чтобы не быть обманутым вашей собственной моделью во время ее оценки,
по возможности разбивайте данные по времени, а не случайным образом. Напри
мер, если у вас есть данные за пять недель, используйте данные за первые четыре
для формирования тренировочной части. А затем случайным образом разделите
данные за пятую неделю на проверочную и тестовую части (рис. 5.7).

Масштабирование перед разделением

Как уже отмечалось в разд. «Масштабирование», важно масштабировать признаки
ваших данных. Для этого потребуется их глобальная статистика (например, среднее
значение и дисперсия). Одна из распространенных ошибок — использование всех
обучающих данных для формирования глобальной статистики перед разделением
базы на фрагменты. Это приводит к утечке средних значений и значений дисперсии
тестовых выборок в процесс обучения, позволяя модели подгонять результаты под
тестовые выборки. Подобной информации не будет в реальной работе, поэтому
вероятнее всего после запуска в производство производительность модели сни
зится.

Во избежание такого рода утечки всегда сначала разбивайте свои данные, прежде
чем их масштабировать, а затем используйте статистику из обучающей части для
масштабирования других частей. Некоторые специалисты даже предлагают делить
данные перед любым предварительным анализом и обработкой данных, чтобы слу
чайно не получить информацию из обучающей части.

Заполнение отсутствующих данных
статистикой из тестовой части

Нередко специалисты обрабатывают отсутствующие значения заполнением (вво
дом) средних значений или медианой всех присутствующих значений. Утечка
может произойти, если эти значения вычисляются из всего пула данных вместо
того, чтобы делать это только на данных из обучающей части. Такой тип утечки
аналогичен типу, вызванному масштабированием, и его можно предотвратить ис
пользованием данных только из обучающей части.

Плохая обработка дублированных данных
перед разделением

Если в ваших данных есть дубли или почти дубли, их перед разбивкой надо уда
лить. В противном случае это может привести к появлению аналогичных выбо
рок — как при обучении, так и при проверке и тестировании. Дублирующиеся дан
ные в производстве весьма распространены. Их также находили в популярных ис
следовательских наборах данных. Например, в CIFAR-10 и CIFAR-100— двух
широко известных наборах данных, используемых для исследований в области
компьютерного зрения. Их представили в 2009 году, но только в 2019 году было
обнаружено, что 3,3% из CIFAR-10 и 10% изображений из CIFAR-100 имеют дубли
в обучающей части14.
