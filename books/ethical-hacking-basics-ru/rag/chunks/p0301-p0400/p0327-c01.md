   Модель данных может представлять собой сложный набор данных, в котором несколько частей данных связаны между
   собой и должны быть организованы вместе. Это сильно отличается от простой передачи строки с веб-страницы на веб-
   сервер. Это может быть передача нескольких строк, нескольких целых чисел, а также некоторой организующей информации.
   Одним из способов организации данных является использование расширяемого языка разметки (XML - Extensible Markup
   Language). XML позволяет объединить все связанные данные в единую структуру данных, дополненную организующей
   информацией, указывающей, что представляет собой каждая часть. Распространенным способом передачи данных между
   клиентом и сервером является использование XML для структурирования данных и передачи этого XML.

   Как вы увидите в других типах атак на веб-приложения, атака с внедрением XML-сущностей происходит из кода на веб-
   сервере, принимающего данные, поступающие от клиента, без какой-либо проверки данных. Это означает, что программисты
   не предусмотрели никакой проверки данных, когда они поступают в приложение. Даже если это код сценария в содержимом
   страницы, который отображает данные, пользователь все равно может подделать их или даже сгенерировать передачу
   данных для отправки на сервер. В результате любым данным, поступающим от пользователя, никогда нельзя доверять,
   поскольку нет никакой гарантии, что нормальный поток управления программой не был подделан. Когда программисты не
   проверяют данные, неверные данные могут попасть в программу и изменить ожидаемое поведение.

   Пример XML-пакета, который может позволить злоумышленнику получить доступ к системным файлам, показан в
   следующем листинге кода. XML обращается к внешнему объекту системы. В данном случае это файл. Злоумышленник
   запрашивает, чтобы содержимое файла /etc/passwd было доставлено обратно в представление и показано в окне
   браузера:

     <?xml version="1.0" encoding="ISO-8859-1"?>
      <!DOCTYPE wubble [
      <!ELEMENT wubble ANY>
      <!ENTITY xxe SYSTEM "file:///etc/passwd" >]><wubble>&xxe;</wubble>

   Причем, благодаря этой простой атаке, сервер приложений может выполнить часть работы за вас. Допустим, вы хотите
   узнать, работает ли внутренний веб-сервер (например, тот, к которому вы, как злоумышленник, не можете получить доступ
   из-за правил брандмауэра). Один из способов сделать это — заставить сервер приложений инициировать запрос, передав
   URL-адрес в системный тег. В этом случае сервер приложений выполнит вызов системы с помощью URL-адреса, который
   система будет интерпретировать как запрос на получение указанной страницы. Ниже вы можете увидеть пример XML,
   который позволит это сделать:

     <?xml version="1.0"?>
     <!DOCTYPE GVI [<!ENTITY xxe SYSTEM "https://172.30.42.25:8443">]>

   Конечно, такая проверка ресурсов или "сканирование портов", если хотите, — это не единственное, что вы можете сделать с
  помощью этого подхода.

   Лучший способ предотвратить такого рода атаки — выполнить проверку ввода. Проверка ввода должна выполняться на
   стороне сервера. Вы можете выполнить проверку ввода на стороне клиента, но ожидайте, что она будет обойдена.
   Достаточно легко использовать перехватывающий прокси-сервер или даже инструмент в браузере для перехвата запросов и
   их изменения перед отправкой на сервер.

   В подобных примерах просто запрет любому XML использовать внешний объект системы (SYSTEM) является началом
   защиты от успешной атаки. Любое действие, которое приложение должно выполнить через систему, должно выполняться
   непосредственно приложением после анализа данных. Если пойти еще дальше, было бы полезно оценить, существует ли
