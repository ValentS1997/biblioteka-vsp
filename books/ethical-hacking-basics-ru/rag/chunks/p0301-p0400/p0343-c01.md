  Шаг 7

  Защита приложений

   Как отмечалось ранее, одним из способов защиты операционной системы и работающих приложений является
   использование рандомизации структуры адресного пространства. ASLR (Address Space Layout Randomization) — это метод,
   который значительно усложняет злоумышленникам использование атак на переполнение буфера. Атака на переполнение
   буфера может быть успешной только в том случае, если злоумышленник сможет управлять указателем инструкции, чтобы
   получить информацию от операционной системы для выполнения кода, предоставленного злоумышленником. Другими
   словами, злоумышленнику необходимо знать, где в памяти находится предоставленный им код. Если адрес каждый раз
   меняется, это непредсказуемо. Один запуск программы может дать один адрес, тогда как последующий запуск даст
   совершенно другой адрес.

   Однако есть способ обойти эту проблему — использовать технику Атаки возврата в библиотеку (Return-to-libc attack) .
   Стандартная библиотека языка C (поскольку многие программы по-прежнему пишутся на C и производных языках, таких как
   C++) представляет собой набор функций, которые очень часто используются в программах. Например, следующая
   программа полностью написана с использованием функций стандартной библиотеки C. Одна функция printf используется
   для вывода информации, а другая scanf  - используется для получения информации от пользователя.

     #include<stdio.h>
     int main(int argc, char **argv) {
      char name[25];
      printf("What is your name? ");
      scanf("%s", name);
      printf("Hello, %s\n", name);
      return 0;
     }

   Было бы очень неэффективно использовать память для загрузки стандартной библиотеки C для каждой программы, которая
   собиралась ее использовать. Вместо этого - почему бы не использовать одну копию библиотеки, которая уже загружена в
   память, и позволить каждой программе ссылаться на нее там, где она находится? Это означает, что стандартная библиотека
   C вполне может находиться в фиксированном месте в памяти. Правильный адрес для функций предоставляется программе
   во время выполнения, поэтому при запуске программы используются адреса вместо имен функций. Если это правда, адреса
   этих вызовов функций можно предсказать. Это означает, что злоумышленнику больше не нужно предоставлять код. Можно
   использовать существующие функции из стандартной библиотеки, такие как execv . Функция execv и ее производные
   вызывают операционную систему для выполнения программы, которая может существовать где-то на диске. Как только это
   станет возможным, злоумышленник сможет просто вызвать оболочку напрямую, а не внедрять код для вызова этой
   оболочки.

   Термину «шеллкод» (shellcode) уже несколько десятилетий, и он относится к тому факту, что большая часть внедренного
   кода атаки представляет собой просто скомпилированные вызовы оболочки, которая представляет собой интерфейс
   командной строки, предоставляемый пользователю. Когда вы открываете окно терминала в Unix-подобной операционной
   системе, такой как Linux или macOS, вы запускаете оболочку. Когда вы вводите команду, оболочка получает и интерпретирует
    ее. Весь рабочий стол Windows, управляемый, по крайней мере частично, процессом Explorer.exe  , иногда называют
   оболочкой Windows.
