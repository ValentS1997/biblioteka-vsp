   К счастью, сейчас нам больше не нужно полагаться на атаки Smurf для усиления атак. Другой протокол, который можно
   использовать, — это DNS. В последние годы данный вид атак приобрёл некоторую популярность. Одной из широко известных
   атак стала атака на сайт Брайана Кребса Krebs on Security  , на котором публикуются статьи по информационной
   безопасности, написанные Кребсом, журналистом-расследователем. На пике объем трафика достигал 620 гигабит в секунду.

   Какая же механика атаки? DNS-запрос использует UDP в качестве транспортного протокола, и, как и в ICMP, проверка адреса
   источника не выполняется, что делает подделку адреса источника тривиальной. Атака работает, по основному принципу -
   запрос DNS небольшой, тогда как правильный ответ DNS может быть значительно больше. Обычная атака с усилением DNS
   имеет соотношение 70:1, что означает, что на каждый байт, отправленный в запросе, ответ имеет 70 байт. Для атаки
   действительно требуется отражатель, то есть DNS-сервер, который будет выполнять рекурсивные запросы
   (преобразователь, а не авторитетный сервер), открытый для Интернета. В идеале, конечно, использовать несколько
   преобразователей и несколько хостов, генерирующих запросы, чтобы получить максимальный объем.

   Конечно, существует ряд инструментов, которые можно использовать для запуска таких атак типа «отказ в обслуживании».
   Одним из них является LOIC . Это программа .NET, которая может работать как в системах Windows, так и в системах Linux, в
   которых установлен пакет Mono. Вы можете увидеть интерфейс LOIC на рисунке ниже. Эту программу можно использовать
   для отправки запросов как на URL-адреса, так и на IP-адреса. Вы можете использовать LOIC  для отправки TCP, UDP или
   HTTP-запросов к цели.
