   Wi-Fi Protected Access

   Шифрование сложное, и схемы шифрования находятся под постоянным контролем. Как уже отмечалось, WEP был взломан.
   Улучшения в технологиях, особенно в вычислительной мощности, значительно облегчили взлом шифрования, что обычно
   ограничивает срок годности новых механизмов шифрования. Благодаря этому вы можете понять, почему разработка новых
   способов шифрования данных занимает много времени. WEP считался проблематичным, но его нельзя было легко заменить
   долгосрочным решением. В качестве временной меры Wi-Fi Alliance выпустил защищенный доступ Wi-Fi (WPA - Wi-Fi
   Protected Access). WPA можно реализовать без каких-либо изменений оборудования. Аппаратное обеспечение,
   обеспечивающее работу WEP, также может использоваться для WPA. WPA можно включить после обновления прошивки.

  WPA представила протокол целостности временного ключа TKIP (Temporal Key Integrity Protocol). Там, где WEP объединял
   вектор инициализации с PSK, TKIP смешивал ключи. Это часть того, что позволило устройствам с поддержкой WEP работать
   с WPA. Тот же ключ, полученный другим способом, можно использовать в том же алгоритме RC4 для шифрования
   сообщений. TKIP также не использует сеансовый ключ, как это принято в других криптосистемах. Вместо этого он использует
   ключ для каждого пакета.Каждый пакет имеет свой ключ для шифрования и дешифрования, причем он содержит временную
    часть, поскольку каждый ключ привязан ко времени. Это было необходимо для решения одной из проблем WEP - когда
   набор кадров мог дать достаточно данных для получения ключа из-за слабости протокола при векторном алгоритме
   инициализации.

   Что касается целостности, передаваемые сообщения могут быть перехвачены и изменены. WEP использовал циклическую
   избыточную проверку (CRC - cyclic redundancy check) для проверки целостности сообщения. Это было сочтено
   недостаточным. Вместо этого WPA реализовала проверку целостности сообщения (MIC - message integrity check), которую
   иногда называют кодом аутентификации сообщения (MAC - message authentication code). Его не следует путать с MAC-
   адресом. Этот MAC предназначен для проверки целостности и подлинности отправленного сообщения. Принимающая
   сторона сверяет свои собственные расчеты MAC с расчетами, включенными в сообщение. Если MAC совпадают, сообщение
   не было подделано или иным образом повреждено при передаче.

  WPA поддерживает два режима аутентификации:

   Первый работает по существу так же, как ключ, используемый в WEP, и называется WPA-Personal. Это метод PSK. PSK
   действует как пароль, а также предоставляет ключ, который используется с вектором инициализации для генерации ключа
   шифрования, используемого с алгоритмом шифрования RC4.
   Второй режим аутентификации, называемый WPA-Enterprise, использует расширяемый протокол аутентификации (EAP -
    Extensible Authentication Protocol). EAP можно использовать для поддержки различных серверных хранилищ паролей.
   Например, вы можете использовать WPA-Enterprise с существующей базой данных пользователей предприятия и схемой
   аутентификации, например Windows Active Directory. EAP используется для передачи информации аутентификации вместе с
   ответами об успехе или сбое.

   Еще одним средством аутентификации является протокол WPS (Wi-Fi Protected Setup). Для этого может потребоваться
   физическое управление точкой доступа, поскольку для этого может потребоваться нажатие кнопки. Для завершения WPS
   также может потребоваться персональный идентификационный номер (PIN - personal identi cation number). Он используется
   для распределения ключей, поэтому пользователи клиентских устройств не знают, что это за ключ. Ключ хранится в
   конечной точке и используется для связи с точкой доступа, когда устройства подключаются к сети. Однако есть проблемы с
   WPS.
