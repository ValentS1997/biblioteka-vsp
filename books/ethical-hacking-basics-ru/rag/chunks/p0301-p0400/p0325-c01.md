   Модель (Model) — это структура данных. Несмотря на то, что она фактически хранится в базе данных (Database), существует
   сервер приложений (Application Server), который управляет моделью, создавая структуру и действуя на ее основе. Сервер
   приложений использует сервер базы данных для постоянного хранения информации, но вся обработка данных (модели)
   выполняется на сервере приложений. Традиционно этим сервером базы данных была реляционная база данных. Это
   означает, что все манипуляции с данными инициируются на сервере приложений, хотя выполнение логики иногда может
   происходить на сервере базы данных. Имейте в виду, что взаимодействие с базой данных осуществляется посредством
   использования языка структурированных запросов (SQL - Structured Query Language) при использовании сервера
   реляционной базы данных. Хотя бизнес-логика и логика приложения выполняются на сервере приложений, иногда
   манипуляции фактически выполняются на сервере базы данных.

   Контроллер (Controller) — это часть приложения, которая получает запросы и обрабатывает их, направляя запрос
   соответствующему модулю приложения, работающего на сервере приложений. В нашем примере с веб-приложением,
   контроллером выступает веб-сервер (Web Server).

   Наконец, представление (View) — это компонент взаимодействия с пользователем, обычно веб-браузер. Модель
   представлена таким образом, что пользователь может использовать ее в браузере. Существует код в виде языка
   гипертекстовой разметки (HTML - Hypertext Markup Language), используемый для описания и отображения страниц. Также на
   страницах могут быть различные скрипты, помогающие с работой страницы в браузере.

   Сервер приложений обрабатывает бизнес-логику приложения и может использовать разные языки программирования в
   зависимости от типа сервера приложений. В Windows кто-то может использовать службы Microsoft Internet Information
    Services, у которых есть сервер приложений, поддерживающий языки .NET, такие как C# и Visual Basic. Java-приложения
   доступны от многих вендоров. Широко используемые Tomcat, WildFly (ранее JBoss), WebLogic и многие другие — это типы
   серверов приложений Java. Сервер приложений сам по себе может содержать различные уязвимости и методы атак, но
   существует также множество общих атак, общих для веб-приложений.

   Однако при рассмотрении атак на веб-приложения важным моментом является то, какой компонент подвергается атаке.
   Некоторые атаки могут быть нацелены на клиентское устройство (представление), тогда как другие могут быть нацелены на
   веб-сервер (контроллер) или хранилище данных (базы данных). Однако точка атаки не всегда находится там, где вы могли
  бы устранить атаку. Это означает, что даже если, например, клиент стал целью атаки, клиент может быть не лучшим местом
   для защиты от атаки.

  Шаг 3

  OWASP Top 10

   Проект безопасности открытых веб-приложений (OWASP - Open Web Application Security Project) на самом деле представляет
   собой набор проектов. Одним из них является проект «Топ-10 уязвимостей» (https://owasp.org/Top10/). Это список
   уязвимостей, которые распространены во всех веб-приложениях. Хотя они были специально определены для веб-
   приложений, многие из проблем, лежащих в основе этих выявленных уязвимостей, существуют и в собственных
   приложениях.

   Список периодически обновляется, хотя большинство уязвимостей в текущем списке представляют собой варианты
   уязвимостей, которые в той или иной форме существовали во многих версиях. Со временем они претерпевают изменения в
   названиях и консолидируются, но многие из этих уязвимостей в той или иной форме существуют уже много лет. Версия
   списка 2021 года, обновленная по сравнению с версией 2017 года, включает следующие уязвимости:

      • A01:2021 Broken Access Control  - Нарушение контроля доступа.
