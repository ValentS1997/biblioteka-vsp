   Во-первых, любое новое вредоносное ПО не будет идентифицировано, поскольку для него не существует сигнатуры до тех
   пор, пока оно не будет проанализировано и сигнатура не будет добавлена в базу данных антивирусного ПО. Иногда
   вредоносное ПО может быть полиморфным. Это означает, что он имеет множество форм -программа переписывает себя по
   мере распространения, внося по ходу незначительные изменения. Это означает, что каждая копия может выглядеть по-
   разному. Конечно, это потребует от вредоносной программы внесения изменений в двоичный файл, возможно, путем записи
   новой копии по мере ее распространения. Большинство типов вредоносных программ могут быть полиморфными, но это
   требует определенных навыков от автора вредоносного ПО. Им необходимо знать, как вносить изменения в копии
   программы так, чтобы исполняемый файл не запускался.
   Во-вторых, вредоносное ПО может использовать упаковщики и шифровальщики, чтобы затруднить его обнаружение
   антивирусом. Использование другой схемы упаковки, возможно, путем более сильного или менее сильного сжатия, может
   привести к тому, что файл будет выглядеть по-другому, поскольку раздел данных будет выглядеть другим. При шифровании
   может использоваться другой ключ, и файл будет выглядеть по-другому. Даже в тех случаях, когда антивирус или
   обнаружение конечной точки отслеживает поведение, удаленные файлы могут иметь случайно сгенерированные имена. То
   же самое относится и к ключам и значениям реестра. Запись файлов и значений реестра в качестве действий не
   представляет особого труда, поэтому эти решения защиты не могут просто идентифицировать эти действия. Было бы
   слишком много предупреждений об общих действиях. Им нужны более конкретные детали для поиска. Это одна из причин,
   по которой системы, на которых установлены антивирусные решения, могут быть заражены вредоносным ПО.

   Распространенным программным обеспечением, используемым сегодня в корпоративных средах, является обнаружение и
   реагирование конечных точек (EDR - endpoint detection and response). Многие EDR-программы включают возможность
   обнаружения вредоносного ПО. Он наблюдает за тем, как работают исполняемые файлы. Существует несколько шаблонов
   выполнения, которые использует вредоносное ПО. Например, вредоносное ПО может читать и записывать в определенные
   разделы реестра. При этом, рабочий каталог будет другим, поскольку подобные действия из системных каталогов будут
   легитимными.

   Вредоносное ПО по большей части не является чем-то одноразовым. Это особенно актуально, когда целью вредоносного ПО
   является предоставление злоумышленнику удаленного доступа. Злоумышленник хочет, чтобы вредоносное программное
   обеспечение продолжало работать при входе в систему, выходе из системы и перезагрузках. Злоумышленник может
   использовать несколько методов, чтобы обеспечить постоянную работу программного обеспечения. Начиная с процесса
   загрузки, вредоносное ПО может установиться и запуститься еще до запуска операционной системы. Это позволяет ему
   контролировать процесс загрузки и гарантировать, что он находится в памяти, прежде чем будут задействованы какие-либо
   средства защиты.Вредоносное ПО перед загрузкой встречается нечасто, но оно является одним из наиболее опасных,
   поскольку его труднее обнаружить, поскольку оно уже запущено до запуска какой-либо антивирусной программы.

   В системах Windows злоумышленники как правило используют реестр Windows для добавления ключей, которые будут
   автоматически запускать программное обеспечение. Есть несколько часто используемых ключей реестра. Первый —
    HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run  , который запускает программное обеспечение при
   запуске системы. Другой — HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run .
