  Обнаружение снифферов

   Хотя сниффер работает в одной системе и собирает информацию (что вы можете считать пассивной деятельностью),
   существуют способы определить, когда интерфейс находится в неразборчивом режиме. Самый простой способ —
   просмотреть систему, интерфейс которой находится в беспорядочном режиме, например, в системе macOS с запущенным
    tcpdump вы увидите следующий вывод ifconfig :

     en0: flags=8963<UP,BROADCAST,SMART,RUNNING,PROMISC,SIMPLEX,MULTICAST> mtu 1500
          options=50b<RXCSUM,TXCSUM,VLAN_HWTAGGING,AV,CHANNEL_IO>
          ether 14:98:77:31:b2:33
          inet6 fe80::10c6:713a:e86f:556d%en0 prefixlen 64 secured scopeid 0x7
          inet 192.168.1.144 netmask 0xffffff00 broadcast 192.168.1.255
          inet6 2601:18d:8b7f:e33a::52 prefixlen 64 dynamic
          inet6 fd23:5d5f:cd75:40d2:87:38bc:9448:3407 prefixlen 64
          autoconf secured
          nd6 options=201<PERFORMNUD,DAD>
          media: autoselect (1000baseT <full-duplex,flow-control,energy-efficient-ethernet>)
          status: active

   Если вы посмотрите на строку с флагами, вы увидите PROMISC . Это указывает на то, что интерфейс находится в
   неразборчивом режиме, то есть интерфейс не выполняет никакой фильтрации MAC-адресов. Любой пакет, проходящий через
   интерфейс, будет отправлен в операционную систему. К сожалению, это касается не всех операционных систем. В недавней
   установке Kali Linux с запущенным tcpdump  , как и в системе macOS, ifconfig показывает следующий вывод:

     eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST> mtu 1500
           inet 192.168.1.128 netmask 255.255.255.0 broadcast 192.168.1.255
           inet6 fd23:5d5f:cd75:40d2:8922:b227:ed41:59a1 prefixlen 64 scopeid 0x0<global>
           inet6 fd23:5d5f:cd75:40d2:20c:29ff:fee9:f642 prefixlen 64 scopeid 0x0<global>
           inet6 fe80::20c:29ff:fee9:f642 prefixlen 64 scopeid 0x20<link>
           ether 00:0c:29:e9:f6:42 txqueuelen 1000 (Ethernet)
           RX packets 9145 bytes 6754039 (6.4 MiB)
           RX errors 0 dropped 0 overruns 0 frame 0
           TX packets 4214 bytes 913545 (892.1 KiB)
           TX errors 0 dropped 0 overruns 0 carrier 0 collisions 0

   Другой способ получения адресной информации об интерфейсах, с помощью команды ip a  , также не показывает, что
   интерфейс находится в неразборчивом режиме. То же самое относится и к получению состояния канала интерфейса, с
  помощью команды ip link . Также учитывайте, что ipconfig в Windows показывает несколько иную функцию, чем в Unix-
   подобных операционных системах. Он просто предоставляет конфигурацию IP, а не конфигурацию интерфейса, поэтому вы
   также не увидите, находится ли интерфейс в неразборчивом режиме.

   Однако вам не обязательно находиться на компьютере, чтобы определить, находится ли устройство в беспорядочном
   режиме, это можно определить по косвенным признакам. Например, сетевой администратор или системный администратор,
   ответственный за DNS-сервер, может определить устройство, которое перехватывает пакеты, поскольку такие инструменты,
   как Wireshark и tcpdump, по умолчанию, выполняют резолв имени хоста по его IP-адресу, а соответственно генерируют
   большое количество DNS-запросов. Поэтому для каждого нового IP-адреса будет выполняться соответствующий поиск DNS
   операционной системой, в которой происходит перехват пакетов. И хотя это не гарантия того, что кто-то перехватывает
   пакеты на устройстве, но может быть полезным индикатором.

   Если в вашей сети используются концентраторы, а не коммутаторы, существуют некоторые различия в идентификации
   устройств, перехватывающих пакеты. Во-первых, гораздо проще наблюдать за трафиком самостоятельно, чем нуждаться в
