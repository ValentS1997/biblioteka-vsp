   Тайм-менеджмент

   Все файлы в файловой системе имеют связанные с ними даты и время. Обычно у вас есть даты изменения, доступа и
   создания для каждого файла. Если вы попытаетесь заменить общий файл в файловой системе трояном, содержащим
   созданную вами полезную нагрузку, у него будут метки времени, связанные с загружаемым вами файлом. Это делает его
   более заметным. Вместо этого вы можете изменить время файлов. Опять обращаемся к Meterpreter. В следующем коде вы
   можете увидеть использование timestomp для управления временем файла. С его помощью, мы можем установить время
   для загруженного нами файла, которое идентично отметкам времени в законном файле. Когда мы переместим наш файл на
   место, он будет иметь правильное время.

     meterpreter> upload regedit.exe
     [*] uploading : regedit.exe -> regedit.exe
     [*] Uploaded 72.07 KiB of 72.07 KiB (100.0%): regedit.exe -> regedit.exe
     [*] uploaded: regedit.exe -> regedit.exe
     meterpreter> timestomp regedit.exe -f /windows/regedit.exe
     [*] Pulling MACE attributes from /windows/regedit.exe

   Каждый раз, когда вы манипулируете файлом, вы будете корректировать значения времени в файле, просто обращаясь к
   нему. Например, вы измените время изменения и доступа. Чтобы замести следы, вы можете убедиться, что значения
   времени в файлах, к которым вы обращались, вернулись к тем значениям, которые были до изменения файла.

  Шаг 10

  Внедрение процесса (Process Injection)

   Поскольку мы не хотим оставлять вокруг себя какие-либо процессы, которые можно было бы отследить, мы можем
   подумать об использовании другого пространства процессов. Один из способов сделать это — внедрить код в существующий
   процесс. Идея внедрения процесса заключается в том, чтобы взять код, который хочет запустить злоумышленник, и затем
   внедрить его в существующий процесс. После внедрения кода в процесс злоумышленнику необходимо запустить новый
   поток, использующий внедренный код. В системе Windows это делается путем получения дескриптора процесса и
   последующего использования этого дескриптора для выделения памяти в целевом процессе. Дескриптор с точки зрения
   Windows API по сути является указателем на запись процесса в списке процессов.

   Как только злоумышленник получит дескриптор и внедрит код в пространство процесса, этот код может быть выполнен. Это
   означает, что код выполняется в пространстве целевого процесса. Код фактически скрыт внутри этого нового процесса.
   Например, в следующем листинге вы можете увидеть модуль Metasploit, который внедряет код в процесс, указанный в
   качестве параметра модуля. Выбранный процесс — это процесс postgres  , что означает, что шелл-код выполняется в
   пространстве процессов сервера базы данных. Выполняемая полезная нагрузка будет привязана к TCP-порту, значение
   которого по умолчанию равно порту 4444  , поскольку в качестве параметра не было указано другое значение.
