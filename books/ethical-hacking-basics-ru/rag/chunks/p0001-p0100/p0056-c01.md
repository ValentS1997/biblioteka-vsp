  Шаг 5

   Межсетевые экраны прикладного уровня

   Помимо брандмауэров DPI существуют брандмауэры прикладного уровня. несмотря на то, что эти брандмауэры
   также проверяют содержимое сообщения, они обычно специфичны для определенного протокола. Например, в сетях
   передачи голоса по IP (VoIP - voice over IP) можно использовать устройство, называемое пограничным контроллером сеанса
   (SBC - session border controller). Это устройство, которое понимает протоколы VoIP — обычно использует протоколы H.323
   или SIP (Session Initiation Protocol). Таким образом, оно не только может принимать решения о легитимности пересылаемых
   сообщений, но также может открывать динамические порты, позволяющие передавать мультимедийные сообщения,
   используя протокол RTP (Real-time Transport Protocol). SBC может быть примером брандмауэра прикладного уровня,
   поскольку он имеет возможность принятия решений о разрешении передачи собщений. Он принимает эти решения на
   основе понимания работы протокола прикладного уровня и просмотра всего потока сообщений.

   Другим распространенным брандмауэром прикладного уровня является брандмауэр веб-приложений (WAF - web application
     rewall). WAF использует набор правил для обнаружения и блокировки запросов и ответов. Учитывая число запросов в
   случае веб-атак, соблюдение этих правил может оказаться непростой задачей. Например, для защиты веб-серверов Apache
   можно использовать бесплатный ModSecurity (модуль с открытым исходным кодом), равно как и любые коммерческие WAF.

     [mod-security Rule]
      SecRule RESPONSE_BODY "@rx (?i)(?:supplied argument is not a valid
     MySQL|Column count doesn't match value count at row|mysql_fetch_array\(\)|on
     MySQL result index|You have an error in your SQL syntax;|You have an error in
     your SQL syntax near|MySQL server version for the right syntax to
     use|\[MySQL\]\[ODBC|Column count doesn't match|Table '[^']+' doesn't
     exist|SQL syntax.*MySQL|Warning.*mysql_.*|valid MySQL result|MySqlClient\.)"
     \
      "capture,\
      setvar:'tx.msg=%{rule.msg}',\
      setvar:tx.outbound_anomaly_score=+%{tx.critical_anomaly_score},\
      setvar:tx.sql_injection_score=+%{tx.critical_anomaly_score},\
      setvar:tx.anomaly_score=+%{tx.critical_anomaly_score},\
      setvar:tx.%{rule.id}-OWASP_CRS/LEAKAGE/ERRORS-
      %{matched_var_name}=%{tx.0}"

   Правило, которое вы видите выше, ищет в теле ответа сообщение, которое находится после @rx . Сообщение представлено
   в виде регулярного выражения. Это своеобразный "поисковый шаблон". Если последовательность символов в
   анализируемом сообщении соответствует данному шаблону, данное правило сработает и вся информация данного
   сообщения будет сохранена в соответствующих переменных для дальнейшей обработки. В зависимости от настроенных
   правил обработки, дальнейшая отправка данного сообщения может быть заблокирована и оно не дойдет до веб-сервера. Это
   означает, что WAF находится в разрыве сети перед защищаемым веб-сервером. Иногда WAF, такой как ModSecurity,
   реализуется на границе сети как обратный прокси-сервер, поэтому клиенты отправляют сообщения обратному прокси-
   серверу, который обрабатывает сообщение от имени сервера, анализируя его на наличие потенциально неверных запросов,
   прежде чем отправить его фактическому веб-серверу. Ответы также проходят через обратный прокси-сервер.

   Это всего лишь несколько примеров межсетевых экранов прикладного уровня. Их также можно назвать шлюзом
   прикладного уровня - любое устройство, способное принимать решения на основе происходящего в протоколе прикладного
   уровня, и имеющее возможность отбросить любое подозрительное сообщение.
