   Конечно, не каждая система похожа на Unix. В системах Windows сообщения журнала по умолчанию отправляются в
   подсистему событий. Вместо текстовых сообщений, которые использует системный журнал, подсистема событий использует
   двоичную систему хранения. Конечно, одно из преимуществ данного способа хранения подсистемы событий заключается в
   том, что к ним можно запрашивать, как если бы это была база данных. Другими словами, это позволяет легко находить и
   отображать требуемую информацию в связанных сообщениях с помощью одного запроса.

   Подсистема событий в Windows также содержит большой объем данных. Помимо основных журналов, соответствующим
   различным категориям, таких как система, безопасность и приложение, существуют идентификаторы событий (Event ID).
   Идентификатор события может объединять все записи, которые являются одинаковыми. Поиск идентификатора события
   может дать вам каждый экземпляр определенного события, которое может произойти в нескольких процессах.

   В обоих случаях, разработчики приложений могут использовать предусмотренную системой функцию ведения журнала. Что
   касается Unix, любой разработчик может писать в системный журнал, и служба системного журнала сохранит информацию в
   соответствующем журнале, в зависимости от настроек в файле конфигурации. Таким образом, ответственность за
   разработку схем журналирования ложится на разработчиков, и при этом обеспечивается единое место для хранения
   событий.

   То же самое справедливо и для систем Windows. Любой разработчик приложений может использовать подсистему событий,
   для записи сообщений журнала. Приложение может даже иметь собственный файл журнала, и Windows разложит события
   по соответствующим журналам.
