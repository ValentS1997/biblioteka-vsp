   Помимо создания ложных целей, как обсуждалось ранее, вы можете поручить nmap позаботиться о фрагментации за вас.
   Хотя fragroute хорош и может использоваться в самых разных обстоятельствах, nmap позаботится о фрагментации легко,
   если все, что вам нужно сделать, это сканировать.

     $ sudo nmap -f -p80,443 192.168.178.1
     Starting Nmap 7.93 ( https://nmap.org ) at 2022-11-20 19:26 CET
     Nmap scan report for fritz.box (192.168.178.1)
     Host is up (0.12s latency).
     PORT STATE SERVICE
     80/tcp filtered http
     443/tcp filtered https

   Другой способ добиться чего-то подобного — заставить nmap установить MTU. Это поле в заголовке IP, которое сообщает
   сетевому оборудованию, насколько большими могут быть IP-пакеты в зависимости от среды передачи. Некоторые сети
   принимают только кадры данных ограниченного размера. Например, Ethernet допускает максимальную единицу передачи в
   1500 байт. Любой сегмент данных большего размера необходимо фрагментировать с соответствующим образом
   установленными заголовками фрагментации. Получающая сторона должна собрать все сообщение в правильном порядке.
   Если вы установите MTU достаточно маленьким, некоторые промежуточные устройства, такие как маршрутизаторы или
   брандмауэры, могут предпочесть переслать сообщения без их сбора и просмотра содержимого. Разрешение nmap
   установить MTU выглядит следующим образом, учитывая, что MTU должно быть кратно 8:

     $ sudo nmap --mtu 24 -p80,443 192.168.178.1

     Host is up (0.12s latency).
     PORT STATE SERVICE
     80/tcp filtered http
     443/tcp filtered https
