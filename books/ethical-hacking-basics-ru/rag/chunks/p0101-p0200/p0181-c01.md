  Шаг 9

  Радужные таблицы

   Для каждого пароля, проверенного с помощью John, вам необходимо вычислить хэш для проверки. Это требует времени и
   вычислительной мощности. С современными процессорами необходимое время и вычислительная мощность не имеют
   большого значения, разве что они складываются. Микросекунды на слово в миллионах слов превращаются в часы. Перед
   выполнением проверок проще предварительно вычислить хеши. Все, что вам нужно сделать, это найти хэш в индексе и
   получить простой текст, который использовался для создания этого хеша. Вся трудоемкая работа выполняется задолго до
    того, как вам понадобится взламывать пароли. Конечно, есть компромисс. Предварительное вычисление хешей означает,
   что вам нужно их где-то хранить.

   Радужные таблицы (Rainbow tables) — это сохраненные предварительно вычисленные хеши. Радужная таблица не так
   проста, как просто сопоставление хеша и пароля. Радужные таблицы хранятся в цепочках, чтобы ограничить количество
   хранимых паролей в виде открытого текста. В некоторых случаях можно вывести простой текст, если он не сохранен
   напрямую. Существует множество инструментов, которые можно использовать для поиска паролей из этих таблиц, но
   сначала нам нужны таблицы. В проекте Rainbow Crack есть инструмент как для поиска пароля, так и для создания
   радужной таблицы. Этот инструмент создания не используется для создания хэшей из списков слов. Вместо этого он
   сгенерирует хеш из всех возможных значений пароля в рамках предоставленных ограничений. В качестве примера, можно
   посмотреть на использование rtgen для создания радужной таблицы.
