   Одно и то же NetBIOS-имя может быть зарегистрировано для записей разного типа, каждая из которых содержит признак
   сетевой службы, существующей для данного имени. Например, мы видим систему BILLTHECAT  , которая одновременно
   является рабочей станцией (имеет код типа ресурса - 00) и файловым сервером (код 20). Другими словами, система
   действует как рабочая станция или клиент в сети, а также вней включен общий доступ к файлам.

   Таким образом, для получения информации нам нужны имена хостов, а получить их можно из широковещательных
   сообщений. Особенно это эффективно когда нет централизованной базы данных для поиска имен — системы объявляют
   свои имена и свою активность, когда они выходят в сеть, а затем периодически повторяют эту процедуру. Другим местом,
   где можно найти перечень хостов являтся сервис WINS (Windows Internet Name Server), который является центральным
   хранилищем имен систем в корпоративной сети. Для просмотра хостов в сети, отвечающих на широковещательный запрос,
   можно воспользоваться командой nbtstat -r . Все эти системы — macOS, но они обмениваются файлами в сети с
  помощью SMB. Для этого они должны вести себя как любая другая система, взаимодействующая с использованием SMB.

   Есть и другие функции, которые предлагает nbtstat  , но они больше связаны с функциональностью локальной системы и не
   так важны для нас. Основной минус nbtstat - он доступен только в системах Windows. Если у вас есть система Linux и
   установлен пакет Samba, который предоставляет службы, позволяющие Linux взаимодействовать с использованием SMB, вы
   можете использовать инструмент nmblookup . Его можно использовать для запроса WINS, а также для поиска имен,
   которым системы просто передают свою информацию. Например, чтобы получить подробную информацию о системе
    billthecat  , как мы делали ранее, можно использовать команду nmblookup -S -B billthecat

     $ nmblookup -S -B 192.168.86.255 billthecat
     querying billthecat on 192.168.86.255
     192.168.86.32 billthecat<00>
