   Конечно, nmap может дать вам хороший старт для получения списка сервисов и номеров версий, но этого не всегда
   достаточно. Тогда на помощь приходят различные сценарии, которые устанавливаются вместе с nmap. Эти сценарии можно
   использовать для извлечения большого количества информации, например, список используемых алгоритмов SSH, которые
   иначе трудно получить. SSH может предоставлять услуги шифрования, но не все алгоритмы шифрования свободны от
   уязвимостей, поэтому информация о возможности использования слабых алгоритмов очень ценна. Никогда не знаешь, где
   можно столкнуться с уязвимостью.

  Варианты защиты

   Каждая служба будет иметь разные параметры конфигурации, которые предотвратят перебор злоумышленниками, но на
   высоком уровне для каждой службы следует учитывать следующие контрмеры:

      • Брандмауэры. Как сетевые, так и хостовые брандмауэры можно использовать для защиты служб, не позволяя
        системам, которые не должны взаимодействовать, отправлять запросы.
      • Аутентификация. Строгая аутентификация может помочь защитить некоторые службы, поскольку аутентификация
       может производиться до того, как к службе будут сделаны запросы.
      • Уменьшите количество предоставляемой информации. Некоторые службы позволяют вам настроить объем
       информации, предоставляемой в баннере — информации, которую служба приветствует пользователя, когда
       приложение получает запрос на соединение.

  Шаг 3

  Удаленный вызов процедур

   Удаленный вызов процедур (RPC - Remote Procedure Calls) — это служба, которая позволяет удаленным системам
   использовать процедуры, внешние по отношению к вызывающему их приложению. Например, программа в системе А может
   вызывать функцию или процедуру в системе В удаленно через сеть, с помощью протокола RPC. Что касается программы на
   локальном компьютере, вызывающей удаленную процедуру на этом же компьютере, то это локальная процедура,
   существующая в том же пространстве процесса, что и остальная часть кода. Программа вызывает эту процедуру, получает
   информацию и продолжает свой путь. RPC таким образом предоставляют возможность двум процессам взаимодействовать
   друг с другом. Несмотря на то, что "удаленный" обычно означает другой сервер, но два локальных процесса также могут
   использовать RPC для связи друг с другом.

   Идея межпроцессного взаимодействия существует уже несколько десятилетий. На протяжении десятилетий существовало
   несколько реализаций протоколов запроса-ответа. Удаленный вызов методов Java (RMI - remote method
    invocation) является его примером. До этого существовала архитектура брокера общих объектных запросов (CORBA -
  Common Object Request Broker Architecture), которая не зависела от языковой реализации. Иногда, при использовании RPC
   для обращения к службе, вам нужно нечто, что по сути является службой каталогов, чтобы указать динамические порты, на
   которых работают различные службы.

   Распространенной реализацией удаленных вызовов процедур является программа portmap  , также известная как rpcbind .
   Эта программа используется для предоставления информации о программах, зарегистрированных в службе portmapper  ,
   обеспечивая эти удаленные процедуры. Сопоставитель портов назначает порт для прослушивания службы и по запросу
   может предоставить эту информацию обратно. Типичными примерами служб, использующих rpcbind/portmap, являются
   серверы обмена файлами, такие как Network File Server (NFS). Пакет, предоставляющий службу portmap или rpcbind  , также
   может содержать утилиты, которые также могут взаимодействовать с использованием RPC. Это делается через порт 111.
   Для идентификации программ и связанных с ними портов в удаленной системе вы можете использовать команду rpcinfo
   -p .
