## Главный принцип

**Защита информации — управляемая бизнес-риском система, а не одиночное устройство.** Сначала определяются активы, свойства CIA, угрозы/потери и требования; политика устанавливает намерения, стандарты — требования реализации, процедуры — конкретные шаги. Затем применяются профилактические, обнаруживающие и корректирующие меры, логирование, аудит и подготовка к реагированию. Источник: `p0043:c01`, `p0048:c01`–`p0053:c01`, `p0064:c01`, `p0067:c01`–`p0071:c01`.

## Состав знаний

1. **CIA + Parker:** конфиденциальность (в том числе data at rest/in transit), целостность и доступность; контроль/владение, подлинность и возможность использования как дополнительные свойства по Паркеру. `p0043:c01`–`p0047:c01`.
2. **Риск и решения:** вероятность × потери — количественная модель источника; варианты обработки риска: принять, передать, снизить, избежать. Технические, административные и физические контроли могут быть превентивными, обнаруживающими и корректирующими. `p0047:c01`–`p0050:c01`.
3. **Контракты процесса:** политика (намерение/приоритеты) → стандарт (как требование должно быть реализовано) → процедура (конкретные действия); рекомендации не обязательно обязательны. `p0050:c01`–`p0052:c01`.
4. **Технологии:** фильтрация пакетов; stateful tracking; DPI; WAF/протокольно-ориентированные шлюзы; UTM; IDS/IPS и риски false positive; EDR и SIEM для наблюдаемости/расследования. `p0053:c01`–`p0063:c01`.
5. **Архитектура и операционность:** глубокоэшелонированные слои, защита вширь, границы сетевых сегментов, централизованное ведение журналов, Windows Event ID и Linux Audit. `p0064:c01`–`p0071:c01`.

## Safety boundary

На страницах 54–55 содержатся **state-changing** команды `iptables`, способные прервать действующие соединения при неподходящем порядке правил. Они сохранены **только как цитаты источника**, не как рекомендации к запуску. Scope, интерфейс, возможность восстановления консольного доступа, pre-check, тестовый стенд, разрешение изменения и rollback — **[Needs confirmation]**. В книге также присутствуют правила ModSecurity/Snort с признаками разрыва длинных строк при извлечении; они не нормализованы в исполняемый конфиг без подтверждения.
