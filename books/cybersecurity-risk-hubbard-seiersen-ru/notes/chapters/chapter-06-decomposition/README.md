# Глава 6. Разложение на составляющие

**Книга:** Дуглас У. Хаббард, Ричард Сирсен — «Как оценить риски в кибербезопасности: лучшие инструменты и практики».  
**Book ID:** `cybersecurity-risk-hubbard-seiersen-ru` · **Глава:** 06 · **Контракт:** BIBLIOTEKA-VSP-CHAPTER-ARTIFACT-COLLECTION v1.7.  
**Статус:** `RAG_GROUNDED`; все выводы основаны на адресуемом каноническом RAG.

## Главная идея

Разложение полезно не само по себе. Оно должно превращать абстрактную неопределённость в **более понятные, наблюдаемые и полезные для решения величины**, о которых аналитик знает больше, чем об исходной агрегированной оценке.

Авторы развивают простую модель главы 3: вероятность события и диапазон потерь можно раскладывать на более конкретные компоненты — тип события, продолжительность простоя, стоимость часа простоя, категории затрат и т. п. Но **чрезмерное или неинформативное разложение способно ухудшить оценку**.

## Практические правила главы

1. **Понятность:** все одинаково понимают, что означает компонент.
2. **Наблюдаемость:** можно указать, что именно будет наблюдаться при его проявлении.
3. **Полезность:** знание компонента должно менять решение.
4. **Информативность:** компонент должен быть лучше известен, чем исходная агрегированная величина.
5. **Simulation check:** разложенную модель нужно сопоставлять с исходной прямой оценкой.
6. **Dependency check:** коррелированные компоненты нельзя автоматически считать независимыми.
7. **Stop condition:** если есть хорошие эмпирические данные по итоговой величине, дальнейшее разложение может не давать пользы.
