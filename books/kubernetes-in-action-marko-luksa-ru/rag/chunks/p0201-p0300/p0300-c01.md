8.2 Обмен с сервером API Kubernetes    299

   ПРИМЕЧАНИЕ. Эти исходные типы ресурсов без группы API сейчас входят в
     состав ключевой группы API.

  Изучение конечной точки REST группы API batch
  Давайте рассмотрим API ресурса Job. Для начала вы взглянете на то, что сто-
ит за путем /apis/batch (версию вы пока отложите в сторону), как показано в
следующем ниже листинге.

   Листинг 8.8. Вывод списка конечных точек в /apis/batch:
   http://localhost:8001/apis/batch

$ curl http://localhost:8001/apis/batch
{
  "kind": "APIGroup",
  "apiVersion": "v1",
  "name": "batch",
  "versions": [
    {
      "groupVersion": "batch/v1",                       
      "version": "v1"
    },                                                   Группа API batch
    {                                                  содержит две версии
      "groupVersion": "batch/v2alpha1", 
      "version": "v2alpha1"
    }
  ],                                              Клиенты должны использовать
  "preferredVersion": {                        версию v1 вместо v2alpha1
    "groupVersion": "batch/v1",    
    "version": "v1"
  },
  "serverAddressByClientCIDRs": null
}

  В ответе показано описание группы API batch, включая доступные версии и
предпочтительную версию, которую должны использовать клиенты. Давайте
продолжим и посмотрим, что стоит за путем /apis/batch/v1. Это показано в
следующем ниже листинге.

   Листинг 8.9. Типы ресурсов в batch/vl: http://localhost:8001/apis/batch/v1

$ curl http://localhost:8001/apis/batch/v1
{                                                         Это список ресурсов API
  "kind": "APIResourceList",             в группе API batch/v1
  "apiVersion": "v1",           
  "groupVersion": "batch/v1",               Вот массив, содержащий все
  "resources": [                  типы ресурсов в этой группе
