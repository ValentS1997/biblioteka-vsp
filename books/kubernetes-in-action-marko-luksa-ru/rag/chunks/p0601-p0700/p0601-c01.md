  При запуске этого модуля вы вскоре увидите, что статус модуля будет пока-
зан как CrashLoopBackOff. Если вы затем выполните команду kubectl describe,
то сможете увидеть, почему контейнер умер, без необходимости копаться в
его журналах, как показано в следующем ниже листинге.

   Листинг 17.9. Просмотр сообщения о терминации контейнера с помощью команды
   kubectl describe

$ kubectl describe po

...
Containers:
...
    State:      Waiting

    Last State: Terminated                    не проверяя его журналы
      Reason:   Error
      Message:  I've had enough    
      Exit Code:           1
      Started:             Tue, 21 Feb 2017 21:38:31 +0100
      Finished:            Tue, 21 Feb 2017 21:38:31 +0100
      Ready:               False
      Restart Count:       6

  Как видите, сообщение «I’ve had enough» (С меня хватит), которое процесс
написал в файл /var/termination-reason, показано в секции Last State кон-
тейнера. Обратите внимание, что этот механизм не ограничивается только
аварийно прекращающими работу контейнерами. Его также можно исполь-
зовать в модулях, которые запускают завершенную задачу и прекращают ее
работу успешно (вы найдете соответствующий пример в файле termination-
message-success.yaml).

вывода специфичных для приложений сообщений о статусе не только терми-
