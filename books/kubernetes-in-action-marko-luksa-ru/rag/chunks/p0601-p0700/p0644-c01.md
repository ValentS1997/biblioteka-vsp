A.2 Использование инструмента kubectl со множеством кластеров или пространств имен    643

  Следующая ниже команда используется для создания нового контекста,
связывающего кластер и созданного пользователя:

$ kubectl config set-context some-context --cluster=my-other-cluster
     --user=foo --namespace=bar➥
  Она создает контекст под названием some-context, который применяет
кластер my-other-cluster и учетные данные пользователя foo. Пространство
имен, которое будет использоваться по умолчанию, в этом контексте имеет
значение bar.
  К примеру, вы также можете использовать ту же команду для изменения
пространства имен текущего контекста. Имя текущего контекста можно по-
лучить следующим образом:

$ kubectl config current-context
minikube

  Затем можно изменить пространство имен:

$ kubectl config set-context minikube --namespace=another-namespace

  Выполнение этой простой команды один раз намного удобнее, по сравне-
нию с включением параметра --namespace при каждом выполнении kubectl.

    СОВЕТ. Для того чтобы легко переключаться между пространствами имен, опре-
     делите такой псевдоним: aalias kcd='kubectl config set-context $(ku-
    bectl config current-context) --namespace', после чего можно переклю-
     чаться между пространствами имен с помощью kcd somenamespace.

  A.2.4 Использование инструмента kubectl с разными
  кластерами, пользователями и контекстами
  При выполнении команд kubectl используются кластер, пользователь и
пространство имен, определенные в текущем контексте файла kubeconfig, но
их можно переопределить с помощью следующих далее параметров команд-
ной строки:
  --user для использования другого пользователя из файла kubeconfig;
  --username и --password для использования другого имени пользовате-
     ля и/или пароля (их не нужно указывать в конфигурационном файле).
    При использовании других типов аутентификации можно использовать
     --client-key и --client-certificate или –token;
  --cluster для использования другого кластера (должен быть определен
     в файле конфигурации);
  --server для указания URL-адреса другого сервера (которого нет в кон-
     фигурационном файле);
  --namespace для использования другого пространства имен.
