18.1 Определение своих собственных объектов API    613

   Листинг 18.2. Манифест определения ресурса CustomResourceDefinition:
   website-crd.yaml
apiVersion: apiextensions.k8s.io/v1beta1          Полное имя вашего
                            собственного объектаkind: CustomResourceDefinition
metadata:                                                        Определения CustomResourceDefinition
  name: websites.extensions.example.com     принадлежат этой группе API и версии
spec:
  scope: Namespaced               Вы хотите, чтобы ресурсы Website
  group: extensions.example.com               имели пространство имен
  version: v1                                                               Определить группу API
  names:                                       и версию ресурса Website
    kind: Website
    singular: website                  Необходимо указать разные формы
                     имени своего собственного объекта    plural: websites
  После отправки дескриптора в систему Kubernetes она позволит создавать
любое количество экземпляров пользовательского ресурса Website.
  Объект CRD можно создать из файла website-crd.yaml, который имеется в
архиве кода:

$ kubectl create -f website-crd-definition.yaml
customresourcedefinition "websites.extensions.example.com" created

  Уверен, что вы задаетесь вопросом о длинном имени CRD. Почему бы не на-
звать его Website? Причина простая – чтобы предотвратить конфликты имен.
Добавляя суффикс к имени CRD (который обычно включает имя организации,
создавшей CRD), вы сохраняете уникальные имена объектов CRD. К счастью,
длинное имя означает, что вам придется создавать ресурсы вашего сайта не
как kind: websites.extensions.example.com, а как kind: Website. Это указано
в свойстве names.kind ресурса CRD. Фрагмент extensions.example.com являет-
ся группой API вашего ресурса.
  Вы видели, как создание объектов Deployment требует выставления вер-
сии apiVersion в apps/v1beta1 вместо v1. Фрагмент перед косой чертой – это
группа API (развертывания принадлежат группе API apps), а фрагмент после
нее – имя версии (в случае развертываний v1beta1). При создании экземпля-
ров своего собственного ресурса Website необходимо для свойства apiVersion
задать значение extensions.example.com/v1.

  Создание экземпляра пользовательского ресурса
  Учитывая то, что вы уже знаете, теперь вы создадите правильный YAML для
вашего экземпляра ресурса Website. Соответствующий манифест YAML пока-
зан в следующем ниже листинге.

   Листинг 18.3. Свой собственный ресурс Website: kubia-website.yaml
apiVersion: extensions.example.com/v1    Ваша собственная группа и версия API
