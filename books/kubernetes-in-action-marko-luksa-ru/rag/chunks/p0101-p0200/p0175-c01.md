полезной нагрузке, которую они несут. Поскольку файлы cookie являются кон-
струкцией протокола HTTP, службы о них не знают, что и объясняет, почему
сохранение сессий не может быть основано на файлах cookie.

  Обеспечение доступа к нескольким портам в одной и той же службе
  Ваша служба обеспечивает доступ только к одному порту, однако службы
также могут поддерживать несколько портов. Например, если ваши модули
прослушивали два порта – скажем, 8080 для HTTP и 8443 для HTTPS, – вы мо-
жете использовать одну службу для перенаправления портов 80 и 443 на пор-
ты 8080 и 8443 модуля. В таких случаях не требуется создавать две разные
службы. Использование единой мультипортовой службы позволяет обеспечи-
вать доступ ко всем портам службы через единый кластерный IP-адрес.

    ПРИМЕЧАНИЕ. Во время создания службы с несколькими портами вы должны
     для каждого порта указать имя.

  Свойство spec ресурса многопортовой службы показано в следующем ниже
листинге.

   Листинг 5.3. Указание нескольких портов в определении службы

apiVersion: v1
kind: Service
metadata:
  name: kubia
spec:
  ports:
                                   Порт 80 увязан с портом 8080  – name: http
                                  модуля    port: 80       
    targetPort: 8080
  – name: https                   Порт 443 увязан с портом
    port: 443          8443 модуля
    targetPort: 8443
  selector:                Селектор меток всегда применяется
    app: kubia                 ко всей службе в целом

    ПРИМЕЧАНИЕ. Селектор меток применяется ко всей службе в целом – он не
    может быть настроен для каждого порта индивидуально. Если вы хотите, чтобы
     разные порты увязывались с разными подмножествами модулей, необходимо со-
     здать две службы.

  Поскольку ваши модули kubia не прослушивают на нескольких портах,
создание мультипортовой службы и мультипортового модуля оставлено для
вас в качестве упражнения.
