  4.2.3 Просмотр контроллера репликации в действии
  Поскольку нет ни одного модуля с меткой app=kubia, контроллер реплика-
ции должен развернуть три новых модуля из шаблона модуля. Выведем список
модулей, чтобы увидеть, сделал ли контроллер репликации то, что он должен:

$ kubectl get pods
NAME         READY  STATUS             RESTARTS  AGE
kubia-53thy  0/1    ContainerCreating  0         2s
kubia-k0xz6  0/1    ContainerCreating  0         2s
kubia-q3vkg  0/1    ContainerCreating  0         2s

 И действительно! Требовалось три модуля, и он создал три модуля. Теперь
он управляет этими тремя модулями. Давайте теперь немного с ними пора-
ботаем, чтобы увидеть, как контроллер репликации отвечает на эти дейст
вия.

  Реакция контроллера репликации на удаление модуля
  Сначала вы удалите один из модулей вручную, чтобы увидеть, как контрол-
лер репликации немедленно запускает новый, в результате чего количество
соответствующих модулей вернется к трем:

$ kubectl delete pod kubia-53thy
pod "kubia-53thy" deleted
