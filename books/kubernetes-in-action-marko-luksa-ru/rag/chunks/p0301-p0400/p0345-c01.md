344     Глава 9. Развертывания: декларативное обновление приложений

  Для того чтобы изменить образ и сразу внести проверку готовности, ис-
пользуйте команду kubectl apply. Как показано в следующем ниже листин-
ге, для обновления развертывания вы будете использовать следующий ниже
YAML (вы будете хранить его как kubia-deployment-v3-with-readinesscheck.
yaml).

   Листинг 9.11. Развертывание с помощью проверки готовности:
   kubia-deployment-v3-withreadinesscheck.yaml

apiVersion: apps/v1beta1
kind: Deployment
metadata:
  name: kubia
spec:
  replicas: 3                   Вы задаете minReadySeconds
  minReadySeconds: 10      равным 10
  strategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0      Вы задаете maxUnavailable равным 0,
    type: RollingUpdate            чтобы развертывание заменяло модули
  template:                          один за другим
    metadata:
      name: kubia
      labels:
        app: kubia
    spec:
      containers:                    Вы определяете проверку
      – image: luksa/kubia:v3           готовности, которая будет
      name: nodejs                        выполняться каждую секунду
      readinessProbe:
        periodSeconds: 1     
        httpGet:               Проверка готовности выполнит запрос
          path: /                 HTTP GET к нашему контейнеру
          port: 8080

  Обновление развертывания с помощью команды kubectl apply
  Чтобы обновить развертывание, на этот раз вы воспользуетесь командой
kubectl apply следующим образом:
$ kubectl apply -f kubia-deployment-v3-with-readinesscheck.yaml
deployment "kubia" configured
  Команда apply обновляет развертывание всем тем, что определено в файле
YAML. Она не только обновляет образ, но и добавляет определение проверки
готовности и все остальное, что вы добавили или изменили в YAML. Если но-
вый YAML также содержит поле replicas, которое не соответствует количест
