366     Глава 10. Ресурсы StatefulSet: развертывание реплицируемых приложений...

$ kubectl get po
NAME     READY  STATUS             RESTARTS  AGE
kubia-0  1/1    Running            0         8s
kubia-1  0/1    ContainerCreating  0         2s

  Видите, первый модуль запущен, а второй создан и только запускается.

  Исследование сгенерированного модуля с внутренним состоянием
  Давайте более подробно рассмотрим спецификацию первого модуля в сле-
дующем ниже листинге, чтобы увидеть, как объект StatefulSet сконструировал
модуль из шаблона модуля и шаблона заявки PersistentVolumeClaim.

   Листинг 10.6. Модуль с внутренним состоянием, созданный объектом StatefulSet

$ kubectl get po kubia-0 -o yaml
apiVersion: v1
kind: Pod
metadata:
  ...
spec:
  containers:
  – image: luksa/kubia-pet
    ...                                         Монтирование тома, как
    volumeMounts:                       указано в манифесте
    – mountPath: /var/data
                 
      name: data
    – mountPath: /var/run/secrets/kubernetes.io/serviceaccount
      name: default-token-r2m41
      readOnly: true
  ...
                                                Том, созданный  volumes:                                              объектом StatefulSet
  – name: data           
    persistentVolumeClaim:
      claimName: data-kubia-0        Заявка, на которую
  – name: default-token-r2m41              ссылается этот том
    secret:
      secretName: default-token-r2m41

  Шаблон заявки PersistentVolumeClaim использовался для создания заявки
PersistentVolumeClaim и тома внутри модуля, который ссылается на создан-
ную заявку PersistentVolumeClaim.
