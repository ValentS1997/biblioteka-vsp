332     Глава 9. Развертывания: декларативное обновление приложений

       Способы изменения развертываний и других ресурсов
     В ходе этой книги вы узнали несколько способов изменения существующего
       объекта. Давайте перечислим их все вместе, чтобы освежить вашу память.

      Таблица 9.1. Модификация существующего ресурса в Kubernetes
     Метод             Что он делает
      kubectl edit       Открывает манифест объекта в редакторе, заданном по
                        умолчанию. После внесения изменений, сохранения
                       файла и выхода из редактора объект обновляется.
                       Пример: kubectl edit deployment kubia
      kubectl patch      Модифицирует отдельные свойства объекта.
                        Пример: kubectl  patch  deployment  kubia  -p
                       '{"spec":{"template": {"spec": {"containers":
                       [{"name": "nodejs", "image": "luksa/kubia:v2"
                       }]}}}}'
      kubectl apply      Модифицирует объект, применяя значения свойств
                         из полного файла YAML или JSON. Если  объект,
                        указанный в YAML/JSON, еще не существует, он будет
                           создан. Файл должен содержать полное определение
                         ресурса (он не может включать только поля, которые
                     вы хотите обновить, как в случае с kubectl patch).
                       Пример: kubectl  apply  -f  kubia-deployment
                       -v2.yaml
      kubectl replace    Заменяет объект на новый объект из файла YAML/
                          JSON. В отличие от команды apply, эта команда
                          требует существования объекта; в противном случае
                        выводится сообщение об ошибке.
                       Пример: kubectl replace -f kubia-deployment
                       -v2.yaml
      kubectl set image  Меняет образ контейнера, определенный в модуле,
                      шаблоне контроллера репликации, развертывании,
                       наборе демонов, задании или наборе реплик.
                       Пример: kubectl set image deployment kubia
                       nodejs=luksa/kubia:v2

      Что касается развертывания, все эти методы эквивалентны. Они изменяют специ
     фикацию развертывания. Это изменение затем инициирует процесс раскрутки.
