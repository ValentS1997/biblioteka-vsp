9.2 Выполнение автоматического плавного обновления с помощью контроллера...    321

---            Файлы YAML могут содержать несколько          Служба поддерживает
apiVersion: v1            определений ресурсов, разделенных               все модули, созданные
kind: Service              строкой с тремя дефисами                      контроллером репликации
metadata:
  name: kubia
spec:
  type: LoadBalancer
  selector:                         
    app: kubia
  ports:
  – port: 80
    targetPort: 8080

  YAML задает контроллер репликации под названием kubia-v1 и службу под
названием kubia. Продолжайте и отправьте YAML в Kubernetes. Через неко-
торое время все три модуля v1 и подсистема балансировки нагрузки должны
быть запущены, и вы сможете найти внешний IP-адрес службы и начать по-
падать в службу с помощью утилиты curl, как показано в следующем ниже
листинге.

  Листинг 9.3. Получение внешнего IP-адреса службы и попадание в службу в цикле
   с помощью утилиты curl

$ kubectl get svc kubia
NAME CLUSTER-IP EXTERNAL-IP PORT(S) AGE
kubia 10.3.246.195 130.211.109.222 80:32143/TCP 5m
$ while true; do curl http://130.211.109.222; done
This is v1 running in pod kubia-v1-qr192
This is v1 running in pod kubia-v1-kbtsk
This is v1 running in pod kubia-v1-qr192
This is v1 running in pod kubia-v1-2321o
...

   ПРИМЕЧАНИЕ. Всли вы используете Minikube или любой другой кластер
     Kubernetes, где службы балансировки нагрузки не поддерживаются, то для до-
     ступа к приложению вы можете применить порт узла службы. Это разъясняется в
     главе 5.

  9.2.2 Выполнение плавного обновления с помощью kubectl
  Далее вы создадите версию 2 приложения. Чтобы все оставалось простым,
вам нужно лишь изменить отклик, который будет сообщать: «This is v2»:

response.end("This is v2 running in pod " + os.hostname() + "\n");

  Эта новая версия доступна в образе luksa/kubia: v2 в Docker Hub, поэтому
вам не нужно создавать ее самостоятельно.
