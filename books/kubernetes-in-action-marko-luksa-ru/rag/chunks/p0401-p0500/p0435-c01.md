Субъект (который может быть человеком, учетной записью ServiceAccount или
группой пользователей или учетных записей ServiceAccounts) связан с одной
или несколькими ролями, и каждой роли разрешено выполнять определен-
ные команды на определенных ресурсах.
  Если пользователь имеет несколько ролей, то он может делать все, что ему
позволяет любая из ролей. Если ни одна из ролей пользователя не содержит
разрешения, например на обновление секретов, сервер API не позволит поль-
зователю выполнять запросы PUT или PATCH на секретах.
  Управлять авторизацией посредством плагина RBAC очень просто. Все де-
лается путем создания четырех специфичных для RBAC ресурсов Kubernetes,
которые мы рассмотрим далее.
