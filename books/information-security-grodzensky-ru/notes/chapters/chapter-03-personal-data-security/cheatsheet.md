# Шпаргалка: защита персональных данных

Цель: пройти от факта обработки персональных данных к обоснованным мерам защиты по логике главы 3.

## Symptom / problem framing

Проблема возникает, когда организация:

- не понимает, какие процессы являются обработкой персональных данных;
- не определила себя как оператора;
- не классифицировала актуальные угрозы;
- не определила уровень защищённости;
- внедряет средства защиты без связи с нормативными требованиями и моделью угроз.

## Baseline / context

### Персональные данные

По источнику: информация, относящаяся к прямо или косвенно определённому или определяемому физическому лицу.

### Обработка

Включает:

- сбор;
- запись;
- систематизацию;
- накопление;
- хранение;
- уточнение;
- извлечение;
- использование;
- передачу;
- обезличивание;
- блокирование;
- удаление;
- уничтожение.

### Ключевая последовательность

```text
processing context
      ↓
threat type
      ↓
personal-data category
      ↓
record count
      ↓
protection level
      ↓
Order No. 21 controls
      ↓
effectiveness assessment
```

## Read-only checks

Глава не содержит CLI-проверок. Поддерживаемые источником проверки:

1. Зафиксировать, какие персональные данные обрабатываются.
2. Зафиксировать все операции с ними.
3. Определить, кто является оператором.
4. Установить, где происходит обработка: внутри периметра, удалённо, на мобильных устройствах.
5. Определить актуальные типы угроз.
6. Определить категорию персональных данных.
7. Определить объём обработки: более или менее 100 000 записей.
8. Определить уровень защищённости.
9. Сопоставить уровень с мерами Приказа ФСТЭК № 21.
10. Проверить соответствие внедрённых мер модели угроз.

## Interpretation

### Если данные передаются через незащищённое интернет-соединение

Источник рекомендует VPN-подключение к корпоративным ресурсам; при риске компрометации по открытым каналам также упоминается применение СКЗИ.

### Если обработка идёт на мобильных устройствах

Рассматривать EMM-решения для управления и защиты мобильных устройств.

### Если неизвестен набор мер

Сначала определяется уровень защищённости по Постановлению № 1119, затем меры выбираются по Приказу ФСТЭК № 21.

### Если есть формальные меры, но нет модели угроз

Нужно проверить, действительно ли внедрённые меры соответствуют актуальным источникам угроз, уязвимостям, способам реализации и объектам воздействия.

## Next action

1. Инвентаризировать процессы обработки.
2. Определить угрозы и уровень защищённости.
3. Сформировать модель угроз.
4. Определить обязательный набор мер.
5. Проверить организационные документы.
6. Внедрить требуемые технические меры.
7. Провести оценку эффективности.
8. Устранить выявленные несоответствия.

## Modifying action

Примеры изменений из главы:

- внедрение VPN для защищённого удалённого доступа;
- внедрение EMM на мобильных устройствах;
- применение СКЗИ при защите передачи данных;
- внедрение сертифицированных СЗИ;
- настройка идентификации и аутентификации;
- настройка управления доступом;
- внедрение регистрации событий безопасности;
- антивирусная защита;
- обнаружение/предотвращение вторжений;
- управление конфигурацией;
- разработка организационно-технической документации.

Перед изменениями должны быть определены применимые требования и модель угроз.

## Verification / acceptance checks

По главе проверка включает:

- оценку эффективности внедрённых мер;
- проверку соответствия требованиям выбранного уровня защищённости;
- соответствие мер актуальной модели угроз;
- наличие отчёта о выявленных недостатках и мер по их устранению;
- наличие организационно-технической документации.

Конкретные технические acceptance-команды: `[Not applicable]`.
