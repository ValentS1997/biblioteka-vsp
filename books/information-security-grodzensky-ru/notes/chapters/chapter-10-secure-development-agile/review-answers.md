# Ответы на вопросы для самопроверки — глава 10

Ответы основаны только на RAG главы 10.

## 1. Чем отличается статический анализатор кода от динамического?

SAST анализирует исходный код без исполнения программы.

DAST анализирует приложение во время его выполнения. В главе приведены примеры, показывающие, что часть runtime-ошибок проще обнаруживается динамически, тогда как некоторые структурные ошибки кода лучше видны статическому анализатору.

Источник делает вывод о целесообразности совместного применения обоих подходов.

Provenance: `p0069:c01`, `p0070:c01`, `p0071:c01`.

## 2. На что необходимо обращать внимание при выборе анализатора кода?

Для статического анализатора глава предлагает учитывать:
- количество поддерживаемых языков программирования;
- скорость работы;
- интеграцию с системами управления версиями;
- возможность визуализации графов выполнения анализируемого кода.

Также в предыдущем тексте главы обсуждается важность false positive и false negative.

Provenance: `p0069:c01`, `p0071:c01`.

## 3. Для чего нужны средства разработчика, встроенные в браузер?

В контексте главы они используются для анализа клиентской части web application:
- просмотра source;
- изучения ресурсов, загруженных через iframe/script и другие элементы;
- анализа HTML/JavaScript;
- проверки того, что web-site сохраняет на стороне пользователя;
- анализа client-side application state.

Provenance: `p0072:c01`.

## 4. Приведите примеры ошибок при написании кода ПО.

Источник перечисляет:
- переполнение буфера;
- утечки памяти;
- переполнение стека;
- использование неинициализированной переменной;
- нарушение прав доступа;
- синтаксические ошибки;
- базовые ошибки в написании алгоритма.

Provenance: `p0068:c01`.
