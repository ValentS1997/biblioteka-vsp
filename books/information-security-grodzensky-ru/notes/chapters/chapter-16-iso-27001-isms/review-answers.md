# Ответы на вопросы для самопроверки — глава 16

Ответы основаны только на RAG главы 16.

## 1. В чем суть цикла Шухарта-Деминга?

PDCA — повторяющийся цикл управления и непрерывного улучшения:

- Plan — проектирование СУИБ: контекст, область, процессы, цели, ресурсы, оценка рисков;
- Do — внедрение и эксплуатация процессов и защитных мер;
- Check — мониторинг, измерение, внутренний аудит и анализ СУИБ руководством;
- Act — корректирующие действия и совершенствование СУИБ.

Источник связывает этот цикл с постоянным повышением зрелости СУИБ и адаптацией к меняющемуся ландшафту угроз.

Provenance: `p0103:c01`, `p0104:c01`.

## 2. Что такое СУИБ?

По тексту главы со ссылкой на ISO 27000, СУИБ — система управления информационной безопасностью, являющаяся частью общей системы менеджмента организации и основанная на оценке бизнес-рисков в цикле создания, внедрения, поддержания и улучшения ИБ.

СУИБ должна:
- учитывать ожидания заинтересованных сторон;
- иметь владельца с достаточными полномочиями;
- быть применимой к деятельности организации;
- быть интегрирована в бизнес.

Provenance: `p0108:c01`.

## 3. Что должен содержать документ «Политика ИБ»?

По главе Политика ИБ должна:
- соответствовать целям организации;
- включать цели ИБ, которые должны быть измеримыми;
- содержать обязательства по соблюдению применимых требований ИБ;
- содержать обязательство по постоянному улучшению СУИБ;
- быть доступной сотрудникам;
- распространяться и доводиться до заинтересованных сторон;
- быть утверждена высшим руководством;
- иметь установленный порядок/период пересмотра.

Provenance: `p0110:c01`, `p0111:c01`.

## 4. Опишите метод 8D и диаграмму Исикавы.

### 8D

Источник описывает следующие шаги:
- D0 — планирование;
- D1 — формирование команды;
- D2 — количественное описание проблемы через 5W2H;
- D3 — промежуточные containment actions;
- D4 — выявление и проверка root cause и escape points;
- D5 — выбор и проверка долговременной коррекции;
- D6 — внедрение и проверка corrective actions;
- D7 — preventive actions для недопущения повторения;
- D8 — признание/поощрение команды.

### Диаграмма Исикавы

Это cause-and-effect diagram («рыбья кость»), которая структурирует факторы и причины проблемы.

Источник предлагает:
1. точно определить проблему;
2. выделить основные влияющие факторы;
3. определить вероятные причины внутри каждого фактора;
4. проанализировать диаграмму и проверить наиболее вероятные причины.

Для первичных факторов предлагается 5M:
- material;
- machine;
- man;
- method;
- measuring.

Диаграмму рекомендуется сочетать с методом «Пять почему?».

Provenance: `p0111:c01`–`p0114:c01`.
