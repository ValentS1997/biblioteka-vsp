# Команды и инструменты — глава 04

**Provenance:** canonical RAG PDF 111–154, chunks `p0111:c01`–`p0154:c01`, source SHA-256 `fa3cfb6d7dc9af0354a5c908e606626629929ae54b646ca4eaaa11b7868eb1b9`. Примеры из книги отражают момент написания, **не проверены** на текущих версиях инструментов.

**Контекст:** выполнять сетевые команды исключительно в собственной лаборатории или на **явно разрешённых** узлах, при согласованной нагрузке. `<AUTHORIZED_HOST>`, `<AUTHORIZED_CIDR>`, `<AUTHORIZED_DOMAIN>`, `<READ_COMMUNITY>` — placeholders, не реальные цели/секреты.

## Read-only interpretation: локальный эксперимент / чтение ответа

| Команда или конструкция в RAG | Класс | Эффект/проверка | RAG |
|---|---|---|---|
| `ping <AUTHORIZED_HOST>` | Workload-generating | ICMP запросы; потери/задержка; отсутствие ответа не равно выключенному узлу | [p0112:c01](../../../rag/chunks/p0101-p0200/p0112-c01.md) |
| `nc -nvv -w 1 -z 127.0.0.1 5980-5990` | Workload-generating, loopback | TCP-попытки соединений; в примере видны `open` и `Connection refused` | [p0116:c01](../../../rag/chunks/p0101-p0200/p0116-c01.md) |
| `nc -nv -u -z -w 1 127.0.0.1 198-202` | Workload-generating, loopback | UDP, отсутствие ответа неоднозначно | [p0117:c01](../../../rag/chunks/p0101-p0200/p0117-c01.md) |
| `dig <AUTHORIZED_DOMAIN> mx +short` | Workload-generating, DNS запрос | MX записи; цифра перед MX обозначает приоритет | [p0131:c01](../../../rag/chunks/p0101-p0200/p0131-c01.md), [p0132:c01](../../../rag/chunks/p0101-p0200/p0132-c01.md) |
| `dig <AUTHORIZED_DOMAIN> txt +short` | Workload-generating, DNS запрос | TXT/SPF из DNS; может содержать сведения инфраструктуры | [p0132:c01](../../../rag/chunks/p0101-p0200/p0132-c01.md) |
| `host <AUTHORIZED_DOMAIN>` | Workload-generating, DNS запрос | Ответ DNS или `NXDOMAIN`; не перебор без ограничений | [p0133:c01](../../../rag/chunks/p0101-p0200/p0133-c01.md) |

*Термин «read-only» здесь относится к состоянию наблюдаемой системы: даже чтение запрашивает информацию по сети и может создавать логи.*

## Активная проверка разрешённого объёма

| Подтверждённая команда/флаг | Класс, назначение | Риск и критерий результата | RAG |
|---|---|---|---|
| `nmap -sn <AUTHORIZED_CIDR>` | Workload-generating: обнаружение хостов без обычного портового скана | Результат `Host is up`; отсутствие ответа неопределённо | [p0122:c01](../../../rag/chunks/p0101-p0200/p0122-c01.md) |
| `nmap -p 80,443,53 <AUTHORIZED_CIDR>` | Workload-generating: ограниченная проверка портов | `open/closed/filtered`; даже ограниченный скан вызывает сетевой трафик | [p0123:c01](../../../rag/chunks/p0101-p0200/p0123-c01.md) |
| `nmap -sT -p <AUTHORIZED_PORTS> <AUTHORIZED_HOST>` | Workload-generating: TCP connect | Может отражаться в журналах; согласовать заранее | [p0120:c01](../../../rag/chunks/p0101-p0200/p0120-c01.md) |
| `nmap -sU -p <AUTHORIZED_PORTS> <AUTHORIZED_HOST>` | Workload-generating: UDP | Часто `open|filtered`; отличать от доказанного `open` | [p0121:c01](../../../rag/chunks/p0101-p0200/p0121-c01.md) |
| `nmap -sV <AUTHORIZED_HOST>` | Workload-generating: определение версии сервиса | Баннер может быть изменён; приложение потенциально реагирует на probe | [p0127:c01](../../../rag/chunks/p0101-p0200/p0127-c01.md) |
| `nmap -O <AUTHORIZED_HOST>` | Workload-generating: OS fingerprint | Низкая определённость при фильтрах и изменениях стека | [p0125:c01](../../../rag/chunks/p0101-p0200/p0125-c01.md), [p0126:c01](../../../rag/chunks/p0101-p0200/p0126-c01.md) |
| `nmap -p 80 --script http-title <AUTHORIZED_CIDR>` | Workload-generating: NSE, заголовки сайтов | Отправляет HTTP-запросы; не равнозначно exploit | [p0128:c01](../../../rag/chunks/p0101-p0200/p0128-c01.md) |
| `nmap -v -p 139,445 <AUTHORIZED_CIDR>` | Workload-generating: поиск SMB/NetBIOS | Только явно разрешённые узлы; не перечислять учетные записи автоматически | [p0140:c01](../../../rag/chunks/p0101-p0200/p0140-c01.md) |

## Подтверждённые дополнительные инструменты

**Nmap:** `--top-ports` сокращает объём, `-sS` — TCP SYN, `-A` включает дополнительные проверки, `-Pn` пропускает стадию обнаружения хоста, `-oN`/`-oX`/`-oG` сохраняют отчёт, `-T` управляет скоростью. Некоторые варианты меняют требуемые привилегии и нагрузку. [p0120:c01](../../../rag/chunks/p0101-p0200/p0120-c01.md), [p0122:c01](../../../rag/chunks/p0101-p0200/p0122-c01.md), [p0124:c01](../../../rag/chunks/p0101-p0200/p0124-c01.md), [p0128:c01](../../../rag/chunks/p0101-p0200/p0128-c01.md).

**DNS:** `dig`, `host`, `dnsrecon`, `dnsenum`; типы записей A, AAAA, CNAME, MX, NS, PTR, SOA, SRV, TXT, CAA. Методики перебора словарей и AXFR являются активными проверками, способными раскрывать инфраструктуру; здесь не приводится готовая команда массового перечисления чужих зон. [p0130:c01](../../../rag/chunks/p0101-p0200/p0130-c01.md)–[p0139:c01](../../../rag/chunks/p0101-p0200/p0139-c01.md).

**SMB/NetBIOS:** `nbtscan`, `nbtstat`, `net view`, `enum4linux`; источник описывает общие ресурсы, пользователей, группы и анонимные сеансы. Получение идентификаторов людей и проверка null-session требуют отдельного scope; не включать реальные списки пользователей в публикуемые результаты. [p0139:c01](../../../rag/chunks/p0101-p0200/p0139-c01.md)–[p0145:c01](../../../rag/chunks/p0101-p0200/p0145-c01.md).

**NFS:** `rpcinfo` (NSE), `nfs-showmount`; исследование экспортов и особенно монтирование/изменение локального UID — действия повышенного риска, не одобрены для автоматического повторения. В RAG команда NSE `map -sV ...` конфликтует с контекстом `nmap`; см. findings. [p0146:c01](../../../rag/chunks/p0101-p0200/p0146-c01.md)–[p0148:c01](../../../rag/chunks/p0101-p0200/p0148-c01.md).

**SMTP:** `VRFY`, `EXPN`, `RCPT TO` и `smtp-user-enum` — методы перечисления имён/ящиков, а не нейтральная проверка связи; результаты могут быть персональными данными. [p0148:c01](../../../rag/chunks/p0101-p0200/p0148-c01.md)–[p0150:c01](../../../rag/chunks/p0101-p0200/p0150-c01.md).

**NTP:** NSE `ntp-monlist` — получение сведений о клиентах NTP при соответствующей конфигурации; в современных реализациях, согласно автору, часто недоступно. [p0151:c01](../../../rag/chunks/p0101-p0200/p0151-c01.md).

## Local state-changing actions

- `nmap -sn <AUTHORIZED_CIDR> -oG results.txt`: кроме сетевых запросов **создаёт локальный файл отчёта**; проверить его содержимое и доступ, при очистке учитывать требования фиксации доказательств. [p0122:c01](../../../rag/chunks/p0101-p0200/p0122-c01.md), [p0123:c01](../../../rag/chunks/p0101-p0200/p0123-c01.md).
- Словарь имён DNS и локальные скрипты из главы меняют состояние рабочей среды и могут порождать **массовые запросы**. Пример пользовательского перечня `dns-names.txt` описан на [p0134:c01](../../../rag/chunks/p0101-p0200/p0134-c01.md); готовые циклы для чужих доменов не предлагаются.
- `mount`, `adduser` и изменение `/etc/passwd` в примере NFS — **state-changing**, затрагивают системную конфигурацию/контроль доступа. **Не запускать из конспекта.** В источнике нет безопасного rollback; [p0147:c01](../../../rag/chunks/p0101-p0200/p0147-c01.md), [p0148:c01](../../../rag/chunks/p0101-p0200/p0148-c01.md).
- Настройка **SNMP read/write** способна менять состояние сетевого оборудования; в этой главе воспроизводятся только чтения из MIB. [p0151:c01](../../../rag/chunks/p0101-p0200/p0151-c01.md), [p0152:c01](../../../rag/chunks/p0101-p0200/p0152-c01.md).
