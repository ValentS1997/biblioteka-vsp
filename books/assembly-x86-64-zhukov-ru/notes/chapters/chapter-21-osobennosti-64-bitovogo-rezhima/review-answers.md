# Глава 21 — разборы контрольных вопросов по RAG

**Источник:** [review-questions.md](review-questions.md), canonical RAG PDF 341–372. **Не** официальный ключ издателя и **не** результаты собственных запусков Bochs, NASM или физического ПК. Обозначения Q1–Q16 — навигационные.

**Q1 (341–344).** Добавлены R8–R15 и их части D/W/B. По 21.1 запись в `EDX` очищает старшие 32 бита `RDX`, тогда как запись `DX` сохраняет старшие. Новый байт `SIL` допустим в 64-bit. Комбинации старых high-byte регистров AH/CH и расширенных регистров требуют особого кодирования; 21.1 помещает недопустимые формы под `%if 0`.

**Q2 (343–345).** `JECXZ` проверяет ECX, `JRCXZ` — RCX; `LOOP` использует счётчик, выбранный адресной размерностью, `a32` переключает его на ECX в показанном 64-битном коде. `rel` — знаковое 32-битное смещение от текущего RIP, `abs` — адрес относительно начала памяти, закреплённый при сборке. 21.2 сравнивает реальные байты: `mov edx,[rel mem]` и `mov eax,[abs mem]`.

**Q3 (342–345).** В блоке ошибок примеры `mov ah,sil`, `mov r8b,ah`, `r0`, программно недоступного `rip`, `jcxz`, `into`, `bound`; NASM останавливается на недопустимой форме. Для сборки двух половин 64-битного числа автор сначала сдвигает 64-битное значение, затем комбинирует с отдельно подготовленным 32-битным операндом (`mov eax` после сдвига разрушил бы старшую половину) (p. 343–344).

**Q4 (345–348).** 21.3 размещает код относительно `start64` (выровнен на 0x200) и загрузчик помещает его по линейному 0x300. 21.4 копирует блок на +0x100, то есть к 0x400. При перекрытии копирование назад сохраняет ещё не прочитанный источник. При `default rel` `vendor` и `str8` находят после переноса; при `default abs` ссылки остаются на прежний код/данные, что видно по рис. 21.1 и 21.2.

**Q5 (347–348).** Автор предлагает `reloc_ofs=1` либо 300 и ожидает корректный перенос из-за порядка копирования; слишком большой сдвиг опасен, так как промежуток между областями полностью перезаписывается 0x55 (прим. 12). Без `default rel` перемещённый код адресует старые ячейки, а новая строка не получает требуемые данные.

**Q6 (349–351).** В 64-битовом режиме обычные сегменты имеют нулевую базу, но FS/GS могут иметь ненулевую. 21.5 программирует адрес видеообласти для выбранного FS/GS через дескриптор до перехода в 64-bit. Предел сегмента, по изложению автора, в 64-битовом режиме не контролирует доступ как в protected/compatibility; эксперимент с изменением limit является наблюдением его конкретной установки.

**Q7 (351–352).** MSR с номерами 0xC0000100/101 используются для FS/GS base, а `RDMSR/WRMSR` требуют CPL=0. Альтернативный набор `RDFSBASE/WRFSBASE` зависит от соответствующего бита CR4. Для приведённого CPU в Bochs попытка включить поддержку заканчивается `check_CR4 ... not supported`. Это **ограничение эмулятора**, а не доказательство отсутствия функции в других средах.

**Q8 (352–355).** `STAR` хранит селекторы входа/выхода, связанные селекторы SS выводятся из соседних дескрипторов; `CSTAR` содержит точку входа из compatibility, `LSTAR` — из 64-bit. `SFMASK` определяет сбрасываемые при входе флаги, `EFER.SCE` включает механизм. `SYSCALL` сохраняет продолжение в RCX и FLAGS в R11, поэтому ISR-система не использует для возврата обычный стековый адрес; сама служебная процедура может пользоваться стеком и сохранять эти регистры.

**Q9 (354–356).** После `SYSRET` авторский пример оказывается при CPL=3; следующий `WRMSR` из тела пользовательского кода не разрешён. В 21.8 вход выбирается через LSTAR (64-bit caller), а `o64 sysret` возвращает в 64-bit вместо compatibility, которое использует форма из 21.7. Отдельно автор признаёт недостаток модели DPL/CPL в 21.7.
