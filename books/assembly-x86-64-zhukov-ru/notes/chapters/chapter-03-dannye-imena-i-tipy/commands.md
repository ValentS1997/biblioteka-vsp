# Команды, операторы и инструменты — глава 3

**RAG-only:** `p0031:c01`–`p0055:c01`, PDF 31–55. Это синтаксис `a86` и учебные сеансы `Bochs-FreeDOS/d86` из книги, а не общие команды Linux.

## Непосредственные вызовы

| Команда / ввод | Класс | Результат и источник |
|---|---|---|
| `a86 exa1.8` | **State-changing** | Генерирует `exa1.com` и `exa1.sym`; data-only COM нельзя запускать (p. 32). |
| `a86 exa1.8 +L` | **State-changing** | Формирует листинг `.lst` с адресами, байтами и именами; `+L` можно задавать после `a86` (p. 32–33). |
| `+L +H5` или `+LH5` при трансляции | **State-changing configuration** | Увеличивает число строк кодов в листинге (p. 36). |
| `d86 exa2.com` | **Workload-generating / наблюдение** | Загружает данные с адреса `0100` для просмотра, а не выполнения data-only COM (p. 35). |
| `b4,0100`, `w4,0104`, `w8,010c` в d86 | **Read-only view configuration** | Отображают 4 байта / 4 слова / 8 слов по адресу (p. 35). |
| `b4,data0`, `w4,data1`, `w8,data2`, `r,caption` | **Read-only view configuration** | Адресация окон d86 символами, формат `r` для ASCII (p. 36). |
| `k s alta` в d86 | **State-changing** | Сохраняет клавиатурную последовательность в `alta.d8k`; `Alt+A` воспроизводит её (p. 35). |
| `k s exa10` в d86 | **State-changing** | Сохраняет настройки в `exa10.d8k`; затем при запуске одноимённого COM они воспроизводятся (p. 42). |
| `F1` в d86 | **State-changing execution** | Single-step выполняет очередную машинную инструкцию, изменяющую CPU/данные (p. 41). |
| `not area1` в d86 | **State-changing** | Инвертирует байт по адресу `area1`; `F3` повторяет команду (p. 41). |
| `dir /w *.com` | **Read-only** | Указан автором как один из способов изучить выходные COM-файлы (p. 40). |
| `q` + Enter в d86 | **Session exit** | Выход из отладчика (p. 35). |

## Язык a86: конструкции, поддержанные главой

```asm
; Листинг 3.1: обход данных, выполнение только кода
    jmp start
    ; db / dw / dd
start:
    int 020
```

```asm
; Листинги 3.2 и 3.9: данные и константы
    dw   0123
    dd   0abcd1234
    db   '?8', 3 dup 1, ?
dozen equ 12
bakers_dozen equ dozen + 1
```

```asm
; Листинг 3.11 и 3.12: размерность по типу, явная смена типа
area1 db   bit 2, 055, 7
area2 dw   2, 0aa, 7
    not    area1
    not    word ptr area1
    not    w area1
    mov    ax, area2
    mov    ax, offset area2
```

**Замечание:** второй блок сводит совместимые фрагменты из двух листингов для демонстрации семантики; это не готовая компилированная программа. Фактический запуск не выполнялся.

| Оператор | Значение в источнике |
|---|---|
| `equ`, `$`, `this` | Символьное выражение / текущее значение счётчика (p. 38, 46). |
| `dup` | Заданное на первом проходе число повторений; допускается вложенность (p. 33–34, 49–50). |
| `bit`, `low`, `high`, `by`, `shl`, `shr`, `mod`, `not` | Операции константных выражений a86, с приоритетом из табл. 3.2 (p. 38–39). |
| `offset` | Временная типизация `abs`: числовой адрес вместо типизированной переменной (p. 42–44). |
| `type` | Число байтов 1/2/4, для `abs` ноль (p. 43). |
| `extrn item:w` | Опережающее описание типа, не выделяет память (p. 42–43). |
| `>l1` | Следующее определение локального имени в a86 (p. 51). |
| `end` | Неявное имя первого байта после программы, не объявлять явно (p. 52–53). |

## Эффекты, проверки, rollback

**Трансляция:** создаёт/перезаписывает выходные файлы; проверять `.lst`, `.sym`, формат байтов и таблицу имен. Откат — повторно создать файлы из сохранённой версии исходника; точные команды [Needs confirmation].

**`not`:** изменяет адресуемую память, размер определяется типом операнда. Проверять по шагам в `d86` и по окнам данных; для контроля иметь исходный образ до эксперимента. Откат в главе не детализирован: [Needs confirmation].

**Опасные выражения:** `bit 16` (a86 v4.05) и `-4*-2` не следует трактовать по ожидаемому математическому значению без проверки `.lst`. Попытки использовать `end:` могут исключить последний оператор из COM (p. 33, 39, 52–53); отложенную ссылку `>l1` надо использовать согласно правилам p. 51.
