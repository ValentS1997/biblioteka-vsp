## Центральная идея

**Имя в a86 характеризуется числовым значением и типом.** Для переменной числовое значение — адрес данных, для метки — адрес инструкции, для `equ` — значение выражения (возможно, вместе с типом адреса). Эти атрибуты определяют размер операции, допустимость выражений и корректность повторных определений. Ассемблер сначала определяет имена и занимаемые байты, затем генерирует данные и машинные коды.

## Что важно запомнить

1. `db/dw/dd` размещают соответственно 1, 2 и 4 байта на элемент; начальный счётчик для COM — `0100` (256), то есть после PSP (p. 32–33, 46).
2. У одного битового образа есть несколько интерпретаций: `0ff` — 255 без знака либо −1 со знаком. Различаются знаковые/беззнаковые операции и диапазоны: для `db` источник указывает объединённый диапазон −128…255 (p. 34).
3. В a86 имя `area1 db ...` имеет тип `byte` и обозначает адрес, а не само значение первого байта. `not area1` инвертирует байт; тип можно переопределить **для одной команды** через `w`, `b`, `word ptr` (p. 40–42).
4. `offset area2` даёт числовое значение адреса; `mov ax, area2` загружает данные по адресу `area2`, а `mov ax, offset area2` — его адрес (p. 42–43).
5. В выражениях с переменными допустимы только сложение/вычитание; тип результата обычно берётся от **первого операнда**, кроме сложения с одной переменной (p. 43–44). `type(name)` возвращает размер переменной 1/2/4 или 0 для `abs`.
6. Первый проход должен знать размеры, поэтому количество повторов `dup` нельзя задавать значением, которое на первом проходе ещё не известно (p. 46, 49–50).
7. Повторение имени в a86 допустимо, **если числовое значение и тип не изменились**. Локальные имена вида «буква + цифры» могут быть переопределены, а `>l1` означает последующее определение (p. 50–51).
8. Имена `ax`, `mov`, `b/w/d` и другие встроенные нельзя определять самостоятельно. `end` в a86 уже означает адрес первого байта **после** программы; попытка определять `end` явно приводит к пропуску операторов и опасным переходам (p. 52–53).

## Отдельные риски и ограничения

- **Никогда не запускать data-only COM**: глава требует просматривать сгенерированные данные как данные, например через `lst`, VC или `d86` (p. 32–35).
- `not` **изменяет данные/код** по адресу. В листинге 3.12 явное `w start` может привести к изменению инструкции: это опасный демонстрационный пример, не рекомендуемая практика (p. 42–43).
- Версия `a86 v4.05` не соответствует ожидаемому результату `bit 16…31` в `dd`, значение −129 преобразует необычным образом, `-4*-2` вычисляет неожиданно (p. 33, 36, 39). Проверять действительный результат трансляции; не переносить эти эффекты на другие ассемблеры.
- **Несоответствие в источнике:** табл. 3.7 содержит «128» для размещения `Pixels`, тогда как соседнее объяснение определяет 256; подробности в [source-findings.md](source-findings.md).
