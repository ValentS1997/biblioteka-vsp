## Главная идея

FPU — стековая вычислительная машина с **восемью физическими регистрами**, отображаемыми как логический стек `st(0)…st(7)` относительно указателя **ST**, меняющегося циклически. У неё отдельные **слово состояния sw** (включая результаты сравнения и исключения), **слово управления cw** (округление, точность, маски) и особенности обмена с памятью. Переход от выражения к инструкциям производится через **постфиксную (обратную польскую) запись** и планирование максимальной глубины стека.

## Принципы, которые необходимо усвоить

**1. Стек, а не набор обычных регистров.** `fld` помещает новое значение в логическую вершину; физические данные остаются на местах, меняется ST. `fadd` без операндов свёртывает два значения: `st(1) op st(0)`, затем pop. Порядок важен для `fsub/fdiv`; варианты с `r` разворачивают его. `fstp 0` удаляет вершину; `fxch` меняет `st(0)` с выбранным регистром (p. 113–114, 126–132).

**2. Тип и размер определяют команду.** `fld 2.0` в a86 — макрокоманда загрузки **непосредственного вещественного значения**, а `fld 2` — копирование `st(2)`. `fld` работает с real, `fild` — с целыми, `fbld` — с BCD; неправильный вариант может дать неожиданное число (8.5, p. 126–128). Запись 10-байтового real `fstp`, целого 64-битного `fistp` и BCD `fbstp` выполняется с pop (p. 114, 128, 146).

**3. Данные и исключения.** FPU хранит промежуточные значения в расширенном формате 80 бит; p. 123–124 показывают поля sign (1), exp (15), sgnd (64), смещение порядка 03fff. Стандартные 32/64-битовые переменные имеют меньшую точность и диапазон; преобразования сопровождаются округлением и событиями PE/UE/OE/DE/ZE/IE. `fclex` очищает события, `finit` сбрасывает FPU (p. 119–125).

**4. Сравнение и флаги CPU.** `ftst/fcom` ставят в sw `c3/c2/c0`, последовательность `fstsw ax; sahf` переносит их в CPU `z/e/c`. `c2 → e` здесь обозначает **Unordered**, не обычную проверку чётности CPU. С `fcomi` флаги CPU устанавливаются напрямую. `fcmovb`, но не `fcmovc`, — исходный пример условия переноса для копирования (p. 117–118, 135–136).

**5. Слова управления и устойчивость вычислений.** `fstcw/fldcw` читают и записывают cw; `RC` задаёт near/down/up/chop, `PC` — точность. Для половин `3.5,-3.5,-2.5` источник описывает выбор ближайшего чётного (p. 115, 120–121). Большая разность масштабов приводит к неточному остатку (`fprem1`, p. 134–135). Для степени автор комбинирует логарифм, деление показателя на целую и дробную части, `f2xm1` и `fscale` (p. 137–140).

**6. Состояние и его восстановление.** `fstenv/fldenv` работают с окружением, `fsave/frstor` — с регистрами и окружением. По описанию `fsave` также инициализирует FPU; в учебном примере запись идёт по `[0]` в PSP, поэтому такой приём нельзя бездумно переносить в обычную программу (p. 142–143).

## Практика и неопределённости

Проверенные текстом задания: 3 выражения с эталонными числами на p. 117; отдельная задача на параллельные сопротивления (p. 116); **9 нумерованных итоговых задач** на p. 143–145. См. [review-questions.md](review-questions.md) и [review-answers.md](review-answers.md). Запуск `d86/a86` **не выполнялся**, фактические регистры не измерены.

В [source-findings.md](source-findings.md) без исправления RAG зарегистрированы противоречия: пример `2^0.5` с приписанным результатом `2^5` (p. 138); несовпадающие ограничения для `fyl2xp1` (p. 137/140); неоднозначное описание записи `sw/cw` (p. 143). Достоверность рис. 8.1 и иных изображений ограничена текстовым извлечением RAG — самостоятельный мультимодальный объект отсутствует.
