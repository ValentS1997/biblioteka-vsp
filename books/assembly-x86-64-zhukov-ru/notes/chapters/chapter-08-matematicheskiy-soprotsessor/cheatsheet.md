# Глава 8 — оперативная шпаргалка FPU

**Источник:** canonical RAG, PDF 111–148, `p0111:c01`–`p0148:c01`, только a86/d86 и FPU из книги.

## Symptom / problem framing

Результат вычисления неверен, стек FPU переполнен/пуст, `NaN` либо `Infinity`, не тот режим округления, неожиданно изменился результат сравнения или потеряна точность при переходе от 80 к 64/32 битам. Анализировать **тип входа → глубину стека → порядок операндов → sw/cw → формат выхода**.

## Baseline / context

- **Стек:** восемь `st(0)…st(7)`; ST движется по кольцу, Tags отмечает занятость/тип; `finit` инициализирует, `F10` в d86 открывает окно FPU (p. 111–113).
- **Порядок:** безоперандное `fsub/fdiv` вычисляет `st(1) op st(0)` с pop; `fsubr/fdivr` меняют порядок (p. 114, 131–132).
- **Адресация:** `fld 2.0` = встроенная макрокоманда для константы a86; `fld 2` = дублирование `st(2)`; `fld 0` дублирует вершину (p. 112, 127–128).
- **Формат:** real `dd/dq/dt` (32/64/80 бит), integer `dw/dd/dq` и BCD `dt`; для integer применять `fild/fist`, для real — `fld/fst` (p. 112–115, 125–128).
- **Управление:** `sw` — флаги сравнения/исключений; `cw` — RC/PC и маски; `fstsw ax`, `sahf`, `fstcw`, `fldcw` (p. 117–121).

## Read-only checks

1. До изменения посмотреть `st(0)…st(7)`, `Tags`, ST, режим RC/PC и события `sw`; после `finit` источник ожидает свободный стек и `round near` (p. 111, 141).
2. Проверить размер переменной и нужное семейство команд: `fild` для целого, `fld` для вещественного. В листинге 8.5 неправильная пара даёт неадекватно большое либо малое число (p. 127).
3. Оценить максимальную глубину по постфиксному выражению: `aa*bb*-π*` требует **3** регистра, не 5 (p. 116).
4. Для сравнения `ftst/fcom` проверить `c3,c2,c0`: несопоставимые 111, `>` 000, `<` 001, `=` 100; перенос в CPU `c2→e, c0→c, c3→z` (p. 117, 136).
5. Проверить события `PE/UE/OE/DE/ZE/IE`, `SF`, `C1`; события сохраняются до `fclex` или `finit` (p. 119–120).
6. Если результат читается из памяти, проверить конверсию из 80 бит к 64/32 и возможный underflow/overflow (p. 121–125).

## Interpretation

| Симптом | Интерпретация источника |
|---|---|
| `fld 2` скопировал неожиданное значение | Обозначен регистр FPU №2, не константа 2.0 (p. 112, 146). |
| `fstp 0` уменьшил логическую глубину | Удаление вершины без сохранения в другой регистр (p. 129). |
| `fcom` → `sahf` установил CPU `e` | В данном использовании это FPU Unordered, а не обычная чётность (p. 117, 136). |
| `fist i16` округлил −2.5 к −2 | Режим near, выбирается ближайшее чётное (p. 115). |
| `IE=1,SF=1,C1=1` | Переполнение стека FPU; `C1=0` — операция с пустой вершиной (p. 120). |
| `fst f32` превратил число в ноль | Источник демонстрирует потерю диапазона и `UE/PE` при конверсии (p. 122). |
| `fsincos` оставил 2 числа | `cos` на вершине, `sin` под ним (p. 137). |

## Next action

Проверять по одному шагу в `d86`, отделяя исходное состояние, эффект команды, флаги и память. Для постфиксной программы сначала посчитать глубину и выбрать типы данных, затем добавить контроль исключений и ожидаемые значения автора.

## Modifying action

- `finit` сбрасывает стек и настройки; `fclex` только очищает события; `ffree` помечает регистр свободным (p. 113, 141).
- `fld/fstp/fadd/fxch` меняют глубину, данные или порядок регистров; `fldcw` меняет RC/PC и маски исключений (p. 120–121, 126–132).
- `fstenv/fldenv/fsave/frstor` изменяют память, настройки и контекст FPU. `fsave` дополнительно сбрасывает FPU; `fstenv` меняет маскирование (p. 142–143).
- В 8.22 учебный адрес `[0]` принадлежит PSP DOS COM: не применять без изолированной копии (p. 143).

## Verification / acceptance checks

- `a=3,b=2`: `((a*a)-(b*b))*π ≈ 15.7`, максимум три занятых регистра (p. 115–116).
- `round near`: `3.5→4`, `−3.5→−4`, `−2.5→−2` (p. 115).
- `fsincos` для π/3: `cos≈0.5` в `st(0)`, `sin≈0.866` в `st(1)` (p. 137).
- `fscale` при `st(0)=5`, `st(1)=3.9` даёт `40` (p. 135).
- При `what 1.625` поле exp = `03fff`, мантисса `1.101`; для `what 0.8125` экспонента на единицу меньше (p. 123).
