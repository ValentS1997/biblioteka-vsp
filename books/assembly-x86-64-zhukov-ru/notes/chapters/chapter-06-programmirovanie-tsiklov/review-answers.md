# Глава 6 — ответы и разбор заданий на базе RAG

**Источник:** [review-questions.md](review-questions.md) и канонические чанки `p0085:c01`–`p0092:c01`. Это **аналитические объяснения по книге**, не авторский ключ ответов и не протокол реального запуска `a86/d86`.

## A. Контрольные эксперименты

**A1.** `size=$-array` — размер байтовой области; `cx` — число проходов; `si=array-1` позволяет выполнять `inc si` *до* чтения каждого элемента. `cmp b[si],x` выставляет `z`; `loopne` прекращает цикл при `z=1` или `cx=0`. Если совпадение пришлось на последний байт, оба условия могут выполниться одновременно: для выбора ветви нужен `jne miss`, то есть состояние флага (p. 85–86).

**A2.** Исходный массив содержит `x=7` последним элементом, поэтому автор ожидает остановку на `found: int 3` одновременно с `cx=0,z=1`. После замены последнего байта на другое значение ожидается ветвь `miss` и достижение `int 020`; после записи 7 в первый элемент поиск должен остановиться на `found` с ненулевым остатком `cx` (p. 86). Не заявляется о выполненной отладке: [Needs confirmation].

**A3.** В неверном `find_1b.8` после `cmp` исполняется `inc si`, изменяющая `z`; следовательно, `loopne` считывает флаг *инкремента*, а не сравнения. Автор прямо объясняет ошибку этим нарушением порядка команд (p. 86–87).

**A4.** Для массива слов число итераций `size/2` вместо `size`, начальная позиция `array-2`, шаг `add si,2`, сравнение `cmp w[si],x`; строки массива задаются `dw` (листинг 6.3, p. 87).

**A5.** `scasw` сравнивает `ax` со словом по `di` и продвигает `di`; `cld` задаёт прямое направление. В 6.4 за `scasw` следует `loopne`, а в 6.5 их функции объединены в `repne scasw`; после цикла отдельная `jne miss` по `z` подтверждает отсутствие совпадения (p. 87–88).

**A6.** Для знаковых байтов используется `cmp b[si],x`, `jg found`, `loop l1`. Семейство `loop<x>` не содержит условия `g`, поэтому ветвь вынесена отдельно (p. 88–89). Сокращённый пример 6.7 с `scasb` нельзя считать проверенным: инициализация `di/al` в видимом фрагменте недостаточна для доказательства корректности [Needs confirmation].

**A7.** `lodsb` читает очередной байт; значение **ниже 10** пропускается ветвью `jb`, значение **выше 99** — ветвью `ja`. Только оставшиеся значения увеличивают `dx`. Тесты 9,10,11 и 98,99,100 проверяют включённость обеих границ диапазона (p. 89–90).

**A8.** Массив `map` содержит 10 нулей (0–9), 90 единиц (10–99) и 156 нулей (100–255), итого **256**. В `al` попадает исходное значение байта через `lodsb`; `xlat` заменяет его на признак 0/1 из таблицы по адресу `bx+al`. Для сложения с 16-битным `dx` очищают `ah`, затем `add dx,ax` добавляет признак (p. 90–92).
