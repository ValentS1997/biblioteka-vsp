# Глава 20 — компактная оперативная шпаргалка

**Источник:** canonical RAG PDF 331–340; листинги 20.1–20.6. Только разбор источника, запусков нет.

## Локализация проблемы

Если после перехода из compatibility mode в 64-bit код исполняется неправильно, сначала выяснить: **какой CS-селектор загружен → L/D кодового дескриптора → формат far-перехода → размер стека/адреса возврата → состояние памяти и paging**. Нельзя путать включение long mode и переключение в 64-битный *кодовый сегмент*.

## Инварианты из книги

| Объект | Семантика |
|---|---|
| Обычные base/limit в 64-битовом коде | База 0, проверка лимита не выполняется; для FS/GS оговорено исключение (p.331,339). |
| Дескриптор code64 | **L=1, D=0**, селектор выбирает режим 64-битного исполнения (p.334–335). |
| Дескриптор code32 | **L=0**, возвращает в режим совместимости (p.335–336). |
| Операнды по умолчанию | **32 бита** даже при L=1; доступ к 64 битам через REX (прим. 3, p.339). |
| Call gate | **16 байт**, расширенный адрес и целевой селектор, `S=0`; `retfq` возвращает offset и selector (p.337,340). |
| Цикл LOOP в 64-битовом коде | По умолчанию **RCX** как счётчик (прим. 15, p.340). |
| 64-bit fixed point | Старшие 32 бита — целая, младшие — дробная часть (p.339). |

## Точки проверки без исполнения

**20.1/20.2:** процедура чтения проверяет `CF`, нулевой размер и заполнение всего буфера: полное заполнение не доказывает EOF. Учебный loader переносит в `0:0100`, где начинается область векторов, поэтому его фактическое применение **опасно** (p.331–333).

**20.3:** в GDT есть `code32` и `code64`; вход `long_mode` ещё исполняется в режиме совместимости, затем far `jmp` загружает code64 и `entry64`. `CPUID` (нулевая функция) записывает строку идентификатора из `EBX/EDX/ECX`; в листинге показана адресация через `r15` (p.334–335).

**20.4:** обратное переключение использует размещённую в памяти пару «64-bit offset + 16-bit selector», а не immediate far-address. Примечание 12: нулевой селектор в модификации опыта оставит 64-битную интерпретацию следующего кода (p.335–336,340).

**20.5/20.6:** вентиль содержит расширенный адрес, вложенные вызовы внутри `use64` выполняются косвенно; `retfq` снимает оба поля. `iter` начально 8 и убывает до нуля (p.337–339).

## Источниковые наблюдения и запреты

- Во фрагментах 20.3–20.6 RAG не показывает **все подготовительные строки**; нельзя утверждать, что собранный образ полностью проверен (см. [source-findings.md](source-findings.md)).
- Рисунки GDT/Page Table из Bochs описаны в тексте, но представлены неполно — [Needs confirmation].
- Изменение памяти по адресу 0:0100, маскировка IRQ, вывод в видеопамять и бесконечный цикл — неоткатываемые без отдельного снимка действия.
- Универсального rollback, теста частоты и производительности фиксированной точки по этому RAG нет. Сравнение скорости с i80x87 **не измерено**.

**Acceptance:** сопоставить L/D, selector, `retfq`, формат адреса и роль `ld0`; маркировать границы извлечённого кода, не выдавать действия за совершённые.
