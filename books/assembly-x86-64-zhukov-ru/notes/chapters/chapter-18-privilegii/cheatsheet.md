# Глава 18 — operational cheatsheet: привилегии

**Источник:** канонический RAG PDF 307–320, примеры 18.1–18.9. Работа с состоянием CPU, портами и таблицами проводилась **только как текстовый анализ**.

## Problem framing

Упала программа при смене CPL, стал недоступен DS, некорректно восстановился стек, недоступен I/O-порт либо запрещена запись на страницу. Проверять **CPL/CS → DPL и RPL селектора → старый/новый SS:ESP → TSS/SS0:ESP0 → IOPL/IOPB либо P/RW/User**.

## Baseline по RAG

- **DPL** — привилегия сегмента, **CPL** — младшие 2 бита CS, **RPL** — младшие 2 бита запрошенного селектора. 0 — самый привилегированный, 3 — пользовательский (p. 307).
- **Понижение полномочий 0→3:** подготовить кадр `SS3:ESP3, CS3:EIP3`; `retf` меняет CPL и стек (p. 307–310).
- **Таблица 18.1:** `CS=0008→0013`, `SS=0018→0023`, `ESP=0000fffe→00000100`; DS/ES после переключения обнуляются как непригодные на новом уровне (p. 310).
- **Данные:** `max(CPL,RPL) ≤ DPL`; общий flat-сегмент `DPL=3` пригоден и для кольца 0, и для 3 (p. 311).
- **Конформный код:** переход к DPL=0 не уменьшает CPL=3; нет смены стека или права на данные 0; разрешён произвольный кодовый offset (p. 311–313).
- **Call Gate:** дескриптор DPL=3 ведёт к фиксированной процедуре DPL=0, CPL понижается до 0, SS0:ESP0 загружаются из TSS через TR (p. 313–315).
- **I/O:** если `CPL≤IOPL`, проверка IOPB не нужна; иначе бит порта в IOPB=1 запрещает доступ. Противоречивые результаты на p.317 — в findings (p. 317–318).
- **Paging:** для пользовательского доступа P=1, User=1, RW=0 означает чтение без записи (p. 318–320).

## Read-only verification

| Наблюдение | Вывод из RAG |
|---|---|
| CS 0013 и ESP 0100 | `retf` достиг CPL3 с новым стеком (18.1). |
| ES остался доступен при ring3 | Сегмент DPL3 проходит `max(CPL,RPL)` (18.2). |
| Конформная подпрограмма исполняется при CPL3 | CPL не меняется и стек не переключается (18.3). |
| Call Gate исполняет код CPL0 | TSS определяет привилегированный стек (18.4). |
| При возврате DS становится 0 | Предыдущий селектор недоступен с CPL3 (18.4). |
| Пользовательская запись page 0 вызывает ошибку | RW не разрешён у тестовой страницы (18.9). |

## Safety / changing actions

Команды изменения GDT/TSS, установки IOPB/IOPL, вызовы привилегированного вентиля и любые чтения аппаратных I/O-портов **не выполнять** в работающей системе. Они могут изменить защищённое состояние и спровоцировать исключения; результаты зависят от Bochs. Предполагаемая проверка — только на отдельной восстанавливаемой VM и при согласованном стековом кадре.
