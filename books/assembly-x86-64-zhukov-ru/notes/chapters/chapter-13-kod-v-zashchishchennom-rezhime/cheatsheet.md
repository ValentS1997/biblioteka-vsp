# Глава 13 — оперативная шпаргалка: код в защищённом режиме

**Основание:** canonical RAG PDF 219–234, листинги 13.1–13.6. Это анализ процедур из книги, **не инструкция для запуска на рабочей машине**.

## Что проверять при отказе

Если переход в protected mode даёт сбой, сначала проверить **линейную базу GDT → GDTR limit/base → селектор CS → дескриптор → P/G/D/предел → дальний переход → стек**. Консоль Bochs сообщает признаки вроде `code segment not present`, `non-conforming code seg`, `RIP > limit`; их смысл зависит от изменения полей в конкретном опыте (p. 225–227).

## Инварианты

- В protected mode сегментный регистр — **селектор**, индексирующий запись GDT; дескриптор — **8 байт**, нулевой элемент зарезервирован. `CS=8` указывает на первый рабочий дескриптор кода (p. 219–221).
- `GDTR` хранит **предел GDT** и её **линейную базу**. Адрес COM-программы автор вычисляет как `CS_real*16`, затем прибавляет смещение GDT (p. 221–222).
- Непосредственно перед переходом выполняется `LGDT`, изменение `CR0.PE` и дальний `JMP` для загрузки защищённого CS и корректной 32-битной декодировки последующих команд (p. 221–223).
- Видимый селектор и его **скрытая кешированная часть** — разные вещи: дескриптор считывается при загрузке селектора, а не на каждом обращении к памяти (п. 2 примечаний, p. 232).
- В первом опыте DS не перезагружается после перехода, и его прежние скрытые поля остаются доступны. Это учебное упрощение, **не** гарантия корректной защищённой настройки данных (p. 223).

## Дескриптор кода (p. 221, 225–227)

| Поле | Смысл/эксперимент |
|---|---|
| Base | Линейная база кодового сегмента, вычисленная из размещения COM |
| Limit | Максимально доступное смещение; в поле хранится предел с поправкой −1 |
| P | Присутствие; P=0 даёт отказ `code segment not present` |
| R | Возможность чтения кода; без неё `execute only` |
| A | Флаг доступа, процессор может устанавливать его при обращении |
| G | 0: байты; 1: 4-Кбайтные страницы |
| D | 1: 32-битный код; 0: 16-битный код |
| DPL | Уровень дескриптора; начальный пример — 0 |
| CPL / RPL | Текущий уровень кода / уровень запроса селектора |

## Межсегментное управление

- `13.3: call 2*8:subr` и `retf`. В 32-битном примере в стек помещается **8 байт** (4-байтовое EIP, 4-байтовое поле CS). При стартовом SP=0100h после одного вызова `ESP=0F8h` (p. 228).
- `13.4`: `ENTER 0,0` сохраняет EBP. `[EBP+4]` — EIP, `[EBP+8]` — CS, `[EBP+12]` и `[EBP+14]` — два 16-битных параметра. Повторяющийся цикл **расходует стек**, потому что параметры остаются после `retf` (p. 229).
- `13.5`: дескриптор **call gate (S=0)** задаёт селектор и смещение цели. При его использовании поле offset в команде вызова игнорируется (p. 230).

## Режим, возврат и ограничения

В 13.6 обратный переход требует согласованного 16-битного дескриптора кода, изменения бита PE и дальнего перехода на прежний сегментный CS; значение CS снова означает **номер параграфа**, не индекс GDT (p. 231–232). Полного самостоятельного рецепта восстановления всей DOS-среды эта глава не предоставляет — **[Needs confirmation]**.

**Небезопасно:** запуск на реальном компьютере, намеренные неправильные селекторы/пределы, чтение/запись системной памяти через неверную базу, оставление внешних IRQ отключёнными, бесконечный цикл без выхода. Проверять на RAG и гипотетической изолированной VM, но в текущем анализе **ничего не исполнялось**.
