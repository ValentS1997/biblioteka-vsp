# Глава 1 — operational cheatsheet

**Источник:** `rag/chunks/p0001-p0100/p0015-c01.md`–`p0019-c01.md` (PDF p. 15–19). Книга №0017, canonical RAG (PDF p. 15–19).

## Symptom / problem framing

Нужно получить загрузочный сеанс Bochs-FreeDOS с a86/d86 и проверить отдельный графический отладчик Bochs. Возможные симптомы по главе: отсутствие `disk_c.img`, отсутствие нужных команд в FreeDOS, несовместимая опция `gui_debug` у рабочего `bochs.exe`.

## Baseline / context

Среда из главы: Windows как хост; Bochs 2.7; два исполняемых варианта `bochs.exe` и `bochsdbg.exe`; стартовый каталог с `__work.bat`, `__debug.bat`, `bochsrc`, `debug_on.txt`, `bx_enh_dbg.ini`; FreeDOS-образ `disk_c.img`. Дополнительно нужны `BIOS-bochs-latest`, `VGABIOS-lgpl-latest`. Источник p. 15–16.

## Read-only checks

1. Проверить наличие названных файлов в стартовом каталоге (способ проверки не задан в RAG; [Needs confirmation]).
2. Посмотреть в `bochsrc` путь к `disk_c.img` и настройку `display_library` (p. 15–16, 18).
3. После загрузки образа проверить приглашение `C:\>` (p. 16).
4. После наполнения образа проверить доступность `a86`, `nasm`, `bitmap` — они должны отвечать не сообщением `Bad command or filename` (p. 18).

## Interpretation

- Ошибка `could not open hard drive image file 'disk_c.img'`: образ ещё не подготовлен либо не доступен по указанному имени (p. 16).
- `Bad command or filename` при вызове инструмента: проверка его доступности не пройдена (p. 18).
- `bochs.exe` не работает с `gui_debug`: включение этой отладочной опции в общий `bochsrc` не подходит; глава применяет `debug_on.txt` отдельно (p. 18).

## Next action

Подготовить образ `disk_c.img`, затем проверить рабочий запуск Bochs; после установки утилит проверить FreeDOS/VC и только затем графический отладочный вариант. Этапы исходят из последовательности p. 15–18.

## Modifying action

- Создание/копирование стартовых файлов, перенос `fdosmini.img` в `disk_c.img`, правка образа через WinImage, копирование инструментов — меняют локальные файлы/образ (p. 15–17).
- В исходном сценарии `xcopy` копирует DOS-утилиты, а `deltree` удаляет исходный каталог `dos` **рекурсивно** (p. 16–17). Без проверки диска и резервной копии такую команду не выполнять.
- Опциональное создание загрузочной USB с Rufus включает форматирование: **риск потери данных на выбранном носителе**; в главе требуется резервная копия перед операцией (p. 18).

## Verification / acceptance checks

Пройти последовательно: `C:\>` → автоматический запуск VC через `autoexec.bat` → запуск `a86`/`nasm`/`bitmap` без ошибки поиска команды → запуск `__debug.bat` и появление встроенного графического отладчика. Источник p. 16–18.

## Rollback

- Глава требует сохранять резервные копии `disk_c.img` после наполнения образа (p. 17–18); восстановление из них — практическая точка возврата, но пошаговая процедура восстановления **[Needs confirmation]**.
- Перед работой с USB глава требует резервную копию данных (p. 18); порядок восстановления **[Needs confirmation]**.
- Для удаления `dos` отдельная процедура rollback в главе не приведена: **[Needs confirmation]**.
