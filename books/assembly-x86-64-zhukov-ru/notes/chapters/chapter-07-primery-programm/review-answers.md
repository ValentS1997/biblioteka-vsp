## Эксперименты из разделов главы

- **7.1 (`var_1.8`)**: `lodsb` читает байт, внутренний `loop` восемь раз выполняет `shr` и `adc`; внешний `cx` сохраняется через `push/pop`. Исходный набор `1, 130, 255, 0` теоретически даёт `1, 2, 8, 0` установленных битов. Это расчёт по исходным данным, не наблюдение отладчика (p. 94).
- **7.2 (`var_1b.8`)**: вместо восьми итераций фиксированно — повторять до `al=0`; сначала `clc`, после цикла `adc al,0`, чтобы не потерять последний вытесненный бит. Сравнить количество шагов в `d86` — [Needs confirmation] (p. 95).
- **7.6–7.8**: `lea` адреса не требует знания размера будущего `byte/word`; `mov ax,x_3` может преждевременно предположить `abs`; неизвестный `mov days,7` неоднозначен. Сравнить с явным `extrn buf:byte` и машинными байтами `.lst` (p. 98–100).
- **7.9–7.10**: пример первой тетрады 6 и второй 8 приводит к `01101000`; перенос из `dl` в `al` через `c` при `shr/rcr` либо общий сдвиг `ax` (p. 101–102).

## Первый уровень — решения на уровне алгоритма (№1–15)

**Общее для всех:** автор требует отладочную и потоковую реализации (p. 102); нельзя объявлять задачу решённой, пока не проверены `d86`, данные и файл результата. Для пары массивов читать и делить длину поровну; число байтов из `ax` после `dos 03f`. Ограничения кратности и переполнения на p. 104.

1. **Максимум / нули.** Сделать проход по словам для определения максимума, затем второй проход для замены нулей. Пустой массив и конкретный критерий для максимума без входных данных — [Needs confirmation].
2. **Двойные символы.** Сравнивать соседние ASCII-литеры; пример `tutti buzz` содержит две пары по автору. Политика перекрывающихся совпадений явно не определена в этом задании: [Needs confirmation].
3. **Сумма и среднее.** Накапливать значения байтов в слове, затем разделить на число элементов, результат представить байтом. Проверять переполнение при суммировании, как требует p. 104; деление при нулевой длине — [Needs confirmation].
4. **Заглавные латинские.** Увеличивать словный счётчик для байтов из алфавитного диапазона; проверить переполнение счётчика и записать слово.
5. **Абсолютные значения слов.** Обрабатывать знаковые слова, отрицательные менять через `neg`, проверяя переполнение. Крайнее отрицательное значение не должно молча приводиться к неверному положительному — p. 103 требует проверку, фактический код [Needs confirmation].
6. **Буквы и цифры.** Две проверки диапазона и два независимых словных счётчика; контролировать переполнение сложения (p. 103–104).
7. **Парные совпадения двух массивов.** Сравнить пары байтов, компактно помещать совпавшие значения в первую область и считать их число. Точный формат области после укорочения автор не определяет — [Needs confirmation].
8. **Обратный порядок ASCII.** Читать массив по одному указателю с конца, формировать результат другим указателем в обратной последовательности. Конкретная стратегия безопасного исполнения *на месте* не задана — [Needs confirmation].
9. **Индексы совпадений.** Сравнивать два массива, записывать индексы с нуля в первый массив; количество совпадений вести отдельно. Представимость индекса одним байтом для длинных массивов — [Needs confirmation].
10. **Индексы значений в знаковом диапазоне.** Использовать знаковые отношения для сравнения и записывать нулевые индексы подходящих элементов. Точные границы задаются входом, не приведены (p. 103).
11. **Верхний регистр ASCII.** Для букв нижнего регистра делать соответствующее преобразование на месте, остальные байты оставлять. Конкретная битовая маска в главе для этого задания не предложена — [Needs confirmation].
12. **Слова вне диапазона.** Отбирать подходящие беззнаковые слова и компактно записывать их в исходную область. Проверять, что число входных байтов кратно 2 (p. 104).
13. **Произведение знаковых слов.** Поэлементно умножать, сохранить результат первого массива и проверять переполнение, как требует автор. Формат обработки переполнения — [Needs confirmation]; длина ввода кратна 4 (p. 104).
14. **Нижний регистр ASCII.** Преобразовать заглавные латинские буквы к нижнему регистру на месте, прочие символы сохранить; проверить вход и выход в отображении `r`.
15. **Частное и остаток слов.** Делить пары беззнаковых слов, частные записывать в первый, остатки — во второй массив, выводить остатки. Проверить деление на ноль и вход длины кратной 4; программа для этих проверок в RAG не приведена.

## Второй уровень — стратегии и авторские ожидаемые результаты (№1–12)

1. **Гистограмма 10 цифр.** Массив из десяти слов, индекс выбирать по встреченной цифре. Автор сообщает ожидаемые числа для `test1.bin`: **2, 6, 11, 19, 26, 39, 50, 67, 83, 102** (p. 104). Их фактическое получение не подтверждено.
2. **Подсчёт битов в двойном слове.** Применить метод `shr`/переноса из 7.1 и перенос разряда между частями счётчика через `add` и `adc`, как требует p. 104. Авторское ожидаемое число записано `016000`, без самостоятельной смены системы счисления; проверить `test2.bin` [Needs confirmation].
3. **Коды Грея 2→8 бит.** Первый блок новой последовательности повторяет исходный с ведущим нулём, второй — исходный в обратном порядке с ведущей единицей. Начать с `00,01,11,10` и поэтапно расширять до области 256 байтов. Сравнить с `test3.bin` (p. 104–105).
4. **Шестибитовая упаковка.** Использовать только шесть значимых битов каждого из четырёх байтов, сохранить их порядок в трёх выходных байтах (4×6 = 24 бита); длина входа кратна 4. Сравнить `test4.out` (p. 105).
5. **Бит чётности / семибитовая упаковка.** Добавить в разряд 6 требуемое дополнение до чётности к исходным шести битам, затем упаковать восемь полученных 7-битовых кодов в семь байтов (8×7 = 56). Длина кратна 8; сравнить `test5.out` (p. 105–106).
6. **RADIX-50.** Перевести три символа в номера по табл. 7.1, затем вычислить `(c1 × 50xq + c2) × 50xq + c3`. По автору `ABC` → `3223xq`; вход кратен 3, результат сравнивать с `test6.out`. Для символа `.` таблица и последующее предложение противоречат друг другу: **[Needs confirmation]** (p. 106).
7. **Сглаживание.** Формировать значение из трёх соседних беззнаковых байтов; длина выхода на 2 меньше. Источник предлагает менее затратную по делениям формулу `((A(i−1)+A(i+1))/2 + A(i))/2`, вычисления над словами и проверку переполнения. Точная погрешность целочисленного округления не рассчитана — [Needs confirmation] (p. 106).
8. **Текст в спираль.** Подобрать нечётную сторону квадрата с достаточной ёмкостью, витками заполнять матрицу по направлениям влево, вниз, вправо, вверх, уменьшая число шагов. Дописать хвост `null`. Само изображение рис. 7.1 недоступно как мультимодальный RAG-объект, поэтому **точная ожидаемая матрица [Needs confirmation]** (p. 107).
9. **Чтение по спирали.** Первый байт задаёт нечётную сторону **3–127**, последующие — строковое представление матрицы. Обходить последовательные витки для извлечения в том же порядке, что описан для спирали (p. 107). Ожидаемый вывод для `test9.bin` не приведён — [Needs confirmation].
10. **Серии соседних букв.** Считать **одну** серию для трёх одинаковых букв подряд, игнорировать повторы небуквенных символов. Для `test10.bin` автор сообщает **5** серий (p. 107); не интерпретировать их как количество всех перекрывающихся пар.
11. **Транспонирование 8×8.** Менять местами роли строк и столбцов при чтении и записи байтов, сверять отображение `r8`. Для `test11.bin` ожидаемая поэлементная матрица в RAG не указана — [Needs confirmation] (p. 107).
12. **Перекодировка с 4-битовым уплотнением.** Цифры → 0–9, минус → `0a`, точка → `0b`, группа разделителей → один `0c`, завершение → `0f`. Первый код пары в младшей тетраде. Для авторского примера получены `03a 01b 0c4 061 0f` (p. 108). Проверка на `test12.bin` — [Needs confirmation].
