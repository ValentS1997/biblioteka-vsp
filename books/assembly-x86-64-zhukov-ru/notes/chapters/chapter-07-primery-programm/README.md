## Ключевые механизмы

**Подсчёт единичных битов (7.1).** Указатели `si` и `di` начинаются с одного `buf`. Внешний цикл читает каждый байт через `lodsb`; вложенный выполняет ровно восемь сдвигов `shr al,1` с переносом вытесненного бита во флаг `c`. `adc ah,0` увеличивает счётчик. Поскольку оба цикла используют `cx`, внешний счётчик сохраняется `push cx` и восстанавливается `pop cx`. `stosb` заменяет исходный байт числом его единичных разрядов (p. 94).

**Оптимизация (7.2).** Внутренний цикл теперь завершается `jnz`, когда сдвигаемый `al` стал нулём. `clc` перед первым `adc` убирает посторонний перенос; `adc al,0` после цикла учитывает последний вытесненный бит. Автор сравнивает число операций, а не объявляет вариант универсально более быстрым (p. 94–95).

**Потоковая программа (7.3–7.5).** Вместо жёстко определённого массива читаются данные из стандартного входа. Для чтения `bx=0, cx=08000, dx=buf, dos 03f`, `ax` — число прочитанных байтов, `c=1` — ошибка. `make` преобразует прочитанное *in situ*, запись использует `bx=1, dos 040`, завершение — `dos 04c` с кодом 0/1 (p. 95–98). В показанном `var_2.8` один вызов чтения, а не доказанный многошаговый цикл по всему потоку: большие файлы/частичные записи **[Needs confirmation]**.

**Опережающие ссылки (7.6–7.8).** При первом проходе неизвестный тип имени может влиять на длину команды. `lea` не требует знания `byte/word` адресуемых данных; `mov` с неизвестным операндом-приёмником может быть неоднозначен. `extrn buf:byte` (или `extrn buf:b` в a86) сообщает тип заранее. Для локальных меток a86 использует короткие переходы; основной тип `jmp` вперёд без такого указания может занять больше байтов (p. 98–100).

**Упаковка тетрад (7.9–7.10).** Для кодов 6 и 8 формируется байт с комбинацией `01101000` (p. 101). В 7.9 биты `dl` передаются по одному через перенос `c` командами `shr` и `rcr`; в 7.10 младшие тетрады `ah` и `al` объединяются через `shl al,4`, `shr ax,4` (p. 101–102).

## Ограничения, проверка и риски

- Перенаправление вывода `>` создаёт или **обнуляет** существующий целевой файл (p. 95). Проверка тестов должна использовать отдельные пути и копии.
- В `var_2.8` `buf db` обозначает адрес **без явного резервирования** в COM, рассчитанный на свободную память ниже стека; это контекст описанного DOS-окружения, не универсальная гарантия буфера (p. 98).
- Автор требует проверок переполнения, кратности объёма входа 2 или 4 и деления на ноль в подходящих заданиях (p. 103–104). Не придумывать готовый безопасный код там, где он не дан.
- Рис. 7.1 на p. 107 не является самостоятельным визуальным RAG-объектом; точное расположение символов в образце спирали **[Needs confirmation]**. См. [source-findings.md](source-findings.md).
- Поскольку окружение a86/d86 в текущем сеансе не запускалось, кодировки команд и выходные файлы не объявляются фактически проверенными.
