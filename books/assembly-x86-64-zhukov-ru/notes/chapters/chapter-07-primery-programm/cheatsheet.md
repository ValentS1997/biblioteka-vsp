# Глава 7 — operational cheatsheet: от битовых циклов к потокам

**Источник:** только canonical RAG, PDF p. 93–110 (`p0093:c01`–`p0110:c01`). Синтаксис a86/DOS и 16-битный контекст книги.

## Symptom / problem framing

Требуется подсчитать установленные биты каждого байта, обработать массив неизвестной длины, получить и записать результат через DOS, упаковать 4-битовые коды либо объяснить ошибку опережающей ссылки при трансляции. Важно различать **наблюдение состояния**, **изменение данных/файлов** и **неизвестные свойства внешнего окружения**.

## Baseline / context

- `var_1.8`: `buf db bit 0, bit 1 + bit 7, -1, 0`, `size equ $-buf`. `si/di` изначально указывают на `buf`, `cld` задаёт прямой обход (p. 94).
- Вложенный `loop`: внешний `cx=size`, внутренний `cx=8`, между ними `push cx/pop cx`; каждый `shr al,1` переносит вытесненный бит в `c`, `adc ah,0` учитывает его (p. 94).
- `var_1b.8`: `clc` до первого `adc ah,0`; `shr al,1` и `jnz l2` завершают цикл раньше; после выхода `adc al,0` учитывает последний перенос (p. 95).
- `var_2.8`: `dos` через `int 021`; 03f = читать, 040 = записать, 04c = завершить; `bx=0/1` для stdin/stdout (p. 95–97).

## Read-only checks

1. Проверить число входных байтов, формат элементов и требование кратности 2 или 4 (p. 102–104, примечание 10 p. 109).
2. Проверить исходные `cx`, `si`, `di`, `ah`, `c` перед каждым уровнем цикла; при двух `loop` `cx` должен быть сохранён (p. 94).
3. Прочитать `.lst` на предмет типа имени и длины команды; `lea` с опережающей ссылкой отличается от неоднозначного `mov` (p. 98–100).
4. Для потоковых данных проверить `c` после системного вызова и `ax` как число байтов (p. 96). Не путать успех системного вызова с успешным полным выводом.
5. Для `pack_1.8` проверить четыре переноса битов из `dl` через `c` в `al` и результат для 6/8, `01101000` (p. 101).

## Interpretation

| Симптом | Объяснение по источнику |
|---|---|
| Нарушен внешний цикл при подсчёте битов | Внутренний `loop` изменяет тот же `cx`; требуется `push cx/pop cx` (p. 94). |
| Лишняя единица в варианте с `jnz` | До первого `adc` нужно `clc`, после выхода — учесть последний перенос (p. 95). |
| После `dos 03f` выставлен `c` | Автор обозначает это как ошибку чтения; `ax` содержит длину только при успешном результате (p. 96). |
| На выходе нет содержимого или файл уже пуст | Перенаправление `>` обнуляет существующий файл перед работой программы (p. 95). |
| `mov days,7` до определения days вызывает ошибку | Размер будущего операнда byte/word неоднозначен для a86 (p. 99–100). |
| `lea si,buf` при позднем определении buf допустима | Адрес имеет фиксированную ширину независимо от `byte/word` (p. 98). |

## Next action

Для отладки выбрать `var_1.8` с фиксированным массивом, проверить результат после каждой итерации, затем `var_1b.8`. Для потокового варианта отдельно проверять чтение, преобразование, запись и код завершения. При проблеме с опережающей ссылкой прочитать тип имени и `.lst`, затем использовать `extrn buf:byte` для явной декларации по образцу p. 100.

## Modifying action

- `lodsb/stosb` читают и **перезаписывают массив на месте**, `shr/adc` меняют регистры и флаги (p. 94–95).
- `dos 03f` пишет входные байты в `buf`; `dos 040` пишет данные в стандартный выходной поток, а `>` может уничтожить прежнее содержимое файла (p. 95–97).
- `dos 04c` завершает программу с кодом 0/1 (p. 97).
- `k s alta` сохраняет нажатия отладчика; `Alt+A` воспроизводит (p. 102).

## Verification / acceptance checks

- Для `buf=(1,130,255,0)` расчёт ожидаемого числа установленных битов: **1,2,8,0**, сверить с окнами памяти `d86` (p. 94; результат вычислен по алгоритму, не наблюдался).
- При подсчёте `F9` у команды `loop l1` выполняет очередную итерацию с наблюдением данных (p. 94).
- `dos 03f`: `c=0` и `ax` число прочитанных; `dos 040`: `c=0` и `ax` число записанных. Авторская программа 7.5 не доказывает обработку произвольной длины за несколько чтений — [Needs confirmation].
- Упаковка двух тетрад 6 и 8 должна дать `01101000`, сверить через `=e1,ax` и `=e1,dx` (p. 101).

## Rollback

Исходник не задаёт универсального отката изменённой памяти, файлов или состояния отладчика: **[Needs confirmation]**. До перенаправления stdout выбирать новый выходной файл или сохранять копию существующего; тестировать только на копиях учебных входов. Для произвольного ввода и длинных файлов гарантии выходного размера отсутствуют.
