# Команды и инструменты — глава 2

**RAG provenance:** `assembly-x86-64-zhukov-ru:p0021:c01`–`p0030:c01`, PDF p. 21–30. Примеры синтаксиса взяты только из главы.

| Вызов / конструкция | Класс | Подтверждение, эффект и осторожность |
|---|---|---|
| `a86 test1.8` | **State-changing** | Трансляция; `test1.com`/`test1.sym` при успехе, при ошибке `.old` и сообщения внутри `test1.8`; возможен `.und` (p. 21–22). |
| `a86 bmp_0.8 TO bmp_0.bmp` | **State-changing** | Создание файла `bmp_0.bmp` из директив данных (p. 26). |
| `bitmap bmp_0.bmp` | **Workload-generating / read-only viewing** | Открывает графический файл в описанной FreeDOS-среде; `F5` — цветной просмотр (p. 26). |
| `fc /b var_<n>.com var_<n>.dat` | **Read-only** | Побайтовое сравнение созданного COM с эталонными данными (p. 25). |
| `F3`, `F4` в VC | **Read-only viewing / state-changing edit** | Просмотр / редактор исходного файла (p. 29, примечания 3–4). |
| `db`, `dw`, `dd` | **State-changing at generation** | Определения байтов, слов, двойных слов в выходном файле (p. 22–27). |
| `equ`, `dup`, `$`, `offset`, `bit` | **Assembly-time expressions** | Константы, повторения, текущий адрес, адрес символа, единица в заданном бите (p. 23–27, 30). |

## Исходные фрагменты из листингов

**Листинг 2.3, PDF p. 23 — 128 байт:**

```asm
sz      equ  1k/8
seq     db   sz/2 dup (0, 1)
sz      equ  $ - seq
```

Первая константа задаёт ожидаемую длину, второе определение проверяет фактический размер. В тексте вычисления есть опечатка, сохранённая в `source-findings.md`.

**Листинг 2.6, PDF p. 25 — 300 байт:**

```asm
sz      equ     300
area    db      sz/3 dup (1, 2, 0)
sz      equ     $ - area
```

Пара `2,0` представляет младший и старший байт слова со значением 2 в записи Intel (p. 25).

**Листинг 2.7, PDF p. 25 — порядок байтов:**

```asm
dw   0100
db   0, 1

dd   010003
dw   3, 1
db   3, 0, 1, 0
```

Исходник демонстрирует эквивалентность представлений; три последних варианта не нужно одновременно считать частью одного значения.

**Листинг 2.8, PDF p. 26–27 — константы BMP:**

```asm
iWidth        equ   64
iHeight       equ   32
bitsPerPixel  equ   1
Colors        equ   bit bitsPerPixel
pixelsPerByte equ   8 / bitsPerPixel
bytesPerLine  equ   iWidth / pixelsPerByte
byteCount     equ   bytesPerLine * iHeight
```

Часть завершающих проверок: `Colors equ ($ - Palette) / 4`, `zero equ ($ - Palette) mod 4`, `byteCount equ $ - Pixels` (p. 27). `Colors`, `zero` и `byteCount` повторно определяются для контроля.

## Реестр рисков и проверок

- **a86:** перед трансляцией скопировать исходный `.8`; ошибка может вызвать модификацию и даже порчу исходного файла. Проверить `.old`, `.und`, `.com`, `.sym` и отсутствие диагностик. Rollback: восстановить оригинал из `.old` (p. 21–24); команда восстановления [Needs confirmation].
- **Изменение `dup`/размеров:** проверить повторное `equ`, результат `fc /b`; неправильная разность адресов вызывает `Object Overflow` (p. 24–25). Rollback: вернуть исходный фрагмент; пошаговая процедура [Needs confirmation].
- **Изменение BMP:** сверить все три проверки палитры и растра и визуально проверить `bitmap` (p. 27–28). Rollback: удалить экспериментальную строку/байт или восстановить параметры; точные команды [Needs confirmation].
- **Данные в COM:** не вызывать на исполнение `test1.com` и аналогичные data-only COM (p. 22).

Не добавлялись команды установки, флаги a86 или синтаксис NASM, которых нет в RAG этой главы.
