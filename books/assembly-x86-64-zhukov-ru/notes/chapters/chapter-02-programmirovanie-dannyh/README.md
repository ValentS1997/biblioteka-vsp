# Глава 2. Программирование данных

**Книга:** А. В. Жуков, «Ассемблер и программная модель процессоров x86/64» (2024), часть I — «Реальный режим».  
**Область:** PDF p. 21–30, глава 3 начинается на PDF p. 31.  
**Источник:** canonical RAG, чанки `assembly-x86-64-zhukov-ru:p0021:c01`–`assembly-x86-64-zhukov-ru:p0030:c01`.  
**SHA-256 PDF:** `f65a7ec88148cb29d7e75d1ce34ef14c3a7ddf8af264ec7abcf9b8a0437220c2`.  
**Политика:** `rag_only`; никакие сведения о версиях программ, платформе или формате BMP извне не добавляются.

## Центральная идея

В этой главе ассемблер **генерирует данные**, не исполняемую логику. Директивы `db`, `dw`, `dd` и `equ`, выражения времени трансляции, счётчик адресов `$` и повторения `dup` позволяют задать последовательности байтов и составить файл bitmap с согласованными полями. Повторное определение одной и той же константы в `a86` служит встроенной **проверкой размера** данных: при расхождении ожидаемого и фактического значений возникает `Conflicting multiple definition`.

## Механизмы и контрольные точки

1. **Трансляция `a86` (p. 21–22).** Вызов по имени исходного файла создаёт `.com` и `.sym` при успехе. При диагностируемой синтаксической ошибке сохраняется `.old`, а сообщения внедряются в исходный файл. Неопределённые имена могут появляться в `.und`. **Сгенерированный только из данных `.com` не запускать** — его байты будут восприняты как команды.
2. **Директивы и `$` (p. 23–25).** В `var_0a.8`: `sz equ 1k/8` задаёт 128, `db sz/2 dup (0,1)` создаёт 128 байт; начальный `$` в COM равен 256. Проверка `sz equ $ - seq` сопоставляет фактический размер с ожидаемым.
3. **Размещение младшего байта первым (p. 25).** Для `dw 0100` исходник показывает `db 0,1`; для `dd 010003` показаны эквивалентные `dw 3,1` и `db 3,0,1,0`.
4. **BMP из данных (p. 26–29).** `iWidth=64`, `iHeight=32`, `bitsPerPixel=1`; вычисляются `Colors`, `pixelsPerByte`, `bytesPerLine`, `byteCount`. Три проверки: количество цветов, кратность размера палитры четырём и длина растра. Изображение по описанию состоит из двух красных вертикальных линий на синем фоне.
5. **Испытания (p. 28–29).** Изменить размер изображения, палитру и глубину цвета, наблюдая как взаимосвязанные поля сохраняют либо нарушают согласованность.

## Важные ограничения

- `a86` может **изменить исходный файл** при обработке ошибок (p. 21–22). Хранить копию, не полагаться на `.old` как безусловно надёжный механизм.
- При ошибках вставки сообщений возможно повреждение исходного текста; источник рекомендует срочное восстановление из `.old` (p. 24).
- COM ограничен приблизительно 64 КиБ минус 256 байтов PSP (p. 24, 29); искусственная ошибка размера приводит к `Object Overflow`.
- `?` обозначает неопределённое значение, обычно ноль (p. 30). Содержимое растровых примеров здесь извлечено как **текст**; сами изображения в RAG отдельно не представлены.
- В описании листинга 2.3 обнаружено несогласованное арифметическое выражение `284 − 256 = 128`. Исходный вариант сохранён в [source-findings.md](source-findings.md), без замены из памяти.
