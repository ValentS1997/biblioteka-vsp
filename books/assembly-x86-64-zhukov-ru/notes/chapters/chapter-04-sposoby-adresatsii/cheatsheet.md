# Глава 4 — operational cheatsheet

**RAG:** PDF 57–68, `p0057:c01`–`p0068:c01`. Применимо к описанному автором `a86` и i8086/286; другие трансляторы не проверены.

## Symptom / problem framing

Непонятно, почему ассемблер запрещает `inc 7`, `not [082]`, `inc b[ax]`, `inc b[si+di]` или `mov w[si],[di]`. Нужно разобрать *адресацию*, *роль операнда* и *размерность*.

## Baseline / context

- Восемь регистров: `ax bx cx dx sp bp si di`. Регистры `ax/bx/cx/dx` доступны также по старшим/младшим байтам (`ah/al` и аналогично; p. 57–58).
- В двухоперандных командах назначения обычно первое: `add al,bl` пишет результат в `al`; `mul cx` имеет неявные `ax` и `dx:ax` (p. 59–60).
- Регистр/константа/память — три класса местонахождения (p. 60). Для памяти есть прямая и косвенная адресация.

## Read-only checks

1. Проверить по тексту, не является ли первый операнд немодифицируемой константой (`inc 7`, `add 3,ax`; p. 60).
2. Проверить по типу имени или другому операнду ширину `[адрес]`; иначе `not [082]` даёт `Is it Byte or Word?` (p. 61).
3. Для косвенной адресации i8086/286 проверить допустимость `si/di/bx/bp`; для пары — одну базу `bx/bp` и один индекс `si/di` (p. 64, 66).
4. Исключить два явно адресуемых операнда памяти (`add b[0103],[si]` — нарушение из листинга 4.14, p. 67).
5. Сравнить по `.lst` формы `area[si]`, `[si]area`, `[area+si]` (p. 65). Трансляция, производящая файл, — отдельное изменяющее действие.

## Interpretation

| Наблюдение | Трактовка по книге |
|---|---|
| `Is it Byte or Word?` | Размер памяти не указан (p. 61). |
| `Byte/Word Combination Not Allowed` | `mov word ptr [082],al` смешивает 16- и 8-битные операнды (p. 62). |
| `mov [082],1` | Без указания размера константа `1` неоднозначна для `a86` (p. 61–62). |
| `inc b[ax]`, `inc b[si+di]` | Недопустимый регистр / пара регистров в 16-битном контексте (p. 64, 66). |
| `mov w[si],[di]` | Оба операнда явно в памяти, что запрещено для этой инструкции (p. 67). |

## Next action

Уточнить, какой источник адресации нужен: `b[si]` (указатель), `[si+area]` (индекс) либо `[bx+si]` (база + индекс). Если размер нельзя определить, обозначить `b/w`, `byte ptr/word ptr`. Перетранслировать с `+L` и проверить эффект в `d86` (p. 60–65).

## Modifying action

- `inc b[si]` меняет байт по адресу из `si`; `inc si` перемещает указатель на один байт (p. 63).
- `mov si,offset area` и `mov si,0` задают два варианта обхода массива (p. 64).
- `add si,2` требуется для перехода к следующему слову после замены `db` на `dw` (p. 65).
- Циклы с `jmp l1` (p. 63–64) не содержат проверок границ и могут продолжить менять память за пределами массива.

## Verification / acceptance checks

- `a86` + `+L`: отсутствие ожидаемых ошибок, контроль байтов непосредственного операнда и длины инструкции (p. 60–62, 65).
- `d86` с параметрами `123 abc` или `1234`: показать `082`, окна `b/w/r`, затем выполнять только по шагам `F1`, наблюдая изменяемые байты (p. 62–63).
- Для разных форм `area[si]` коды в листинге должны совпасть; для нулевого суммарного смещения автор ожидает короткую форму (p. 65).

## Rollback

В главе не дана самостоятельная процедура возврата изменённых байтов PSP, массива или регистров: **[Needs confirmation]**. Для упражнений необходимы изоляция сеанса и исходная сохранённая копия; **не запускать безусловные циклы бесконтрольно**.
