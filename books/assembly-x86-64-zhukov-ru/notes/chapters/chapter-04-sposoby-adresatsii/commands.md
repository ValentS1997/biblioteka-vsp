# Глава 4 — команды и обозначения операндов

**Источник:** canonical RAG, `p0057:c01`–`p0068:c01`, PDF 57–68. Все машинные операции представлены как примеры автора, фактический запуск не выполнялся.

| Команда / форма | Класс действия | Происхождение и эффект |
|---|---|---|
| `mov dx,0`, `inc dh`, `mov al,dh` | Изменяет регистры | `dx=0100`, `al=1`; `ah` не определялся (листинг 4.1, p. 58). |
| `nop` | Нет полезного изменения | Пример инструкции без операндов (4.2, p. 59). |
| `mov ax,10`, `add al,bl` | Изменяет первый операнд | Размеры согласованы (4.2, p. 59). |
| `shl ax,cl` | Изменяет `ax` | Особый случай: число сдвигов — байтовый `cl` (4.2, p. 59). |
| `mul cx` | Изменяет `dx:ax` | Неявный множитель `ax`; второй — `cx` (p. 60). |
| `inc si`, `mov dh,cl` | Изменяет регистры | Регистровая адресация (4.3, p. 60). |
| `add al,012`, `add ax,03456` | Изменяет регистр | Непосредственное число внутри инструкции (4.4, p. 60). |
| `inc 7`, `add 3,ax` | **Ошибка** | Нельзя менять непосредственную константу (4.4, p. 60). |
| `not b_1`, `not w_1`, `not byte [082]` | Изменяет память | Прямая адресация; тип определяет ширину (4.5, p. 61). |
| `not [082]`, `mov [082],1` | **Ошибка** | Не определён размер памяти (4.5, p. 61–62). |
| `mov word ptr [082],al` | **Ошибка** | Несовпадение размеров byte/word (4.5, p. 61–62). |
| `d86 exa5.com 123 abc` | Запуск сессии отладки | Просмотр/изменение PSP с `082` (p. 62). |
| `k s alta` + `Alt+A` в d86 | Создание файла/воспроизведение | Запись нажатий `alta.d8k` и повтор (p. 62–63). |
| `d86 exa6.com 1234` | Запуск сессии отладки | Проверка косвенной адресации и `r,si` (p. 63). |
| `mov si,082`, `inc b[si]`, `inc si` | Изменяет память/регистры | Адрес байта — содержимое `si` (4.6, p. 63). |
| `mov si,offset area`, `inc b[si]` | Изменяет память/регистры | `si` служит указателем (4.8, p. 64). |
| `mov si,0`, `inc [si+area]` | Изменяет память/регистры | `si` служит индексом относительно `area` (4.9, p. 64). |
| `area[si]`, `[si]area`, `[area+si]` | Формы адреса | По книге одинаковые коды в листинге (4.12, p. 65). |
| `add si,2` | Изменяет `si` | Шаг в массиве слов (p. 65). |
| `inc b[si+bx]`, `inc b[bp+di+2]` | Изменяет память | База плюс индекс (4.13, p. 66). |
| `inc b[si+di]` | **Ошибка** | Два индексных регистра (4.13, p. 66). |
| `movsw` | Изменяет память | Неявные адреса `[si]` и `[di]` (p. 67). |

## Мини-практикум по ошибкам

```asm
; p. 61: недостаточно сведений о ширине:
not [082]             ; Is it Byte or Word?
not byte [082]        ; явное указание byte

; p. 62: несовместимые типы:
mov word ptr [082], al  ; Byte/Word Combination Not Allowed
mov [082], al           ; ширина определяется по al

; p. 64: указатель против индекса:
mov si, offset area
inc b[si]               ; адрес в si
mov si, 0
inc [si+area]           ; индекс от area
```

**Фрагменты не составляют единую программу** и намеренно содержат заведомо ошибочные строки, выделенные комментариями. Примеры используются для чтения и трансляционных экспериментов, не как команды для безусловного запуска.

## Специальные замечания о синтаксисе источника

В листинге 4.13 автор использует `mov bx,bp,080` и прямо называет это **встроенной макрокомандой a86**; не подменять на обычный синтаксис `mov` из другого ассемблера (p. 66). Там же `inc w[di][bx]` — авторская запись пары индекса и базы. В листинге 4.12 `b -4[si](2 * bit 1)` имеет суммарное нулевое смещение, что объясняет сокращённое кодирование (p. 65).

## Проверка, риски и возврат

Сверять `.lst` (положение непосредственных байтов, длину и код машинной инструкции), затем в `d86` выполнять только по шагам `F1`. Модифицирующие `inc/add/mov/not` затрагивают регистры и память, а циклы с `jmp l1` не ограничены длиной массива. Сохранение исходного состояния необходимо; готовый rollback-сценарий в главе не дан — **[Needs confirmation]**.
