# Глава 15 — operational cheatsheet: IDT, fault, IRQ

**Источник:** canonical RAG PDF 253–268, листинги 15.1–15.7. Не результаты выполнения.

## Контекст диагностики

Симптомы: обработчик не вызывается, исключения повторяются, стек расходуется, IRQ клавиатуры не обслуживается, IF неожиданно обнулён. Аналитический порядок: **номер события → наличие дескриптора IDT → тип Gate → селектор/offset → кадр исключения → код ошибки → EOI и устройство → IRET**.

## Опорная таблица

| Параметр | Значение по книге | Где |
|---|---|---|
| IDT / IDTR | 8 байт на Gate, IDTR задаёт линейную базу и предел | 253–256 |
| Trap Gate | тип 1111b, атрибут 8Fh, **IF не очищается** | 254, 266 |
| Interrupt Gate | тип 1110b, атрибут 8Eh, **IF очищается** | 254, 261, 266 |
| Векторы 0, 1 | В 15.1 счётчики двух исключений | 254–256 |
| #GP = 13 | В protected mode добавляет DWORD ошибки в стек | 258–259 |
| IDT для 0..39 | 40×8=320 байт; предел 0x13f | 256–258 |
| Вектор 40 | Следующий адрес 0x140 → #GP, код примера 0x142 | 258–259 |
| IRQ0 до настройки | 8, но №8 занят Double Fault | 259–260 |
| IRQ0–IRQ7 после настройки | 32–39, в примере 15.5 | 262–265 |
| IF / EFLAGS | бит 9, маска 0x200 | 265–266 |
| IOPL | двухбитовое поле 12–13, уровень доступа к I/O | 266–267 |

## Механизмы

**Trap против fault.** Прямой `int` из 15.1 и ошибка `div al` приводят к одному обработчику №0, но сохраняют **разные точки продолжения**: явный `int` — после инструкции; fault — собственную адресу, поэтому повторяется (p. 255–256). Gate не меняет точку возврата.

**Код ошибки.** В авторском сценарии превышение IDT вызывает #GP со стеком из четырёх двойных слов: код ошибки, EIP, CS, EFLAGS. `0x142`: индекс IDT = `0x140/8=40`, установлен признак IDT, бит EXT=0. Перед штатным IRET дополнительный код ошибки должен быть согласованно исключён из кадра (p. 258–259).

**Внешние IRQ.** После перемещения PIC 32–39 обработчики внешних событий имеют Interrupt Gate, отдельный вход на источник и EOI; исключения имеют Trap Gate и не требуют EOI. Для клавиатуры нужен ещё и её собственный ACK (p. 260–265).

**IF и IOPL.** `eflags.asm` считывает EFLAGS в ISR; после Trap Gate флаг IF остаётся установлен, после Interrupt Gate очищен. В примере с CPL=0 настройка IOPL не меняет доступность I/O-портов (p. 265–267).

## Проверки без запуска

- Вычислить `limit=40*8−1=0x13f`; для вектора 40 требуется `0x140`, которого нет.
- По `max_int=39` проверить **40**, а не 39, обработчиков и дескрипторов.
- Разобрать стековую четвёрку в p. 258; не выдавать сомнительное значение ESP из прозы за проверенный регистр — см. source findings.
- Разделить события `int 0`, `div`, IRQ0, IRQ1 и событие #GP; у каждого отличать источник и требования выхода.

## Изменяющие операции, защита и откат

Эксперименты с IDT/PIC, заведомо отсутствующим Gate или fault меняют глобальное состояние VM. Неправильный ISR может расходовать стек до отказа; без EOI аппаратные линии могут оставаться необслуженными. Анализ выполнен без запуска, безопасного универсального rollback в этих RAG-страницах нет — **[Needs confirmation]**. До любых внешних экспериментов нужен отдельный одноразовый снимок VM и полный способ восстановления.
