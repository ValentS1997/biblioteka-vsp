# Глава 15 — ответы на вопросы по RAG

**Источник:** [review-questions.md](review-questions.md) и canonical RAG PDF **253–268**. Нумерация Q1–Q14 редакционная. Это **аналитические расчёты**, не официальный ключ и не выполненные запуски NASM/Bochs.

**Q1 (253–254).** В real mode IVT начинается от линейного 0, вектор содержит два 16-битных слова, всего четыре байта. В protected mode IDT может размещаться по иной линейной базе, задаваемой вместе с limit через IDTR. Один восьмибайтовый Gate задаёт селектор кодового сегмента, смещение ISR и атрибуты. Индекс n задаёт смещение `8*n`.

**Q2 (254, прим. 2 p. 267).** Gate типа **1110b** автоматически сбрасывает IF, Gate типа **1111b** сохраняет его. Trap Gate не превращает fault в trap: при неверной инструкции сохраняется адрес самой инструкции. Разница касается внешней маскируемой IRQ во время обработки.

**Q3 (254–256).** `isr0` и `isr1` сохраняют EDX, задают в EDX номер 0/1 и переходят в общий `isr`. Там `lea eax,[i_cnt+edx*4]` вычисляет адрес соответствующего DWORD, счётчик увеличивается. `_SHOW_` включает вывод, без него остаётся накопление статистики. Прямые вызовы дают по меньшей мере два события №0 и одно №1 до попытки `div`; после неё №0 повторяется, пока причина не устранена.

**Q4 (255–256).** `AX=0101h` и `div al` при AL=1 дают частное 257, которое не помещается в AL, поэтому возникает исключение 0. Оно сохраняет текущий IP и повторяется после обычного IRET. Прямой `int 0` является явным вызовом и возвращает следующую команду. Строка `*** Fin ***` содержит 11 символов при ширине экранной позиции 10, последний символ автор не видит.

**Q5 (256–258).** `max_int=39` означает включительно номера **0..39**, следовательно 40 записей по 8 байт = **320**; limit = 319 = **0x13f**. Счётчики векторных вызовов `int 0`, `int 0`, `int 39` — **2** и **1** соответственно, если аварийный вызов 40 оставлен закомментированным.

**Q6 (258–259).** Для номера **40** нужен Gate со смещением `40*8=0x140`, за пределом 0x13f. В авторском опыте #GP возвращает код ошибки **0x142**: поле смещения дескриптора = 0x140, IDT-бит 1 установлен, EXT=0 — внутренний источник; 0x140/8=40. Лог Bochs затем показывает повторные исключения и исчерпание стека, это наблюдение из книги, не новый прогон.

**Q7 (258–259).** #GP 13 добавляет DWORD кода ошибки сверх обычного кадра. В источнике приведены, в порядке возрастания адресов: `00000142` (ошибка), `000005D4` (возвратный EIP), `00000008` (CS), `00010002` (EFLAGS). Суммарно четыре DWORD = **16 байт**. При типичном выходе с IRET обработчик обязан учесть лишнее DWORD, иначе адрес возврата трактуется неверно. Текст `ESP=0xf010 → 0xff00` **не согласован** с объявленной разностью 0x10: арифметически должно быть 0xf000. Это finding, а не доказанное содержимое регистра Bochs.

**Q8 (259).** Вентиль с DPL=3 открыт для вызова программами разных уровней, но кодовый дескриптор обработчика с DPL=3 при рассмотренном CPL=0 непригоден для такого входа. Автор наблюдает отказ `not accessible or not code segment`. Не переносить этот вывод на все варианты перехода привилегий без главы 18.

**Q9 (259–260).** В 15.3 читаются младшая и старшая части счётчика таймера; их изменение подтверждает счёт. Вектор IRQ0=8 в исходной настройке PIC конфликтует с protected-mode исключением **Double Fault №8**. Поэтому нужен отдельный диапазон внешних векторов.

**Q10 (260–262).** Временный 15.4 использует векторы 8–15 как Interrupt Gate, чтобы IF очищался при входе. Контроллер PIC отдельно ждёт EOI; IF и EOI — разные механизмы. При таймере около 18,2 Гц **91/18,2≈5 секунд**, но автор оговаривает отличающийся ход времени в Bochs. Событие отпускания Enter может быть единственным заметным IRQ клавиатуры из-за отсутствия подтверждения устройства.

**Q11 (262–265).** В 15.5 `trap_no=pic_vect` равен **32**, а `intr_no=8`: первые 32 вентиля — Trap Gate для исключений 0–31, ещё 8 — Interrupt Gate для IRQ0–7 на векторах **32–39**. Внешние ISR ветвятся по устройствам и сходятся на EOI; клавиатуре требуется собственное подтверждение; исключения CPU переходят непосредственно к общему выходу без EOI.

**Q12 (265–266).** В ISR сохраняется EFLAGS через `pushf/pop eax`. Маска IF — **0x200 (бит 9)**. В Trap Gate при установленном до входа IF этот бит остаётся единицей, в Interrupt Gate становится нулём. Автор сравнивает числа с 0x200; более точное извлечение бита — по маске `0x200`, не просто общая величина EFLAGS. Наблюдения собственных регистров не выполнялись.

**Q13 (266–267).** IOPL (биты 12–13 EFLAGS) задаёт минимально допустимый уровень I/O для рассматриваемой операции. В программе автора **CPL=0**, поэтому установка IOPL=3 не создаёт заметного ограничения доступа портов. Это наблюдение конкретного режима/привилегии, не тест CPL=3.

**Q14 (261, 267).** В примечании p.267 автор говорит, что gate не меняет точку возврата для fault. Про Bochs оговариваются ускорение таймера, зависимость от FreeDOS и результаты аварийного стека. Ссылка p.261 на **листинг 11.6** не совпадает с видимой нумерацией главы 11: обработчик клавиатуры приведён под номером **11.5**. Сверка авторского errata — [Needs confirmation].

## Предел доказательства

Результаты вычислений и цитируемых наблюдений относятся только к RAG. Код ошибок, стек и порты не проверялись собственным запуском; изменение IDT/PIC и бесконечные fault здесь не производились. [Source findings](source-findings.md) фиксирует все существенные расхождения без изменения PDF.
