# Глава 19 — оперативная шпаргалка: compatibility mode

**Provenance:** canonical RAG PDF 323–330, `p0323:c01`–`p0330:c01`. Листинги 19.1–19.4. **Не выполнять** приведённые действия с CPU-регистрами на рабочей системе.

## Диагностическая формулировка

Задача: отличить **наличие long mode**, **запрос long mode** через `EFER.LME`, **фактическую активацию** через `EFER.LMA` и **выбранный кодовый подрежим** через `CS descriptor.L`. Их смешение даёт неверное объяснение «почему процессор всё ещё в 32 битах» (p. 323, 326–327).

## Четыре независимых признака

| Признак | По книге | Проверка по RAG |
|---|---|---|
| Поддержка CPU | `CPUID(80000001h): EDX[29]` | Перед этим `CPUID(80000000h)` подтверждает наличие функции |
| Разрешение | `EFER.LME`, бит **8** | Макрос 19.1 `set_efer_lme` |
| Активация | `EFER.LMA`, бит **10** | `chk_efer_lma` копирует результат в CF |
| Кодовый подрежим | Дескриптор кода `L=0` / `L=1` | Compatibility / 64-bit mode соответственно |

**Следствие:** установленный LME **не равен** LMA=1: листинг 19.2 остаётся в ожидающем цикле до добавления страницы и включения paging из 19.3.

## Память в образце 19.3

| Уровень | Линейная база учебной таблицы | Запись |
|---|---|---|
| PML4 | `100000h` | Начальная запись → PDP |
| PDP | `101000h` | Начальная запись → directory |
| Directory | `102000h` | Начальная запись → page table |
| PT0 | `103000h` | 512 элементов по 8 байт |

Для 512 страниц по 4096 байт охвачен начальный диапазон **2 MiB**. Автор предварительно обнуляет четыре таблицы, затем заполняет младшие DWORD записей с `pg_flags=111b`; дополнительное продвижение указателя пропускает старшие 32 бита (p. 326–327). Эти адреса принадлежат **авторской тестовой раскладке**, не стандартному размещению таблиц.

## Что означает результат эксперимента

- `chk_longmode` → CF=1: авторский положительный ответ о поддержке (p. 324–325).
- После `set_efer_lme` цикл `chk_efer_lma` продолжает ожидание: без paging бит LMA ещё не установлен (p. 326).
- После подготовки таблиц и включения PAE/CR3/paging: LMA=1, но кодовый `L=0`, значит compatibility mode (p. 327).
- Gate с расширением до 16 байт успешно вызывается до long mode, но после — Bochs сообщает **`not 64-bit code segment in call gate 64`** (p. 328–329). Не выдавать это за проверку всех gate-сценариев.

## Безопасные действия и подтверждение

**Только пассивный анализ:** сверить записи `CPUID` и `EFER` в тексте, вывести числа уровней, объяснить ограничение 2 MiB и кадр вызова на основании 19.4. Запуск не проводился.

**Потенциально изменяющие состояния CPU:** `WRMSR`, переключение `CR4.PAE`, запись `CR3`, включение `CR0.PG`, правка GDT и page tables — критические действия внутри VM. Без изолированной среды и снимка состояния не выполнять. Документированного универсального rollback исходный фрагмент не предоставляет — **[Needs confirmation]**.

**Фиксируемый результат:** все четыре формы «поддержка / разрешение / активация / подрежим» правильно различены, а суждения о gate ограничены наблюдением 19.4.
