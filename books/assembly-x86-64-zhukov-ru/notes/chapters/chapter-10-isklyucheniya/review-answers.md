# Глава 10 — разбор контрольных вопросов по RAG

**Источник:** [review-questions.md](review-questions.md), canonical RAG PDF 177–196. Это анализ текста, **не** авторский ключ и **не** журнал работы отладчика. Номера Q1–Q13 принадлежат этому комплекту.

**Q1.** IVT: 256×4=**1024 байта**, начало линейной памяти. Смещения (hex): вектор 0→0000; 4→0010; 5→0014; 13→0034 (номер 13 в десятичной записи для GP); 020→0080, 021→0084, 080→0200. Младшее слово — IP, старшее — CS. Адреса из рисунка 10.1 зависят от сеанса (p. 177–178).

**Q2.** `int n` сохраняет FLAGS, CS, IP и загружает новый CS:IP из IVT. `iret` возвращает IP/CS/FLAGS. Ручной вызов ISR через дальний `call` предваряется `pushf`, чтобы обеспечить ожидаемый кадр возврата (p. 178, 181).

**Q3.** TSR-пример сохраняет 1 Кбайт, т. е. 64 параграфа. Для строки `mem /u` с MCB-сегментом `3632` адрес начала самого модуля — `3633`; числа принадлежат конкретному примеру. BIN с `org 0` имеет смещение входа 0. Собственный `DS=CS` у ISR нужен, поскольку регистр DS не устанавливается вызовом автоматически (p. 179–180).

**Q4.** Вектор 080 расположен по `0200`. Листинг 10.3 эквивалентно выполняет `pushf` и косвенный дальний вызов. Для BIN `entry=0`, для COM из 10.4 — `0107`. В 10.6 старый вектор сохраняют и потом восстанавливают (p. 180–182).

**Q5.** Три вызова функции DOS записывают в `trace` IP **команд после каждого `int 021`**. В 10.7 прежнему ISR передают управление через дальний `jmp` без собственного `iret`; в 10.8 прежний ISR вызывается как подпрограмма посредством `pushf/call`, затем свой `iret` (p. 183–185). Числа IP — [Needs confirmation].

**Q6.** `07e+1=07f` не переполняет знаковый byte, поэтому первое `into` пропускается; `07f+1=080` устанавливает `o=1`, поэтому второе `into` вызывает **4**; `int 4` делает это безусловно (p. 186).

**Q7.** Для `range dw -3,2` значения **−3** и **2** допустимы, **−4** и **3** нарушают границы. Исключение **5** сохраняет адрес текущей команды `bound`; без исправления причины та же проверка повторяется (p. 187).

**Q8.** Автор предлагает проверить, сохраняется ли при ошибке `div/idiv` адрес текущей либо следующей инструкции. В RAG **нет готового результата опыта**; ответ **[Needs confirmation]** (p. 187).

**Q9.** В программе `gp.asm` регистр EDI задаёт эффективный адрес больше `0ffff`, предел сегмента real mode в изложении книги. Автор ожидает **GP 13** и повторяющийся IP команды записи в `trace`; Bochs показывает `write beyond limit`. Исполнение не проводилось (p. 188–190).

**Q10.** NASM: `vect_0` — адрес, `[vect_0]` — содержимое. Для COM нужен `org 0x100`, при неоднозначной ширине — `byte/word/dword`; `%include` заменяет форму a86, `enter` задаётся явно. В образце нет привычного `.sym` (p. 190–192).

**Q11.** `%macro set_seg 2` использует два аргумента `%1/%2`; `%macro _exit 0-1 0` позволяет параметр по умолчанию. `.text/.data` хранятся в COM, `.bss` размещается за образом с резервированием `resw 128` и `resd 1` без сохранённых инициализаторов (p. 192–193).

**Q12.** `int 3` — одна ячейка кода; `int 080` — две. Поэтому двухбайтовая замена однобайтовой `inc ax` затрагивает начало следующей инструкции, как намеренно демонстрирует 10.16 (p. 193–194).

**Q13.** `t_flag` переключает бит 8 FLAGS через `pushf/pop ax/xor/push/popf`. Событие **1** происходит после команды при T=1; на входе в ISR T очищен, а `iret` восстанавливает сохранённый T. При заполнении `trace` обработчик 10.18 меняет сохранённый IP на путь восстановления IVT и сбрасывает сохранённый T, чтобы не войти в бесконечную трассу (p. 194–196).
