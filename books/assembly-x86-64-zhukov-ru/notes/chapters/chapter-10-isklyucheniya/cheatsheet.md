# Глава 10 — operational cheatsheet: исключения и IVT

**Источник:** canonical RAG PDF 177–196, `p0177:c01`–`p0196:c01`; примеры a86/a386/nasm, d86/d386 и Bochs из книги. **Никаких запусков в этом сеансе.**

## Symptom / problem framing

Программа ушла по неверному адресу после `int`, повторяет одну fault-команду, не возвращается через `iret`, потеряла исходный DOS-обработчик или отладчик остановился внутри изменённого кода. Диагностика: **номер вектора → смещение в IVT → кадр стека → адрес сохранённого IP → адреса старого/нового ISR → возможность безопасного восстановления**.

## Baseline

- **IVT:** 256 векторов по **4 байта**, линейные адреса 0000–03ff; вектор `n` в `n*4` (p. 177–178). Вектор `020` → `080`, `021` → `084`, `080` → `0200`.
- **Вектор:** младшее слово — IP, старшее — CS. Адреса в `fig. 10.1` — снимок конкретного окружения, не универсальные значения (p. 177–178).
- **`int n`:** сохранить FLAGS, CS, IP; загрузить CS:IP из IVT[n]; **`iret`** восстановит IP, CS и FLAGS. Для ручного `far call` к ISR нужен `pushf` (p. 178, 181).
- **`into`:** вызывает вектор **4** только при `o=1`; **`int 4`** безусловно (p. 185–186).
- **`bound`:** для `range dw -3,2` значения −4 или 3 вне диапазона; вектор **5**, возврат указывает на **текущую** команду (p. 187).
- **DIV/IDIV:** ошибочное деление → **0**; какой адрес сохраняется в кадре — вопрос автора, ответ **[Needs confirmation]** (p. 187).
- **GP:** в real mode использование 32-битного `EDI` с offset за `0ffff` → **13** в описанном эксперименте (p. 188–189).
- **Debug:** `int 3` — **1-байтная** команда, exception **3**; `t=1` порождает exception **1** после инструкции; `iret` восстанавливает `t` (p. 193–196).

## Read-only checks

1. По RAG и `.lst` проверить адрес вектора `4*n` и значения сохранённого `CS:IP` в кадре; не считать `700029/F000FF53` универсальными (p. 177–178).
2. Проследить `trace` в 10.9: после `into` с `o=0` записи нет, после `into` с `o=1` есть, после `int 4` есть (p. 186).
3. Отличать **trap** (последующая инструкция) и **fault** (текущая инструкция). `bound` без исправления ошибки повторяется (p. 187).
4. В NASM разделять `x` как адрес и `[x]` как содержимое, выставить `org 0x100`, проверить `byte/word/dword` и секции `.text/.data/.bss` (p. 190–193).
5. Для отладочных ловушек проверить длину команды и занятых байтов: `int 3` — один, `int 080` — два (p. 194).

## Interpretation

| Наблюдение | Интерпретация |
|---|---|
| `int 080` уходит к 0000:0000 | В IVT[080] ноль в показанном снимке; автор предупреждает о катастрофическом результате (p. 178). |
| После `iret` флаги не прежние | ISR или кадр стека могли изменить сохранённое FLAGS (p. 178, 195). |
| `BOUND` бесконечно повторяется | Адрес fault-команды сохранён как IP; она не была исправлена (p. 187). |
| Bochs пишет `write beyond limit` | Offset `EDI` превысил границу сегмента в примере GP (p. 188). |
| Состояние трассы достигает 128 записей | Ограничитель в ISR направляет выполнение на восстановление IVT (p. 186, 192). |
| Вторая точка останова портит следующий код | Два байта `int 080` перекрывают 1-байтный `inc ax` (p. 194). |

## Next action

Сначала реконструировать механизм **без записи IVT**. Для сравнения CPU состояния анализировать исходные листинги и их ожидаемые значения. Если требуется исполнение — отдельная восстановимая виртуальная машина с подтверждённым образом памяти, правильным обработчиком и снимком до старта.

## Modifying actions and rollback

В примерах `e32`, `f2m`, `es xchg` и установка IVT **переписывают системную память**; `DOS AH=031` оставляет модуль резидентным; `int 080` или GP/DIV fault может передать управление неправильному адресу; `pushf/popf`, `t_flag`, `iret` меняют флаги (p. 179–195).

В 10.6 показано сохранение старого IVT-вектора в стек с последующим восстановлением. В 10.7 старый вектор хранится в `vect_0` перед подменой `021` и восстанавливается до завершения. Но универсального способа отката **повреждённой IVT, PSP, кода и зависшего эмулятора** в RAG нет — **[Needs confirmation]**. Сохранение старого вектора само по себе не гарантирует безопасность ISR.

## Verification / acceptance

- Различить `int`, `into`, `bound`, `div`, GP и `int 3` по источнику, текущей/следующей точке возврата и номеру вектора.
- Найти пример `pushf; es call d[n_vect*4]` (10.3, p. 181) и два способа цепочки DOS: `jmp`/собственное `iret` (10.7/10.8, p. 184–185).
- Проверить конечный путь возврата после исчерпания буфера `trace`; в 10.18 дополнительно требуется снять `t` в сохранённых FLAGS, иначе получится бесконечная трассировка (p. 195–196).
