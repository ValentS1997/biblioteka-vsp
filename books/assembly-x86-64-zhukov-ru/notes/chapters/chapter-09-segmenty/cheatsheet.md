# Глава 9 — оперативная шпаргалка: сегментная адресация

**Provenance:** канонический RAG PDF 149–176, `p0149:c01`–`p0176:c01`. Синтаксис `a86/d86`, 16-битный реальный режим.

## Symptom / problem framing

Программа считывает не те данные после изменения `DS`, стек перестал работать после переноса `SS`, отладчик показывает метки не на тех адресах после дальнего `JMP`, или строковая операция пишет не в тот буфер. Проверять **базовый сегмент → смещение → адрес → режим передачи управления → состояние отладчика**.

## Baseline

- COM: в начале `CS=DS=SS=ES`, `IP=0100`, PSP — первые `0100` байтов, программа начинается со смещения `0100` (p. 149, 153).
- **Линейный адрес:** `segment * 010 + offset` (все числа hex). Пример `06312:0107 = 063227`; сегмент — 16-битный **номер параграфа**, не адрес байта (p. 152).
- По умолчанию: **CS:IP** — код, **DS** — данные через BX/SI/DI/константу, **SS:SP** — стек, **SS:BP** — данные через BP, **DS:SI** → **ES:DI** — строковое копирование (p. 151–153, 167).
- Видеопамять в тексте: `0b8000`; при смещении `160*20=0c80` адрес `0b8c80`, представимый как `0b800:0c80` и `0b8c8:0` (p. 154–155).
- Один операнд в машинном коде может иметь несколько адресных форм; `LEA` сохраняет эффективный адрес, не обращаясь к памяти (p. 150–151).

## Read-only checks

1. Снять в d86 значения `CS,DS,SS,ES,IP,SP,BP,SI,DI`; вычислить линейные адреса для **каждого** обращения. `BP` по умолчанию использует `SS`, а `BX` — `DS` (p. 151–153).
2. Просмотреть `.lst`, `sym` и `map` для смещений, размеров секций и релокаций, не доверять одной подписи метки после `leap1` (p. 158, 165).
3. При `MOVSB/MOVSW` проверить `DS:SI`, `ES:DI`, `CX`, флаг направления `D`; после изменения `DS` обязательно восстановить ожидаемое значение (p. 159–160).
4. В Bochs данные в Memory Dump **не обновляются автоматически**: повторить `F7` / `Ctrl+F7` (p. 152).
5. Перед анализом `push/call/enter/leave/ret` определить линейную вершину стека и места параметров `[BP+4]`, `[BP+6]` и локальной области `[BP-2]` (p. 170–171).

## Interpretation

| Наблюдение | Объяснение |
|---|---|
| `BP` читает не то, что `BX` | По умолчанию `SS` против `DS`, если их базы уже различны (p. 153, 167). |
| `rep stosw` пишет за пределами COM | Использует `ES:DI`, например видеоадрес `0b8000` (p. 154). |
| После `set_ds -9` программа читает PSP | Эффективное смещение прежнее, базовый `DS` уменьшен на `090` байтов (p. 159). |
| После `leap1 2` `sym` показывает неверные метки | При смещении CS/IP меняется логическое начало кода; исходные смещения символов не перекодируются (p. 158). |
| `call far` меняет CS, `retf` восстанавливает | Работа с разными секциями кода в EXE (p. 164–165). |
| `es call subr` не меняет адрес доступа | Префикс в этом варианте `call` бессмыслен: нет операнда памяти через DS (p. 171). |

## Next action

Сначала реконструировать адреса **без исполнения**. Затем читать нужные строки RAG и листинг, сверяя тип адресации и сегмент по умолчанию. Небезопасные действия с `SS:SP`, `CS:IP`, PSP, TSR, вектором 0 и BIOS/видеобуфером не выполнять в обычной среде.

## Modifying action

- `mov es,0b800` (макрос a86), `rep stosw`, `rep movsw` меняют сегментное состояние или память (p. 154–155, 159).
- `cli/sti` изменяют разрешение внешних прерываний при согласованной перенастройке `SS:SP` (p. 156–157).
- `leap1` и дальний `jmp` меняют `CS:IP`; `DOS 031` оставляет память резидентной (p. 158, 161).
- Макрос `fill 256` в `prep.8` **перезаписывает PSP** последовательностью байтов (p. 168).
- `reboot.com` с `jmp 0f000:0fff0` меняет поток исполнения на системный адрес (p. 171); не запускать.

## Verification / acceptance

- Контроль адреса `06312:0107 → 063227` и видеоадреса `0b800:0c80 → 0b8c80`.
- Для `ea_1.8` из p. 151 автор ожидает: `area` уменьшен на 1, `x` инвертирован, `push 055aa` обращается к `0100-2=0fe`; конкретное выполнение [Needs confirmation].
- Для `stack_1.8` проверить, что линейная вершина стека сохранилась, но доступная ёмкость уменьшилась (p. 156).
- Для `steps.8` сравнить, где действуют `DS/SS/CS/ES` и что не меняет префикс (p. 169–171).
