# Глава 9 — команды и контрольные действия с сегментами

**Источник:** canonical RAG PDF 149–176, листинги 9.1–9.16. Статус: команды описаны, **не выполнялись**. Часть строк — специальные макросы `a86`, а не однокомандные машинные инструкции.

| Команда/фрагмент | Класс | Значение/эффект в книге |
|---|---|---|
| `lea ax,[bp+x-s_top+si]` | Read-only вычисление адреса, изменение AX | Эффективный адрес, без обращения к памяти (9.1, p. 150–151). |
| `mov al,[bx]`, `not w[bp+...]` | Чтение/изменение данных | По умолчанию `DS:BX` или `SS:BP` (p. 151–153). |
| `push 055aa` | Изменение памяти/стека | Адрес по `SS:SP`; в 9.1 автор приводит смещение `0fe` (p. 151). |
| `r,06312,0107` в d86 | Read-only просмотр | Сегментный и эффективный адрес строк данных (p. 152). |
| `__debug.bat`, Bochs `F7/Ctrl+F7` | Запуск отладчика/просмотр | Дамп линейных или физических адресов; обновлять через повторный вызов (p. 152). |
| Bochs `Watch Write` / `Breakpoint ASM selected` | Отладочные остановы | Наблюдение записи в массив или точки кода (p. 152–153). |
| `mov es,0b800`, `mov di,160*20` | Изменение сегмента/индекса | Адресация текстового видеобуфера; первое — макрос a86 (p. 154, 160). |
| `mov ax,5 by '*'`, `cld; rep stosw` | **Запись в видеопамять** | Запись символов и атрибутов (9.2, p. 154). |
| `e1,041,7` | Read-only просмотр в d86 | Байта признаков клавиатуры по линейному адресу `0417` (p. 155). |
| `set_ss`, `mov sp,...`, `cli/sti` | **Высокорисковое изменение стека и IF** | Согласованное перенесение `SS:SP` (9.3–9.4, p. 156–157). |
| `leap0`, `leap1 2`, `jmp d[m1]` | **Дальний переход** | Запись нового `CS:IP`; преобразование адреса в двойном слове (9.5–9.6, p. 157–158). |
| `set_ds -9` | **Изменение DS** | Смещение обращений данных в PSP, не менять без сохранения состояния (p. 159). |
| `mov ds,0b800`, `lea di,buf`, `rep movsw`, `mov ds,cs` | **Копирование видеоданных в память**, восстановление DS | `DS:SI` → `ES:DI` (9.7, p. 159–160); сегментные `mov` — макросы a86. |
| `mov ah,031`, `mov dx,p_sz`, `int 021` | **TSR** | DOS сохраняет часть памяти программы (9.8, p. 161). |
| `mem /u`, `jmp base:0100` | Просмотр / **дальний переход к TSR** | Повторный запуск оставшегося в памяти фрагмента (9.9, p. 162). |
| `D1 segment`, `C2 segment`, `_stack segment stack` | Сборка/размещение | Отдельные именованные секции (9.10, p. 163–164). |
| `a86 +O ea2.08 +HL5` | Трансляция/запись файлов | Формирование `.obj` и `.lst` в объектном режиме (p. 164). |
| `warplink /mx ea2.obj` | Компоновка/запись файлов | EXE и подробная map секций (p. 165). |
| `call far work_with_area`, `retf` | Межсегментное управление | Вызов и возврат с изменением CS (p. 163–165). |
| `extrn work_with_area:far, x:word`, `public work_with_area,x` | Ссылки между OBJ | Экспорт и импорт имён (9.11a/б, p. 165–166). |
| `warplink /mx ea2_1.obj ea2_2.obj` | Компоновка | Объединение модулей и `segment public` (p. 166). |
| `cs mov [bx],bl` / `cs movsb 4` | **Запись/копирование PSP** | Переназначение сегмента для обращения к памяти (9.12a/б, p. 167–170). |
| `ss not w0`, `not b cs:[bp]` | Изменение памяти с префиксом | Явный сегмент вместо стандартного (p. 170–171). |
| `enter 2`, `leave`, `ret 4` | Стековый кадр/возврат | Параметры `[bp+4],[bp+6]` и локальное `[bp-2]` (9.12б, p. 170). |
| `les di,d[far_adr]`, `cs lds si,d[far_adr]` | **Загрузка сегмента и регистра** | Младшее слово → индекс, старшее → ES/DS (9.14, p. 172). |
| `jmp 0f000:0fff0` | **Опасная передача управления** | Учебный пример `reboot.8`, не запускать (p. 171). |

## Разбор типов адреса

```text
Линейный адрес = (сегмент << 4) + смещение
06312:0107 -> 063120 + 0107 = 063227
0b800:0c80 -> 0b8000 + 0c80 = 0b8c80
0b8c8:0000 -> 0b8c80
```

**Не путать** с реальной записью байтов по `0:0` или командой перехода `jmp 0f000:0fff0`. Четвёртая задача главы просит вызвать системный обработчик через адрес, хранящийся в векторе `0:0` (p. 173). В текущей работе это только исходное условие, исполняемый рецепт намеренно не приводится.

## Проверка и rollback

Пассивно проверять `.lst/.map`, пары `CS:IP/DS:SI/ES:DI/SS:SP`. Для экспериментов использовать изолированную среду со снимком, потому что `rep stosw`, `fill`, TSR и стековые изменения пишут в реальные области памяти эмулятора.
