  Еще одна категория задач в этом сценарии — классификация, где вывод
   должен представлять собой действительные классы.
2. Задачи, результаты которых используются приложениями на следующих
   этапах. В этом сценарии для самой задачи структурированные данные не тре
   буются, но, поскольку результаты выводов требуются другим приложениям,
   последние должны иметь возможность их анализировать.
   Так, если вы используете модель AI для написания электронного письма, само
   письмо не обязательно должно быть структурированным. Однако исполь
  зующему его приложению может потребоваться, чтобы оно соответствовало
   конкретному формату, скажем, было в формате JSON-документа с опреде
  ленными ключами, например {"title": [TITLE], "body": [EMAIL BODY]}.
  Это особенно важно для агентных рабочих процессов, в которых вывод модели
   часто передается в качестве входных данных в инструменты, которые может
   использовать модель, как обсуждается в главе 6.

К инструментам, поддерживающим структурированные результаты, относятся
Guidance (https://github.com/guidance-ai/guidance), Outlines (https://github.com/
dottxt-ai/outlines), instructor (https://github.com/instructor-ai/instructor) и llama.cpp
(https://github.com/ggerganov/llama.cpp/discussions/177). Кроме того, каждый по
ставщик моделей может применять собственные методы для совершенствова
ния способности моделей генерировать структурированный вывод. Компания
OpenAI первой из поставщиков моделей ввела режим JSON (https://oreil.ly/
NxZDF) в свой API генерации текста. Обратите внимание: режим JSON в API
обычно гарантирует только то, что результаты выводов будут представлять
собой корректные JSON-файлы, и не отвечает за контент JSON-объектов.
Сгенерированные JSON-файлы могут быть корректными во всем остальном,
но оказаться усеченными и, следовательно, не поддающимися анализу, если
генерация прекратится слишком рано, например, при достижении максимальной
длины выходного токена. Однако если максимальная длина токена чересчур
велика, ответы модели будут создаваться слишком медленно и стоить дорого.

На рис. 2.20 показаны два примера применения инструмента Guidance для
генерации результатов, ограниченных до набора вариантов и регулярных вы
ражений.
