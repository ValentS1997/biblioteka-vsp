230        Глава 11. Финальные советы по экономии времени

Применяйте контроль версий к повседневным файлам
Допустим, что нам требуется отредактировать файл, но мы опасаемся его испор-
тить. Можно сделать резервную копию для надежности и отредактировать ори-
гинал, зная, что сможем восстановить резервную копию, если допустим ошибку:

$ cp myfile myfile.bak

Но это решение не масштабируется. Что, если у нас есть десятки или сотни фай-
лов и над ними работают десятки или сотни людей? Системы контроля версий,
такие как Git и Subversion, были изобретены для решения этой проблемы путем
отслеживания нескольких версий файла.

Git широко используется для поддержки исходного кода программного обеспече-
ния, но я рекомендую изучить и использовать его для любых важных текстовых
файлов, в которые могут вноситься изменения. Возможно, это личные файлы
или файлы операционной системы в /etc. В разделе «Путешествие с вашим
окружением» на с. 132 предлагалось отслеживать файлы конфигурации bash
с помощью контроля версий.

При написании этой книги я использовал Git, чтобы сравнивать разные способы
подачи материала. Без особых усилий я создал и отслеживал три разные версии
книги: одну с полным текстом, другую, содержащую только главы, которые
я отправил своему редактору на проверку, и одну для экспериментов, в которой
я пробовал новые идеи. Если мне не нравилось написанное, всего лишь одна
команда восстанавливала предыдущую версию файла.

Изучение Git выходит за рамки этой книги, но вот несколько примеров команд,
которые покажут базовый рабочий процесс и, возможно, понравятся вам. Пре-
образуем текущий каталог (и все его подкаталоги) в репозиторий Git:

$ git init

Отредактируем некоторые файлы. После этого добавим измененные файлы в не-
видимую «промежуточную область», что заявляет о нашем намерении создать
новую версию:

$ git add .

Создаем новую версию, оставив комментарий для описания изменений в файлах:

$ git commit -m"Changed X to Y"

Просматриваем историю версий:

$ git log
