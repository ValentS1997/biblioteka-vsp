# Cheatsheet — глава 2. Администрирование вычислительных сетей

**RAG-only:** PDF p. 51–85; p0051-c01–p0085-c01; источник SHA256 \`a5d6a2677d4b0e33a34dec3b7aae8b77f711bb748046d25766becb479f66663f\`. Учебная памятка — не готовый production runbook.

## Symptom / problem framing
Отсутствие связи или отклика может иметь причины в физической среде, канальном обмене, маршрутизации, транспортных протоколах и правах на ресурс. Отдельно разбирать разрыв шинного сегмента/отсутствие терминаторов, отказ центрального узла звезды, нарушение кольца, IP-маршрут или несоответствие учётных записей (p0053–p0057, p0060–p0066, p0070–p0076, p0082–p0084).

## Read-only checks
1. Установить реальные узлы и соединения, тип сетевой среды, наличие/состояние терминаторов **для описанного варианта шины** (p0052–p0055).
2. Зафиксировать MAC и IP адреса интерфейсов, IPv4/IPv6, маску/сеть, соседний маршрутизатор, записи таблицы маршрутов **не изменяя конфигурацию** (p0068–p0076).
3. Выяснить, является ли ресурс частью локальной SAM или доменной базы; определить субъекта и его учетную запись для разрешения доступа (p0082–p0084).
4. **Активный тест с нагрузкой, не read-only:** \`ping <TARGET_IP>\` генерирует ICMP-трафик, когда разрешён тест. Точный пример источника: \`ping 172.16.20.2\` (p0071-c01); заменить IP целевым разрешённым адресом.

## Interpretation
- Шина — общий сегмент с терминаторами; звезда зависит от центрального оборудования; кольцо описано через передачу маркера. Дерево и гибриды сочетают компоненты (p0053–p0058).
- OSI семиуровневая учебная модель; протоколы реальных систем могут совмещать несколько уровней (p0058–p0059).
- MAC адрес кадра описывает получателя на текущем канальном сегменте; IP адрес назначения указывает конечный сетевой узел. При переходе между сетями изменяется обрамление кадра, а не обязательно IP-адрес назначения (p0064, p0072–p0074).
- Маршрутизатор использует сведения таблицы маршрутов для следующего шага; статическую запись вносит администратор, динамическая обновляется по протоколам обмена сведениями (p0070–p0077).
- Рабочая группа: отдельные локальные SAM; домен: общие доменные аккаунты и репликация между контроллерами (p0082–p0084).

## Next action
Локализовать задействованный уровень и изменение состояния: среда → кадр → IP/маршрут → транспорт → служба/доступ. Сопоставить наблюдения с ожидаемыми параметрами **конкретной** сети. Без измерений нет основания утверждать root cause; команда для реализации: [Needs confirmation].

## Modifying action
Изменяемые объекты по главе: конфигурация активных устройств, физическое соединение/топология, статическая таблица маршрутов, локальные или доменные учетные записи (p0051–p0052, p0070–p0071, p0082–p0084). Риск: потеря соединений, нарушение доступности или прав доступа. Требуются локальное разрешение на изменение, baseline и проверенный план; конкретные конфигурационные команды **не предоставлены источником**.

## Verification / acceptance checks
Повторить разрешённые проверки связности, маршрутизации и авторизованного доступа; сравнить с записанным baseline. Точные пороги, SLA, узлы, критерии и значения: [Needs confirmation].

## Rollback
Книга не даёт исполняемого плана отката маршрутов, физической топологии или базы SAM/домена. Требуется независимая процедура, согласованная с владельцем инфраструктуры: **[Needs confirmation]**.

## Ограничения источника
p0069 описывает anycast неоднозначно; p0071 делает необоснованно категоричный прогноз первого ping timeout; расшифровки FTP различаются между p0068 и p0080. Проблемы сохранены в [source-findings.md](source-findings.md). Не добавлять из памяти \`ip route\`, \`traceroute\`, \`nslookup\` или команды настройки сетевых устройств.
