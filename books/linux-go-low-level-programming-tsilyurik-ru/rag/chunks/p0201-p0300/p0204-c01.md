Тот же функционально код на Go:

skoc.go :

package main

import (
        "fmt"
        "math"
        "math/rand"
        "os"
        "strconv"
)

func main() {
        n := 1000
        if len(os.Args) > 1 {
                n, _ = strconv.Atoi(os.Args[1])
        }
        s1, s2 := 0., 0.
        for i := 0; i < n; i++ {
                r := rand.NormFloat64()
                s1 += r
                s2 += r * r
        }
        s1 /= float64(n)
        s2 = s2/float64(n) - s1*s1
        fmt.Printf("%d чисел: среднее=%f, СКО=%f\n", n, s1, math.Sqrt(s2))
}

Любопытно видеть насколько близки два показанных примера! Сборка:

$ make
go build -o sko -compiler gc sko.go
g++ -o skoc -lm skoc.cc

И выполнение, для последовательности из 100 миллионов случайных значений:

$ time ./sko 100000000
100000000 чисел: среднее=0.000017, СКО=0.999985
real      0m2,725s
user      0m2,728s
sys       0m0,004s

$ time ./skoc 100000000
100000000 чисел: среднее=-3.48074e-05, СКО=1.00006
real      0m13,505s
user      0m13,505s
sys       0m0,000s

Достаточно интересное соотношение времён выполнения для Go и C++ … но это, скорее всего,
никак не связано с вычислениями, а определяется используемыми генераторами случайных чисел
и тем, с какой тщательностью они проводят генерацию.
