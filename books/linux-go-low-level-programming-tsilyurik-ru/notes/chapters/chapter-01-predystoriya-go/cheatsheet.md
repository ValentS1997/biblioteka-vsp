# Cheatsheet — глава 1 «Предыстория Go»

## Symptom / problem framing

Исходный вопрос главы: зачем нужен ещё один язык программирования и какие задачи проектировщики Go пытались решить.

Основные мотивы по источнику:

- современная альтернатива C без тяжеловесности C++;
- естественная поддержка параллельных вычислений;
- переносимость между ОС и аппаратными архитектурами;
- высокая скорость компиляции;
- производительность скомпилированного кода, близкая к C для сопоставимых задач;
- удобная документированность и самостоятельная экосистема.

## Baseline / context

Автор рассматривает Go только в контексте Linux и сравнивает его с C, C++, Java, Python и Rust.

Ключевая рамка:

- Go — компилируемый язык;
- результат сборки — исполнимый бинарный файл;
- `go run` в источнике описывается как скрытая быстрая компиляция с последующим выполнением, а не интерпретация;
- benchmark зависит от класса задачи, версии реализации и конкретного окружения.

## Read-only checks

Source-confirmed проверки окружения:

```bash
dnf list 'golang*'
dnf list 'golang*' | wc -l

gcc --version
g++ --version
clang++ --version
go version
javac --version
java --version

ls -l fibo_c
ls -l fibo_cc
ls -l fibo_cl
ls -l fibo_go
ls -l fibo.class
ls -l fibo_rs
file fibo.class
```

## Interpretation

Не делать универсальных выводов из одного теста.

Источник показывает:

- один рекурсивный Fibonacci workload;
- одинаковую постановку задачи для нескольких языков;
- явную фиксацию версий инструментов;
- результаты конкретной машины/окружения;
- предупреждение автора, что относительная производительность меняется по классам задач.

Поэтому корректная интерпретация внутри главы: benchmark иллюстрирует различия конкретной реализации задачи, а не устанавливает абсолютный рейтинг языков.

## Next action

После историко-мотивационного введения следующая глава переходит к развёртыванию Go-экосистемы в Linux.

Для текущей главы практический next action: перед собственным сравнением зафиксировать версии компиляторов/рантаймов и использовать эквивалентную постановку задачи.

## Modifying action

Компиляция создаёт или заменяет исполнимые/байткод-файлы:

```bash
gcc fibo_c.c -O3 -o fibo_c
g++ fibo_cc.cc -O3 -o fibo_cc
clang++ -O3 -I/usr/include/c++/11/ -I/usr/include/x86_64-linux-gnu/c++/11 \
  -L /usr/lib/gcc/x86_64-linux-gnu/11 fibo_cc.cc -o fibo_cl

go build -o fibo_go fibo_go.go
javac fibo.java
rustc fibo_rs.rs
```

Effect: создаются артефакты сборки в текущем каталоге.

Risk: команды зависят от наличия соответствующих toolchains, библиотек и путей из окружения автора. Команда Clang содержит конкретные Ubuntu/GCC 11 include/library paths.

## Verification / acceptance checks

После сборки источник проверяет созданные файлы через:

```bash
ls -l fibo_c
ls -l fibo_cc
ls -l fibo_cl
ls -l fibo_go
ls -l fibo.class
ls -l fibo_rs
file fibo.class
```

Для benchmark все варианты должны вычислять одно и то же значение для одного аргумента; в примере для `45` выводится `1836311903`.
