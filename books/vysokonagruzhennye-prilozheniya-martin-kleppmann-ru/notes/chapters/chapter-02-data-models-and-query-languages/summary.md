# Резюме главы 2

Источник: раздел 2.4 «Резюме», `p0090:c01`–`p0091:c01`, PDF 90–91.

Глава рассматривает модели данных как разные способы представить структуру предметной области и связи между данными.

Исторически иерархическая модель хорошо выражала дерево, но плохо подходила для связей «многие-ко-многим». Реляционная модель решила эту проблему другим представлением связей. Позднее появились нереляционные модели, лучше подходящие для отдельных сценариев.

## Три основных семейства

### Relational

Подходит для широкого класса структурированных данных и связей, где joins и references являются естественной частью модели.

### Document

Ориентирована на сценарии, где данные приходят как отдельные документы, а links между документами сравнительно редки. Tree-like structure и locality могут упростить application model.

### Graph

Ориентирована на противоположный случай: данные потенциально сильно взаимосвязаны, а traversing relationships является центральной операцией.

Ни одна модель не является универсальной. Их можно эмулировать друг через друга, но результат часто становится неудобным, поэтому разные задачи используют разные systems/models.

## Schema

Document и graph systems часто не требуют жесткой schema при записи. Это не означает отсутствия структуры: application code все равно ожидает определенную форму данных.

Различие лучше выражать как:

- `schema-on-write` — структура проверяется при записи;
- `schema-on-read` — структура интерпретируется/проверяется при чтении.

## Query languages

Глава рассматривает SQL, MapReduce, MongoDB aggregation pipeline, Cypher, SPARQL и Datalog. CSS и XSL/XPath используются как параллели declarative style.

Основная идея декларативного запроса: описать pattern/result, а не пошаговый algorithm. Это дает implementation больше свободы оптимизировать execution.

## Итог

Выбор модели данных должен исходить из структуры данных, cardinality relationships и типов запросов. При необходимости приложение может использовать разные модели для разных задач вместо попытки найти единственное универсальное хранилище.
