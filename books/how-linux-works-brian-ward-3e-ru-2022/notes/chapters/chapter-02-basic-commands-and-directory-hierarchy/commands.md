# Команды и инструменты — глава 2

**Контракт:** только команды, синтаксис и операции, явно присутствующие в `p0039:c01`–`p0078:c01` (PDF/печатные с. 39–78). Без достройки по памяти. Обозначения `file`, `dir`, `pid`, `command`, `target`, `linkname` — **условные аргументы из источника**, а не реальные имена объектов.

**Классы:** `RO` — read-only observation; `WG` — workload-generating/interaction; `SC` — state-changing (включая состояние текущей оболочки). Запись `ls > f` считается **SC**, хотя `ls` отдельно — RO.

Строки `grep -i`, `sort -n`, `diff -u`, `tail +n` выше обозначают **опции или частичный синтаксис**, а не готовую команду со всеми аргументами. Полные примеры приведены только там, где они имеются в RAG.

### Потоки и управление интерактивной оболочкой

- `cat` без аргументов: читает stdin терминала и воспроизводит строки; `Ctrl+D` на пустой строке посылает EOF (`p0042:c01`).
- `Ctrl+C`: обычно завершает программу; `Ctrl+Z`: приостанавливает foreground job, **не** завершает её (42,64–65).
- `less`: `Space` — вперёд, `b` — назад, `q` — выход, `n` — следующее совпадение. Назад в RAG напечатано как `-?ord` — **[Needs confirmation]**, см. `source-findings.md` (49).
- Shell editing (55): `Ctrl+B/F` курсор, `Ctrl+P/N` история, `Ctrl+A/E` границы строки, `Ctrl+W/U/K` удаление части ввода, `Ctrl+Y` вставка.
- `vi`, `Emacs`, `nano`, `Pico` — редакторы, а не готовые примеры редактирования конкретного файла. `screen`/`tmux` упомянуты как работа с терминальными сессиями (55–56,65).
- `ps` поля `PID`, `TTY`, `STAT`, `TIME`, `COMMAND`; `S` sleeping, `R` running. PID может повторно использоваться после завершения процесса (62–63).

## 2. Shell syntax: ввод-вывод, окружение и раскрытие

| Синтаксис источника | Класс | Эффект / риск | Verification / rollback |
|---|---|---|---|
| `echo Hello there.` | RO | Печатает строку в stdout | Виден вывод; [Not applicable] |
| `echo *` / `echo '*'` | RO | Применяется glob / выводится литерал | Сопоставить с именами файлов; [Not applicable] |
| `STUFF=blah` | SC: shell | Установить переменную текущей оболочки | `echo $STUFF`; прежнее значение: [Needs confirmation] |
| `export STUFF` | SC: shell | Сделать переменную окружения доступной дочерним процессам | `echo $STUFF` показывает значение, **не** отдельно статус export; полная проверка: [Needs confirmation] |
| `PATH=dir:$PATH`, `PATH=$PATH:dir` | SC: shell | Добавить каталог для поиска программ в начало/конец; меняется порядок поиска | `echo $PATH`; неправильный PATH — открыть новую оболочку (§2.9) |
| `command > file` | SC: filesystem | Создать или **перезаписать** файл | Проверить целевой файл; rollback: [Needs confirmation] |
| `command >> file` | SC: filesystem | Дополнить файл | Проверить добавленный текст; rollback: [Needs confirmation] |
| `command 2> file` | SC: filesystem | Перенаправить stderr в файл (`2>` показано в составе примера `ls`) | Сверить stderr; rollback: [Needs confirmation] |
| `ls /fffffffff > f 2> e` | SC: filesystem | `f` получает stdout, `e` — stderr, файлы создаются/перезаписываются | Сверить `f`/`e`, не использовать реальные файлы без проверки |
| `ls /fffffffff > f 2>&1` | SC: filesystem | Объединить stderr со stdout, записать в `f` | В файле `f`; rollback: [Needs confirmation] |
| `head < /proc/cpuinfo` | RO | Читает stdin из указанного файла | Вывод команды; [Not applicable] |
| `head /proc/cpuinfo \| tr a-z A-Z` | RO | Преобразование потока через `tr` | Вывод в stdout; [Not applicable] |
| `set -C` | SC: shell | Bash запрещает затирание существующих файлов оператором `>` (§2.14) | Проверка настройки и точный откат: [Needs confirmation] |

Оператор `*` разворачивается **оболочкой до вызова команды**; `grep` использует **регулярные выражения**, имеющие другой синтаксис. Нельзя бездумно смешивать glob и regexp (§2.4.4–2.5.1).

## 3. Операции изменения состояния — точная форма автора

| Пример/инструмент | Класс | Изменение | Риск и проверка | Rollback |
|---|---|---|---|---|
| `cd dir`, `cd` | SC: shell | Текущий каталог | `pwd` / `pwd -P` | Возврат в исходный каталог [Needs confirmation] |
| `cp file1 file2`, `cp file dir` | SC: filesystem | Копировать файл | Перед запуском проверить исходный/целевой пути; `ls -l` | [Needs confirmation] |
| `mv file1 file2` | SC: filesystem | Переименовать/переместить | Убедиться в корректности путей; `ls -l` | [Needs confirmation] |
| `touch file` | SC: filesystem | Новый пустой файл / обновление mtime | `ls -l file` показывает время | [Needs confirmation] |
| `mkdir dir` | SC: filesystem | Создать каталог | `ls -l` для каталога | [Needs confirmation] |
| `rmdir dir` | SC: filesystem | Удалить **пустой** каталог | При содержимом отказывает | [Needs confirmation] |
| `rm file` | SC: filesystem, destructive | Удалить файл | Автор предупреждает о возможной необратимости | Нужна предшествующая копия; иначе [Needs confirmation] |
| `rm -r dir` | SC: filesystem, **high risk** | Рекурсивно удалить каталог и содержимое | **Не** сочетать `-r` с `*`; до запуска перепроверить | [Needs confirmation], данные могут быть утрачены |
| `passwd`, `chsh` | SC: account | Сменить пароль / оболочку | Влияние на доступ пользователя; глава описывает диалог без полноценного rollback | [Needs confirmation] |
| `chmod g+r file`, `chmod o+r file`, `chmod go+r file`, `chmod go-r file` | SC: ACL bits | Добавить/снять разрешения | `ls -l`, права каталога отличаются по смыслу | Исходный режим [Needs confirmation] |
| `chmod 644 file` | SC: ACL bits | Задать полный восьмеричный режим | Проверить `ls -l` | [Needs confirmation] |
| `umask 022`, `umask 077` | SC: shell | Изменить права **новых** объектов | Не возвращает права уже созданным файлам | Предыдущая umask [Needs confirmation] |
| `ln -s target linkname` | SC: filesystem | Создать символьную ссылку | Проверить порядок аргументов; `ln` без `-s` означает hard link | Удалить *только неверную* ссылку после проверки; точный план [Needs confirmation] |
| `kill pid`, `kill -STOP pid`, `kill -CONT pid` | SC: process | TERM / остановить / продолжить | PID может быть переиспользован; `ps` / `jobs` | STOP → CONT с проверкой PID; TERM [Needs confirmation] |
| `kill -9 pid`, `kill -KILL pid` | SC: process, high risk | Принудительно завершить процесс | В книге — крайняя мера; нет времени на cleanup | [Needs confirmation] |
| `fg`, `bg`, `gunzip file.gz &` | WG/SC: job/file | На передний план/в фон; распаковка в фоне | stdout/stderr могут мешать терминалу; фоновые задания могут ждать ввода | [Needs confirmation] |
| `gzip file`, `gunzip file.gz`, `gunzip file.tar.gz` | SC: filesystem | Сжать/распаковать файловые данные | Меняет набор файлов/суффикс | [Needs confirmation] |
| `tar cvf archive.tar file1 file2 ...` | SC: filesystem | Создать tar-архив | Проверить исходные пути и цель | [Needs confirmation] |

| `zcat file.tar.gz \| tar xvf -` | SC: filesystem | Извлечь архив через поток | То же, что извлечение из tar, но без промежуточного файла | [Needs confirmation] |

| `visudo` | SC: privileged/editor | Редактировать sudoers с проверкой синтаксиса | Конфигурация sudo критична; не выполнять без change plan | [Needs confirmation] |

### Сведения об архивировании (PDF 71–74)

- `tar` **архивирует**, `gzip` **сжимает**; `tar.gz` предполагает два слоя.
- `tar`: `c` создать, `x` извлечь, `t` перечислить, `v` подробный вывод, `f` аргумент с именем архива; `z` подключает gzip. Рекомендуется проверить содержимое (режим `t`) перед извлечением (§2.18.2–2.18.4).
- `zcat` функционально сопоставлен с `gunzip -dc`; `unxz`, `bunzip2`, `zip`, `unzip` упомянуты, но без полных безопасных примеров для каждого варианта.
- Расширение для bzip2 в `p0073:c01` указано как `.z2` — **[Needs confirmation]**, источник не исправлен.

### Сигналы, процессы и привилегии (PDF 62–66, 77–78)

- `kill` по умолчанию посылает **TERM**; `Ctrl+C` соответствует INT; `Ctrl+Z` соответствует TSTP; `kill -STOP pid` и `kill -CONT pid` показывают приостановку/возобновление.
- `jobs` показывает задания текущего терминала; PID могут переиспользоваться, **не** посылать сигнал по устаревшему PID.
- `sudo vipw` и `visudo` — учебные примеры **высокого риска**; не применять их как эксплуатационную процедуру из этой сводки.
- Строки `User_Alias ...`, `NOPASSWD: ALL` в `/etc/sudoers` из §2.20.2 описывают **неограниченное** повышение привилегий без пароля; не приводятся здесь как copy-paste настройка. См. `source-findings.md` о границах применимости.

## 5. Acceptance / rollback discipline

Read-only команды оцениваются по релевантности результата. Для каждой `SC` операции требуется контроль исходного пути/PID/режима, ожидаемый эффект, readback и откат. Если источник не описывает такую процедуру, обозначение **[Needs confirmation]** означает реальный стоп-фактор на рабочем сервере, а не разрешение восполнить действия «по привычке».
