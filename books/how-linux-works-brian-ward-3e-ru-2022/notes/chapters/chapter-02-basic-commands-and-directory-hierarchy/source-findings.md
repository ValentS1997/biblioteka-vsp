# Source findings — глава 2

**Контракт:** исходный RAG `p0039:c01`–`p0078:c01`, PDF/печатные с. 39–78. Не является слоем тихого исправления текста или проверки работоспособности на реальном хосте. Внешние источники / model memory не использовались.

## F-01 — [Needs confirmation] Нотация обратного поиска в `less`

- **Locator:** `p0049:c01` (раздел 2.5.2, PDF 49).
- **Вариант в тексте источника:** `/word` для поиска вперёд, **`-?ord`** для поиска назад; `n` — продолжить найденное совпадение.
- **Наблюдение:** второй токен визуально отличается от первой нотации и не подтверждён дополнительным примером внутри главы.
- **Классификация:** возможная **[Source extraction issue]** или опечатка в исходном тексте; без чтения исходного изображения установить природу нельзя.
- **Решение:** не нормализовать и не выдавать `-?ord` за проверенный keyboard sequence; в `commands.md` указать **[Needs confirmation]**.

## F-02 — [Needs confirmation] Расширение bzip2

- **Locator:** `p0073:c01` (раздел 2.18.5, PDF 73).
- **Вариант источника:** `xz` создаёт файлы `.xz`; рядом с названием `bzip2` в RAG указано **`.z2`**. Упомянуты `unxz`, `bunzip2`.
- **Наблюдение:** это точная запись в извлечённом тексте. Внутриглавного второго подтверждения расширения нет.
- **Классификация:** **[Needs confirmation]**, возможная **[Source wording/code mismatch]** / **[Source extraction issue]**; конкретное исправленное расширение **не предлагается** из внешнего знания.
- **Решение:** сохранить токен `.z2` как source variant и не использовать его для автоматизации без независимой проверки.

## F-03 — [Source wording/code mismatch] Рекомендация по отсутствующему пути в примере ошибки

- **Locator:** `p0060:c01` (§2.15.1, PDF 60).
- **Пример ошибки:** `scumd: cannot access /etc/scumd/config: No such file or directory`.
- **Следующий совет автора:** «скорее всего» следует **создать каталог** `/etc/scumd/config`.
- **Возможная неоднозначность:** ошибка подтверждает отсутствие объекта по пути, но **не** подтверждает, должен ли конечный компонент `config` быть файлом или каталогом; дополнительной информации о фиктивной программе нет.
- **Решение:** в шпаргалке сохраняется верный диагностический принцип (проверить первую ошибку и путь), но создание указанного каталога не выдается за готовое исправление. Тип объекта: **[Needs confirmation]**.

## F-04 — [Source extraction issue] Схемы рисунков не являются доступными мультимодальными RAG-объектами

- **Рис. 2.1:** подпись о составных частях режима файла в `p0066:c01`; текст о `rwx` и владельцах — `p0067:c01`. Недоступно точное визуальное расположение блоков.
- **Рис. 2.2:** подпись об иерархии `/`, `/usr`, `/var` в `p0074:c01`; текстовое описание каталогов — `p0074:c01`–`p0076:c01`. Не подтверждено точное дерево на рисунке.
- **Evidence:** `rag/manifest.yaml`, `known_limitations`: изображения и диаграммы не кодируются как самостоятельные мультимодальные RAG-объекты.
- **Решение:** Mermaid и два SVG опираются только на написанное в тексте и **не** являются копиями оригинальных рис. 2.1/2.2.

## F-05 — [Needs confirmation] Контекстная безопасность примера sudoers

- **Locators:** `p0077:c01`–`p0078:c01` (§2.20.2).
- **Варианты источника:** строки правил с `User_Alias ADMINS`, `NOPASSWD: ALL`, альтернативой `(ALL)` и правило `root ALL=(ALL) ALL`.
- **Факт источника:** автор поясняет выдачу права запуска любых команд от root без ввода пароля и рекомендует применять `visudo` для синтаксической проверки.
- **Риск:** это **широкая** привилегия; контекст доверия пользователей, границы хостов и журналирования в книге не превращаются в безопасную политику конкретной инфраструктуры.
- **Решение:** описание сохраняется как учебный пример, не как рекомендуемая настройка. В `commands.md` нет готового блока на вставку в production `/etc/sudoers`.
