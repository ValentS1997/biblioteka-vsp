# Cheatsheet — глава 2 «Основные команды и иерархия каталогов»

**Source:** `how-linux-works-brian-ward-3e-ru-2022:p0039:c01`–`p0078:c01`; PDF/печатные с. 39–78. Только `rag_only`. В таблицах ниже команды и утверждения не выходят за рамки главы.

## Symptom / problem framing — постановка задачи

Глава даёт инструменты для типовых ситуаций: неизвестно, какой файл/каталог используется; не получается найти команду или файл; неизвестно, куда направляется вывод; неясно, почему программа завершилась с ошибкой; нужно отличать работающий процесс от приостановленного; требуется проверить права, разобрать архив или выполнить ограниченную привилегированную операцию.

**Правило книги при ошибке:** сначала разобрать **первое** диагностическое сообщение, выделить программу, путь и текст причины (`p0060:c01`); дополнительные сообщения могут быть следствиями. Это не разрешение автоматически создавать отсутствующие системные пути.

## Baseline / context — исходная модель

| Компонент | Что требуется понимать | Provenance |
|---|---|---|
| Shell | Команда = программа или shell builtin + аргументы/параметры; `$` в примере — приглашение, а не символ для ввода | 40–41 |
| cwd / path | `/` — корень, `..` — родитель, `.` — текущий каталог; `cd` меняет рабочий каталог текущей оболочки | 45–46 |
| glob | `*` = 0+ символов, `?` = 1 символ; расширение происходит **до запуска** команды | 46–47 |
| dotfiles | `ls` скрывает имена с точкой, `ls -a` показывает; обычный glob `*` их не охватывает | 51 |
| env / PATH | `export` делает переменную доступной дочерним процессам; PATH содержит разделённые `:` каталоги в порядке поиска | 52–53 |
| stdio | stdin — ввод, stdout — обычный вывод, stderr — диагностический вывод | 42–43, 58–59 |
| process / PID | `ps` показывает PID/TTY/STAT/TIME/COMMAND; CPU TIME не равен прошедшему wall time | 62–63 |
| permission bits | тип объекта + права user/group/other (r/w/x); у каталога x нужен для доступа к файлам внутри | 66–69 |
| root/sudo | `sudo` повышает полномочия для одной команды; права задаёт `/etc/sudoers`, автор рекомендует `visudo` | 77–78 |

## Read-only checks — сначала наблюдение

Команды ниже **не предписывают модификации** и представлены в границах главы:

```sh
pwd
pwd -P
ls -l
ls -a
file file
grep root /etc/passwd
find dir -name file -print
head /etc/passwd
tail /etc/passwd
diff file1 file2
ps
ps auxw
jobs
groups
man ls
man -k keyword
man 5 passwd
journalctl SYSLOG_IDENTIFIER=sudo
tar ztvf file.tar.gz
```

Заменить `file`, `file1`, `file2`, `dir` и имена архивов на проверенные объекты **до выполнения**. `tar ztvf` читает список архива, не извлекает файлы. `journalctl` показан только для записей sudo, без утверждения, что такая запись гарантированно доступна на каждом хосте (§2.20.3).

**Подсказка:** `echo '*'` печатает литерал, `echo *` выводит результат расширения имён по шаблону в текущем каталоге (§2.4.4). Не путать shell glob с regexp для `grep` (§2.5.1).

## Interpretation — интерпретация результатов

| Наблюдение | Интерпретация из главы | Следующее уточнение |
|---|---|---|
| `No such file or directory` / `ENOENT` | Команда обращается к несуществующему файлу/компоненту пути | Проверить точно указанный путь, нет ли опечаток (§2.15). |
| `Not a directory` | В компоненте пути использован обычный файл там, где ожидался каталог | Проверить структуру по компонентам (§2.15.2). |
| `Permission denied` | Нет необходимых разрешений на файл, каталог или исполнение | Сверить владельца/группу/`rwx` (§2.15.2, §2.17). |
| `Operation not permitted` | Пример: сигнал чужому процессу не разрешён | Проверить владельца процесса (§2.15.2). |
| `No space left on device` | Устройство не имеет места для указанного действия | Количественные команды определения объёма не даны: [Needs confirmation]. |
| `ps` показывает `S` или `R` | Sleeping / running; процесс может иметь CPU TIME, не равный времени существования | Сопоставить PID, COMMAND, STAT, TIME; PID может переиспользоваться. |
| Пустой файл после `ls ... > f`, ошибка в терминале | stdout перенаправлен, а stderr остался в терминале | Разделить `1` и `2`, см. §2.14. |
| `locate` не видит новый файл | Индекс `locate` периодически обновляется | Применить файловый поиск `find` (§2.5.6). |
| `ls -l` показывает `lrwxrwxrwx` | Символическая ссылка | Проверить цель ссылки; цель может отсутствовать (§2.17.2). |

## Next action — безопасная последовательность

1. Зафиксировать контекст: текущий каталог (`pwd`), объект (`ls -l`, `file`) или процесс (`ps`).
2. Если ошибка — разобрать **первое** сообщение; выбрать read-only уточнение (`find`, `grep`, `man`, `ls`) по существу вопроса.
3. Если изменяется вывод — распознать `stdout` и `stderr`; до перенаправления `>` учитывать перезапись, `>>` — добавление; stderr отдельно `2>`.
4. Если дело в правах — различить `r`/`w`/`x` файла и каталога. Проверить, достаточно ли собственных прав, не выбирать root автоматически.
5. Если требуется архив — **сначала** `tar ztvf file.tar.gz` (содержимое и пути), затем принимать решение о распаковке в безопасном каталоге.
6. Если требуется изменение — определить эффект, исходное состояние и план восстановления. Если нет подтверждения, **остановить изменение: [Needs confirmation]**.

Этот порядок — систематизация прочитанных советов, а не дословный runbook книги.

## Modifying action — что меняет состояние

| Операция из главы | Эффект | Основной риск / предостережение |
|---|---|---|
| `touch file`, `mkdir dir` | Создать пустой файл или каталог; `touch` меняет timestamp существующего | Не делать без подтверждения пути. |
| `cp file1 file2`, `mv file1 file2` | Копировать или переименовать/переместить | Проверить исходные и целевые пути перед записью. |
| `rm file`, `rmdir dir`, `rm -r dir` | Удалить; `rmdir` — только пустой каталог | `rm -r` отмечен автором как особо опасный; не применять `-r` с `*`; возможна невосстановимая потеря. |
| `chmod go+r file`, `chmod 644 file`, `umask 077` | Изменить режим существующего файла / права будущих файлов | Неверный `x` на каталоге делает путь недоступным; широкое `w` опасно. |
| `ln -s target linkname` | Создать symlink на путь | Перепутанные аргументы дают неверный объект; с `ln` без `-s` создаётся hard link. |
| `kill pid`, `kill -STOP pid`, `kill -CONT pid` | Послать TERM, приостановить, возобновить процесс | PID переиспользуется; не останавливать неизвестные сервисы. |
| `kill -KILL pid` / `kill -9 pid` | Принудительно завершить | Автор: **только в крайнем случае**; процесс не получает времени для очистки. |
| `tar xvf archive.tar`, `gunzip file.tar.gz` | Извлечь содержимое/распаковать архив | Файлы появляются в каталоге; `gunzip` меняет набор имён; сначала просмотреть содержимое. |
| `command > file` / `command >> file` | Создать/перезаписать или дополнить файл | Самая простая команда может модифицировать файл через shell-redirection. |
| `passwd`, `chsh`, `sudo vipw`, `visudo` | Сменить пароль/оболочку или открыть административное редактирование | Требуются права, синтаксическая проверка и контролируемое применение. |

Записи `command`, `file`, `dir`, `pid` — **метапеременные автора**, не готовые рабочие команды. Изменяющие примеры не предназначены для безусловного выполнения.

## Verification / acceptance checks — подтвердить исход

| После действия | Возможное подтверждение, прямо поддержанное главой | Неизвестное |
|---|---|---|
| `touch` | `ls -l file` показывает timestamp (PDF 44) | Нужен ли этот файл системе: [Needs confirmation]. |
| `cd dir` | `pwd`, при symlink-разночтении `pwd -P` (45–49) | [Not applicable] |
| `chmod` | `ls -l` показывает новый режим (66–69) | Кто/что зависит от новых прав: [Needs confirmation]. |
| `kill` | `ps` и `jobs` позволяют наблюдать процессы (62–65) | Успешная graceful-остановка конкретного приложения: [Needs confirmation]. |
| `tar` | `tar ztvf` выводит содержимое и проверяет базовую целостность перед извлечением (72–73) | Целостность и доверенность всех файлов вне базовой проверки: [Needs confirmation]. |
| `sudo` | `journalctl SYSLOG_IDENTIFIER=sudo` там, где записи доступны (78) | Конкретная политика sudoers и способ хранения логов: [Needs confirmation]. |

## Rollback — стратегия восстановления

- Для `cd`, `export` и изменений `PATH` глава позволяет вернуться к предыдущему состоянию в рамках оболочки; для испорченного PATH автор предлагает открыть новый терминал (53). **Это не восстановление конфигурационных файлов**, изменённых ранее.
- `kill -STOP pid` → `kill -CONT pid` в границах той же действительной идентичности процесса (64). Повторное использование PID нужно исключить проверкой.
- `chmod` — перед изменением запомнить исходный режим через `ls -l`; точная обратная команда для конкретного сервера: **[Needs confirmation]**.
- `rm`, `rm -r` — восстановление удалённого требует заранее существующего резервного экземпляра; без него **[Needs confirmation]** (44, 46).
- `tar x`, `mv`, `sudo vipw`, `visudo`, `passwd`, `chsh` — универсальный rollback глава **не приводит**: **[Needs confirmation]**. Не считать удаление появившихся файлов безопасным без проверки путей и исходного состояния.

## Особые границы безопасности

- Пример `NOPASSWD: ALL` (§2.20.2) описывает предоставление **любых** административных команд без пароля и не является безопасной стандартной настройкой. Не применять как готовый конфиг.
- `p0049:c01` содержит сомнительный синтаксис поиска назад `-?ord`; использовать как copy-paste **нельзя без проверки** (`source-findings.md`).
- Текст главы о `/bin/sh`, размещении каталогов и архивах — описание издания; актуальное состояние конкретной ОС **[Needs confirmation]**.
