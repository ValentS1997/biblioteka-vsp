# Cheatsheet — глава 3 «Устройства»

Source: `how-linux-works-brian-ward-3e-ru-2022:p0079:c01`–`p0101:c01`; страницы 79–101. **RAG-only**.

## Symptom / problem framing

Нужно понять, какое устройство видит ядро, как оно обозначено в `/dev`, где расположены свойства в `/sys`, какие события обрабатывает `udevd` и через какие драйверы работает storage (§3.1–3.6). Глава **не** является готовым runbook по ремонту дисков.

## Read-only checks

Подтверждённые RAG команды для наблюдения (цель должна существовать в проверяемой системе):

```sh
ls /dev
ls -l /sys/block
cat /proc/devices
journalctl -k
mount
lsscsi
lsscsi -g
nvme list
ls -l /dev/disk/by-id
udevadm info --query=all --name=/dev/sda
```

`udevadm monitor` и `udevadm monitor --kernel --subsystem-match=scsi` — длительный просмотр событий. `cat dev` встречается как команда внутри конкретного каталога устройства `sysfs`; её рабочая директория должна быть подтверждена (§3.2). Сканирование не доказывает, что `/dev/sda` всегда соответствует одному и тому же накопителю.

## Interpretation

1. Проверить тип интерфейса через `ls -l`: `b` — блоки, `c` — поток; `p`/`s` — IPC-объекты. Major/minor указывают устройство в модели ядра (§3.1).
2. Сравнить назначения `/dev` (ввод-вывод) и `/sys/devices` (свойства/управление); не считать пути взаимозаменяемыми (§3.2).
3. Найти связь `/dev` → `/sys` через `udevadm info`; в выводе `P` — sysfs path, `N` — node, `S` — symlink, `E` — environment (§3.5.3).
4. Сверить имена `/dev/sdX` с symlinks `/dev/disk/by-id` прежде, чем судить об идентичности носителя; буква `sdX` может измениться (§3.4.1; §3.5.1).
5. Сопоставить события `KERNEL` и `UDEV` через `udevadm monitor`; при необходимости `--property`, `--kernel` или `--udev` (§3.5.4).
6. При SCSI/storage-интерфейсах `lsscsi` показывает host:bus:target:LUN; `-g` добавляет `/dev/sg*`. SATA/USB-storage могут использовать мосты к SCSI (§3.6).

## Next action

До изменений установить **существующий узел**, **идентичность устройства** и **его класс**. Использовать наблюдение `udevadm`, `sysfs` и `lsscsi` вместо догадки по `/dev/sdX`. Если этих фактов нет, остановиться: **[Needs confirmation]**. Работа с разделами и файловыми системами относится к следующей главе 4.

## Modifying action

| Элемент главы | Эффект | Риск |
|---|---|---|
| `dd` с выходным файлом `of=` (§3.3) | Копирует блоки, создаёт/перезаписывает получатель | Перепутанный путь может разрушить данные, особенно при обращении к диску. |
| `mknod` (§3.4.11) | Создаёт специальный device node | Привилегированная операция; пример для конкретной конфигурации не универсален. |
| `chvt` (§3.4.7) | Переключает активную виртуальную консоль | Изменяет интерактивную сессию. |
| `screen` и serial tty (§3.4.8) | Открывает сеанс с интерфейсом, возможно передаёт данные | Фактические права, параметры порта и устройство [Needs confirmation]. |
| Запись правил udev (§3.5.2) | Меняет реакцию на `uevent`, права или ссылки | Нет безопасной готовой процедуры применения/отката. |
| `udevadm` reload/trigger (§3.5.3) | Средство меняет правила/создаёт события, но полный синтаксис в главе не дан | Нельзя достраивать команды из памяти. |

Отдельно автор приводит **учебный** пример `dd`, который пишет из `/dev/zero` в `new_file` 1024 байта. Пример не должен подменяться реальным `of=/dev/...`: запись в устройство без известной цели и backup небезопасна. `echo` с перенаправлением в `/dev/null` удаляет данные из выходного потока, не очищает диск (§3.1).

## Verification / acceptance checks

| Цель | Проверка | Acceptance |
|---|---|---|
| Устройство найдено | `udevadm info`, `ls -l /sys/block` | Подтверждены node, sysfs path, свойства |
| Идентичность носителя | `ls -l /dev/disk/by-id` | Видно соответствие ссылки и узла |
| Событие устройства | `udevadm monitor` | Видны стадии KERNEL/UDEV при реальном событии |
| Драйверная цепочка | `lsscsi`, `lsscsi -g` | Показаны адрес и подходящие node/generic node |
| Изменяющие операции | Автор не предоставляет end-to-end acceptance | **[Needs confirmation]** |

## Rollback

Read-only команды не меняют состояние — **[Not applicable]**. Для записи `dd` на диск, изменения узлов/udev-правил, атрибутов устройства или serial-сеанса в главе **нет** полной обратной процедуры: **[Needs confirmation]**. Возможная потеря данных потребовала бы заранее проверенной резервной копии.

**Open risks:** нельзя переносить из главы идентификаторы `/dev/sda`, major/minor, серийные номера или правила udev на живой хост без readback. Противоречивые текстовые фрагменты source сохранены отдельно в `source-findings.md`.
