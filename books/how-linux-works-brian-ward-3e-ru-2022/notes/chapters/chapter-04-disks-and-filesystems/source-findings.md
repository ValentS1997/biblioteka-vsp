# Source findings — глава 4 «Диски и файловые системы»

Политика: **rag_only**, `p0102:c01`–`p0155:c01`. Этот реестр сохраняет варианты источника **без молчаливых исправлений** и без обращения к актуальным внешним руководствам.

## F-01 — [Source wording/code mismatch]: `mkfs` и имя раздела

- **Источник:** `p0117:c01` (§4.2.2).
- **Вводный текст:** предлагается создать ext4 «в `/dev/sda2`».
- **Командный пример:** `mkfs -t ext4 /dev/sdf2`.
- **Несоответствие:** разные устройства; глава **не** задаёт способ выбора корректного из этих двух имён.
- **Решение:** не исправлять по памяти, не выполнять пример. Реальное устройство и разрешение уничтожить прежние данные: **[Needs confirmation]**.

## F-02 — [Source contradiction]: повтор UUID

- **Источник:** `p0119:c01` (§4.2.4), пример вывода `blkid`.
- **Вариант A:** `/dev/sdf2` отмечен `TYPE="ext4"` с `UUID="b600fe63-d2e9-461c-a5cd-d3b373a5e1d2"`.
- **Вариант B:** `/dev/sda5` отмечен `TYPE="swap"` с **тем же** `UUID="b600fe63-d2e9-461c-a5cd-d3b373a5e1d2"`.
- **Контекст:** раздел объясняет UUID как способ идентификации FS, независимый от имени устройства, и далее монтирует примерный UUID на `/home/extra`.
- **Несоответствие:** два объекта разных типов показаны под идентичным значением. Это **не** доказательство уникальности какого-либо носителя в реальности.
- **Решение:** сохранить оба значения, не выбирать «правильный». Использование UUID из листинга для монтирования запрещено без фактического `blkid`/mount readback.

## F-03 — [Source code mismatch / output inconsistency]: имя VG в примере

- **Источник:** `p0140:c01`–`p0141:c01` (§4.4.1).
- **Команды:** `vgcreate myvg /dev/sdb1`; `vgextend myvg /dev/sdc1`.
- **Пример вывода после расширения:** `vgs` показывает имя группы `my-vg` вместо ранее созданной `myvg`.
- **Решение:** не подменять выведенное имя в исходном артефакте; сопоставление имен/томов на реальном хосте **[Needs confirmation]**.

## F-04 — [Source extraction issue]: разрыв команды mount

- **Источник:** `p0123:c01` (§4.2.8), строка fstab: `/dev/sr0 /cdrom iso9660 ro,user,nosuid,noauto 0 0`.
- **Соседний текст:** пример упрощённой команды отображён как `mount /cd rom` (с пробелом).
- **Проблема:** текстовый RAG не подтверждает, является ли разрыв переносом при извлечении или содержимым оригинала.
- **Решение:** не представлять раздробленную строку как проверенный copy-paste; конкретный путь к mountpoint **[Needs confirmation]**.

## F-05 — [Source extraction issue]: отдельные артефакты терминов

- **Источник:** `p0150:c01` (§4.6): слово `inodev` рядом с правильным `inode`; `p0126:c01`: `cd/; du` в иллюстрации обхода каталогов.
- **Решение:** не переносить эти формы как синтаксис команд и не исправлять фрагменты в сохранённом RAG. Релевантные выводы об inode и `du` представлены другими текстовыми утверждениями этой же главы.

## F-06 — [Source extraction issue]: графика не представлена в RAG

- В диапазоне PDF **103–154** автор размещает рисунки **4.1–4.10** (слои диска, CHS, LVM, inode). В текстовом RAG доступны подписи и описание, **не** сами изображения.
- `rag/manifest.yaml`: `known_limitations` прямо указывают, что diagrams/images/tables не представлены самостоятельными мультимодальными объектами.
- **Решение:** `diagram.md` и два SVG реконструируют только явно описанные в тексте отношения. Геометрия, расположение элементов и точные стрелки исходных рисунков: **[Needs confirmation]**.

## Дополнительные оговорки, не «исправления»

- `p0124:c01`: описание автомонтирования содержит термин `ubus`. Его связь с другой программой в границе главы не проверена, поэтому замена термином из внешних знаний **не производится**.
- `p0135:c01`: пояснение к `vgdisplay` использует метку `Act LV` при описании активных физических томов; принадлежность метки конкретному реальному полю вывода **[Needs confirmation]**.
- Утверждения автора о распространённости FS, размерах swap и старых интерфейсах датированы контекстом издания (2022). Актуальные требования конкретной инфраструктуры **[Needs confirmation]**.

**Главное следствие:** ни один пример разметки, форматирования, автоматического восстановления или LVM нельзя считать одобренным изменением состояния production из одного только текста главы.
