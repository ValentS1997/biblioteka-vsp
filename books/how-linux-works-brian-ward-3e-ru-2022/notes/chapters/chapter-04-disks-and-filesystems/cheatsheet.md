# Cheatsheet — глава 4 «Диски и файловые системы»

**Источник:** `how-linux-works-brian-ward-3e-ru-2022:p0102:c01`–`p0155:c01`; PDF/печатные страницы 102–155. Только `rag_only`.

## Symptom / problem framing

Читатель должен различать, **какое устройство и раздел используется, какая файловая система там находится, где она смонтирована, сколько места доступно и как она связана с LVM, swap и inode**. Глава иллюстрирует также действия форматирования, монтирования и восстановления, но **не** предоставляет готового безопасного runbook для диска с пользовательскими данными.

## Baseline / context

| Слой | Что он делает | Source PDF |
|---|---|---:|

| UUID / `blkid` | Идентификация FS без зависимости от текущей буквы `sdX` | 119–120 |
| `df` / `du` | Занятость filesystem / оценка объёма каталога | 124–126 |
| Swap | Вынос неактивных страниц памяти на диск/в файл | 130–132 |
| LVM `PV → VG → LV` | Абстракция блочных устройств, управляемая user-space LVM и kernel mapper | 132–149 |
| inode и каталоги | Идентификаторы и ссылки на данные; имена в записях каталогов | 150–155 |

## Read-only checks

В главе прямо названы следующие примеры и режимы **наблюдения**. На реальном хосте предварительно проверяется существование объекта; названия авторских тестовых дисков не копируются без подтверждения.

```sh
lsblk
parted -l
fdisk -l
journalctl -k
cat /proc/partitions
mount
blkid
df
df -h
du -s *
free
vgs
vgdisplay
lvs
lvdisplay
pvs
pvdisplay
dmsetup info
dmsetup table
ls -i
stat .
```

`du -s *` пропускает скрытые dotfiles/каталоги и может быть ресурсоёмким при большом дереве (§4.2.10). `ls -i` и `stat` демонстрируют inode (§4.6.1). Команды LVM `vgs/lvs/pvs` не отображают файловый уровень занятости; `VG VFree` означает ещё не выделенные **logical** extents (§4.4.1).

**Особый случай:** `fsck -n` предлагает проверку без изменения данных (§4.2.11), но её **не выполнять на смонтированной read-write файловой системе**. Глава категорически предупреждает о такой проверке (PDF 127). Безусловно read-only проверкой на production она не считается.

## Interpretation

| Признак | Проверенное значение в главе | Осталось неизвестным |
|---|---|---|
| `parted -l`: `msdos` или `gpt` | Тип partition table, границы, типы разделов | Какой диск допустимо переписывать: [Needs confirmation] |
| `fdisk -l`: 512-byte sectors | Единицы отображения и размер логических секторов требуют прочтения вместе | Соответствие номеров носителю: [Needs confirmation] |
| `blkid` и `/etc/fstab` | UUID и устройство/FS; fstab содержит шесть полей | Повторы UUID в примере источника: source finding |
| `mount` | Device → mountpoint, FS type, options `ro/rw` | Использующие FS процессы не выявляются этой командой |
| `df` не «сходится» по total-used-free | Ext reserved blocks могут быть недоступны обычному пользователю | Конкретная резервная квота: [Needs confirmation] |
| `du` vs `df` | `du` суммирует объём по каталогам, `df` — по filesystem | Алгоритм согласования расхождений в главе отсутствует |
| `free`: `Swap` | Размер и текущее использование подкачки | Требуемая swap capacity зависит от нагрузки |
| `lvdisplay`: `LV Path` | Устойчивое имя указывает на `/dev/dm-*` | Фактическая цепочка mapping на хосте: [Needs confirmation] |
| `ls -i` / `stat` | inode и количество ссылок | Уникальность значима в пределах данной файловой системы |

## Next action

1. Выяснить, **какой именно диск/раздел/том** рассматривается: `lsblk`, `parted -l`, `blkid`, LVM `pvs/vgs/lvs` по потребности.
2. Проверить mount state и тип файловой системы через `mount`; заполненность через `df` и `du`, swap — через `free`.
3. Для предстоящей операции подтвердить **отсутствие использования** целевых разделов, резервную копию, ожидаемую таблицу и план восстановления. Источник требует backup и отсутствие использования перед изменением таблицы (PDF 108).
4. Если нет доверенного идентификатора устройства или подтверждения rollback: **[Needs confirmation] — STOP**. К инвазивной работе не переходить.

Это практическая схема сопоставления тем книги, **не дословная последовательность автора**.

## Modifying action

| Операция | Эффект | Риск и требуемый контроль |
|---|---|---|
| `fdisk`, запись `w`; `parted` | Изменение границ/таблицы разделов | У `fdisk` до `w` правки в памяти, выход `q` без сохранения; `parted` пишет сразу. Потеря данных возможна (108–111). |
| `mkfs -t ext4` | Создание новой файловой системы | **Уничтожает существующую FS и данные** на выбранном разделе; повторно не выполнять (116–117). |
| `mount`, `umount`, remount | Изменяет mount state и режим доступа | Нужны точный source, mountpoint, FS type и текущие пользователи (117–122). |
| `/etc/fstab`, `mount -a` | Постоянная конфигурация и массовое монтирование | Ошибка может нарушить загрузку/доступ; rollback конкретного хоста не описан (122–124). |
| `fsck`, `e2fsck`, `fsck -p/-y` | Проверка с потенциальным исправлением структур | **Не выполнять по смонтированной RW FS**; исправления могут уничтожить сохранившиеся данные (126–129). |
| `mkswap`, `swapon`, `swapoff` | Изменение сигнатуры и активного пула swap | `mkswap` перезаписывает метаданные; `swapoff` требует доступной памяти (130–132). |
| `vgcreate/vgextend/lvcreate` | Создают PV/VG/LV и mapping | Изменяются метаданные хранилища; цель/backup [Needs confirmation] (139–143). |
| `lvremove` | Удаляет логический том | **Необратимая потеря данных**; автор выделяет риск пропущенного `/` в `myvg/mylv2` (143–144). |
| `lvresize`, `fsadm resize` | Меняет размер LV и файловой системы | Для расширения нужны два уровня; сокращение — другая последовательность, с размонтированием (144–145). |
| `dd`, `rm`, `ln` в опытах с inode | Прямые записи/удаление имён/создание hard link | Выполнять только в заранее подготовленном тестовом каталоге/носителе (147,150–153). |

**Не исполнять эти примеры на хосте лишь потому, что они напечатаны в книге.** Аргументы `/dev/sdf2`, `/dev/sdd`, `myvg/mylv1` — фиктивная топология автора, не подтверждение среды пользователя.

## Rollback

- **Read-only** наблюдения: **[Not applicable]**.
- В `fdisk` **до сохранения** `q` отменяет изменения; **после** `w` это не откат (PDF 110–111).
- Для `parted`, `mkfs`, `lvremove`, `fsck` с исправлением, raw I/O **глава не задаёт автоматического восстановления**. Нужен заранее проверенный backup/образ, точный план и согласованное окно: **[Needs confirmation]**.
- Для mount/remount/resize требуются сохранённая исходная конфигурация, тип FS, точка монтирования и поддерживаемая обратная операция. Особенно **shrinking не является простым обращением growing** (PDF 145).
- `swapoff` не выполнять без достаточной памяти; способ безопасного полного возврата в конкретной системе: **[Needs confirmation]**.

## Source / risk boundary

Источниковые примеры имеют проблемы: имя раздела в тексте отличается от `mkfs` команды (PDF 117), UUID повторяется у ext4 и swap (119), в LVM-выводе есть `myvg` / `my-vg` (141). Не копировать их в инфраструктурные команды — см. `source-findings.md`.
