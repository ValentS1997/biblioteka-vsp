184     Глава 6. Масштабирование банковских данных клиентов в системе RAG

Кроме того, была добавлена функция для обработки последнего пакета, размер
которого может не соответствовать установленному:

# Обработка оставшихся чанков
if chunk_end < len(chunks):
    remaining_chunks = chunks[chunk_end:]
    remaining_embeddings = [get_embedding(chunk, model=embedding_model) for
      chunk in remaining_chunks]
    embeddings.extend(remaining_embeddings)

В выводе отражаются счетчик и время обработки:

 All chunks processed.
 Batch 1 embedded.
 ...
 Batch 10 embedded.
 Response Time: 2689.46 seconds

Время выполнения получилось значительным, и для каждого раза оно будет
иным, но при масштабировании это естественно. Глупо ожидать быстрой обра
ботки больших объемов данных без просадки производительности.

При желании в качестве проверки можно вывести полученное векторное пред
ставление:

print("First embedding:", embeddings[0])

Вот первое:

 First embedding: [-0.024449337273836136, -0.00936567410826683,…

Теперь проверим, совпадает ли у нас число чанков и полученных векторов:
# Проверяем количество чанков и эмбеддингов
num_chunks = len(chunks)
print(f"Number of chunks: {num_chunks}")
print(f"Number of embeddings: {len(embeddings)}")

Вывод подтверждает, что можно переходить в Pinecone:

 Number of chunks: 10000
 Number of embeddings: 10000

На этом разбивка и векторизация данных завершена. Далее мы продублируем
эти данные, сымитировав таким образом масштабирование.

Дублирование данных
