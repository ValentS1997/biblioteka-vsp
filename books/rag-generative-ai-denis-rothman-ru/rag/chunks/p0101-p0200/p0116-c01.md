В выводе (рис. 4.2) мы видим текстовый датасет и его структуру: embedding (век
торы), id (уникальный строковый идентификатор), metadata (в нашем случае

        Рис. 4.2. Вывод структуры текстового датасета и его содержимого

Далее инициализируем механизм обработки запросов к LLM.

Инициализация механизма для обработки запросов к LLM
Как и в главе 3, мы проиндексируем векторную базу данных документов по техно
логии БПЛА (documents_llm) из датасета (ds). Метод GPTVectorStoreIndex.from_
documents() создает индекс, обеспечивающий ускоренное извлечение документов
на основе векторного сходства:

from llama_index.core import VectorStoreIndex
vector_store_index_llm = VectorStoreIndex.from_documents(documents_llm)

По аналогии с той же главой 3 метод as_query_engine() настраивает этот индекс
в качестве механизма обработки запросов с конкретными параметрами опреде
ления сходства и глубины извлечения, чтобы система отвечала на ввод, выпол
ненный пользователем, находя наиболее релевантные документы:

vector_query_engine_llm = vector_store_index_llm.as_query_engine(similarity_top_k=2,
    temperature=0.1, num_output=1024)

Далее добавим пользовательский ввод.

Ввод пользователя для мультимодальной RAG
В контексте модульной системы RAG пользовательский ввод применяется для
формулирования запроса, который задействует и текстовый механизм обработ
ки, и механизм обработки изображений. Так мы позволим системе генерировать
полноценный и точный ответ на основе нескольких источников информации:

user_input="How do drones identify a truck?"

В этом контексте ввод, выполненный пользователем, выступает своеобразной
основой, или опорным запросом, применяемым для проверки способностей систе
мы. Он позволит установить базовый ориентир, помогающий понять, насколько
хорошо она может обрабатывать запросы и отвечать на них с помощью доступных
