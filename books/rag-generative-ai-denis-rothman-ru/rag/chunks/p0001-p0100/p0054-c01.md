54     Глава 2. Хранение эмбеддингов RAG с помощью Deep Lake и OpenAI

С появлением параметрических моделей, в которых информация скрыта в глу
бинах настраиваемых обучением параметров, формирующих системы по типу
«черный ящик», возник острый вопрос обеспечения прозрачности. И разработка
RAG в этом смысле стала прорывом (см. рис. 2.1), поскольку информацию, кото
рой подобные механизмы оперируют, легко отследить.

z Слева (текст): во фреймворках RAG каждый фрагмент сгенерированного со
   держимого можно проследить вплоть до исходных данных, что обеспечивает
   прозрачность итогового вывода. И генеративная модель OpenAI отвечает,
   применяя дополненный ввод, выполненный пользователем.
z Справа (эмбеддинги): векторные представления данных видимы и привязаны
   к тексту, что резко отличает их от параметрических моделей, в которых ис
   точники данных закодированы в параметры.

Следующим шагом после создания из текста эмбеддингов будет их удобное со
хранение для быстрого извлечения. Для этого используются векторные храни
лища. Векторное хранилище — это специализированная база данных, созданная
для обработки высокоразмерных данных наподобие эмбеддингов. Мы можем
создавать датасеты на бессерверных платформах, подобных Activeloop (рис. 2.2).
Их создание и последующий доступ через API реализуем в коде в разделе «Соз
дание пайплайна RAG» далее в этой главе.

        Рис. 2.2. Управление датасетами с помощью векторных хранилищ

Еще одна особенность векторных баз данных — возможность извлекать ин
формацию с помощью оптимизированных механизмов. Векторные хранилища
создаются с использованием мощных методов индексирования, о чем мы пого
ворим в следующей главе. Такая особенность позволяет механизму RAG быстро
находить и получать наиболее релевантные эмбеддинги на этапе генерации, до
полнять запрос пользователя и обеспечивать модели больше возможностей для
выдачи качественного ответа.
