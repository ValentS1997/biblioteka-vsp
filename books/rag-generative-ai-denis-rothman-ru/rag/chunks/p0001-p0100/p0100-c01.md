100     Глава 3. Реализация индексируемой RAG

  scores = [node.score for node in response.source_nodes if node.score is not None]
  if scores:    # Проверяем наличие валидных показателей
      weights = np.exp(scores) / np.sum(np.exp(scores))
      perf = np.average(scores, weights=weights) / elapsed_time
  else:
      perf = 0  # Или других предустановленных значений, если все показатели None

В результате получим соотношение взвешенного среднего показателя и про
шедшего времени:

perf = np.average(scores, weights=weights) / elapsed_time

Теперь можно вызвать написанную функцию:
info_metrics(response)

Вывод покажет примерную оценку качества ответа:

 Average score: 0.8374
 Query execution time: 1.3266 seconds
 Performance metric: 0.6312

Полученный показатель эффективности не является абсолютным значением.
Это лишь индикатор, который можно использовать для сравнения конкретного
вывода с результатом применения других механизмов индексирования. При
чем ввиду стохастической природы алгоритмов ML он может различаться от
случая к случаю. Кроме того, качество вывода зависит также от субъективного
восприятия пользователя. В любом случае эта метрика поможет нам сравнить
эффективность механизмов обработки запросов в текущей главе.

Ранее мы получили вполне удовлетворительный показатель, несмотря на то что
загрузили в датасет разнородные данные, включая не связанные с темой доку
менты. Интегрированная функциональность LlamaIndex, Deep Lake и OpenAI,
объединяющая механизм извлечения и генерации ответа, оказалась довольно
эффективной.

Механизм индексирования на основе дерева
Такой механизм LlamaIndex создает иерархическую структуру для эффективного
запроса текстовых документов и управления ими. Тем не менее здесь мы имеем
дело не с классической иерархической структурой. Древовидный индекс опти
мизирует эту структуру, ее содержимое и порядок узлов (рис. 3.5).

В древовидном индексе документы организуются в виде дерева, где на верхних
уровнях находятся узлы с общей информацией, а на нижних — с подробностями.
Каждый узел описывает текст, с которым он связан. Такой вид индексирования
эффективен для больших датасетов и частых запросов к объемным коллекциям
