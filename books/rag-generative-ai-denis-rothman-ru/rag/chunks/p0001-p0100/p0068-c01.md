68     Глава 2. Хранение эмбеддингов RAG с помощью Deep Lake и OpenAI

Добавление данных в векторное хранилище
Мы установили флаг добавления данных на True:
add_to_vector_store=True
if add_to_vector_store == True:
    with open(source_text, 'r') as f:
        text = f.read()
        CHUNK_SIZE = 1000
        chunked_text = [text[i:i+1000] for i in range(0, len(text), CHUNK_SIZE)]

vector_store.add(text = chunked_text,
              embedding_function = embedding_function,
              embedding_data = chunked_text,
              metadata = [{"source": source_text}]*len(chunked_text))

Исходный текст, source_text = "llm.txt", был преобразован в эмбеддинги и со
хранен. Вывод демонстрирует структуру датасета, указывая, что он был загружен:

Заметьте, что датасет содержит четыре тензора:
z  embedding — каждый чанк данных преобразован в вектор;
z  id — представляет строку символов и является уникальным;
z  metadata — содержит источник данных, в нашем случае файл llm.txt;
z  text — содержимое чанка текста из датасета.

Как мы увидим в главе 4, структура датасета для каждого проекта может быть
своя. Кроме того, в любой момент можно визуализировать датасет, чтобы прове
рить его структуру. Следующий код отобразит сводку, которую мы видели ранее:

# Вывод сводки по векторной базе данных
print(vector_store.summary())

При желании также можно визуализировать информацию хранилища.

Информация о векторной базе данных
Ссылка из Activeloop API https://docs.deeplake.ai/en/latest/ предоставит всю информа
цию, необходимую для управления датасетами, которые мы сможем легко визуа
лизировать после авторизации по адресу https://app.activeloop.ai/datasets/mydatasets/.
