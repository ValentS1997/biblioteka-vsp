92     Глава 3. Реализация индексируемой RAG

id — это уникальная строка кода:

 ID:
 ['a89cdb8c-3a85-42ff-9d5f-98f93f414df6']

Поле metadata содержит информацию, необходимую для прослеживания истории
получения содержимого вплоть до его исходного файла и адреса этого файла,
а также все сопутствующие данные, начиная с самого источника и заканчивая
векторным представлением. Помимо этого, здесь указывается информация узла,
созданного из данных записи, которую далее можно будет использовать для ме
ханизма индексирования в компоненте 3:

z  file_path — путь к файлу в датасете (/content/data/1804.06985.txt);
z  file_name — имя файла (`1804.06985.txt`);
z  file_type — тип файла (`text/plain`);
z  file_size — размер файла в байтах (`3700`);
z  creation_date — дата создания файла (`2024-08-09`);
z  last_modified_date — дата последнего изменения файла (`2024-08-09`);
z  _node_content — подробное содержимое узла, включая следующие основные
   элементы:
     id_ — уникальный идентификатор (`a89cdb8c-3a85-42ff-9d5f-
      98f93f414df6`);
     embedding — полученный из текста эмбеддинг (null);
     metadata — повтор метаданных файла;
     excluded_embed_metadata_keys — ключи, удаленные из метаданных эмбед
      динга (для эмбеддинга не нужны);
     excluded_llm_metadata_keys — ключи, удаленные из метаданных LLM (для
    LLM не нужны);
     relationships — информация о связях с другими узлами;
     text — фактическое содержимое документа. Это может быть сам текст, его
      аннотация, конспект или любой иной формат для оптимизации функций
      поиска;
     start_char_idx — индекс начального символа текста;
     end_char_idx — индекс последнего символа текста;
     text_template — шаблон для вывода текста с метаданными;
     metadata_template — шаблон для вывода метаданных;
     metadata_separator — разделитель, используемый при выводе мета
     данных;
     class_name — тип узла (например, `TextNode`);
