# Глава 2 — cheatsheet

**Основание:** RAG `p0030:c01–p0042:c01`, PDF 30–42. Описывает способы построения циклов, а не проверенное выполнение в инфраструктуре читателя.

## Symptom / problem framing

Нужно перебрать аргументы сценария, числа, файлы или записи массива; возможны ошибки: разбиение элемента с пробелами на несколько итераций, смешение `"${list[@]}"` и `"${list[*]}"`, а также преждевременное выполнение изменяющих команд. [PDF 31–39]

## Baseline / context

| Сценарий | Идиома по источнику | PDF |
| --- | --- | --- |
| Числовой счётчик | `for ((i=0; i<10; i++)); do ...; done` | 31 |
| Параметры сценария/функции | `for arg; do ...; done` или явная `for arg in "$@"; do ...; done` | 31–32, 41 |
| Перечень | `for num in 1 2 3 4 5; do ...; done` | 32 |
| Диапазон | `for i in {01..10}; do ...; done` | 33–34 |
| Массив с пробелами | `for person in "${namelist[@]}"; do ...; done` | 37 |
| Ключи ассоциативного массива | `for key in "${!hash[@]}"; do ...; done` | 36 |
| Условные циклы | `while ...; do ...; done`, `until ...; do ...; done` | 40 |

## Read-only checks

Источник предлагает для **предварительной визуальной проверки** использовать `echo` перед командой. При итерациях по именам файлов пример: `for file in *.JPEG; do echo mv -v $file ${file/JPEG/jpg}; done`. Это печать плана, **не** проверка реального результата `mv`; в именах с пробелами демонстрационный пример не гарантирует сохранение границ аргументов без дополнительных проверок. [PDF 37–39]

При `for person in ...` печать `echo` каждого значения позволяет увидеть, происходит ли неожиданное разделение имён. [PDF 36–38]

## Interpretation

- `for arg` в основной части сценария использует позиционные параметры самого сценария; внутри функции — параметры функции. [PDF 31–32]
- `"${namelist[@]}"` сохраняет каждый элемент массива; `"${namelist[*]}"` даёт одну строку и одну итерацию. Без кавычек имена с пробелами разбиваются на отдельные слова. [PDF 37–38]
- `for i in $(seq 1 10)` сравнивается с арифметическим `for ((i=1; i<=10; i++))`. Авторы специально отмечают **разное значение i после цикла**: 10 и 11 соответственно. [PDF 33]
- `{01..10}` зависит от возможностей/версии Bash; дополнение чисел нулями авторы относят к Bash 4.0+. [PDF 33–34]
- Описание `while/until` имеет сомнительную формулировку относительно статуса проверки; см. [source-findings.md](source-findings.md), **без молчаливой замены авторского текста**. [PDF 40]

## Next action

Для конкретного цикла определить источник элементов, нужны ли кавычки, конечен ли список, каким будет фактический эффект тела. Для потенциально изменяющих файлов/удалённые хосты действий — сначала распечатать план через `echo`, проверить имена и только затем обсуждать реальный запуск. [PDF 37–42]

## Modifying action

В главе обсуждается переименование JPEG-файлов (`mv`), выполнение команд на множестве серверов (`ssh`) и заполнение хеша (`declare -A`; запись `hash[$key]`). Их выполнение меняет имена файлов, создаёт удалённую нагрузку либо изменяет состояние переменных оболочки соответственно. Конкретные пользователи, хосты, каталоги и файлы: **[Needs confirmation]**. Нельзя превращать печатаемый через `echo` пример в изменяющую операцию без подтверждения этого контекста.

## Verification / acceptance checks

Подтвердить ожидаемое количество итераций и границы элементов; проверить распечатанный план `echo` на корректность путей/аргументов; после разрешённого изменения проверить конкретный эффект. Команда измерения, ожидаемый результат в пользовательской среде и факт исполнения: **[Needs confirmation]**.

## Rollback

Для `mv`, удалённых `ssh`-действий и изменения массива глава не содержит проверенной универсальной процедуры восстановления: **[Needs confirmation]**. Бесконечный цикл `for ((;;))` без ограничения требует предотвращения случайного запуска; сценарий аварийного завершения не специфицирован источником: **[Needs confirmation]**.
