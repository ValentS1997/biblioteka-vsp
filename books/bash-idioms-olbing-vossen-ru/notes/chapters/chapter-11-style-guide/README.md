## Главный принцип

Выбрать согласованное руководство по стилю, **записать правила и придерживаться их**. При сопровождении уже существующей кодовой базы авторы рекомендуют следовать принятому в ней стилю вместо самовольного переоформления. [PDF 175, 179]

- Имена должны отражать назначение; комментарии — объяснять прежде всего **почему**; функции — быть понятными, с описанными входными и выходными данными. [PDF 178–184]
- Для Bash авторы предпочитают `[[ ... ]]`, `$(...)`, `(( ... ))`, говорящие имена, разумные кавычки, четыре пробела на уровень отступа, ширину строки около 78 знаков. Это **авторские предпочтения**, не доказательство обязательности для чужих проектов. [PDF 182–188]
- Предложенный шаблон содержит реальные shell-конструкции, но также **заглушки**, комментарии и необязательный строгий режим; его нельзя слепо запускать. [PDF 188–189]
- Руководство относится **именно к Bash**, его нельзя переносить без адаптации на `sh`, Dash или POSIX-оболочки; авторы отдельно упоминают контейнеры. [PDF 177]
