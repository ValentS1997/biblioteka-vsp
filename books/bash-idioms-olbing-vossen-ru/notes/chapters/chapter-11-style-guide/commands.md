# Глава 11 — команды и конструкции, подтверждённые RAG

**Источник:** PDF 175–192, `p0175:c01–p0192:c01`. Классы: `read-only` (без изменения состояния в данном контексте), `workload-generating` (вычисление/запуск), `state-changing` (переменные, поток исполнения, ФС). Это **иллюстрации к соглашениям**, а не проверенные пользовательские рецепты.

| Конструкция или инструмент из главы | Класс | Смысл и ограничения |
| --- | --- | --- |
| `rsync` | state-changing **в зависимости от параметров** | Упомянут как пример готового инструмента, который можно повторно использовать. Конкретной безопасной команды/режима нет, PDF 176. |
| `source` для `.cfg`/`.conf` | **state-changing по содержимому** | Авторы предпочитают явное слово `source` вместо незаметной точки; подключаемый код требует доверия, PDF 178. |
| `sort -V` | workload-generating, read-only к входным данным | Упомянут для упорядочивания версий/IP-подобных значений, GNU-вариант; переносимость ограничена, PDF 178. |
| `diff --quiet` / `diff -q` | read-only / workload-generating | Длинный ключ как более понятный пример; совместимость с не-GNU системами проверять отдельно, PDF 179. |
| `$(...)` | workload-generating или state-changing по вложенной команде | Авторы предпочитают обратным кавычкам; один вид подстановки не означает отсутствие побочных эффектов, PDF 179, 187. |
| `PROGRAM=${0##*/}` | state-changing (shell variable) | Присваивание имени сценария без пути, в примере с комментариями и в шаблоне, PDF 180, 189. |
| `readonly`, `declare -r` | state-changing (shell state) | Объявление констант, PDF 182. |
| `grep -P '^\s*function '` | workload-generating, read-only к входному файлу | Упомянут как обоснование формы `function Name {`; наличие `grep -P` [Needs confirmation], PDF 183. |
| `function My_Func_Name {` | state-changing (function definition) | Авторский стиль объявлений; описание входов/выходов и `local`, PDF 183. |
| `local my_input` и `my_input="$(some-command)"` | state-changing (shell state) | Раздельное объявление и присваивание помогает сохранить статус команды; `some-command` — заглушка, не исполнять, PDF 184. |
| `[[ "$foo" == 'bar' ]]` | read-only при чистой проверке | Иллюстрирует кавычки в строковой проверке, PDF 185. |
| `echo "cd to '$DIR' failed"` | workload-generating | Оформление диагностического сообщения для отличения пустого значения, PDF 185. |
| `printf` с одинарными кавычками вокруг строки формата | workload-generating | Авторская рекомендация для формата, PDF 185. |
| `#!/bin/bash -`, `#!/usr/bin/env bash` | настройка среды исполнения | Рекомендуемые в тексте shebang, не команда для запуска; `#!/bin/sh` авторы не рекомендуют для Bash, PDF 187–188. |
| `[[ ... ]]`, `[ ... ]` | read-only при чистых выражениях | Для Bash предпочитают двойные, для совместимости оставляют одинарные, PDF 187. |
| `(( ... ))`, `$(( ... ))` | read-only либо state-changing по выражению | Арифметическая команда и подстановка; могут содержать присваивания, PDF 187. |
| `let`, `expr` | зависит от аргументов | Упомянуты как менее предпочтительные формы, PDF 187. |
| `[[ expr ]] && block` / `[[ expr ]] || block` | state-changing или workload-generating по `block` | Авторы допускают простые конструкции; предостерегают от цепочки `&& block || block`, PDF 187. |
| `set -euo pipefail` | **state-changing (shell policy)** | Режим для выявления ряда ошибок, предложен к рассмотрению, не гарантирует полной безопасности, PDF 188–189. |
| `IFS=$'\n\t'` | **state-changing (word splitting)** | Авторы советуют особую осторожность или избегать, PDF 188. |
| `echo 'A Bad Thing happened' 1>&2` | workload-generating | Явный вывод сообщения об ошибке в STDERR, PDF 188. |
| `[ -x /path/to/tool ]` | read-only | Проверка доступности исполняемого инструмента; путь — placeholder, PDF 188. |
| `exit` | state-changing (control flow) | Явно задавать коды завершения, PDF 188. |
| `python -c "import this"` | workload-generating, без правки ФС в книжном примере | Пример чтения «Дзен Python», PDF 177. |
| ShellCheck | read-only / workload-generating для проверки кода | Упомянут как linter, но авторы не всегда согласны с предлагаемыми исправлениями, PDF 191–192. |
| Опасное удаление с неопределённой переменной | **state-changing (filesystem), DO NOT RUN** | Книжный **антипаттерн**; не превращать в готовую команду и не экспериментировать, PDF 177. |

## Проверка перед применением

Разделите стиль и изменение поведения. Перед включением `set -euo pipefail` или `IFS` нужен отдельный тест на конкретном сценарии; `source` нельзя трактовать как простое чтение конфигурации. Операции с реальными каталогами/правами, командами подстановки или глобальными именами зависят от пользовательского контекста. **Проверка результата и rollback: [Needs confirmation]**.

Обратите внимание: пример шаблона на PDF 188–189 содержит заглушки `...`, не определённые адреса и описательные комментарии. Не исполнять как рабочий сценарий. Неконсистентное написание `~=` и регистр комментария закрытия функции вынесены в [source-findings.md](source-findings.md).
