# Глава 5 — «В заключение: стиль и удобочитаемость»

**Точное место:** PDF **81–82**, печатные **80–81**; [p0081:c01](../../../rag/chunks/p0001-p0100/p0081-c01.md), [p0082:c01](../../../rag/chunks/p0001-p0100/p0082-c01.md). Смысловой конспект раздела, без дополнения внешними фактами.

1. Для математических выражений авторы выбирают **двойные круглые скобки**. С `$` они дают значение вычисления, без `$` — статус успешности/неуспешности.
2. Арифметическая форма не требует `$` перед именами переменных. Есть также встроенная команда `let`, и авторы допускают разные стили, если логика остаётся понятной.
3. Объявление переменной через `declare -i` позволяет арифметические присваивания без скобок, но авторы **не рекомендуют** полагаться на эту форму: легко спутать переменные разных типов и получить строку вместо числа.
4. Для строковых сравнений авторы используют `[[ ... ]]`, в том числе из-за поддержки регулярных выражений.
5. Для арифметических сравнений они предпочитают `(( ... ))`, а не запись арифметики через `[[ ... ]]`.

**Следствие для чтения кода:** похожие знаки в Bash обозначают разные вычислительные контексты. Выбранную форму следует соотносить с нужным значением, статусом и уровнем переносимости.
