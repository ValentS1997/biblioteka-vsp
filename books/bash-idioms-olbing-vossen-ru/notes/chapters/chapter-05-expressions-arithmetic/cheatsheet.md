# Глава 5 — cheatsheet

**Источник:** RAG `p0073:c01–p0082:c01`, PDF 73–82. Приведённые проверки являются примерами из книги, не результатами исполнения в пользовательской среде.

## Symptom / problem framing

В Bash внешне похожий синтаксис может обозначать **возвращаемое значение**, **команду с кодом завершения**, **сравнение строк**, **арифметическую проверку** или **присваивание**. Неправильный выбор скобок и кавычек ведёт к неожиданному выполнению или сравнениям. [PDF 73–81]

## Baseline / context

| Задача | Книжная форма | Смысл |
| --- | --- | --- |
| Получить вычисленное число | `max=$(( intro + body + outro - 1 ))` | Арифметическая подстановка, PDF 74 |
| Ветвление по выражению | `if (( max - 3 > x * 4 )); then ...` | Арифметический статус, PDF 75 |
| Изменить счётчик | `(( step++ ))` | Изменение переменной, PDF 75 |
| Старый стиль | `let "step++"` | Арифметическая команда, PDF 76 |
| Переменная с типом integer | `declare -i SEE` | Меняет интерпретацию присваивания, PDF 77 |
| Проверить непустую строку | `[[ -n "$DIR" ]]` | Строковая проверка, PDF 79 |
| Проверить пустую строку | `[[ -z "$DIR" ]]` | Строковая проверка, PDF 79 |
| Регулярное выражение | `[[ "$FILE_NAME" =~ .*xyzz*.*jpg ]]` | Сопоставление с regex, PDF 79 |
| Арифметическое сравнение | `(( OTHERVAL * 10 <= VAL / 5 ))` | Читаемое числовое сравнение, PDF 81 |

## Read-only checks

- `man bash`: документация раздела Conditional Expressions, упомянута на PDF 79.
- `help test`: краткая справка по проверкам, PDF 79.
- Сравнить в исходном коде `[ ... ]` и `[[ ... ]]`: первая форма является командой наподобие `test`, вторая — ключевым словом. Для `[ ... ]` операторы `<`/`>` требуют экранирования, поскольку иначе возможна интерпретация как перенаправление. [PDF 78–80]
- Изучить код перед запуском: оператор `(( ... ))` может включать присваивание. Проверка выражения *не обязательно* read-only. [PDF 75–76]

## Interpretation

- `$(( expression ))` выдаёт числовое значение; `(( expression ))` даёт статус для `if` и может изменять переменные. Ненулевой результат означает статус 0, нулевой — 1. [PDF 74–76]
- Внутри `(( ... ))` и `$(( ... ))` префикс `$` у обычных арифметических переменных не обязателен. [PDF 74–75]
- Самостоятельное `$((step++))` авторы **не рекомендуют**: результат подстановки может быть воспринят как имя запускаемой команды. [PDF 76]
- `declare -i` делает дальнейшие присваивания арифметическими, но без явного объявления аналогичный текст останется строкой; авторы предпочитают явные скобки или `let`. [PDF 77, 81]
- `[[ ... ]]` поддерживает `=~`. В приведённом авторами примере регулярное выражение не заключено в кавычки. Строковые сравнения, порядок сортировки, экранирование `<`/`>` и переносимость отличаются у `[` и `[[` — см. исходный разбор. [PDF 79–80]

## Next action

Выбрать выражение, соответствующее задаче: результат вычисления → `$((...))`; условие или изменение арифметических переменных → `((...))`; строковое условие/regex → `[[...]]`. Если нужна POSIX-совместимость, отдельно рассмотреть ограничения `[ ... ]` из исходника. [PDF 78–82]

## Modifying action

`((step++))`, `((dist*=4))`, `let "step++"` и `declare -i SEE` способны менять переменные. `if cd $DIR; then ...` запускает `cd` и при успехе меняет рабочий каталог. Вспомогательный сценарий `fp` с `awk` и его запуск через `sleep $(fp "6 * 0.25")` — пример делегирования вычислений; он не подтверждает доступность этих программ в среде читателя. [PDF 74–78]

## Verification / acceptance checks

Перед выполнением описать ожидаемое **значение**, **статус** и **изменение состояния** независимо друг от друга. В учебном примере `seesaw.sh` источник показывает `SEE = 12`, `SAW = X+Y`, `SUM = 9+3` для `X=9`, `Y=3`; это результат книги, не текущей среды. [PDF 77]
