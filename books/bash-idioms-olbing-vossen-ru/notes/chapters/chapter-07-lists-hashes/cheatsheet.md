# Глава 7 — cheatsheet

**Основание:** только RAG `p0094:c01–p0110:c01` (PDF 94–110). Результаты выполнения на инфраструктуре читателя не установлены.

## Symptom / problem framing

Нужно хранить несколько значений, сохранять элементы с пробелами, выполнять перебор, соединение, срез или удаление; либо считать уникальные значения и частоты. Неправильные `[@]` / `[*]`, кавычки или `unset` способны нарушить структуру данных. [PDF 94–110]

## Read-only checks

- `declare -p mylist` / `declare -p myhash` дают представление объявления и текущих элементов; `printf '%q|'` делает видимыми границы и экранирование. [PDF 99, 101, 104, 106]
- Проверять, не раскалывается ли значение `"five by five"` на отдельные аргументы. В выводах 7.2/7.4 выражение `"${name[*]}"` даёт один аргумент; именно такое поведение показывают авторы как «Broken!». [PDF 101, 106]
- У хеша вывод ключей без сортировки не равнозначен гарантированному порядку; в примере подсчёта слова сортируются командой `sort`. [PDF 102–109]

## Interpretation

- Списки: числовые индексы с нуля; при `mylist+=(...)` значение добавляется, в отличие от `mylist=(...)` или `mylist=bar`, которые могут заменить элементы. [PDF 97–98]
- Хеши: строковые ключи; для создания обязателен `declare -A` (либо `local -A` / `readonly -A`). [PDF 102–103]
- `"${array[@]}"` сохраняет каждый элемент; `"${array[*]}"` формирует одну строку. Специальное использование `"$*"` для соединения значений через изменённый `IFS` показано отдельно; это **осознанное исключение**. [PDF 96, 99, 104]
- `mylist=("${mylist[@]:1}")` имитирует удаление первого элемента списка; `unset -v 'mylist[-1]'` удаляет последний в Bash 4.3+; для хешей понятия первого/последнего ключа не имеют того же смысла. [PDF 99–105]

## Modifying action

`mylist+=(...)`, `myhash[key]=...`, `mylist=("${mylist[@]:1}")`, `unset -v 'mylist[2]'` изменяют состояние Bash. Пример 7.5 выполняет `> $WORD_FILE` (обнуление или создание файла), `>> $WORD_FILE` (добавление), `trap "rm -f $WORD_FILE" ...` (удаление файла на событиях). Фактический путь из книги — `/tmp/words.txt`, поэтому **не запускать пример как есть**. [PDF 98–109]

## Verification / acceptance checks

Для списков — проверить численность, индексы, сохранение пробелов и порядок; для хешей — ключи и значения без предположения о порядке обхода. Перед файловым примером подтвердить отдельный безопасный путь, содержимое, результат и контролируемую очистку. Выполнение и ожидаемые значения в пользовательской системе: **[Needs confirmation]**.

## Rollback

Восстановление удалённых элементов/массивов требует исходного состояния, которого глава не предоставляет; удаление `/tmp/words.txt` может затронуть имеющийся файл. Подтверждённого универсального rollback нет: **[Needs confirmation]**.
