# Глава 1 — cheatsheet

RAG p0021:c01–p0029:c01 · PDF 21–29 · печатные 20–28. Все сведения получены из RAG; это не протокол выполненных проверок.

## Symptom / problem framing
Требуется краткая условная команда. Ошибка в сочетании `||` и `;` способна завершить сценарий независимо от результата проверки. Книжный антипаттерн: `cd /tmp || echo "cd to /tmp failed." ; exit` (PDF 24–25).

## Baseline / context
- `[[ -n "$DIR" ]]` проверяет непустое значение, `[[ -z "$DIR" ]]` — пустое (PDF 21–24).
- `A && B` запускает B при успехе A; `A || B` — при неуспехе A (PDF 21–24).
- `&&` и `||` имеют одинаковый приоритет и ассоциативность слева направо (PDF 26).

## Read-only checks
- `help test` — объяснение ключей проверок, в том числе `-n` (PDF 23).
- `help [` — справка по встроенной проверке (PDF 23).
- `type -a команда` — определение типа/разрешения команды (PDF 23).
- `[[ -n "$DIR" ]]` / `[[ -z "$DIR" ]]` — проверить длину значения без изменения состояния (PDF 21–24).

## Interpretation
При пустом DIR правая часть `[[ -n "$DIR" ]] && cd "$DIR"` пропускается. При непустом значении будет предпринята попытка `cd`, но её успех отдельно не гарантирован. Команда после `;` в ошибочном примере выполняется независимо от предшествующего условия. [p0021–p0025:c01]

## Next action
Для одиночного короткого действия выбирать наиболее читаемую идиому; при составных ветвях и смешанных цепочках — сгруппировать команды либо использовать явный `if`. [p0024–p0029:c01]

## Modifying action
Из книги (не запускать без подтверждённого контекста):

```bash
[[ -n "$DIR" ]] && cd "$DIR"
cd /tmp || { echo "cd to /tmp failed." ; exit ; }
```

Первая команда может поменять текущий каталог; вторая в ветке ошибки выводит сообщение и завершает текущую оболочку/сценарий. Группировка в `{ ... ; }` обязательна для объединения действий в ветке `||`. [p0021–p0025:c01]

## Verification / acceptance checks
Проверить ожидаемый поток до запуска: успех левой части `&&` запускает правую, ошибка левой `||` запускает правую; действие `exit` находится внутри нужной ветки; смешанная цепочка интерпретирована слева направо. Фактические результаты в среде пользователя: **[Needs confirmation]**.

## Rollback
Возврат после `cd`, восстановление после `rm`, а также возобновление завершённого `exit` процесса в главе не документированы: **[Needs confirmation]**.
