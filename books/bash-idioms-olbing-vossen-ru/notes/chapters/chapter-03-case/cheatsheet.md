# Глава 3 — cheatsheet

Источник: PDF 43–57, RAG `p0043:c01–p0057:c01`. Никаких внешних сведений или результатов исполнения не добавлено.

## Symptom / problem framing

Нужно выбирать одно из нескольких действий по подкоманде или строковому шаблону. Длинные цепочки `if/then/else` могут быть менее понятны, чем `case`; сложный переход по `;&` и `;;&` повышает риск ошибки. [PDF 43, 55–57]

## Baseline / context

`case "$var" in` начинает выбор, `pattern)` отмечает вариант, `esac` закрывает конструкцию. `?` соответствует ровно одному символу, `*` — любому числу символов, `[Nn]` — одному символу из класса, `|` — альтернативным шаблонам одной ветви. Общую ветвь `*)` обычно ставят последней. Это glob-подобные шаблоны, **не** регулярные выражения. [PDF 43–45]

## Read-only checks

Перед запуском сравните входные значения с шаблонами и порядок ветвей. Например, `[Nn][Oo]*` охватывает слова, начинающиеся с «no» в разных регистрах; `[Yy]??` и `[Oo][Kk]*` демонстрируют другие совпадения. Проверьте, попадает ли неизвестное значение в последнюю `*)`. [PDF 44–45]

В примере `list.sh` сначала проверьте, какая ветвь соответствует `color`, `last|latest`, `len*`, `long` или неизвестной команде. [PDF 46–48]

## Interpretation

После совпадения: `;;` завершает ветвление; `;&` переходит к следующему телу **без** проверки его шаблона; `;;&` продолжает сравнивать последующие шаблоны. Три варианта не эквивалентны. [PDF 55–57]

## Next action

Для нового сценария-обёртки составьте список подкоманд, явно укажите шаблоны, общий `*` поставьте после специальных случаев и документируйте нестандартные переходы. Для сложных комбинаций вместо `;&`/`;;&` авторы предлагают рассмотреть обычный `if/then/else`. [PDF 55–57]

## Modifying action

В `wrapper.sh` операции `index`, `rerun` и `cleanup` изменяют файлы; подкоманды работы с буфером обмена могут изменить его содержимое; `cd` меняет каталог, `shift` — параметры оболочки. До запуска нужны точные пути, список затрагиваемых файлов и одобрение действия. [PDF 49–52]

## Verification / acceptance checks

Подтвердить выбранную ветвь на допустимых и недопустимых входах; перед файловой операцией — цель, ожидаемый эффект и результат; после изменения — фактический итог. Ни один пример главы не был выполнен для данной среды: **[Needs confirmation]**.
