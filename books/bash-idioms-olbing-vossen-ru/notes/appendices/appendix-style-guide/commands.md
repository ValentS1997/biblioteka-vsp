# Приложение — команды и конструкции из RAG

**Источник:** PDF 193–202, чанки `p0193:c01–p0202:c01`. Классы: **read-only**, **workload-generating** (вычисление/вывод), **state-changing** (изменяет переменные, поток исполнения, файлы либо внешнее состояние). Это стилевые иллюстрации, не самостоятельные проверенные рецепты.

| Форма из источника | Класс | Действие и оговорки |
| --- | --- | --- |
| `source` для файлов `.cfg`/`.conf` | **state-changing по содержимому** | Авторы предпочитают явную команду точке; исполняет подключённый код, а не читает как обычный текст (PDF 194). |
| `sort -V` | workload-generating / read-only к входным данным | GNU-версия сортировки для упорядочивания данных; переносимость требуется проверять (PDF 194). |
| `diff --quiet` / `diff -q` | workload-generating / read-only к входным данным | Предпочтение длинной форме ключа при наличии поддержки (PDF 194). |
| `readonly`, `declare -r` | **state-changing (shell variable)** | Отмечать константы (PDF 195). |
| `for var in $regular_var` | workload-generating по телу | Пример, который авторы предлагают рассмотреть вместо сложного массива; **не гарантирует сохранения границ слов**, реальный контекст [Needs confirmation] (PDF 196). |
| `grep -P '^\s*function '` | workload-generating / read-only input | Поиск строк с `function`, availability/применимость [Needs confirmation] (PDF 196). |
| `function My_Func_Name {` | **state-changing (shell namespace)** | Объявление функции; описание параметров и глобальных зависимостей требуется по стилю (PDF 196). |
| `local junk1="$2"` | **state-changing (local shell variable)** | Заполнитель ради читаемости в примере функции (PDF 197). |
| `local my_input` | **state-changing (local shell variable)** | Объявление отдельно от последующего присваивания (PDF 197). |
| `my_input="$(some-command)"` | state-changing по присваиванию; вложенная команда **может иметь побочные эффекты** | `some-command` — placeholder. В источнике раздельность показана ради сохранения кода неуспешного выполнения (PDF 197). |
| `[[ "$foo" == 'bar' ]]` | read-only при чистом сравнении | Строковое сравнение, иллюстрация кавычек (PDF 198). |
| `var="$(command)"` | state-changing (переменная), действие команды зависит от тела | Подстановка команды в кавычках. `command` — placeholder, не подтверждённая безопасная операция (PDF 198). |
| `echo "cd to '$DIR' failed"` | workload-generating | Сообщение об ошибке с визуальным выделением значения переменной (PDF 198). |
| `printf` с одинарными кавычками вокруг формата | workload-generating | Стилевое предпочтение для форматов, без отдельного нового рецепта (PDF 198). |
| `if expression; then`, `for expression; do`, `case ... esac` | зависит от тел | Примеры единой строки начала блока и правил отступов, не исполняемые алгоритмы (PDF 199). |
| `#!/bin/bash -`, `#!/usr/bin/env bash` | параметр исполнения, не standalone-команда | Bash shebang. `#!/bin/sh` отвергается для кода, рассчитанного на Bash (PDF 199). |
| `"$@"` / `"$*"`, `$(...)` | read-only как подстановка **либо** workload/state-changing по выражению | Выбирать `$@` по умолчанию, `$(...)` вместо обратных кавычек; содержимое может запускать команды (PDF 200). |
| `[[ ... ]]` / `[ ... ]` | read-only при чистой проверке | Для Bash предпочитается `[[` при отсутствии задачи POSIX-совместимости (PDF 200). |
| `(( ... ))` / `$(( ... ))` | read-only **или** state-changing по выражению | Арифметический статус/значение; возможны присваивания; `let`/`expr` авторы советуют избегать (PDF 200). |
| `[[ expression ]] && block`, `[[ expression ]] || block` | зависит от блока | Допустимые читаемые сокращения; цепочку с `&& block || block` авторы не рекомендуют как замену `if` (PDF 200). |
| `set -euo pipefail` | **state-changing (shell policy)** | Неофициальный строгий режим; авторы предлагают попробовать, не гарантируют отсутствие ошибок (PDF 200–201). |
| `IFS=$'\n\t'` | **state-changing (word splitting)** | Авторы рекомендуют осторожность, предпочтительно избегать (PDF 200–201). |
| Syslog (журналирование) | **state-changing (external log)** | Рекомендация для системных сценариев; точная команда не предоставлена, не добавляем её из внешних знаний (PDF 200). |
| `echo 'A Bad Thing happened' 1>&2` | workload-generating | Явная отправка ошибки в STDERR (PDF 200). |
| `[ -x /path/to/tool ]` | read-only при чистой проверке | Проверка наличия исполняемого инструмента, `/path/to/tool` — placeholder (PDF 200). |
| `exit` | **state-changing (control flow)** | Явные коды завершения, особенно для ошибки (PDF 200). |
| `PROGRAM=${0##*/}`, `ID=''`, `LOG_DIR='/path/to/log/dir'` | **state-changing (shell vars)** | Демонстрационный шаблон; реальные пути и переменные требуют настройки (PDF 201). |
| `function Foo {`, `function Bar {` | state-changing по определению | Функции шаблона содержат `...` и неполные тела. В комментариях к закрытию имена записаны строчными (PDF 201–202), см. [source-findings.md](source-findings.md). |

## Read-only → change → verification

Сначала сверить выбранную оболочку, читаемость, отступы, значения аргументов и зависимости. **Ни один вариант `source`, `set`, `IFS` или шаблон со строками `...` не запускать без проверки конкретного пользовательского сценария.**

Перед изменениями подтвердить место вызова, состояние переменных и ожидаемый статус; после — проверить код завершения, вывод и поведение. В RAG нет замеров конкретной среды и универсального rollback: **[Needs confirmation]**.

В тексте приложения на PDF 198 оператор для regex выглядит как `~=`; он сохранён отдельно в [source-findings.md](source-findings.md). Никаких команд, не встречающихся в источнике, не добавлено.
