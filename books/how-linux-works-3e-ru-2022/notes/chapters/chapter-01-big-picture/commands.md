# Команды, системные вызовы и интерфейсы главы 1

В главе мало shell-команд. Таблица ниже включает только явно подтверждённые RAG главы элементы; знакомые Linux-команды из внешнего знания не добавлялись.

## v1.6 command contract normalization

Для всех строк с типом `state-changing` применяется следующий контракт:

- **Effect** — действие, явно указанное в колонке «Роль в главе»/описании строки.
- **Risk** — только source-supported ограничение/риск из строки; если отдельный риск не дан, `[Needs confirmation]`.
- **Verification** — только явно указанный source-supported check; если check не дан, `[Needs confirmation]`.
- **Rollback** — только явно указанный обратный путь; если источник его не даёт, `[Needs confirmation]`.

Этот блок является нормативной интерпретацией таблицы ниже для `BIBLIOTEKA-VSP-CHAPTER-ARTIFACT-COLLECTION v1.6`; недостающие поля не достраиваются из model knowledge.

| Элемент | Роль в главе | Тип | Effect / риск | Verification | Rollback |
|---|---|---|---|---|---|
| <code>ls</code> | Пример программы, запускаемой из командной строки | read-only | Выводит содержимое каталога; в главе используется для демонстрации запуска процесса | Наблюдать запуск программы и её вывод | <code>[Not applicable]</code> |
| <code>fork()</code> | Системный вызов: ядро создаёт почти идентичную копию процесса | workload-generating | Создаёт новый процесс/копию процесса | В главе проверка отдельной командой не приводится | <code>[Needs confirmation]</code> |
| <code>exec(program)</code> | Семейство системных вызовов: ядро загружает программу и заменяет текущий процесс | state-changing | Меняет образ текущего процесса на указанную программу | В главе проверка отдельной командой не приводится | <code>[Needs confirmation]</code> |
| <code>/dev/random</code> | Пример псевдоустройства, реализованного ядром | read-only | Показывает kernel-provided interface, выглядящий для процесса как устройство | Способ проверки в главе не задан | <code>[Not applicable]</code> |

## Пример запуска <code>ls</code>

~~~text
shell process
   │
   ├─ fork()
   │    └─ почти идентичная копия shell
   │
   └─ child process → exec(ls)
                        └─ образ процесса заменён программой ls
~~~

Это пример взаимодействия пользовательского процесса с ядром через системные вызовы.

## Дополнительные компоненты, явно названные в главе

| Компонент | Что подтверждено источником |
|---|---|
| <code>init</code> | Указан как исключение из общего утверждения о запуске новых пользовательских процессов через <code>fork()</code>; детали отложены до главы 6 |
| <code>kthreadd</code>, <code>kblockd</code> | Примеры потоков ядра с доступом к kernel space |
| <code>syslog</code> | Стандартная служба логирования, которую используют многие программы пользовательского пространства |
| UID | Числовой идентификатор пользователя, которым оперирует ядро |
| root | Суперпользователь с широкими правами над процессами и файлами, но всё ещё в user mode |

## Operational boundary

Дополнительные знакомые Linux-команды из внешнего знания намеренно не добавлялись: файл ограничен элементами, явно подтверждёнными RAG главы.

State-changing административных команд в главе 1 нет. Для <code>fork()</code> и <code>exec()</code> rollback как системного механизма в источнике не описан: <code>[Needs confirmation]</code>.
