54 ■  Глава 2

Многоступенчатые сборки

Оптимизировать процесс сборки образов позволяют и многоступенчатые сборки,
благодаря которым можно значительно сократить размер создаваемого образа.
В многоступенчатых сборках используется несколько инструкций FROM в Dockerfile.
Каждая инструкция FROM задает отдельную базу и начинает новый этап сборки. Мы
можем копировать все необходимое из одного этапа на другой и исключать ненуж
ное  из  финального  образа.  Многоступенчатая  сборка  позволяет существенно
уменьшить размер финального образа, так что нам не придется стараться сократить
количество слоев в образе.
Теперь, вооружившись необходимыми знаниями, давайте напишем Dockerfile и со
берем образ.
vi Dockerfile
FROM uЬuntu : latest
ENV НОМЕ /root
LAВEL uЬuntu=myuЬuntu
ENTRYPOINT ["sleep"]
CMD  ["50" ]
RUN useradd -m -G root testuser
USER root
RUN apt-get update && apt-get install net-tools - у
RUN apt-get install iputils-ping -у

Далее сохраним файл , закроем редактор и запустим команду сборки:
docker build --tag myuЬuntu_image   .

Это команда для сборки образа из текущего каталога (не пропустите точку в конце
команды). Вы могли заметить, что мы намеренно не оптимизировали образ, ис
пользовав несколько отдельных команд RUN, в результате чего каждой из них был
собран и сохранен отдельный слой образа.
Чтобы оптимизировать сборку, достаточно запустить одну команду RUN и перечис
лить все элементы , разделив их двойным амперсандом   ( &&). Тогда образ будет
меньше. Вот как это выглядит (рис. 2.39).
