ADD. Команда ADD просто копирует файлы из исходного расположения  ( на хосте)

адресу.

EXPOSE. Указывает порты, которые контейнер будет прослушивать во время выпол

те внимание: EXPOSE не публикует порт, а просто сообщает о портах, которые можно
опубликовать при запуске контейнера.

WORКDIR. Задает рабочий каталог для инструкций RUN, CMD, ENTRYPOINТ, СОРУ и ADD. Если не
указать WORКDIR, каталог все равно будет создан , даже если в конечном итоге он не
будет использоваться в других инструкциях Dockerfile.
USER. Эта инструкция задает UID (имя пользователя) или GID (группу пользовате
лей), которые будут использоваться при выполнении контейнера, созданного из
образа, с инструкциями RUN, CMD и ENТRYPOINТ.

VOLUМE. Инструкция VOLUME просто создает точку монтирования с указанным именем.
Значение тома можно записать как массив JSON или обычную строку. Создание
нового тома инициализирует команда docker run.

Кеш сборки

Когда мы собираем образ, Docker выполняет инструкции в Dockerfile строка за
строкой. Процесс отчасти оптимизирован -  прежде чем выполнить инструкцию,
Docker ищет существующий образ в кеше и, если находит, использует его, чтобы не
создавать дубликат. Этот кеш , известный как кеш сборки, позволяет оптимизиро
вать работу Docker.
Здесь стоит упомянуть, что локальная сборка образов на хосте Docker происходит
немного иначе. Базовое содержимое локально собранного образа остается таким
же, как в образе, извлеченном из реестра, но объект конфигурации, содержащий
элементы конфигурации, включая упорядоченный список контрольных сумм (дай
джестов) слоев , немного отличается.

Существует так называемый промежуточный образ, который создается , когда мы
фиксируем слой во время сборки образа. Промежуточный образ имеет все внешние
атрибуты финального образа. У него тоже есть объект конфигурации, который
представляет собой список контрольных сумм, используемых Docker Engine для
создания файловой системы. Эти промежуточные образы также включают иденти
фикатор родительского образа, т. е. образа слоя, который находится сразу под ним.

Промежуточные  образы и ссылки на родительские образы используются для
сопоставления с существующими образа.ми в кеше сборки. Если совпадение найде
но, Docker будет использовать его , чтобы не создавать этот образ повторно.
