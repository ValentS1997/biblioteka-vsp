126 ■  Глава 6
Сеть Host
Для создания контейнера также можно использовать сеть хоста (host). При этом
контейнер создается без своего пространства имен сети и использует пространство
имен сети хоста. Кроме того , контейнеру не назначается собственный IР-адрес .
Зачем может понадобиться такая конфигурация? Обычно только в том случае, если
требуется отладить или проанализировать трафик сети host.

   У контейнера нет собственного сетевого стека, -  он использует сетевой стек хоста, по
   этому нет возможности сопоставить порты. Любые параметры для сопоставления пор
   тов будут игнорироваться, и мы получим предупреждение .

Запустить контейнер с использованием пространства имен хоста очень просто -
достаточно подключить контейнер к сети хоста, как показано на рис. 6.16.
docker run -dit --name hostnet --network host busybox:latest

Давайте узнаем IР-адрес хоста и сравним его с IР-адресом контейнера. IР-адреса
выделены на рис. 6.17. Это ожидаемое поведение.
ifconfig -а eth0
docker ехес -it hostnet sh
ip addr

Мы видим, что из контейнера доступен весь сетевой стек хоста, а IР-адреса совпа
дают. Как было сказано ранее , у контейнера нет собственного сетевого стека.

Сеть None
Если контейнеру не нужна связь с внешним миром, можно использовать сеть None.
В этом случае контейнер будет полностью изолирован от внешнего мира, а выпол
няющееся в нем приложение будет существовать только в пределах контейнера.
Давайте посмотрим, как это работает, запустив соответствующую команду и изу
чив рис . 6.18.
docker run -dit --name nonenet --network none busybox:latest

Как и ожидалось, у контейнера нет интерфейса для соединения с внешним миром.
