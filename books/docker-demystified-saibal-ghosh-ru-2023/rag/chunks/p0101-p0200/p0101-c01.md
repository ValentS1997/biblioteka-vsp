Блокировка и разблокировка кластера Swarm
Начиная с Docker 1.13, где было представлено управление секретами, журналы Raft
хранятся на диске в зашифрованном виде. Может возникнуть вопрос: почему эти
журналы так важны? Дело в том, что у всех управляющих узлов должен быть
доступ к одной и той же версии журналов, чтобы в случае сбоя лидера любой из
доступных управляющих узлов мог взять на себя его роль.
С появлением функции секретов в Docker можно обеспечивать шифрование журна
лов Raft в месте хранения, чтобы защитить их от злоумышленников.

Пара ключей, которая используется для шифрования, хранится вместе с зашифро
ванными журналами. Для шифрования журналов Raft и защиты взаимодействия
между узлами используется закрытый (private) ключ.
При перезапуске Docker ключи для шифрования и дешифрования журналов Raft на
диске и все, что касается обеспечения безопасности коммуникаций (Transport Layer
Security, TLS) между узлами, кешируется в памяти каждого управляющего узла.
Начиная с версии Docker 1.13, эти ключи можно использовать, чтобы блокировать
и разблокировать Swarm. Данная функция называется автоблокировкой (autolock).
При наличии автоблокировки управляющий узел после перезапуска должен предъ
явить ключ разблокировки кластера, чтобы вернуться в этот кластер.

   При добавлении нового узла в кластер Swarm нет необходимости его разблокировать ,
   поскольку ключ распространяется через взаимный TLS.
При перезапуске Docker нужно сначала разблокировать Swarm с помощью ключа
шифрования, который Docker создал при блокировке Swarm. Этот ключ шифрова
ния можно сменить в любое время.
