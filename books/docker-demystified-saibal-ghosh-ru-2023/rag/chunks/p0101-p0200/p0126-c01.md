Сети Docker ■  131

2. Драйвер MACVLAN работает только на хосте Linux и не поддерживается
    в Docker Desktop для Мае и Windows или Docker Engine Enterprise (ЕЕ) для
  Windows Server.
3. Для использования MACVLAN требуется версия ядра Linux не ниже 3.9, а луч
  ше 4.0 и выше.
4. Интерфейс MACVLAN должен быть назначен той же подсети, что и родитель
   ский интерфейс.
5. Сетевая карта (NIC) хоста должна находиться в режиме promiscuous (неразбор
   чивый).
6. Для каждого родительского интерфейса в одной подсети можно определить
   только одну сеть типа МACVLAN.
7. Можно указать диапазон IР-адресов для контейнера, а также вспомогательный
   адрес, который система IPAM в Docker не должна назначать контейнерам.
Сеть MACVLAN может работать в режимах bridge и trunk bridge по стандар
ту 802.1 Q. Разница в том, что в режиме bridge трафик проходит через физический
интерфейс на хосте , а в режиме trunk bridge 802. lQ Docker создает подынтерфейс,
который является частью родительского. Единственное преимущество последнего
варианта заключается в том , что мы можем более детализированно контролировать

процессы и параметры сети.

MACVLAN в режиме bridge

Давайте создадим сеть МACVLAN, используя родительский интерфейс eth0. Преж
де всего узнаем IР-адрес и подсеть, связанные с интерфейсом eth0. Для этого ис
пользуем команду ifconfig -а eth0, а затем изучим выходные данные на рис. 6.26.


        root@dockernet:~# ifconfig -а ethO

                 inet6 fe80::e037:c5ff:fe75:70af  prefixlen 64  scopeid Ox20<link>
                ether e2 :37:c5:75:70:af  txqueuelen 1000  (Ethernet)
                 RX packets 15513  bytes 109165518 (109.1 МВ)
                 RX errors О  dropped О  overruns О  frame О
                ТХ packets 6839  bytes 875207 (875.2 КВ)
                ТХ errors О  dropped О overruns О  carrier О  collisions О
