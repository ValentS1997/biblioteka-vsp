Сети в Docker Swarm
Понимание принципов работы сетей в Docker Swarm крайне важно. Этой теме
посвящена вся следующая глава, а здесь мы рассмотрим сети в контексте Swarm.
При создании кластера Swarm происходит следующее:
1. Создается сетевой мост с именем docker _gwbridge, который используется для со
   единения контейнеров в кластере Swarm с внешним миром.
2. Создается оверлейная сеть с именем ingress, которая отвечает за коммуникации
  между контейнерами.

Если оверлейная сеть не определена пользователем, создается сеть по умолчанию
с именем ingress, которая используется для контроля и передачи данных в пределах
кластера Swarm.

Мы можем создавать пользовательские оверлейные сети и сетевые мосты , причем
сервисы и контейнеры могут быть подключены к нескольким сетям одновременно.

  Правила межсетевого экрана для демонов Docker
  при использовании оверлейных сетей
   Нужно открыть следующие порты для входящего и исходящего трафика каждого хоста
   Docker в составе оверлейной сети:
     •  ТСР 2377(для управления коммуникациями кластера) ;
     •  ТСР и UDP 7946 (для коммуникаций между узлами);
     •  UDP 4789 (для трафика оверлейной сети).

Теперь давайте узнаем, какие сети доступны для управляющего узла Swarm.
Команда и выходные данные ниже (рис. 5.28).
docker network ls
