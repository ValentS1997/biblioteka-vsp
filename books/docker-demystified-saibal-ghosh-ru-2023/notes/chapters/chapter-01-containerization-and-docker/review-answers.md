## Ответы на открытые вопросы

### 1. Что такое контейнер?

В логике главы контейнер — изолированная среда, в которую упаковываются приложение, его конфигурация, библиотеки и другие зависимости. Контейнер использует ядро операционной системы хоста совместно с другими контейнерами и не требует отдельной гостевой ОС.

### 2. Чем контейнер отличается от виртуальной машины?

Виртуальная машина использует отдельную операционную систему и слой гипервизора. Контейнер использует ядро хоста и поэтому легче, быстрее запускается и требует меньше вычислительных ресурсов. Глава также связывает контейнер с переносимостью одинаковой runtime-среды между development, test и production.

### 3. Что такое Docker Registry?

Docker Registry — система хранения и доставки Docker-образов. Образы различаются по тегам; их можно отправлять в registry и получать из него. Registry может быть публичным или закрытым.

### 4. Что такое Docker Swarm?

Docker Swarm представлен как встроенный в Docker механизм кластеризации и оркестрации. Он используется для управления и масштабирования контейнерных сервисов на одном или нескольких хостах.

### 5. Что такое микросервисы?

Микросервисы — компоненты приложения с чётко определёнными границами, которые можно развёртывать, изменять, обновлять и масштабировать независимо друг от друга. Контейнеры дают каждому такому сервису изолированную среду выполнения.

### 6. Какие встроенные функции безопасности имеются в Docker?

Глава перечисляет несколько уровней защиты:

- namespaces изолируют процессы контейнера;
- cgroups ограничивают ресурсы и помогают их распределять;
- контейнер получает отдельную сетевую инфраструктуру;
- capabilities позволяют ограничить набор привилегий;
- Docker Content Trust позволяет Docker Engine запускать только подписанные образы;
- принцип минимальных привилегий используется как базовая рекомендация.

При этом источник отдельно указывает, что Docker daemon является чувствительной security boundary: доступ к нему должен быть ограничен доверенными пользователями.
