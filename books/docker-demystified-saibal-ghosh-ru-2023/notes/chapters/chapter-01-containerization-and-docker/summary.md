# Итог главы 1

## Заключение

Глава вводит контейнеризацию как способ упаковать приложение вместе с его runtime-средой и зависимостями в переносимую и изолированную единицу. В отличие от виртуальной машины контейнер не требует отдельной гостевой ОС и использует ядро хоста совместно с другими контейнерами, что делает его легче и быстрее.

Docker представлен как платформа контейнеризации и набор компонентов для создания, управления, доставки и оркестрации контейнеров. Docker Engine использует клиент-серверную модель, где клиент взаимодействует с Docker daemon через API, а демон управляет контейнерами, образами, сетями, хранилищами и томами.

Docker Registry выполняет роль хранилища и механизма доставки образов по тегам; Docker Hub рассматривается как облачный вариант такого репозитория. Registry естественно включается в CI/CD-поток.

Контейнеры хорошо сочетаются с микросервисной архитектурой: отдельные сервисы можно развертывать, масштабировать и обновлять независимо, а контейнер предоставляет каждому из них изолированную среду.

Базовая security-модель главы включает namespaces, cgroups, сетевую изоляцию, контроль доступа к Docker daemon, capabilities, принцип минимальных привилегий и Docker Content Trust.

## Основные тезисы

- Контейнер включает приложение, runtime-среду и зависимости.
- Контейнер не требует отдельной гостевой ОС и использует ядро хоста.
- Контейнеры легче ВМ и быстрее запускаются.
- Docker работает как платформа управления контейнерами и связанными объектами.
- Docker Engine состоит из демона, REST API и CLI.
- Docker Registry хранит и доставляет образы; Docker Hub — облачный репозиторий образов.
- Контейнеризация уменьшает расхождения между development, test и production.
- Микросервисы и контейнеры дополняют друг друга за счёт независимого развёртывания и масштабирования.
- Docker Swarm в главе представлен как встроенный механизм кластеризации и оркестрации.
- Security boundary включает изоляцию, ограничения ресурсов, контроль доступа к daemon и ограничение привилегий.

## Ключевые термины

| Термин | Смысл в главе |
|---|---|
| Контейнер | Упакованное приложение с runtime-средой и зависимостями, выполняемое изолированно и использующее ядро хоста |
| Docker Engine | Клиент-серверная система из daemon, REST API и CLI |
| Docker Registry | Система хранения и доставки Docker-образов по тегам |
| Docker Hub | Облачный репозиторий для создания, тестирования, хранения и распространения образов |
| Docker Swarm | Встроенный в Docker инструмент кластеризации и оркестрации |
| Микросервис | Компонент с чёткими границами, который можно независимо развёртывать, обновлять и масштабировать |
| Namespace | Механизм изоляции процессов контейнера |
| cgroups | Механизм ограничения и распределения ресурсов |
| Capabilities | Набор отдельных привилегий, который можно ограничивать |
| Docker Content Trust | Проверка подписанных образов перед запуском |
