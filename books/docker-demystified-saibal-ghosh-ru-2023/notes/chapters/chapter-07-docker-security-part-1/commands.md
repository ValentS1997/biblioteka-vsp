# Команды главы 7

Команды основаны только на RAG главы 7. Изменение kernel boot parameters, MAC policy, Docker daemon config и host security mode может привести к потере доступа или остановке workloads.

## Read-only / observation

| Команда | Что проверяет | Risk |
|---|---|---|
| `ps` | Process view inside namespace | read-only |
| `ifconfig` / `ip addr` | Container network namespace | read-only |
| `cat /proc/sys/kernel/cap_last_cap` | Highest capability number in source environment | read-only |
| `capsh --print` | Current/bounding capabilities | read-only |
| `lscpu \| grep CPU` | Host CPU information | read-only |
| `apparmor_status` / `aa-status` | AppArmor module/profiles/modes | read-only |
| `getenforce` / `sestatus` | SELinux state/mode | read-only |
| `docker info --format '{{ .SecurityOptions }}'` | Docker security options | read-only |
| `docker inspect <id> \| grep "Label"` | Process/mount labels | read-only |
| `grep CONFIG_SECCOMP= /boot/config-$(uname -r)` | Kernel seccomp config | read-only |

## Namespace experiments

### PID

```bash
docker run -dit --name test couchbase
docker run -dit --name test1 couchbase
docker exec -it test sh
ps
docker exec -it test1 sh
ps
```

Effect: creates containers and compares process namespaces.

### NET / same container port

```bash
docker run -dit --name test_nw -p 80:4000 busybox:latest
docker run -dit --name test1_nw -p 81:4000 busybox:latest
```

Effect: publishes two host ports to the same internal port in separate containers.

### IPC sharing

```bash
docker run -dit --name shared --ipc shareable centos
docker run -dit --name shared1 --ipc container:shared centos
```

Effect: second container joins the IPC namespace of the first.

### Drop CAP_CHOWN

```bash
docker run -dit --name test1 --cap-drop cap_chown centos:latest
docker exec -it test1 sh
touch myfile
chown 5000 myfile
```

Expected source result: `Operation not permitted`.

### Add LINUX_IMMUTABLE

```bash
docker run -dit --name test --cap-add linux_immutable ubuntu:latest
docker exec -it test sh
touch myfile
chattr +i myfile
rm myfile
chattr -i myfile
rm myfile
```

Expected:
- removal fails while immutable bit is set;
- succeeds after `chattr -i`.

## AppArmor package/profile management

Install utilities:

```bash
apt install apparmor-utils
```

Effect: modifies host packages.

Observe:

```bash
apparmor_status
aa-status
```

Create autogenerated profile:

```bash
aa-autodep useradd
```

Effect: writes AppArmor profile under `/etc/apparmor.d`.

Set enforce:

```bash
aa-enforce useradd
aa-status
```

Effect: policy may block `useradd` even for root.

Tune from logs:

```bash
aa-logprof
```

Interactive state-changing policy edit.

### Docker default profile

```bash
docker run -dit --name test_profile busybox:latest
aa-status
```

Explicit attach:

```bash
docker run -dit --name test_profile1   --security-opt apparmor=docker-default   ubuntu:latest
```

## Enable SELinux integration in Docker

Edit/create `/etc/docker/daemon.json`:

```json
{
  "selinux-enabled": true
}
```

Then:

```bash
systemctl restart docker
docker info --format '{{ .SecurityOptions }}'
```

Acceptance in source: security options include `name=selinux`.

Inspect container labels:

```bash
docker run -dit --name test ubuntu:latest
docker inspect <container-id> | grep "Label"
```

MCS category example:

```bash
docker run -dit --name max   --security-opt label=level:s0:c0,c3   busybox
```

## Safety boundary

- Do not edit GRUB, SELinux mode, AppArmor profiles, sysctl, or Docker daemon configuration without rollback access.
- Dropping capabilities can break application functionality.
- Adding capabilities expands privilege and attack surface.
- AppArmor/SELinux policy changes can block administrative commands or container startup.
- Reboot/restart Docker affects workloads.
