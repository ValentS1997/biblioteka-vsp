# Глава 5 — source findings (RAG-only)

Цель: сохранять расхождения текстового источника и ограничения воспроизводимости, **не исправляя их по модели или внешней документации**. Все ссылки — RAG PDF 197–228. `RAG_MISS` означает недоступность конкретного значения из неразмеченного рисунка.

## 1. [Source code mismatch] Различающиеся интерфейсные OID в пояснении LLD

- **Вариант A:** перед перечислением значений `{#IFNAME}` пояснение на p222 содержит строку «после OID `.1.3.6.1.2.1.2.2.2.1.2` заполняем LLD-макрос» — [p0222](../../../rag/chunks/p0201-p0300/p0222-c01.md).
- **Вариант B:** **на той же странице** перечислены `.1.3.6.1.2.1.2.2.1.2.1 = STRING: lo` и `.1.3.6.1.2.1.2.2.1.2.2 = STRING: ens192`, где перед суффиксом индексного значения **нет дополнительного `.2`**. Далее p223 ссылается на второй вид OID, `.1.3.6.1.2.1.2.2.1.2` + индекс — [p0222](../../../rag/chunks/p0201-p0300/p0222-c01.md), [p0223](../../../rag/chunks/p0201-p0300/p0223-c01.md).
- **Следствие:** literal OID правила LLD нельзя копировать из первого абзаца как проверенный. Точное правило `net.if.discovery` и поля с рисунка 5.38 = `RAG_MISS`; точный OID в целевой среде = `[Needs confirmation]`. Сохранены оба варианта, без незаметной правки.

## 2. [Source wording/code mismatch] Семантика Operational status и 0/up(1)

- **Вариант A:** p223 приводит `.1.3.6.1.2.1.2.2.1.8.1 = INTEGER: up(1)` и `...1.8.2 = INTEGER: up(1)`, то есть конкретное наблюдаемое значение `up(1)` — [p0223](../../../rag/chunks/p0201-p0300/p0223-c01.md).
- **Вариант B:** p224 описывает обнаруженный триггер: `Operational status = 0`, `Admin status = 1` и поясняет, что событие нужно только если административно интерфейс включён — [p0224](../../../rag/chunks/p0201-p0300/p0224-c01.md).
- **Следствие:** текст даёт пример `up(1)` и отдельную формулировку `Operational status = 0`; **полного expression и значения, означающего down, в текстовом RAG нет**. Нельзя на основании этих фрагментов утверждать безошибочность готового триггера. Точная формула на рис. 5.42: `RAG_MISS`, семантика порогов = `[Needs confirmation]`.

## 3. [Needs confirmation] Мгновенное удаление LLD-ресурсов и истории

- **Рецепт:** p217 ставит `Delete lost resources = Immediately` для **тестового** template — [p0217](../../../rag/chunks/p0201-p0300/p0217-c01.md).
- **Предупреждение того же источника:** кратковременная пропажа SNMP-ресурса может привести к удалению автоматически созданных items/triggers **вместе с их историческими данными**. Книга предлагает изменить политику под стандарт production, но **не даёт конкретной безопасной длительности или rollback удалённой истории**.
- **Следствие:** не рекомендовать Immediately для production и не объявлять восстановление истории возможным без резервного плана. Правильная retention policy и восстановление = `[Needs confirmation]`.

## 4. [Needs confirmation] Конфигурация SNMP и секреты

- [p0203](../../../rag/chunks/p0201-p0300/p0203-c01.md) включает `snmpwalk` с буквальными демонстрационными `my_authpass`, `my_privpass`, `snmpv3user` и IP. В [commands.md](commands.md) они заменены на placeholders, чтобы не превращать учебные credentials в рекомендацию.
- [p0206](../../../rag/chunks/p0201-p0300/p0206-c01.md) советует использовать тип «скрытый текст» для макросов, **но в рамках этой главы нет подтверждённого механизма шифрования хранимых значений**. Не утверждать, что secret text обеспечивает encryption at rest.
- [p0216](../../../rag/chunks/p0201-p0300/p0216-c01.md) приводит `view systemview included .1` для открытия SNMP-дерева. Риск расширения доступа к данным и policy правильной view: `[Needs confirmation]`.

## 5. [Needs confirmation] Формы LLD/макросов/триггеров доступны только на рисунках

Рисунки 5.1–5.2 (точные fields создания шаблона), 5.10–5.13 (SNMP item/host macros), 5.15–5.25 (trigger expressions и имя `{$...}`), 5.28–5.38 (Value mapping, discovery rule, prototypes и теги), 5.43–5.46 (uptime item и template binding) не закодированы отдельно в текстовом RAG. Их конкретные значения **`RAG_MISS`**. Книга текстом подтверждает `sysName`, OID, имя шаблона, `{#IFNAME}`/`{#SNMPINDEX}` и организацию workflow, но не все поля окон. Не реконструировать рабочие expression, keys и filters по памяти или сторонней документации.
