Источник: **accepted RAG PDF 412–433**. Все внешние программы и UI-only значения остаются не подтверждёнными: `RAG_MISS`. Варианты исходника сохранены и не заменены исправлениями из памяти или текущего Интернета.

## 1. [Source wording/code mismatch] Разные пути results

- **Вариант A:** после `python3 api_test.py` на [p0421](../../../rag/chunks/p0401-p0500/p0421-c01.md) сказано посмотреть результат через **`cat /home/zabbix/results`**.
- **Вариант B:** объяснение на [p0422](../../../rag/chunks/p0401-p0500/p0422-c01.md) говорит, что `generate_host_file` пишет результат в **`/home/results`**.
- **Следствие:** конечный путь не установлен надёжно без отсутствующей точки входа `api_test.py` и её `host_file`. Запись файла в произвольное место `[Needs confirmation]`, обе версии сохранены.

## 2. [Source code mismatch] Команда mv стороннего скрипта слиплась

- **Буквальная строка** [p0428](../../../rag/chunks/p0401-p0500/p0428-c01.md): `mv zabbix-toggle-hosts-from-frontend-2.0/enable_disable-host.py./`.
- Описание требует перенести скрипт из распакованного каталога в текущий, но **между исходным файлом и `./` нет разделителя-аргумента**; после `.py` прямо следует `./`.
- **Решение:** literal строку не исполнять. В журнале `commands.md` она только упоминается как неисполнимая; фактический архив, файл и его расположение не проверялись — `[Needs confirmation]`.

## 3. [Source wording/code mismatch] Jumphost cron-путь не соответствует установленному расположению

- **Подготовка:** [p0424](../../../rag/chunks/p0401-p0500/p0424-c01.md) предлагает `wget https://raw.githubusercontent.com/cheatas/zabbix_scripts/main/host_pull_zabbix.py`, но **не показывает** `cd /home` или перемещение скрипта именно в `/home/`.
- **Автоматизация:** [p0426](../../../rag/chunks/p0401-p0500/p0426-c01.md) задаёт `*/15 * * * * $(which python3) /home/host_pull_zabbix.py >> ~/cron.log 2>&1`.
- **Следствие:** путь в cron не вытекает из предшествующей последовательности. Фактическая директория, permissions, регулярный запуск, обработка ошибок и безопасный rollback cron = `[Needs confirmation]`.

## 4. [Source wording/code mismatch] Jumphost endpoint содержит другое имя API

- **Вариант A:** [p0419](../../../rag/chunks/p0401-p0500/p0419-c01.md) и [p0424](../../../rag/chunks/p0401-p0500/p0424-c01.md) показывают `http://10.16.16.152/api_jsonrpc.php` как пример API endpoint.
- **Вариант B:** p424 предлагает заменить первоначальный `https://myzabbix.com/apijsonrpc.php` в переменной `zabbix_url`. Здесь **`apijsonrpc.php`** без подчёркивания `_`, в отличие от второго пути.
- **Следствие:** не считать оба написания эквивалентными; конкретный правильный URL целевого Zabbix проверяется отдельно. Доступ по незашифрованному `http://` для token-bearing API небезопасен без отдельного защищённого канала — `[Needs confirmation]`.

## 5. [Source security risk] Super admin и практически бессрочный API-токен

- **Учебный рецепт:** [p0413](../../../rag/chunks/p0401-p0500/p0413-c01.md)–[p0416](../../../rag/chunks/p0401-p0500/p0416-c01.md) создаёт `API Users` с `Read-write` на многочисленные host/template groups, назначает `API` роль **Super admin** и предлагает далёкий срок `Expires` либо отключение срока.
- **Второе утверждение того же источника:** [p0414](../../../rag/chunks/p0401-p0500/p0414-c01.md) советует ограничить группы в production; [p0417](../../../rag/chunks/p0401-p0500/p0417-c01.md) объясняет, что токены действуют в пределах user permissions, и рекомендует адекватную дату истечения для периодического обновления.
- **Решение:** tutorial shortcut **не рекомендуем для production**. Scope, ограниченная роль, expiry, revocation/rotation и авторизация хостов должны быть проверены. Эти две авторские формулировки не являются полностью логическим противоречием, но требуют сохранения **разного контекста — lab и production**.

## 6. [Source security risk / extraction issue] Буквальные токены и пробелы в token в коде

- [p0419](../../../rag/chunks/p0401-p0500/p0419-c01.md) и [p0424](../../../rag/chunks/p0401-p0500/p0424-c01.md) включают длинное буквальное значение `api_token` внутри Python-строки рядом с демонстрационным HTTP endpoint; [p0429](../../../rag/chunks/p0401-p0500/p0429-c01.md) задаёт `token = " <hex> "` с **пробелами внутри кавычек** и `url` с завершающим `?`.
- **Решение:** literal credential **не повторяется** в артефактах/Git/логах, происхождение и статус ключа неизвестны. Пробелы могут стать частью значения, если строка взята буквально. Точный вызов Python и API auth semantics — `[Needs confirmation]`. В коде памятки только `<API_TOKEN_FROM_SECRET_STORE>`.

## 7. [Source wording ambiguity] Status Disabled vs maintenance period в toggle script

- **Вариант A:** [p0431](../../../rag/chunks/p0401-p0500/p0431-c01.md) ожидает `Monitoring → Hosts → Status = Disabled` сразу после `Disable → Execute`.
- **Вариант B:** далее в объяснении на **той же странице** сказано, что привилегированный скрипт `создает период обслуживания` (maintenance period) для host.
- **Следствие:** host.disabled и maintenance — **не одно и то же состояние**. Точный API-method, payload и side effects стороннего `enable_disable-host.py` в RAG не содержатся; невозможно подтвердить правильное действие без source code review. Не утверждать, что они автоматически равнозначны.

## 8. [Security boundary / Needs confirmation] Вызов от User с привилегиями другого пользователя

- [p0427](../../../rag/chunks/p0401-p0500/p0427-c01.md)–[p0431](../../../rag/chunks/p0401-p0500/p0431-c01.md) обосновывает map scripts возможностью пользователя `User` включать/выключать monitoring, поскольку скрипт работает **в elevated-контексте другого пользователя**.
- В [p0432](../../../rag/chunks/p0401-p0500/p0432-c01.md) показана замена target `{HOST.HOST}` на `{MANUALINPUT}`. Правило валидации и точные ограничения доступа показаны только рисунком 10.23 → `RAG_MISS`.
- **Следствие:** технически это граница делегированного повышения полномочий, риски unauthorized target / injection и impersonation должны быть оценены до любой публикации в UI. Полный контроль ролей, конкретный исполняющий user, audit trail и rollback отсутствуют — `[Needs confirmation]`.

## 9. [Destructive / Needs confirmation] Полная перезапись /etc/hosts

- [p0423](../../../rag/chunks/p0401-p0500/p0423-c01.md) прямо предупреждает, что **каждый вызов `host_pull_zabbix.py` переписывает `/etc/hosts`**, и разрешает пример лишь на «пустом» server без прежних модификаций.
- [p0426](../../../rag/chunks/p0401-p0500/p0426-c01.md) усиливает риск периодической cron-перезаписью **каждые 15 минут**.
- Нет исходникового полного `host_pull_zabbix.py`, атомарной записи, backup/restore, проверки конфликтов/дубликатов, прав на `/etc/hosts` и процедуры безопасного отключения cron. Для production **не запускать как есть**.
