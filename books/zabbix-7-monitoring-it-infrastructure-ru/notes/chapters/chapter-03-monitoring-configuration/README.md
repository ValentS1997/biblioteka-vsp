## Понимание методов сбора

**Главное решение — кто инициирует получение значения и как оно преобразуется.** Пассивный Agent 2 опрашивается сервером Zabbix/прокси; активный агент выполняет назначенные активные проверки и отправляет значения сам. Для активного режима важно совпадение `Hostname` агента и конфигурации узла в Zabbix. Оба вида проверок можно сочетать ([p0095](../../../rag/chunks/p0001-p0100/p0095-c01.md)–[p0101](../../../rag/chunks/p0101-p0200/p0101-c01.md)).

**SNMP** опрашивает OID на устройстве. Вместо многочисленных одиночных запросов новый рецепт `walk[]` собирает данные пакетно, а зависимые элементы извлекают нужный OID через preprocessing. Книга объясняет повышение эффективности и возможность уменьшить хранение повторов; точный выбор OID и индекс интерфейса зависит от устройства ([p0106](../../../rag/chunks/p0101-p0200/p0106-c01.md), [p0110](../../../rag/chunks/p0101-p0200/p0110-c01.md)–[p0115](../../../rag/chunks/p0101-p0200/p0115-c01.md)).

**Simple check** проверяет сетевую службу с точки зрения Zabbix server/прокси: блокировка порта брандмауэром может дать «недоступно», даже когда SSH работает локально ([p0116](../../../rag/chunks/p0101-p0200/p0116-c01.md), [p0122](../../../rag/chunks/p0101-p0200/p0122-c01.md)). **Trapper** работает в обратном направлении: `zabbix_sender` отправляет значение с host в заранее созданный элемент trapper ([p0120](../../../rag/chunks/p0101-p0200/p0120-c01.md)–[p0123](../../../rag/chunks/p0101-p0200/p0123-c01.md)).

**Calculated item** вычисляет агрегат из уже собранных значений; **dependent item** использует основной элемент как источник и обрабатывает его значение без собственного отдельного цикла получения; без preprocessing может повторять исходные данные ([p0124](../../../rag/chunks/p0101-p0200/p0124-c01.md)–[p0130](../../../rag/chunks/p0101-p0200/p0130-c01.md)).

**JMX/ODBC/HTTP/browser** — разные способы получить результат из Java, SQL, HTTP или настоящего браузерного взаимодействия. Их возможности нельзя смешивать: Java gateway необходим для JMX, ODBC требует драйвер/DSN и реальный DB-запрос, browser требует Selenium и script ([p0133](../../../rag/chunks/p0101-p0200/p0133-c01.md)–[p0135](../../../rag/chunks/p0101-p0200/p0135-c01.md), [p0136](../../../rag/chunks/p0101-p0200/p0136-c01.md)–[p0143](../../../rag/chunks/p0101-p0200/p0143-c01.md), [p0144](../../../rag/chunks/p0101-p0200/p0144-c01.md)–[p0153](../../../rag/chunks/p0101-p0200/p0153-c01.md)).

## Практический порядок и проверки

1. Подготовить установленный Zabbix Server, БД и учебные хосты; определить вид проверки, интерфейс и шаблон.
2. Создать хост и элементы через `Data collection → Hosts → Items`, при необходимости шаблон, группу/макросы, теги и параметры preprocessing.
3. Проверить `Monitoring → Hosts/Latest data` (значение и поддерживаемость элемента), прежде чем расширять мониторинг.
4. Для составных метрик — один мастер-элемент и зависимые элементы; выбирать `Do not keep history` для сырого потока **только если** дальнейшая история действительно не нужна ([p0113](../../../rag/chunks/p0101-p0200/p0113-c01.md), [p0130](../../../rag/chunks/p0101-p0200/p0130-c01.md)).
5. Перед опасными операциями на хосте отделять read-only диагностику от установки пакетов, исполнения внешнего кода, сетевых запросов, доступа к БД и использования секретов. Конкретные действия и ограничения: [commands.md](commands.md).
6. При несоответствии исходника и исполнимой команды использовать [source-findings.md](source-findings.md), не исправляя текст молча.

## Ограничения

- Учебные значения IP, паролей, имён интерфейсов и OID не переносятся в production буквально. `Secret text` скрывает значения в интерфейсе, но **по тексту главы** не обеспечивает шифрование макроса в базе данных ([p0105](../../../rag/chunks/p0101-p0200/p0105-c01.md)).
- Примеры `JMX authenticate=false/ssl=false`, `AllowKey=system.run[*]`, тестовые SNMP-пароли и Selenium-сервис — **не безопасные готовые конфигурации**; границы: [source-findings.md](source-findings.md).
- Browser JavaScript упоминается в тексте, но файл примера по внешнему URL не загружался. Полный воспроизводимый скрипт и часть полей из иллюстраций = `RAG_MISS`.
- В конце главы [p0160](../../../rag/chunks/p0101-p0200/p0160-c01.md) нет отдельного «Итог», контрольных вопросов и упражнений: условные `summary.md`, `review-questions.md`, `review-answers.md` не создаются.
- Полный rollback изменений ОС, прав на скрипты, SNMP, JMX и ODBC **не описан**, используется маркер `[Needs confirmation]`. Изменений статуса чтения нет.
