# Глава 4 — source findings (RAG-only)

**Диапазон:** PDF 161–196, принятый книжный RAG. Все варианты ниже сохранены **как утверждения источника**, без внешней проверки, исправления по памяти или молчаливого выбора удобного значения. `RAG_MISS` — отсутствие воспроизводимых данных в адресуемом текстовом RAG.

## 1. [Source contradiction] Триггер SSH: срабатывает при 1 или 0?

- **Вариант A:** текст объяснения утверждает, что результат простой проверки **`1 = UP` (порт доступен)** и **`0 = DOWN` (порт недоступен)**. Это дано в [p0167](../../../rag/chunks/p0101-p0200/p0167-c01.md).
- **Вариант B:** ниже утверждается, что для первого триггера **PROBLEM срабатывает, если последнее значение становится равным `1`**, а обычно получаемое значение должно быть `0` ([p0168](../../../rag/chunks/p0101-p0200/p0168-c01.md)). В [p0162](../../../rag/chunks/p0101-p0200/p0162-c01.md) задача первого триггера описана как сообщение о *недоступности* SSH.
- **Дополнение:** подпись к рис. 4.2 на p163 называет «сработавший триггер — порт 22 доступен», хотя инструкция блокирует SSH; возможен дополнительный дефект текста/подписи ([p0163](../../../rag/chunks/p0101-p0200/p0163-c01.md)).
- **Классификация и эффект:** логическая несовместимость в воспроизводимом учебном сценарии. **Не выдавать** ни `last(...)=1`, ни `last(...)=0` за правильное правило на основании одного текста. Точная формула выражения находится на рисунках 4.1/4.7 и не доступна как структурированные RAG-данные → `RAG_MISS`. Фактическое значение item, определение состояния и выражение триггера в целевой версии требуют `[Needs confirmation]`.

## 2. [Source code mismatch] Сетевой тест портит доступ, обратная операция не описана

- **Исходный пример:** [p0163](../../../rag/chunks/p0101-p0200/p0163-c01.md) предлагает `iptables -A INPUT -p tcp -i ens192 -s 10.16.16.152 --destination-port 22 -j DROP` для имитации SSH-down. Автор просит заменить интерфейс и IP на собственные.
- **Проблема:** добавляется блокирующее правило на входящие SSH-соединения; есть риск потерять доступ к контролируемому хосту. В пределах главы **нет проверенной обратной команды** для удаления правила и восстановления соединения.
- **Вывод:** переносить в production без отдельного плана восстановления нельзя; rollback `[Needs confirmation]`. Сам рецепт сохраняется для источникового анализа, не заменяется выдуманной последовательностью `iptables -D`.

## 3. [Source wording/code mismatch] Неоднозначность порядка вычитания в time-shift

- **Вариант A:** объяснение [p0180](../../../rag/chunks/p0101-p0200/p0180-c01.md) перечисляет первым значение прошлой недели, вторым — текущее, но фраза о математическом операторе говорит, что «мы вычтем результат первого выражения из результата второго» (означало бы `текущее - прошлое`).
- **Вариант B:** последующий текст и численные примеры [p0181](../../../rag/chunks/p0101-p0200/p0181-c01.md) недвусмысленно указывают **`(прошлая неделя − эта неделя)`**, `80 - 50 = 30 > 20` → TRUE и `80 - 70 = 10 > 20` → FALSE.
- **Вывод:** направления в словесной фразе и приведённой арифметике различаются. Не исправлять формулировку без источника; проверять фактическую формулу через конструктор `Test`, выражение на рисунке 4.22 не реконструируется.

## 4. [Needs confirmation] Формулы и SMTP-поля только на рисунках

- **Рисунки 4.1–4.4, 4.7–4.10, 4.14–4.22:** показывают конкретные функции, host/key и recovery expression; текст поясняет смысл `change`, `trendavg`, `timeleft`, shift, но не содержит полный независимый программный код для каждого условия. **Точное выражение** = `RAG_MISS`, а не синтаксис, дописанный по памяти.
- **Рисунки 4.26–4.35, 4.40–4.41:** дают конкретные UI-значения action, SMTP Office 365, user media и шаблона; они не выделены в RAG как мультимодальные элементы. Фактические адреса/credentials, URL, SMTP/Message fields = `RAG_MISS`.
- **Рисунки 4.44–4.46:** иллюстрируют изменение глобального severity; точные новые значения в UI на рисунке не извлечены. Текстом подтверждён лишь вариант организации, которой нужны названия вроде P1/P2 ([p0194](../../../rag/chunks/p0101-p0200/p0194-c01.md)–[p0196](../../../rag/chunks/p0101-p0200/p0196-c01.md)).

## 5. [Needs confirmation] Доставка и откат

Книга описывает логическую схему `PROBLEM → Action → Media Type → User Media` и `OK → Recovery operation` ([p0189](../../../rag/chunks/p0101-p0200/p0189-c01.md)–[p0190](../../../rag/chunks/p0101-p0200/p0190-c01.md)). Но **не содержит** полноценного проверяемого плана деградации SMTP, диагностики доставки и rollback серверной настройки почты. Не заявлять получение уведомлений гарантированным фактом от одной лишь конфигурации. Схема тестирования настоящего email и восстановление прежней конфигурации: `[Needs confirmation]`.
