## Основная модель: данные → событие → адресное уведомление

**Триггер** анализирует собранное значение по функции, объекту (host/template), item key, оператору и константе; состояние бывает **PROBLEM/OK**. При сложных выражениях могут использоваться `and`/`or` и отдельное **Recovery expression**: возврат в OK требует, чтобы условие проблемы стало FALSE, а восстановления — TRUE ([p0167](../../../rag/chunks/p0101-p0200/p0167-c01.md)–[p0173](../../../rag/chunks/p0101-p0200/p0173-c01.md)).

Для SSH используется простой check порта 22; для новой версии — `change` и дополнительное условие восстановления; для потерь пакетов — несколько items с `or` ([p0162](../../../rag/chunks/p0101-p0200/p0162-c01.md)–[p0171](../../../rag/chunks/p0101-p0200/p0171-c01.md)). **В исходнике имеется внутреннее противоречие о значениях 0/1, на которых срабатывает SSH-trigger**, поэтому не следует выполнять его как проверенную формулу. Оба варианта: [source-findings.md](source-findings.md).

**Продвинутые функции**: `trendavg` использует агрегированные часовые тренды (пример `1w:now-1w` и порог 800 Мбит/с); `timeleft` прогнозирует момент 100 % занятости диска по 7 часам истории и горизонту меньше недели; time shifting сравнивает текущую и прошлую неделю ([p0174](../../../rag/chunks/p0101-p0200/p0174-c01.md)–[p0181](../../../rag/chunks/p0101-p0200/p0181-c01.md)). Конкретные выражения из рисунков 4.14–4.22 помечены `RAG_MISS`.

**Уведомления — отдельный контур**. `Trigger action` определяет получателей и условия: `Operations` для PROBLEM, `Recovery operations` для OK, `Update operations` для изменения/подтверждения; `Media types → Email` задаёт SMTP/формат, а `Users → Users → Media` — конкретный адрес пользователя ([p0182](../../../rag/chunks/p0101-p0200/p0182-c01.md)–[p0190](../../../rag/chunks/p0101-p0200/p0190-c01.md)). Созданного триггера недостаточно для доставки email.

**Эффективность:** наименование и теги помогают понять *что*, *где* и *насколько важно*. Книга рассматривает теги `component` и `scope` (например `availability`, `performance`, `security`, `capacity`) и настройку шаблона сообщения. Шесть классов severity можно назвать иначе на уровне глобального отображения, например P1/P2, но это опциональный приём ([p0190](../../../rag/chunks/p0101-p0200/p0190-c01.md)–[p0196](../../../rag/chunks/p0101-p0200/p0196-c01.md)).

## Учебный операционный порядок

1. Проверить Zabbix server, MariaDB, frontend и поступающие значения от Linux-хоста с Agent 2/проверками главы 3 ([p0161](../../../rag/chunks/p0101-p0200/p0161-c01.md)–[p0162](../../../rag/chunks/p0101-p0200/p0162-c01.md)).
2. Создать **триггер на конкретном host** через `Data collection → Hosts → Triggers`; проверить expression, severity, теги, зависимости от item и частоту его обновления.
3. Для сложных условий использовать конструктор `Add → Select/Function`, не переносить отсутствующие в текстовом RAG выражения из неразмеченных рисунков.
4. Провести проверку логики и граничных значений, в том числе `Expression constructor → Test` (книга сравнивает 80 %/50 % и 80 %/70 %) ([p0180](../../../rag/chunks/p0101-p0200/p0180-c01.md)–[p0182](../../../rag/chunks/p0101-p0200/p0182-c01.md)).
5. Создать `Trigger action` с операциями PROBLEM/RECOVERY/UPDATE и определить получателей.
6. Настроить `Email` media type, message templates, затем запись `Media` пользователя; только после этого проверять доставку и информативность.
7. Привести naming, tags и message format к принятой структуре; изменение глобальных severity — отдельная, необязательная операция.

## Безопасность и пределы

- Для проверки SSH пример предлагает **добавление блокирующего правила iptables**. Это может нарушить административный доступ и должно рассматриваться как service-disrupting испытание, а **проверенная процедура возврата правила не приведена**; выполнять на рабочем сервере нельзя по неполной инструкции ([p0163](../../../rag/chunks/p0101-p0200/p0163-c01.md)).
- В RAG не показаны достоверные конкретные SMTP credentials, серверные настройки и гарантированный end-to-end тест доставки. Их значения `[Needs confirmation]`. Использовать placeholders, не учебные секреты.
- Не приравнивать срабатывание триггера к успешной отправке, а смену цвета/названия severity к изменению корпоративного процесса приоритизации.
- **Отдельного chapter-end summary, контрольных вопросов и упражнений нет**: [p0196](../../../rag/chunks/p0101-p0200/p0196-c01.md) заканчивается описанием отображения severity, [p0197](../../../rag/chunks/p0101-p0200/p0197-c01.md) начинает главу 5. Условные summary/review-файлы не создаются.
