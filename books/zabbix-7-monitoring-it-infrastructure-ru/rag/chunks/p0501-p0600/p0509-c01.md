Объяснение
В наши дни мониторинг Docker-контейнеров в Zabbix не требует больших усилий
благодаря появлению Zabbix Agent 2 и добавлению новых шаблонов по умолча
нию. Однако в некоторых случаях такой шаблон не подходит. Попробуем разо
браться почему.

Почти все элементы данных, которые мы можем увидеть на узле сети, являются
зависимыми элементами данных, большинство из которых зависят от основного
элемента данных — Docker: Get info. Это самый важный элемент данных в шабло
не Docker. Он вызывает ключ элемента данных docker.info, поддержка которого
встроена в новый Zabbix Agent 2. Этот элемент извлекает список со всевозможной
информацией о сервисе Docker, запущенного на узле сети. Далее мы используем
зависимые элементы данных и предварительную обработку, чтобы получить нуж
ные значения из этого основного элемента.

Кроме того, шаблон Docker by Zabbix agent 2 содержит два правила обнаружения
Zabbix: для Docker-образов и Docker-контейнеров. Если мы изучим правило обна
ружения Docker-контейнеров под названием Containers discovery, то поймем, что
произойдет. Zabbix будет использовать ключ элемента данных docker.containers.
discovery, чтобы найти каждый Docker-контейнер и поместить его в макрос {#NAME}
