                               Рис. 4.42. Схема триггера

Теперь мы сразу видим, какая служба на каком порту какого узла сети не работает.

Кроме того, мы добавили тег для неработающей службы, который теперь бу
дет отображаться в интерфейсе, предупреждая о том, что именно происходит
(рис. 4.43).

                             Рис. 4.43. Дополнительный тег

В Zabbix 6 была введена новая политика тегов. Поскольку мы создали элемент дан
ных с тегом component и просто добавили тег триггера с именем scope (категория),
то последовали этому новому стандарту. На предыдущем скриншоте сразу видно,
что у нас есть проблема, влияющая на доступность службы SSH по протоколу TCP.
Значение тега категории обычно содержит один из пяти вариантов: availability
(доступность), performance (производительность), notification (уведомления),
security (безопасность) и capacity (емкость).

Более подробная информация о новой политике тегов Zabbix, которая по-прежнему
используется в Zabbix 7, доступна по ссылке https://blog.zabbix.com/tags-in-zabbix-6-0-
lts-usage-subfilters-and-guidelines/19565/.

Еще одно действие, которое мы совершили, — удалили макрос {HOST.NAME}, если
использовали его раньше. Поскольку поле Host (Узел сети) уже содержит имя
узла сети, к которому принадлежит триггер, макрос нам не требуется. Нам нуж
но, чтобы имена триггеров были короткими и информативными, поэтому будем
использовать макросы имени узла сети на вкладке Media (Способы оповещений)
или просто выбирать поле, уже доступное в интерфейсе.
