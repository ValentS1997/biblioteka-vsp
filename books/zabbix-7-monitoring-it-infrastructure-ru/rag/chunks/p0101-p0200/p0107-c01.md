Настройка SNMP-мониторинга по-новому     107

Если мы опросим этот OID с помощью консольной утилиты SNMPwalk или нашего
сервера Zabbix, то получим в ответ несколько OID:

.1.3.6.1.4.1.2021.4.1.0 = INTEGER: 0
.1.3.6.1.4.1.2021.4.2.0 = STRING: swap
.1.3.6.1.4.1.2021.4.3.0 = INTEGER: 1679356 kB
.1.3.6.1.4.1.2021.4.4.0 = INTEGER: 1674464 kB
.1.3.6.1.4.1.2021.4.5.0 = INTEGER: 1872872 kB
.1.3.6.1.4.1.2021.4.6.0 = INTEGER: 184068 kB

Сюда входит и наш OID 1.3.6.1.4.1.2021.4.6.0 со значением, которое содержит
нашу свободную память. Таким образом, SNMP использует древовидную струк
туру.

Настройка SNMP-мониторинга по-новому
Начиная с версии Zabbix 6.4 SNMP-мониторинг был полностью переработан,
и в нем появился новый способ настройки SNMP-мониторинга. Старый способ
по-прежнему доступен и работает.

Новый способ использует массовые запросы, что сильно увеличивает его эф
фективность. Поэтому в текущем разделе мы рассмотрим, как настроить SNMP-
мониторинг новым способом.

Подготовка
Нам понадобятся два хоста Linux:
z наша серверная среда Zabbix;
z любой хост Linux, на котором запущен SNMP-сервер.

Порядок действий
Рассмотрим порядок создания массовых SNMP-запросов. Прежде всего подго
товьте свои хосты.

1. Сначала войдите в CLI вашего сервера Zabbix. Мы начнем с установки неко
  торых дополнительных инструментов, чтобы упростить настройку SNMP-
   мониторинга.

  Для RHEL:

   dnf install net-snmp-utils

  Для Ubuntu:

   apt install libsnmp-dev
