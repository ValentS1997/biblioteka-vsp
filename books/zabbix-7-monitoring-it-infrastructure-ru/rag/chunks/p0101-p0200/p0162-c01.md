162     Глава 4   •  Работа с триггерами и оповещениями

Настройка триггеров
Триггеры являются крайне важным компонентом любой системы мониторинга, по
тому что они уведомляют вас о том, что происходит с вашими данными. Мы хотим,
чтобы наш триггер сработал, когда наши данные достигают определенного порога
или когда мы получаем определенное значение.

Итак, приступим к настройке нескольких интересных триггеров. Существует мно
жество различных вариантов создания триггеров, но после прочтения этого раздела
вы сможете настроить несколько из наиболее важных.

Подготовка
Для этого примера понадобятся сервер Zabbix и хост Linux. Можно использовать
хост lar-book-agent_simple из предыдущей главы, поскольку он уже содержит
некоторые готовые элементы данных.

Кроме того, нам понадобится еще один узел сети, на котором должен быть установ
лен Zabbix agent 2 и подключен штатный шаблон Zabbix agent. Для этого можно
использовать хост lar-book-agent_passive из предыдущей главы.

Там уже есть несколько готовых триггеров, но мы расширим их функционал для
лучшего информирования.

Порядок действий
Далее мы создадим три триггера, которые будут отслеживать изменения состоя
ния.

Триггер 1. Мониторинг службы SSH
Приступим к созданию простого триггера на узле сети lar-book-agent_simple.
Ранее мы создали простую проверку на этом узле сети под названием Check if
port 22 is available, но еще не создали ничего, что могло бы уведомлять нас о ее
состоянии.

1. Для начала выберите раздел Data collectionHosts (Сбор данныхУзлы сети),
   затем щелкните на узле сети и перейдите в раздел Triggers (Триггеры). Именно
   здесь вы найдете уже существующие триггеры и сможете создавать новые.
2. Создайте новый триггер, нажав синюю кнопку Create trigger (Создать триггер)
   в правом верхнем углу. Укажите следующие параметры, как на рис. 4.1.
3. Нажмите кнопку Add (Добавить) и завершите создание триггера. В результате
   будет создан триггер, который будет срабатывать, когда порт Secure Shell (SSH)
   станет недоступным для подключения.
