Настройка партиционирования в MySQL      469

11. Скопируйте и вставьте подготовленный MySQL-запрос из шага 9 и нажмите
     Enter. Процесс может занять некоторое время, так как таблица может быть до
    вольно большой. По окончании вы увидите следующее (рис. 12.3).

            Рис. 12.3. Подтверждение успешного партиционирования таблиц history

12. Выполните такое же разделение для остальных таблиц history; убедитесь, что
    для самой ранней партиции используется правильная временная метка UNIX:
      history_uint;
      history_str;
      history_text;
      history_log;
      history_bin.
13. Итак, все таблицы history разделены. Теперь разделим таблицы trends.
   Их две — trends и trends_uint.
14. Cнова проверяем временные метки с помощью следующих запросов:

    SELECT FROM_UNIXTIME(MIN(clock)) FROM trends;
    SELECT FROM_UNIXTIME(MIN(clock)) FROM trends_uint;

15. Для этих таблиц важно обратить внимание на самый ранний месяц. В нашем
    случае это шестой месяц 2023 года.
16. Теперь подготовимся и выполним партиционирование этой таблицы. Создадим
    две дополнительные партиции, начиная с самой ранней даты, указанной в метке
    времени на шаге 14:

    ALTER TABLE trends PARTITION BY RANGE ( clock)
    (PARTITION p2023_06 VALUES LESS THAN (UNIX_TIMESTAMP("2023-07-01
    00:00:00")) ENGINE = InnoDB,
    PARTITION p2023_07 VALUES LESS THAN (UNIX_TIMESTAMP("2023-08-01
    00:00:00")) ENGINE = InnoDB,
    PARTITION p2023_08 VALUES LESS THAN (UNIX_TIMESTAMP("2023-09-01
    00:00:00")) ENGINE = InnoDB);

17. И снова мы создаем партиции, начиная с самой ранней временной метки UNIX
   и заканчивая текущим месяцем. Но можно создать и несколько новых партиций
    для будущих данных (рис. 12.4).
