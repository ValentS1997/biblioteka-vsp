Создание триггеров на уровне шаблона     207

Объяснение
Когда мы создаем элементы данных в нашем шаблоне, эти элементы автоматически
создаются на узлах сети, к которым подключен шаблон. Это позволяет назначить
шаблон нескольким узлам сети; таким образом, нам нужно настроить элемент дан
ных на уровне шаблона только один раз, вместо того чтобы создавать его вручную
на каждом отдельном узле сети. Например, наш вновь созданный узел сети будет
показывать следующие последние данные (рис. 5.14).

          Рис. 5.14. Раздел MonitoringLatest data (МониторингПоследние данные)

Каждый узел сети будет хранить свое значение элемента данных.

  ПРИМЕЧАНИЕ
   При создании элемента данных SNMP имейте в виду следующее. SNMP OID в поле
   элемента данных всегда содержит числовое представление идентификатора объ
   екта. Это делается для того, чтобы гарантировать, что вам для работы шаблонов
   не нужны файлы MIB.

Кроме того, ключ элемента данных будет основан на символическом представле
нии OID. В нашем случае символическим представлением идентификатора был
sysName, который мы превратили в ключ элемента данных sysName. Это общие пра
вила, которых следует придерживаться при создании шаблонов, чтобы убедиться,
что они структурированы одинаковым образом для всех.

Читайте также
Узнать больше о Zabbix и SNMP OID/MIB можно в этой статье: https://blog.zabbix.
com/zabbix-snmp-what-you-need-to-know-and-how-to-configure-it/10345/#snmp-oid.

Создание триггеров на уровне шаблона
Создание триггеров на уровне шаблона происходит примерно так же, как и соз
дание элементов данных шаблона или обычных триггеров. Рассмотрим процесс,
чтобы понять, как это делается.
