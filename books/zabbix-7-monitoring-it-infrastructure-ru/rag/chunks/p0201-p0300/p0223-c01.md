Использование низкоуровневого обнаружения в шаблонах      223

LLD-макрос {#SNMPINDEX}. SNMPINDEX — последнее число из нашего SNMP-опроса.
В этом случае мы увидим следующее:

.1.3.6.1.2.1.2.2.1.8.1 = INTEGER: up(1)
.1.3.6.1.2.1.2.2.1.8.2 = INTEGER: up(1)

Первой записью, полученной при опросе OID .1.3.6.1.2.1.2.2.1.2 с под
ставленным значением SNMPINDEX, равным .1 (то есть итоговый OID был
.1.3.6.1.2.1.2.2.1.2.1), было значение lo.

Теперь Zabbix LLD создаст элемент данных Interface lo: Operational status,
который будет опрашивать SNMP OID:

.1.3.6.1.2.1.2.2.1.8.1 = INTEGER: up(1)

Кроме того, будет создан элемент Interface ens192: Operational status, который
будет опрашивать SNMP OID:

.1.3.6.1.2.1.2.2.1.8.2 = INTEGER: up(1)

Созданные элементы будут выглядеть так, как показано на рис. 5.40.

                           Рис. 5.40. Экран последних данных

Помимо создания этих элементов низкоуровневого обнаружения, мы создали
прототип LLD-триггера. Он работает так же, как и прототипы элементов данных.
Если мы проверим триггеры нашего узла сети, то увидим два созданных триггера
(рис. 5.41).
