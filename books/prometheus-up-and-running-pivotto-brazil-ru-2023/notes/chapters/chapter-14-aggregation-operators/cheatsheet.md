# Cheatsheet — глава 14: операторы агрегирования

**Источник:** PDF 246–257, `p0246:c01`–`p0257:c01`. Только `rag_only`. Запросы не выполнялись.

## Симптомы и постановка задачи

- В панели тысячи серий: заменить индивидуальные ряды вычислением групп с `without` или `by` (PDF 246–248).
- Потерялся `env`/`cluster` в алерте: `by` сохраняет **только** перечисленные метки; `without` удаляет только явно названные (PDF 247–249).
- Сумма Counter не отражает актуальную скорость: сначала `rate(...[5m])`, потом `sum` (PDF 250).
- Сумма несуществующих данных выглядит как отсутствие значения, а не 0: `sum(non_existent_metric)` → пустой instant vector (PDF 249).
- Дашборд `topk` с историей слишком широк: набор top-N может меняться на каждом шаге (PDF 254).
- Среднее по заранее вычисленным средним даёт NaN/ошибочную статистику: агрегировать числители и знаменатели, как рассмотрено в главе 13 (PDF 251–252).

## Baseline

| Оператор | Что возвращает по книге | PDF |
| --- | --- | --- |
| `sum` | Сумму чисел группы | 249–250 |
| `count` | Количество series, независимо от их значений | 250–251 |
| `avg` | Арифметическое среднее | 251 |
| `group` | `1` для каждой группы | 252 |
| `stddev`, `stdvar` | Стандартное отклонение (генеральной совокупности), дисперсию | 252–253 |
| `min`, `max` | Минимальное/максимальное значение | 253 |
| `topk`, `bottomk` | До k **исходных series** в группе со всеми исходными labels | 254 |
| `quantile` | Квантиль значений в instant vector group | 254–255 |
| `count_values` | Частоты точных значений с добавленной меткой | 255–257 |

## Read-only проверки

1. Сравнить `sum without(fstype,mountpoint)(node_filesystem_size_bytes)` с `sum by(job,instance,device)(node_filesystem_size_bytes)` для показанного состава labels; при иных target labels результаты могут различаться (PDF 247–248).
2. Убедиться, что `sum without()(node_filesystem_size_bytes)` сохраняет число series, но убирает метрику `__name__`; `sum by()(node_filesystem_size_bytes)` создаёт одну группу (PDF 248–249).
3. Проверить `sum(non_existent_metric)` → пустой instant vector, не `{ } 0` (PDF 249).
4. Сравнить `count without(device)(node_disk_read_bytes_total)` (число устройств) с `sum without(device)(rate(node_disk_read_bytes_total[5m]))` (суммарная скорость) (PDF 250).
5. Для CPU число логических процессоров можно получать `count without(cpu)(count without(mode)(node_cpu_seconds_total))` — внутренний `count` считает режимы на CPU, внешний CPU (PDF 250–251).
6. Средняя доля режимов CPU: `avg without(cpu)(rate(node_cpu_seconds_total[5m]))` (PDF 251). `quantile without(cpu)(0.9,rate(node_cpu_seconds_total{mode="system"}[5m]))` — квантиль по CPU в момент расчёта, не по времени (PDF 254–255).
7. Частоты версий: `count_values without(instance)("version",software_version)`; число уникальных версий: внешнее `count without(version)` от результата (PDF 256).
8. Для выявления экземпляров-выбросов в книге приведено `avg + 2 * stddev` с `ignoring(instance) group_left()`; синтаксис сопоставления векторов раскрывается лишь в главе 15 (PDF 252–253).

## Интерпретация

- В PromQL нет различия между target/instrumentation labels при группировке. `__name__` обычно исчезает при агрегировании, но `by(__name__)` специально сохраняет его (PDF 247–249).
- `avg` считает арифметическое среднее, а не взвешенное; разные доли CPU/средние задержки требуют осторожности (PDF 251–252).
- `stddev` в примере — отклонение популяции. Авторские приблизительные доли 68/95 % относятся к нормальному распределению, не любой метрике (PDF 252).
- `min`/`max` возвращают сгруппированные labels; для возврата **исходных меток** использовать `topk`/`bottomk` (PDF 253–254).
- `quantile`, `quantile_over_time`, `histogram_quantile` работают на разных видах векторов/агрегации (PDF 255).
- `count_values` полезен для дискретных значений. Если много уникальных дробных значений, результирующая кардинальность может вырасти (PDF 255–256).
