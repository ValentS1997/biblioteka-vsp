# Source findings — глава 14

**Источник:** канонический RAG `p0246:c01`–`p0257:c01`, PDF 246–257. **source SHA256:** `ab45c7bc9a393b15bc60628dfceaa45db71388fd28e75c5c55ab6eaf5930f787`; строгий `rag_only`. Противоречия и неясности исходного текста сохраняются без «молчаливой» правки.

## F-01 — [Source contradiction]: 12 или 11 операторов?

- **RAG `p0246:c01`:** «В PromQL есть **12** функций агрегирования, поддерживающих два необязательных модификатора».
- **RAG `p0249:c01`:** «Все **11** операторов агрегирования используют одинаковую логику группировки».
- **RAG `p0249:c01`–`p0256:c01`:** разделы именуют `sum`, `count`, `avg`, `group`, `stddev`, `stdvar`, `min`, `max`, `topk`, `bottomk`, `quantile`, `count_values`, то есть **12** отдельных имён.
- **Результат:** несоответствие двух чисел в описании; перечень разделов сохраняется, число в PDF 249 не правится. Реальная поддержка в пользовательской версии Prometheus [Needs confirmation].

## F-02 — [Source interpretation mismatch]: направление неравенства при quantile 0.9

- **RAG `p0254:c01`:** `quantile without(cpu)(0.9, rate(node_cpu_seconds_total{mode="system"}[5m]))`.
- **RAG `p0255:c01`:** результат `0.024558620689654007`, затем «90 % наших процессоров проводят в режиме system **не менее 0.02 с** за секунду».
- **Проблема:** выражение вычисляет 90-й процентиль распределения по CPU, но объяснение использует направление «не менее» применительно к 90 %; оно не следует непосредственно из указанной операции. Строгое распределение фактических значений/интерполяция здесь не показаны.
- **Действие:** не объявлять фразу проверенным определением квантиля; буквальное выражение сохраняется. При проверке на исходных данных определить число CPU ниже/выше порога: [Needs confirmation].

## F-03 — [Source mathematical issue]: сноска про NaN

- **RAG `p0251:c01`–`p0252:c01`:** `avg` при входном `NaN` тоже может вернуть `NaN`; источник предупреждает об опасности усреднения предварительно вычисленных средних при нулевых знаменателях.
- **RAG `p0252:c01`, сноска:** «Это как **1/0 = NaN**».
- **Проблема:** сноска недостаточна для корректного описания семантики деления с плавающей точкой; смешиваются разные ситуации деления на ноль. Не использовать эту фразу как техническое правило для PromQL без отдельной верификации. 
- **Действие:** сохранить цитату с риском, не подменять альтернативным расчётом.

## F-04 — [Needs confirmation]: статистические предположения про stddev

- **RAG `p0252:c01`:** доли 68 % и 95 % «для нормально распределённых данных», затем упомянуто неравенство Чебышёва для ненормальных; `stddev` вычисляет отклонение генеральной совокупности.
- **RAG `p0253:c01`:** пример `some_gauge > ignoring(instance) group_left() (avg without(instance)(some_gauge) + 2 * stddev without(instance)(some_gauge))`; при очень узком распределении в тексте предложен дополнительный порог +20 %, но нет полной PromQL-формулы.
- **Ограничение:** ни нормальность реальных данных, ни влияние NaN, ни достоверность выбранного порога здесь не верифицируются. Выражение записано как в RAG, не дополнено скрытым фильтром.

## F-05 — [Needs confirmation]: стоимость запросов и история topk

- **RAG `p0248:c01`:** `sort_desc(count by(__name__)({__name__=~".+"}))` потенциально дорого, затрагивает все активные series.
- **RAG `p0254:c01`:** при `query_range` и `topk(5,some_gauge)` на тысяче шагов может вернуться до 5000 разных рядов; автор рекомендует `@`.
- **Ограничение:** конкретные границы ресурсоёмкости, допустимый timeout и правило подзапросов среды не приводятся. Не переносить пример на production без дополнительных ограничений.

## F-06 — [Source description ambiguity]: quantile vs histogram

- **RAG `p0255:c01`:** подчёркнуто различие `quantile`, `quantile_over_time`, `histogram_quantile`.
- **Следствие:** эти имена нельзя считать взаимозаменяемыми. Численные значения квантилей в примерах учебного стенда не проверены через реальную TSDB и не должны использоваться как acceptance значения.
