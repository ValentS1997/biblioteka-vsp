## Главные положения

1. **Скаляр и instant vector — разные типы.** `0` — скаляр, `{} 0` — instant vector из одного образца без меток. Арифметика с scalar применяется к каждому образцу instant vector и удаляет имя метрики; `5 % 1.5` по примеру даёт `0.5` (PDF 258–260).
2. **Сравнение по умолчанию — фильтр.** `process_open_fds > 10` оставляет значения, прошедшие условие, в исходном масштабе; `> bool 10` сохраняет сопоставленные образцы и превращает их в 1 или 0 с удалением `__name__`. Поэтому `sum without(instance)(process_open_fds > bool 10)` возвращает и 0 для `node` в учебном примере (PDF 260–262). Сравнение двух скаляров без `bool` не допускается (PDF 261–262).
3. **Арифметика двух векторов требует сопоставления по меткам**, исключая `__name__`. Если соответствующая правая серия отсутствует, левая не включается в результат. `ignoring(mode)` исключает метку из ключа, `on(instance,job)` перечисляет только участвующие метки (PDF 263–264).
4. **Многие к одному нужно разрешать явно.** `group_left` допускает несколько образцов слева, соответствующих одному справа; без модификатора движок сообщает `multiple matches for labels`. `group_left(version)` дополнительно копирует названную метку из правой информационной метрики, но уникальность правой стороны обязательна (PDF 265–268).
5. **Логические операторы используют присутствие рядов.** `or` берёт левый ряд, иначе правый; `unless` исключает левый ряд, если справа найден соответствующий; `and` оставляет левый ряд при наличии правого. Эти операторы допускают many-to-many, не исполняя арифметических действий (PDF 268–271). В пояснении `unless` на PDF 270 обнаружено противоречие, см. [source-findings.md](source-findings.md).
6. **Отсутствие дочернего ряда нельзя безусловно превращать в 0.** При `node_custom_metric or up*0` метрика `up` существует даже для неудачного scrape и для посторонних jobs; в книге показана более узкая версия `node_custom_metric or (up{job="node"} == 1) * 0` (PDF 269–270).
7. **Приоритет задаёт смысл формулы.** Самый высокий у `^`, затем `* / % atan2`, затем `+ -`, сравнения, `unless and`, `or`. Все, кроме `^`, левоассоциативны; `^` — правоассоциативен (PDF 272).

## Особые случаи и риски

- `up * on(instance) group_left(version) prometheus_build_info` полезно для добавления `version`, но `on(instance)` не гарантирует уникального соответствия в каждом окружении; сам источник предлагает добавить `job` при необходимости (PDF 266–267).
- `node_hwmon_temp_celsius * ignoring(label) group_left(label) node_hwmon_sensor_label` не вернёт `sensor="temp1"` без дополнения через `or` (PDF 267–269). `x*0+1` не заменяет `NaN` на 1, как уточнено в сноске (PDF 269).
- Выражения сравнения удобны для алертов, но `count` от фильтра возвращает только прошедшие серии, не нулевые группы. Для долей используется `avg` от `bool`-вектора (PDF 261–262).
- В примерах смешаны `http_request_duration_seconds_*` (PDF 271, первый запрос) и `http_request_duration_microseconds_*` (второй). Контекст исходника различен; подтверждать наличие таких семейств на конкретном сервере отдельно.
- `hour()` в PDF 271 возвращает UTC-час, не локальный; использование в алертах требует отдельной проверки временной зоны.
