## F-01 — [Source wording/code mismatch]: используемое vs доступное место

- **RAG `p0134:c01`, текст:** `node_filesystem_avail_bytes` описан как пространство, доступное пользователям, в противоположность `node_filesystem_free_bytes`.
- **Там же, следующий переход:** для «используемого дискового пространства» приводится выражение:
  ```promql
  node_filesystem_avail_bytes
  /
  node_filesystem_size_bytes
  ```
- **Внутренний конфликт:** выражение рассчитывает **отношение доступного к общему пространству**, а не «используемого», если опираться на определения самого источника.
- **Решение:** сохранить обе исходные формулировки. В `commands.md` указан смысл компонентов и предупреждение; формула `used` не реконструируется по памяти. Причина исходного расхождения — [Needs confirmation].

## F-02 — [Needs confirmation]: имя `MemAvailable` в прозе без единиц

- **RAG `p0136:c01`:** все метрики памяти представлены с префиксом `node_memory_`; примеры включают `node_memory_MemTotal_bytes`, `node_memory_MemFree_bytes`, `node_memory_Cached_bytes`, `node_memory_Buffers_bytes`.
- **Там же:** текст называет `node_memory_MemAvailable` без суффикса `_bytes`, при этом описывает его как эвристику доступной памяти, появившуюся в Linux 3.14.
- **Ограничение:** собственный пример экспорта для `MemAvailable` в этом диапазоне не приведён, поэтому строку без `_bytes` нельзя выдавать за проверенный работающий селектор. Не менять исходное имя и не добавлять суффикс в цитату.

## F-03 — [Source extraction issue]: разрыв задания cron при переносе строк

- **RAG `p0142:c01`, пример 7.3:** после строки `*/5 * * * * root (echo -n 'shadow_entries '; grep -c . /etc/shadow)` отдельно стоят `> $TEXTFILE/shadow.prom.$$` и `&& mv $TEXTFILE/shadow.prom.$$ $TEXTFILE/shadow.prom`.
- **Текст книги прямо указывает:** «Весь следующий код должен быть набран в одну строку».
- **Ограничение:** блок RAG нельзя копировать в `/etc/crontab` дословно. Для контроля provenance `commands.md` сохраняет структуру переноса, не выдаёт её за запускаемую команду.
- **Дополнительный риск:** для чтения `/etc/shadow` использован root. Факт подсчёта строк не разрешает автоматизировать privileged доступ в пользовательском окружении.

## F-04 — [Needs confirmation]: зависимость от ядра, платформы, сборки

- **RAG `p0132:c01`:** авторы приводят метрики Node Exporter 1.4.0 с Linux 5.18.0; ОС Unix и различия коллекторов с FreeBSD упомянуты отдельно.
- **RAG `p0139:c01`:** PSI впервые обсуждается как функция Linux 4.20, которую может потребоваться собрать/включить; в примере — `psi=1`.
- **Ограничение:** современная доступность флагов, метрик, PSI и способов деплоя в машине пользователя не подтверждена RAG; нет права заменять книгу современным мануалом.

## F-05 — [Needs confirmation]: сохранность и доступность textfile данных

- **RAG `p0141:c01`–`p0143:c01`:** каталог textfile, расширение `.prom`, ограничение отсутствия timestamps, атомарность переименования в одной файловой системе, метрика `node_textfile_mtime_seconds`.
- **Ограничение:** нет полного регламента прав, владельцев каталогов, безопасного хранения файлов и rollback для root cron. В production эти параметры должны быть отдельно проверены.
