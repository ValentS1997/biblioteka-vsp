## Главный принцип

**PromQL анализирует выборку временных рядов, а смысл результата зависит от типа исходной метрики, сохранённых меток и временного окна.** Для счётчиков сначала используется `rate`, затем агрегирование. Для Summary/Histogram агрегировать надо исходные суммы/счётчики или bucket-потоки **до** расчёта среднего/квантиля (PDF 229–233).

### Методические выводы

1. `sum without(device, fstype, mountpoint)(...)` агрегирует файловые системы по оставшимся меткам, например `job`, `instance`; операции преобразования могут удалить имя метрики. `avg without(instance, job)(process_open_fds)` показывает обобщение по заданиям (PDF 227–229).
2. `rate(node_network_receive_bytes_total[5m])` получает байты/с, а `sum without(device)(rate(...))` суммирует скорости интерфейсов. Дробные величины объясняются несовпадением scrape с границами окна (PDF 229).
3. Средняя величина события за период вычисляется отношением **агрегированных** `rate(_sum)` и `rate(_count)`; усреднение средних некорректно, как и агрегирование квантилей Summary (PDF 230–231).
4. `histogram_quantile` работает с `rate(_bucket)`, а для общего квантиля buckets предварительно агрегируются. Окно 1d в примере уплотнения TSDB выбрано из-за редких событий и может быть дорогостоящим; экстремальные квантили при малом числе событий неустойчивы (PDF 231–233).
5. Селекторы instant возвращают до одного актуального образца на series; range `[1m]` — множество образцов с исходными timestamps. Prometheus 2.x использует маркеры устаревания в instant-selectors (исключение для данных с пользовательским timestamp); в range эти маркеры не выдаются (PDF 233–237).
6. `offset 1h` сдвигает отдельный selector, `@` фиксирует время selector по Unix timestamp или `start()`/`end()`; `[30m:1m]` — подзапрос за 30 минут с минутным шагом (PDF 238–240).
7. HTTP `/api/v1/query` возвращает `vector`, `matrix` или `scalar`; `query_range` выполняет серию мгновенных вычислений от `start` до `end` с `step`. Интервал для `rate` должен превышать шаг; лимит **11 000 шагов** указан для версии книги (PDF 240–245).

## Ограничения и проблемы источника

- **PDF 228:** запрос `node_filesystem_size_bytes`, но входные ряды `node_filesystem_free_bytes`, а приведённый результат `32511390720` соответствует сумме перечисленных `free_bytes`, но не подтверждает результат запроса `size_bytes`; расхождение нельзя устранять молча.
- **PDF 232–233:** `prometheus_tsdb_compaction_duration_seconds_bucket` в одном запросе, но в примере агрегированного квантиля используется `prometheus_tsdb_compaction_duration_bucket`, а аналогичные `_sum`/`_count` также отличаются базовым именем.
- **PDF 235:** текст определяет имя метрики как `__name__`, но эквивалент записывает `{name="process_resident_memory_bytes",job="node"}`; оба варианта сохранены в [source-findings.md](source-findings.md).
- **PDF 240:** в описании модификатора `@` фраза «интервал, начинающийся в тот же момент» не согласована с пояснением `[1m]` как окна до времени запроса на PDF 236.
- **PDF 242:** запрос `prometheus_tsdb_head_samples_appended_total[1m]`, JSON-результат показывает `process_resident_memory_bytes`; примеры не согласованы.
- **PDF 244:** JSON `query_range` содержит лишнюю запятую после последнего `[1514765700, "146.8"]` — не копировать как строго валидный JSON. Статусы, часы и числа в примерах исторические.
- Другие подробности и точные locators: [source-findings.md](source-findings.md). Скриншот рис. 13.1 есть в RAG лишь как подпись; SVG здесь вновь построенные схемы, не копии рисунка.
