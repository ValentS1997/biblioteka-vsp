# Source findings — глава 18 «Оповещение»

**Provenance:** RAG `p0307:c01`–`p0320:c01`, PDF 307–320, SHA256 `ab45c7bc9a393b15bc60628dfceaa45db71388fd28e75c5c55ab6eaf5930f787`. Strict `rag_only`; причины расхождений без прямой проверки оригинала не установлены. Не производить silent corrections.

## F-01 — [Source wording mismatch]: `ALERTS_FOR_STATE` vs `ALERT_FOR_STATE`

- **RAG `p0309:c01`, первый абзац:** alerting rules заполняют **`ALERTS` и `ALERTS_FOR_STATE`**.
- **Там же позже:** «Значение `ALERT_FOR_STATE` — это отметка времени начала оповещение».
- **Проблема:** в одном разделе два разных написания имени метрики; подтверждено только одно первичное перечисление. Это нельзя представлять как два доказанно разных API.
- **Действие:** в артефактах используем `ALERTS_FOR_STATE` по первому перечислению; расхождение явно указано здесь. Причина (типографика/извлечение) [Needs confirmation].

## F-02 — [Source semantics caution]: разные пороги, обе severity могут сработать

- **RAG `p0313:c01`:** два правила `alert: FDsNearLimit` с `0.95` `severity: page` и `0.8` `severity: ticket`.
- **Источник предупреждает:** при использовании >95 % оба alert могут быть активны, но грубая попытка сделать их строго взаимоисключающими создаст дребезг и помешает выполнению `for`.
- **Ограничение:** это осознанный design tradeoff из источника, а не ошибка дублирования. Конкретная политика dedup/receiver Alertmanager [Needs confirmation].

## F-03 — [Source semantics limitation]: `for` зависит от непрерывности series

- **RAG `p0310:c01`–`p0312:c01`:** `for` требует сохранения одного и того же ряда; один пропущенный scrape датчика может сбросить состояние. Source example `max_over_time(process_open_fds[5m]) > max_over_time(process_max_fds[5m])*0.9` учитывает недавние данные.
- **Ограничение:** это не означает, что `max_over_time` восстанавливает отсутствовавшие samples или одинаково подходит для любой метрики. `up` рассматривается как специальная метрика: сохраняется даже при failed scrape, когда target присутствует.
- **Действие:** не обобщать на полностью исчезнувший target; проверять отдельно.

## F-04 — [Source extraction / transcription risk]: marker `❶` в YAML

- **RAG `p0318:c01`:** первая строка `alerting.alertmanagers[*].static_configs` показана с пометой `❶` непосредственно после `- static_configs:`.
- **RAG `p0319:c01`:** сноска поясняет раздел обнаружения Alertmanager.
- **Проблема:** символ `❶` — издательский маркер, а не YAML Prometheus; буквальное копирование приведёт к некорректной конфигурации.
- **Действие:** в `commands.md` он удалён из executable-format учебного блока, но исключение явно зарегистрировано. Это **не** исправление исходного PDF/RAG.

## F-05 — [Source scope]: external labels и момент применения

- **RAG `p0319:c01`–`p0320:c01`:** `global.external_labels` применяется после вычисления rules, до `alert_relabel_configs`; не используется HTTP API; в Prometheus annotation templates недоступен; в Alertmanager notification templates доступен.
- **Там же:** внешние labels — только default: если серия уже имеет то же имя label, исходное значение остаётся.
- **Следствие:** нельзя обещать, что `$labels.region` в alert annotation появится только из `external_labels`; не следует использовать `external_labels` для меняющегося внутри Prometheus значения. Это ограничение времени применения, не логическая ошибка.

## F-06 — [Source performance caution]: templates выполняют дополнительные запросы

- **RAG `p0315:c01`–`p0316:c01`:** Go template `query` и `range` может выполняться для каждого alert; при сотнях alerts дополнительная нагрузка становится существенной.
- **Ограничение:** точное число выполняемых запросов, ограничения PromQL и границы безопасности текущего сервера в источнике не даны. Оценивать при внедрении [Needs confirmation].

## F-07 — [Source author guidance, not measured requirements]: for и шум

- **RAG `p0310:c01`–`p0311:c01`:** авторы обычно предлагают `for >= 5m`, небольшую палитру `5m/10m/30m/1h`, при этом короткие реакционные интервалы могут требовать автоматизации.
- **RAG `p0317:c01`–`p0318:c01`:** авторам предпочтительнее alerts по симптомам, с владельцем и необходимостью вмешательства; идеал «не более двух инцидентов в день».
- **Ограничение:** не универсальные SLO, KPI или безопасные пороги для неизвестной среды. Не выдавать за технически проверенные константы.
