## Главные принципы

1. **Инструментировать код там, где возникает событие.** Определение метрик и экспорт по `/metrics` разделены; счётчики и датчики доступны через реестр Python-клиента (PDF 54–57).
2. **Выбирать метрику по семантике:** Counter для накопления; Gauge для состояния; Summary для суммы и количества; Histogram для распределения задержек с корзинами (PDF 56–67).
3. **Экспортировать исходные события, вычислять отношения в PromQL.** Например, из `_sum` и `_count` можно рассчитать среднюю задержку. Отдельные квантили математически агрегировать нельзя (PDF 59, 63–68).
4. **Инструментировать полезные сигналы:** RED для онлайн-обслуживания, USE для конвейеров и очередей, время последнего успеха для пакетных заданий; учитывать стоимость серий и сегментов (PDF 70–72).
5. **Именовать стабильно:** snake_case, суффикс `_total` у Counters, единицы `_seconds` и `_bytes`, библиотечный префикс, метки — отдельно от имени; переименование ломает запросы и дашборды (PDF 62, 73–75).
