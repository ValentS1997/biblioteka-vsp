# Cheatsheet — глава 3: инструментирование приложений

**Provenance:** PDF 54–75, RAG `p0054:c01`–`p0075:c01`. Демонстрационная среда Python 3, библиотека `prometheus_client` (PDF 54).

## Symptom / problem framing

- Неясна частота запросов/ошибок: добавить счётчики исходных событий, оценить `rate` (PDF 56–60).
- Требуется текущее число задач/потоков/очередь: использовать Gauge, а не Counter (PDF 60–62).
- Средняя задержка скрывает хвост распределения: использовать Histogram и сегменты; помнить, что квантили приближённые (PDF 63–68).
- Слишком много серий: проверить кардинальность меток и количество buckets; глава предупреждает об издержках и об опасности профилирования через каждую функцию (PDF 66–67, 72).
- Нестабильные имена метрик ломают дашборды/запросы (PDF 73–75).

## Baseline / context

- HTTP-обработчик «Hello World» доступен на `localhost:8001`, метрики — через `start_http_server(8000)`; сервер Prometheus собирает `localhost:8000` каждые 10 s (PDF 54–55).
- В Python метрики добавляются в реестр по умолчанию; имена уникальны. В других клиентах способ регистрации может отличаться (PDF 57).
- Counter увеличивается неотрицательными величинами и подходит для частот событий. Gauge может увеличиваться, уменьшаться или быть установленным в абсолютное значение (PDF 56–62).
- Summary даёт `_count` и `_sum`; Histogram — `_bucket` с меткой `le`, а также `_sum`, `_count` (PDF 63–68).
- Пример `rate(...[1m])` — окно одной минуты, а не универсальная эксплуатационная рекомендация.

## Read-only checks

1. Открыть `http://localhost:8000/` для метрик приложения; `http://localhost:9090/` для браузера выражений после настройки scrape (PDF 55).
2. Запрос `python_info` подтверждает наличие экспортируемой библиотекой платформенной метрики (PDF 55–56).
3. `rate(hello_worlds_total[1m])`: скорость обслуженных запросов по добавленному Counter (PDF 57).
4. `rate(hello_world_exceptions_total[1m])`: скорость исключений (PDF 59).
5. `hello_world_last_time_seconds` и `time() - hello_world_last_time_seconds`: последний запрос и прошедшее время (PDF 61).
6. `rate(hello_world_latency_seconds_sum[1m]) / rate(hello_world_latency_seconds_count[1m])`: средняя задержка (PDF 64, 68).
7. `histogram_quantile(0.95, rate(hello_world_latency_seconds_bucket[1m]))`: оценка 0.95 квантиля из кумулятивных сегментов (PDF 65–66).

## Interpretation

- Counter: важно изменение, не только абсолютное накопленное значение. Нельзя `inc` отрицательное число (PDF 56–60).
- Gauge: состояние непосредственно отражает текущую величину; `track_inprogress` учитывает исключения; `set_function` вызывается во время scrape и требует внимания к потокобезопасности (PDF 61–63).
- Summary average = скорость суммы / скорость количества; **квантили нельзя корректно складывать и усреднять** (PDF 63–65, 68).
- Histogram buckets кумулятивны, имеют `le` и обязательный `+Inf`; каждый bucket создаёт серию и стоит ресурсов (PDF 66–67).
- Для SLO/SLA с фиксированным порогом особенно полезен явный bucket на пороге. На PDF 67 обнаружено расхождение «дольше порога» vs. приведённая доля `<=` порога: [Source wording/code mismatch] — см. [source-findings.md](source-findings.md).
- Отсутствие запросов делает отношение ошибок к числу запросов неопределённым (`NaN`), а не равным 0 (PDF 59).

## Next action

- Онлайн-сервис: начать с **RED** — rate, errors, duration на стороне сервера и клиента (PDF 70).
- Конвейер, очередь, worker pool: **USE** — utilization, saturation, errors плюс длина очереди/объём работы (PDF 70, 72).
- Batch: записывать длительность, время последнего успешного выполнения; в главе названы Pushgateway и textfile collector Node Exporter как отдельные варианты (PDF 70–71).
- Для дорогих/критичных метрик тестировать семантику через изменение значения до/после события; не требовать автотестирования каждой отладочной метрики (PDF 68–69).

## Modifying action

- `pip install prometheus_client` устанавливает библиотеку в выбранную среду Python (PDF 54).
- Добавление `Counter` / `Gauge` / `Summary` / `Histogram` меняет код сервиса и может создавать новые временные ряды. Метрики определяются на уровне файла, чтобы избежать повторной регистрации (PDF 56–57).
- `Counter.inc`, `Gauge.inc/dec/set`, `Summary.observe`, `Histogram.time` изменяют показатели приложения; исключения, потоки и bucket-границы требуют проверки (PDF 58–67).
- Изменение имени метрики, label-комбинаций или buckets влияет на дашборды и ресурсы; план миграции и команда отката в главе не приведены: [Needs confirmation] (PDF 67, 72–75).

## Verification / acceptance checks

- `/metrics` показывает задуманную метрику; `python_info` есть в ответе демонстрационного сервера, Prometheus может её запросить (PDF 55–57).
- При вызове `do_GET` значение `hello_worlds_total` увеличивается; возможен дополнительный запрос браузера к `/favicon.ico` (PDF 57).
- `REGISTRY.get_sample_value('foos_total')`: сравнить до/после `foo()`, ожидаемое приращение 1 (PDF 69).
- `_count`, `_sum`, `_bucket` и `rate` отражают тип и частоту наблюдений (PDF 63–68).
- Метрики стабильны по имени, содержат единицы, не плодят лишние комбинации labels (PDF 72–75).

## Rollback

- Для изменения кода/имён/библиотек конкретный rollback в главе не описан: **[Needs confirmation]**.
- Безопасный эксплуатационный подход должен учитывать восстановление предыдущей версии кода и прежних запросов, но точная процедура для пользовательского окружения **не установлена RAG**. Не объявлять исходные примеры production-ready.
