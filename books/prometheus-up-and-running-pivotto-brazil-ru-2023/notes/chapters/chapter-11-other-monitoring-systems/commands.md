# Commands, protocols и конфигурации — глава 11

**Строгий источник:** RAG `p0209:c01`–`p0214:c01` (PDF 209–214). Исторические версии: InfluxDB Exporter `0.10.0`, StatsD Exporter `0.22.8`. **Ничего не выполнялось**. Категории: `read-only` (получение данных), `state-changing` (файлы/настройки/агрегаты), `workload-generating` (сеть/процессы). Команды shell со скачиванием — учебные, не production-установочные.

## Каталог совместимых интеграций (PDF 209–211)

| Исходный формат | Экспортер и особенности |
| --- | --- |
| InfluxDB line protocol | `InfluxDB Exporter`: HTTP write → scrape, timestamps из исходного события не сохраняются в `/metrics` |
| collectd | `Collectd Exporter`; начиная с collectd 5.7 также плагин Write Prometheus по тексту |
| Graphite | `Graphite Exporter`: точечные имена и извлечение меток, в сноске указана поддержка тегов Graphite 1.1.0 |
| StatsD | `StatsD Exporter`: TCP/UDP события в Counter/Gauge и timed metrics, mapping dot-path → labels |
| JVM/JMX | `JMX Exporter`: Java agent, regex mapping нестандартизованных mBean |
| SNMP/MIB | `SNMP Exporter`: network device, генерация config по MIB и удалённое probing |
| SaaS | `CloudWatch Exporter`, `New Relic Exporter`, `Pingdom Exporter`, `Stackdriver Exporter`: квоты/расходы API |
| NRPE | `NRPE Exporter`: переход для сложных Nagios remote checks |
| Dropwizard | Java client и встроенный `/metrics`, предпочтительнее JMX при контроле кода |

Для JMX/SNMP/SaaS/NRPE/collectd/Graphite отдельные готовые команды развёртывания в PDF 209–214 отсутствуют; не реконструировать.

## InfluxDB Exporter (PDF 211–212)

**State-changing / workload-generating — исходный пример 11.1:** скачивание архива, распаковка, запуск. URL перенесён из RAG без подтверждения сети; проверка релиза [Needs confirmation]; rollback [Needs confirmation].

```sh
wget https://github.com/prometheus/influxdb_exporter/releases/download/v0.10.0/influxdb_exporter-0.10.0.linux-amd64.tar.gz
tar -xzf influxdb_exporter-0.10.0.linux-amd64.tar.gz
cd influxdb_exporter-0.10.0.linux-amd64/
./influxdb_exporter
```

**State-changing — отправка одного наблюдения по HTTP POST, пример PDF 212:**

```sh
curl -XPOST 'http://localhost:9122/write' --data-binary \
    'example_metric,foo=bar value=43 1517339868000000000'
```

**Read-only — после POST просмотреть `http://localhost:9122/metrics`. Ожидаемое по книге:**

```text
# HELP example_metric InfluxDB Metric
# TYPE example_metric untyped
example_metric{foo="bar"} 43
```

**Важное ограничение:** исходная отметка `1517339868000000000` в `/metrics` не присутствует; при отсутствии timestamp Prometheus датирует образец временем scrape. Отправка в `/write` не гарантирует восстановление истории исходных событий (PDF 212).

**State-changing — Prometheus scrape, пример 11.2:**
```yaml
global:
  scrape_interval: 10s
scrape_configs:
 - job_name: application_name
   static_configs:
    - targets:
      - localhost:9122
```

Verification: exporter выдаёт видимый ряд, scrape проходит и label `foo=bar` сохранён. Rollback записи/состояния exporter: [Needs confirmation]. Не подставлять данные пользовательского production.

## StatsD Exporter (PDF 212–214)

**State-changing / workload-generating — пример 11.3, учебный выпуск:**
```sh
wget https://github.com/prometheus/statsd_exporter/releases/download/v0.22.8/statsd_exporter-0.22.8.linux-amd64.tar.gz
tar -xzf statsd_exporter-0.22.8.linux-amd64.tar.gz
cd statsd_exporter-0.22.8.linux-amd64/
./statsd_exporter
```

В книге exporter принимает StatsD по UDP/TCP `:9125` и Prometheus HTTP `:9102`. Наличие `nc` на хосте [Needs confirmation].

**State-changing (экспортируемые агрегаты) + workload-generating (TCP):**
```sh
echo 'example_gauge:123|g' | nc localhost 9125
echo 'example_counter_total:1|c' | nc localhost 9125
echo 'example_latency_total:20|ms' | nc localhost 9125
```

**Read-only:** `http://localhost:9102/metrics` — для первого события в книге показано:
```text
# HELP example_gauge Metric autogenerated by statsd_exporter.
# TYPE example_gauge gauge
example_gauge 123
```

**State-changing — файл `mapping.yml` по примеру PDF 213–214:**
```yaml
mappings:
- match: app.http.requests.*.*
  name: app_http_requests_total
  labels:
    region: "${1}"
    path: "${2}"
```

**State-changing / workload-generating — запуск с mapping:**
```sh
./statsd_exporter -statsd.mapping-config mapping.yml
```

**State-changing (агрегаты) / workload-generating (события):**
```sh
echo 'app.http.requests.eu-west-1./foo:1|c' | nc localhost 9125
echo 'app.http.requests.eu-west-1./bar:1|c' | nc localhost 9125
```

**Read-only — ожидаемые ряды из PDF 214:**
```text
# HELP app_http_requests_total Metric autogenerated by statsd_exporter.
# TYPE app_http_requests_total counter
app_http_requests_total{path="/bar",region="eu-west-1"} 1
app_http_requests_total{path="/foo",region="eu-west-1"} 1
```

**Source finding:** в пояснительной фразе p0213:c01 регион написан `euwest-1` без дефиса, но входные строки и результирующие метки p0214:c01 — `eu-west-1`. Примеры выше сохраняют значения из ввода/вывода, не исправляя исходную фразу; детали в [source-findings.md](source-findings.md).

## Границы и приёмка

- Исходник предупреждает: StatsD не полностью стандартизирован, реализации могут принимать только целочисленные значения; базовые единицы, привычные Prometheus, не всегда обеспечиваются (PDF 213).
- `|ms` означает StatsD timing event; имя `example_latency_total` не подтверждает, что итоговая метрика — Prometheus Counter, Histogram или Summary без проверки вывода конкретного exporter (PDF 213).
- Для InfluxDB/StatsD/Graphite/collectd push-to-pull рекомендована привязка одного экземпляра exporter к одному приложению с общим жизненным циклом; конкретный процессный менеджер/конфигурация не указаны (PDF 214).
- Согласование портов `:9122`, `:9125` (TCP/UDP), `:9102`, ограничения сети, секреты и rollback зависят от пользовательского окружения: [Needs confirmation].
- Ключевые действия примеров меняют локальные агрегаты и/или процессы. Их **не выполняли**. Для production не задаются команды установки новых выпусков, отсутствующие в исходнике.
