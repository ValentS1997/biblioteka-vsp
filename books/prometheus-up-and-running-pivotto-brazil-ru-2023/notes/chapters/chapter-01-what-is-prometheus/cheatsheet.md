**Scope:** «Что такое Prometheus?», PDF 18–33; `p0018:c01, p0019:c01, p0020:c01, p0021:c01, p0022:c01, p0023:c01, p0024:c01, p0025:c01, p0026:c01, p0027:c01, p0028:c01, p0029:c01, p0030:c01, p0031:c01, p0032:c01, p0033:c01`.

## Symptom / problem framing

Нужно понять, **что наблюдать** и **каким инструментом**. Метрики показывают агрегированную динамику состояния и производительности, тогда как отдельный запрос, событие и его контекст требуют других механизмов. Prometheus не является хранилищем журналов или отдельных событий. Источник: `p0020:c01, p0023:c01, p0026:c01, p0033:c01`.

## Baseline / context

- Четыре применения мониторинга по авторам: **оповещение**, **отладка**, **анализ тенденций**, **решение практических задач** (побочное применение конвейера мониторинга). `p0020:c01`.
- Подходы к телеметрии: профилирование (ограниченные срезы контекста), трассировка (пути исполнения/выборка), журналы (выбранные события с контекстом), метрики (агрегаты во времени). `p0022:c01, p0023:c01, p0024:c01, p0025:c01, p0026:c01`.
- Временной ряд в Prometheus определяется **именем метрики и набором меток**; PromQL агрегирует ряды по меткам. `p0019:c01`.
- **Кардинальность** — операционное ограничение. Пример адреса email пользователя как метки неразумен: множество значений не ограничено, возможны проблемы с персональными данными. Рекомендация авторов помнить ориентир **10 000 метрик на процесс** — не заявленная техническая жёсткая граница. `p0026:c01`.
- Prometheus по умолчанию хранит временные ряды локально и использует pull-модель; сбор с целей регулярно повторяется, часто через **10–60 с** (описательная величина из главы, не обязательная настройка). `p0030:c01`.

## Read-only checks

Концептуальная последовательность проверки проекта наблюдаемости (без исполняемых команд):
1. Установить, какой вопрос задан: общее состояние службы, конкретный запрос, путь выполнения или затраты CPU. `p0023:c01, p0024:c01, p0026:c01`.
2. Убедиться, что метрики доступны из инструментированного приложения или экспортера. `p0027:c01, p0028:c01, p0029:c01`.
3. Проверить наличие актуального списка целей из service discovery и соответствия меток вашей архитектуре. `p0029:c01`.
4. Различать доступность цели для scraping и состояние самого приложения: Prometheus получает свои метрики успешности и длительности сбора. `p0030:c01`.
5. Проверить, что искомые данные исследуются через PromQL / browser или Grafana, а уведомления генерируются правилами Prometheus, затем обрабатываются Alertmanager. `p0031:c01, p0032:c01`.

## Interpretation

| Наблюдение / задача | Выбор по логике главы | Ограничение |
| --- | --- | --- |
| Общая производительность/нагрузка сервиса | Метрики Prometheus | Контекст отдельных событий ограничен |
| Кто выполнил конкретный запрос, какие данные были переданы | Журналы | Объём, требования к хранению, приватность |
| Где распределённый запрос потратил время | Трассировка | Выборка и накладные расходы |
| Какие функции расходуют CPU | Профилирование | Детальный сбор может быть дорогим |
| Уведомить ответственного | Правила Prometheus → Alertmanager | Маршрутизация — не определение условий |
| Долгая история метрик | Remote-read / remote-write интеграция | Локальное хранение ограничено диском |

Источники: `p0023:c01, p0024:c01, p0025:c01, p0026:c01, p0031:c01, p0032:c01`.

## Modifying action

Глава концептуальная. Возможные изменения (инструментирование кода, подключение экспортера, изменение сопоставления меток или правил записи/оповещения) прямо **упомянуты**, но пошаговых процедур, конкретных конфигураций и команд глава 1 не предоставляет. **Не выполнять** такие изменения по этому cheatsheet. Эффекты: изменение набора собираемых метрик/целей или поведения оповещений; риски: рост кардинальности, затрат на хранение и ошибочная маршрутизация. `p0026:c01, p0027:c01, p0028:c01, p0029:c01, p0031:c01, p0032:c01`.

## Verification / acceptance checks

Концептуальные критерии: метрики доступно собирать; целевые сервисы обнаружены; выборки попадают в хранилище; PromQL позволяет исследовать нужный показатель; правила генерируют ожидаемые уведомления, которые маршрутизируются Alertmanager. **Способ конкретной верификации и ожидаемые значения для окружения:** [Needs confirmation]. `p0027:c01, p0029:c01, p0030:c01, p0031:c01, p0032:c01`.
