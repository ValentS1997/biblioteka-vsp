# Cheatsheet — глава 6: дашборды Grafana

**Источник:** PDF 112–129, RAG `p0112:c01`–`p0129:c01`. UI и версии — по изданию 2023 года, не подтверждённые текущие инструкции.

## Symptom / problem framing

- Промежуточный просмотр через браузер выражений Prometheus не заменяет дашборд для регулярной диагностики. Нужен набор связанных панелей с явной задачей (PDF 112).
- Источник данных не проходит `Save & Test`: в книге предлагается проверить, запущен ли Prometheus и доступен ли **из Grafana** (PDF 115–116).
- «Стена графиков»: слишком много панелей/рядов повышают когнитивную нагрузку и мешают реагированию на инцидент (PDF 117).
- Внешний вид rate-графика меняется при обновлении: `aliasing` и переменный шаг оценки; это не обязательно изменение исходных данных (PDF 121).
- Нужен общий сетевой дашборд для устройств: не копировать по одному дашборду на каждый интерфейс — использовать переменные Grafana (PDF 126–129).

## Baseline / context

- Учебные endpoint: Grafana `http://localhost:3000/`, Prometheus `http://localhost:9090` в окружении `--net=host` из примера (PDF 113, 115).
- Источник — Docker-команда `docker run -d --name=grafana --net=host grafana/grafana:9.1.6`. Том в примере не монтируется; состояние остаётся внутри контейнера (PDF 113).
- Создать источник данных типа **Prometheus**, сохранить и проверить. Дашборд допускает панели из разных источников, в том числе объединённые (PDF 115).
- Виды панелей: **Time series** (временной ряд), **Stat** (число/метка), **Table** (несколько рядов компактно), **State timeline** (смена состояния) (PDF 117–125).
- Настройки времени по умолчанию в примере: **Last 6 hours**; окно и интервал обновления управляются на уровне всего дашборда, возможна настройка панели (PDF 119).

## Read-only checks

1. Открыть `http://localhost:3000/`; убедиться, что ожидаемая Grafana отвечает. Переход к редактированию уже **не** read-only (PDF 113–116).
2. На странице data source проверить ранее сохранённое соединение Prometheus; сам `Save & Test` является **операцией GUI проверки и настройки**, а не заменой мониторинга цели (PDF 115).
3. В Query: `process_resident_memory_bytes` — память процесса Prometheus/экспортера, а не всей системы; график Time series (PDF 118–119, в контексте главы 2).
4. В Stat: `prometheus_tsdb_head_series` — приблизительное количество текущих рядов TSDB (PDF 121).
5. В Stat с Table/Fields=`release`: `node_uname_info` — информация о версии ядра из меток Node Exporter (PDF 122).
6. В Table: `rate(node_network_receive_bytes_total[1m])`, `Instant`, `Format=Table`, `Organize fields`, единицы bytes/sec (IEC) (PDF 123–124).
7. В State timeline: `up`; привязка `1→UP, 2→DOWN` **как напечатано в PDF 125**, но требует adjudication (в RAG главы 2 `up=0` для недоступной цели). Не объявлять это подтверждённым результатом.

## Interpretation

- `{{job}}` и `{{job}} / {{instance}}` — шаблоны легенды Grafana, а не PromQL (PDF 119, 125).
- Назначить единицы вывода соответственно метрике: `data/bytes (IEC)` для памяти и `bytes/sec (IEC)` для скоростей сети (PDF 119, 124).
- Time series показывает изменение во времени, Stat — последнее/выбранное значение, Table — компактный набор временных рядов, State timeline — дискретные состояния (PDF 117–125).
- `label_values(node_network_receive_bytes_total, device)` — **функция переменных Grafana, не PromQL** (PDF 126, сноска). `$Device` — подстановка; `$__rate_interval` зависит от данных/шага панели (PDF 127–128).
- Для одного значения переменной книга использует `device="$Device"`, для Multi-value — `device=~"$Device"` (PDF 127).
- Для корректного вывода важно время, окно rate и настройка refresh; искажения графиков не следует принимать за первичное доказательство инцидента (PDF 119–121).

## Next action

- Проверить цель дашборда: обзорный (не более одного экрана) или экспертный (детальнее). Устранить лишние графики ради сокращения когнитивной нагрузки (PDF 117).
- После успешного соединения источника создать четыре типа панелей с правильными единицами измерения и сохранением изменений (PDF 115–125).
- Для повторного использования дашборда настроить переменную `Device`; позже архитектурные сценарии могут использовать `job`, `instance`, data source (PDF 126–129).
- Использовать `Share dashboard` и снимки для передачи коллегам/послеаварийного анализа (PDF 129).

## Modifying action

- Запуск контейнера Grafana **изменяет Docker-хост** и открывает HTTP-сервис. Используются host networking, демонстрационный пароль, нет постоянного тома. Нужны отдельные controls безопасности и хранения, не описанные в главе (PDF 113).
- Добавление data source, дашборда, панели, переменной и сохранение изменений меняет состояние Grafana (PDF 115–119, 126–129).
- `Save & Test`, `Apply`, `Ctrl+S`, `Save As`, `Duplicate`, `Share` — функции UI книги, не shell-команды (PDF 115–129).
- Запуск/остановка Prometheus или переключение datasource в пользовательском окружении: **[Needs confirmation]** (PDF 116).
- В случае ошибки `2→DOWN` или неверного исходящего PromQL из PDF нельзя принимать результат на веру — зарегистрированы в [source-findings.md](source-findings.md).

## Verification / acceptance checks

- `Save & Test` показывает успешную проверку источника данных Prometheus (PDF 115–116).
- Time series отображает память с `{{job}}`, IEC bytes, заголовком **Memory Usage**; дашборд сохранён (PDF 118–119).
- Stat отображает количество рядов и **Kernel version** через `node_uname_info` / `release` (PDF 121–123).
- Table содержит сетевой приём, выбранные поля и единицы bytes/sec, заголовок **Network Traffic Received** (PDF 123–124).
- State timeline визуализирует временные состояния, однако конкретный DOWN mapping в книге конфликтует с ранним примером (PDF 125); [Needs confirmation].
- Выпадающий `Device` меняет график сетевого приёма; формат legend `{{device}}`, заголовок **Bytes Received** (PDF 126–129). Выражение для Bytes Transmit не объявляется исполнимым без проверки (PDF 128).
- Реальные скриншоты/значения, работоспособность Docker и Prometheus в пользовательской среде: [Needs confirmation].

## Rollback

- Книга упоминает **Save As**, удобный для экспериментов с копией дашборда (PDF 117). Но полный rollback панелей/источников и сохранённого состояния не описан: **[Needs confirmation]**.
- Docker volume в демонстрационном примере отсутствует, поэтому при операциях с контейнером есть риск утраты состояния (PDF 113); точные действия восстановления — [Needs confirmation].
- Нельзя переносить учебный `admin/admin` и host networking в production без отдельной проработки безопасности (PDF 113).
