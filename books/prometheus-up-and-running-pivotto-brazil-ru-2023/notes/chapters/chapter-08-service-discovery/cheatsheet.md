# Cheatsheet — глава 8: обнаружение служб

**Provenance:** `p0144:c01`–`p0169:c01`, PDF 144–169. Все конфигурации — из исторических примеров книги, не из внешнего руководства.

## Symptom / problem framing

- Новые узлы не появляются в Prometheus без ручного обновления `static_configs`: требуется service discovery из файлов, HTTP или системы вроде Consul/EC2 (PDF 144–150).
- Цель есть на странице `/service-discovery`, но `/metrics` не опрашивается: **discovery не означает работающий exporter**; пример Consul иллюстрирует это различие (PDF 149–151).
- Внезапно исчезли все цели: последовательные взаимоисключающие `keep` могут удалить весь набор (PDF 155).
- Цели/временные ряды меняются после переименования региона/команды/instance: target labels влияют на идентичность и стабильность PromQL (PDF 157–158).
- Отсутствует список после перезапуска и сбоя HTTP SD: в книге указано, что промежуточный cache не хранится на диске (PDF 150).
- Метрики дорогие по кардинальности: `metric_relabel_configs` может исключать их **перед сохранением**, но сеть и парсинг уже произошли (PDF 167–168).

## Baseline / context

- `static_configs` — для редко меняющегося набора машин; может задавать `targets` и `labels`. `job_name` уникален в списке scrape jobs (PDF 146–147).
- File SD — JSON/YAML с `targets` и `labels`, local path относительно рабочего каталога Prometheus; glob можно использовать в именах файлов, но не каталогов. Изменения обнаруживаются автоматически, файл следует обновлять атомарно (PDF 147–150).
- HTTP SD — endpoint возвращает **200 + Content-Type application/json + JSON в формате file SD**. По книге refresh каждые 60 s, можно изменить `refresh_interval`; failures считать через `prometheus_sd_http_failures_total` (PDF 150).
- Consul/EC2 SD возвращают метаданные; EC2 обычно даёт private IP и требует права API, по книге минимум `EC2:DescribeInstances` (PDF 151–153).
- Восходящий SD (регистрация экземпляра самим собой, например Consul) и нисходящий SD (знание ожидаемых объектов, например EC2) дают разные возможности проверки отсутствующих экземпляров (PDF 146).
- Relabel RE2 по умолчанию соответствует **всей строке**; `source_labels` склеиваются через `;` (PDF 154–156).
- `__address__` — фактический host:port scrape, `instance` обычно копирует `__address__`; `job` обычно копирует `job_name`. Внутренние `__meta_*` удаляются после target relabel (PDF 161–162).

## Read-only checks

1. Открыть `http://localhost:9090/service-discovery`; сравнить найденные metadata и окончательные target labels; проверить число целей и поведение правила `keep` (PDF 148–151).
2. Для file SD сверить наличие расширения `.json`, `.yml`/`.yaml`, корректность структуры targets/labels и **путь относительно рабочего каталога** (PDF 147–148).
3. Для HTTP SD проверить ожидаемые `application/json` и код 200, а также `prometheus_sd_http_failures_total`; рост говорит об ошибках обновления целей (PDF 150).
4. Посмотреть итоговые `job`, `instance`, `__address__` до внутренних преобразований в представлении discovery и проверить, что адрес действительно соответствует exporter (PDF 161–162).
5. Проверить RE2 и порядок правил — два `keep` с `infra` и `monitoring` могут оставить **ноль** целей. Для альтернатив в книге показан `regex: infra|monitoring` (PDF 155).
6. При конфликтующих метках посмотреть `exported_job`/требуемую семантику `instance=""` и параметр `honor_labels` (PDF 169).

## Interpretation

- Не отфильтровывать нездоровые экземпляры на уровне SD только из-за проверки health: они могут ещё экспортировать полезную диагностику запуска/завершения (PDF 156).
- Не опрашивать группу экземпляров через балансировщик как одну цель: разные scrape могут попадать на разные экземпляры, а счётчики выглядеть уменьшающимися (PDF 156).
- В file SD `job_name` — значение по умолчанию, может быть переопределён меткой из файла; `job`/ `instance` доступны у каждой цели (PDF 149, 162).
- `keep` оставляет совпадения, `drop` исключает совпадения; `replace` меняет значение; `labelmap` меняет **имена**. `lowercase`/`uppercase` нормализуют регистр (PDF 155–164).
- Пример `__meta_consul_tags` содержит список с начальными/конечными запятыми. `.*,prod,.*` применяется для фильтрации по тегу (PDF 164–165).
- `metric_relabel_configs` применяется после scrape к метрикам и не затрагивает `up`, которую формирует сам scrape (PDF 167–168).
- `honor_labels: true` отдаёт приоритет экспортируемой метке; в особом случае `instance=""` сохраняет отсутствие `instance` для Pushgateway (PDF 169).

## Next action

- Для стабильных небольших сред оставить статический список; для динамических использовать управляемый SD источник с понятными метаданными и lifecycle (PDF 144–146).
- Сначала определить политику target labels и право владения пространством имён `monitor_`, затем relabel для адресации и отбора (PDF 154–165).
- До изменения `keep/drop` проверить ожидаемое количество обнаруженных, оставленных и исключённых целей — контрольный список здесь является операционным следствием примеров, конкретных чисел инфраструктуры нет.
- Для высококардинальной метрики рассматривать фильтрацию как временное решение, а исходную проблему исправлять у exporter/приложения (PDF 167–168).

## Modifying action

- Правка `prometheus.yml`: `static_configs`, `file_sd_configs`, `http_sd_configs`, `consul_sd_configs` или `ec2_sd_configs` меняет состав отслеживаемых целей; перезапуск/reload зависит от инфраструктуры и в главе **не указан**: [Needs confirmation] (PDF 146–154).
- `relabel_configs` с `keep`/`drop` исключает цели; `replace` на `__address__` переключает адрес. Ошибка может прекратить scrape и оповещения (PDF 154–162).
- `metric_relabel_configs` отбрасывает образцы до хранения, но не устраняет сетевые издержки (PDF 167–168).
- `honor_labels` меняет приоритет конфликтующих меток и поведение Pushgateway (PDF 169).
- Примеры с `insecure_skip_verify: true` и inline `basic_auth.password` из PDF 165 **не применять как безопасную конфигурацию**. Реальные секреты только через согласованное безопасное хранение: [Needs confirmation].

## Verification / acceptance checks

- После контролируемого обновления SD сверить отображение целей на `/service-discovery`, ожидаемые `job`, `instance`, `team`, `datacenter` и scrape конкретных exporters (PDF 148–153).
- Для HTTP SD после восстановления источника должен возвращаться доступный список; `prometheus_sd_http_failures_total` перестаёт увеличиваться из-за неудачных запросов (PDF 150).
- Для Consul Node Exporter `__address__` строится из IP и порта `:9100`; `instance` можно дополнительно присвоить по имени узла (PDF 161–162).
- Для `metric_relabel_configs` подтвердить, что отфильтрованные ряды не сохраняются, но `up` остаётся метрикой самого scrape (PDF 167–168).
- Для `honor_labels` проверить конфликтные target/instrumentation labels, а не предполагать приоритет без чтения config (PDF 169).
- Точные хосты, доступы, нагрузка и схема rollback конкретной системы: [Needs confirmation].

## Rollback

- Источник описывает конфигурации, но **не содержит явной пошаговой процедуры rollback** для релизов SD/relabel: [Needs confirmation].
- Возврат прежней конфигурации и проверка состава целей требуют пользовательских параметров инфраструктуры. Не конструировать команд reload из памяти модели.
- Перенос target labels и удаление рядов не восстанавливают автоматически исторические данные/идентичность рядов; источниковый регламент восстановления не приведён: [Needs confirmation].
