## Основные выводы

1. **Обнаружение цели — не успешный scrape.** SD предоставляет адреса и метаданные; Prometheus отдельно пытается получить `/metrics`. Consul может обнаруживать машины, но пример обнаруженной службы Consul сам по себе не обеспечивает пригодный `/metrics` (PDF 151).
2. **Целевые метки добавляет Prometheus, не приложение.** Они позволяют независимо организовать разные представления одной инфраструктуры для разных команд. Изменение target labels меняет идентичность временного ряда и создаёт разрывы данных (PDF 144–145, 157–158).
3. **File SD** читает JSON/YAML из локальных файлов; **HTTP SD** ожидает JSON с кодом 200 и правильным Content-Type. Временный сбой HTTP сохраняет последний обнаруженный список, но после перезапуска может не оказаться никакого списка (PDF 147–150).
4. **`keep` и `drop` выбирают цели до опроса**. Несколько `keep` применяются последовательно — два противоречащих правила могут удалить все цели (PDF 154–156).
5. **`__address__` определяет куда подключаться**, `instance` по умолчанию наследует адрес; `job` по умолчанию равен `job_name`. Их можно управляемо менять, не добавляя лишнюю уникальную метку host (PDF 161–162).
6. **`metric_relabel_configs` влияет на ряды после получения, но до записи**, а не на обнаружение целей. Фильтрация уменьшает стоимость хранения, не устраняя затраты на передачу и парсинг уже полученных метрик; `up` не обрабатывается этим механизмом (PDF 167–168).
7. **`honor_labels` меняет приоритет конфликтующих меток**, важен для Pushgateway, но требует отдельной проверки семантики `instance` и безопасности (PDF 169).

## Примечания по точности и безопасности

- Конфигурация изучается в контексте **Prometheus 2.37.0** (PDF 145). Современная версия и доступность опций неизвестны: [Needs confirmation].
- В PDF 163 пример `labelmap` содержит шаблон `__meta_ec2_public_tag_monitor_(.*)`, но в тексте и соседних примерах EC2 используются имена `__meta_ec2_tag_*`. Это несогласованность источника; не подменять строку молча: [source-findings.md](source-findings.md).
- В PDF 167 встречается форма `metrics_relabel_configs` в прозе при `metric_relabel_configs` в заголовке и примерах; пример 166–167 использует `relabel` вместо полного ключа из других разделов; зарегистрированы как [Source wording/code mismatch] / [Source code mismatch].
- PDF 165 приводит `insecure_skip_verify: true`, а также демонстрационные имя пользователя и пароль. Такой пример **не безопасная production-конфигурация**. Подлинные секреты и токены в артефакты не добавляются. Доступность HTTPS и авторизация проверяются отдельно (PDF 165–166).
- Примеры EC2 с IAM/секретными ключами — placeholders, никаких реальных учётных данных не включать (PDF 152–153). Искажение видимости в SD при слишком широких `labelmap` опасно для запросов/оповещений (PDF 163).
- Рис. 8.1–8.4 доступны только как подписи RAG, а не факсимильные рисунки; SVG здесь основаны на тексте.
- Отдельного chapter-end summary и контрольных вопросов PDF 144–169 не содержит; условные `summary.md`, `review-questions.md`, `review-answers.md` не создаются.
