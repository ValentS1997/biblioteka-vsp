## Основная последовательность

1. Запустить Prometheus с `scrape_interval: 10s`; убедиться в состоянии UP на странице **Status → Targets**, открыть собственный `/metrics` (PDF 35–37).
2. В браузере выражений проверить `up`, память процесса и изменение счётчика через `rate` (PDF 38–42).
3. Запустить Node Exporter; добавить цель `localhost:9100` и применить конфигурацию перезапуском Prometheus (PDF 43–46).
4. Остановить Node Exporter **в рамках лабораторного сценария**: цель переходит в DOWN, `up == 0` выбирает недоступный экземпляр (PDF 47–48).
5. Добавить `rules.yml` и `alertmanager.yml`, перезапустить Prometheus и запустить Alertmanager; при наличии работоспособного SMTP-маршрута получить уведомление (PDF 49–52).

**Принцип:** `scrape` собирает метрики, PromQL описывает как наблюдение, так и условие тревоги; Prometheus создаёт alert, а Alertmanager доставляет уведомление. `job` и `instance` помогают различать источники (PDF 38, 43–49).
