# Cheatsheet — глава 5: метки

**Provenance:** PDF 97–111; RAG `p0097:c01`–`p0111:c01`; строго `rag_only`.

## Symptom / problem framing

- Для каждого URL/метода создана отдельная метрика: сложно агрегировать. В книге — общий `http_requests_total` с измерениями `path`, `method` (PDF 97–99, 101).
- При запуске `/metrics` не содержит ожидаемый ряд: `labels()` ещё не вызван для конкретного child (PDF 102).
- Меняются суммы или запросы после правки labels: добавление/удаление инструментированной метки — breaking change, в частности для `without` (PDF 108).
- Увеличивается потребление ресурсов мониторинга: количество комбинаций меток, экземпляров и сегментов Histogram растёт мультипликативно (PDF 109–111).
- При переключении one-hot состояний иногда видно 0 или 2 активных: возможна гонка между обновлением Gauge и scrape (PDF 105–106).

## Baseline / context

- Ряд определяется именем и набором меток; порядок меток семантически несущественен (PDF 97–98).
- **Инструментированные labels** относятся к внутренним свойствам приложения; **целевые labels** отражают job/instance/окружение/команду/регион и прикрепляются при scrape (PDF 98–100).
- `__name__` — системная метка имени метрики; `up` соответствует `{__name__="up"}`. Имена с `__` зарезервированы (PDF 100).
- Python `labelnames=['path']`, **не** строка `labelnames='path'` (это последовательность букв). `labels(self.path)` выбирает child (PDF 99).
- Label values допускают UTF-8 и пустую строку, но пустое значение может восприниматься как отсутствие метки (PDF 100).
- `sum without(...)` удаляет перечисленные метки; `sum by(...)` оставляет указанные; оба подхода рассматриваются в главе (PDF 103–104, 108).

## Read-only checks

1. Посмотреть `/metrics`: у отдельных путей есть ряды `hello_worlds_total{path="/"}`, `{path="/foo"}`, при обращении браузера возможен `/favicon.ico` (PDF 99).
2. `rate(hello_worlds_total[5m])` — скорость по сочетаниям `job`, `instance`, `path`, `method` (PDF 103).
3. `sum without(path)(rate(hello_worlds_total[5m]))` — свёртка по path, сохраняющая instance/method (PDF 103–104).
4. `sum without(path, instance)(rate(hello_worlds_total[5m]))` — свёртка по экземплярам/путям: в таблице 5.3 GET=45, POST=18 (PDF 104).
5. `avg_over_time(resource_state[1h])` и `sum without(resource)(resource_state)` — анализ enum Gauge с 0/1 (PDF 105).
6. `sum by (version)(python_info)` — число Info-рядов по версии (PDF 108).
7. Проверить `__name__` и устойчивость `job`/`instance`; избегать конфликтующих имён (PDF 100).

## Interpretation

- Gauge-перечисление: в каждый момент один state = 1, остальные = 0. Нужна согласованность при изменениях, в книге используется `Lock` внутри custom collector (PDF 105–106).
- Info: Gauge `_info` со значением 1 позволяет присоединить строковую метку к другим рядам: `up * on(instance, job) group_left(version) python_info` (PDF 107–108).
- `sum without(method, instance)` в таблице 5.4 сохраняет `path`. Одна исходная строка таблицы содержит `method="POST"` и классифицирована как **[Source wording/code mismatch]**, а не исправлена (PDF 104).
- Временные ряды, которые уже включают `label="total"`, могут приводить к двойному подсчёту при `sum` (PDF 109).
- Типичная рекомендация авторов: меньше 10 комбинаций у обычной метрики на один экземпляр; несколько исключений около 100 допускаются (PDF 111). Пример масштабирования 10 млн серий и 1000 экземпляров — не обещание производительности конкретной установки (PDF 110).

## Next action

- Определить измерения до добавления labels; избегать значений email, клиентов, IP и потенциально неограниченных URL в labels (PDF 109–110).
- Проверить, можно ли осмысленно суммировать/усреднять значения по метке; если нет, возможно, нужны разные имена метрик или журналирование (PDF 108–109).
- Для Enum с согласованными переходами состояний использовать атомарный снимок под блокировкой; конкретный `StateMetric` приведён в источнике (PDF 105–106).
- Для регистрации статичных дочерних элементов вызвать `labels('/foo')` и `labels('/bar')` при запуске (PDF 102).

## Modifying action

- Добавление `labelnames` и `labels(...)` меняет форму выдаваемых рядов и требует согласования запросов/дашбордов; изменение меток — breaking change (PDF 99, 108).
- `REQUESTS.labels(self.path).inc()` создаёт/увеличивает child Counter (PDF 99).
- Создание `StateMetric`, `REGISTRY.register(sm)`, `sm.set_state("blaa","RUNNING")` изменяет реестр и состояние custom collector (PDF 105–106).
- Удаление child упоминается только для модульных тестов; во время жизни сервиса может нарушить `rate` (PDF 103).
- `sample_limit` упомянут как предохранитель при высокой кардинальности; конкретное изменение YAML/значение здесь **не описано** — [Needs confirmation] (PDF 111).
