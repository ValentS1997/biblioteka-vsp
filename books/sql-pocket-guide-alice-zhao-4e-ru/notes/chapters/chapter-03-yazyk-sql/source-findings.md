# Source findings — глава 3. Язык SQL

Book: `sql-pocket-guide-alice-zhao-4e-ru`, PDF 55–69, RAG `p0055:c01`–`p0069:c01`. 
Ниже фиксируются наблюдения над оригинальным текстом и его извлечением; **ни один пример не исправлен в исходном RAG**.

## F-01 · [Source code mismatch] · заявленная одинаковая логика DECODE и CASE

В `p0058:c01` автор приводит два варианта и заявляет, что второй имеет ту же логику:

**Вариант 1 — Oracle DECODE (исходный fragment):**
```sql
DECODE (flag, 0, 'No', 1, 'Yes')
```

**Вариант 2 — CASE (исходный fragment):**
```sql
CASE WHEN flag = 0 THEN 'No'
     ELSE 'Yes' END
```

**Разбор только по тексту:** для значения `flag = 0` обе записи явно предполагают `'No'`; для `flag = 1` — `'Yes'`. Однако `CASE` имеет ветвь `ELSE 'Yes'`, в то время как в видимом `DECODE` перечислены только значения `0` и `1`, без явно записанной ветви по умолчанию. Семантика `DECODE` для прочих значений, включая `NULL`, в RAG **не описана**. Полную эквивалентность на остальных значениях утверждать нельзя: **[Needs confirmation]**.

**Риск:** перенос в другую РСУБД с изменением результата на неучтённых значениях. **Действие:** сохранить оба варианта без молчаливой коррекции; при работе вне режима `rag_only` сначала отдельно проверить семантику на реальных данных и документации выбранной системы. Это зафиксированное **возможное** расхождение, не доказанный результат SQL-исполнения.

## F-02 · [Source wording/code mismatch] · идентификатор order в JOIN

В `p0059:c01` оба исходных примера соединения ссылаются на таблицу как `order o`, без кавычек. В той же главе `p0064:c01` явно встречается `ORDER BY`, а `p0062:c01` предупреждает не использовать ключевые слова как идентификаторы.

**Риск:** потенциальный конфликт с ключевым словом в зависимости от диалекта. **Точный статус синтаксической ошибки:** [Needs confirmation], поскольку запуск на целевой РСУБД не выполнялся. Оба исходных фрагмента сохранены; не переименовывать таблицу и не добавлять кавычки без отдельной проверки.

## F-03 · [Source contradiction] · переносимость и версии стандартов

- `p0057:c01`: ANSI SQL в пояснении описывается как переносимый между РСУБД, но далее в том же разделе указано, что системы лишь **частично** следуют стандартам.
- `p0058:c01`: отмечена проблема переноса нестандартного SQL между РСУБД.
- `p0069:c01`: в завершающем резюме снова используется упрощённая формулировка о работе ANSI SQL во всех программах.
- `p0057:c01`, `p0059:c01`: «последним» стандартом на момент написания назван `ANSI SQL2016`.

**Интерпретация:** сведения о переносимости — учебное обобщение, а `ANSI SQL2016` — утверждение **издания**, не удостоверенный текущий статус стандартизации. Из этих пунктов нельзя заключать, что произвольный ANSI-запрос гарантированно работает на любой версии каждой РСУБД. **Внешней проверки не было.**
