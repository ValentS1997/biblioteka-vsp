## Цель главы

Разобраться, почему SQL — **декларативный язык специального назначения**, что значит стандарт ANSI SQL и чем стандарт отличается от диалектов конкретных РСУБД; научиться читать ключевые элементы оператора; классифицировать SQL-код по назначению и безопасности.

## Выводы, подтверждённые текстом

1. **Декларативность:** Python-пример суммирует элементы циклом, SQL-пример описывает желаемое значение `SELECT SUM(calories) FROM workouts;`. В книге SQL назван специальным языком для взаимодействия с реляционной БД. `p0055:c01`–`p0056:c01`.
2. **Стандарты ≠ одинаковая реализация:** глава называет ANSI-89, ANSI-92 и ANSI SQL2016 (последний — как характеристика издания, **не установленный текущий стандарт**). У РСУБД остаются собственные расширения и различия реализации. `p0057:c01`–`p0059:c01`.
3. **Состав SQL:** keywords, functions, identifiers, aliases, statements, clauses, expressions, predicates, comments, quotes, whitespace. `p0059:c01`–`p0067:c01`.
4. **Псевдоним не изменяет таблицу:** `employee e`, `sales s`, `AS num_sales` действуют в рамках запроса. `p0062:c01`.
5. **NULL:** отсутствие значения проверяется `IS NULL`; предикаты могут принимать `TRUE`, `FALSE`, `UNKNOWN`. `p0065:c01`–`p0066:c01`.
6. **Подъязыки:** DQL (`SELECT`), DDL (`CREATE`/`ALTER`/`DROP`), DML (`INSERT`/`UPDATE`/`DELETE`), DCL (`GRANT`/`REVOKE`), TCL (`COMMIT`/`ROLLBACK`). Это **классификация**, не разрешение запускать команды из этого перечня. `p0068:c01`–`p0069:c01`.

## Правила достоверности

- `DECODE` и `CASE` сохранены в авторском виде, без молчаливой правки. Эквивалентность для значений `flag` вне `0/1` не вытекает из доступного описания; см. `source-findings.md`.
- `ANSI SQL2016` записано **как утверждение книги**, не как проверка современных стандартов.
- Примеры с `order` в `FROM` остаются без исправления и требуют проверки на конкретной РСУБД.
- Типы, схема, существование `employee`, `sales`, `items`, `workouts`, `customer`, `order`, права пользователя и план выполнения — [Needs confirmation].
- Самостоятельных контрольных вопросов и упражнений на PDF 55–69 нет; `review-questions.md` и `review-answers.md` **не создаются**.
- Для SQL на запись требуется отдельное санкционирование/rollback. Здесь DDL/DML/DCL/TCL представлены по тексту только как категории.
