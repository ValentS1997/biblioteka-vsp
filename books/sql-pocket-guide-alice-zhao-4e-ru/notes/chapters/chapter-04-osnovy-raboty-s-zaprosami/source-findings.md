**Book:** `sql-pocket-guide-alice-zhao-4e-ru`. **Source:** RAG chunks `p0070:c01`–`p0104:c01`, PDF 70–104. `rag_only`; ошибок источника молча не исправлять.

## F-01 — [Source code mismatch] · waterfall против waterfalls

**Вариант A (коррелированный подзапрос):** `p0079:c01`:
```sql
SELECT o.id, o.name,
       (SELECT COUNT(*) FROM waterfall w
        WHERE o.id = w.owner_id) AS num_waterfalls
FROM owner o;
```

**Вариант B (предложенная автором перепись):** `p0080:c01`:
```sql
SELECT   o.id, o.name,
         COUNT(w.id) AS num_waterfalls
FROM     owner o LEFT JOIN waterfalls w
         ON o.id = w.owner_id
GROUP BY o.id, o.name
```

В большинстве прочих примеров главы используется имя **`waterfall`**, а не **`waterfalls`** (`p0070:c01`, `p0083:c01`, `p0094:c01`). **Верно ли `waterfalls` как реальная таблица, в RAG не подтверждено.** Не заменять на другое имя без документации реальной схемы. Автор описывает JOIN как более быстрый, но в анализе нет фактических измерений: выигрыш — [Needs confirmation].

**Риск:** копирование альтернативы с неверным именем может вызвать ошибку доступа к таблице; сравнение производительности не репрезентативно без одинаковых источников данных.

## F-02 — [Source wording/code mismatch] · COALESCE и сохранение строк LEFT JOIN

В `p0100:c01` приведён:
```sql
SELECT COALESCE(o.name, 'Unknown') AS owner,
       w.name AS waterfall_name
FROM   waterfall w
       LEFT JOIN owner o ON w.owner_id = o.id;
```

`p0101:c01` выводит в результирующем наборе строки `Unknown`, а пояснение утверждает, что **без `COALESCE` водопады без владельцев были бы исключены из результата**. Ранее `p0085:c01` различает соединения по сохранению несопоставленных строк.

**Классификация:** в изложении смешаны замена пустого отображаемого значения `o.name` и вопрос присутствия строки в результате `LEFT JOIN`. Это внутреннее семантическое несоответствие **между текстовым пояснением и конструкцией JOIN**, а не результат реального запуска.

**Политика:** сохранить и оператор, и авторскую формулировку для ревизии. Не выдавать `COALESCE` за механизм включения строк в набор и не подменять источник исправленной версией. Результат конкретной РСУБД — [Needs confirmation].

## F-03 — [Source wording/code mismatch] · MAX(stop) используется как число остановок

В `p0083:c01` для соединения `waterfall` и `tour` используется **`w.id = t.stop`**, то есть поле `stop` связывается с ID водопада:
```sql
FROM waterfall w JOIN tour t
     ON w.id = t.stop;
```

В `p0088:c01` «количество остановок в туре» определяется как:
```sql
SELECT name, MAX(stop) as num_stops
FROM tour
GROUP BY name;
```

**Проблема:** в доступном RAG нет условия, гарантирующего, что максимальное значение ID остановки совпадает **с количеством строк остановок** в туре. Авторские значения `11`, `6`, `14` не устанавливают общую эквивалентность.

**Политика:** выражения остаются неизменными. Семантика `tour.stop`, гарантия упорядоченной/непрерывной нумерации и корректность вычисления для произвольной БД — [Needs confirmation]. Не добавлять альтернативу `COUNT(...)` как «исправление» без проверки.
