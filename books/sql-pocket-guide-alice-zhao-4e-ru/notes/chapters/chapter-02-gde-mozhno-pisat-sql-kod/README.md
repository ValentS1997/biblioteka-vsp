## Главная идея

SQL пишут не в единственном универсальном приложении. Глава объясняет три интерфейса: **консоль самой РСУБД**, **графические клиенты** и **код Python/R с драйвером базы**. Прежде чем выбирать способ, нужно установить используемую РСУБД, способ подключения, полномочия и характер операций.

## Проверенные факты главы

1. **SQLite:** запуск `sqlite3` без имени файла в примере автора — сессия в памяти; `sqlite3 my_new_db.db` использует файловую БД. Создание таблицы и вставка строк **изменяют состояние** (`p0036:c01`).
2. **Различия консолей:** `mysql>`, `SQL>`, `postgres=#`, `1>`, `sqlite>`; `go` в приведённом SQL Server-примере служит явной отправкой блока (`p0036:c01`–`p0040:c01`).
3. **Клиенты:** DB Browser for SQLite, MySQL Workbench, Oracle SQL Developer, pgAdmin, SQL Server Management Studio, DBeaver. GUI работает через драйвер (`p0040:c01`–`p0042:c01`).
4. **Подключение:** host, port, database, username, password; SQLite вместо сетевых полей использует путь к файлу БД (`p0042:c01`–`p0043:c01`). Приведённые номера портов — **значения из книги, не фактические параметры целевой среды**.
5. **Python/R:** установка драйвера → соединение → запрос → обработка результата → **закрытие соединения**. Для многократного анализа прямое соединение сокращает цикл ручного CSV-экспорта (`p0044:c01`–`p0054:c01`).
6. **Учётные данные:** глава показывает буквальные демонстрационные пароли в коде, одновременно предупреждает об их небезопасности (`p0047:c01`–`p0048:c01`, `p0053:c01`). Здесь реальные значения заменяются placeholders, а небезопасные учебные паттерны не предлагаются для эксплуатации.
