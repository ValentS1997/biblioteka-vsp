## Symptom / problem framing

Нужно работать с БД, но неясно, **где писать SQL** и **как подключиться**. Глава предлагает три интерфейса: консоль СУБД, GUI-клиент и встроенный SQL в Python/R. Наличие клиента не равно наличию прав и действующего подключения (`p0033:c01`, `p0040:c01`, `p0044:c01`).

## Interpretation

**Сценарий доступа из главы** (`p0040:c01`–`p0043:c01`):
- CLI → непосредственный текстовый доступ к РСУБД.
- GUI → драйвер → РСУБД; возможность исследовать объекты и писать SQL.
- Python/R → драйвер → РСУБД → результаты/структуры данных.

**Работа аналитика** (`p0044:c01`):
- Однократно: SQL в клиенте → CSV → Python/R.
- Повторяемая аналитика: Python/R подключается к БД → исполняет SQL → обрабатывает результат без промежуточного CSV.

**SQLite:** `sqlite3` без файла и `sqlite3 my_new_db.db` — не одинаковые сценарии сохранения (`p0036:c01`).

## Modifying action

Учебная пара **`CREATE TABLE test (...)`** и **`INSERT INTO test ...`** (`p0036:c01`–`p0039:c01`) изменяет БД и требует отдельной тестовой базы и разрешения. `CREATE DATABASE my_new_db;` (`p0042:c01`) создаёт БД. `sqlite3 my_new_db.db` использует файловую БД, запуск может изменить файловое состояние. `pip install`, `conda install`, `brew install` и R `install.packages()` модифицируют среду. Исполнение здесь **не выполнялось**.

**Риск:** изменение схемы/данных, создание файлов, установка зависимостей, доступ к неверной БД, раскрытие учётных данных. **Rollback:** [Needs confirmation]; глава не задаёт безопасный универсальный план отката для всех этих операций. Не предлагать произвольный `DROP` как «универсальный rollback».
