## Symptom / problem framing

Задача главы — быстро отличать хранилище данных от языка обращения к нему, понимать разницу между SQL-запросом и более общим SQL-оператором, читать простые запросы и распознавать связь таблиц. Частые проблемы: путаница `SQL` и `PostgreSQL`, копирование синтаксиса другой РСУБД, смешение порядка записи с логическим порядком обработки (`p0023:c01`, `p0024:c01`, `p0029:c01`).

## Read-only checks

Выполнение **не производилось**; команды показывают авторскую форму запроса на чтение. Целевые таблицы и права: [Needs confirmation].

```sql
SELECT * FROM my_table;
```

Прочитать все столбцы/строки таблицы `my_table` (`p0027:c01`).

```sql
SELECT *
FROM my_table
WHERE column1 > 100
ORDER BY column2;
```

Отфильтровать строки по `column1` и отсортировать результат по `column2` (`p0028:c01`).

**Проверка понимания без изменения БД:** найти в тексте оператора источник данных `FROM`, фильтр `WHERE`, критерий сортировки `ORDER BY` и сопоставить с моделью данных. Факт работы запроса на вашей РСУБД: [Needs confirmation].

## Interpretation

**Порядок написания** (`p0028:c01`):

`SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY`

**Логический порядок обработки в книге** (`p0029:c01`, `p0030:c01`):

`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`

- `FROM` — собрать исходные данные.
- `WHERE` — фильтровать строки.
- `GROUP BY` — группировать строки.
- `HAVING` — фильтровать группы.
- `SELECT` — определить выводимые столбцы.
- `ORDER BY` — отсортировать результат.

**Две таблицы в модели** (`p0031:c01`, `p0032:c01`): `Students.student_id` — PK; `Grades.student_id` — FK; связь `Students (1) → Grades (много)`. Точный графический вид рис. 1.3 не восстановлен (см. `source-findings.md`).
