# Chapter 2 cheatsheet — «Переводы»

## Symptom / problem framing

Проблема, которую описывает глава: технический английский может быть барьером для
изучающих программирование. Переводы уменьшают этот барьер и делают учебный материал
доступнее для локальных сообществ.

## Baseline / context

- Глава содержит 22 пронумерованных языковых направления в разделе 2.1.
- Статусы различаются: где-то перевод завершён или доступен, где-то только начат или
  находится в процессе.
- Работа в ряде случаев ведётся несколькими добровольцами совместно.
- Источник содержит исторические даты и ссылки; их современная актуальность
  [Needs confirmation] в режиме `rag_only`.

## Read-only checks

Перед тем как начинать или помогать переводу, по логике главы проверить:

1. Есть ли уже запись для нужного языка.
2. Есть ли названный переводчик/команда.
3. Указан ли статус: доступен, завершён, начат, в процессе.
4. Есть ли связанная страница/контакт в RAG.
5. Нет ли уже нескольких параллельных переводов.
6. Нет ли source finding, из-за которого имя/URL нельзя безопасно нормализовать.

## Interpretation

- Наличие существующей работы — сигнал сначала рассмотреть участие в ней, а не
  автоматически начинать новый перевод.
- Ценность перевода в главе связана с доступностью обучения для людей, которым
  технический английский мешает освоению Python.
- Истории переводчиков показывают распределённую volunteer-модель: преподаватели,
  студенты, разработчики и локальные сообщества создают языковые версии.
- Статусы в главе исторические и не являются текущим live-registry переводов.

## Next action

Если читатель хочет помочь с переводом, источник предлагает:

1. просмотреть существующий список волонтёров/переводов для нужного языка;
2. решить, начинать ли новый перевод или помогать существующему;
3. если начинается новый перевод — прочитать инструкцию по переводу.

## Modifying action

Перевод текста — содержательная модификация производного материала, но глава не даёт
Git/репозиторных команд, формата patch или процедуры публикации.

Effect: создаётся или изменяется языковая версия книги.

Risk: параллельная/дублирующая работа, несогласованность с существующим переводом.

## Verification / acceptance checks

После главы можно проверить понимание следующими source-grounded вопросами:

- почему автор предлагает сначала изучить существующие переводы и волонтёров;
- какие виды статуса перевода встречаются;
- почему участники считают локализацию полезной для начинающих;
- какое правило дано для восстановления замаскированных e-mail адресов;
- почему точные URL из RAG нельзя автоматически считать исправленными/актуальными.
