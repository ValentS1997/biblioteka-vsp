## Source type matters

- **Textbook / tutorial:** broad conceptual reinforcement.
- **Standard:** authoritative interface definition; POSIX is the chapter's explicit example.
- **Implementation internals:** useful when moving from abstractions to actual kernel structures and algorithms.
- **Classic paper / survey:** useful for a narrow mechanism, historical context or research problem.
- **Design essay / experience report:** useful for architecture, engineering tradeoffs and project lessons.

## How to use the chapter

1. Choose the knowledge gap, not the most famous title.
2. Use a broad text for conceptual gaps.
3. Use a standard when exact API semantics matter.
4. Use internals books when implementation detail is the goal.
5. Use papers/surveys when narrowing onto one mechanism or research question.
6. Treat listed editions and venue timing as source-era information until independently verified.
