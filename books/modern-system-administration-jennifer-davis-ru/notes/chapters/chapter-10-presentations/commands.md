## Исторический пример, а не инструкция для запуска

Перенос клиентских NoSQL-таблиц (PDF 124–127): автор описывает копирование таблицы, отслеживание копии, ожидание переключения клиента на новую конечную точку, изменение региональной конфигурации, отключение серверов и уведомление SiteOps. Эти действия **state-changing** и способны повлиять на доступность и данные. Готовых команд, схем консистентности, полномочий, проверки корректности миграции и **rollback нет — [Needs confirmation]**. Их нельзя исполнять, опираясь только на главу.

При изменении визуальных элементов (цвет, размер, форма, оси, аннотации) меняется интерпретация, а не обязательно состояние инфраструктуры. Проверять корректность источника данных, доступность без цвета и понятность сообщения (PDF 127–133).

**Не дополнять по памяти модели:** команды `perl`, `node`, API endpoints, реальные учетные данные, D3.js исходник, маршрутизация трафика и команды остановки серверов — всё **[Needs confirmation]**.
