# Глава 8. Безопасность инфраструктуры

Книга: **Дженнифер Дэвис — «Современное системное администрирование»**, часть II «Методы»; русское издание БХВ-Петербург, 2024.

## Суть главы

Инфраструктурная безопасность — защита оборудования, программного обеспечения, сетей и данных от повреждения, хищения и несанкционированного доступа. Автор не обещает полной защиты: предлагает **уменьшать риск посредством распределённой ответственности, моделирования угроз, многоуровневой защиты и раннего участия в архитектурных решениях**. Классификация уязвимостей и единый язык КЦД (конфиденциальность, целостность, доступность) помогают командам согласовывать приоритеты.

## Структура главы

1. **Что такое безопасность инфраструктуры** (PDF 100–101): защита ресурсов, невозможность абсолютной безопасности, работа с риском и обратной связью.
2. **Распределяйте обязанности по обеспечению безопасности** (PDF 101–102): инфраструктура/платформа/функция как сервис, зоны ответственности клиента и провайдера, уведомления и эскалация; рис. 8.1.
3. **Оценивайте безопасность с точки зрения злоумышленника** (PDF 102–104): угрозы, активы, векторы входа, злоумышленники, мотивы, ресурсы и окно возможностей; инструменты NIST/CVSS, Microsoft Threat Modeling Tool, PASTA и OWASP.
4. **Проектирование с учётом обеспечения безопасности** (PDF 105–106): defense in depth, zero trust, ранняя проверка архитектуры, пример незащищённого MySQL; триада КЦД и OWASP ASVS.
5. **Классификация обнаруженных проблем** (PDF 106–107): CVE, ошибки реализации против дефектов проектирования; примеры Heartbleed, EternalBlue, Dirty COW, Meltdown, KRACK.
6. **Заключение** (PDF 108): сотрудничество, снижение угроз, архитектурные меры и контекст для определения приоритетов.
