# Глава 2. Вычислительные среды

Книга: Дженнифер Дэвис, «Современное системное администрирование» (БХВ-Петербург, 2024). Инв. № 0011.

**Основной принцип:** выбирать вычислительную среду по характеристикам нагрузки, требованиям приложения и эксплуатационным ограничениям, а не по популярности технологии.

## Выводы для системного администратора

1. Классифицируйте приложение по ресурсу, способному стать ограничением: CPU, память или операции хранения. Это отправная точка, а не универсальный рецепт.
2. Сначала отделите ограничения размещения (собственная площадка, облако, регуляторика, доступное оборудование) от выбора единицы исполнения.
3. При совместном размещении сервисов оцените обмен меньшей сетевой задержки на конкуренцию за CPU/RAM/storage.
4. Выбирайте между функцией, управляемым приложением, контейнером и VM с учетом степени контроля, стоимости эксплуатации, изоляции, старта и переносимости.
5. Не предполагайте, что поставщик отвечает за все: модель сервиса определяет, какой объем среды обслуживает ваша команда.
6. Не оптимизируйте преждевременно: глава допускает достаточное, хотя и не идеальное, решение в рамках бюджета, с последующей корректировкой.

## Ограничения

Глава представляет принципы выбора, но не дает измеренных пороговых значений для CPU, RAM, задержек, стоимости или готовых shell-команд. Их нельзя выдумывать. Конкретные параметры и шаги развертывания требуют подтверждения: **[Needs confirmation]**.

Ни команды провайдеров, ни технические действия изменения инфраструктуры не запускаются этим анализом. Публикация учебных файлов не изменяет `reading/progress.yaml`.
