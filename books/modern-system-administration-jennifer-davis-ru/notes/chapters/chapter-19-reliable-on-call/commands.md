# Инструменты и классы действий — глава 19

**Источник:** canonical RAG PDF **226–240**, чанки `p0226:c01`–`p0240:c01`. `rag_only`: только названные в главе средства, без внешнего CLI.

## Операционная классификация

| Операция | Класс | Эффект / риск / проверка |
|---|---|---|
| Читать политику ротации, маршруты эскалации и журналы | **Read-only** | Сверить ожидания, незавершенные инциденты, резервные контакты (PDF 228–229, 234–235) |
| Наблюдать за опытным инженером (shadowing) | **Read-only / workload-generating** | Передача знаний и нагрузка на сопровождающего (PDF 229) |
| Отправить тестовое оповещение | **Workload-generating** | Проверяет доставку, может вызвать лишнюю эскалацию; согласовать тест и проверку результата (PDF 231) |
| Подтвердить/классифицировать/переадресовать оповещение | **State-changing** | Меняет состояние тикета и маршрут реакции; проверка: нужные коллеги осведомлены; rollback **[Needs confirmation]** (PDF 227, 229, 233) |
| Настроить каналы/эскалацию/повторы/расписание | **State-changing** | Может скрыть критический сигнал либо увеличить нагрузку; проверить тестом; rollback **[Needs confirmation]** (PDF 229–231, 238) |
| Устранить причину инцидента | **State-changing** | Изменяет production систему; книга здесь не дает технических команд, verifications или rollback — **[Needs confirmation]** (PDF 233) |
| Заполнить handoff, обновить документацию, скорректировать alert severity | **State-changing** | Влияет на дальнейшие решения; перепроверить полноту передачи, отсутствие потерянных сигналов; rollback **[Needs confirmation]** (PDF 234–235) |
| Изменить компенсацию или кадровую нагрузку | **State-changing, организационное** | Требует команды/руководства и норм организации; нет универсальных условий/rollback (PDF 228, 233–234, 238–239) |

**Исполняемые команды:** готовых CLI/API команд для Slack, Zendesk, alertmanager, графика дежурств, подтверждения или рестарта сервисов в этой главе **нет**. Привычные команды не добавлены по памяти.

## Значения из текста, не нормативы

- **15 минут на ответ** и повторный звонок через **10 минут** — пример персональной настройки автора, **не общий SLA** (PDF 230).
- Предлагаемые **1 час**, **8 рабочих / 4 внерабочих часа** как условия компенсации/следующего дня — примеры возможной политики, **не универсальное правило** (PDF 233–234).
- **8- или 24-часовая** смена упомянута как один из распространенных вариантов, не обязательный шаблон (PDF 226).
- Точное время, эскалация, компенсация, право на подмену и целевые метрики вашей команды — **[Needs confirmation]**.
