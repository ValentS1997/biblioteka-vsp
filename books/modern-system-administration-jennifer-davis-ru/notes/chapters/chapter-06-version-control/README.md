# Глава 6. Контроль версий

Книга: Дженнифер Дэвис, «Современное системное администрирование». Часть II «Методы».

## Основной принцип

Контроль версий — **метод отслеживания изменений данных и управления ими**. Он распространяется не только на исходные тексты приложений: для системного администратора столь же важны конфигурации, сценарии инфраструктуры, результаты сборок и образы. Цели — восстановимость конфигурации, совместная работа, воспроизводимость и наблюдаемая история решений (RAG PDF 83–88).

## Карта главы

1. **Зачем контроль версий администратору?** (PDF 83). Согласованный способ фиксировать изменения, не полагаться на ручные копии и разрозненные договорённости.
2. **Понятия и уровни** (PDF 83–84). Метод контроля версий; система контроля версий (Git, SVN); размещение у провайдера (GitHub, GitLab, Bitbucket) либо самостоятельно; отдельные системы для бинарных артефактов. Рис. 6.1.
3. **Преимущества** (PDF 85–86). История и версии, контроль доступа, разрешение конфликтов, документирование, воспроизводимость, адаптация команды, видимость и аудит.
4. **Структура инфраструктурных проектов** (PDF 86–87). Монорепозиторий и множество репозиториев: поиск кода, масштаб проектов, версии, зависимости и ответственность команд.
5. **Заключение** (PDF 87–88). Контроль версий как метод управления критически важными инфраструктурными данными.

## Ограничения

Глава не содержит законченной последовательности CLI-команд по настройке Git, созданию репозитория, выпуску версии, восстановлению конфигурации или отмене изменений. Такие процедуры и команды нельзя конструировать на основе общих знаний: **[Needs confirmation]**. Книга описывает выбор практики и её свойства; конкретное развертывание требует отдельного контекста.
