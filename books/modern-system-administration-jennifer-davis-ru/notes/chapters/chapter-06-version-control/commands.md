# Инструменты и команды — глава 6

**Источник:** RAG PDF 83–88 (`p0083-c01` — `p0088-c01`), режим `rag_only`. Эта глава — о методе и архитектурных компромиссах. В ней **нет однозначной пошаговой последовательности Git CLI**: не подставляем `git init`, `git add`, `git commit`, `git checkout`, `git revert` и другие команды по памяти модели.

## Названные в источнике средства

| Инструмент или практика | Классификация | Подтверждённое назначение | Источник |
|---|---|---|---|
| **Git** | Read-only при просмотре; state-changing при изменении истории/содержимого | Распределённая система контроля версий; отслеживание и управление изменениями | PDF 83–84 |
| **Subversion / SVN** | Read-only либо state-changing по операции | Централизованная система контроля версий | PDF 84 |
| **GitHub, GitLab, Bitbucket** | Read-only при обзоре; state-changing при публикации или изменении | Провайдеры решений на основе СКВ | PDF 83–84 |
| **Самоуправляемый сервис** | Workload-generating / state-changing при развёртывании; read-only при просмотре | Способ организации размещения сервиса контроля версий | PDF 84 |
| **Системы управления артефактами** | Read-only при инспекции; state-changing при публикации бинарных артефактов | Управляют хранилищами скомпилированных бинарных файлов | PDF 84 |
| **Artifactory** | Зависит от операции; публикация/удаление — state-changing | Приведён автором как пример имеющегося у организации инструмента | PDF 83 |

Классы обозначают характер **возможных операций**, а не доказательство, что автор привёл конкретные команды для них.

## Подтверждённые действия без синтаксиса CLI

- **Чтение истории изменений и авторства (read-only):** аудит и отслеживаемость, PDF 85–86. Конкретные флаги CLI — [Needs confirmation].
- **Развёртывание определённой версии конфигурации (state-changing / workload-generating):** возможность воспроизводимости, PDF 85. Эффект — изменение управляемой системы, риск — отличия от ожидаемого состояния; команда, верификация и rollback — [Needs confirmation].
- **Внесение изменения в конфигурацию (state-changing):** автор противопоставляет версионирование множеству отдельных `.bak`-копий, PDF 85. Конкретные команды изменения и перезапуска сервиса в RAG не представлены.
- **Настройка прав на просмотр и утверждение (state-changing):** PDF 85–86. Риск — некорректное разграничение доступа; процедура и rollback — [Needs confirmation].
- **Фиксация и документирование выбора структуры репозиториев (state-changing для документа):** PDF 86–87. Требуется учитывать поиск кода, зависимость проектов и взаимодействие команд.

## Безопасность операций

Прежде чем выполнять любую state-changing операцию, необходимы подтверждённые для вашей инфраструктуры: цель, права доступа, последовательность команд, метод проверки и способ возврата. Автор даёт причины и свойства контроля версий, но не универсальный операционный runbook; отсутствующие детали сохранены как **[Needs confirmation]**.
