# Source findings — глава 4 «Сеть»

**Политика:** только RAG; выявленные особенности исходного текстового слоя и неоднозначности не исправляются молча внешними источниками.

## 1. [Source extraction issue] — искажения текстового слоя

- **PDF 64, 66, 70:** в строках колонтитулов встречается `Гпава` вместо последовательного оформления заголовка `Глава`. Эти формы наблюдаются в `p0064:c01`, `p0066:c01`, `p0070:c01`.
- **PDF 71:** в предложении о развитии практик слово извлечено как `ёеѵорз` (`p0071:c01`). Это не используется для подтверждения точного написания термина.
- **PDF 68–69:** встречаются неоднородные латинские/кириллические глифы в технических аббревиатурах (например, `АРІ`, `РоР`); читатель должен сверять точные строки и идентификаторы с оригиналом при цитировании.

**Влияние:** неисправные глифы нельзя преобразовывать в команды, идентификаторы API или числовые данные без проверки. В других файлах применяются однозначно представленные в RAG обычные сокращения CDN, SDN, HTTP/2, QUIC, но это не объявляется исправлением исходного текста.

## 2. [Needs confirmation] — оценка задержки через RTT и размер запроса

**PDF 69, `p0069:c01`:** после таблицы 4.1 с расстояниями, задержками и RTT присутствует предложение, предлагающее умножить RTT на размер запроса. Конкретный алгоритм такой оценки, единицы конечной величины и зависимость от числа сетевых обменов в тексте не раскрыты. В артефактах не вводится выдуманная формула «время = RTT × размер запроса», и табличные значения не объявляются измеренными характеристиками реальной инфраструктуры.

**Классификация:** [Needs confirmation] — математический смысл этой фразы и практическое использование требуют отдельной проверки исходного замысла; во время RAG-only анализа такое решение не выносится.

## 3. [Needs confirmation] — описание southbound/northbound API

**PDF 68, `p0068:c01`:** в описании SDN указано, что southbound API используются для передачи информации к сетевым устройствам, а northbound API — для передачи сведений о состоянии контроллеру. Это сохранено как формулировка главы. Направления и интерфейсы конкретной реализации не выводятся из внешних знаний; `diagram.md` использует общую схему контроллера и устройств без подстановки непроверенной семантики обоих API.

**Действие:** не исправлять текст источника молча; при подготовке практического проекта сверить с документацией выбранного SDN-контроллера. В этом артефакте внешняя документация не использовалась.
