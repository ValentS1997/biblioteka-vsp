# Глава 13. Обеспечение безопасности инфраструктуры

**Книга:** Дженнифер Дэвис, «Современное системное администрирование», русское издание БХВ-Петербург (2024), часть III «Сборка системы».

## Главная идея

Обеспечение безопасности — повседневная часть системного администрирования независимо от наличия отдельной роли ИБ. **Не существует единственной меры защиты:** нужно оценить пути атаки на всех этапах сборки и доставки, затем постепенно ограничивать риски для учётных данных, секретов, вычислительных ресурсов и сетевого взаимодействия. Автор предлагает не полный security framework, а практичный способ выбрать **небольшие достижимые цели** (RAG PDF 157, 170–171).

## Приоритеты защиты

1. **Идентификационные данные и доступ**: назначать минимальные права на требуемую работу, проверять MFA, отдельно учитывать служебные учётные записи и доступ к API (PDF 159–162).
2. **Секреты и следы их использования**: не держать секреты в коде/репозитории и открытых журналах; предусмотреть ротацию, отзыв, изоляцию, шифрование, аудит и доступность хранилища (PDF 162–165).
3. **Вычисления и сеть**: контролировать конфигурацию ОС и приложений, проверять совместимость обновлений, не доверять только внутренней сети, ограничивать каждый поток по политике (PDF 165–169).
4. **Проверяемый инфракод**: автоматизировать требования безопасности, искать ошибочные настройки статическими анализаторами, сканировать Git на секреты, делать политики наблюдаемыми (PDF 169–170).

Авторский пример Terraform для Google Cloud Storage имеет повреждённый при извлечении идентификатор поля, поэтому в [commands.md](commands.md) он сохранён **как доказательство наличия примера, не как готовая конфигурация**. Результаты Checkov относятся только к конкретному примеру из текста (PDF 169–170).
