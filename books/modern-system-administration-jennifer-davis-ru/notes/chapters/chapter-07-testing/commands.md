# Инструменты, синтаксис и классификация — глава 7

**Источник:** только RAG PDF 89–99. Глава преимущественно концептуальная; команды запуска конкретных систем тестирования не приведены. Ничего не дополняется по памяти модели.

## Пример 7.1 — настройка RuboCop

**RAG PDF 91 (`p0091:c01`)** описывает файл `rubocop.yml` и предел в 100 символов. В текстовом слое извлечён фрагмент:

```text
Metrics/LineLength:  Max:  100
```

**Классификация:** изменение конфигурационного файла — **state-changing**. Предполагаемое назначение — установить порог длины строки; риск — правила могут не соответствовать практикам команды, а структура YAML могла быть утрачена при извлечении.

**Проверка:** автор рекомендует сначала просмотреть предупреждения и согласовать правила команды. Достоверно восстановленная многострочная YAML-форма, команда применения и rollback: **[Needs confirmation]**. **Не использовать извлечённую строку как готовую конфигурацию** без сверки с источником.

Связанная фраза о предупреждении для строк *менее* 100 символов расходится с контекстом максимальной длины и вынесена отдельно в `source-findings.md`, без исправления по догадке.

## Поддержанные виды испытаний без конкретных CLI-команд

- **Исследовательское тестирование** в непроизводственной среде: workload-generating, иногда state-changing относительно тестовой среды; эффект — исследование поведения, риск — ошибочное перенесение выводов на production (PDF 89).
- **Модульный тест** изолированного участка: workload-generating в среде выполнения; проверяет ожидаемые свойства написанного кода, а не его внешние зависимости (PDF 92).
- **Интеграционная проверка** развертывания и соединения с БД: workload-generating / state-changing в эфемерной тестовой среде; время, сложность и внешние зависимости больше, чем у unit-тестов (PDF 93).
- **E2E** с реалистичными тестовыми данными: workload-generating / state-changing при создании временных экземпляров; ограниченная локализация сбоя (PDF 93).
- **Многодневное моделирование нагрузки:** workload-generating, может потребовать существенных ресурсов; уместность зависит от срока жизни системы (PDF 98).

Для всех state-changing операций точные команды, критерии остановки и rollback на конкретной инфраструктуре — **[Needs confirmation]**, если источник их не задаёт. Нельзя конструировать CI pipeline и пороги метрик из общих знаний.
