# Глава 11. Разработка сценариев инфраструктуры

**Книга:** Дженнифер Дэвис, «Современное системное администрирование» (русское издание БХВ-Петербург, 2024), часть III «Сборка системы».

## Ключевая идея

**Инфраструктура как код (инфракод, Infrastructure as Code)** позволяет описывать оборудование, программное обеспечение и сетевые ресурсы в форме, понятной людям и компьютерам, чтобы управлять ими согласованно, повторяемо и прозрачно. Выбор автоматизации должен исходить из потребностей организации, конкретного рабочего процесса и людей, которые его поддерживают, а не из убеждения, что один инструмент должен решать всё (PDF 135–144).

## Две важные оговорки автора

1. **Автоматизированная конфигурация может быть неверной.** Синтаксически корректное описание DNS-записей не предотвращает нарушение доставки почты из-за забытых SPF/DKIM; повторное развёртывание ошибочной конфигурации не решает эту проблему (PDF 141).
2. **Инфракод не должен быть монолитной технологией.** Приведён допустимый комбинированный подход: Packer для образов, Terraform для определённых ресурсов, Terraform вместе с Chef для более долговечных экземпляров (PDF 143–144). Конкретная технологическая связка — пример, не предписание для любой среды.
