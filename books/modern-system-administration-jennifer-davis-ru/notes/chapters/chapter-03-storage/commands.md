# Инструменты и команды — глава 3 «Хранилище»

**Источник:** RAG PDF 48–62; никакие команды не добавлены по памяти. Эта глава прежде всего концептуальная. Подтверждено явное упоминание утилиты `iostat`; **флаги, аргументы, установки и интерпретация конкретных полей в книге не приведены**. [PDF 52]

## Подтвержденный CLI

| Команда ровно в форме из RAG | Категория | Для чего упоминается | Влияние и ограничения |
|---|---|---|---|
| `iostat` | **Read-only** (средство наблюдения) | Средство оценки производительности хранения в Linux; автор предлагает инструменты измерения для оптимизации характеристик. [52] | Не изменяет хранилище в описанной роли. Конкретный синтаксис, перечень метрик и пороговые значения: **[Needs confirmation]**. |

`iostat` в книге упомянута как пример утилиты, но готовой тестовой команды или выводов автор не приводит. Не следует выдавать `dd`, `fio`, `lsblk`, `mkfs`, `mount`, `cryptsetup`, `rsync` или команды провайдеров за команды данной главы: **RAG не подтверждает эти вызовы**.

## Технологии, не являющиеся подтвержденными командами главы

| Технология/сервис | Описанная роль | Категория практического действия |
|---|---|---|
| RAID, SAN | Объединение блочных ресурсов и сети хранения. [52] | **State-changing** при конфигурации массива/сети; последствия, команды, rollback: **[Needs confirmation]** |
| NFS, Samba | Сетевые файловые ресурсы. [53] | **State-changing** при настройке/монтировании; права и процедура отката: **[Needs confirmation]** |
| Amazon EBS / EC2 | Пример сопоставления IOPS, емкости, пропускной способности и задержки (таблица историческая). [51–52] | **Read-only** при сравнении; **state-changing** при изменении томов (конкретного CLI нет) |
| Redis, Amazon DynamoDB | Примеры хранилищ ключ–значение. [55] | **State-changing** при изменении данных/службы; команды не даны |
| Neo4j, AWS Neptune | Примеры графовых БД. [56] | **State-changing** при изменении графовых данных/службы; команды не даны |
| Apache Cassandra, Apache HBase | Примеры хранилищ с широкими столбцами; обсуждение компромиссов согласованности. [55–56] | **State-changing** при конфигурации или записи; настройки и rollback: **[Needs confirmation]** |
| CDN, облачные «холодные» уровни | Распределение контента, снижение стоимости редко используемых данных. [58] | **State-changing** при репликации/переносе; проверять географию, задержку, стоимость |

## Разграничение действий

- **Read-only:** инвентаризация типов данных, анализ требований к емкости/IOPS/задержке, `iostat`, просмотр параметров предложения хранилища. [50–52, 56–58]
- **Workload-generating:** нагрузочное измерение или моделирование восстановления может порождать нагрузку; глава **не дает исполнимых команд** и конкретной тестовой нагрузки. [52, 61]
- **State-changing:** создание и перенос томов, репликация, удаление/агрегация, шифрование, изменение прав, восстановление. Эти действия могут повлиять на доступность, стоимость, сохранность и безопасность; **исполняемых процедур и rollback в RAG нет**. [57–62]

**Правило:** сначала подтверждать требования и последствия, затем планировать отдельное управляемое изменение. Исторические характеристики Amazon EBS в книге не считать текущей конфигурационной рекомендацией. См. `source-findings.md`.
