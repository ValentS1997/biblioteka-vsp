# Глава 15. Мониторинг вычислительной инфраструктуры и программного обеспечения на практике

**Книга:** Дженнифер Дэвис, «Современное системное администрирование» (БХВ-Петербург, 2024), часть IV «Наблюдение за системой». Inventory `0011`.

## Главная идея

Начинать нужно **не с перечня метрик или выбора продукта**, а с желаемых результатов мониторинга: какие проблемы пользователей, команды и сервиса необходимо обнаруживать и решать. Мониторинг внедряется небольшими последовательными изменениями, а сигналы, SLI, SLO, уведомления и инструменты выбираются исходя из эффекта для конкретной системы (PDF 182–186, 189–194).

## Рабочая модель главы

1. Сформулировать проблему и ожидаемый результат **со стороны пользователя или работы команды** (PDF 182–185).
2. Инвентаризировать текущую архитектуру, инструменты, ограничения доступа к данным и уже имеющиеся сигналы (PDF 185–188).
3. Выбрать применимые сигналы: **RED** для сервисного поведения, **USE** для ресурсов; дополнить их под среду (PDF 185–188).
4. Выбрать SLI, измеряющие эффект для пользователей; сформулировать достижимый SLO. В книге приведён **иллюстративный**, а не универсальный пример: 99% успешных веб-запросов быстрее секунды (PDF 189–190).
5. Переосмыслить alerting: уведомлять об actionable воздействии на пользователей, исключать дублирование и повышать качество информации для дежурного (PDF 187, 189–190).
6. Сравнить инструменты по нужной функции, а не популярности, стоимости внедрения в отрыве от эксплуатации или маркетингу (PDF 190–193).
7. Внедрять поэтапно и пересматривать результаты; мониторинг не имеет конечной «окончательной настройки» (PDF 184–185, 194).
