# Глава 12. Управление инфраструктурой

**Книга:** Дженнифер Дэвис, «Современное системное администрирование», русское издание (БХВ-Петербург, 2024), часть III «Сборка системы».

## Главный тезис

Управление инфраструктурой требует не разрозненных сценариев, а **устойчивых командных процессов**: инфракода, версионного контроля, проверки изменений, тестирования, автоматизированной доставки и наблюдения за результатом. Автор сопоставляет модели **Infrastructure as Code (IaC)** и **Infrastructure as Data (IaD)**, рассматривает GitOps и рекомендует **поэтапно улучшать конкретные рабочие процессы**, не автоматизировать всё ради самой автоматизации (RAG PDF 145–156).

## Существенные различия

**IaC — не IaaS.** IaC обозначает применение методов разработки ПО к описанию и управлению инфраструктурой, а IaaS — сервисную модель облачного поставщика (PDF 145, 149).

**IaD не требует отказаться от IaC.** Модель инфраструктурных данных делает явными важнейшие ресурсы, метаданные и изменения; код и данные рассматриваются как взаимодополняющие описания (PDF 150).

**GitOps не волшебная замена процессам.** В главе это набор принципов версионированного декларативного состояния и непрерывной сверки, объединяющий более ранние практики IaC и IaD; пользу необходимо оценивать в своей организации (PDF 150).
