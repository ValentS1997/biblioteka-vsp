2.3. Тестирование      135

  Как и в предыдущем случае, мы получили сообще
ние, что функция не прошла тестирование. Кроме того,
по результатам теста изменится внешний вид дерева
тестов проекта: непройденные будут подсвечены
(рис. 2.18).
   Создавая тест для того или иного функционала,
старайтесь максимально проверять работоспособность
этого элемента, подавая на вход различные значения
и проверяя граничные случаи.                                Рис. 2.18. Тесты, доступные в проекте

2.3.2. Написание табличных (Table-Driven) тестов в Go
Такой вид тестирования очень похож на предыдущий, за исключением того, что из
начально разработчик формирует таблицу из подаваемых на вход значений и того,
что ожидается на выходе по завершении работы функции. Этот подход позволяет
протестировать несколько комбинаций входных данных с ожидаемыми выходными
значениями тестируемой функции:

   // baseURL/part_2/2.3/2.3.2/golang/testing/test/calculator_test.go
   package test_test

   import (
       calc "golang/testing/calculator"
       "testing"
   )

   type testData struct {
       arg1, arg2, expected int
   }

   func TestAdd(t *testing.T) {
       cases := []testData{
           {2, 3, 5},
           {10, 5, 15},

       for _, it := range cases {
           result := calc.Add(it.arg1, it.arg2)
           if result ! = it.expected {
               t.Errorf("result %d, expected %d", result, it.expected)
           }
       }
   }
