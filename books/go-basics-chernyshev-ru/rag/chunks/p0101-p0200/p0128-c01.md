   Каталог utils может содержать сколько угодно файлов, но все они должны
входить в пакет utils, то есть начинаться со строки package utils. Иначе говоря,
имя каталога, в котором будут храниться файлы пакета, задает имя самого пакета.
Это негласное правило. Единственное место в проекте, где оно не действует, —
корневой каталог. Здесь имя пакета может совпадать с именем каталога, либо же
пакет может носить имя main. В первом случае проект будет считаться служебным
модулем, а во втором — исполняемым.
  В Go действует еще одно ограничение: несмотря на наличие в пакете нескольких
файлов, в нем не должно быть ни одной глобальной переменной, функции и так да
лее с одинаковыми именами! Иначе это приведет к ошибке при сборке приложения.

2.2.7. Именование пакетов и нюансы их импортирования
Имя пакета должно состоять только из букв и цифр. Никакие другие символы
не приемлемы! Но иногда одного слова недостаточно при объявлении имени ката
лога, в котором будет находиться создаваемый пакет. Либо же возникает необходи
мость нарушить правило, что пакет должен называться как каталог, в котором он
создается, или имя импортируемого пакета слишком громоздкое. В этих случаях
можно использовать псевдонимы.
   Создадим новый каталог another_package и добавим в него файл mypack.go со
следующим кодом:

   // baseURL/part_2/2.2/2.2.7/golang/first/another_package/mypack.go
   package mypack

   func Add(a, b int) int {
       return a + b
   }
   Обратите внимание на имя пакета! Оно кардинально отличается от имени ка
талога, и поэтому в файл main.go он должен импортироваться совершенно иначе,
