2.3. Тестирование      139

  Но одно дело — узнать, на сколько процентов пакет по
крыт тестами, и совсем другое — понять, тесты для какой
функциональности еще предстоит написать. Вторым мы
сейчас и займемся. Введите в терминале команду:

   go test ./... -coverprofile="coverage.out"
которая сформирует в корневой директории файл cove
rage.out, хранящий информацию о тестовом покрытии
пакетов (рис. 2.22).
                                                                        Рис. 2.22. Текущее состояние   Теперь посмотрим в браузере, какие функции не по
                                                                                   структуры проектакрыты тестами. Для этого выполните команду:

   go tool cover -html="coverage.out"
   Результат ее выполнения показан на рис. 2.23.

                        Рис. 2.23. Визуализация информации о тестовом покрытии

  Пока объем кода невелик, размещение тестов и основного кода проекта в одном
пакете облегчает контроль тестового покрытия. Но при увеличении сложности
программного обеспечения, самой структуры проекта и кодовой базы тесты лучше
вынести в отдельный пакет.
