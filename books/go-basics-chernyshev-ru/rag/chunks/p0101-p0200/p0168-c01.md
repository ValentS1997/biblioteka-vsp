  Иногда переопределяемые методы продолжают работать с методом базовой
структуры. Например, использовать в ходе своей работы возвращаемый ей резуль
тат. Перепишем метод из файла rectangle.go так:

   func (r *Rectangle) GetName() string {
       return "Super-puper " + r.shape.GetName()
   }

  И заново запустим код исполняемого пакета:

   // baseURL/part_3/3.6/golang/factory/main.go
   package main

   import (
       "fmt"
       "golang/factory/shape"
   )

   func main() {
       rectangle := shape.NewRectangle(10, 6, shape.Point{X: 6, Y: -8}, "Gold")

       fmt.Printf("%+v\n", *rectangle)
       fmt.Printf("%+v\n", rectangle.GetName())
   }
   /*{shape:{name:Rectangle center:{X:6 Y:-8} color:Gold} width:10 length:6}
   Super-puper Rectangle */
  На самом деле нельзя сказать, что мы переопределили метод. Просто при об
ращении к методу с таким именем Go сначала искал его среди методов, связанных
с производной структурой Rectangle, и, не найдя его там, переключался на методы
вложенной анонимной структуры (базовой структуры shape).

3.7. Интерфейсы и полиморфизм времени исполнения

Полиморфизм бывает двух видов: статический и динамический. Статический ис
пользуется для перегрузки методов и функций, а также при написании обобщен
ного кода, на этапе компиляции приложения. Перегружать методы в Go нельзя,
а перегрузка функций поддерживается только на уровне, когда у функции есть
аргумент, указывающий на то, что на вход может подаваться различное количество
переменных (например, func myFunc(values ...int) (sum int)).
  Что касается динамического полиморфизма, то он реализуется с помощью ин
терфейсов (переопределение метода из примера в разделе 3.6 тоже можно отнести
к динамическому полиморфизму). Интерфейс позволяет сделать только объявле
ние методов, без их реализации. Такие методы называются чисто виртуальными,
а объявлять их реализацию должны структуры, которые будут реализовывать
интерфейс. Это поведение дает возможность приводить структуры к интерфейсу,
