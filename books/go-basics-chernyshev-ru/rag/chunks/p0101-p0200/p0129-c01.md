128       Глава 2   Функции, модули, пакеты и их тестирование

       mypack "golang/first/another_package"
       "golang/first/utils"

       "github.com/google/uuid"
   )

   func main() {
       firstUUID := uuid.New()
       fmt.Println(utils.ReplaceSymbols(firstUUID, "–", ""))
       // 6f2356bb85a54c2581d11656a3b25794
       print(mypack.Add(4, 7)) // 11
   }
  Даже если мы заменим в коде псевдоним mypack на другой, это не будет счи
таться ошибкой. Кроме того, псевдонимы можно задавать любым импортируемым
пакетам:

   // baseURL/part_2/2.2/2.2.7/golang/first/main.go
   package main

   import (
       f "fmt"
       pack "golang/first/another_package"
       u "golang/first/utils"

       id "github.com/google/uuid"
   )

   func main() {
       firstUUID := id.New()
       f.Println(u.ReplaceSymbols(firstUUID, "–", ""))
       print(pack.Add(4, 7))
   }
   // 45f09a89584b4f66936cf3368e3f634b
   // 11
   Такой способ импортирования пакетов позволяет избежать всех трудностей,
которые могут возникнуть при их создании и использовании: несоответствие имени
пакета имени каталога, громоздкое имя пакета, у нескольких внешних зависимостей
совпадает имя пакетов и т. д.

2.2.8. Создание и импортирование локального модуля
Разберем такую ситуацию: модуль, выступающий в качестве внешней зависимости
в проекте, располагается локально на компьютере и разработчик не имеет возмож
ности или желания выкладывать его в публичный репозиторий. Чтобы подключить
такой локальный модуль, потребуется в каталог golang, созданный ранее, добавить
папку second и открыть ее в VS Code (через меню FileOpen Folder (ФайлОткрыть
папку)).
   Создаваемый модуль будет служебным, и в дальнейшем мы подключим его
к предыдущему проекту — исполняемому модулю first. Но для начала инициа
лизируем новый модуль, введя в терминале:

   go mod init golang/second
