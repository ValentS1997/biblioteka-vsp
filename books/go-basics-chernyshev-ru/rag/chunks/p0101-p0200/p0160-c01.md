3.1. Тип данных Struct      159

   func main() {

       myShape := shape.Shape{
           Name:   "Cube",
           Center: shape.Point{X: 4, Y: 5},
       }

       myShape1 := shape.Shape{"Triangle", shape.Point{1, 9}}

       fmt.Printf("%+v\n", myShape) // {Name:Cube Center:{X:4 Y:5}}
       fmt.Printf("%+v\n", myShape1) // {Name:Triangle Center:{X:1 Y:9}}
       myShape.Center.Y = 2
       myShape.Name = "Circle"
       fmt.Printf("%+v\n", myShape) // {Name:Circle Center:{X:4 Y:2}}
   }

  Добавим в структуру Shape приватное поле:

   type Shape struct {
       Name   string
       Center Point
       color string
   }

   Первая же ошибка в коде после таких изменений будет в этой строке:

   myShape1 := shape.Shape{"Triangle", shape.Point{1, 9}}
   // too few values in struct literal
  Она связана с тем, что используется позиционный формат инициализации и у нас
нет возможности при создании переменной инициализировать добавленное новое
поле, так как оно считается приватным. Если используется именованный формат
инициализации (с помощью литералов) создаваемой структуры, то полю color
будет присвоено текстовое значение по умолчанию:

   func main() {
       myShape := shape.Shape{
           Name:   "Cube",
           Center: shape.Point{X: 4, Y: 5},
           // color: "Gold" // приведет к ошибке
       }
       fmt.Printf("%+v\n", myShape) // {Name:Cube Center:{X:4 Y:5} color:}
   }
   Теперь попробуем явным образом обратиться к приватному полю, что приведет
к следующей ошибке:

   func main() {
       myShape := shape.Shape{
           Name:   "Cube",
           Center: shape.Point{X: 4, Y: 5},
       }
       myShape.color = "Blue" // error: myShape.color undefined
   }
  Именно так в Go работает механизм сокрытия — доступность определяется
регистром первых букв структур и их полей, функций, констант и глобальных
переменных, определенных в пакете, импортируемом в проект.
