Глава 3
ОБЪЕКТНО-ОРИЕНТИРОВАННОЕ
ПРОГРАММИРОВАНИЕ В GO

Go не совсем объектно-ориентированный язык программирования (ООП)
в привычном понимании этого подхода. Но это совершенно не означает, что
Go не поддерживает такие базовые концепции ООП, как инкапсуляция, насле
дование и полиморфизм. Они просто реализованы в нем несколько иначе. Эти
концепции присущи не только ООП-языкам и использовались задолго до их
появления.
  В классическом ООП основой выступает класс, который представляет собой
описание объекта предметной области и инкапсулирует в себе его состояние
(переменные класса) и поведение (методы класса). В Go за состояние отвеча
ют структуры, а поведение реализуется методами, которые можно назначать
именованным типам, поддерживая их инкапсуляцию (объединение) на уровне
пакета. В целом, вне зависимости от языка программирования, при разработке
сложного ПО на первый план всегда выходит абстракция. И чем быстрее разра
ботчик начнет использовать абстракции более высокого уровня, тем проще будет
вносить функциональные изменения и поддерживать программное обеспечение
и тем больше возможностей появится для реализации сложных архитектурных
решений.

3.1. Тип данных Struct

Структура представляет собой набор из полей, объединяющий разные типы данных.
Если в ООП класс описывает сущность, включающую состояния и поведение, то
в Go структура используется только для описания и хранения состояния объекта
предметной области.
  Обобщенный формат объявления структуры выглядит так:

   type имяСтруктуры struct {
       имяПоля1 типПоля1
       имяПоля2 типПоля2
       ...
   }
