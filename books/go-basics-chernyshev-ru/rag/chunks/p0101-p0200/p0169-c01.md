что в процессе приведения сработает механизм сокрытия, сделав недоступными
обычные (не интерфейсные) методы структуры. В Dart, Java и прочих объектно-
ориентированных языках программирования можно явно указать, что класс реа
лизует интерфейс. Благодаря этому компилятор не даст собрать приложение, если
в классе нет переопределенных методов интерфейса. Но в Go все совсем не так.
Задача помнить о том, какие виртуальные методы реализованы методами той или
иной структуры, целиком ложится на разработчика.
  Однако хватит теории. Приступим к написанию кода. Для начала в каталоге
shape нужно создать еще два файла: ishape.go и triangle.go:

   factory
   ├── shape/
   │      ├── ishape.go
   │      ├── rectangle. go
   │      ├── shape. go
   │      └── triangle. go
   ├── go.mod
   └── main.go
  В файле ishape.go объявим несколько интерфейсов, которые будут реализовы
вать методы структур Rectangle и Triangle:

   // baseURL/part_3/3.7/golang/factory/shape/ishape.go
   package shape

   type IShape interface {
       GetArea() float64
       GetPerimeter() uint
       MoveCenter(point Point)
       GetCenter() Point
   }

   type IShapeArea interface {
       GetArea() float64
   }

   type IShapePerimeter interface {
       GetPerimeter() uint
   }
   Поскольку площадь треугольника не целочисленная, то возвращаемый тип
данных метода GetArea() структуры Rectangle необходимо изменить так:

   // baseURL/part_3/3.7/golang/factory/shape/rectangle.go
   func (r *Rectangle) GetArea() float64 {
       return float64(r.length * r.width)
   }
