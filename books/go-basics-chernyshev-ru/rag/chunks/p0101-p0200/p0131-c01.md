130       Глава 2   Функции, модули, пакеты и их тестирование

  Служебный модуль second готов! Закрываем текущую папку в VS Code (FileClose
Folder (ФайлЗакрыть папку)) и открываем предыдущий проект — исполняемый
модуль first. После чего перейдем в файл go.mod и добавим следующие строки:

   // baseURL/part_2/2.2/2.2.8/golang/first/go.mod
   module golang/first

   go 1.24

   replace golang/second => ../second // путь относительно текущей директории проекта

   require golang/second v0.0.0–00010101000000–000000000000

   require github.com/google/uuid v1.6.0
  Если вы используете для хранения внешних зависимостей каталог vendor, то
в терминале придется повторно выполнить эту команду:

   go mod vendor
   Далее перейдем в файл main.go и организуем импорт и использование функций
из нашего локального модуля:

   // baseURL/part_2/2.2/2.2.8/golang/first/main.go
   package main

   import (
       f "fmt"
       pack "golang/first/another_package"
       u "golang/first/utils"

       "golang/second"

       id "github.com/google/uuid"
   )

   func main() {
       firstUUID := id.New()
       f.Println(u.ReplaceSymbols(firstUUID, "–", ""))
       f.Println(pack.Add(4, 7))
       f.Println(second.AddInt(3, 5))
       f.Println(second.DivFloat(54.48, 3.66))
   }
   // 8912acef6d3d40aa94f21333faa1c679
   // 11
   // 8
   // 14.885245901639342
  Если локальный модуль, выступающий в качестве внешней зависимости, на
ходится довольно далеко от текущей директории проекта, то путь к нему можно
задать явно (относительно корневой директории операционной системы):

   module golang/first

   go 1.24

   // в моем случае путь такой
   replace golang/second => E:\code\golang\second

   require golang/second v0.0.0–00010101000000–000000000000
   require github.com/google/uuid v1.6.0
