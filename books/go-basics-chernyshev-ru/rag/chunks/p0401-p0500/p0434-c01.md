8.5. Пример реализации REST API веб-сервиса      433

   Результат показан на рис. 8.10.

                                    Рис. 8.10. Созданный документ

  Нажмите Ctrl+S и сохраните файл под именем todo-service-api.yaml в дирек
тории проекта.
   Теперь приступим к формированию спецификации API разрабатываемого
сервиса. Я хочу показать различные нюансы OpenAPI 3, поэтому она специально
будет не соответствовать лучшим практикам REST API.

   Документ спецификации OpenAPI 3 состоит из нескольких разделов:
   yy info (заголовок) — описание, версия разрабатываемого API и т. д.;
   yy path (путь) — здесь прописываются URL доступа к ресурсам;
   yy components (компоненты) — элементы для хранения различных схем спе
     цификации.
  Отступы в документе имеют особое значение и подразумевают уровни вложен
ности, так что будьте внимательны.
  В заголовок документа внесите следующее описание:

   openapi: 3.1.1
   info:
     title: ToDo client-server api
     description: | Документация по описанию конечных точек сервера, через которые
   осуществляется доступ к ресурсам
     version: 1.0.0
   servers:
   - url: http://127.0.0.1:8080/api/v1/todo

   tags:
   - name: task
   - name: project

   Раздел path пока будет содержать следующие заглушки:
   paths:
     /project:
       post: # тип запроса к ресурсу
