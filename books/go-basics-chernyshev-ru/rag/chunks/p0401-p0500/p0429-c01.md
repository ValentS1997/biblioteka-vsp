8.5. Пример реализации REST API веб-сервиса
8.5.1. Основы REST API
REST (representational state transfer, передача репрезентативного состояния) — ар
хитектурный стиль программного обеспечения, который определяет, как должен
работать и вести себя веб-сервис. Этот стиль разработан так, чтобы использовать
преимущества HTTP (HyperText Transfer Protocol, протокол передачи гипертекста)
при взаимодействии между клиентом и сервером.
   Поскольку HTTP — клиент-серверный протокол, то вся ответственность за
инициализацию взаимодействия лежит на получателе (обычно это браузер), а обще
ние между клиентом и сервером происходит с помощью одиночных сообщений.
Такие сообщения со стороны клиента принято называть запросами, а со стороны
сервера — ответами. Чаще всего для взаимодействия между клиентом и сервисом
используются следующие типы HTTP-запросов (сообщений):
   yy GET — позволяет получить данные (ресурсы) от сервиса;
   yy PUT — используется для отправки запроса на создание/записи новых данных
     на стороне сервиса или обновления существующих;
   yy POST — используется для отправки запроса на создание/записи новых
     данных на стороне сервиса;
   yy DELETE — позволяет запросить сервис удалить данные.
  Под API (Application Programming Interface, интерфейс программирования
приложений) понимается совокупность документов, инструментов и функций
в виде интерфейса, благодаря которым одна программа может взаимодействовать
с другой. Основным требованием перед разработкой любого веб-сервиса (сервера)
