400       Глава 7   Конкурентность в Go

Проект: игра «Крестики-нолики», v.6

В игре есть несколько мест, которые можно изменить.
    1. Сейчас каждый возможный ход оценивается алгоритмом минимакс последо
      вательно. Мы можем добавить компьютеру возможность использовать раз
     личные параллельные стратегии при работе с большими игровыми досками.
    2. Можно распараллелить проверку выигрышных комбинаций для досок боль
     шего размера.
    3. Можно переписать реализацию сохранения результата завершенной игры
     и загрузки сессии с использованием горутин.

Реализация параллельных стратегий хода компьютера
на высоком уровне сложности
Помимо распараллеливания алгоритма минимакс для доски маленького размера
(3 × 3), мы реализуем различные стратегии, которые позволят компьютеру работать
с большими досками за приемлемое время. Для этого мы внесем изменения в пакет
player, добавив три файла, в которых и разместим реализацию этих стратегий:

   tic_tac_toe_v6
   ├── player/
   │    ├── computer_player.go
   │    ├── i_player.go
   │    ├── player.go
   │    ├── strategy_heuristic.go
   │    ├── strategy_limited_minimax.go
   │    └── strategy_zonebased.go
  В качестве первой стратегии напишем реализацию улучшенной эвристической
стратегии ходов, которая используется на среднем уровне сложности компьютера.
Каждый возможный ход будет оцениваться параллельно с использованием функции
evaluateBoardHeuristic, которая анализирует позицию на основе количества поч
ти завершенных линий для игрока и для оппонента, а также учитывает занятость
центральной клетки. Этот вариант стратегии ходов поместим в файл strategy_heu
ristic.go:
