276       Глава 5   Работа с файлами и каталогами. Сборка приложения

5.6.5. Конфигурация через .env-файл
Прежде чем переходить к очередному изменению проекта игры «Крестики-
нолики», мы рассмотрим еще один способ конфигурации приложений — файл
.env, в котором данные представлены в формате ключ=значение. В зависимости от
типа сборки (отладка, итоговая) название файла может варьироваться. Напри
мер: .dev_env, .release_env или .env_dev и т. д.
   Нельзя сказать, что это самый безопасный способ хранения приватных данных
приложения (переменные среды компиляции подходят лучше), но вот по удобству
он явно может посоревноваться с вариантами, которые мы рассмотрели в предыду
щих подразделах. Главное, не забыть добавить в файл .gitignore запрет на выгрузку
файлов этого формата в удаленный репозиторий проекта (GitHub, GitVerse и т. д.).
  В качестве примера напишем собственную реализацию библиотеки dotenv,
которая позволит хранить в файле данные в строковом, целочисленном и булевом
формате данных. Создайте проект go_dotenv и приведите его структуру к следу
ющему виду:

   go_dotenv
   ├── dotenv /
   │     └── dotenv.go
   ├── .env
   ├── go.mod
   └── main.go

   Теперь откройте файл dotenv.go и добавьте в него следующий код:
   // baseURL/part_5/5.6/go_dotenv/dotenv/dotenv.go
   package dotenv

   import (
       "bufio"
       "errors"
       "fmt"
       "maps"
       "os"
       "regexp"
       "strconv"
       "strings"
   )

   type DotEnv struct {
       env map[string]interface{}
   }

   // Регулярные выражения для int и bool
   var (
       intPattern  = regexp.MustCompile(`^-?\d+$`)
       boolPattern = regexp.MustCompile(`^(?i:true|false)$`)
   )

   // Создаем новый экземпляр DotEnv

       if platformEnv {
