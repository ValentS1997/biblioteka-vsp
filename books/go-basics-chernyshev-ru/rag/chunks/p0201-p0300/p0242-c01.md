5.3. Операции с JSON-файлами      241

  В корневой директории проекта должен появиться файл actor.json. Теперь
мы прочитаем из него данные и выполним их десериализацию в экземпляр струк
туры:

   // baseURL/part_5/5.3/3.go
   package main

   import (
       "encoding/json"
       "fmt"
       "log"
       "os"
   )

   type Actor struct {
       Name        string
       Age         int
       FilmsAmount int
       AboutActor  string
   }

   func main() {
       actor := &Actor{}

       data, err := os.ReadFile("actor.json")
       if err ! = nil {
           log.Fatal(err)
       }

       err = json.Unmarshal(data, actor) // десериализация в структуру
       if err ! = nil {
           log.Fatal(err)
       }

       fmt.Printf("%+v", *actor)
   }
   /* {Name:Tom Hanks Age:69 FilmsAmount:70 AboutActor:Tom Hanks is an actor...} */
   Обратите внимание: при сериализации и десериализации данных на вход
функций Go подается указатель на экземпляр структуры (значения), а не сам
экземпляр.

5.3.2. Зачем нужен null
В ряде случаев данные могут не храниться на сервере. Поэтому такие поля в воз
вращаемом JSON содержат значение null или вовсе отсутствуют. Так, например,
актер может быть настолько неизвестен, что какая-либо информация о нем попро
сту отсутствует.
   Если вы замените в файле actor.json значение, хранящиеся по ключу "AboutActor"
на null (или удалите эту пару «ключ:значение») и снова запустите приложение из
примера, приведенного в предыдущем подразделе, то в терминал выведется строка,
где поле структуры будет инициализировано значением по умолчанию (пустой
строкой):

   {Name:Tom Hanks Age:69 FilmsAmount:70 AboutActor:}
