Проект: игра «Крестики-нолики», v.0
В этом разделе мы создадим игру, которую будем улучшать и перерабатывать в по
следующих главах. В ходе работы с этим сквозным проектом мы разберем, как:
   yy написать код в одной функции main, а затем перейти к его разделению в про
      цедурном, а далее и объектно-ориентированном стиле;
   yy выделять повторяющийся код в отдельные функции и пакеты, делая при
     ложение более модульным и поддерживаемым;
   yy добавлять в готовое приложение новый функционал: от игрока-компьютера
      с разными уровнями сложности до сохранения и загрузки игровых сессий;
   yy проводить рефакторинг, не ломая существующую логику, и постепенно
     улучшать архитектуру проекта;
   yy работать с файловой системой для сохранения данных, а затем мигрировать
     на полноценную СУБД (SQLite) с использованием GORM;
   yy проектировать интерфейсы и применять принципы инверсии зависимостей
     для создания гибкой и тестируемой архитектуры;
   yy использовать горутины и каналы для распараллеливания вычислений (па
     раллельная проверка выигрышных комбинаций, конкурентные стратегии
      хода компьютера);
   yy организовать взаимодействие по сети, реализовав клиент-серверную архи
      тектуру на TCP с собственной системой команд и сериализацией данных;
   yy проектировать протокол обмена сообщениями и обрабатывать различные
     состояния клиентского приложения;
   yy работать с базами данных в конкурентной среде и избегать проблем с бло
     кировками;
   yy декомпозировать проект на логические пакеты (board, game, player, network,
       room, database) и управлять зависимостями между ними, избегая цикличе
     ских импортов.
   Создайте консольный проект tic_tac_toe и файл конфигурации launch.json,
который позволит вводить данные с клавиатуры во время отладки приложения
(см. раздел 1.14). Затем откройте файл main.go. Реализацию игры мы начнем с объ
явления импортов, констант, описывающих состояние игрового процесса, и пустой
функции main:

   // baseURL/part_1/tic_tac_toe/main.go
   package main
