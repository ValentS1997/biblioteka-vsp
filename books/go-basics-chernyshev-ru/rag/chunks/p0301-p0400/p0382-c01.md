   Теперь код работает корректно, и при повторном запуске приложения на про
верку наличия состояния гонки мы получим следующий результат:

   C:\Users\...\app>go run -race .\main.go
   Value after 1k increment  =  1000
  Чтобы избежать проблем с состоянием гонки за ресурсы, мы защитили крити
ческий раздел кода с помощью мьютекса, расположив его между вызовами методов
mutex.Lock() и mutex.Unlock(). Первая горутина, вызвавшая Lock(), «захватывает»
мьютекс (получает эксклюзивный доступ). Все остальные горутины, которые пыта
ются вызвать этот же метод мьютекса, будут блокироваться и ждать своей очереди.
Когда первая горутина закончит работать с общими данными и вызовет метод Un
lock(), мьютекс освободится и одна из ожидающих горутин «захватит» его, чтобы
выполнить свой критический раздел. Такой подход гарантирует, что изменение
общих данных (запись) всегда выполняется корректно, то есть без конфликтов
между горутинами.
  Что касается операций чтения, то там есть свои особенности. При чтении данных
нам важно получать их актуальное значение, и если одна горутина читает данные,
а другая в этот же момент их изменяет, то существует большая вероятность, что
будут прочитаны поврежденные или устаревшие данные. Поэтому операции чтения
тоже нужно как-то защищать! Однако блокировать мьютекс на все время чтения
(как при записи) неэффективно. В такой ситуации можно использовать второй тип
мьютекса — RWMutex (Read/Write Mutex), позволяющий многим горутинам одно
временно читать одни и те же данные без риска их испортить. Помимо обычных
методов Lock() и Unlock(), которые используются для записи (изменения) данных,
как в обычном мьютексе, RWMutex предоставляет разработчику еще два дополнитель
ных метода: RLock() и RUnlock(). Многие горутины могут одновременно «захватить»
мьютекс на чтение через RLock(), что позволяет горутинам параллельно читать
общие данные, не блокируя друг друга. Запись же всегда эксклюзивна, и только
одна горутина может «захватить» мьютекс для этой цели. Ввиду этого, пока идет
запись, которая запускается методом Lock(), все новые операции чтения (RLock)
и записи (Lock) блокируются.

счетом клиента банка из нескольких горутин. За снятие и пополнение счета будут
отвечать две отдельные горутины, а за чтение данных текущего баланса счета и вы
