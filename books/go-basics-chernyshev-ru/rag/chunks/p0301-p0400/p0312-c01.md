6.1. Разработка приложения ToDo-list с помощью модуля go-sqlite3      311

6.1.4. Программное представление записей базы данных
Данные, извлекаемые из базы или записываемые в нее, должны иметь программное
представление в виде структур, которые будут передаваться в SQLiteRepository
либо возвращаться им. Такие данные принято называть сущностями (entity) или
моделями (model). Разница в том, что модели расширяют сущности и могут содер
жать методы, а сущности представляют собой простую структуру данных (plain old
data, POD). В нашем случае для упрощения сущности помещены в файл models.go.
Фактически структура ProjectTask уже является моделью, поскольку расширяет
сущность Task:

   // baseURL/part_6/6.1/golang/todo/db/models.go
   package db

   type Project struct {
       ID          int
       Name        string
       Description string
   }

   type Task struct {
       ID          int
       Name        string
       Description string
       Priority    uint8
       IsDone      bool
   }

   type ProjectTask struct {
       Task
       ProjectID int
   }

6.1.5. Работа с таблицей projects
Для работы с этой таблицей мы реализуем три метода: AddProject, DeleteProject
и GetAllProjects — для удаления и добавления проекта, а также получения списка
всех проектов. Эти методы мы свяжем со структурой SQLiteRepository и поме
стим их в файл projects_crud.go. CRUD — акроним из первых букв действий над
базами данных: create («создание»), read («чтение»), update («модификация»)
и delete («удаление»). Серверные разработчики, особенно на позиции джуниора,
много времени уделяют именно написанию CRUD-операций. Это утомительная
однотипная работа, но через эту стадию так или иначе проходят все разработчики.
   Поместите в файл projects_crud.go этот код:

   // baseURL/part_6/6.1/golang/todo/db/projects_crud.go
   package db

   import (
       "errors"

       "github.com/mattn/go-sqlite3"
   )
