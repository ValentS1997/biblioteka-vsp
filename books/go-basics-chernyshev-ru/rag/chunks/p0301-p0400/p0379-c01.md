378       Глава 7   Конкурентность в Go

7.6. Состояние гонки
При конкурентном выполнении программы горутины имеют доступ к общей памяти
приложения и общим переменным. Одновременное обращение к ним из различ
ных горутин для записи нового значения, когда результат программы зависит от
последовательности их выполнения, может привести к состоянию гонки и к тому,
что результат выполнения будет некорректным. Части кода, которые изменяют
общие ресурсы, называются критическим разделом и не должны быть доступны
нескольким горутинам одновременно.
  В качестве примера состояния гонки в приложении используем такой код:

   // baseURL/part_7/7.6/1.go
   package main

   import (
       "fmt"
       "sync"
   )

   var value = 0

   func increment(waitGroup *sync.WaitGroup) {
       value = value + 1
       waitGroup.Done()
   }

   func main() {
       var waitGroup sync.WaitGroup
       for i := 0; i < 1000; i+ + {
           waitGroup.Add(1)
           go increment(&waitGroup)
       }
       waitGroup.Wait()
       fmt.Println("Value after 1k increment  = ", value)
   }
   // Value after 1k increment  =  981
  В данном случае результат никогда не достигнет нужного значения — 1000. Это свя
зано с тем, что некоторые горутины начинают выполняться с одинаковым значением
переменной value, из-за чего при их завершении оно не изменяется. Go предоставляет
инструмент для отлавливания таких состояний. Чтобы использовать его, запустите
ваше приложение через терминал VS Code с помощью команды go run -race:
