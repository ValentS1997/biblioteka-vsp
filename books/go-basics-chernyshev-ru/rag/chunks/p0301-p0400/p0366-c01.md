7.4. Ожидание завершения горутин      365

  Любая функция, используемая при создании горутины, не должна возвращать
значения, иначе это приведет к ошибке времени компиляции:

   // baseURL/part_7/7.3/4.go
   package main

   import (
       "fmt"
       "time"
   )

   func namedGorutine(number int) int{
       fmt.Printf("%d ", number)
       return number
   }

   func main() {
       number := go namedGorutine(1)
       time.Sleep(time.Second)
   }
   /* Build Error: go build -o e:\code\golang\gorutines\__debug_bin.exe -gcflags all=-N -l .
   # golang/gorutines
   .\main.go:14:12: syntax error: unexpected go, expecting expression (exit status 2) */

7.4. Ожидание завершения горутин

В реальных программах для ожидания завершения горутин никогда не используется
подход с остановкой главного потока выполнения с помощью таймера. Это связано
с тем, что очень сложно подобрать время выполнения всех горутин. Поэтому в Go
входит пакет sync, предоставляющий механизмы для синхронизации потока вы
полнения программы.
  Перепишем код примера из предыдущего раздела, используя переменную типа
sync.WaitGroup, которая представляет собой счетчик:

   // baseURL/part_7/7.4/1.go
   package main

   import (
       "fmt"
       "sync"
   )

   func namedGorutine(number int, waitGroup *sync.WaitGroup) {
       defer waitGroup.Done() // уменьшение счетчика sync.WaitGroup на 1
       fmt.Printf("%d", number)
   }

   func main() {
       var waitGroup sync.WaitGroup

       for i := 0; i <= 30; i+ + {
           waitGroup.Add(1) // увеличение счетчика на 1
           go namedGorutine(i, &waitGroup)
       }
       waitGroup.Wait() // ожидание завершения всех запущенных горутин
   }
   /* 0 8 2 6 7 11 13 9 12 5 14 1 4 15 10 16 3 17 19 18 20 21 22 23 24 25 26 27 28 30 29 */
