6.3. Выполнение транзакций с помощью модуля gorm
Теперь, когда мы обсудили, как выполнять отдельные операции с базой данных,
рассмотрим транзакции — механизм, который позволяет объединить несколько
операций в одно атомарное действие, обеспечивая согласованное состояние базы
данных. Изменения, сделанные в рамках транзакции, не видны другим пользова
телям и не влияют на их работу, пока не будут зафиксированы (записаны в базу).
  Для этого все изменения, которые могут вноситься в базу с использованием
инструкций insert и update, должны фиксироваться путем вызова метода commit.
Такой способ позволяет за раз внести различное количество изменений. Вносимые
данные сохранятся атомарно, а не по очереди. При этом любая ошибка в момент
выполнения транзакции приведет к откату (rollback), и данные в базе останутся
прежними, в том виде, какой они имели до начала транзакции.
  По умолчанию все операции записи (создание, удаление и обновление) в gorm
выполняются внутри транзакции, что обеспечивает целостность данных. Режим
транзакции можно отключить при инициализации сессии, передав соответству
ющий флаг:

   tx := db.Session(&Session{SkipDefaultTransaction: true})
   tx.Create(&Project{Name: "T", Description: "Oo" })
  Это действие позволит увеличить производительность, но может привести
к нарушению целостности данных. Поэтому при отключении транзакции следует
соблюдать особую осторожность.
   Рассматривать принципы работы с транзакцией мы будем на следующем при
мере:

   // baseURL/part_6/6.3/golang/todo_transaction/main.go
   package main

   import (
       "errors"
       "fmt"
       "log"
       "os"

       "gorm.io/driver/sqlite"
       "gorm.io/gorm"
   )

   const dbName = "todo.db"

   var ErrNotExists = errors.New("row not exists")

   type Project struct {
       ID          int    `gorm:"primary_key;autoIncrement:true;not null"`
       Name        string `gorm:"unique;not null"`
       Description string
   }
