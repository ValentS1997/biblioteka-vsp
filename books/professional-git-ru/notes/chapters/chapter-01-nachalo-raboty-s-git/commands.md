# Глава 1 — команды и инструменты

Источник: **RAG-only**, `professional-git-ru:p0010:c01`–`p0016:c01`, PDF 10–16. Команды ниже основаны исключительно на примерах §§1.1–1.8. Пробелы внутри распознанных слов (`gi t`, `user . name`) устранены **только там, где синтаксис однозначен из данного фрагмента**. Неоднозначные примеры не выдаются за исполняемые: [source-findings.md](source-findings.md).

Условные `<PATH>`, `<URL>`, `<NAME>`, `<EMAIL>` — заполнители. Не копировать их буквально; не публиковать токены, пароли и приватные ключи.

## 2. Создание и изменение локального репозитория — state-changing

| Команда | Эффект и риск | Проверка после | Откат | PDF |
| --- | --- | --- | --- | --- |
| `git init` | Создаёт `.git` в текущем каталоге. Проверить выбранный каталог | `git status` | [Needs confirmation] | 11 |
| `git add <PATH>` | Добавляет **выбранные** файлы в индекс; опасность включить секреты | `git status` | [Needs confirmation] | 11 |
| `git commit -m "Initial commit"` | Создаёт коммит; нужны корректные автор и индекс | `git status` (состояние каталога; проверка идентичности коммита в главе не задана) | [Needs confirmation] | 11 |

До `git add` книга требует заранее настроить `.gitignore` для файлов, которые не должны попасть под контроль версий. Отдельной команды для редактирования `.gitignore` глава не даёт. Строка `git add` без аргументов приведена под смыслом «добавить все» и помечена как противоречивый образец — не используйте её как проверенный рецепт. [p0011](../../../rag/chunks/p0001-p0100/p0011-c01.md).

## 3. Клонирование, удалённые репозитории и публикация

| Команда | Класс | Эффект / риск | Проверка | Откат | PDF |
| --- | --- | --- | --- | --- | --- |
| `git clone <URL>` | state-changing, workload-generating | Создаёт каталог-клон с историей и `.git`; источник URL должен быть известен | Осмотреть созданный каталог; `git status` — доступная проверка состояния Git | [Needs confirmation] | 12 |
| `git clone <URL> MyFolder` | state-changing, workload-generating | Создаёт клон под указанным именем; каталог должен отсутствовать или быть пуст | Проверить файлы каталога | [Needs confirmation] | 12 |
| `git remote add origin <URL>` | state-changing | Регистрирует URL удалённого репозитория; риск выбрать чужой адрес | `git remote -v` | [Needs confirmation] | 11 |
| `git remote add upstream <URL>` | state-changing | Добавляет связь с исходным репозиторием форка | `git remote -v` | [Needs confirmation] | 14 |
| `git remote set-url upstream <URL>` | state-changing | Меняет адрес существующего `upstream` | `git remote -v` | [Needs confirmation] | 14 |
| `git push --set-upstream origin master` | state-changing, network workload | Публикует локальную ветвь и задаёт upstream; команда из §1.3 с восстановленными разрывами внутри одного слова | Подробная проверка результата отправки в главе [Needs confirmation] | [Needs confirmation] | 12 |

При использовании команды `push` учитывайте, что `master` — **именно имя ветви из книги**, а не подтверждение имени ветки в вашей среде. Использовать только если URL, ветвь и право публикации проверены. Сильно повреждённая запись создания bare-репозитория исключена из исполняемых примеров; см. [source-findings.md](source-findings.md). PDF 11–14: [11](../../../rag/chunks/p0001-p0100/p0011-c01.md), [12](../../../rag/chunks/p0001-p0100/p0012-c01.md), [14](../../../rag/chunks/p0001-p0100/p0014-c01.md).

## 4. Идентификация автора — state-changing

| Команда | Эффект / риск | Проверка | Откат | PDF |
| --- | --- | --- | --- | --- |
| `git config --global user.name "<NAME>"` | Задаёт автора по умолчанию для всех репозиториев этого пользователя | Проверить применение ожидаемой области настройки; конкретная проверочная команда в главе [Needs confirmation] | [Needs confirmation] | 13 |
| `git config --global user.email "<EMAIL>"` | Задаёт email автора глобально | То же | [Needs confirmation] | 13 |
| `git config user.name "<NAME>"` | Задаёт имя автора только для текущего репозитория | То же | [Needs confirmation] | 13 |
| `git config user.email "<EMAIL>"` | Задаёт email для текущего репозитория; локальное имеет приоритет над глобальным | То же | [Needs confirmation] | 13 |
| `git config --global user.useConfigOnly true` | Просит Git требовать явную идентификацию при коммите; книга указывает условие Git ≥2.8 | Проверка предусмотрена через попытку коммита, но это меняющее действие; безопасный read-only метод [Needs confirmation] | [Needs confirmation] | 13 |

**Различать:** идентификаторы автора коммита и сетевую аутентификацию (§1.4). Повреждённые команды удаления глобальных настроек (`-- remove-section user . name`) намеренно не преобразованы в советы.

**Исторический контекст:** список версий Git в начале главы заканчивается 2.13/2017 г., а инструкции установки в §1.8 могут не отражать современное состояние систем и сайтов; этот анализ не проверяет их извне. Не запускать команды пакетного менеджера на неподтверждённой ОС и не подменять исходные образцы современными рекомендациями.

## Команды, оставленные в источнике без исполняемого восстановления

- Создание серверного bare-репозитория: в RAG написано `git init --Ьа ге /path/to/ repo . git` (PDF 12). Требует подтверждения исходного синтаксиса.
- В §1.2 под «клонировать в текущий каталог» повторена команда без аргумента каталога (PDF 12). Формулировка и код не совпадают.
- Показанное удаление `user.name` / `user.email` содержит `-- remove-section` и нуждается в проверке исходного текста (PDF 13).

Классификации и точные варианты: [source-findings.md](source-findings.md). Не вводить команды из других глав или модели для заполнения пробелов.
