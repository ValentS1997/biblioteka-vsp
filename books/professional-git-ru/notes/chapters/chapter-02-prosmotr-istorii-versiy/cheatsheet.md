# Глава 2 — памятка по просмотру истории версий

**Источник:** RAG `p0016:c01`–`p0023:c01`, PDF 16–23, §§2.1–2.14. Содержание строго ограничено этими разделами. Неоднозначные OCR-строки отмечены в [source-findings.md](source-findings.md).

## Symptom / problem framing

Вопросы главы: какие коммиты существуют, как построены связи/слияния между ветвями, кто автор, где менялась строка или диапазон файла, какие файлы затронуты и как выглядел конкретный коммит. Это **исследование истории**, а не её переписывание.

## Baseline / context

`git log` выводит коммиты в обратном хронологическом порядке, с идентификатором, автором, датой и сообщением (§2.1). В примерах книги используются SHA-1, ветви `master`, `foo`, `develop`, `origin/master`: это значения из примеров, не свойства произвольного репозитория. Если вывод `git log` открыт в просмотрщике, для выхода предлагается `q`. Опции `--oneline`, `--graph` и `--decorate` меняют отображение, а `-2` ограничивает число коммитов.

## Interpretation

- **Обзор:** `git log` показывает историю, `--oneline` делает список коротким, `--graph --decorate` — удобным для графа и ссылок (§§2.1–2.4).
- **Содержимое:** `-S`/ `-G` демонстрируются на изменениях `#define SAMPLES`, `--grep` применяется к тексту сообщения (§§2.5, 2.7).
- **Диапазон файла:** `-L` сопровождается выводом diffs для строк файла; источник приводит пример `index.html` (§2.8).
- **Временные ограничения:** `--after` / `--since` и `--before` / `--until` фильтруют историю по датам (§2.9).
- **Детальность:** `--patch` показывает изменения, `--stat` — файлы и краткую статистику, `git show` — один коммит (§§2.10–2.12).
- **Ветви:** `master..foo` по тексту книги показывает то, что есть в `foo`, но отсутствует в `master` (§2.13).

## Modifying action

Единственное прямо описанное изменяющее действие в этом разделе — установка глобального псевдонима `lol` командой `git config --global alias.lol "log --decorate --oneline --graph"` (§2.2). Эффект: настройка Git уровня пользователя, после которой книга применяет `git lol`, `git lol HEAD develop origin/master` и `git lol --all`. Риски: изменение пользовательской конфигурации, возможное совпадение с ранее существующим псевдонимом. Проверка: после настройки выполнить `git lol` и убедиться, что отображается ожидаемый журнал; команда проверки конфигурации в источнике не приведена. Откат: **[Needs confirmation]**.

## Verification / acceptance checks

- Для `-2` видны максимум два коммита; для `--oneline` — одна строка на коммит (§§2.1, 2.4).
- Для `--stat` видны имена файлов и количество вставок/удалений (§2.11).
- Для `git show` видны данные и изменения выбранного коммита (§2.12).
- Для `--author`, `--grep`, `--after` проверить, что результат соответствует выбранному ограничению (§§2.7, 2.9).
- Для `master..foo` — сверить, что обсуждаются именно эти ветви и требуемая разность истории (§2.13).

Проверка на реальном пользовательском репозитории и текущих внешних данных не выполнялась; результаты команд зависят от доступной истории.
