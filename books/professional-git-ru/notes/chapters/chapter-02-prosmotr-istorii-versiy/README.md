## Главный принцип

История Git исследуется **без изменения репозитория**: от общего списка коммитов через оформление графа, компактную запись, выборку по содержимому/авторам/датам и конкретным строкам — к диффам, спискам файлов и просмотру определённого коммита. Большинство команд главы только **читают** данные; исключение — настройка псевдонима через `git config --global`. Глава описывает не одну обязательную последовательность, а набор способов ответить на разные вопросы об истории.

## Практическая навигация по истории

1. **Что происходило недавно?** `git log` либо `git log -2` (§2.1).
2. **Как соотносятся ветви?** `git log --decorate --oneline --graph` и `--all` (§2.2).
3. **Нужна короткая сводка?** `git log --oneline` (§2.4).
4. **Где менялась строка?** `git log -S "#define SAMPLES"` либо `git log -G "#define SAMPLES"` — книга демонстрирует разные примеры добавления/удаления и изменения найденной строки (§2.5).
5. **Кто вносил коммиты?** `git shortlog`, `git shortlog -s`, флаги `-n` и `-e` (§2.6).
6. **Какие сообщения содержат фразу?** `git log --grep "removed file"` или `git log --all --grep "removed file"` (§2.7).
7. **Как менялись конкретные строки?** `git log -L 1,20:index.html` (§2.8).
8. **Когда и кем?** `--after`, `--before`, `--author` (§2.9).
9. **Какие правки и файлы в коммитах?** `git log --patch`, `git log --stat`, `git show <commit>` (§§2.10–2.12).
10. **Что есть в одной ветви, но отсутствует в другой?** Источник показывает `git log master..foo` (§2.13). Имена `master` и `foo` — только пример книги, не утверждение об именах ветвей пользователя.
