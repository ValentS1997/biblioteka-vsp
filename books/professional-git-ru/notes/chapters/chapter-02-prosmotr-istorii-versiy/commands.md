# Глава 2 — реестр команд просмотра истории

Источники — **только** RAG, PDF 16–23, `p0016:c01`–`p0023:c01`. **Класс:** read-only = чтение Git-истории; state-changing = изменение Git-конфигурации; workload-generating = вычисление/вывод истории без изменения состояния. Для обычных команд `git log` / `git show` результатом является чтение; большой вывод может создавать вычислительную нагрузку, но не модифицирует коммиты.

**Нормализация:** удалены только несомненные пробелы посреди флагов из извлечённого текстового слоя. Оригинальные искажения перечислены в [source-findings.md](source-findings.md). `master`, `foo`, `index.html`, `#define SAMPLES` и демонстрационные даты — данные примеров книги, а не гарантированно существующие значения.

## 1. Просмотр и форма отображения

| Команда | Класс | Что показывает | PDF |
| --- | --- | --- | --- |
| `git log` | read-only | Список коммитов: SHA, автор, дата, сообщение; в обратном хронологическом порядке; `q` — выход из просмотрщика | 17 |
| `git log -2` | read-only | Два последних коммита (или меньше, если история короче) | 17 |
| `git log --decorate --oneline --graph` | read-only | Графоподобная история со ссылками и компактными записями | 17–18 |
| `git log --oneline` | read-only | Короткий хеш и сообщение, по коммиту в строке | 18 |
| `git log -2 --oneline` | read-only | Два последних коммита компактно | 19 |

§2.3 также перечисляет `--pretty=format:` и цветовые макросы `%h`, `%H`, `%d`, `%s`, `%cr`, `%an`, `%C(...)`, `%Creset`; сквозная строка команды имеет дефекты извлечения и **не** публикуется как безопасная к копированию. §2.14 содержит дефектный фрагмент `tree = log --oneline ...`, который не объявляется рабочим псевдонимом без подтверждения.

## 2. Поиск изменений и текста сообщений

| Команда | Класс | Смысл по RAG | PDF |
| --- | --- | --- | --- |
| `git log -S "#define SAMPLES"` | read-only | Поиск добавления/удаления указанной строки, пример с `#define SAMPLES` | 19 |
| `git log -G "#define SAMPLES"` | read-only | Поиск изменений строк, содержащих заданный текст/шаблон | 19 |
| `git log --all --grep "removed file"` | read-only | Поиск совпадения в тексте сообщений коммитов по всем ветвям | 20 |
| `git log --grep="add file" --invert-grep` | read-only | Инвертировать поиск по строке в сообщении; книга относит возможность к Git 2.4+ | 20 |
| `git log -L 1,20:index.html` | read-only / workload-generating | Показать историю изменения строк 1–20 файла `index.html`, включая diff | 20–21 |

В §2.5 объяснение `-S` частично пересекается по терминологии с описанием `-G`, без последовательного формального различения шаблона/строки; зафиксировано как **[Needs confirmation]**. Нельзя выводить исправленную семантику из внешних справочников при `rag_only`.

## 3. Авторы, время и выборка коммитов

| Команда / флаг | Класс | Назначение | PDF |
| --- | --- | --- | --- |
| `git shortlog` | read-only | Группировка списка коммитов по авторам | 19 |
| `git shortlog -s` | read-only | Только количество коммитов для каждого автора, без сообщений | 19 |
| `-n` / `--numbered` (опция `shortlog`) | read-only при использовании | Сортировка по количеству коммитов | 20 |
| `-e` / `--email` (опция `shortlog`) | read-only при использовании | Добавить адрес электронной почты автора | 20 |
| `--format` (опция `shortlog`) | read-only при использовании | Произвольный формат в терминологии источника | 20 |
| `git log --after '3 days ago'` | read-only | Ограничить коммиты внесёнными после указанного момента | 21 |
| `git log --after 2016-05-01` | read-only | Ограничить по календарной дате (исторический пример) | 21 |
| `git log --author=author` | read-only | Фильтр по автору | 21 |
| `--since`, `--before`, `--until` (опции `git log`) | read-only при использовании | `--since` аналогичен `--after`; `--before`/`--until` — до заданной даты | 21 |

Названия флагов `shortlog` приведены источником как отдельные параметры. Синтаксис комбинирования в произвольном порядке и приоритет фильтров в главе не проверены: **[Needs confirmation]**.

## 4. Диффы, состав файлов, конкретные коммиты, разность ветвей

| Команда | Класс | Что видно | PDF |
| --- | --- | --- | --- |
| `git log --patch` | read-only / workload-generating | Патч изменений для коммитов, также назван флаг `-p` | 21 |
| `git log --stat` | read-only | Файлы и краткие статистики вставок/удалений по коммитам | 22 |
| `git show <commit>` | read-only / workload-generating | Содержимое отдельного коммита; исходник использует краткий и полный хеш | 22–23 |
| `git log master..foo` | read-only | История, относящаяся к `foo`, но отсутствующая в `master` (трактовка источника) | 23 |

**Важно:** §2.10 озаглавлен «Индексация файлов по частям», но приведённая команда только выводит патч истории. В этих артефактах она не описана как операция индексирования. Оригинал сохранён в [source-findings.md](source-findings.md).

## 5. Единственная явно изменяющая конфигурацию команда

```bash
git config --global alias.lol "log --decorate --oneline --graph"
```

**Класс:** state-changing. **Источник:** PDF 18, §2.2; текстовый слой разрывает `alias . lol` и `--g raph`, но смысл и синтаксис повторно подтверждены соседним описанием псевдонима и примерами `git lol`.

**Эффект:** записывает глобальный псевдоним `lol`; книга после этого демонстрирует читающие `git lol`, `git lol HEAD develop origin/master`, `git lol --all`. **Риск:** изменение конфигурации пользователя и возможное замещение ранее заданного псевдонима. **Проверка:** выполнить `git lol` и убедиться в ожидаемом формате истории; чтение фактического конфигурационного значения отдельной командой здесь не описано. **Откат:** **[Needs confirmation]**.

Читающие команды после настройки: `git lol`, `git lol HEAD develop origin/master`, `git lol --all`, все read-only **при существующем псевдониме**. Они зависят от наличия названных ветвей/ссылок.

## 6. Небезопасные для буквального копирования образцы

- Цветной `git log --graph --pretty=format: ...` (§2.3): повреждённые символы формата/переносы; восстановление всей строки — **[Needs confirmation]**.
- `tree = log --oneline --decorate --source --pretty=format: ...` (§2.14): RAG даёт присваивание без команды записи в конфигурацию. **Не исполнять** как оболочечную команду и не создавать способ регистрации по памяти.
- Примеры хешей с перемешанными латинскими/кириллическими символами: как идентификаторы реальных коммитов **[Needs confirmation]**.

Все команды истории **не** предусматривают откат состояния, так как читают данные. Источник не предоставляет тестовый репозиторий или проверенные современные результаты команд.
