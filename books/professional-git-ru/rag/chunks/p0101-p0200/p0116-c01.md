Раздел 30.8. Создание новых коммитов
   Команда gi t commi t выполняет несколько действий:
        1.   Создает объекты типа ЫоЬ и объекты типа "дерево" для представления каталога
        проекта - хранятся в   . git/obj ects
        2.   Создает новый объект типа "коммит" с информацией об авторе, сообщением ком
         мита, и корень дерева из шага 1 - также сохраняется в   . git/obj ects
       3.  Обновляет ссылку HEAD в   . gi t/HEAD на хеш только что созданного коммита
   В результате в gi t будет добавлен новый слепок проекта, связанный с предыдущим со
стоянием.

Раздел 30. 9. Перемещение HEAD
   Когда вы запускаете git checkout для коммита (указанного в виде хеша hash или ref),
вы говорите gi t, чтобы ваш рабочий каталог выглядел так, как он выглядел на момент соз
дания слепка.
        1.  Обновить файлы в рабочем каталоге в соответствии с деревом внутри коммита.
       2.  Обновить HEAD с тем, чтобы он указывал на определенный хеш или на ссылку.

Раздел 30.1 О. Перемещение ссылки HEAD
   Выполнение gi t reset --ha rd перенаправляет ссылки на указанный хеш/реф. Переме
щение MyBranch в b8dc53:
     $ git checkout MyBranch         # перемещает HEAD в MyBranch     $ git reset --hard b8dc53       # заставляет MyBranch указывать  на b8dc53
Раздел 30.1 1 . Создание новых типов ссылок (Refs)
   Выполнение команды git checkout  -Ь  < refname>  создаст новую ссылку, указываю-
щую на текущий коммит:
     $ cat     . git/head
        1 f324a
     $ git checkout  -Ь TestBranch
     $ cat     . git/ refs/heads/TestBranch
        1 f324a
