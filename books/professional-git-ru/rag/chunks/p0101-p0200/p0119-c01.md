Раздел 33.2. Передача локальных изменений в SVN
   Команда:
    git svn dcommit
создаст SVN-ревизию для каждого из ваших локальных git-коммитов. Как и в случае с SVN,
ваша локальная история Git доткна быть синхронизирована с последними изменения
ми в репозитории SVN, поэтому если команда не работает, попробуйте сначала выполнить
git svn rebase .

Раздел 33.3. Работа на локальном уровне
   Просто используйте свой локальный git-репозиторий как обычный git-репозиторий,
с обычными командами git:
     •   git  add  FILE и git checkout  --  FILE для индексирования/отмены индекси
        рования
     •   git commit для сохранения изменений. Эти коммиты будут локальными и не бу
         дут "публиковаться" в SVN-репозитории, как это происходило в обычном git-репо
        зитории
     •   gi t stash и gi t stash рор позволяют использовать "тайники"
     •   git reset HEAD --hard возвращаетвселокальныеизмененияв исходное состояние
     •   g i t log доступ ко всей истории в репозитории
     •   g i t rebase -i, чтобы вы могли свободно переписывать свою локальную историю
     •   git branch и git checkout для создания локальных веток
   Как сказано в документации git-svn, "Subversion - это система, которая гораздо менее
сложна, чем Git", поэтому вы не можете использовать весь фушщионал git без угрозы по
терять историю на сервере Subversion. К счастью, правила очень просты: сохраняйте исто
рию линейной.
   Это означает, что вы можете выполнять практически любые операции с Git: создавать
ветки, удалять/переупорядочивать/объединять коммиты, перемещать историю, удалять
коммиты и т.д. Всё, кроме слияний. Если вам нужно восстановить историю локальных веток,
используйте git rebase.
   При выполнении слияния создается коммит слияния. Особенностью коммитов слияния
является то, что у них есть два родителя, и это делает историю нелинейной. Нелинейная
история будет мешать нормальному функционированию SVN в случае "публикации" ком
митов слияния в хранилище.
   Однако не беспокойтесь: вы ничего не нарушите, если "затолкаете" коммит сJШЯНия
в SVN. Если вы это сделаете, то когда коммит слияния отправится на сервер SVN, он будет
содержать все изменения всех коммитов для этого слияния, поэтому вы потеряете историю
этих коммитов, но не потеряете изменения в вашем коде.

Раздел 33.4. Получение последних изменений из SVN
   Эквивалентом gi t pull является команда
    git svn rebase
   При этом все изменения извлекаются из репозитория SVN и размещаются поверх локаль
ных коммитов в текущей ветке.
   Также можно воспользоваться командой
    git svn fetch
для получения изменений из репозитория SVN и переноса их на локальную машину,
но без применения их к локальной ветке.
