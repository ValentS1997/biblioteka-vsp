1 28                                              Глава 41 . Поиск коммита, в котором появился баг

    # сообщить git ,  что версия хорошая ,
    # это означает,  что даная версия  не содержит ошибки
     $ git bisect good

    # если версия содержит ошибку,
    # то сообщить git ,  что она плохая
     $ git bisect bad
   gi t продолжит выполнять бинарный поиск в каждом оставшемся подмножестве пло
хих версий в зависимости от ваших указаний. В конечном итоге gi t выдаст одну версию,
которая, в том случае если ваши параметры хороший/плохой бьmи верными, будет версией,
в которой впервые была обнаружена ошибка.
   После этого не забудьте выполнить команду git bisect  reset, чтобы завершить сеанс
поиска bisect и вернуться в HEAD:
     $ git bisect reset
   Если у вас есть скрипт, который может проверить наличие ошибки, вы можете автомати
зировать этот процесс с помощью команды:
     $ git bisect run    [ script ]    [ a rguments ]
   Здесь  [ sc ript ] - путь к вашему скрипту, а  [ а rguments ] - любые аргументы, кото
рые необходимо передать скрипту. Выполнение этой команды автоматически запустит би
нарный поиск, выполнив команды git bisect good или git bisect bad на каждом шаге
поиска в зависимости от кода выхода вашего скрипта. Выход с кодом О означает "хорошо",
а выход с кодами 1-124, 126 или 127 - "плохо". 125 означает, что скрипт не может проверить
данную версию (что вызовет пропуск git bisect).
   Документацию по команде gi t bisect можно найти на сайте https://git-scm.com/docs/git-Ьisect.
Раздел 41 .2. Полуавтоматический поиск коммита с ошибкой
   Представьте, что вы находитесь на мастер-ветке и что-то работает не так, как ожида
лось (в программе нашли баг), но где именно, вы пока не знаете. Все, что вы знаете, так это
то, что это работало в последнем релизе (который был, например, отмечен соответствую
щим тегом или вы знаете хеш этого коммита, пусть к примеру это будет old- rel).
   В этом случае Git поможет вам, найдя ошибочный коммит, внесший баг, с помощью не
большого количества шагов (бинарный поиск).
   Прежде всего начнем с разбиения коммитов на группы:
    git bisect start master old- rel
   Это сообщит Git, что maste r - это версия, в которой сейчас нашли баг (или первая вер
сия с наличием бага), а old- rel - последняя известная рабочая версия.
   В этот момент можно провести тестирование текущей версии проекта. В зависимости
от того, рабочая она или нет, выдайте:
    git bisect good
или
    git bisect bad
   В случае если этот коммит не может быть проверен, вы можете командой git  reset
сделать сброс и повторно проверить очередной коммит, Git позаботится об этом. После не
скольких шагов Git выведет хеш коммита, содержащего ошибку.
   Для того чтобы прервать процесс поиска, достаточно ввести команду:
    git bisect reset
... и Git восстановит предыдущее состояние.
