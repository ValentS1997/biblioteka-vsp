Раздел 51 .1 . Восстановление после неудачного перемещения
   Предположим, что вы запустили интерактивную команду перемещения rebase в интер
активном режиме:
    git rebase --interactive HEAD~20
... и так получилось, что вы по ошибке объединили или удалили несколько коммитов, кото
рые не хотели терять, но затем все же завершили процедуру перемещения. Чтобы восстано
вить первоначальное состояние, выполните команду gi t  reflog, и вы увидите на экране
примерно такой вывод:
    ааааааа HEAD@{0} rebase -i (finish)  :  retu rning to refs/head/master
    ЬЬЬЬЬЬЬ HEAD@{1 } rebase -i   ( squash)  :  rebase -i   ( squash)  : Fix pa rse error

    ссссссс HEAD@{n} rebase -i (start)  : checkout HEAD~20
    ddddddd HEAD@{n+1 }     .  .  .

   В этом случае последний коммит ddddddd (или HEAD@{n+1 }) является вершиной вашей
ветви на момент прямо перед проведением операции перемещения. Таким образом, чтобы
восстановить этот коммит (и все родительские коммиты, включая те, которые были случай
но удалены или объединены), сделайте следующее:
     $ git checkout HEAD@{n+1 }
   После этого вы можете создать новое ответвление от данного коммита командой
gi t checkout -Ь   [ Ь ranch ] . Более подробная информация приведена в разделе "Ветвление".
