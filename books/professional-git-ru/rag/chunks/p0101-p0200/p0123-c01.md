Глава 36. Переход на Git
Раздел 36.1 . SubGit
    SubGit может быть использован для однократного импорта SVN-репозитория в Git, кото
рый можно осуществить следующей командой:

     $ subgit import --non-interactive --svn-url http  : //svn  . my . co/ repos/
    myproj ect myproj ect  . git

   Более подробную и развернутую информацию по применению инструмента синхрониза
ции SubGit можно почитать по адресу http://www.subgit.com/remote-book.html#7.

Раздел 36.2. Миграция с SVN на Git с помощью утилиты
преобразования Atlassian
   Загрузите утилиту преобразования Atlassian по адресу https://Ьitbucket.org/atlassian/svn
migration-scripts/downloads/svn-migration-scripts.jar. Для работы  этой утилиты требуется
Java, поэтому убедитесь, что на машине, на которой планируется выполнять преобразова
ние, установлена среда выполнения Java Runtime Environment JRE. Если она не установлена,
то скачать и установить ее можно, обратившись по адресу https://www.java.com/en/download/
installed.jsp.
   С помощью команды j ava  - j a r  svn-mig ration-sc ripts  . j a r verify можно прове
рить, нет ли на вашей машине программ, необходимых для завершения преобразования.
В частности, эта команда проверяет наличие утилит Git, subversion и git -svn. Она также
проверяет, что миграция выполняется в файловой системе с учетом регистра. Миграция
на Git должна выполняться в файловой системе, чувствительной к регистру, чтобы избе
жать повреждения репозитория.
   Далее необходимо сгенерировать файл авторов. Subversion отслеживает изменения толь
ко по имени автора, отправляющего коммиты. Git же использует две части информации
для различения пользователей: реальное имя и адрес электронной почты. Следующая ко
манда создает текстовый файл, в котором имена пользователей Subversion будут сопостав
лены с их эквивалентами в Git:
       j ava  - j a r svn-mig ration-sc ripts  . j ar authors <svn- repo> authors . txt
... где <svn-repo> - URL-aдpec репозитория subversion, который необходимо преобразовать.
После выполнения этой команды идентификационные данные авторов будут отображены
в файле authors  . txt. Адреса электронной почты будут иметь вид <имя  пользователя>
@mycompany . com. В файле авторов необходимо вручную изменить имя каждого сотрудника,
выданное по умолчанию (которое по умолчанию стало его именем пользователя), на его на
стоящее имя. Не забудьте также проверить правильность всех адресов электронной почты,
прежде чем приступать к работе.
   Следующая команда клонирует репозиторий SVN в репозиторий Git:
    git svn clone --stdlayout --authors-file=authors  . txt <svn- repo>
    <git-repo-name>
... где <svn-repo> - тот же URL репозитория, что и в команде выше, а <git-repo-name>
имя папки в текущем каталоге, в которую нужно клонировать репозиторий. Перед исполь
зованием этой команды следует учесть несколько моментов:
     •   Параметр --std layout , указанный выше, сообщает Git, что вы используете стан
        дартную схему с папками t runk, branches и tags. Для репозиториев Subversion
           с нестандартной компоновкой необходимо указать расположение папки t runk,
       любой или всех папок ветвей и папки tags. Это можно сделать, выполнив, на
        пример, следующую команду: git  svn  clone  --t runk=/t runk  --branches=/
