Раздел 43.6. Отслеживаемая / удаленная ветвь:
<branchname>@{upstream}
     $ git log @{upst ream}  .  .  # то,  что было сделано локально и еще не было
                             # опубликовано
     $ git show master@{upst ream}    # вывести содержимое ветки     ' maste r '
   Суффикс  @{upstream} ,    добавляемый к имени  ветки  (краткая форма  записи
<branchname>@{u }), относится к ветке, указанной в переменной branchname (настраивает
ся с помощью параметров branch . <name>  . remote и branch . <name>  . merge или с помощью
gi t branch --set-upst ream-to=<b ranch> ). При отсутствии branchname по умолчанию ис
пользуется текущая ветвь.
   Вместе с синтаксисом для диапазонов версий очень полезно узнать, на сколько ком
митов ваша локальная ветка опережает ветку, расположенную в удаленном репозито
рии (коммиты, содержащиеся в локальном репозитории, еще не присутствуют в удален
ном репозитории). Также можно узнать, скольких коммитов не хватает в локальной ветке
в отличие от удаленной (коммиты в удаленной ветке, еще не слитые в локальную ветку),
или и то и друrое:
     $ git log --oneline @{u}  .
     $ git log --oneline     .  . @{u}
     $ git log --oneline --left- right @{u}  .  .  .      # то же самое ,  что     .  .  . @{u}
Раздел 43.7. Цепочка предыдущих версий: <rev>л, <rev>~<n> и т. д.
     $ git reset --ha rd НЕдDл            # отменить последний коммит
     $ git rebase --interactive HEAD~S   # переместиться на четыре коммита назад
   Суффикс л, добавляемый к параметру версии, означает первого родителя данного комми
та. л<n> означает <n>-ro родителя (т. е. < rev> л эквивалентно < rev> л1 ).
   Суффикс ~<n> к параметру версии означает коммит, который является предком <n>-ro
поколения именованного коммита, следуя только за первыми родителями. Это означает,
что, например, < rev>~3 эквивалентно < rev> л л л. Можно записать < rev>~ в качестве сокра
щенной записи команды < rev>~1 . То же самое относится и к командам < rev> л 1 или < rev> л.
   Этот синтаксис является составным.
   Для поиска по таким символическим именам можно использовать команду gi t name-rev :
     $ git name-rev 33db5f4d9027a1 0e477ccf054b2c1 ab94f74c85a
    33db5f4d9027a1 0e477ccf054b2c1 ab94f74c85a tags/v0 . 99~940
   Обратите внимание, что в следующем примере необходимо использовать параметр
--p retty=oneline, а не -oneline  .
     $ git log --pretty=oneline       I  git name-rev --stdin --name-only
     $ git log --pretty=oneline       I  git name- rev --stdin --name-only
    master Sixth batch of topics for 2  . 1 0
    master~1 Merge branch     ' ls/p4-tmp- refs '
