1 00                                                              Глава 24. Перехватчики в Git (Hook)
Раздел 24.1 О. Перехватчик prepare-commit-msg
   Этот перехватчик вызывается после перехватчика p re-commit для возможности ввода
в текстовом редакторе сообщения коммита. Обычно он используется для изменения авто
матически генерируемых сообщений коммитов при операциях перемещения или слияния.
   Этому перехватчику передается от одного до трех аргументов:
     •  Имя временного файла, который содержит сообщение.
     •  Тип коммита, либо
          о   message (опция -m или -F),
          о   tamplate (опция -t),
          о   merge (если это фиксация слияния), или
          о   squash (если он подавляет другие коммиты).
     •  хеш SHA1, соответствующей коммиту. Указывается только в том случае, если бьша
         задана опция -с, -с или - - amend  .
   Как и в случае с перехватчиком p re-commit, выход с ненулевым статусом прерывает
коммит.

Раздел 24.1 1 . Перехватчик pre-rebase
   Этот перехватчик вызывается перед тем, как команда git  rebase  начнет изменять
структуру кода. Обычно этот перехватчик используется для того, чтобы убедиться в целесо
образности операции перемещения rebase.
   Этот перехватчик принимает два параметра:
        1.  ветвь из удаленного репозитория, на основе которой был сделан fork.
        2.  перемещаемая ветвь (мажа опустить этот параметр, если перемещаемая ветвь -
         текущая).
  Вы можете прервать операцию rebase, ВЫЙДЯ из нее с ненулевым статусом.

Раздел 24.1 2. Перехватчик pre-receive
   Этот перехватчик выполняется каждый раз, когда кто-то запускает команду gi t  push
для отправки коммитов в репозиторий. Он всегда располагается в удаленном репозитории
на сервере, который является местом назначения команды push, а не в исходном (локаль
ном) хранилище.
   Перехватчик запускается до того, как будут обновлены все ссылки. Обычно он использу
ется для обеспечения соблюдения какой-либо политики разработки.
   Сценарий не принимает никаких параметров, но каждая ссьшка, пересьшаемая коман
дой push, передается скрипту в отдельной строке в стандартном вводе в следующем формате:
    <старое-значение> <новое-значение> <имя ссылки>
Раздел 24.1 З. Перехватчик update
   Этот перехватчик вызывается после перехватчика р ге- гесе i ve, и работает он точно так
же. Он вызывается до того, как что-либо будет обновлено, но вызывается отдельно для ка
ждой ссьшки, которая бьша отправлена, а не для всех сразу.
   Этот перехватчик принимает следующие три аргумента:
     •  имя обновляемой ссылки (name_ref)
     •   старое имя объекта, хранящееся по ссьшке
     •   новое имя объекта, хранящееся в ссылке
   Это та же информация, что передается в перехватчик p re- receive, но поскольку пере
хватчик update вызывается отдельно для каждой ссьшки ref, вы можете отклонять одни
ссьшки и разрешать другие.
