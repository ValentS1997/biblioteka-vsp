Глава 32. Пустые каталоги в Git
Раздел 32.1 . Git не отслеживает каталоги
   Предположим, что вы инициализировали проект со следующей структурой каталогов:

    /build
    арр . j s

   Затем вы добавляете и индексируете все изменения, которые создали до этого момента,
и делаете коммит:
    git init
    git add
    git commit -m  " Initial commit"
    Git будет отслеживать только файл арр . j s .
   Предположим, что вы добавили шаг сборки в свое приложение и полагаетесь на то, что ка
талог "build" будет там в качестве выходного каталога (и вы не хотите делать это инструк
цией по настройке, которой должен следовать каждый разработчик). Тогда в соответствии
с принятой практикой вы должны включить файл "  . gitkeep" в этот каталог и позволить
Git отслеживать этот файл.

      / build
              . gi tkeep арр . j s

   Затем проиндексируйте этот новый файл:
    git add build/  . gitkeep
    git commit -m "Кеер the build directory a round "
   Теперь Git будет отслеживать файл build/  . gi tkeep и, следовательно, папка build будет
доступна при проверке. Опять же, это просто соглашение, а не функция Git.

Глава 33. git-svn
Раздел 33.1 . Клонирование SVN-репозитория
   Для этого необходимо создать новую локальную копию репозитория с помощью ко
манды:
    git svn clone SVN_REPO_ROOT_URL    [ DEST_FOLDER_PATH ]  -Т TRUNK_REPO_PATH  -t
    TAGS_REPO_PATH -Ь BRANCHES_REPO_PATH

   Если ваш SVN-репозиторий имеет стандартную структуру (ствол, ветви, папки с тегами),
то вы можете сэкономить на наборе текста:
    git svn clone -s SVN_REPO_ROOT_URL   [ DEST_FOLDER_PATH ]
   git  svn  clone поочередно проверяет каждую ревизию SVN и делает git-коммит в ло
кальном репозитории, чтобы воссоздать историю. Если в SVN-репозитории много коммитов,
это займет некоторое время.
   После выполнения команды у вас будет полноценный git-репозиторий с локальной вет
кой master, которая отслеживает ветку trunk в SVN-репозитории.
