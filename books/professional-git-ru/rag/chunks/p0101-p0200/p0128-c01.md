Раздел 40.1  . Отображение истории коммитов для одного файла                                           1 27
Глава 40. Графическое отображение
истории коммитов с помощью
команды gitk
Раздел 40.1 . Отображение истории коммитов для одного файла
    gitk path/to/myfile

Раздел 40.2. Отображение всех коммитов
между двумя любыми коммитами
   Допустим, у вас есть два коммита d9e1 db9 и 5651 06 7, и вы хотите посмотреть, что прои
зопто междУ ними. d9e1 db9 - это самый старый предок, а 5651 067 - последний потомок
в цепочке коммитов.

    gitk  - - ancest ry- path d9e1 db9 5651 067

Раздел 40.3. Отображение коммитов с момента
появления тега версии
   Если у вас есть тег версии v2  . 3 ,  то вы можете отобразить все коммиты, начиная с это
го тега.

    gitk v2  . 3  .  .

Глава 41 . Поиск коммита, в котором
появился баг
Раздел 41 .1 . Бинарный поиск коммита с ошибкой (git blsect)
   Команда git bisect позволяет найти, в каком коммите была обнаружена ошибка, ис
пользуя бинарный поиск.
   Начните с разбиения сессии на части, предоставив две ссьшки на коммиты: на хороший
коммит до ошибки и плохой коммит после ошибки. Как правило, плохой коммит-это HEAD.

    #                    git bisect      запустить сессию
     $ git bisect start

    #      задать коммит,  в котором ошибки еще не существует
     $ git bisect good 49c747d

    #      задать коммит,  в котором ошибка уже существует
     $ git bisect bad HEAD
