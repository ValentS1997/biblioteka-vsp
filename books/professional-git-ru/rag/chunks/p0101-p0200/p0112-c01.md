Раздел 29.3. Принудительная публикация                                                                      1 1 1
  Отправка в новый репозиторий
   Чтобы выполнить отправку в репозиторий, который вы еще не успели создать, или в пу
стой репозиторий:
         1.   Создайте репозиторий на GitНub (если это применимо)
        2.  Скопируйте предоставленный вам url в виде https  : / /gi thub . com/USERNAME/
        REPO_NAME . gi t.
       3.  Перейдите в локальный репозиторий и выполните команду git remote add or
         igin URL
          о  Чтобы убедиться в том, что он бьт добавлен, выполните команду gi t remote -v
       4.  Выполните команду git push origin master
   Теперь ваш код должен бьт переместиться в GitНub.
   Для получения дополнительной информации просмотрите раздел "Добавление удален
ного репозитория".

  Пояснение
   Публикация кода (push) означает, что Git проанализирует различия междУ вашими ло
кальными коммитами и удаленными и отправит их на запись в удаленный репозиторий.
При успешном выполнении комады push ваш локальный репозиторий и удаленный репози
торий синхронизируются, и другие пользователи смогут видеть ваши коммиты.
   Подробнее о понятиях "upstream" и "downstream" см. в Примечаниях.

Раздел 29.3. Принудительная публикация
   Иногда, когда локальные изменения несовместимы с изменениями, размещеными в уда
ленном репозитории (то есть вы не можете быстро переслать удаленную ветку, или удален
ная ветка не является прямым предком вашей локальной ветки), единственным способом
пересьтки изменений является принудительная публикация:
    git push -f
   или
    git push --force
  Важные замечания
   В результате все изменения, содержащиеся в удаленном репозитории, будут перезаписа
ны, и содержимое удаленного репозитория станет эквивалентно содержимому локального
репозитория.
   Внимание: использование этой команды может привести к потере коммитов в удаленном репози
   тории. Более того, настоятельно не рекомендуется выполнять команду force push, если вы предо
   ставляете этот удаленный репозиторий другим пользователям, так как в их истории будет сохра
   няться каждый перезаписанный коммит, что приведет к рассинхронизации их работы с удаленным
   репозиторием.
   Как правило, принудительную публикацию следует применять только тогда, когда:
     •   Никто, кроме вас, не вносил изменений, которые вы пытаетесь переписать.
     •  Вы сможете заставить всех клонировать свежую копию после принудительной пу
        бликации и заставить всех применить к ней свои накопленные изменения (люди
        могут возненавидеть вас за это).

Раздел 29.4. Отправка тегов
    git push --tags
   Отправляет из локального репозитория все gi t-теги, которых нет в удаленном репози
тории.
