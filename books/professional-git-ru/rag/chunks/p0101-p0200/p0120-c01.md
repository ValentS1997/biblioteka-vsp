Раздел 33.5. Работа с пустыми папками
    Git не распознает концепцию папок, он работает только с файлами и их файловыми пу
тями. Это означает, что Git не отслеживает пустые папки. А вот SVN отслеживает. Использо
вание git-svn означает, что по умолчанию любые изменения, связанные с пустыми папками
в Git, не будут распространяться в SVN.
   Использование флага -- rmd i r при выдаче комментария исправляет эту проблему и уда
ляет пустую папку в SVN, если вы локально удалили последний файл в ней:
    git svn dcommit  - - rmdir
  К сожалению, эта команда не удаляет существующие пустые папки: это необходимо де
лать вручную.
   Чтобы не добавлять параметр --rmd i r каждый раз при выполнении dcommit, или чтобы
перестраховаться, если вы используете инструмент git GUI (например SourceTree), вы може
те установить этот параметр в качестве поведения по умолчанию с помощью команды:
    git config  - -global svn  . rmdir true
   Это изменит ваш файл   . gi tconfig и добавит в него следующие строки:
          [ svn ]    rmdir = true
   Для удаления всех неотслеживаемых файлов и папок, которые должны оставаться пу
стыми для SVN, используйте команду Git:
    git clean -fd
   Обратите внимание: предыдущая команда удалит все неотслеживаемые файлы и пустые
папки, даже те, которые должны отслеживаться SVN. Если необходимо сгенерировать пу
стые папки, отслеживаемые SVN, используйте команду:
    git svn mkdirs
  На практике это означает, что если вы хотите очистить рабочее пространство от неотсле
живаемых файлов и папок, то всегда используйте обе команды для воссоздания пустых па
пок, отслеживаемых SVN:
                               mkd i rs    git clean -fd && git svn
