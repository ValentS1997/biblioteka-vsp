Глава 31 . Плагин git-tfs
Раздел 31 .1 . Клонирование в системе git-tfs
     $ git tfs clone http  : //tfs  : 8080/tfs/DefaultCollection/ $/My . Proj ect  . Name
   В результате будет создана папка с тем же именем, что и проект, то есть /My.Project.Name.

Раздел 31 .2. Клонирование в системе git-tfs из "пустого"
репозитория Git
   Клонирование из git-репозитория в десять раз быстрее, чем клонирование непосред
ственно из TFVS, и хорошо работает при командной разработке проекта. По крайней мере,
один из членов команды должен будет создать "пустой" git-репозиторий, выполнив снача
ла обычное клонирование в системе git-tfs. Затем новый репозиторий может быть заrружен
для работы с TFVS.
     $ git clone x  : /filesha re/git/My . Proj ect  . Name . git
     $ cd My . Proj ect  . Name
     $ git tfs bootstrap
     $ git tfs pull
Раздел 31 .3. Установка плагина git-tfs через Chocolatey
  Ниже предполагается, что вы будете использовать kdiffЗ для нахождения дельты (diff)
файлов. Это очень хорошая идея, хотя и не обязательная для применения.
    С : \> choco install kdiffЗ
   Сначала устанавливается Git, и вы можете указать любые параметры. Здесь также уста
навливаются все инструменты Unix, а 'NoAutoCrlr означает, что обработка окончаний строк
будет проводиться исходя из приципа "как есть".
    С : \> choco install git -pa rams     '  ' /GitAndUnixToolsOnPath /NoAutoCrlf '  '
   Это все, что вам нужно для установки git-tfs через chocolatey.
    С : \> choco install git-tfs
Раздел 31 .4. Индексация изменеий в git-tfs командой Check ln
   Запуск диалога Check In для TFVS осуществляется командой:
     $ git tfs checkintool
   При этом все локальные коммиты будут проиндексированы и создан единый check-in.

Раздел 31 .5. git-tfs push
   Отправка всех локальных коммитов в удаленный TFVS.
     $ git tfs rcheckin
   Замечание: это не сработает, если требуется наличие Check-in Notes. Это можно обойти, добавив
   git- tfs-force  :  rcheckin в сообщение коммита.
