Раздел 1 2.9. Настройка команды git-pull для автоматического
выполнения rebase вместо команды merge
   Если ваша команда придерживается рабочего процесса, основанного на перемещениях,
возможно, будет выгодно настроить git таким образом, чтобы во время выполнения коман
ды git pull каждая вновь созданная ветка выполняла операцию перемещения - rebase,
а не операцию слияния - me rge.
   Чтобы настроить автоматическое перемещение каждой новой ветки, добавьте в файл
.gitconfig или в файл   . git/config следующие строки:
           [ b ranch ]  .
    autosetuprebase = always
   Командная строка: git config    [ --global ] branch  . autosetuprebase always
   В качестве альтернативы можно настроить команду gi t pull так, чтобы она всегда вела
себя, как если бы бьша передана опция -- rebase  :
           [ pull ]  .
    rebase = true
   Командная строка: git config   [ --global ] pull  . rebase true

Раздел 1 2.1 О. Отправка локальной ветки в удаленный
репозиторий после процедуры перемещения
   Иногда требуется переписать историю версий при перемещении, но gi t  push может
не сработать, потому что вы переписали историю.
   Эту проблему можно решить с помощью команды git push --force, но можно также
рассмотреть и вариант gi t push  -- force-wi th-lease, указав, что вы хотите, чтобы push
не выполнялся, если локальная ветка, отслеживаемая в удаленном репозитории, отличает
ся от версии ветки в удаленном репозитории. Например, кто-то другой сделал push в удален
ную ветку после последней выборки командой fetch. Это позволит избежать случайной пе
резаписи чужого недавнего push.
   Замечание: команда git push --force -и даже --force-wi th-lease - может быть опасна,
   поскольку она переписывает историю ветки. Если дРуrой человек выполнил команду gi t  pull
    с этой ветки до вызова git push --force, то его git  pull или git  fetch будет содержать
   ошибки, поскольку локальная история и удаленная история не совпадают. Это может привести к не
   ожиданным ошибкам. При тщательном просмотре ссылочных логов (reflog) работа дРуrого пользо
   вателя может быть восстановлена, но это может привести к потере времени. Если вам приходится
   делать gi t push --fo rce в ветку с другими участниками, постарайтесь скоординировать свои
   действия с ними, чтобы им не пришлось сталкиваться с ошибками.
