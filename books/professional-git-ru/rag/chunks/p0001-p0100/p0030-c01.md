Раздел 5.1 . Игнорирование файлов и каталогов с помощью файла .gitignore                    29
Глава 5. Исключение из отслеживания
отдельных файлов и папок
   В этой теме показано, как избежать добавления в репозиторий нежелательных фай
лов (или изменений файлов). Существует несколько способов (глобальный или локальный
 . gitignore ,     . git/exclude , git update-index -- assume-unchanged и git update-index -
skip-t гее), но следует помнить, чго Git управляет содержимым, а это означает, чго фактически
игнорируется именно содержимое папок (то есть файлы). Пусть1е папки будут игнорироваться
по умолчанию, так как они все равно не могут бьггь добавлены под контроль версий.

Раздел 5.1 . Игнорирование файлов и каталогов
с помощью файла .gitignore
  Вы можете заставить Git игнорировать определенные файлы и каталоги, то есть ис
ключить их из отслеживания Git, создав в вашем репозитории один или несколько файлов
 . gitigno re. Более подробная информация о файлах .gitignore приведена на ресурсе https://
git-scm.com/docs/gitignore.
   В программных проектах файл  . g i t ig по ге обычно содержит список файлов и/или ката
логов, которые создаются в процессе сборки или во время запуска программы. Записи в фай
ле   . gi tigno ге могут включать имена или пути, указывающие на:
        1.  Временные ресурсы, например, кэши, файлы журналов, скомпилированный код и т. д.
        2.  Локальные файлы конфигурации, которые не должны передаваться другим разра
         ботчикам.
        3.  Файлы, содержащие секретную информацию, например, пароли для входа в систе
          му, ключи и учетные данные.
   При создании в каталоге верхнего уровня правила будут рекурсивно применяться ко всем
файлам и подкаталогам во всем хранилище. При создании в подкаталоге правила будут при
меняться к данному каталогу и его подкаталогам.
   Если файл или каталог является игнорируемым, то он не будет:
         1.   Отслеживаться с помощью Git.
        2.  Фигурировать в результатах работы таких команд, как gi t status или gi t di ff .
        3.  Индексироваться с помощью таких команд, как gi t add -А .
   В необычном случае, когда необходимо игнорировать отслеживаемые файлы, следует
проявить особую осторожность. См: как игнорировать файлы, которые уже были зафикси
рованы в Git-репозитории.
  Примеры
   Приведем несколько общих примеров правил в файле   . gitigno re, основанных на ша-
блонах с применением метасимволов (https://en.wikipedia.org/wiki/Glob_(programming)):
    # Строки ,  начинающиеся с   ' # '  ,  являются комментариями  .
    # Игнорировать файлы с именем     ' file . ext  '
    file . ext
    # Комментарии не могут находиться в одной строке с правилами  !
    # Следующая строка игнорирует файлы с именем     ' file  . ext # не комментарий '
    file . ext # не комментарий
    # Игнорирование файлов с полным путем  .
    # Это также справедливо для файлов в корневом каталоге и подкаталогах тоже .
    # т . е . othe rfile . ext будет игнорироваться в любом месте дерева  .
    dir/othe rdir/file . ext
    othe rfile . ext
