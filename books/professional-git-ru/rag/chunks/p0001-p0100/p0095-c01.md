94                                         Глава 23. Извлечение кода из репозитория. Команда pull
Раздел 23.1 . Извлечение изменений в локальный репозиторий
   Простая выгрузка
   Когда вы работаете с удаленным репозиторием (например GitНub) вместе с кем-то дру
гим, в какой-то момент вам понадобится поделиться с ним своими изменениями. После того
как другие разработчики вьmожили свои изменения в удаленный репозиторий, вы можете
получить эти изменения путем извлечения из этого репозитория.
    git pull
   В большинстве случаев эта команда заканчивается успешно.
  Извлечь дюmые из тобого удаленного репозитория wm ветви.
  Вы можете извлекать изменения из любого удаленного репозитория или ветки, просто
указав в команде их имя:
    git pull origin featu re-A
   Будет извлечена ветка featu ге-А из ветки о rigin, расположеной на сервере, в вашу ло
кальную ветку. Обратите внимание, что вместо имени удаленного сервера можно напрямую
указать URL, а вместо имени ветки - имя объекта, например, хеш SHA коммита.
  Извлечение данных вручную
   Чтобы имитировать поведение  git  pull, можно использовать gi t   fetch, а затем
git merge
     git fetch origin         # получение объектов и обновление ссылок из origin
    git merge origin/featu re-A      # фактически выполнить слияние
   Это повышает уровень контроля над процессом и позволяет проверить удаленную вет
ку перед слиянием с ней. Действительно, после запуска команды fetch вы можете просмо
треть удаленные ветки с помощью git branch  -а, проверить, и если надо выполнить ряд
подготовительных операций (ввести изменения, что-то отредактировать и т. д.). Вот набор
команд, который позволяет это сделать:
    git checkout -Ь local-branch-name origin/featu re-A   # просмотр ветки ,
    # внесение коммитов ,  выполнение объединений коммитов ,
    # их исправлений  и т . д . проверка удаленной ветки
    git checkout merging-branches   # перемещение в целевую ветвь
    git merge local-branch-name     # выполнение слияния
   Это может быть очень удобно при обработке запросов на выгрузку.

Раздел 23.2. Обновление с учетом локальных изменений
   При наличии локальных изменений команда gi t pull прерывает выполнение с сооб-
щением об ошибке:

     error: Your local changes to the following files would Ье overwritten Ьу merge
   #ошибка: Ваши локальные изменения в следующих файлах будут перезаписаны в результате слияния
   Для возобновления работы и обновления содержимого ветки (подобно тому, как это дела-
ет svn update с subversion) можно выполнить команду:
    git stash
    git pull -- rebase
    git stash рор
   Однако гораздо удобнее задать псевдоним с помощью:
