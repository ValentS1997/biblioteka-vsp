38                                Глава 5. Исключение из отслеживания отдельных файлов и папок
Раздел 5.1 4. Игнорирование изменений
в отслеживаемых файлах [stub]
   Механизм, связанный с применением файлов   . gi tigno re и   . gi t /info/exclude, работа
ет только для неотслеживаемых файлов. Об этом более подробно можно почитать по адресу
https://git-scm.com/docs/gitignore.
   Чтобы установить флаг игнорирования для отслеживаемого файла, используйте коман
ду update-index:
    git update-index  - - skip-wo rkt ree myfile . c
   Чтобы отменить игнорирование, используйте:
    git update-index  - - no-skip-wo rkt ree myfile . c
  Вы можете добавить этот фрагмент в свою глобальную конфигурацию Git, чтобы затем
применить более удобные команды, такие как gi t hide, gi t unhide и gi t hidden:
           [ alias ]
        hide = update- index  - - skip-wo rkt ree
       unhide = update- index  - - no-skip-wo rkt ree
       hidden  =  "  ! git ls-files -v        I  g rep  л [ hsS ]         1  cut -с 3 - "
   С документацией по команде  update- index вы можете  озакомиться по  адресу
https://git-scm.com/docs/git-update-index. Документацию по глобальному файлу конфигурации
вы можете найти по адресу https://git-scm.com/docs/git-config.
   Также можно использовать параметр  - -assume-unchanged с функцией update- index:
    git update-index  - -assume-unchanged <file>
   Если понадобится снова просмотреть этот файл на предмет изменений, используйте команду:
    git update-index  - - no-assume-unchanged <file>
   При указании параметра --as sume-u пс hanged пользователь обязуется не изменять файл
и разрешает Git считать, что файл рабочего дерева соответствует тому, что записано в индек
се. Git не справится с задачей, если ему вдруг понадобится изменить этот файл в индексе, на
пример, при слиянии в коммите; таким образом, если предполагаемый не отслеживаемый
файл будет изменен выше по ветке, вам придется обрабатывать ситуацию вручную. В этом
случае основное внимание уделяется производительности.
   Параметр  - - skip-wo rkt ree полезен в том случае, когда вы указываете Git не трогать
конкретный файл, поскольку он будет изменен локально, а вы не хотите случайно зафик
сировать эти изменения (например, файл конфигурации/свойств, настроенный для кон
кретного окружения). Параметр - -skip-wo rkt ree имеет приоритет над assume-unchanged
в том случае, когда установлены оба эти параметра.

Раздел 5.1 5. Удаление уже зафиксированных в истории версий
файлов, включенных в файл .gitignore
   Иногда случается так, что файл отслеживался  Git, но впоследствии был добавлен
в файл   . gitigno ге, чтобы игнорировать его дальнейшие изменения. Очень часто бывает,
что перед добавлением в   . gi tignore такие файлы забывают удалить. В этом случае старый
файл все еще будет висеть в репозитории.
   Чтобы решить эту проблему, можно выполнить "сухое" удаление всех файлов из репози
тория с последующим добавлением всех файлов обратно. Если у вас нет ожидающих измене
ний файлов и передан параметр - -cached, то эта команда вполне безопасна для выполнения:
    # Удалить все  из индекса   ( файлы останутся в файловой системе)
     $ git rm -г --cached
