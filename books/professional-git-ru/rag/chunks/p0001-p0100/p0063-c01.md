62                                                       Глава 1 2. Перемещение (команда rebase)
Раздел 1 1 .7. Обновление кода при сохранении линейной истории
   Иногда требуется вести линейную (не ветвящуюся) историю фиксаций кода. Если вы ра
ботаете над веткой в течение некоторого времени, это может быть затруднительно, посколь
ку вы должны регулярно делать gi t  pull , и в этом случае будет зафиксировано слияние
с основной веткой:
           [ alias ]
        up = pull  - - rebase

   Выполнение этой команды обновит удаленный репозиторий, а затем последовательно
добавит все не добавленные ранее версии вашего проекта на вершину основной ветки уда
ленного репозитория поверх добавленных ранее.
   Для использования:
    git up

Раздел 1 1 .8. Отменить индексирование ранее
проиндексированных файлов
   Обычно для удаления файлов, проиндексированных и отправленных на фиксацию, при
менялась команда gi t reset commi t. Команда reset имеет множество функций, зависящих
от заданных ей аргументов. Чтобы полностью отменить индексацию проиндексированных
ранее файлов, мы можем использовать команду g i t aliases, создав прежде новый псевдо
ним, использующий команду reset с необходимыми аргументами. И теперь нам не нужно
будет помнить о необходимости предоставить правильные аргументы для команды reset.
    git config --global alias  . unstage  " reset  - - •  .
   Теперь в любой момент, когда вы захотите отменить индексирование, ранее проиндекси
рованных файлов, введите команду git unstage.

Глава 1 2. Перемещение (команда rebase)
   Параметр        Подробности
    - - continue      Перезапустить процесс перемещения после разрешения конфлик
                    та слияния.
    - -abo rt          Прервать операцию перемещения и сбросить указатель HEAD на исход
                ную ветку. При отмене незавершенной операции указатель HEAD будет
                    указьmать на ветку, которая бъта выбрана в качестве параметра для ко
                 манды rebase. В противном случае HEAD будет указьmать туда, куда
                   он указывал на момент начала операции rebase. Говоря простыми
                    словами, вернуться в состояние до использования команды rebase.
    - - keep-empty    Сохранять в результатах пустые коммиты, то есть те коммиты, ко
                  торые ничего не меняют по отношению к родителю.
    - - skip           Перезапустить процесс перемещения, пропустив текущий патч.
    -m,  - -me rge     Использовать стратегии слияния для перемещения. Если использу
                      ется рекурсивная стратегия слияния (по умолчанию), это позволяет
                 перемещению быть в курсе переименований на стороне удаленно
                      го репозитория. Обратите внимание, что слияние rebase работа
                     ет следующим образом: происходит передача каждого коммита
