Раздел 8.3. Остановка слияния
   После запуска слияния вы можете захотеть остановить слияние и вернуть всё в состоя
ние, предшествовавшее слиянию. Для этого используйте команду --abort:
    git merge --abort
Раздел 8.4. Слияние с коммитом
   По умолчанию, когда слияние выполняется как быстрое, обновляется только указатель
ветви, без создания коммита слияния. Для принудительного выполнения коммита слияния
используйте --no-ff:
    git merge cbranch_name> --no-ff -m "ссообщение_коммита>"
Раздел 8.5. Сохранять информацию только об одной
из ветвей сторон, участвующих в слиянии
   Во время слияния вы можете передать в g i t checkout команду --ou г s или ---t he i rs ,
чтобы принять все изменения для файла с одной или другой стороны слияния:
     $ git checkout --ou rs -- file1  . txt     # Использовать нашу версию истории
    # изменений для file1  , удалить все изменения другого участника слияния
     $ git checkout --theirs  -- file2 . txt   # Использовать версию file2 ,
    # удалить все наши собственные изменения

Раздел 8.6. Слияние двух ветвей, одна из которых текущая
    git merge incomingBranch
   При этом ветка incomingBranch объединяется с веткой, в которой вы находитесь в дан
ный момент. Например, если в данный момент вы находитесь в ветке master, то ветка
incomingBranch будет объединена с веткой master .
   В некоторых случаях слияние может привести к конфликтам. В этом случае появится
сообщение Automatic  merge  failed ;  fix  conflicts  and  then  commit  the  result
(Ошибка автоматического слияния; устраните конфликты и зафиксируйте результат) . Вам
придется вручную отредактировать конфликтующие файлы или отменить попытку слия
ния, выполнив команду:
    git merge --abort
