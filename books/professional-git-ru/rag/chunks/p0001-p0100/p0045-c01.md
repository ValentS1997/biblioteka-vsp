44                                                                   Глава 7. Отмена изменений
   Для отката к предыдущему коммиту с сохранением изменений выполните команду:
    git reset --soft 789abcd
   Откат к последнему коммиту:
    git reset --soft HEAD~
   Чтобы окончательно отменить все изменения, сделанные после определенного коммита,
используйте команду:
    git reset --hard 789abcd
   Чтобы окончательно отменить все изменения, сделанные после последнего коммита:
    git reset --hard HEAD~
   Осторожно: если отмененные коммиты можно восстановить с помощью reflog  и
reset, то незафиксированные изменения восстановить невозможно. Для безопасности ис
пользуйте gi t stash ; gi t reset вместо gi t reset --ha rd.
Раздел 7 .2. Отмена изменений
   Отменить изменения файла или каталога в рабочей копии можно при помощи команды:
    git checkout -- file  . txt
   Используется по всем путям к файлам, рекурсивно от текущего каталога, и отменяет все
изменения в рабочей копии:
    git checkout --
   Для отмены только части изменений используйте команду --patch. Для каждого изме
нения будет задан вопрос, следует ли его отменять или нет:
    git checkout --patch -- dir
   Для отмены изменений, добавленных в индекс, можно воспользоваться командой:
    git reset --hard
    Без параметра --ha rd будет выполнен мягкий сброс.
   С локальными коммитами, которые еще предстоит отправить на удаленный сервер, так
же можно выполнить мягкий сброс. Таким образом, вы можете сначала внести изменения
в файлы, а затем в коммиты:
    git reset HEAD~2
   Приведенный выше пример отменит два последних коммита и вернет файлы в вашу ра
бочую копию. После этого можно вносить дальнейшие изменения и делать новые коммиты.
   Осторожно: все эти операции, за исключением мягкого сброса, приведут к безвозврат
ному удалению изменений. Для более безопасного варианта используйте git  stash  -р
или gi t stash соответственно. Впоследствии вы сможете отменить изменения при помощи
команды stash рор или удалить их навсегда при помощи stash d гор.

Раздел 7 .3. Использование reflog
   Если вы запутались в операции перемещения (rebase) коммитов или веток, то одним
из вариантов начать всё сначала является возврат к коммиту (до перемещения).
   Это можно сделать при помощи ссылочного лога  reflog  (в ссылочном логе хранится
история всех ваших действий за последние 90 дней - это можно настроить):
     $ git reflog
    4а5сЬЬ3 HEAD@{0}  :  геЬаsе finished  :  retu rning to refs/heads/foo
    4а5сЬЬ3 HEAD@{1 }  :  геЬаsе  : fixed such and such
