Раздел 24.З. Автоматическое перенаправление команд push
в другой репозиторий
   Перехватчики post- receive  могут быть использованы для автоматического перена-
правления входящих pushes в другой репозиторий:
     $ cat     . git/hooks/post- receive
    # ! /bin/bash
    IFS= '
    while read local_ ref local_sha remote_ ref remote_sha
    do
       echo "$remote_ ref"        1 egrep     • л гefs\ /heads\ / [A-Z ] +- [ 0-9 ] +$ ' >/dev/null &&
     {
             ref= ' echo $remote_ ref        I  sed -е     ' s/ л гefs\ /heads\ / //  '  '
            echo Forwa rding featu re branch to othe r repository : $ref
            git push -q --force othe r_repos $ref
       }
    done
   В данном примере регулярное выражение eg гер отыскивает определенный формат ветки (здесь: формат, соответствующий JIRA-12345, ветка, куда Jira отправляет все фрагменты,
связанные с ошибками). Конечно, можно не указывать эту часть, если требуется направить
вывод команды push во все ветки.

Раздел 24.4. Перехватчик commit-msg
   Этот перехватчик аналогичен перехватчику prepare-commit-msg, но вызывается по
сле ввода пользователем сообщения коммита, а не перед этим. Обычно он используется
для предупреждения разработчиков о том, что их сообщение коммита имеет неправильный
формат.
   Единственным аргументом, передаваемым этому перехватчику, является имя файла,
содержащего сообщение. Если вам не нравится сообщение, введенное пользователем, вы
можете либо изменить этот файл на месте (аналогично тому, как это делает перехватчик
prepa re-commit-msg), либо полностью прервать процесс коммита, выйдя из него с ненуле
вым статусом.
   Следующий пример используется для проверки наличия в сообщении коммита слова
"ticket", за которым следует число:
    word="ticket   [ 0-9 ] "
    isPresent=$ (grep -Eoh "$word"  $1 }
     if   [ [  -z $isPresent   ] ]
       then echo "Commit message КО ,  $word is missing"  ; exit  1  ;
       else echo "Commit message ОК"  ; exit 0 ;
    fi
