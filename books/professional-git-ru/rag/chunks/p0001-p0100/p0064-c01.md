Раздел 1 2.1 . Перемещение ветвей в локальном репозитории
   При перемещении серия коммитов одной ветки накладьmается поверх коммита на другой
ветке. Чтобы переместить ветку, сделайте ее текущей, а затем переместите поверх другой ветки:
    git checkout topic
    git rebase master        # переместить текущую ветку topic на ветку master
   Это может привести к:
                  topic       А---в---с      /
    D---E---F---G master
   Превратиться в:
               A ' --B  ' --C ' topic
      /
    D---E---F---G master
   Эти операции могут быть объединены в одну команду, которая делает ветвь для переме
щения текущей ветвью и сразу же перемещает ее:
    git rebase master topic         # перемещает ветвь topic в ветвь master
   Важно: после перемещения переотправленные коммиты будут иметь другой хеш.
Не следует переотправлять коммиты, которые вы уже отправили на удаленный репозито
рий. Следствием этого может стать невозможность выполнения команды g i t push локаль
ной ветки и ее перемещения в удаленный репозиторий. Единственным выходом в этом слу
чае станет запуск комады gi t push --force .
   Более подробно о команде rebase можно узнать из документации, расположенной
по адресу https://git-scm.com/docs/git-rebase.

Раздел 1 2.2. Перемещение: "наша" и "их", локальная ветка
и удаленная ветка
   Перемещение меняет местами понятия "наше" и "их":
    git checkout topic
    git rebase master        # перемещает ветку topic на вершину ветки master
   Все, на что указывает HEAD, - "наша"
