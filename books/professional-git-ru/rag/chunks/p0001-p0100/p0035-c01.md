Раздел 5.6. Игнорирование файлов локально без фиксации
правил игнорирования
          . gitignore игнорирует файлы локально, но он предназначен для фиксации в репози
тории и обмена с другими контрибьюторами и пользователями. Можно задать глобальный
 . gi tigno re, но тогда все ваши репозитории будут совместно использовать эти настройки.
   Если вы хотите локально игнорировать определенные файлы в хранилище и не делать
их частью какого-либо еще хранилища, отредактируйте файл   . git/info/exclude внутри
вашего репозитория. Например:
    # эти файлы игнорируются только в данном репозитории
    # эти правила никому не передаются ,
    # так как они являются локальными
    gtk_tests . py
    gui/gtk/tests/*
    localhost
    pushRepo rts . py
    se rve r /

Раздел 5.7. Игнорирование последующих изменений файла
(без его удаления)
   Иногда требуется, чтобы файл хранился в Git, но система контроля версий игнорировала
последующие изменения в нем. Укажите Git игнорировать изменения в файле или каталоге
с помощью команды update- index:
    git update-index  - -assume-unchanged my-file . txt
   Приведенная выше команда предписывает Git считать, что файл my- file . txt не был
изменен и что его не надо проверять и не надо сообщать об изменениях в нем. Файл по-преж
нему присутствует в репозитории.
   Это может быть полезно для предоставления настроек по умолчанию и разрешения ло-
кальных переопределений окружения, например:
    # создать файл с некоторыми значениями в
    cat <<EOF MYSQL_USER=app
    MYSQL_PASSWORD=FIXME_SECRET_PASSWORD
     EOF  >     . env
    # commit to Git
    git add     . env
    git commit -m "Добавление шаблона     . env"
    # игнорировать будущие изменения  в     . env
    git update-index  - -assume-unchanged     . env
    # обновить пароль
    vi     . env
    # без изменений  !
    git status
