83Раздел 1 7.1  . Копирование коммитов из одной ветки в другую
Глава 1 7. Команда cherry-pick
   Параметры   Пояснения
    -е, --edit  При использовании этой опции команда git cherry-pick позволит вам
               редактировать сообщение коммита перед фиксацией.
             При записи коммита добавляет к оригиналу строку "(cherry picked from   -х
               commit   ... )". Это сообщение коммита указывает, из какого коммита бьшо
                взято данное изменение для команды git cherry-pick . Действует толь
               ко для неконфликтных коммитов.
   --ff        Если текущий указатель HEAD  совпадает  с родительским коммитом
               che г ry-pick, то будет выполнен быстрый переход к этому коммиту.
   --continue Продолжить выполняемую операцию, используя информацию из фай
               ла    . git/sequencer. Может применяться для указания продолжать ра
                боту после разрешения конфликтов даже в том в случае, если команды
               cherry-pick или revert закончились неудачей.
   --quit      Забыть о текущей выполняемой операции. Этот параметр может быть ис
               пользован для очистки состояния секвенсора после неудачного заверше
             ния комад cherry-pick или revert.
   --abort    Отменить операцию и вернуться в исходное состояние.

   Cherry-pick берет исправление, которое бьшо внесено в коммит и сохранено в патче,
и пытается повторно применить его к ветке, на которой вы сейчас находитесь.
   Более подробно об особенностях команды git  cherry-pick можно узнать, перейдя
по ссылке https://git-scm.com/Ьook/en/v2/Distributed-Git-Maintaining-a-Project.

Раздел 1 7 .1 . Копирование коммитов из одной ветки в другую
   Команда git cherry-pick <commit-hash> применяет изменения, сделанные в суще
ствующем коммите, к другой ветке, одновременно записывая новый коммит. По сути, вы мо
жете копировать коммиты из ветки в ветку.
   Далее будет рассмотрен пример, в основу которого бьша взята статья по адресу
https://www.devroom.io/2010/06/10/cherry-picking-specific-commits-from-another-branch/.  Исход-
ные данные для примера были взяты из этой статьи.
   Пусть у нас имеется следующее дерево:

    dd2e86 - 946992 - 91 43а9 - a6fd86 - 5а6057   [ master ]
                     \
               76cada - 62есЬ3 - Ь886а0   [ featu re ]

   Допустим, мы хотим скопировать коммит Ь886а0 в ветку master (поверх коммита 5а6057).
Тогда мы можем выполнить команду:
    git checkout master
    git cherry-pick Ь886а0
   Теперь наше дерево истории версий будет выглядеть примерно так

    dd2e86 - 946992 - 91 43а9 - a6fd86 - 5а6057 - а66Ь23  [master ]
                     \
               76cada - 62есЬ3 - Ь886а0   [ featu re ]

   Здесь новый коммит а66Ь23 имеет то же содержание (исходную дельту diff, сообщение
коммита), что и в коммите Ь886а0 (но уже с другим предыдущим коммитом-родителем). За
метим, что cherry-pick заберет только изменения в этом коммите (в данном случае в ком
мите Ь886а0), а не все изменения в ветке feature (для этого нужно использовать либо пере
мещение, либо слияние).
