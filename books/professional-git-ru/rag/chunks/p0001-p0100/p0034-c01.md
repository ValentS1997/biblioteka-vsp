Раздел 5.5. Как игнорировать файлы, которые уже были зафиксированы в Git-репозитории        зз
          ван, так как игнорируемые файлы будут выгружаться в репозиторий все то вре
         мя, пока ПК с глобальным   . gitignore не будет обновлен. Именно поэтому, если
        над проектом работает команда, лучше использовать   . gi tignore для конкретно
          го локального репозитория, чем глобальный.
   Глобальный файл - это отличное место для хранения правил игнорирования специфи
ческих для платформы, машины или пользователя файлов, например, файлов .DS_Store
в случае OSX, Thumbs  . db в случае Windows или файлов *  . ext~ и * . ext  . swp в случае Vim,
если вы не хотите хранить их в репозитории. И, таким образом, один член команды, рабо
тающий на OS Х, может добавить в глобальный .gi tignore все эти по-настоящему бесполез
ные файлы   . DS_STORE и _MACOSX, а другой член команды, работающий с Windows, может до
бавить в него все thumbs  . bd.
   Более подробно о глобальном файле   . gi tignore можно узнать в докуметации по адресу
https://help.github.com/articles/ignoring-files/#create-a-global-gitignore.

Раздел 5.5. Как игнорировать файлы, которые уже были
зафиксированы в Git-репозитории
   Если вы уже добавили файл в свой Git-репозиторий и теперь хотите прекратить его от
слеживание (то есть чтобы он не присутствовал в будущих коммитах), вы можете удалить
его из индекса:
    git rm --cached <file>
   В результате файл будет удален из репозитория, и дальнейшие изменения не будут отсле
живаться Git. Параметр -cached гарантирует, что файл не будет удален физически.
   Обратите внимание, что ранее добавленное содержимое файла по-прежнему будет вид
но в истории Git.
   Следует иметь в виду, что если после удаления файла из индекса кто-то еще возьмет его
из хранилища, то у него его копия будет физически удалена.
   С помощью параметра skip wo rkt гее можно заставить Git делать вид, что версия фай
ла в рабочем каталоге актуальна, и читать вместо нее проиндексированную версию (тем са
мым игнорируя изменения в ней):
    git update-index --skip-workt ree <file>
   Документацию по применению этого параметра вы можете найти по адресу https://www.
kernel.org/pub/software/scm/git/docs/git-update-index.html#_skip_worktree_Ьit.
   На физическое состояние файла этот параметр не влияет, безопасность содержи
мого остается на первом месте. Вы никогда не потеряете файл со своими драгоценны
ми игнорируемыми сейчас изменениями; с другой стороны, этот параметр конфликтует
с созданием "тайников". Чтобы удалить этот параметр, используйте команду:
    git update-index --no-skip-workt ree <file>
   Иногда ошибочно рекомендуют обманывать Git и заставлять его считать, что файл неиз
менен, не проверяя его. На первый взгляд это выглядит как игнорирование любых дальней
ших изменений файла, без удаления его из индекса:
    git update-index --assume-unchanged <file>
   Это заставит Git игнорировать все изменения, сделанные в файле (имейте в виду, что если
вы внесете какие-либо изменения в этот файл или спрячете его, то проигнорироваш1ые из
менеIШЯ, учитываемые Gitoм ранее, будут потеряны).
   Если вы хотите, чтобы Git снова стал "заботиться" об этом файле, выполните следующую
команду:
    git update-index --no-assume-unchanged <file>
