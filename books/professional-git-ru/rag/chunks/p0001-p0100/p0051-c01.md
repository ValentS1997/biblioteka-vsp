50                                                                             Глава 9. Подмодули
   Это приведет к клонированию подмодулей, входящих в состав большого проекта, и раз
мещению их в соответствующих папках (включая подмодули внутри подмодулей). Это экви
валентно выполнению git submodule update --init  --  recu rsive сразу после завер
шения клонирования.

Раздел 9.2. Обновление подмодуля
   Подмодуль ссьmается на определенный коммит в другом репозитории. Чтобы проверить
точное состояние, на которое ссьmаются все подмодули, выполните команду:
    git submodule update -- recu rsive
   Иногда вместо использования состояния, на которое есть ссьmка, требуется обновить ло
кальный подмодуль до последнего актуального состояния подмодуля, содержащегося в уда
ленном репозитории. Чтобы проверить все подмодули на соответствие их состояния послед
нему актуальному состоянию в удаленном репозитории с помощью одной команды, можно
использовать:
    git submodule foreach git pull  < remote> <branch>
... или воспользоваться стандартными параметрами команды gi t pull:
    git submodule foreach git pull
   Обратите внимание, что при этом будет обновлена только локальная рабочая копия. За
пуск git status отобразит каталог подмодуля в виде грязного состояния в своем рабочем
каталоге, если он изменился в результате выполнения этой команды. Чтобы обновить репо
зиторий и затем ссылаться на новое состояние, необходимо выполнить коммит произошед
шего изменения:
    git add <submodule_directory>
     git commit
   Возможно, некоторые ваши изменения могут конфликтовать при слиянии, если вы ис
пользуете команду git рull, поэтому вы можете использовать git pull -- геЬаsе для пе
ремотки ваших изменений в конечное состояние, в большинстве случаев это уменьшает ве
роятность конфликта. Также эта команда копирует все ветки в локальную копию подмодуля:
    git submodule foreach git pull -- rebase
   Чтобы проверить последнее состояние конкретного подмодуля, можно использовать ко
манду:
    git submodule update -- remote <submodule_directory>
Раздел 9.3. Добавление подмодуля
  Вы можете включить другой Git-репозиторий в состав своего проекта в качестве новой
папки, отслеживаемой Git:
     $ git submodule add https  : //github . com/j query/j query . git
   Необходимо добавигь и зафиксировать новый файл   . gi tmodules; он указывает Git, какие
подмодули должны быть клонированы при выполнении команды gi t submodule update .
Раздел 9.4. Привязка отслеживания подмодуля
к отслеживанию всей ветви
   Подмодуль всегда проверяется по определенному коммиту с хешем SHAl ("gitlink", специ
альная запись для него в индексе родительского репозитория). Но можно запросить обнов
ление этого подмодуля до последнего коммита ветки этого подмодуля, находящегося в уда
ленном репозитории.
