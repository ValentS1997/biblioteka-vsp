Раздел 9.6. Удаление подмодуля
   Версия > 1.8.
   Удалить подмодуль (например the_submodule) можно с помощью вызова следующих
команд:

     $ git submodule deinit the_submodule
     $ git rm the_submodule

     •   git submodule deinit the_submodule удаляет запись the_submodules из файла
        конфигурации   . git/config. Это исключает подмодуль the_submodule из вызовов
         gi t submodule update, gi t submodule sync и gi t submodule foreach и удаля
         ет его локальное содержимое. Кроме того, это не будет отображено как изменение
         в родительском репозитории. Команды git  submodule  init и git submodule
         update восстановят подмодуль, опять же без отображения изменений в родитель
        ском репозитории.
   С документацией по командам просмотра подмодулей можно ознакомиться на сайте
https://git-scm.com/docs/git-submodule#git-submodule-deinit.
     •   git rm the_submodule удалит подмодуль из рабочего дерева. При этом исчезнут
       и файлы, и запись подмодуля в файле  . gi tmodules. Если выполнить только gi t rm
        the_submodule  (без предварительного git submodule deinit the_submodule),
         то запись подмодулей в файле   . gi t/ config останется.
   С документацией по командам удаления подмодулей можно ознакомиться на сайте
https://git-scm.com/docs/git-rm#_submodules.
   Версия < 1.8.
        1.  Удалите соответствующую секцию из файла   . gi tmodules .
         2.  Проиндексируйте  изменения  в      . gi tmodules    путем выполнения команды
        git add     . gitmodules.
        3.  Удалите соответствующую секцию из   . git/config.
       4.  Выполните команду git rm --cached path_ to_submodule (без слэша в конце).
        5.  Выполните команду rm  - гf     . git/modules/path_ to_submodule.
        6.  Выполните команду git commit -m "Удален субмодуль <имя > " .
        7.  Удалите теперь уже не отслеживаемые файлы подмодулей.
       8.   rm  - гf path_to_submodule .
  Данный пример взят с сайта StackOverflow (https://stackoverflow.com/questions/1260748/
how-do-i-remove-a-suЬmodule/1260982#1260982).

   --message ,  -m              Сообщение для включения в коммит. Указание этого па
                               раметра позволяет обойти обычное поведение Git с ав
                             томатическим запуском текстового редактора для ввода
                             сообщения коммита.
   --amend                      Указывает, что изменения, находящиеся в текущей ста
                                 дии, должны быть добавлены (изменены) в предыдущий
                               коммит. Будьте осторожны, это может переписать исто
