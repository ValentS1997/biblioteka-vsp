66                                                       Глава 1 2. Перемещение (команда rebase)

   Как только в области индексирования появятся все изменения, которые вы хотели вне
сти в этот коммит, зафиксируйте изменения. При этом отобразится старое сообщение ком
мита, которое может быть отредактировано для отражения сути нового коммита.
   Разбиение одного коммита на несколько коммитов
   Допустим, вы сделали коммит, но позже решили, что этот коммит можно разбить на два
коммита или более. Используя ту же команду, что и раньше, замените pick на edit и нажми
те Enter.
   Теперь Git остановится на коммите, который вы отметили для редактирования, и поме
стит все его содержимое в область индексирования (staging). После этого вы можете выпол
нить команду git  reset НЕдDл, чтобы поместить коммит в рабочий каталог. Затем можно
индексировать и фиксировать файлы в другой последовательности в конечном счете, разби
вая один коммит на п коммитов.
  Объединение нескольких коммитов в один общий
   Допустим, вы выполнили некоторую работу и сделали несколько коммитов, которые,
по вашему мнению, можно было бы заменить одним. Для этого вы можете выполнить
gi t rebase -i НЕАD~З, заменив 3 на соответствующее количество коммитов.
   На этот раз замените pick на squash. Во время выполнения команды rebase коммит, ко
торому вы указали быть объединенным, будет объединен с предыдущим коммитом, превра
тив их в один коммит, и записан поверх него.

Раздел 1 2.4. Откат до начальной фиксации при помощи
команды rebase
   Начиная с версии Git 1.7.12 стало возможным выполнять перемещение вплоть до корне
вого коммита. Корневой коммит является первым коммитом в репозитории и обычно не мо
жет быть отредактирован. Используйте следующую команду:
    git rebase -i  - - root
Раздел 1 2.5. Настройка autostash
   Autostash - очень полезная опция конфигурации при использовании rebase для ло
кальных изменений. Часто бывает так, что вам нужно перенести коммиты из удаленной
ветки, но вы еще не готовы сделать коммит.
   Однако Git не позволяет начать перемещение, если рабочий каталог не очищен. На по
мощь приходит autostash:
    git config --global rebase . autostash   # однократная конфигурация
    git rebase @{u}    # пример выпполения  rebase на удаленной ветке upst ream
   Autostash будет выполняться до тех пор, пока не завершит свою работу команда rebase.
При этом не имеет значения, завершилось ли перемещение успешно или будет прервано.
Autostash будет применен в любом случае. Если перемещение прошло успешно, но базовый
коммит при этом изменился, то может возникнуть конфликт между autostash и новыми
коммитами. В этом случае необходимо разрешить конфликт перед тем, как сделать коммит.
   Это ничем не отличается от того, как если бы вы вручную сохранили информацию, а за
тем восстановили, поэтому ничто не мешает делать то же самое автоматически.

Раздел 1 2.6. Тестирование всех коммитов во время процесса
перемещения
   Прежде чем выполнить команду pull  request, полезно убедиться в успешной компи
ляции и прохождении тестов для каждого коммита в ветке. Мы можем сделать это автома
тически с помощью параметра -х.
   Например:
    git rebase -i  -х make
