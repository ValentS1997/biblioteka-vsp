Раздел 1 8.1 . Восстановление после сброса
   С помощью Git можно (почти) всегда повернуть время вспять.
   Не бойтесь экспериментировать  с командами, переписывающими журнал версии  .
По умолчанию Git не удаляет ваши коммиты в течение 90 дней, и на протяжении этого вре
мени вы можете легко восстановить их из ссылочного журнала reflog:
     $ git reset @~З  # вернуться  на 3 коммита назад
     $ git reflog
    c4f708b HEAD@{0}  :  reset  : moving to @~З  # сброс : перемещение на 3 коммита назад
    2с52489 HEAD@ { 1 }  :  commi t  : more changes # коммит : больше изменений
    4a5246d HEAD@{2 }  : commit  : make impo rtant changes  # коммит : внести важные
                                                      # изменения
     е8571 е4 НЕАD@{З }  : commi t  : make some changes # коммит : внести некоторые изменения
               .   .   . более ранние коммиты
     $ git reset 2с52489
               .   .   . возвращаемся туда ,  откуда начали вы вернетесь туда ,  откуда начали #

Раздел 1 8.2. Восстановление из git-apxивa
   Чтобы получить самую актуальную информацию после выполнения git stash, используй
те команду:
    git stash apply
   Чтобы просмотреть список своих "заначек", используйте:
    git stash list
  Вы получите список, который выглядит следующим образом:
    stash@{0 }  : WIP оп maste r  : 67а4е01 Merge tests into develop       # Слить тесты в ветку develop
    stash@{1 }  : WIP оп master : 70f0d95 Add user role to localStorage оп user login       # Добавление роли пользователя в localStorage при входе пользователя в систему
   Выбрать другой git-"тайник" для восстановления информации на основе его номера мож
но при помощи команды:
    git stash apply stash@{2 }
  Вы также можете выбрать команду gi t  stash  рор. Она работает так же, как и комада
gi t stash apply, например:
    git stash рор
   или
    git stash рор stash@{2 }
   Разница между командами g i t stash apply и g i t stash рор ...
    git stash рор  :
данные из "тайника" будут взяты с вершины стека, в котором хранятся ссылки на "тайни
ки". Например:
    git stash list

    * При этом следует остерегаться таких параметров, как --hard и - - - fo rce, поскольку они могут
привести к удаленmо данных. Кроме того, избегайте переписывания истории в ветках, над которыми
вы совместно с кем-то работаете.
