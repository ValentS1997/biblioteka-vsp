Раздел 9.5. Перемещение подмодуля                                                           51

   Вместо того чтобы заходить в каждый подмодуль и делать git  checkout  abranch
--t rack origin/abranch ,  git  pull, можно просто запустить (из родительского репози
тория) команду:
    git submodule update -- remote -- recu rsive
   Так как SHA1 подмодуля изменится, вам все равно придется следовать за ним:
    git add
    git commit -m  " обновить подмодули "
   Это предполагает, что подмодули были:
     •   либо добавлены с текущей веткой:
          git submodule -Ь abranch -- /url/of/submodule/ repo
     •   либо настроены (для текущего подмодуля) на отслеживание по ветви:
          cd /path/to/pa rent/ repo
          git config -f     . gitmodules submodule . asubmodule . branch abranch

Раздел 9.5. Перемещение подмодуля
   Версия > 1.8
   Запуск:
     $ git mv /path/to/module new/path/to/module
   Версия , 1.8
        1.  Отредактируйте   . gitmodules, измените путь к подмодулю соответствующим об
        разом и поместите его в индекс с помощью команды gi t add     . gitmodules.
       2.  При необходимости создайте родительский каталог для нового расположения под
        модуля (mkdir -р /path/to).
        3.  Переместите всё содержимое из старого каталога в новый (mv -vi /path/to/module
          new/path/to/submodule).
       4.   Убедитесь, что Git отслеживает этот каталог (gi t add  /path/to).
        5.  Удалите старый каталог с помощью комады git  rm --cached /path/to/module.
        6.  Переместите  каталог       . git/modules//path/to/module  со  всем  его  содержимым
         в .git/modules//path/to/module .
         7.  Отредактируйте файл    . git/modules//path/to/config, убедитесь, что элемент
        workt ree указывает на новые места, поэтому для данного примера в файле кофи
        гурации должна быть строка workt ree =    •  • /  .  • /  .  . /  •  . /  •  • //path/to/module. Как
         правило, должно быть еще два символа подкаталога   .  . затем прямой путь к этому
          месту. Отредактируйте файл /path/to/module/.git, убедитесь, что путь в нем указы
         вает на правильное новое местоположение внутри папки   . gi t основного проек
           та. Для данного примера это gi tdir  :  .  . /  .  . /  .  . /  . gi t/modules/ /path/to/module .
   После этого вывод команды gi t status должен выглядеть следующим образом:
    # Оп branch master
    # Changes to Ье committed  :
    #     ( use "git reset HEAD <file>  .  .  . •  to unstage)
    #
    #         modified  :                   . gitmodules
    #          renamed  :       old/path/to/submodule -> new/path/to/submodule
    #
       8.  Наконец, выполните коммит этого изменения.
