Раздел 12.7. Перемещение перед окончательной подготовкой кода к релизу                   67

   Эта команда запустит rebase в интерактивном режиме и будет останавливаться после
каждого коммита для выполнения команды make. В случае неудачной отработки команды
make Git остановится, чтобы дать вам возможность исправить проблемы и внести поправки
в коммит, прежде чем вы перейдете к следующему коммиту.

Раздел 1 2. 7. Перемещение перед окончательной подготовкой
кода к релизу
  Резюме
   Основная цель такой процедуры, вынесенной в заголовок, - реорганизовать все ваши
разрозненные коммиты в более осмысленные коммиты для облегчения проверки кода. Если
существует слишком много уровней изменений одновременно в большом количестве фай
лов, то проводить Code Review становится сложнее. Если вы сможете реорганизовать хроно
логически созданные коммиты в тематические коммиты, то процесс Code Review станет про
ще (и, возможно, меньше ошибок проскользнет через этот процесс).
   Этот довольно простой пример не является единственной стратегией использования Git
для более качественного анализа кода. Этот способ просто должен вдохновить других на раз
мышления о том, как сделать анализ кода и историю версий Git проще и лучше.
   Это также является учебной демонстрацией возможностей rebase в целом. Этот пример
предполагает, что вы знаете об интерактивном режиме команды rebase.
   Предполагается, что:
      •  вы работаете над веткой функций от master
      •   ваша функция имеет три основных уровня: front-end, back-end, база данных (БД)
      •  вы сделали много коммитов во время работы над веткой функций, причем каж
       дый коммит затрагивает сразу несколько уровей
      •  вы хотите, чтобы (в конечном итоге) в вашей ветке было только три коммита:
          о   один содержит все изменения фронтенда
          о   один содержит все изменения в бэкенде
          о   один содержит все изменения в БД
   Стратегия:
      •  мы собираемся изменить наши хронологические коммиты на "тематические".
      •   во-первых, разделите все коммиты на несколько более мелких коммитов, каждый
         из которых содержит только одну тему (в нашем примере темами являются front
          end, back-end, изменения в БД)
      •   затем необходимо будет переупорядочить наши тематические коммиты и объеди
        нить их в один тематический коммит (по одному на каждый уровень)
   Пример:
     $ git log --oneline master .  .  .
    975430Ь db adding works  : db . sql logic . rb  # добавление работ : db . sql logic . rb
    3702650 t rying to allow adding todo items  : page . html # попытка разрешить
    # добавление элементов todo  : page . html logic . rb
    43Ь075а first d raft page . html и db . sql  # первый набросок : page . html и db . sql
     $ git rebase -i master
   Вот то, что будет отображено в текстовом редакторе при выполнении этой команды:

    pick 43Ь075а first d raft  : page . html and db . sql
    pick 3702650 t rying to allow adding todo items  : page . html logic  . rb
    pick 975430Ь db adding works  : db . sql logic . rb
   Изменим его до вида:

     е 43Ь075а первый проект : page . html и db . sql
