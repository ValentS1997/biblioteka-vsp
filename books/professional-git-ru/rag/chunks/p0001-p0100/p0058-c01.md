Раздел 10.7. Создание пустого коммита                                               57
   При этом будут проиндексированы выбранные вами фрагменты файлов. Затем можно за
фиксировать все проиндексированные изменения следующим образом:
    git commit -m     ' Сообщение коммита '
   Изменения, которые не были проиндексироваы или зафиксированы, по-прежнему будут
отображаться в рабочих файлах, и при необходимости могут быть зафиксированы позже.
Если же оставшиеся изменения нежелательны, их можно отбросить:
    git reset --hard
   Помимо разбиения большого изменения на более мелкие коммиты такой подход также
полезен для проверки того, что вы собираетесь фиксировать. Подтверждая каждое измене
ние по отдельности, вы имеете возможность проверить написанное и избежать случайной
фиксации ненужного кода, например, операторов println/logging.

Раздел 1 О. 7. Создание пустого коммита
   Вообще говоря, пустые коммиты (или коммиты с состоянием, идентичным родительско
му) - это ошибка.
   Однако при тестировании отдельных частей, СI-систем и других систем, запускающих
коммит, удобно иметь возможность легко создавать коммиты без необходимости редакти
ровать/создавать фиктивные файлы.
   Фиксация --allow-empty позволяет обойти эту проверку:
    git commit  -m "Это пустой коммит" --allow-empty
Раздел 1 0.8. Исполнение обязательств от имени другого лица
   Если код, который вы фиксируете, написан кем-то другим, вы можете отобразить этот
факт с помощью опции -- author  :
    git commit  -m  "msg" --author "John Smith <j ohnsmith@example . com> "
  Вы также можете указать шаблон, который Git будет использовать для поиска предыду
щих авторов:
     git commit -m "msg" --author "John"
   В этом случае будет использована информация об авторе из последнего коммита с авто
ром, содержащим имя "J ohn".
   На GitHub коммиты, сделанные любым из вышеперечисленных способов, будут отобра
жаться в виде большой миниатюры автора, а человек, оформивший коммит - меньшей
и расположенной перед ней:

          -о-  Commits оп Арг 1 7. 201 5

                   Further improvements t o soundness proof for addition.
                    RenuAB committed wrth gebn оп 23 Feb 201 5
