676     Глава 20   •  Автоматическое масштабирование подов и узлов в Kubernetes

         Функция изменения ресурсов пода без его перезапуска находится на стадии
          альфа-тестирования1 и может быть изменена в будущих версиях Kubernetes без
         предварительного уведомления. Ее не следует использовать в рабочих средах
         ввиду возможной нестабильности. В целом любые функции, находящиеся на
          стадии альфа-тестирования, не считаются финальными и могут быть изменены
          в любой момент.

Для активизации этой функции необходимо использовать флаг --feature-gates
на всех узлах кластера.

Это можно сделать следующим образом.
1. Отредактируйте манифест /etc/kubernetes/manifests/kube-apiserver.yaml
   (или соответствующий конфигурационный файл в вашей среде Kubernetes).
2. Добавьте флаг --feature-gates:
   # /etc/kubernetes/manifests/kube-apiserver.yaml
   ...
     - command:
       - kube-apiserver
       ...<фрагмент опущен для краткости>...
       - --feature-gates=InPlacePodVerticalScaling=true
  При использовании среды minikube добавьте этот флаг при запуске кластера:

    $ minikube start --feature-gates=InPlacePodVerticalScaling=true

Далее мы поговорим о включении VPA в кластере GKE.

Включение VPA в кластере GKE
Включить вертикальный автоскейлер (VPA) в кластере GKE (Google Kubernetes
Engine) можно с помощью следующей команды:

 $ gcloud container clusters update <имя_кластера> --enable-vertical-pod-
 autoscaling

Учтите, что выполнение этой операции инициирует перезапуск управляющего
слоя Kubernetes.
Чтобы включить VPA при создании нового кластера, используйте дополнитель-
ный аргумент --enable-vertical-pod autoscaling:

 $ gcloud container clusters create k8sforbeginners \
     --num-nodes=2 \
     --zone=us-central1-a \
     --enable-vertical-pod-autoscaling

1  С выходом версии 1.35 функционал переведен в стабильные и флаг --feature-gates
   не требуется.
