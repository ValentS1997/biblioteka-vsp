626     Глава 18   •  Безопасность в системе Kubernetes

spec:
  containers:
  - name: app-container
    securityContext:
      readOnlyRootFilesystem: true  # Монтирование корневой файловой системы
                                    # в режиме "только для чтения"

Существуют и другие настройки SecurityContext, такие как Security Enhanced
Linux (SELinux), AppArmor (https://kubernetes.io/docs/tutorials/security/apparmor/),
Seccomp и др. Подробнее о них можно узнать в официальной документации по
адресу https://kubernetes.io/docs/tasks/configure-pod-container/security-context/.
В следующем разделе мы поговорим о выборе оптимального места использова-
ния параметра securityContext в конфигурации.

Задание параметра SecurityContext на уровне пода
и контейнера
В Kubernetes параметр securityContext можно задавать как на уровне пода,
так и на уровне контейнера, что обеспечивает гибкость в настройке параметров
безопасности для приложений.
Задание параметра SecurityContext на уровне пода. При задании параметра
securityContext на уровне пода его настройки наследуются всеми контейнерами
внутри этого пода, что обеспечивает согласованность их параметров безопасности:

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  securityContext:
    runAsUser: 1000    # Все контейнеры в поде запускаются
                       # от имени пользователя с ID 1000
    runAsGroup: 1000   # Все контейнеры в поде запускаются
                       # от имени группы с ID 1000
  containers:
  - name: app-container
    image: my-app-image
  - name: sidecar-container
    image: my-sidecar-image

Задание параметра SecurityContext на уровне контейнера. При задании па-
раметра securityContext на уровне контейнера соответствующие настройки
затрагивают только его, что позволяет задавать разные параметры безопасности
для разных контейнеров одного пода:

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
