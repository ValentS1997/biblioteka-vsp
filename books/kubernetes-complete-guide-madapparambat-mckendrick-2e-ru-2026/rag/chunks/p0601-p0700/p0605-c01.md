Аутентификация и авторизация: управление пользовательским доступом     605

 7. Проверьте и одобрите CSR следующим образом:

     $ kubectl certificate approve iamgini
     certificatesigningrequest.certificates.k8s.io/iamgini approved

 8. После одобрения CSR извлеките из него данные сертификата и сохраните
    их в файл iamgini.crt с помощью следующей команды:

     $ kubectl get csr iamgini -o json | jq -r '.status.certificate' | base64
     --decode > iamgini.crt

 9. Итак, у нас есть закрытый ключ и сертификат (файл .csr можно удалить —
    он нам больше не понадобится):

     $ ls iamgini.*
     iamgini.crt  iamgini.csr  iamgini.key

10. Теперь настроим kubeconfig, добавив нового пользователя и контекст. Соз-
    дайте запись о пользователе в kubeconfig следующим образом (не забудьте
    указать полный путь к файлам ключа и сертификата):

     $ kubectl config set-credentials iamgini \
         --client-key=/full-path/iamgini.key \
         --client-certificate=/full-path/iamgini.crt
     User "iamgini" set.

11. Создайте контекст, связанный с новым пользователем:

     $ kubectl config set-context iamgini --cluster=minikube --user=iamgini
     Context "iamgini" created.

12. После обновления kubeconfig можно проверить доступ. Для этого переклю-
    чите контекст с помощью следующей команды:

     $ kubectl config use-context iamgini
     Switched to context "iamgini".

13. Проверьте текущий контекст и подключение:

     $ kubectl auth whoami
     ATTRIBUTE   VALUE
     Username    iamgini
     Groups      [web1 frontend system:authenticated]

 Итак, мы успешно настроили аутентификацию на основе сертификата X.509.
 Однако учтите, что созданный нами пользователь не сможет выполнять никакие
 операции до тех пор, пока вы не настроите соответствующие ресурсы RBAC.

 Ниже перечислены преимущества и недостатки использования сертифика-
 тов X.509 для прохождения аутентификации.
