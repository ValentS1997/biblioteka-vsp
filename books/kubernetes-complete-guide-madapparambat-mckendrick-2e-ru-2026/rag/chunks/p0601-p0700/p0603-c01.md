Аутентификация и авторизация: управление пользовательским доступом     603

3. Пользователь должен предоставить клиентский сертификат при аутенти-
  фикации на API-сервере. API-сервер проверяет этот сертификат на соот-
   ветствие корневому центру сертификации. В зависимости от результата
   запрос либо успешно проходит процедуру аутентификации, либо отклоня-
   ется. Если вы используете кластер minikube, то фактически уже применяете
   метод аутентификации на основе сертификатов, как показано в следующем
   примере:

    $ kubectl config view -o json | jq '.users[]'
    {
      "name": "example-sa",
      "user": {
        "token": "REDACTED"
      }
    }
    {
      "name": "minikube",
      "user": {
        "client-certificate": "/home/iamgini/.minikube/profiles/minikube/
         client.crt",
        "client-key": "/home/iamgini/.minikube/profiles/minikube/client.key"
      }
    }

  При работе с kubectl пользователи могут настроить этот метод аутентифика-
  ции в файле kubeconfig с помощью команды kubectl config set-credentials,
   как было показано ранее. На рис. 18.5 представлена схема, обобщающая
   описанный выше процесс.
