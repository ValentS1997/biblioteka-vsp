Аутентификация и авторизация: управление пользовательским доступом     609

z Соответствие требованиям протокола TLS. IdP-сервис должен использовать
   актуальные, неустаревшие шифры TLS (Transport Layer Security — безопас-
   ность транспортного уровня), поскольку от этого зависит безопасность пере-
   дачи конфиденциальных данных аутентификации.
z Наличие сертификата, подписанного центром сертификации. Независимо
   от того, используете ли вы коммерческий центр сертификации или само-
   подписанный сертификат, флаг CA в сертификате IdP-сервиса должен быть
   установлен в значение TRUE. Это необходимо потому, что Kubernetes исполь-
   зует TLS-клиент, реализованный на языке Go, который требует выполнения
   этого условия, чтобы доверять сертификатам IdP-сервиса при проверке
   пользовательских токенов.

        При самостоятельном развертывании IdP-сервиса (без участия коммерческо-
          го CA) можно использовать такие инструменты, как сценарий gencert из про-
          екта Dex, позволяющий создавать корректный CA-сертификат вместе с ключом
          подписи.

Ниже перечислены популярные OIDC-провайдеры для Kubernetes.

z Dex — один из самых легковесных и популярных IdP-сервисов с открытым
  исходным кодом, специально разработанный для использования в сре-
   де Kubernetes. Он поддерживает протокол OIDC и хорошо вписывается
   в ожидаемую Kubernetes модель аутентификации. Dex интегрируется с та-
  кими внешними IdP-сервисами, как LDAP, GitHub и Google, что делает
   его хорошим выбором для организаций, использующих сложные сценарии
   идентификации.
z  Keycloak — IdP-сервис с открытым исходным кодом и широкой поддержкой
   протоколов OIDC и SAML, предоставляющий такие расширенные корпора-
   тивные функции, как федеративная идентификация и управление доступом
   на основе ролей (RBAC). Keycloak подходит для случаев, требующих повы-
   шенного контроля или глубокой кастомизации механизма аутентификации.
z OpenUnison — еще один IdP-сервис, оптимизированный для Kubernetes.
   Поддерживает нативную интеграцию с механизмом RBAC Kubernetes и фе-
   деративную идентификацию. Подходит предприятиям, которым требуется
   готовая, но настраиваемая система аутентификации для защиты Kubernetes-
   кластеров.
z Cloud Foundry User Account and Authentication (UAA) — многофункцио-
  нальный IdP-сервис с открытым исходным кодом, изначально разрабо-
  танный как часть платформы Cloud Foundry. Он поддерживает протокол
  OIDC и интеграцию с облачными платформами и корпоративными систе-
  мами аутентификации, поэтому хорошо подходит для сложных Kubernetes-
   развертываний, работающих в гибридных облачных средах.
