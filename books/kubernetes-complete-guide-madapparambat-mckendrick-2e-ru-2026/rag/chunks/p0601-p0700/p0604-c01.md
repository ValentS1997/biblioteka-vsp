604     Глава 18   •  Безопасность в системе Kubernetes

Следует отметить, что на схеме изображен случай, когда исходный запрос на
подпись сертификата (CSR, Certificate Signing Request) обрабатывается API
Certificate внутри кластера Kubernetes. Однако это не является обязатель-
ным — центр сертификации может быть внешним по отношению к кластеру,
а API-сервер Kubernetes может использовать копию файла CA в формате .pem
для проверки клиентских сертификатов.

В следующем упражнении мы настроим аутентификацию в Kubernetes с ис-
пользованием клиентских сертификатов.

1. Создайте закрытый ключ с помощью команды openssl:

    $ openssl genrsa -out iamgini.key 2048

2. Сформируйте запрос на подпись сертификата (CSR):

    $ openssl req -new -key iamgini.key -out iamgini.csr -subj "/CN=iamgini/
    O=web1/O=frontend"

3. Просмотрите содержимое CSR и закодируйте его в формат base64:

    $ cat iamgini.csr | base64 -w 0

4. Теперь нам нужно создать ресурс CertificateSigningRequest с помощью
   API Certificates. Для этого понадобится YAML-файл csr.yaml со следующим
   содержимым:
   # csr.yaml
   apiVersion: certificates.k8s.io/v1
   kind: CertificateSigningRequest
   metadata:
     name: iamgini
   spec:
     request: <содержимое CSR, закодированное на шаге 3>
     signerName: kubernetes.io/kube-apiserver-client
     usages:
       - client auth
5. Примените манифест для создания CSR:

    $ kubectl apply -f csr.yaml
    certificatesigningrequest.certificates.k8s.io/iamgini created

6. Теперь администраторы (или пользователи с привилегией certificates
   igningrequests) могут просматривать ресурсы CSR:

    $ kubectl get csr
    NAME     AGE   SIGNERNAME                            REQUESTOR
    REQUESTEDDURATION   CONDITION
    iamgini   25s  kubernetes.io/kube-apiserver-client   minikube-user <none>
    Pending
