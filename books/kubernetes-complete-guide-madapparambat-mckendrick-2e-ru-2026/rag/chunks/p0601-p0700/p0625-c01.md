Привилегии Linux. Привилегии (capabilities) — это специальные разрешения,
которые можно предоставить контейнеру в дополнение к правам обычного поль-
зователя. Параметр securityContext позволяет указать, какие именно привиле-
гии должен иметь контейнер, и тем самым реализовать определенные функции
без предоставления ему полного доступа, как показано в следующем примере:

apiVersion: v1
kind: Pod
metadata:
  name: privileged-container
spec:
  containers:
  - name: app-container
    securityContext:
      capabilities:
        add:
        - CAP_NET_ADMIN   # Предоставление привилегий для управления сетью

Подробнее о привилегиях Linux можно узнать в официальной документа-
ции: https://linux-audit.com/kernel/capabilities/linux-capabilities-hardening-linux-binaries-by-
removing-setuid/.
Привилегированный режим. По умолчанию контейнеры запускаются в не-
привилегированном режиме. Параметр securityContext позволяет запустить
контейнер в привилегированном режиме, предоставив ему права суперполь-
зователя. Однако из-за повышенных рисков безопасности использовать этот
режим следует с осторожностью. Ниже приведен пример YAML-манифеста
пода с активизированным привилегированным режимом:

apiVersion: v1
kind: Pod
metadata:
  name: privileged-container
spec:
  containers:
  - name: app-container
    securityContext:
      privileged: true   # Запуск контейнера в привилегированном режиме
                         # (использовать с осторожностью)

Файловая система, доступная только для чтения. С помощью параметра
securityContext можно настроить контейнер так, чтобы его корневая файловая
система была доступна только для чтения. Это повышает уровень безопасности,
предотвращая случайные или преднамеренные изменения базовой системы:

apiVersion: v1
kind: Pod
metadata:
  name: read-only-container
