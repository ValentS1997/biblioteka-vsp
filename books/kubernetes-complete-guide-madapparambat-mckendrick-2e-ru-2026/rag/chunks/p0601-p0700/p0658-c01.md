658     Глава 19   •  Продвинутые методы планирования подов

Kubernetes автоматически назначает ряд ограничений с эффектом NoExecute,
отслеживая состояние узлов. Следующие ограничения встроены в систему
и управляются контроллером узла (NodeController) или агентом kubelet.

z  node.kubernetes.io/not-ready — назначается в тех случаях, когда состояние
   узла Ready имеет значение False.
z  node.kubernetes.io/unreachable — назначается в тех случаях, когда состоя
   ние узла Ready имеет значение Unknown. Это происходит, когда компонент
   NodeController не может связаться с узлом.
z  node.kubernetes.io/memory-pressure — узел испытывает нехватку памяти.
z  node.kubernetes.io/disk-pressure — узел испытывает нехватку дискового
   пространства.
z  node.kubernetes.io/network-unavailable — сеть на узле недоступна.
z  node.kubernetes.io/unschedulable — узел находится в состоянии, при кото-
  ром ему нельзя назначать поды.
z  node.cloudprovider.kubernetes.io/uninitialized — используется для узлов,
   которые подготавливаются внешним облачным провайдером. После ини-
   циализации узла компонентом cloud-controller-manager это ограничение
   автоматически удаляется.

Для назначения ограничения узлу используется команда kubectl taint node:

 $ kubectl taint node =:<имяУзла> <ключ>=<значение>:<эффект>

Например, если мы хотим задать для узла 1 ограничение с ключом machine-
check-exception, значением memory и эффектом NoExecute, можем использовать
следующую команду:

 $ kubectl taint node minikube machine-check-exception=memory:NoExecute
 node/minikube tainted

Для удаления этого ограничения используется такая же команда, только с сим-
волом - в конце определения:

 $ kubectl taint node minikube machine-check-exception=memory:NoExecute-
 node/minikube untainted

Мы также можем удалить все ограничения с определенным ключом:

 $ kubectl taint node minikube machine-check-exception:NoExecute-
