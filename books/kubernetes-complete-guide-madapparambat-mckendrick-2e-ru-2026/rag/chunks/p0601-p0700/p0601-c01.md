Аутентификация и авторизация: управление пользовательским доступом     601

     $ kubectl get po -n example-ns
     NAME         READY   STATUS    RESTARTS   AGE
     nginx-pod    1/1     Running   0          18m

13. Как видите, результат соответствует ожиданиям! Теперь попробуйте полу-
    чить список подов из пространства имен kube-system:

     $ kubectl get pods -n kube-system
     Error from server (Forbidden): pods is forbidden: User
     "system:serviceaccount:example-ns:example-sa" \
     cannot list resource "pods" in API group "" in the namespace "kube-system"

14. Аутентификация прошла успешно, однако механизм RBAC правомерно за-
    претил выполнение операции. В завершение попробуйте получить список
    сервисов:

     $ kubectl get svc -n example-ns
     Error from server (Forbidden): services is forbidden: User
     "system:serviceaccount:example-ns:example-sa" \
     cannot list resource "services" in API group "" in the namespace "example-ns"

 Этот результат также является ожидаемым, поскольку в механизме RBAC
 не заданы правила, разрешающие этому объекту ServiceAccount просматривать
 ресурсы типа Service в пространстве имен example-ns.
 Итак, мы успешно аутентифицировались с помощью токена ServiceAccount
 и проверили свои привилегии. Теперь можно переключиться на прежний кон-
 текст с помощью команды kubectl config use-context <имя_контекста>.

          Описанную процедуру настройки контекста kubectl с bearer-токеном можно ис-
           пользовать и при аутентификации с помощью статического файла с токенами.

 Ниже перечислены преимущества и недостатки метода аутентификации с по-
 мощью токенов ServiceAccount.

 Преимущества:

 z простота настройки и использования;
 z управление осуществляется кластером Kubernetes, что избавляет от потреб-
    ности во внешних поставщиках услуг аутентификации;
 z объекты ServiceAccount ограничены пространством имен.

 Недостаток состоит в том, что объекты ServiceAccount предназначены для иден-
 тификации процессов, выполняющихся внутри подов, и предоставления им воз-
 можности использовать механизм RBAC системы Kubernetes. Использование то-
 кенов ServiceAccount обычными пользователями не является хорошей практикой.
