В следующем разделе мы применим параметр SecurityContext к поду.

Применение параметра SecurityContext к поду
В этом примере создается под с контейнером, который запускается от имени
непривилегированного пользователя и группы с корневой файловой системой,
доступной только для чтения:

# pod-with-security-context.yaml
apiVersion: v1
kind: Pod
metadata:
  name: security-context-demo
spec:
  containers:
  - name: app-container
    image: nginx:latest
    securityContext:
      runAsUser: 1000              # Запуск процессов в контейнере
                                   # от имени пользователя с ID 1000.
      runAsGroup: 1000             # Запуск процессов в контейнере
                                   # от имени группы с ID 1000.
      readOnlyRootFilesystem: true # Монтирование корневой файловой системы
                                   # в режиме только для чтения
    volumeMounts:
    - name: html-volume
      mountPath: /usr/share/nginx/html
  volumes:
  - name: html-volume
    emptyDir: {}                   # Том, предоставляющий пространство для записи

В этом YAML-манифесте стоит обратить внимание на следующие параметры.
z  runAsUser и runAsGroup — гарантируют запуск контейнера от имени конкрет-
  ных пользователя и группы, не имеющих прав суперпользователя, в соот-
   ветствии с принципом наименьших привилегий.
