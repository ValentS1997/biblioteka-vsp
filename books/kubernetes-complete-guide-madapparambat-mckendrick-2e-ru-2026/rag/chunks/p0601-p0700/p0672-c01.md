672     Глава 20   •  Автоматическое масштабирование подов и узлов в Kubernetes

Для каждого контейнера в поде нужно заполнить поле .spec.template.spec.con
tainers[*].resources. В данном примере мы задали следующие параметры:
limits — 200m KCU (ресурсы ЦП) и 60Mi (оперативная память), requests — 100m
KCU и 50Mi.
После применения манифеста с помощью команды kubectl apply -f resource-
limit/nginx-deployment.yaml вы можете выполнить команду kubectl describe
node для описания одного из узлов, которому назначены поды нашего объекта
Deployment. В выводе команды будет содержаться детальная информация
о квотах и текущем распределении вычислительных ресурсов:

Теперь, опираясь на полученную информацию, вы можете поэксперименти-
ровать, запросив для контейнера объем ресурсов ЦП, превышающий емкость
одного узла в кластере. Изменим соответствующий параметр в файле resource-
limit/nginx-deployment.yaml следующим образом:

...
        resources:
          limits:
            cpu: 2000m
            memory: 60Mi
          requests:
            cpu: 2000m
            memory: 50Mi
...
