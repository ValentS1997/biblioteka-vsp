4. Примените манифест к кластеру с помощью команды kubectl apply -f
   04_taints/nginx-deployment.yaml и снова проверьте статус подов и узлы,
  которым они назначены. Возможно, вам придется дождаться завершения
   обновления объекта Deployment:

    $ kubectl get pods --namespace default \
        --output=custom-columns="NAME:.metadata.name,STATUS:.status.phase,
    NODE:.spec.nodeName"
    NAME                         STATUS    NODE
    nginx-app-84d755f746-4zkjd   Running   minikube
    nginx-app-84d755f746-58qmh   Running   minikube-m02
    nginx-app-84d755f746-5h5vk   Running   minikube-m03
    nginx-app-84d755f746-psmgf   Running   minikube-m02
    nginx-app-84d755f746-zkbc6   Running   minikube-m03

   Результат может показаться неожиданным. Как видите, часть подов была на-
   значена узлу 2 и узлу 3, но узел 1 также получает поды, которые выселяются
  каждые 60 секунд! Причина в том, что из-за параметра tolerationSeconds,
   заданного в допуске для ограничения NoExecute, эффект этого ограничения
   полностью игнорируется на протяжении 60 секунд. Поэтому планировщик
  может назначить под узлу 1, даже если позднее этот под будет выселен.
5. Давайте исправим это поведение, следуя рекомендации, в соответствии
   с которой использование ограничения NoExecute должно сопровождаться
   заданием ограничения NoSchedule. Это гарантирует то, что выселенные поды
   не смогут быть повторно назначены узлу с таким ограничением, если только
   у подов не появится допуск и для этого ограничения. Назначьте узлу 1 огра-
   ничение NoSchedule с помощью следующей команды:

    $ kubectl taint node minikube machine-check-exception=memory:NoSchedule
    node/minikube tainted

6. Проверьте статус подов и узлы, которым они назначены:

    $ kubectl get pods --namespace default \
        --output=custom-columns="NAME:.metadata.name,STATUS:.status.phase,
    NODE:.spec.nodeName"
    NAME                         STATUS    NODE
    nginx-app-84d755f746-58qmh   Running   minikube-m02
    nginx-app-84d755f746-5h5vk   Running   minikube-m03
    nginx-app-84d755f746-psmgf   Running   minikube-m02
    nginx-app-84d755f746-sm2cm   Running   minikube-m03
    nginx-app-84d755f746-zkbc6   Running   minikube-m03

  Как видите, поды распределены между узлом 2 и узлом 3, что нам и требо-
   валось.
