Вертикальное автомасштабирование подов     681

   Этот VPA создан для объекта Deployment hamster, как указано в поле
   .spec.targetRef. Режим работы 'Off' задан в поле .spec.updatePo
   licy.updateMode (значение 'Off' необходимо заключать в кавычки, чтобы
   оно не было интерпретировано как логическое). Политика для контейне-
   ра настроена в поле .spec.resourcePolicy.containerPolicies и допускает
   автоматическую корректировку запросов: для ресурсов ЦП — в диапазоне
   от 100m до 1000m, а для памяти — от 50Mi до 500Mi.
2. Примените манифест к кластеру:

    $ kubectl apply -f vpa/hamster-vpa.yaml
    verticalpodautoscaler.autoscaling.k8s.io/hamster-vpa created

3. Подождите, пока будет рассчитано первое рекомендуемое значение. После
   этого проверьте его, описав объект VPA:

    $ kubectl describe vpa hamster-vpa -n vpa-demo
    ...<фрагмент опущен для краткости>...
    Status:
      Conditions:
        Last Transition Time:  2024-08-11T09:20:44Z
        Status:                True
        Type:                  RecommendationProvided
      Recommendation:
        Container Recommendations:
          Container Name:  hamster
          Lower Bound:
            Cpu:     461m
            Memory:  262144k
          Target:
            Cpu:     587m
            Memory:  262144k
          Uncapped Target:
            Cpu:     587m
            Memory:  262144k
          Upper Bound:
            Cpu:     1
            Memory:  500Mi
    Events:          <none>

  VPA порекомендовал выделить чуть больше ожидаемых 500m KCU и 262144k
   памяти. Это логично, так как ресурсы ЦП требуются поду с небольшим за-
   пасом.
4. Теперь проверим VPA в действии и переключим его режим на Auto. Для
   этого измените файл vpa/hamster-vpa.yaml следующим образом:
   # vpa/hamster-vpa.yaml
   apiVersion: autoscaling.k8s.io/v1
   kind: VerticalPodAutoscaler
