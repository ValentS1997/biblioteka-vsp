Защита подов и контейнеров     633

 $ kubectl apply -f default-deny-ingress.yaml -n web2
 networkpolicy.networking.k8s.io/default-deny-ingress created

Теперь еще раз попробуем обратиться к поду nginx2 из пода nginx1:

 $ kubectl -n web1 exec nginx1 -- curl 10.244.120.72
   % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                              Dload  Upload   Total   Spent    Left   Speed
   0     0    0     0    0     0      0       0 --:--:--  0:02:15 --:--:--     0
 curl: (28) Failed to connect to 10.244.120.72 port 80 after 135435 ms: Couldn't
 connect to server
 command terminated with exit code 28

Как видите, весь трафик, направляемый к подам в пространстве имен web2,
блокируется сетевой политикой default-deny-ingress.
Теперь настроим сетевую политику для пода nginx2 в пространстве имен web2,
чтобы явно разрешить прием трафика от пода nginx1 в пространстве имен web1.
Для этого создадим YAML-манифест со следующим содержимым:

# allow-from-web1-netpol.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-web1-netpol
  namespace: web2
spec:
  podSelector:
    matchLabels:
      app: nginx2
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              project: web1
        - podSelector:
            matchLabels:
              app: nginx1
      ports:
        - protocol: TCP
          port: 80

Обратите внимание на то, что в поле namespaceSelector.matchLabels использует-
ся метка project: web1, которую мы заранее назначили пространству имен web1
именно для этой цели. Применим YAML-манифест с помощью команды:

 $ kubectl apply -f allow-from-web1-netpol.yaml
 networkpolicy.networking.k8s.io/nginx2-networkpolicy created
