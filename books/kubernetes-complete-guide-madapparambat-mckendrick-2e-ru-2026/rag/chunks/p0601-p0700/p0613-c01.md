z ABAC (Attribute-Based Access Control — управление доступом на основе
   атрибутов). Это часть общей парадигмы контроля доступа, применяемая
   не только в Kubernetes и основанная на политиках, учитывающих атрибуты
   пользователя, ресурса и среды. Данный подход обеспечивает очень дета-
   лизированный контроль доступа. Например, он позволяет задать правило,
  разрешающее пользователю доступ к файлу только при одновременном
   выполнении трех условий: если у пользователя есть допуск к конфиденци-
  альным данным (атрибут пользователя), если владельцем файла является
  Майк (атрибут ресурса) и если запрос поступает из внутренней сети (атрибут
   среды). Таким образом, политика представляет собой набор атрибутов, кото-
   рые должны присутствовать одновременно, чтобы действие было разрешено.
  В Kubernetes она реализуется с помощью объекта Policy. Например, можно
   определить политику, разрешающую аутентифицированному пользовате-
  лю по имени Mike читать любые поды в пространстве имен default. Чтобы
   предоставить те же права пользователю Bob, необходимо создать для него
   отдельный объект Policy.
z  Node. Специальный режим авторизации, используемый для проверки запро-
   сов к API, поступающих от компонента kubelet внутри кластера.
z Webhook. В этом режиме API-сервер отправляет внешнему сервису объект
   SubjectAccessReview через HTTP-запрос типа POST. Сервис проверяет запрос
  и возвращает объект SubjectAccessReview с результатом проверки (доступ
   разрешен/доступ запрещен). В зависимости от ответа API-сервер либо вы-
   полняет запрос, либо возвращает код 403. Такой подход часто используется
  при интеграции с корпоративными системами управления доступом.
z  AlwaysAllow. Разрешает выполнение всех запросов без ограничений. Исполь-
   зуется исключительно в тестовых средах по соображениям безопасности.
z AlwaysDeny. Блокирует выполнение всех запросов. Применяется только
   в тестовых целях, например для проверки поведения системы при полном
   запрете доступа.

В настоящее время режим RBAC считается отраслевым стандартом благодаря
своей гибкости и простоте управления. Поэтому в следующих разделах мы со-
средоточимся именно на нем.
