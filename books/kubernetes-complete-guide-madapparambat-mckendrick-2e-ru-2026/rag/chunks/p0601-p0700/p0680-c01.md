680     Глава 20   •  Автоматическое масштабирование подов и узлов в Kubernetes

Теперь создадим объект VPA для наших подов. VPA может работать в четырех
режимах, задаваемых в поле .spec.updatePolicy.updateMode.

z Recreate — запросы и лимиты контейнера назначаются при создании пода
  и в дальнейшем динамически пересчитываются. Обновление значений требует
   перезапуска пода, что может приводить к прерыванию работы приложения.
z  Auto — в текущей реализации эквивалентен режиму Recreate, но в будущем,
   с появлением механизма, обеспечивающего обновления на месте, автомати-
   чески переключится на его использование1.
z Initial — запросы и лимиты задаются при создании пода и впоследствии
   не изменяются.
z Off — режим «только рекомендации». Предлагаемые значения запросов
  и лимитов ресурсов можно посмотреть в объекте VPA, например, с помощью
   утилиты kubectl.

Сначала создадим VPA для объекта Deployment hamster, который будет рабо-
тать в режиме Off, а затем включим режим Auto. Для этого сделайте следующее.

1. Создайте YAML-манифест VPA vpa/hamster-vpa.yaml:
   # vpa/hamster-vpa.yaml
   apiVersion: autoscaling.k8s.io/v1
   kind: VerticalPodAutoscaler
   metadata:
     name: hamster-vpa
     namespace: vpa-demo
   spec:
     targetRef:
       apiVersion: apps/v1
       kind: Deployment
       name: hamster
     updatePolicy:
       updateMode: 'Off'
     resourcePolicy:
       containerPolicies:
         - containerName: '*'
           minAllowed:
             cpu: 100m
             memory: 50Mi
           maxAllowed:
             cpu: 1
             memory: 500Mi
           controlledResources:
             - cpu
             - memory

1  Развитие Kubernetes динамично, этот режим уже признан устаревшим и скоро будет
   удален, на смену ему приходит InPlaceOrRecreate.
