606     Глава 18   •  Безопасность в системе Kubernetes

Преимущества:

z более высокая безопасность по сравнению с использованием токенов Ser
   viceAccount и статических файлов с токенами;
z сертификаты не хранятся внутри кластера, что исключает риск компроме-
   тации сразу всех учетных данных. Клиентские сертификаты X.509 можно
   использовать для учетных записей с повышенными привилегиями;
z при необходимости сертификаты можно отозвать, что особенно важно при
   возникновении инцидентов.

Недостатки:

z сертификаты имеют ограниченный срок действия. В простых сценариях
   разработки это может быть неудобно, но в рабочих средах это является
  преимуществом с точки зрения безопасности. Однако помните, что сер-
  тификат необходимо хранить в безопасном месте, поскольку механизм
   аутентификации на основе файлов представляет угрозу безопасности, так
   как файл может быть похищен и использован для получения несанкцио-
   нированного доступа;
z необходимость контролировать сроки действия, отзыв и ротацию сертифи-
   катов. Эти процессы следует автоматизировать, чтобы быстрее реагировать
   на инциденты;
z использование клиентских сертификатов для аутентификации в браузере
  может создавать трудности, например, при попытке входа в веб-интерфейс
   Kubernetes Dashboard.

В целом аутентификация с использованием клиентских сертификатов X.509 —
это безопасное решение, однако для того, чтобы воспользоваться всеми его
преимуществами, необходимо грамотно управлять сертификатами. Далее мы
обсудим токены OpenID Connect — рекомендуемый метод аутентификации
для облачных сред.
Токены OpenID Connect. Используя протокол OpenID Connect (OIDC), вы
можете реализовать механизм единого входа (Single Sign-On, SSO) для вашего
кластера Kubernetes (а также для других ресурсов вашей организации). OIDC
представляет собой уровень аутентификации, работающий поверх протокола
OAuth 2.0, который позволяет сторонним приложениям проверять подлин-
ность конечного пользователя и получать базовую информацию о его профиле.
OIDC использует JWT-токены, которые можно получить с помощью потоков
аутентификации, соответствующих спецификации OAuth 2.0. Основная про-
блема при использовании OIDC для аутентификации в Kubernetes заключается
в ограниченной доступности OpenID-провайдеров. Преимуществом управляе
