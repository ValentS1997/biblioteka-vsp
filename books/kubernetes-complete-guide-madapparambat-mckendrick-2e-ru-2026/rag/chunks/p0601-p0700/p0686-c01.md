686     Глава 20   •  Автоматическое масштабирование подов и узлов в Kubernetes

2. Примените этот манифест, чтобы создать пространство имен:

    $ kubectl apply -f hpa/hpa-demo-ns.yaml
    namespace/hpa-demo created

3. Для демонстрации мы используем простой контейнер с веб-сервером на
   основе пользовательского образа quay.io/iamgini/one-page-web:1.0. Сле-
  дующий YAML-манифест содержит определение объекта Deployment, соз-
   дающего одну реплику пода:
   ---
   # hpa/todo-deployment.yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: todo-app
     namespace: hpa-demo
   spec:
     replicas: 1  # Скорректируйте при необходимости
     selector:
       matchLabels:
         app: todo
     template:
       metadata:
         labels:
           app: todo
       spec:
         containers:
           - name: todoapp
             image: quay.io/ginigangadharan/todo-app:2.0
             ports:
               - containerPort: 3000
                 resources:
                   requests:
                     memory: "50Mi"   # Запрашиваем 50 МиБ памяти
                     cpu: "50m"       # Запрашиваем 0,05 ядра ЦП
                  limits:
                     memory: "100Mi"  # Максимум 100 МиБ памяти
                     cpu: "100m"      # Максимум 0,1 ядра ЦП
4. Примените конфигурацию и убедитесь в том, что поды запущены:

    $ kubectl apply -f hpa/todo-deployment.yaml
    deployment.apps/todo-app created

    $ kubectl get po -n hpa-demo
    NAME                          READY   STATUS    RESTARTS   AGE
    todo-app-5cfb496d77-l6r69     1/1     Running   0          8s

5. Чтобы открыть доступ к приложению, создайте объект Service с помощью
   следующего YAML-манифеста:
   # hpa/todo-service.yaml
   apiVersion: v1
   kind: Service
