Аутентификация и авторизация: управление пользовательским доступом     615

2. Создайте тестовый под nginx в этом пространстве имен, используя файл
   02_rbac/nginx-pod.yaml:

    $ kubectl apply -f 02_rbac/nginx-pod.yaml
    pod/nginx-pod created

         Обратите внимание на то, что под nginx сам по себе здесь ничего не делает;
         позднее нам понадобится под pod-logger-app для получения сведений о поде
          nginx в пространстве имен rbac-demo-ns.

3. Создайте объект ServiceAccount pod-logger. Для этого подготовьте манифест
   pod-logger-serviceaccount.yaml:
   # 02_rbac/pod-logger-serviceaccount.yaml
   apiVersion: v1
   kind: ServiceAccount
   metadata:
     name: pod-logger
     namespace: rbac-demo-ns
  И примените его к кластеру с помощью команды:

    $ kubectl apply -f 02_rbac/pod-logger-serviceaccount.yaml
    serviceaccount/pod-logger created

4. Создайте роль pod-reader, разрешающую только операции get, watch и list
   над ресурсами pods в REST API Kubernetes. Фактически это соответствует
   работе с конечной точкой API /api/v1/namespaces/rbac-demo-ns/pods. Зна-
   чение apiGroups: [""] указывает на использование основной (core) группы
   API. Структура манифеста pod-reader-role.yaml выглядит следующим
   образом:

   # 02_rbac/pod-reader-role.yaml
   apiVersion: rbac.authorization.k8s.io/v1
   kind: Role
   metadata:
     namespace: rbac-demo-ns
     name: pod-reader
   rules:
     - apiGroups: [""]
       resources: ["pods"]
       verbs: ["get", "watch", "list"]
5. Примените манифест к кластеру с помощью следующей команды:

    $ kubectl apply -f 02_rbac/pod-reader-role.yaml
    role.rbac.authorization.k8s.io/pod-reader created
