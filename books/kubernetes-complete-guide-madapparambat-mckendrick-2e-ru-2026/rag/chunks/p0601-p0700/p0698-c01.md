698     Глава 20   •  Автоматическое масштабирование подов и узлов в Kubernetes

5. Создайте объект Deployment. Он достаточно прост, но использует специ-
   альный образ контейнера (см. файл ca/elastic-hamster-deployment.yaml):
   ...
       spec:
         serviceAccountName: elastic-hamster
         containers:
           - name: hamster
             image: quay.io/iamgini/elastic-hamster:1.0
             resources:
               requests:
                 cpu: 500m
                 memory: 50Mi
             env:
               - name: TOTAL_HAMSTER_USAGE
                 value: "1.0"
  Мы подготовили пользовательский контейнерный образ elastic-hamster,
   внутри которого находится сценарий hamster.sh (см. файлы ca/Dockerfile
  и ca/hamster.sh в каталоге Chapter20).
6. Создайте объект HPA, который будет выполнять автомасштабирование
   подов:

   # elastic-hamster-hpa.yaml
   apiVersion: autoscaling/v1
   kind: HorizontalPodAutoscaler
   metadata:
     name: elastic-hamster-hpa
     namespace: ca-demo
   spec:
     minReplicas: 1
     maxReplicas: 25
     metrics:
       - resource:
           name: cpu
           target:
             averageUtilization: 75
             type: Utilization
         type: Resource
     scaleTargetRef:
       apiVersion: apps/v1
       kind: Deployment
       name: elastic-hamster
7. Чтобы не использовать YAML-файлы по отдельности, примените сразу все
  манифесты из каталога ca следующим образом:

    $ kubectl apply -f ca/
    namespace/ca-demo created
    role.rbac.authorization.k8s.io/deployment-reader created
    deployment.apps/elastic-hamster created
