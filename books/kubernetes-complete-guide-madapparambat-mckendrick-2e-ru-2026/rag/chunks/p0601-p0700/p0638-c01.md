638     Глава 18   •  Безопасность в системе Kubernetes

Kata Containers рекомендуется использовать в ситуациях, когда необходимо
сочетать высокий уровень безопасности с оптимальной производительностью,
особенно при работе с ресурсоемкими приложениями.

Использование ресурса RuntimeClass
в профилях безопасности
В Kubernetes можно указать среду выполнения контейнеров с помощью поля
runtimeClassName в спецификации пода. Вот пример такой конфигурации:

apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  runtimeClassName: kata-containers   # Указывает Kata Containers
                                      # в качестве среды выполнения
  containers:
  - name: my-app
    image: my-secure-image

Эта настройка указывает Kubernetes использовать среду выполнения Kata
Containers для обеспечения лучшей изоляции и повышенной безопасности.

В этой главе мы рассмотрели множество важных аспектов обеспечения безопас-
ности в Kubernetes. В завершение поговорим о получении доступа к приватным
реестрам и образам контейнеров.

Управление секретами
и учетными данными реестров
В Kubernetes для скачивания образов контейнеров из приватных репозиториев
требуются соответствующие учетные данные. Без них поды не могут получить
доступ к образам, размещенным в этих реестрах. Безопасное управление такими
учетными данными позволяет гарантировать то, что только авторизованные
поды смогут запрашивать и использовать конкретные образы контейнеров.

Команда kubectl create secret docker-registry упрощает управление учетными
данными реестра контейнеров в Kubernetes. Она обеспечивает безопасность за
счет шифрования секретов в состоянии покоя, что делает их доступными толь-
ко для авторизованных узлов. Такой подход устраняет сложность, присущую
ручным методам управления, минимизирует количество ошибок и повышает
операционную эффективность. Кроме того, он легко интегрируется со специ
фикациями подов, упрощая настройку параметра imagePullSecrets для их
аутентификации в приватных реестрах контейнеров.
