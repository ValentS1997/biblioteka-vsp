646     Глава 19   •  Продвинутые методы планирования подов

В нашем примере используется трехузловой кластер (не забудьте указать кор-
ректные имена узлов своего кластера в манифесте). Для удобства будем назы-
вать minikube узлом 1, minikube-m02 — узлом 2, а minikube-m03 — узлом 3.
В качестве демонстрации назначим все пять подов nginx узлу minikube-m02. Для
этого создайте YAML-манифест 01_nodename/nginx-deployment.yaml со следу-
ющим содержимым:

# 01_nodename/nginx-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-app
spec:
  replicas: 5
  selector:
    matchLabels:
      app: nginx
      environment: test
  template:
    metadata:
      labels:
        app: nginx
        environment: test
    spec:
      containers:
        - name: nginx
          image: nginx:1.17
          ports:
          - containerPort: 80

Примените этот манифест следующим образом:

 $ kubectl apply -f 01_nodename/nginx-deployment.yaml
 deployment.apps/nginx-app created

Объект Deployment создаст пять реплик пода. Просмотрите поды и имена узлов
с помощью команды kubectl get pods, настроив ее вывод следующим образом:

 $ kubectl get pods --namespace default \
     --output=custom-columns="NAME:.metadata.name,STATUS:.status.phase,NODE:.
 spec.nodeName"
 NAME                              STATUS    NODE
 nginx-app-7b547cfd87-4g9qx        Running   minikube
 nginx-app-7b547cfd87-m76l2        Running   minikube-m02
 nginx-app-7b547cfd87-mjf78        Running   minikube-m03
 nginx-app-7b547cfd87-vvrgk        Running   minikube-m02
 nginx-app-7b547cfd87-w7jcw        Running   minikube-m03

Как видите, по умолчанию поды распределяются равномерно: узел 1 получил
один под, а узлы 2 и 3 — по два пода. Это результат работы стандартных политик
планировщика kube-scheduler, отвечающих за фильтрацию и оценку узлов.
