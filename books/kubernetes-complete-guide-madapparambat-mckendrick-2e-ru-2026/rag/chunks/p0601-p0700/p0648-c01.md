Далее мы рассмотрим еще один простой способ планирования подов с помощью
поля nodeSelector.

Использование поля nodeSelector
в спецификации подов
В спецификации пода есть поле .spec.nodeSelector, которое позволяет назна-
чать этот под только узлам, имеющим определенные метки. Данный механизм
работает подобно селекторам меток в объектах Deployment и StatefulSet, од-
нако он поддерживает только простые проверки на равенство, но не позволяет
реализовать сложную логику на основе множеств.

Этот подход особенно полезен в следующих сценариях.
z Гибридные кластеры. Указав конкретную ОС в качестве критерия выбора
   узла, можно гарантировать то, что контейнеры Windows будут запускаться
   на узлах Windows, а контейнеры Linux — на узлах Linux.
z Распределение ресурсов. Поды можно назначать узлам, обладающим опре-
  деленными ресурсами (ЦП, память, хранилище), оптимизируя их исполь-
   зование.
z Аппаратные требования. Поды, нуждающиеся в специализированном обо-
   рудовании (например, в GPU), можно назначать только узлам, обладающим
   соответствующими возможностями.
z Зоны безопасности. Мы можем определить зоны безопасности с помощью
   меток и использовать поле nodeSelector для размещения подов только
   в определенных зонах.

Каждый узел Kubernetes по умолчанию имеет набор стандартных меток, среди
которых:

z  kubernetes.io/arch — архитектура процессора узла, например amd64 или arm
   (также существует в виде beta.kubernetes.io/arch);
z  kubernetes.io/os — операционная система узла, например linux или windows
   (также существует в виде beta.kubernetes.io/os);
z  node-role.kubernetes.io/control-plane — роль узла в кластере Kubernetes.
