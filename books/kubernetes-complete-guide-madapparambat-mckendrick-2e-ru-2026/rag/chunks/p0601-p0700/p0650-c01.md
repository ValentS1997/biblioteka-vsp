650     Глава 19   •  Продвинутые методы планирования подов

3. Измените манифест ./nginx-deployment.yaml (или создайте отдельный
  файл 02_nodeselector/nginx-deployment.yaml), указав node-type: superfast
   в качестве селектора узла в шаблоне пода:

   # 02_nodeselector/nginx-deployment.yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: nginx-app
   spec:
     ...
     template:
       ...
       spec:
         nodeSelector:
           node-type: superfast
   ...<фрагмент опущен для краткости>...
4. Примените манифест к кластеру с помощью команды kubectl apply -f 02_
   nodeselector/nginx deployment.yaml и снова проверьте статус подов и узлы,
  которым они назначены. Возможно, вам придется дождаться завершения
   обновления объекта Deployment:

    $ kubectl get pods --namespace default \
        --output=custom-columns="NAME:.metadata.name,STATUS:.status.phase,
    NODE:.spec.nodeName"

    NAME                         STATUS    NODE
    nginx-app-6c5b8b758-2dcsc    Running   minikube-m02
    nginx-app-6c5b8b758-48c5t    Running   minikube-m03
    nginx-app-6c5b8b758-pfmvg    Running   minikube-m03
    nginx-app-6c5b8b758-v6rhj    Running   minikube-m02
    nginx-app-6c5b8b758-zqvqm    Running   minikube-m02

  Как видите, теперь поды назначены узлам minikube-m02 и minikube-m03,
  имеющим метку node-type=superfast (узел minikube-m02 получил три пода,
   а minikube-m03 — два).
5. Если изменить манифест ./nginx-deployment.yaml, указав в качестве селек-
   тора узла в шаблоне пода значение node-type: slow, которое не назначено
  ни одному узлу в кластере, то поды не будут запланированы и развертыва-
   ние зависнет. Отредактируйте манифест следующим образом (или создайте
  новый файл 02_nodeselector/nginx-deployment-slow.yaml):
   # 02_nodeselector/nginx-deployment.yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: nginx-app
