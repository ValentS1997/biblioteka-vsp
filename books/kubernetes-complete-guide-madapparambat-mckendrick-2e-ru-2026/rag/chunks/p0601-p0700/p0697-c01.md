Автомасштабирование узлов Kubernetes     697

Чтобы реализовать автомасштабирование кластера, выполните следующие
шаги.

1. Для изоляции эксперимента создайте пространство имен ca-demo:
   # ca/ca-demo-ns.yaml
   ---
   apiVersion: v1
   kind: Namespace
   metadata:
     name: ca-demo
     labels:
       project: ca-demo
2. Чтобы поды могли обращаться к объектам Deployment через API Kubernetes,
   необходимо назначить дополнительные разрешения RBAC. Подробные све-
   дения о механизме RBAC приведены в главе 18. Подготовьте определение
   объекта Role:
   # ca/deployment-reader-role.yaml
   ---
   apiVersion: rbac.authorization.k8s.io/v1
   kind: Role
   metadata:
     namespace: ca-demo
     name: deployment-reader
   rules:
     - apiGroups: ["apps"]
       resources: ["deployments"]
       verbs: ["get", "watch", "list"]
3. Создайте объект ServiceAccount, который будут использовать поды генера-
   торов нагрузки:
   # ca/elastic-hamster-serviceaccount.yaml
   apiVersion: v1
   kind: ServiceAccount
   metadata:
     name: elastic-hamster
     namespace: ca-demo
4. Подготовьте YAML-манифест для объекта RoleBinding:
   # ca/read-deployments-rolebinding.yaml
   apiVersion: rbac.authorization.k8s.io/v1
   kind: RoleBinding
   metadata:
     name: read-deployments
     namespace: ca-demo
   subjects:
     - kind: ServiceAccount
       name: elastic-hamster
       namespace: default
   roleRef:
     kind: Role
     name: deployment-reader
     apiGroup: rbac.authorization.k8s.io
