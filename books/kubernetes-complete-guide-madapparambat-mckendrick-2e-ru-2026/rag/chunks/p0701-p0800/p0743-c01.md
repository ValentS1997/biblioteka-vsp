Устранение неполадок в Kubernetes     743

Если в поде несколько контейнеров, укажите нужный с помощью флага -c:

 $ kubectl exec blog-675df44d5-gkrt2 -c blog -- env

Одним из наиболее распространенных вариантов использования команды
kubectl exec является запуск сеанса интерактивной оболочки внутри кон-
тейнера. Это позволяет выполнять диагностические команды, например про-
сматривать журналы или изменять конфигурационные файлы, на лету. Чтобы
запустить интерактивную оболочку (например, /bin/sh или /bin/bash), ис-
пользуйте следующую команду:

 $ kubectl exec -it blog-675df44d5-gkrt2 -n trouble-ns -- /bin/bash
 root@blog-675df44d5-gkrt2:/app# whoami; hostname; uptime
 root
 blog-675df44d5-gkrt2
 14:36:03 up 10:19,  0 user,  load average: 0.17, 0.07, 0.69
 root@blog-675df44d5-gkrt2:/app#

Здесь:
z  -i означает интерактивный режим;
z  -t выделяет псевдо-TTY.

Такой интерактивный сеанс особенно полезен, когда вам нужно исследовать
окружение контейнера или выполнить серию команд для устранения непо-
ладок.
Помимо выполнения команд, kubectl exec позволяет копировать файлы в кон-
тейнер и из контейнера с помощью команды kubectl cp. Это особенно удобно,
когда требуется загрузить в контейнер сценарий или извлечь из него журнал
для дальнейшего анализа. Например, чтобы скопировать файл с локальной
машины в контейнер, используйте команду:

 $ kubectl cp troubles/test.txt blog-675df44d5-gkrt2:/app/test.txt -n trouble-ns
 $ kubectl exec -it blog-675df44d5-gkrt2 -n trouble-ns -- ls -l /app
 total 8
 -rw-r--r-- 1 root root  902 Aug 20 16:52 app.py
 -rw-r--r-- 1 1000 1000   20 Aug 31 14:42 test.txt

А чтобы скопировать файл из контейнера в локальную систему, выполните
команду:

 $ kubectl cp blog-675df44d5-gkrt2:/app/app.py /tmp/app.py -n trouble-ns

Эта возможность значительно упрощает перенос файлов между вашей средой
и контейнерами в Kubernetes-кластере, делая процесс диагностики и отладки
более эффективным.
