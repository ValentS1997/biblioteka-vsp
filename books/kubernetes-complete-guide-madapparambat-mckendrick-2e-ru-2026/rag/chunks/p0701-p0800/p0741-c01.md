Устранение неполадок в Kubernetes     741

При отладке Kubernetes-приложений команда kubectl logs является важ
нейшим инструментом для получения и анализа логов отдельных контейнеров
внутри пода, помогающим эффективно выявлять и устранять проблемы.

Чтобы получить логи пода, используйте команду:

 $ kubectl logs todo-app

Эта команда выводит логи первого контейнера в поде. Если под содержит не-
сколько контейнеров, необходимо указать имя конкретного контейнера:

 $ kubectl logs todo-app -c app-container

Для потоковой передачи логов в реальном времени (как при использовании
команды tail -f в Linux) используйте флаг -f:

 $ kubectl logs -f todo-app

Это весьма удобно для наблюдения за работающими процессами. Если под был
перезапущен, логи его предыдущего экземпляра можно получить с помощью
следующей команды:

 $ kubectl logs todo-app --previous

Чтобы отфильтровать логи по меткам, комбинируйте kubectl с такими инстру-
ментами, как jq:

 $ kubectl get pods -l todo -o json \
     | jq -r '.items[] | .metadata.name' \
     | xargs -I {} kubectl logs {}

Для эффективного управления логами и предотвращения переполнения диска
важно обеспечить их ротацию, архивируя или удаляя старые записи по мере по-
явления новых. Использование структурированных логов, например, в формате
JSON упрощает их анализ и разбор с помощью инструментов вроде jq. Кроме
того, внедрение централизованной системы логирования, например стека EFK
(Elasticsearch, Fluentd, Kibana), позволяет агрегировать и с легкостью находить
логи любых компонентов кластера, получая целостное понимание поведения
приложений.

Таким образом, события и аудит-логи предоставляют всесторонние возмож-
ности для мониторинга и обеспечения безопасности. События дают представ-
ление о состоянии и поведении приложений, а журналы аудита фиксируют все
действия в кластере, помогая поддерживать безопасную и соответствующую
требованиям среду.
