744     Глава 21   •  Продвинутые возможности Kubernetes

В следующем подразделе мы обсудим эфемерные контейнеры, которые играют
важную роль в процессе устранения неполадок в Kubernetes.

Эфемерные контейнеры в Kubernetes
Эфемерные контейнеры — это особый тип контейнеров в Kubernetes, пред-
назначенный для таких временных, выполняемых на лету задач, как отладка.
В отличие от обычных контейнеров, которые рассчитаны на длительную работу
внутри подов, эфемерные контейнеры применяются для инспекции и устране-
ния неполадок. Они не перезапускаются автоматически и не имеют гарантиро-
ванного набора ресурсов.

Такие контейнеры можно добавить в уже существующий под, чтобы упростить
диагностику, и они являются особенно полезными в ситуациях, когда традици-
онные методы (например, kubectl exec) оказываются недоступными. К примеру,
если под использует образ distroless без отладочных инструментов, вы можете
добавить эфемерный контейнер, который предоставит оболочку и необходимые
диагностические утилиты (например, nslookup, curl, mysql client и т. д.). Эфе-
мерные контейнеры управляются отдельным API-обработчиком, поэтому их
нельзя добавить через kubectl edit или изменить после создания.
Например, в главе 8 мы использовали образ k8sutils (quay.io/iamgini/
k8sutils:debian12) в качестве отдельного пода для тестирования сервисов
и выполнения других задач. С помощью эфемерных контейнеров мы можем
использовать тот же образ, но внедрить контейнер прямо в рабочий под при-
ложения для целей диагностики.
Допустим, у нас есть под и сервис video-service, развернутые в пространстве
имен ingress-demo (см. файл ingress/video-portal.yaml). В этом случае мож-
но начать отладку, запустив эфемерный контейнер на основе образа k8sutils
с помощью команды:

 $ kubectl debug -it pod/video-7d945d8c9f-wkxc5 \
     --image=quay.io/iamgini/k8sutils:debian12 \
     -c k8sutils \
     -n ingress-demo

 root@video-7d945d8c9f-wkxc5:/# nslookup video-service

 Address:        10.96.0.10#53

 Name:   video-service.ingress-demo.svc.cluster.local
