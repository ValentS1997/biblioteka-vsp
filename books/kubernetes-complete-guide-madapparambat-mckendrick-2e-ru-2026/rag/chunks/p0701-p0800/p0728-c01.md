728     Глава 21   •  Продвинутые возможности Kubernetes

Инструмент etcdctl позволяет создать снимок состояния кластера etcd непо-
средственно с его активного узла. Этот процесс не влияет на производитель-
ность экземпляра etcd.
Инструменты etcdctl и etcdutl можно установить со страницы релизов etcd
(https://github.com/etcd-io/etcd/releases/):

 $ ETCDCTL_API=3 etcdctl \
     --endpoints=https://127.0.0.1:2379 \
     --cacert=/etc/kubernetes/pki/etcd/ca.crt \
     --cert=/etc/kubernetes/pki/etcd/server.crt \
     --key=/etc/kubernetes/pki/etcd/server.key \
     snapshot save /tmp/snapshot-pre-patch.db

Файлы trusted-ca-file, cert-file и key-file обычно можно найти в описании
пода etcd (например, в файле /etc/kubernetes/manifests/etcd.yaml).
После создания снимка следует проверить его целостность с помощью инстру-
мента etcdutl:

 $ etcdutl --write-out=table snapshot status snapshot.db

Эта команда выводит такие сведения, как хеш-значение, номер ревизии, общее
количество ключей и размер снимка.

         Если данные etcd хранятся в томе, поддерживающем создание снимков (напри-
          мер, в Amazon Elastic Block Store), их резервное копирование можно выполнить,

         позволяющих автоматизировать процесс создания снимков хранилища.

В облачных кластерах такие управляемые сервисы, как Google Kubernetes
Engine (GKE), Amazon EKS и Azure AKS, упрощают процесс резервного копи-
рования. Эти платформы обычно предоставляют встроенные инструменты для
автоматизированного создания резервных копий и восстановления. Например,
для регулярного резервного копирования состояния и конфигурации класте-
ра в EKS можно использовать сервис AWS Backup, а в AKS — Azure Backup,
не требующие ручного вмешательства.
