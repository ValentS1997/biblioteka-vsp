Лучшие практики защиты кластера Kubernetes      735

Некоторые концепции, обсуждаемые в этом разделе, уже были затронуты
в главе 18. Здесь мы вновь обратимся к ним, чтобы акцентировать их значение
в контексте лучших практик эксплуатации Kubernetes.

Контроль доступа к API Kubernetes
Поскольку Kubernetes в значительной степени опирается на свой API, для
обеспечения безопасности кластера в первую очередь нужно позаботиться
об ограничении доступа к нему.

z Использование TLS для защиты API-трафика. Kubernetes по умолчанию
  шифрует коммуникацию с API с помощью протокола TLS. Большинство
   методов установки предполагают автоматическое создание и настройку со-
   ответствующих сертификатов. Однако администраторам важно учитывать
   наличие незащищенных локальных портов и своевременно закрывать их.
z Аутентификация в API. Выберите метод аутентификации, соответствующий
  вашим потребностям. Для небольших однопользовательских кластеров мо-
   жет быть достаточно сертификатов или статических bearer-токенов. Крупные
   кластеры обычно требуют интеграции с существующими системами аутен-
   тификации, такими как OIDC или LDAP.
z Авторизация в API. После аутентификации каждый запрос к API проходит
   проверку в рамках процедуры авторизации. Kubernetes использует механизм
  RBAC, сопоставляя пользователей или их группы с набором прав, опреде-
   ленных в ролях. Эти права описывают разрешенные действия над ресурсами
  и могут действовать как в пределах отдельных пространств имен, так и на
   уровне всего кластера. Для повышения безопасности рекомендуется сочетать
   авторизаторы Node и RBAC.

Контроль доступа к kubelet
Агенты kubelet, управляющие узлами и контейнерами, публикуют конечные
точки HTTPS, предоставляющие значительный уровень контроля над узлом.
В рабочих средах необходимо убедиться, что для kubelet включены механизмы
аутентификации и авторизации.
Чтобы эффективно контролировать доступ к kubelet в рабочих кластерах,
следует обеспечить корректную работу механизмов аутентификации и автори-
зации в API Kubelet. По умолчанию разрешены только запросы, проходящие
через API-сервер Kubernetes, что предотвращает несанкционированные прямые
обращения к kubelet. Дополнительно можно усилить защиту, настроив RBAC-
разрешения для пользователей и сервисов и ограничив сетевую видимость
конечных точек kubelet с помощью сетевых политик или правил межсетевого
экрана.
