722     Глава 21   •  Продвинутые возможности Kubernetes

Файл gateway-api/gateway_api/gateway.yaml содержит пример ресурса Gateway,
ссылающегося на dev-cluster-gateway в поле gatewayClassName:

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: dev-gateway
  namespace: gateway-api-demo
spec:
  gatewayClassName: dev-cluster-gateway
  listeners:
    - name: http
      protocol: HTTP
      port: 80

Наконец, ресурс HTTPRoute (по назначению схожий с объектом Ingress) содержит
правила перенаправления трафика к различным сервисам:

# gateway-api/httproute.yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: dev-httproute
  namespace: gateway-api-demo
spec:
  parentRefs:
    - name: dev-gateway
      kind: Gateway
      namespace: gateway-api-demo
  hostnames:
    - "k8sbible.local"
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /video
      backendRefs:
        - name: video-service
          port: 80

Компоненты, участвующие в работе Gateway API, представлены на рис. 21.5.

Если вы хотите глубже разобраться в этой теме, обратитесь к документации
и попробуйте реализовать Gateway API в своем кластере. Gateway API созда-
вался в качестве замены Ingress API, однако он не поддерживает ресурс Ingress
напрямую. Поэтому вам придется единоразово преобразовать существующие
ресурсы Ingress в ресурсы Gateway API. Подробные рекомендации приведены
в руководстве по миграции с Ingress (https://gateway-api.sigs.k8s.io/guides/migrating-
from-ingress).
