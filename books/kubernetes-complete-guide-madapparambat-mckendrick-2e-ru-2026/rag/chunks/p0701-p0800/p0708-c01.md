708     Глава 21   •  Продвинутые возможности Kubernetes

z Один и тот же L4-балансировщик нельзя использовать для обслуживания
   нескольких доменов по технологии виртуального хостинга, основанного на
   именах.
z Маршрутизация на основе пути возможна только при использовании
   L7-балансировщика. Балансировщик уровня L4 в принципе нельзя сконфигу-
   рировать так, чтобы он проксировал запросы вида https://<loadBalancerIp>/
   service1 к сервису Kubernetes service1, а https://<loadBalancerIp>/
   service2 — к сервису service2, поскольку L4-балансировщик не понимает
   протокол HTTP(S).
z Реализация некоторых функций, таких как «липкие» сессии (sticky sessions)
  или привязка к куки (cookie affinity), требует использования балансировщи-
   ка нагрузки уровня L7.

В Kubernetes все эти задачи могут быть решены с помощью объекта Ingress,
который позволяет реализовать функциональность L7-балансировщика на-
грузки. Объект Ingress используется только для определения правил марш-
рутизации и балансировки, например для сопоставления путей с сервисами
Kubernetes.

Вот пример YAML-манифеста для объекта Ingress:

# ingress/portal-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: portal-ingress
  namespace: ingress-demo
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  rules:
    - host: k8sbible.local
      http:
        paths:
          - path: /video
            pathType: Prefix
            backend:
              service:
                name: video-service
                port:
                  number: 8080
          - path: /shopping
            pathType: Prefix
            backend:
              service:
                name: shopping-service
                port:
                  number: 8080
