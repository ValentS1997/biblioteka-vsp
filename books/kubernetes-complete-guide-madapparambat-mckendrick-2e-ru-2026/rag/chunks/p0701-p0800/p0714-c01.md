714     Глава 21   •  Продвинутые возможности Kubernetes

Примените YAML-файлы из каталога ingress:

 $ kubectl apply -f ingress/
 namespace/ingress-demo created
 configmap/blog-configmap created
 deployment.apps/blog created
 service/blog-service created
 ingress.networking.k8s.io/portal-ingress created
 configmap/shopping-configmap created
 deployment.apps/shopping created
 service/shopping-service created
 configmap/video-configmap created
 deployment.apps/video created
 service/video-service created

Проверьте состояние подов, сервисов и ресурсов Ingress:

 $ kubectl get po,svc,ingress -n ingress-demo

Если вы используете облачный кластер Kubernetes, то доменное имя k8sbib
le.local (или любое другое, указанное в конфигурации Ingress) должно быть
привязано к IP-адресу облачного балансировщика нагрузки. Если у вас нет за-
регистрированного доменного имени, вы можете смоделировать его с помощью
локального файла /etc/hosts (в Windows он находится по адресу C:\Windows\
System32\drivers\etc\hosts).

Например, предположим, что мы развернули кластер minikube и добавили
в файл /etc/hosts следующие IP-адреса виртуальной машины, полученные
с помощью команды minikube ip:

 # k8sbible minikube
 192.168.39.18 k8sbible.local
