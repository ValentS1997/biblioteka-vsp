720     Глава 21   •  Продвинутые возможности Kubernetes

Подождите несколько минут, пока компонент Application Gateway обновит
свою конфигурацию. Чтобы получить внешний IP-адрес Ingress-контроллера,
выполните следующую команду:

 $ kubectl get ingress
 NAME             CLASS   HOSTS   ADDRESS        PORTS   AGE
 example-ingress  <none>  *       52.191.222.39  80      36m

В нашем случае используется IP-адрес 52.191.222.39.
Проверьте конфигурацию, перейдя по путям /video и /shopping с использова-
нием полученного IP-адреса.

z Сервис 1: http://<внешний-IP>/video будет обслуживаться подами сервиса
   video-service.
z Сервис 2: http://<внешний-IP>/shopping будет обслуживаться подами сер-
   виса shopping-service.
z Сервис по умолчанию: http://<внешний-IP>/ будет обслуживаться подами
   сервиса blog-service.

Итак, вы успешно настроили и протестировали контроллер AGIC в AKS.

В следующем разделе вы познакомитесь с Gateway API — относительно но-
вым и мощным механизмом управления маршрутизацией трафика в кластере
Kubernetes.

Gateway API
Gateway API — это развивающийся набор ресурсов Kubernetes, предлагающий
более выразительный и расширяемый способ описания правил маршрутизации
сетевого трафика в кластере.

Он призван со временем заменить Ingress API, предоставив более мощный и гиб-
кий механизм для настройки балансировки нагрузки, HTTP-маршрутизации
и других сетевых функций.

Gateway API включает в себя следующие основные ресурсы.
z GatewayClass — определяет класс шлюзов (Gateways), которые разделяют
  общий набор конфигураций и управляются одним и тем же контроллером.
z  Gateway — экземпляр среды, трафик в которой управляется контроллером,
   например облачным балансировщиком нагрузки.
z HTTPRoute — задает правила маршрутизации HTTP-трафика от слушателя
  шлюза к сетевым конечным точкам, обычно представленным объектами
   Service.
