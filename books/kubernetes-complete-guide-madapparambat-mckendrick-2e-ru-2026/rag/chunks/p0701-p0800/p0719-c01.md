Продвинутая маршрутизация трафика с помощью объекта Ingress     719

Для простоты и наглядности мы создадим новый кластер AKS с активизирован-
ным контроллером AGIC, используя единственную команду. Чтобы развернуть
двухузловой кластер с именем k8sforbeginners-aks-agic в группе ресурсов
k8sforbeginners-rg, выполните команду:

 $ az aks create \
     --resource-group myResourceGroup \
     --name myAKSCluster \
     --node-count 2 \
     --network-plugin azure \
     --enable-managed-identity \
     -a ingress-appgw \
     --appgw-name MyAppGateway \
     --appgw-subnet-cidr "10.2.0.0/16" \
     --generate-ssh-keys

В результате будет создан компонент Azure Application Gateway с именем
AksApplicationGateway и подсетью CIDR 10.2.0.0/16.
После развертывания кластера необходимо сгенерировать файл kubeconfig для
использования с утилитой kubectl. Выполните следующую команду (она пере-
ключит контекст на новый кластер, при этом предыдущий контекст останется
доступен):

 $ az aks get-credentials \
     --resource-group k8sforbeginners-rg \
     --name k8sforbeginners-aks-agic
 Merged "k8sforbeginners-aks-agic" as current context in .kube/config

Теперь мы можем использовать YAML-манифесты для объектов Deployment
и Service из каталога ingress репозитория книги, которые использовали в пре-
дыдущем разделе. Однако для работы AGIC в YAML-файлах необходимо внести
некоторые изменения. Для большей ясности мы скопируем содержимое катало-
га ingress в новый каталог aks_agic и внесем изменения там. Скорректируйте
определение ресурса Ingress следующим образом:

# aks-agic/portal-ingress.yaml
...
spec:
  ingressClassName: azure-application-gateway
...

Чтобы изолировать тестовый пример, мы также переименовали пространство
имен в agic-demo. Примените YAML-манифесты из каталога aks_agic следую-
щим образом:

 $ kubectl apply -f aks_agic/
