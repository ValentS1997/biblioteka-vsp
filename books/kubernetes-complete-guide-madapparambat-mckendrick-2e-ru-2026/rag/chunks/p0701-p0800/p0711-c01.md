Продвинутая маршрутизация трафика с помощью объекта Ingress     711

        В облачных средах часто используются специализированные Ingress-кон
         троллеры, задействующие особые возможности конкретного поставщика об-
         лачных услуг, позволяющие внешнему балансировщику нагрузки напрямую
         взаимодействовать с подами. Данный подход не требует создания дополни-
         тельных служебных подов, а иногда даже позволяет обойтись без сервисов
         типа NodePort. Вся маршрутизация осуществляется на уровне программно
         определяемой сети (SDN) и сетевого интерфейса контейнера (CNI), причем
         балансировщик нагрузки может напрямую использовать частные IP-адреса
          подов. Пример применения такого подхода мы рассмотрим в разделе, посвя-
        щенном контроллеру Azure AGIC.

Инструкции по установке ingress-nginx для различных сред можно найти
в официальной документации: https://kubernetes.github.io/ingress-nginx/deploy/.
Хотя применение инструмента Helm является предпочтительным способом
развертывания, некоторые среды могут предусматривать специальные ин-
струкции. В облачных средах установка ingress-nginx обычно крайне про-
ста и сводится к применению одного YAML-манифеста (или к включению
ingress-nginx при создании управляемого облачного кластера Kubernetes),
который создает множество объектов Kubernetes. Например, в AKS или GKE
развернуть необходимые компоненты Ingress-контроллера можно с помощью
единственной команды:

 $ kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/
 controller-v1.11.2/deploy/static/provider/cloud/deploy.yaml

         Эта информация была актуальна на момент написания данной главы и тести-
         рования соответствующего развертывания. Для получения сведений о текущей
         стабильной версии обратитесь к документации Ingress-контроллера. Также
          учтите, что разные дистрибутивы Kubernetes могут предусматривать различные
          условия для реализации подобных функций; например, для включения ingress-
          nginx в GKE вам потребуются права администратора кластера. Подробности вы
         можете найти в документации: https://kubernetes.github.io/ingress-nginx/.

В AWS для публикации Nginx Ingress Controller используется сетевой балан-
сировщик нагрузки (Network Load Balancer, NLB), который настраивается с по-
мощью сервиса типа LoadBalancer:

 $ kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/
 controller-v1.11.2/deploy/static/provider/aws/deploy.yaml

YAML-манифест включает несколько ресурсов, необходимых для настрой-
ки объекта Ingress в кластере, в том числе Role, RoleBinding, Namespace
и ConfigMap.
