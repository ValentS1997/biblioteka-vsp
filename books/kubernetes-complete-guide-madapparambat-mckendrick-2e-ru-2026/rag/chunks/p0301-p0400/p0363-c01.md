ект VolumeSnapshot предоставляет стандартизированный способ получения
точной копии данных тома на конкретный момент времени. Для управления
снимками состояния Kubernetes использует три ресурса: VolumeSnapshot,
VolumeSnapshotContent и VolumeSnapshotClass. Объект VolumeSnapshot
представляет собой пользовательский запрос на создание снимка, а Volu
meSnapshotContent — сам снимок. Эти ресурсы позволяют фиксировать со-
стояние томов без выделения нового тома, что особенно полезно, например,
при создании резервных копий баз данных перед выполнением критически
важных обновлений или удалений. В отличие от обычных объектов PV ресурсы
для работы со снимками состояния томов реализованы в виде CRD (Custom
Resource Definition — определение пользовательского ресурса) и требуют нали-
чия CSI-драйвера, поддерживающего создание таких снимков. Для выполнения
операций CreateSnapshot и DeleteSnapshot CSI-драйвер использует контейнер-
прицеп под названием csi-snapshotter.
Когда пользователь создает снимок, он может быть либо заранее выделен адми-
нистратором, либо динамически создан из существующего PVC. В обоих случаях
контроллер снимков связывает ресурсы VolumeSnapshot и VolumeSnapshotContent,
гарантируя соответствие содержимого снимка запросу пользователя. Снимки
легко удаляются или сохраняются в зависимости от заданной политики удаления
(DeletionPolicy), что обеспечивает гибкость управления данными. Кроме того,
Kubernetes предоставляет возможность при восстановлении данных из снимка
задать иной режим тома (например, Filesystem вместо Block) и создать на его
основе новый объект PVC. Такая функциональность делает VolumeSnapshot
мощным инструментом защиты данных. В сочетании с возможностью клони-
рования томов CSI она позволяет эффективно создавать резервные копии или
тестовые среды, повышая гибкость управления хранилищем в Kubernetes.

         Клонирование томов в Kubernetes идеально подходит для создания идентич-
         ных копий PersistentVolume, что особенно востребовано в средах разработки
         и тестирования. Снимки состояния, в свою очередь, фиксируют состояние тома
          в конкретный момент времени, что делает их полезными для резервного копи-
         рования и восстановления данных.
         Подробнее о снимках состояния томов можно узнать по адресу https://kubernetes.
           io/docs/concepts/storage/volume-snapshots/.

В следующем разделе мы рассмотрим способ увеличить размер тома через PVC.

Увеличение размера тома через PersistentVolumeClaim
Система Kubernetes поддерживает встроенный механизм расширения PVC,
что позволяет с легкостью увеличивать объем хранилища для приложений.
Эта возможность доступна только для томов, выделяемых через CSI-драйверы
(начиная с версии 1.29, другие типы томов признаны устаревшими).
