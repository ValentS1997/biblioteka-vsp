Объект ReplicaSet     381

Примените манифест к кластеру с помощью следующей команды:

 $ kubectl apply -f ./nginx-replicaset-livenessprobe.yaml

Удостоверьтесь в том, что поды успешно запустились:

 $ kubectl get pods

Теперь выберите один из подов ReplicaSet, чтобы смоделировать сбой внутри
контейнера, который приведет к провалу проверки жизнеспособности. В на-
шем примере мы выберем первый под из списка и удалим файл index.html.
Выполните приведенную ниже команду. Она удалит файл index.html, который
предоставляет сервер nginx, и спровоцирует ошибку при обработке HTTP-
запроса типа GET:

 $ kubectl exec -it nginx-replicaset-livenessprobe-example-lgvqv -- rm /usr/
 share/nginx/html/index.html

Чтобы просмотреть события, связанные с этим подом, выполните команду
kubectl describe:

 $ kubectl describe pod/nginx-replicaset-livenessprobe-example-lgvqv
 Name:           nginx-replicaset-livenessprobe-example-lgvqv
 ...<фрагмент опущен для краткости>...

   Normal   Scheduled  2m9s                  default-scheduler  Successfully

   Normal   Pulled     60s (x2 over 2m8s)    kubelet            Container image

   Normal   Killing    60s                   kubelet            Container nginx

Как видите, проверка жизнеспособности правильно зафиксировала неисправ-
ность веб-сервера и инициировала перезапуск контейнера внутри пода.

Важно отметить, что сам объект ReplicaSet не участвовал в перезапуске — это
действие было выполнено на уровне пода. Пример демонстрирует то, как от-
дельные объекты Kubernetes, обладающие разными функциями, могут взаи-
модействовать друг с другом для повышения отказоустойчивости системы.
