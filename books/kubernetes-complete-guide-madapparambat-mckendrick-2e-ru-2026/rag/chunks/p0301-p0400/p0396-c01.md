396     Глава 11   •  Использование объекта Deployment

        body {
    --
      <h1>Welcome to nginx!</h1>
    <p>If you see this page, the nginx web server is successfully installed and
    working. Further configuration is required.</p>

Этот пример демонстрирует то, как сервисы позволяют сделать поды объектов
Deployment доступными для внешнего трафика. Далее мы посмотрим, как мож-
но добиться того же результата с помощью императивных команд.

Создание сервиса императивным способом
Аналогичного результата можно добиться с помощью императивной коман-
ды kubectl expose. Создадим сервис для нашего объекта Deployment nginx-
deployment-example:

 $ kubectl expose deployment --type=LoadBalancer nginx-deployment-example
 service/nginx-deployment-example exposed

Вот подробный разбор этого фрагмента кода.
z Команда создаст сервис с именем объекта Deployment, то есть nginx-
   deployment-example. Если вы хотите использовать другое имя (как в преды-
  дущем примере), укажите параметр --name=nginx-service-example.
z Этот сервис будет использовать порт 80 — тот же, что и поды. Чтобы его из-
   менить, используйте параметры --port=<номер> и --target-port=<номер>.

          Все доступные параметры, используемые для публикации объекта Deployment,
        можно просмотреть с помощью команды kubectl expose deployment --help.

Императивный способ рекомендуется использовать только в ходе разработки
или отладки. В рабочих средах следует применять такие декларативные под-
ходы, как «инфраструктура как код» (IaC) и «конфигурация как код» (CaC).
В следующем пункте вы узнаете, как использовать проверки готовности, жиз-
неспособности и успешности запуска с объектами Deployment.

Роль проверок готовности, жизнеспособности
и успешности запуска
В главе 8 вы узнали о том, что для каждого контейнера, работающего в поде,
можно настроить три типа проверок (или проб):

z проверку готовности (readinessProbe);
z проверку жизнеспособности (livenessProbe);
z проверку успешности запуска (startupProbe).
