356     Глава 9   •  Постоянное хранилище в Kubernetes

Список объектов StorageClass, созданных в кластере, можно вывести с помощью
следующей команды kubectl:

 $ kubectl get sc
 NAME                 PROVISIONER              RECLAIMPOLICY   VOLUMEBINDINGMODE
 ALLOWVOLUMEEXPANSION   AGE
 standard (default)   k8s.io/minikube-hostpath Delete          Immediate
 false                  7d

Подробные сведения об объекте StorageClass можно посмотреть с помощью
параметра -o yaml:

 $ kubectl get storageclasses standard -o yaml
 apiVersion: storage.k8s.io/v1
 kind: StorageClass
 ... <фрагмент опущен для краткости> ...
 metadata:
   name: standard
   resourceVersion: "290"
   uid: f41b765f-301f-4781-b9d0-46aec694336b
 provisioner: k8s.io/minikube-hostpath
 reclaimPolicy: Delete
 volumeBindingMode: Immediate

Кроме того, допустимо использовать форму во множественном числе stora
geclasses, а также псевдоним sc. Следующие три варианта команды эквива-
лентны:

 $ kubectl get storageclass
 $ kubectl get storageclasses
 $ kubectl get sc

Во всех трех случаях вывод одинаков, поэтому мы опустили его для краткости.
Наибольшую важность для нас представляют следующие два поля этого вывода:

z  NAME — имя и уникальный идентификатор объекта StorageClass;
z  PROVISIONER — название базовой технологии хранения; по сути, это фрагмент
   кода, который кластер Kubernetes использует для взаимодействия с выбран-
   ной системой хранения.

        Вы можете создать несколько объектов StorageClass, использующих один
         и тот же провиженер.

Поскольку мы работаем с кластером minikube в лабораторной среде, у нас есть
объект StorageClass standard, использующий провиженер k8s.io/minikube-
hostpath.
