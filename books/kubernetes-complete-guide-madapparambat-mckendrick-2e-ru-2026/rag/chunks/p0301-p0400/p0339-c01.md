Назначение постоянного хранилища данных     339

Управление хранением данных
с помощью объектов PersistentVolume
Как мы уже выяснили, ресурс PersistentVolume является указателем на ме-
сто хранения, которым может быть, например, диск, NFS или дисковый том,
управляемый сторонним оператором. Все эти технологии работают по-разному.
К счастью, в Kubernetes все они представлены через объект PersistentVolume.

Таким образом, YAML-манифесты для создания объектов PersistentVolume
будут немного различаться в зависимости от технологии, лежащей в основе
хранилища. Например, если вы хотите, чтобы PersistentVolume указывал на
общий ресурс NFS, вам необходимо соблюсти два условия:

z общий ресурс NFS должен быть предварительно настроен и доступен для
   узлов Kubernetes;
z YAML-манифест для PersistentVolume должен содержать сведения об NFS-
   сервере и соответствующем общем ресурсе.

Ниже приведен пример YAML-манифеста для создания объекта Persistent
Volume, использующего NFS в качестве технологии хранения данных:

# pv-nfs.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-nfs
spec:
  capacity:
    storage: 5Gi
  volumeMode: Filesystem
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Recycle
  storageClassName: slow
  mountOptions:
    - hard
    - nfsvers=4.1
  nfs:
    path: /appshare
    server: nfs.example.com

Чтобы объект PersistentVolume работал корректно, он должен обеспечить связь
между системой Kubernetes и реальным хранилищем. Для этого необходимо соз-
дать или выделить участок хранилища за пределами Kubernetes, а затем создать
объект PersistentVolume, указав уникальный идентификатор диска или тома,
предоставляемого внешней по отношению к Kubernetes технологией хранения
данных. В следующем разделе мы рассмотрим пример YAML-манифеста для
создания объекта PersistentVolume на основе блочного тома.
