Знакомство с объектом Deployment     399

установлен в значение /bin/sh для выполнения пользовательской команды
оболочки. Дополнительные аргументы сформированы следующим образом.

z  -c — аргумент для /bin/sh, указывающий на то, что далее следует команда,
   которую нужно выполнить в оболочке.
z  touch /usr/share/nginx/html/ready — первая команда, выполняемая в обо-
   лочке контейнера. Она создает пустой файл ready, который сервер Nginx
   будет предоставлять через конечную точку /ready.
z echo "You have been served by Pod with IP address: $(hostname -i)" >
   /usr/share/nginx/html/index.html — вторая команда, которая записывает
   в index.html информацию об IP-адресе пода в кластере. Команда hostname -i
   используется для получения IP-адреса контейнера. Для каждого пода
   Deployment это значение будет своим.
z  nginx -g "daemon off;" — наконец, выполняется стандартная команда запуска
   образа nginx:1.25.4. Это инициирует запуск веб-сервера Nginx в качестве
   основного процесса контейнера.

        Обычно подобные настройки выполняются с помощью нового контейнерно-
          го образа, который наследуется от базового (например, образа nginx) и со-
         держит специализированный сценарий приложения. Представленный здесь
         метод используется в демонстрационных целях и показывает, насколько гибкой
          является среда выполнения Kubernetes. Для создания пользовательских кон-
         тейнерных образов обратитесь к примеру Chapter11/Containerfile в репозитории
          GitHub.

Вторая группа изменений, внесенных в YAML-манифест Deployment, касается
определения проверки готовности (readinessProbe), которая настроена следу-
ющим образом.

z Данная проверка имеет тип httpGet и выполняет GET-запрос к конечной
   точке /ready на порте 80 контейнера.
z  initialDelaySeconds: запросы начинают отправляться через 5 секунд после
   запуска контейнера.
z  periodSeconds: запросы отправляются каждые 2 секунды.
z  timeoutSeconds: время ожидания перед тайм-аутом составляет 10 секунд.
z  successThreshold: для признания пода готовым достаточно одной успешной
   проверки.
z  failureThreshold: для признания пода неготовым требуются две последова-
   тельные неудачные проверки. Значение больше 1 помогает избежать ложных
   срабатываний.
