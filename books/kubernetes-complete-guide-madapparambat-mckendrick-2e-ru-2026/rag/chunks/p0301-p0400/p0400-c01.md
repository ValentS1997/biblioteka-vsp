400     Глава 11   •  Использование объекта Deployment

Для создания объекта Deployment выполните следующие шаги.

1. Примените новый YAML-манифест:

    $ kubectl apply -f ./nginx-deployment-readinessprobe.yaml

2. Убедитесь в том, что сервис nginx-service-example отображает IP-адреса
   бэкенд-подов. Вы увидите три конечные точки, соответствующие подам
   Deployment и готовые обслуживать трафик:

    $ kubectl describe svc nginx-service-example
    Name:                     nginx-service-example
    Namespace:                default
    Labels:                   <none>
    Annotations:              <none>
    Selector:                 app=nginx,environment=test
    Type:                     LoadBalancer
    IP Family Policy:         SingleStack
    IP Families:              IPv4
    IP:                       10.96.231.126
    IPs:                      10.96.231.126
    Port:                     <unset>  80/TCP
    TargetPort:               80/TCP
    NodePort:                 <unset>  32563/TCP
    Endpoints:                10.244.1.6:80,10.244.1.7:80,10.244.2.6:80
    Session Affinity:         None
    External Traffic Policy:  Cluster
    Events:                   <none>

3. Протестируйте доступ к веб-серверу Nginx с помощью пода k8sutils, соз-
   данного ранее в главе. Вы заметите, что ответы приходят от подов с разными
   IP-адресами. Это объясняется тем, что объект Deployment содержит три
   реплики, поэтому запросы могут направляться разным подам:

    $ kubectl exec -it k8sutils -- curl nginx-service-example.default.svc.
    cluster.local
    You have been served by Pod with IP address: 10.244.1.7
    $ kubectl exec -it k8sutils -- curl nginx-service-example.default.svc.
    cluster.local
    You have been served by Pod with IP address: 10.244.2.6

4. А теперь смоделируем неудачное прохождение проверки готовности перво-
   го пода. В нашем случае это nginx-deployment-readiness-69dd4cfdd9-4pkwr
   с IP-адресом 10.244.1.7. Для этого достаточно удалить файл ready внутри
   контейнера с помощью команды kubectl exec:

    $ kubectl exec -it nginx-deployment-readiness-69dd4cfdd9-4pkwr -- rm /usr/
    share/nginx/html/ready

5. Теперь проверка готовности начнет возвращать ошибки, но не сразу.
