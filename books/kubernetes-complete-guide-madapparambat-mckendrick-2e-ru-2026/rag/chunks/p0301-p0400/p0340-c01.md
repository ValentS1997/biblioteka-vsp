340     Глава 9   •  Постоянное хранилище в Kubernetes

Создание объекта PersistentVolume
на основе блочного тома
Следующий YAML-манифест описывает объект PersistentVolume, указывающий
на блочный том:

# pv-block.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-block
spec:
  capacity:
    storage: 100Gi
  accessModes:
    - ReadWriteOnce
  volumeMode: Block
  persistentVolumeReclaimPolicy: Retain
  fc:
    targetWWNs: ["50060e801049cfd1"]
    lun: 0
    readOnly: false

Как видите, раздел fc этого YAML-манифеста содержит сведения о FC-томе, на
который ссылается данный объект PersistentVolume. Конкретный блочный том
определяется ключом targetWWNs. Такого YAML-манифеста системе Kubernetes
достаточно для нахождения соответствующего всемирного имени WWN (World
Wide Name) и поддержания ссылки на него.

Теперь поговорим о выделении ресурсов хранилища.

Может ли Kubernetes выделять
или создавать ресурсы хранилища самостоятельно
Необходимость по отдельности создавать ресурсы хранилища и объекты
PersistentVolume может показаться утомительной.

К счастью, благодаря способности взаимодействовать с API облачного провайде-
ра и другими технологиями хранения Kubernetes может создать тома или диски
на лету. Для этого используется механизм динамического выделения постоянных
томов, который существенно упрощает управление объектами PersistentVolume.
Однако он работает только с поддерживаемыми технологиями хранения и об-
лачными провайдерами.
