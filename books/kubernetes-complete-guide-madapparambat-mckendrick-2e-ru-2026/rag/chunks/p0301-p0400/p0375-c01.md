Объект ReplicaSet     375

В следующем подразделе мы поговорим о тестировании поведения объекта
ReplicaSet.

Тестирование поведения объекта ReplicaSet
Чтобы продемонстрировать гибкость объекта ReplicaSet, удалим один из подов,
которыми управляет объект nginx-replicaset-example, с помощью команды
kubectl delete:

 $ kubectl delete po nginx-replicaset-example-6qc9p -n rs-ns

Если действовать быстро1, то с помощью команды kubectl get pods можно за-
метить, как один из подов завершает работу, а ReplicaSet немедленно создает
новый для восстановления целевого количества реплик.

Чтобы получить больше информации о событиях, произошедших с объектом
ReplicaSet из нашего примера, используйте команду kubectl describe:

 $ kubectl describe rs/nginx-replicaset-example -n rs-ns
 ...
 Events:
   Type    Reason             Age   From                    Message
   ----    ------             ----  ----                    -------
 ...<фрагмент опущен для краткости>...
   Normal  SuccessfulCreate   9m9s  replicaset-controller   Created pod: nginx-
 replicaset-example-r2qfn
   Normal  SuccessfulCreate   3m1s  replicaset-controller   Created pod: nginx-
 replicaset-example-krdrs

В данном случае nginx-replicaset-example-krdrs представляет собой новый
под, созданный объектом ReplicaSet.

Теперь создадим «голый» под, метки которого совпадают с селектором нашего
объекта ReplicaSet. В результате количество подов, удовлетворяющих услови-
ям ReplicaSet, станет равным четырем, и этот объект удалит один под, чтобы
вернуть число реплик к целевому значению, равному трем.

          Будьте осторожны с метками «голых» подов (подов, не находящихся под управ-
         лением объекта ReplicaSet). Объект ReplicaSet может взять под контроль лю-
         бой под с соответствующими метками, что может привести к нежелательным
          результатам. Чтобы избежать подобных конфликтов, снабжайте «голые» поды
         уникальными метками.

1  Для наглядности в соседнем терминале лучше выполнить watch -n 1 kubectl get
   pods -n rs-ns.
