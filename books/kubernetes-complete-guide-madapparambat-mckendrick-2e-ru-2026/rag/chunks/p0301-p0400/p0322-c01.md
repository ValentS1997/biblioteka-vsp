322     Глава 8   •  Публикация подов с помощью сервисов

Проверка жизнеспособности путем установки TCP-соединения
В данной ситуации выполняется попытка установить соединение с TCP-сокетом
на порте 80. В случае успеха проверка жизнеспособности считается пройденной,
а контейнер — готовым к работе. В противном случае проверка завершается
с ошибкой и под отключается. Вот пример соответствующей конфигурации:

# nginx-pod-with-liveness-tcp.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-with-liveness-tcp
spec:
  containers:
    - name: nginx-pod-with-liveness-tcp
      image: nginx
      livenessProbe:
        initialDelaySeconds: 5
        periodSeconds: 5
        tcpSocket:
          port: 80

TCP-проверка во многом похожа на HTTP-проверку, так как протокол HTTP
работает поверх TCP. Она особенно полезна для оценки работоспособности
приложения, которое не использует HTTP в качестве протокола, а также в тех
случаях, когда применение HTTP-запросов не имеет смысла, например при
проверке состояния соединения с LDAP.

Использование именованного порта
в рамках TCP- и HTTP-проверки
Для настройки проверки жизнеспособности типа TCP и HTTP (но не gRPC)
можно использовать именованный порт, как показано ниже:

# nginx-pod-with-liveness-http-named-port.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-with-liveness-http-named-port
spec:
  containers:
    - name: nginx-pod-with-liveness-http-named-port
      image: nginx
      ports:
        - name: liveness-port
          containerPort: 8080
          hostPort: 8080
      livenessProbe:
        initialDelaySeconds: 5
        periodSeconds: 5
        httpGet:
          path: /healthcheck
          port: liveness-port
