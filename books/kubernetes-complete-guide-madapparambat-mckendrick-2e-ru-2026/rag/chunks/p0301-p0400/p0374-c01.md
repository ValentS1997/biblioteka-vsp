374     Глава 10   •  Запуск рабочих нагрузок производственного уровня

на основе множеств можно задать с помощью .spec.selector.matchExpressions.
Например:

# nginx-replicaset-expressions.yaml
...<фрагмент опущен для краткости>...
spec:
  replicas: 4
  selector:
    matchLabels:
      app: nginx
    matchExpressions:
      - key: environment
        operator: In
        values:
          - test
          - dev
  template:
...<фрагмент опущен для краткости>...

Эта конфигурация предписывает ReplicaSet выбирать только те поды, у которых
есть метка app=nginx, а также метка environment=test или environment=dev.

        При определении объекта ReplicaSet значения в разделе .spec.template.meta
            data.labels должны совпадать с содержимым .spec.selector, иначе объект будет
         отклонен API.

Теперь применим манифест ReplicaSet к кластеру с помощью команды kubectl
apply:

 $ kubectl apply -f nginx-replicaset-example.yaml
 replicaset.apps/nginx-replicaset-example created

После этого можно проверить статус нового объекта nginx-replicaset-example:

 $ kubectl describe replicaset/nginx-replicaset-example -n rs-ns
 ...
 Replicas:    4 current / 4 desired
 Pods Status: 4 Running / 0 Waiting / 0 Succeeded / 0 Failed
 ...

Для просмотра подов, которыми управляет ReplicaSet, можно выполнить коман-
ду kubectl get pods -n rs-ns. Подробно изучить метки пода и убедиться, что в его
описании присутствует свойство Controlled By: ReplicaSet/nginx-replicaset-
example, можно с помощью команды kubectl describe pod <Id_пода>.

        При выполнении команд kubectl можно использовать сокращение rs вместо
         полной формы replicaset.
