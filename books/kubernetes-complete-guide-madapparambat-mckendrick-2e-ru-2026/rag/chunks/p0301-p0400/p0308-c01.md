308     Глава 8   •  Публикация подов с помощью сервисов

В отличие от сервисов NodePort сервисы ClusterIP не занимают порт рабочего
узла, поэтому к ним невозможно обратиться извне кластера.

Учтите, что для одного и того же пула подов можно использовать оба типа сер-
висов. Если вы хотите сделать приложение общедоступным и организовать его
внутреннее взаимодействие с другими подами, можете создать два сервиса —
один типа NodePort и один типа ClusterIP.
В этом случае нужно лишь дать сервисам разные имена, чтобы избежать кон-
фликтов при их создании через kube-apiserver. Никаких других ограничений
не существует.

Просмотр списка сервисов ClusterIP
Для вывода списка сервисов типа ClusterIP используется та же команда, что
и для перечисления сервисов NodePort:

 $ kubectl get svc

В ее выводе будут перечислены все сервисы с указанием их типа.

Императивный способ создания сервисов ClusterIP
Сервис ClusterIP является одним из наиболее часто используемых объектов
Kubernetes, поэтому для его создания предусмотрено несколько способов.
В частности, его создать можно:

z  с помощью параметра --expose или метода kubectl expose (императивный
   способ);
z  с помощью YAML-манифеста (декларативный способ).

Императивный способ сводится к использованию параметра --expose с ко-
мандой kubectl run. В следующем примере мы создадим под nginx-clusterip
и сервис ClusterIP для его публикации. Чтобы сделать под доступным, при
использовании параметра --expose необходимо также указать порт, который
сервис ClusterIP будет прослушивать. Код для решения этой задачи выглядит
следующим образом:

 $ kubectl run nginx-clusterip --image nginx --expose=true --port=80
 service/nginx-clusterip created
 pod/nginx-clusterip created

Как видите, в результате создается и под, и публикующий его сервис. Теперь
посмотрим описание этого сервиса.
