312     Глава 8   •  Публикация подов с помощью сервисов

При использовании обычного сервиса ClusterIP вы всегда обращаетесь к од-
ному статичному IP-адресу, закрепленному за сервисом, который перенаправ-
ляет запросы к подам. В случае headless-сервиса система Kubernetes просто
возвращает список DNS-имен подов, а клиент сам выбирает, к какому из них
обращаться.

Как правило, headless-сервисы Kubernetes применяются в сценариях, требу
ющих прямого взаимодействия с отдельными подами в обход единой точки
входа и балансировщика нагрузки.

Они особенно полезны для организации взаимодействия с кластеризованными
сервисами с сохранением состояния, например с LDAP-серверами (Lightweight
Directory Access Protocol — легковесный протокол доступа к каталогам). В таких
случаях может потребоваться, чтобы LDAP-клиент имел доступ к отдельным
DNS-именам подов, на которых запущен LDAP-сервер. Обычный сервис типа
ClusterIP для этого не подходит, так как он предоставляет статический IP-адрес
и реализует балансировку нагрузки средствами Kubernetes. Далее вы познако-
митесь еще с одним типом сервиса.

Сервис типа LoadBalancer
Работа сервисов типа LoadBalancer зависит от облачной платформы, на которой
развернут кластер Kubernetes. То есть для их использования необходимо раз-
местить кластер в облаке, поддерживающем сервисы данного типа.

На облачных платформах, предоставляющих внешние балансировщики на-
грузки, указание значения LoadBalancer в поле type приводит к созданию
такого балансировщика для вашего сервиса. Этот процесс выполняется
асинхронно, а сведения о созданном балансировщике становятся доступны
в поле .status.loadBalancer объекта Service.
Некоторые облачные провайдеры позволяют задать параметр loadBalancerIP
для создания балансировщика с указанным IP-адресом. Если параметр loadBa
lancerIP не указан, балансировщику назначается эфемерный IP-адрес. Однако
если задать loadBalancerIP на платформе, не поддерживающей эту возмож-
ность, данный параметр будет проигнорирован.

Для сервиса типа LoadBalancer также доступно поле .spec.loadBalancerClass,
которое позволяет использовать реализацию балансировщика нагрузки, от-
личную от предоставляемой облачным провайдером по умолчанию. Если
значение loadBalancerClass не задано, Kubernetes использует стандарт-
