Объект ReplicaSet     377

Тестирование доступности и отказоустойчивости
с помощью ReplicaSet
В качестве демонстрации мы используем ранее развернутый объект nginx-
replicaset-example и создадим сервис, чтобы предоставить доступ к этому
приложению:

 $ kubectl apply -f nginx-service.yaml
 service/nginx-service created

Выполним проброс портов для тестирования этого сервиса:

 $ kubectl port-forward svc/nginx-service 8080:80 -n rs-ns
 Forwarding from 127.0.0.1:8080 -> 80
 Forwarding from [::1]:8080 -> 80

Проверим доступ к приложению в другой консоли:

 $ curl localhost:8080

В ответ вы должны получить стандартную страницу приветствия Nginx.

Ранее мы уже тестировали команду удаления пода и убедились в том, что объ-
ект ReplicaSet воссоздает поды для восстановления заданного числа их реплик.
Теперь проверим поведение при удалении узла Kubernetes. Сначала выясним
текущее распределение подов:

 $ kubectl get po -n rs-ns -o wide
 NAME                             READY   STATUS    RESTARTS   AGE   IP
 NODE           NOMINATED NODE   READINESS GATES
 nginx-replicaset-example-cfcfs   1/1     Running   0          24m   10.244.1.3
 kind-worker2   <none>           <none>
 nginx-replicaset-example-krdrs   1/1     Running   0          17m   10.244.3.5
 kind-worker    <none>           <none>
 nginx-replicaset-example-kw7cl   1/1     Running   0          24m   10.244.3.4
 kind-worker    <none>           <none>
 nginx-replicaset-example-r2qfn   1/1     Running   0          24m   10.244.2.4
 kind-worker3   <none>           <none>

Как видите, два пода работают на узле kind-worker. Удалим этот узел из кла-
стера:

 $ kubectl cordon kind-worker
 node/kind-worker cordoned

 $ kubectl drain kind-worker --ignore-daemonsets
