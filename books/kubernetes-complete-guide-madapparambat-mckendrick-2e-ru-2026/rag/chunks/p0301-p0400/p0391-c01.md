Знакомство с объектом Deployment     391

 $ kubectl annotate deployment/nginx-deployment-example kubernetes.io/
 change-cause='Updated image to 1.2.3'

Сразу после создания объекта Deployment можно использовать команду kubectl
rollout, чтобы отслеживать статус развертывания в реальном времени:

 $ kubectl rollout status deployment nginx-deployment-example
 Waiting for deployment "nginx-deployment-example" rollout to finish: 0 of 3
 updated replicas are available...
 deployment "nginx-deployment-example" successfully rolled out

Эта команда позволяет получить подробные сведения о происходящем во время
выкатывания объекта Deployment. Можно также использовать стандартные
команды kubectl get или kubectl describe:

 $ kubectl get deploy nginx-deployment-example
 NAME                       READY   UP-TO-DATE   AVAILABLE   AGE
 nginx-deployment-example   3/3     3            3           6m21s

Как видите, объект Deployment был успешно создан и все три пода находятся
в состоянии готовности.

         Вместо слова deployment в командах kubectl можно использовать сокращение
           deploy.

Просмотреть базовые объекты ReplicaSet можно следующим образом:

 $ kubectl get rs
 NAME                                  DESIRED   CURRENT   READY   AGE
 nginx-deployment-example-5b8dc6b8cd   3         3         3       2m17s

Обратите внимание на сгенерированный хеш 5b8dc6b8cd в имени объекта Re
plicaSet — он совпадает со значением упомянутой ранее метки pod-template-hash.
Наконец, мы можем просмотреть поды в кластере, созданные объектом Deploy
ment, выполнив следующую команду:

 $ kubectl get pods
 NAME                                         READY   STATUS    RESTARTS   AGE
 nginx-deployment-example-5b8dc6b8cd-lj2bz    1/1     Running   0          3m30s
 nginx-deployment-example-5b8dc6b8cd-nxkbj    1/1     Running   0          3m30s
 nginx-deployment-example-5b8dc6b8cd-shzmd    1/1     Running   0          3m30s

Итак, вы создали и исследовали свой первый объект Deployment в Kubernetes!
Далее мы поговорим об использовании сервисов для публикации объектов
Deployment и обеспечения доступа внешнего трафика в кластер.
