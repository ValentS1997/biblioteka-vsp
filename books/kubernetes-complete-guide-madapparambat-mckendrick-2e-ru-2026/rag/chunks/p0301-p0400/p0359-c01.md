Статическое и динамическое выделение объектов PersistentVolume     359

Теперь создадим объект PersistentVolumeClaim, который динамически создаст
том типа hostPath. Ниже приведен YAML-манифест для объекта PVC. Обратите
внимание на значение standard в поле storageClassName:

# pvc-dynamic.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-dynamic-hostpath-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: standard   # ВАЖНО
  resources:
    requests:
      storage: 1Gi
  selector:
    matchLabels:
      type: hostpath
      env: prod

А сейчас создадим объект PVC в нужном пространстве имен:

 $ kubectl apply -f pvc-dynamic.yaml -n dynamicstorage
 persistentvolumeclaim/my-dynamic-hostpath-pvc created

И проверим статус объектов PV и PVC:

 $ kubectl get pod,pvc,pv -n dynamicstorage
 NAME                                       STATUS   VOLUME
 CAPACITY   ACCESS MODES   STORAGECLASS   VOLUMEATTRIBUTESCLASS   AGE
 persistentvolumeclaim/my-dynamic-hostpath-pvc   Bound
 pvc-4597ab27-c894-40de-a7ac-1b6ca961bcdc   1Gi        RWO            standard
 <unset>                 7s

 NAME                                                        CAPACITY
 ACCESS MODES   RECLAIM POLICY   STATUS   CLAIM
 STORAGECLASS   VOLUMEATTRIBUTESCLASS   REASON   AGE
 persistentvolume/pvc-4597ab27-c894-40de-a7ac-1b6ca961bcdc   1Gi        RWO
 Delete           Bound    dynamicstorage/my-dynamic-hostpath-pvc      standard
 <unset>                          7s

Как видите, PV был создан с помощью StorageClass и привязан к PVC в соот-
ветствии с запросом.
После создания объекта PersistentVolumeClaim можно добавить новый под,
в который он будет смонтирован. Вот YAML-манифест для этого пода:

# pod-with-dynamic-pvc.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-dynamic-storage
