Постоянное хранилище
      в Kubernetes9

В предыдущих главах вы познакомились с некоторыми ключевыми концепция
ми Kubernetes. Вы также узнали, что эта система позволяет задавать желаемое
состояние для всех традиционных уровней ИТ-инфраструктуры путем создания
объекта в хранилище etcd, который затем преобразуется в реальные вычисли-
тельные ресурсы внутри кластера.
В этой главе мы поговорим о постоянном хранилище данных для приложений
с сохранением состояния. Как и в случае с другими абстракциями ресурсов, для
организации постоянного хранилища в кластере используется набор объектов.
В Kubernetes оно реализуется с помощью ресурса типа PersistentVolume, обла-
дающего особой механикой. Не переживайте, если она покажется вам сложной,
далее мы подробно разберем все ее особенности.

Технические требования
Для работы с главой вам потребуется:
z локальный или облачный кластер Kubernetes;
z рабочий интерфейс командной строки kubectl, настроенный для взаимо-
   действия с кластером.

Инструкции по созданию кластера Kubernetes и настройке клиента kubectl
приведены в главах 2 и 3.
Примеры кода для этой главы можно загрузить из официального репозитория
GitHub по адресу https://github.com/PacktPublishing/The-Kubernetes-Bible-Second-Edition/
tree/main/Chapter09.
