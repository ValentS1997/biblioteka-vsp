386     Глава 11   •  Использование объекта Deployment

При реализации облачных приложений обычно требуются следующие типы
рабочих нагрузок.

z Без сохранения состояния (stateless). В мире контейнеров приложениями
   без сохранения состояния считаются те, которые не сохраняют данные (со-
   стояние) внутри самого контейнера. Представьте два контейнера с сервером
   Nginx, выполняющих одинаковую функцию: один хранит пользовательские
   данные в файле внутри контейнера, а другой использует отдельный контей-
   нер с MongoDB для постоянного хранения данных. Хотя оба контейнера
  решают одну и ту же задачу, первый сохраняет состояние, так как полагается
   на внутреннее хранилище. Второй, полагающийся на внешнюю базу данных,
   не сохраняет состояние. Такой подход упрощает управление и масштабиро-
   вание приложений в Kubernetes, поскольку позволяет легко перезапускать
   или заменять их без риска потери данных. Обычно для управления рабочими
   нагрузками без сохранения состояния в Kubernetes используются объекты
   Deployment.
z С сохранением состояния (stateful). Поды и контейнеры считаются сохраня-
  ющими состояние, если они хранят изменяемые данные внутри себя. Хоро-
  шим примером является под с MySQL или MongoDB, который читает и за-
   писывает данные в объект PersistentVolume. Управление такими рабочими
   нагрузками усложняется необходимостью контролировать «липкие» сессии
  и разделение данных при обновлениях, откатах и масштабировании. По воз-
   можности рабочие нагрузки с сохранением состояния следует выносить за
   пределы кластера Kubernetes, используя, например, облачные базы данных,
   предоставляемые по модели SaaS (Software-as-a-Service — программное обе-
   спечение как услуга). В Kubernetes для управления рабочими нагрузками
   с сохранением состояния применяются объекты StatefulSet. Подробнее о них
  мы поговорим в главе 12.
z Объекты Job и CronJob. Эти рабочие нагрузки предназначены для выпол-
   нения заданий по расписанию или по требованию. В зависимости от при-
  ложения пакетные (batch) рабочие нагрузки могут использовать тысячи
   контейнеров и множество узлов. К ним могут относиться любые процессы,
   выполняемые в фоновом режиме. Контейнеры для пакетной обработки также
   не должны хранить состояние, чтобы упростить возобновление прерванных
   заданий. В Kubernetes для управления такими нагрузками используются
   объекты Job и CronJob (см. главу 4).
z Объект DaemonSet. Бывают случаи, когда необходимо запустить рабочую
   нагрузку на каждом узле для обеспечения работы кластера Kubernetes. Это
   может быть актуально для системы мониторинга, логирования, агента управ-
   ления хранилищем (например, для PersistentVolume) и т. д. В таких случаях
