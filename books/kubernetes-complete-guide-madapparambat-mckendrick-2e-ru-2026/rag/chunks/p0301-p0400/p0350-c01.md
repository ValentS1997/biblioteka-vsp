Политику освобождения можно задать непосредственно в YAML-манифесте на
уровне объекта PersistentVolume.

Обновление политики освобождения
Политика освобождения является настраиваемым параметром, который можно
изменить и после создания объекта PersistentVolume.

Чтобы продемонстрировать различия между политиками, воспользуемся ранее
созданными объектами:

 $ kubectl get pod,pvc -n pv-ns
 NAME        READY   STATUS    RESTARTS   AGE
 pod/nginx   1/1     Running   0          30m

 NAME                                  STATUS   VOLUME           CAPACITY
 ACCESS MODES   STORAGECLASS   VOLUMEATTRIBUTESCLASS   AGE
 persistentvolumeclaim/my-hostpath-pvc Bound    my-hostpath-pv   1Gi        RWO
 slow           <unset>                 34m

Сначала удалим под, так как он использует объект PVC:

 $ kubectl delete pod nginx -n pv-ns
 pod "nginx" deleted
 $ kubectl delete pvc my-hostpath-pvc -n pv-ns
 persistentvolumeclaim "my-hostpath-pvc" deleted

Теперь проверим статус объекта PV:

 $ kubectl get pv
 NAME             CAPACITY   ACCESS MODES   RECLAIM POLICY   STATUS     CLAIM
 STORAGECLASS   VOLUMEATTRIBUTESCLASS   REASON   AGE
 my-hostpath-pv   1Gi        RWO            Retain           Released   pv-ns/
 my-hostpath-pvc   slow           <unset>                          129m

Из вывода следует, что PV находится в состоянии Released, но еще не переведен
в состояние Available для использования другим объектом PVC.
