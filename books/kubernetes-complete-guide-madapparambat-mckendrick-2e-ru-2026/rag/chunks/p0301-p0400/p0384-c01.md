Использование объекта
       Deployment для управления11       рабочими нагрузками
        без cохранения состояния

В предыдущей главе вы познакомились с двумя важными объектами Kubernetes:
ReplicationController и ReplicaSet. Теперь вы знаете, что они оба предназна-
чены для поддержания заданного количества идентичных и исправных ре-
плик (копий) подов. Фактически объект ReplicaSet является преемником
ReplicationController, и в последних версиях Kubernetes рекомендуется исполь-
зовать именно его вместо устаревшего контроллера репликации.

Пришло время познакомиться с объектом Deployment (развертывание), ко-
торый обеспечивает удобное масштабирование, постепенное обновление
и откат к определенной версии ваших Kubernetes-приложений и сервисов
без сохранения состояния. Объект Deployment строится поверх ReplicaSet
и предоставляет декларативный способ управления этими объектами: вы
описываете желаемое состояние в манифесте Deployment, а Kubernetes осуще
ствляет оркестрацию соответствующих объектов ReplicaSet контролируемым
и предсказуемым образом. Наряду со StatefulSet (который будет рассмотрен
в следующей главе) Deployment является одним из ключевых объектов для
управления рабочими нагрузками в Kubernetes. Он представляет собой осно-
вополагающее средство разработки и эксплуатации Kubernetes-приложений.
В этой главе вы получите все знания и инструменты, необходимые для раз-
вертывания компонентов приложений без сохранения состояния с помощью
объектов Deployment, а также для безопасного выпуска новых версий этих
компонентов.

Технические требования
Для работы с этой главой вам потребуется:
z развернутый кластер Kubernetes. Вы можете использовать как локальный,
   так и облачный кластер, однако для полноценного усвоения материала реко-
   мендуется отдать предпочтение многоузловому облачному кластеру;
z рабочий интерфейс командной строки kubectl, настроенный для взаимо-
   действия с кластером.
