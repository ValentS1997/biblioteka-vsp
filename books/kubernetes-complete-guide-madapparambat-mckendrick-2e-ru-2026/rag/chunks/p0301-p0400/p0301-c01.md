Сервис типа NodePort     301

доступ. По сути, он указывает сервису, куда именно следует перенаправлять тра-
фик. В отсутствии селектора сервис останется неактивным. В данном примере
селектор ищет поды с меткой app=whoami. Таким образом, сервис предоставляет
доступ к обоим подам — whoami1 и whoami2.
В разделе spec указывается тип сервиса (type). При создании сервисов других
типов (ClusterIP или LoadBalancer) значение этого ключа будет иным. В данном
случае мы задаем значение NodePort.
Последним и, пожалуй, самым непростым для понимания является блок ports,
в котором задаются три разных порта.

z nodePort — порт хост-машины (рабочего узла), через который сервис
   NodePort будет доступен извне. Значение 30001 говорит о том, что доступ
   к данному сервису и развернутым за ним подам можно получить по адресу
   <IP_адрес_рабочего_узла>:30001. Учтите, что этот параметр нельзя задать
   произвольно: в стандартной установке Kubernetes допустимым диапазоном
   портов является 30000–32767.
z port — это отдельный внутренний порт, который принадлежит сервису
   NodePort. В этом поле можно указать любое допустимое значение.
z  targetPort — это порт целевых подов, на котором фактически работает при-
   ложение. Именно на него сервис будет перенаправлять трафик.
