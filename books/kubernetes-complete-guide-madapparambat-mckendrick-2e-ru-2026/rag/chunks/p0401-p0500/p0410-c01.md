410     Глава 11   •  Использование объекта Deployment

декларативным способом. Ниже показано, как использовать команду kubectl
для выполнения отката.

1. Для начала императивно выкатим новую версию объекта Deployment.
  На этот раз обновим образ nginx до версии 1.19:

    $ kubectl set image deployment nginx-deployment-rollingupdate
    nginx=nginx:1.19
    deployment.apps/nginx-deployment-rollingupdate image updated

2. Здесь nginx=nginx:1.19 означает, что мы задаем образ nginx:1.19 для кон-
   тейнера nginx в объекте nginx-deployment-rollingupdate.
3. Дождитесь завершения развертывания, проверив его статус с помощью ко-
  манды kubectl rollout status:

    $ kubectl rollout status deployment.apps/nginx-deployment-rollingupdate
    deployment "nginx-deployment-rollingupdate" successfully rolled out

4. Допустим, новая версия 1.19 вызывает проблемы и команда решила отка-
   титься к предыдущей стабильной версии.
5. Чтобы просмотреть все доступные ревизии объекта Deployment, используйте
   команду kubectl rollout history:

    $ kubectl rollout history deployment.apps/nginx-deployment-rollingupdate
    deployment.apps/nginx-deployment-rollingupdate
    REVISION  CHANGE-CAUSE
    1         <none>
    2         <none>
    3         <none>

6. Как видите, у нас есть три ревизии. Первая соответствует созданию исход-
   ного объекта Deployment. Вторая ревизия — это декларативное обновление
   Deployment с использованием образа nginx:1.18. Наконец, третья ревизия
   отражает последнее императивное обновление, инициировавшее выкаты-
   вание версии nginx:1.19. Поле CHANGE-CAUSE является пустым, поскольку
  мы не использовали флаг --record. Этот флаг признан устаревшим и будет
   удален в будущих версиях Kubernetes. При необходимости указать причину
   изменения в поле CHANGE-CAUSE вам следует вручную обновить аннотацию
   объекта Deployment, как было показано ранее в этой главе.
7. Ревизии, созданные в результате декларативных изменений, обычно со-
   держат немного информации в поле CHANGE-CAUSE. Чтобы узнать больше
   о второй ревизии, выполните следующую команду:

    $ kubectl rollout history deploy nginx-deployment-rollingupdate --revision=2
