Управление объектом StatefulSet     435

         Обратите внимание на то, что при применении манифеста мы указали пара-
         метр -n mysql для создания ресурса в пространстве имен mysql.

Выполните следующие шаги, чтобы проверить содержимое подов объекта
StatefulSet.

1. Подключитесь к поду k8sutils для выполнения тестовых команд:

    $ kubectl exec -it -n mysql k8sutils -- /bin/bash
    root@k8sutils:/#

2. Подключитесь к приложению MySQL, работающему в StatefulSet, исполь-
   зуя созданный ранее headless-сервис и пароль, указанный в объекте Secret:

    root@k8sutils:/# mysql -u root -p -h mysql-headless.mysql.svc.cluster.local
    Enter password: <mysqlroot>
    Welcome to the MariaDB monitor.  Commands end with ; or \g.
    Your MySQL connection id is 8

    Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

    MySQL [(none)]>

Итак, мы установили подключение к MySQL и получили доступ к серверу
MySQL, работающему в виде приложения StatefulSet. Теперь посмотрим, как
именно ведет себя headless-сервис.

Использование headless-сервиса
и стабильных сетевых идентификаторов
Ранее вы уже узнали, что такое headless-сервис в Kubernetes и как его можно
использовать для получения доступа к приложениям, развернутым с помощью
объекта StatefulSet (см. подраздел «Headless-сервисы» в главе 8). Теперь углу-
бимся в детали и посмотрим, как headless-сервис работает в контексте StatefulSet.
