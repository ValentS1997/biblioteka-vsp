Знакомство с объектом StatefulSet     427

не ограничивается определением объекта StatefulSet. Рассмотрим, на что сле-
дует обратить внимание.

z Клонирование и синхронизация данных. В отличие от приложений без со-
   хранения состояния, приложения с сохранением состояния опираются на
   постоянно хранящиеся в них данные. Объект StatefulSet управляет порядком
   создания подов и гарантирует их идентичность, но не осуществляет репли-
  кацию данных между ними. Эту функциональность необходимо реализо-
   вать самостоятельно. Для этого обычно применяются следующие подходы:
   использование контейнеров инициализации для копирования данных из
   заранее определенного источника при создании пода, применение встроен-
  ных механизмов репликации в самих приложениях (например, репликация
  MySQL); использование внешних сценариев для управления процессом
   синхронизации данных.
z Доступность удаленного хранилища. Объект StatefulSet гарантирует воз-
   можность переназначения подов любым доступным узлам кластера. Чтобы
   данные сохранялись в ходе этого процесса, хранилище, предоставляемое
   объектом PersistentVolume, должно быть доступно со всех рабочих узлов.
  Это требует выбора класса хранилища, обеспечивающего репликацию дан-
  ных между узлами, либо использования сетевых систем хранения данных,
   доступных всем машинам в кластере.
z Внешнее резервное копирование. Объект StatefulSet предназначен для управ-
   ления жизненным циклом подов и обеспечения сохранности данных внутри
   кластера, но он не выполняет внешнее резервное копирование. Для защиты
  данных от последствий катастрофических сбоев необходимо реализовать
   отдельное внешнее решение для резервного копирования. В данном случае
   речь может идти о создании резервных копий постоянных томов в облачном
   хранилище или на выделенном сервере резервного копирования, располо-
  женном вне кластера Kubernetes.

Существуют лучшие практики и проверенные подходы к управлению данными
в объектах StatefulSet. В следующем подразделе мы обсудим техники управле-
ния репликацией.

Управление репликацией
Как следует из названия, приложения с сохранением состояния, работающие
с данными, часто требуют их инициализации или синхронизации. Для их реа-
лизации можно использовать следующее.

z Контейнеры инициализации — копируют данные из источника (например,
   из объекта ConfigMap) в постоянное хранилище перед запуском основного
   приложения.
