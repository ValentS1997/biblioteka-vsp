предыдущей версии. Например, если установить значение partition равным 1,
то в процессе выкатывания изменений будут обновлены только поды mysql-
stateful-1 и mysql-stateful-2, а под mysql-stateful-0 останется необновлен-
ным и продолжит работать на прежней версии. Управляя значением partition,
можно выполнять канареечные развертывания, начиная с одной реплики и по-
этапно распространяя обновление на остальные поды. По умолчанию значение
partition равно 0, что обеспечивает обновление всех реплик подов.
Теперь выкатим новую версию нашего приложения mysqlserver, используя
стратегию RollingUpdate.

Обновление объекта StatefulSet
В этом разделе мы рассмотрим способ выкатывания новой версии контейнер-
ного образа с использованием созданного ранее YAML-манифеста StatefulSet.

1. Сделайте копию предыдущего YAML-манифеста:

    $ cp mysql-statefulset.yaml mysql-statefulset-rolling-update.yaml

2. Убедитесь, что в спецификации указаны стратегия обновления RollingUpdate
  и параметр partition, равный 0. Обратите внимание: если вы создавали
   StatefulSet с другой стратегией обновления, то не сможете изменить ее без
   удаления объекта:
   # mysql-statefulset-rolling-update.yaml
   apiVersion: apps/v1
   kind: StatefulSet
   metadata:
     name: mysql-stateful
     labels:
       app: mysql
     namespace: mysql
   spec:
     serviceName: mysql-headless
     podManagementPolicy: OrderedReady
     updateStrategy:
       type: RollingUpdate
       rollingUpdate:
         partition: 0
     replicas: 3
   ... <фрагмент опущен для краткости> ...
  Полный YAML-манифест можно найти в репозитории GitHub.
  Эти значения используются по умолчанию, однако имеет смысл задать их
   явно, чтобы лучше разобраться в происходящем.
