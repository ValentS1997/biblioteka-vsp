468     Глава 13   •  Объект DaemonSet: запуск одного пода на каждом узле

2. Примените обновленный манифест к кластеру:

    $ kubectl apply -f fluentd-daemonset.yaml
    namespace/logging unchanged
    daemonset.apps/fluentd-elasticsearch configured

3. Сразу после этого выполните команду kubectl rollout status для отслежи-
   вания прогресса в реальном времени:

    $ kubectl rollout status ds -n logging
    Waiting for daemon set "fluentd-elasticsearch" rollout to finish: 2 out
    of 3 new pods have been updated...
    Waiting for daemon set "fluentd-elasticsearch" rollout to finish: 2 out
    of 3 new pods have been updated...
    Waiting for daemon set "fluentd-elasticsearch" rollout to finish: 2 of 3
    updated pods are available...
    daemon set "fluentd-elasticsearch" successfully rolled out

4. Вы также можете воспользоваться командой kubectl describe, чтобы про-
   смотреть события, связанные с объектом DaemonSet, и увидеть, в каком
   порядке пересоздавались поды.

    $ kubectl describe ds -n logging
    Name:           fluentd-elasticsearch
    Selector:       name=fluentd-elasticsearch
    ... <фрагмент опущен для краткости> ...
    Events:
      Type    Reason            Age    From                  Message
      ----    ------            ----   ----                  -------
    ... <фрагмент опущен для краткости> ...
      Normal  SuccessfulDelete  5m52s  daemonset-controller  Deleted pod:
    fluentd-elasticsearch-zk6pt
      Normal  SuccessfulCreate  5m51s  daemonset-controller  Created pod:
    fluentd-elasticsearch-fxffp

Как видите, поды заменялись один за другим.

         Контейнерный образ DaemonSet также можно изменить императивным спо-
         собом с помощью команды kubectl set image ds fluentd-elasticsearch fluentd-
           elasticsearch=quay.io/fluentd_ elasticsearch/fluentd:v4.7.5 -n logging. Однако этот
          способ не рекомендуется использовать в рабочих средах.

Кроме того, объект DaemonSet автоматически создает поды при добавлении
нового узла в кластер, если этот узел соответствует селектору и правилам пред-
почтения узлов. Когда узел удаляется из кластера, соответствующий под тоже
завершает работу. То же самое произойдет при изменении меток или ограниче-
ний на узле: если новые значения соответствуют условиям DaemonSet, на узле
будет создан новый под; если же они перестанут соответствовать заданным
условиям, существующий под будет удален.
