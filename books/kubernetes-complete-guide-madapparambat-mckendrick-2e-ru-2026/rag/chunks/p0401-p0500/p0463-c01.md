Создание объектов DaemonSet и управление ими      463

Создание объекта DaemonSet
Следуя лучшим практикам, мы будем использовать декларативный подход
для создания объекта DaemonSet в этом примере. Сначала рассмотрим YAML-
манифест fluentd-daemonset.yaml.
Первая часть манифеста создает отдельное пространство имен, предназначен-
ное для логирования:

---
apiVersion: v1
kind: Namespace
metadata:
  name: logging

Далее следует описание самого объекта DaemonSet:
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluentd-elasticsearch
  namespace: kube-system
  labels:
    k8s-app: fluentd-logging
spec:
  selector:
    matchLabels:
      name: fluentd-elasticsearch
# (продолжение далее)

Первая часть показанного выше файла содержит метаданные и селектор меток
подов, аналогичные тем, которые вы уже видели в манифестах Deployment
и StatefulSet. Во второй части файла приводится шаблон пода, который будет
использоваться объектом DaemonSet:

# (продолжение)
  template:
    metadata:
      labels:
        name: fluentd-elasticsearch
    spec:
      containers:
        - name: fluentd-elasticsearch
          image: quay.io/fluentd_elasticsearch/fluentd:v4.7
          resources:
            limits:
              memory: 200Mi
            requests:
              cpu: 100m
              memory: 200Mi
