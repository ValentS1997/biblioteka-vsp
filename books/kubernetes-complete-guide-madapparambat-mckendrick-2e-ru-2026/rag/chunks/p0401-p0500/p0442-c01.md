442     Глава 12   •  Объект StatefulSet: развертывание приложений

        При управлении объектами StatefulSet с помощью Horizontal Pod Autoscaler (HPA)
         или других инструментов горизонтального масштабирования лучше не задавать
          значение параметра .spec.replicas в манифесте. В этом случае управляющий слой
          Kubernetes будет автоматически регулировать количество реплик в зависимости
          от текущей потребности в ресурсах, обеспечивая эффективное масштабирование
         приложения без ручного вмешательства.

Итак, теперь вы знаете, как разворачивать и масштабировать объекты State
fulSet. Далее мы поговорим об их удалении.

Удаление объекта StatefulSet
Удалить объект StatefulSet можно двумя способами:
z удалить StatefulSet вместе с принадлежащими ему подами;
z удалить только StatefulSet, оставив поды нетронутыми.

В обоих случаях объекты PVC и PV, созданные для подов на основе volu
meClaimTemplates, по умолчанию не удаляются.
Однако в версии Kubernetes 1.27 появилось поле .spec.persistentVolu
meClaimRetentionPolicy, позволяющее управлять удалением PVC в рамках
жизненного цикла StatefulSet:

apiVersion: apps/v1
kind: StatefulSet
...
spec:
  persistentVolumeClaimRetentionPolicy:
    whenDeleted: Retain
    whenScaled: Delete
...

Подробнее об этом механизме можно узнать в официальной документации по
адресу https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/#persistent
volumeclaimretention.
Чтобы удалить объект StatefulSet вместе с подами, используйте стандартную
команду kubectl delete:

 $ kubectl delete sts -n mysql mysql-stateful
 statefulset.apps "mysql-stateful" deleted

В этом случае сначала будет завершена работа подов, а затем удален сам объект
StatefulSet. Обратите внимание, что эта операция отличается от масштабиро-
вания StatefulSet до нуля реплик и его последующего удаления. При удалении
