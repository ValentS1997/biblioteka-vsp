Знакомство с объектом DaemonSet     461

После создания кластера мы можем отобразить список узлов кластера, выпол-
нив команду:

 $ kubectl get nodes
 NAME          STATUS   ROLES           AGE     VERSION
 minikube      Ready    control-plane   3m28s   v1.31.0
 minikube-m02  Ready    <none>          2m29s   v1.31.0
 minikube-m03  Ready    <none>          91s     v1.31.0

Теперь проверим наличие объектов DaemonSet в только что созданном кластере:

 $ kubectl get daemonsets -A
 NAMESPACE     NAME          DESIRED   CURRENT   READY   UP-TO-DATE   AVAILABLE
 NODE SELECTOR            AGE
 kube-system   calico-node   3         3         3       3            3
 kubernetes.io/os=linux   63m
 kube-system   kube-proxy    3         3         3       3            3
 kubernetes.io/os=linux   63m

Параметры -A или --all-namespaces использованной выше команды позво-
ляют отобразить запрошенные объекты, принадлежащие всем пространствам
имен.
Если вы создавали кластер minikube тем же способом, то в выводе будут при-
сутствовать такие объекты, как calico-node и kube-proxy, развернутые в виде
DaemonSet. (Вы также можете установить Calico в других кластерах Kubernetes
и выполнить оставшиеся шаги этой инструкции.) Ранее мы уже включили
Calico в качестве CNI-плагина в наш кластер minikube. При организации се-
тевого взаимодействия с помощью Kubernetes Calico обычно развертывается
именно в виде объекта DaemonSet.

         Пока можете не обращать внимания на DaemonSet kube-proxy, поскольку
          в minikube он по умолчанию запускается в виде данного объекта. Это обеспечи-
          вает постоянную доступность kube-proxy (компонента, управляющего сетевым
         трафиком в кластере) на каждом узле в среде minikube.
