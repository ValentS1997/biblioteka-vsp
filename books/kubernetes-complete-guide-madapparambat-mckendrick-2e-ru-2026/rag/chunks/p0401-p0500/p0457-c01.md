Объект DaemonSet:
        запуск одного пода13        на каждом узле

В предыдущих главах мы рассмотрели самые распространенные контроллеры
Kubernetes, предназначенные для управления подами, — ReplicaSet, Deployment
и StatefulSet. Как правило, при запуске компонентов облачных приложений,
содержащих бизнес-логику, для управления подами используются объекты
Deployment или StatefulSet. Для выполнения пакетных рабочих нагрузок при-
меняются объекты Job и CronJob.

Однако бывают ситуации, требующие запуска вспомогательных компонентов,
например, для выполнения служебных задач, сбора логов или агрегирования
метрик. В таких случаях используется объект DaemonSet (набор демонов),
обеспечивающий запуск одной реплики пода на каждом узле кластера (если
не указано иное). При добавлении нового узла в кластер ему автоматически на-
значается под, а при удалении узла работа соответствующего пода завершается.
Все эти действия выполняются контроллером DaemonSet.

Технические требования
Для работы с этой главой вам потребуется:
z развернутый кластер Kubernetes. Вы можете использовать как локальный,
   так и облачный кластер, однако для полноценного усвоения материала ре-
   комендуется отдать предпочтение многоузловому кластеру;
z интерфейс командной строки kubectl, настроенный для взаимодействия
   с кластером.

Инструкции по созданию кластера Kubernetes и настройке клиента kubectl
приведены в главах 2 и 3.

Примеры кода для этой главы можно загрузить из официального репозитория
GitHub по адресу https://github.com/PacktPublishing/The-Kubernetes-Bible-Second-Edition/
tree/main/Chapter13.
