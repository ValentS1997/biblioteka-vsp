 5. Параметр minReadySeconds (значение которого равно 10) задает дополнитель-
   ный промежуток времени, в течение которого под должен оставаться в состоя
   нии готовности, чтобы можно было объявить о его успешном обновлении.
 6. Примените этот YAML-манифест к кластеру:

     $ kubectl apply -f nginx-deployment-rollingupdate.yaml
     deployment.apps/nginx-deployment-rollingupdate created

     $ kubectl get pod
     NAME                                             READY STATUS   RESTARTS AGE
     nginx-deployment-rollingupdate-69d855cf4b-nshn2  1/1   Running  0        24s
     nginx-deployment-rollingupdate-69d855cf4b-pqvjh  1/1   Running  0        24s
     nginx-deployment-rollingupdate-69d855cf4b-tdxzl  1/1   Running  0        24s

   После создания объекта Deployment можно приступать к выкатыванию
    новой версии приложения. Для этого мы изменим образ в шаблоне пода на
    более свежую версию и посмотрим, что произойдет в процессе выкатывания
    обновлений. Выполните следующие шаги:
 7. Измените контейнерный образ в манифесте объекта Deployment на nginx:1.18:
    ...
      template:
        metadata:
          labels:
            app: nginx
            environment: test
        spec:
          containers:
            - name: nginx
              image: nginx:1.18
    ...
 8. Примените изменения к кластеру:

     $ kubectl apply -f nginx-deployment-rollingupdate.yaml
     deployment.apps/nginx-deployment-rollingupdate configured

 9. Сразу после этого используйте команду kubectl rollout status, чтобы от-
    слеживать прогресс в реальном времени:

     $ kubectl rollout status deployment.apps/nginx-deployment-rollingupdate
     deployment "nginx-deployment-rollingupdate" successfully rolled out

10. Выкатывание обновлений займет некоторое время, так как для объекта
    Deployment был задан параметр minReadySeconds, а для проверки готовности
    контейнера — initialDelaySeconds.
