Знакомство с объектом Deployment     401

   необходимо как минимум две неудачные попытки подряд, выполняемые
   с интервалом 2 секунды. Позже вы заметите, что трафик распределяется
  между двумя оставшимися подами, находящимися в состоянии готов-
   ности.
6. Если вы выполните команду kubectl describe svc nginx-service-example,
   то увидите, что вам доступны только две конечные точки:

    $ kubectl describe svc nginx-service-example | grep Endpoint
    Endpoints:               10.244.1.6:80,10.244.2.6:80

7. В списке событий, связанных с подом, также будет указано, что он не на-
   ходится в состоянии готовности:

    $ kubectl describe pod nginx-deployment-readiness-69dd4cfdd9-4pkwr
    Name:     nginx-deployment-readiness-69dd4cfdd9-4pkwr
    ...<фрагмент опущен для краткости>...
    Normal   Started    21m                  kubelet   Started container nginx
    Warning  Unhealthy  72s (x25 over 118s)  kubelet   Readiness probe failed
    with status code: 404

  Можно пойти еще дальше и удалить файл ready в двух других подах, чтобы
   сервис полностью перестал работать:

    $ kubectl exec -it nginx-deployment-readiness-69dd4cfdd9-7n2kz -- rm /usr/
    share/nginx/html/ready
    $ kubectl exec -it nginx-deployment-readiness-69dd4cfdd9-t7rp2 -- rm /usr/
    share/nginx/html/ready

  Поды находятся в состоянии Running, однако ни один из них не может при-
   нимать трафик из-за непрохождения проверки готовности.

    $ kubectl get po -w
    NAME                                         READY   STATUS    RESTARTS  AGE
    k8sutils                                     1/1     Running   0         166m
    nginx-deployment-readiness-69dd4cfdd9-4pkwr  0/1     Running   0         25m
    nginx-deployment-readiness-69dd4cfdd9-7n2kz  0/1     Running   0         25m
    nginx-deployment-readiness-69dd4cfdd9-t7rp2  0/1     Running   0         25m

   Теперь при проверке сервиса с помощью пода k8sutils вы увидите, что за-
   просы остаются в состоянии ожидания и в конечном счете завершаются по
   тайм-ауту. Таким образом, мы смоделировали провал проверки готовности
   всех реплик пода в объекте Deployment.

    $ kubectl exec -it k8sutils -- curl nginx-service-example.default.svc.
    cluster.local
    curl: (7) Failed to connect to nginx-service-example.default.svc.cluster.
    local port 80 after 5 ms: Couldn't connect to server
    command terminated with exit code 7
