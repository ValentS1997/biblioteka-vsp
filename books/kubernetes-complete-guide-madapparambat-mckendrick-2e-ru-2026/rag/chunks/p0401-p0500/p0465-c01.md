Создание объектов DaemonSet и управление ими      465

            env:
              - name: FLUENT_ELASTICSEARCH_HOST
                value: "elasticsearch-logging"
              - name: FLUENT_ELASTICSEARCH_PORT
                value: "9200"

Теперь, имея все необходимые YAML-манифесты, мы можем применить их
к кластеру. Для этого выполните следующие шаги.

1. Создайте объект DaemonSet fluentd-elasticsearch:

    $ kubectl apply -f fluentd-daemonset.yaml
    namespace/logging created
    daemonset.apps/fluentd-elasticsearch created

2. Для наблюдения за процессом создания DaemonSet используйте команду
   kubectl describe:

    $ kubectl describe daemonset fluentd-elasticsearch -n logging

  При работе с kubectl вместо daemonset можно использовать сокращение ds.
3. Выполнив команду kubectl get pods с параметром -w, вы увидите, как для
   каждого узла в кластере будет запланирован отдельный под:

    $ kubectl get po -n logging -o wide
    NAME                       READY   STATUS    RESTARTS   AGE     IP
    NODE          NOMINATED NODE   READINESS GATES
    fluentd-elasticsearch-cs4hm 1/1     Running   0          3m48s
    10.244.120.68  minikube      <none>           <none>
    fluentd-elasticsearch-stfqs 1/1     Running   0          3m48s
    10.244.205.194 minikube-m02  <none>           <none>
    fluentd-elasticsearch-zk6pt 1/1     Running   0          3m48s
    10.244.151.2   minikube-m03  <none>           <none>

В нашем случае кластер состоит из трех узлов, поэтому было создано три пода.

Итак, мы успешно развернули объект DaemonSet и теперь можем убедиться
в том, что он работает ожидаемым образом. Чтобы проверить наличие у подов
Fluentd доступа к логам узлов Kubernetes, подключитесь к одному из них и про-
смотрите содержимое каталога /var/log:

 $ kubectl exec -n logging -it fluentd-elasticsearch-cs4hm -- /bin/bash
