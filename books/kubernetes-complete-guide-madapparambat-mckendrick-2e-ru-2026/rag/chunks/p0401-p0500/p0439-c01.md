Управление объектом StatefulSet     439

Система Kubernetes автоматически пересоздаст все поды в том же порядке:

 $ kubectl get pod -n mysql
 NAME               READY   STATUS    RESTARTS   AGE
 k8sutils           1/1     Running   0          47m
 mysql-stateful-0   1/1     Running   0          44s
 mysql-stateful-1   1/1     Running   0          43s
 mysql-stateful-2   1/1     Running   0          41s

Чтобы убедиться в корректном восстановлении связи между подами и заявками
PVC, можно отобразить список смонтированных постоянных томов (PV):

 $ kubectl describe pod -n mysql -l app=mysql | egrep 'ClaimName|Name:'
 Name:           mysql-stateful-0
 ClaimName:      mysql-data-mysql-stateful-0
 ConfigMapName:  kube-root-ca.crt
 Name:           mysql-stateful-1
 ClaimName:      mysql-data-mysql-stateful-1
 ConfigMapName:  kube-root-ca.crt
 Name:           mysql-stateful-2
 ClaimName:      mysql-data-mysql-stateful-2
 ConfigMapName:  kube-root-ca.crt

Контроллер StatefulSet не удаляет PV при удалении подов или самого объекта
StatefulSet. Очистка данных и удаление PV при полном удалении StatefulSet
выполняются вручную.

Теперь рассмотрим способ масштабирования объекта StatefulSet.

Масштабирование объекта StatefulSet
Объекты StatefulSet можно масштабировать так же, как и объекты Deploy
ment, — путем изменения числа реплик (replicas) в спецификации или с по-
мощью императивной команды kubectl scale. При увеличении числа реплик
новые поды автоматически добавляются в список конечных точек сервиса, а при
уменьшении — удаляются из него.

Однако между объектами StatefulSet и Deployment существуют некоторые
различия.

z При создании объекта StatefulSet с количеством реплик N поды создаются
   последовательно, в порядке от 0 до N – 1. В нашем примере при создании
   StatefulSet с тремя репликами сначала создается под mysql-stateful-0, затем
   mysql-stateful-1 и mysql-stateful-2.
z При увеличении числа реплик в StatefulSet поды также создаются последо-
   вательно и по порядку.
