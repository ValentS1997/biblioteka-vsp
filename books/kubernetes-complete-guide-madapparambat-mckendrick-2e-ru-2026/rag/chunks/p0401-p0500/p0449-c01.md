Выпуск новой версии приложения, развернутого в виде StatefulSet     449

  Как видите, выкатывание новой версии MySQL оказалось успешным, а дан-
  ные сохранились, несмотря на пересоздание подов, что подтверждается на-
   личием базы данных stsrolling, созданной до начала обновления.

        Вы можете изменить контейнерный образ StatefulSet императивно, используя
         команду kubectl -n mysql set image sts mysql-stateful mysql=mysql:8.3.0. Этот
         метод не рекомендуется использовать в рабочей среде. Он подходит только для
         целей тестирования. В целом объектами StatefulSet гораздо проще управлять
         декларативным, нежели императивным способом.

Теперь рассмотрим способ использования поля partition для поэтапного
выкатывания обновлений. Допустим, вы хотите обновить образ MySQL до
версии 8.4.0, но перед этим проверить работоспособность этой версии в вашей
среде, выполнив канареечное развертывание, то есть обновив только одну или
несколько реплик пода. Для этого выполните следующие шаги.

1. В манифесте mysql-statefulset-rolling-update.yaml установите значение
   partition, равное текущему числу реплик, — в нашем случае это 3:

   ... <фрагмент опущен для краткости> ...
   spec:
     serviceName: mysql-headless
     podManagementPolicy: OrderedReady
     updateStrategy:
       type: RollingUpdate
       rollingUpdate:
         partition: 3
   ... <фрагмент опущен для краткости> ...

   Обновите образ до версии 8.4.0:

   ...
       spec:
         containers:
           - name: mysql
             image: mysql:8.4.0
   ... <фрагмент опущен для краткости> ...
   Когда значение partition совпадает с числом реплик, применение мани-
   феста к кластеру не вызывает никаких изменений в подах. Это состояние
   называется подготовкой к выкатыванию.
2. Примените манифест к кластеру:

    $ kubectl apply -f mysql-statefulset-rolling-update.yaml
    statefulset.apps/mysql-stateful configured
