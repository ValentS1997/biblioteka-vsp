440     Глава 12   •  Объект StatefulSet: развертывание приложений

z При уменьшении числа реплик поды завершают работу в обратном поряд-
   ке — от N – 1 к 0. В нашем случае при масштабировании StatefulSet до нуля
   реплик сначала будет удален под mysql-stateful-2, затем mysql-stateful-1
  и наконец mysql-stateful-0.
z При увеличении числа реплик в StatefulSet очередной под создается только
   при условии, что все предыдущие поды находятся в состоянии Running и Ready.
z При уменьшении числа реплик в StatefulSet поды удаляются в порядке,
   обратном порядку создания, и только после полного завершения работы
  и удаления всех предыдущих подов.
z В целом перед выполнением любой операции масштабирования над подом
   объекта StatefulSet все предыдущие поды должны находиться в состоянии
   Running и Ready. Таким образом, если при уменьшении числа реплик с че-
   тырех до одной под mysql-stateful-0 внезапно выйдет из строя, операции
   масштабирования над подами mysql-stateful-1, mysql-stateful-2 и mysql-
   stateful-3 не будут выполнены. Процесс масштабирования возобновится
   только после перехода пода mysql-stateful-0 в состояние готовности.

         Такое последовательное поведение при масштабировании можно изменить, за-
         дав другое значение в поле spec.podManagementPolicy спецификации StatefulSet.
        По умолчанию используется значение OrderedReady. Если заменить его на
             Parallel, операции масштабирования будут выполняться параллельно, как в слу-
         чае с объектом Deployment. Однако важно помнить, что этот параметр влияет
          только на операции масштабирования. Способ обновления StatefulSet при ис-
         пользовании стратегии RollingUpdate остается прежним.

Теперь отмасштабируем объект StatefulSet императивным способом.

1. Увеличьте число реплик:

    $ kubectl scale statefulset -n mysql mysql-stateful --replicas=4
    statefulset.apps/mysql-stateful scaled

2. Если вы выведете список подов с помощью команды kubectl get pods, то
   заметите, как создаются новые поды:

    $ kubectl get pod -n mysql
    NAME               READY   STATUS    RESTARTS   AGE
    k8sutils           1/1     Running   0          56m
    mysql-stateful-0   1/1     Running   0          9m13s
    mysql-stateful-1   1/1     Running   0          9m12s
    mysql-stateful-2   1/1     Running   0          9m10s
    mysql-stateful-3   1/1     Running   0          4s
