408     Глава 11   •  Использование объекта Deployment

11. Используя команду kubectl describe, можно просмотреть список событий,
    показывающий, как масштабировались объекты ReplicaSet:

     $ kubectl describe deploy nginx-deployment-rollingupdate
     Name: nginx-deployment-rollingupdate
     <фрагмент опущен для краткости>
     Events:
       Type    Reason             Age    From                    Message
       ----    ------             ----   ----                    -------
       Normal  ScalingReplicaSet  8m21s  deployment-controller   Scaled up
     replica set nginx-deployment-rollingupdate-69d855cf4b to 3
       Normal  ScalingReplicaSet  2m51s  deployment-controller   Scaled up
     replica set nginx-deployment-rollingupdate-5479f5d87f to 1
       Normal  ScalingReplicaSet  2m51s  deployment-controller   Scaled down
     replica set nginx-deployment-rollingupdate-69d855cf4b to 2 from 3
       Normal  ScalingReplicaSet  2m51s  deployment-controller   Scaled up
     replica set nginx-deployment-rollingupdate-5479f5d87f to 2 from 1
       Normal  ScalingReplicaSet  2m24s  deployment-controller   Scaled down
     replica set nginx-deployment-rollingupdate-69d855cf4b to 1 from 2
       Normal  ScalingReplicaSet  2m24s  deployment-controller   Scaled up
     replica set nginx-deployment-rollingupdate-5479f5d87f to 3 from 2
       Normal  ScalingReplicaSet  2m14s  deployment-controller   Scaled down
     replica set nginx-deployment-rollingupdate-69d855cf4b to 0 from 1

12. Теперь выведем список объектов ReplicaSet в кластере:

     $ kubectl get rs
     NAME                                       DESIRED  CURRENT  READY  AGE
     nginx-deployment-rollingupdate-5479f5d87f  3        3        3      4m22s
     nginx-deployment-rollingupdate-69d855cf4b  0        0        0      9m52s

   Вы заметите, что старый объект ReplicaSet все еще присутствует, но число
    его подов было уменьшено до нуля. Это связано с тем, что объект Deployment
    сохраняет историю ревизий. Каждая ревизия соответствует своему набору
    реплик, который может использоваться для отката обновлений. Количество
   сохраняемых ревизий задается параметром .spec.revisionHistoryLimit
    (по умолчанию его значение равно 10). История ревизий особенно важна,
    если вы вносите изменения императивным способом. Если же вы исполь-
    зуете декларативный подход и фиксируете изменения в системе контроля
    версий, сохранение этой истории может быть менее критическим.
13. Наконец, убедимся, что поды действительно обновились до новой версии
    образа. Для этого используйте следующую команду и проверьте один из по-
    дов в выводе:

     $ kubectl get po
     NAME                                            READY STATUS  RESTARTS AGE
     nginx-deployment-rollingupdate-5479f5d87f-2k7d6 1/1   Running 0        5m41s
     nginx-deployment-rollingupdate-5479f5d87f-6gn9m 1/1   Running 0        5m14s
