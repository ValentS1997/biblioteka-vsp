462     Глава 13   •  Объект DaemonSet: запуск одного пода на каждом узле

Полученный вывод говорит о следующем.
z Поды Calico развернуты на всех узлах minikube. Каждый под работает на
   отдельном узле, который соответствует виртуальной машине minikube
   (minikube, minikube-m02 и minikube-m03). Это указывает на то, что Calico ис-
   пользует DaemonSet для запуска пода на каждом узле.
z Под calico-kube-controllers-ddf655445-jx26x является контроллером
   CNI-плагина Calico.

Поскольку DaemonSet Calico в данном случае устанавливается автоматически
вместе с minikube, мы не будем подробно рассматривать его конфигурацию.
Вместо этого в следующем разделе мы создадим объект DaemonSet с нуля и по
дробно изучим принцип его работы.

Создание объектов DaemonSet
и управление ими
Для демонстрации принципа работы объектов DaemonSet мы воспользуемся
подами Fluentd. Fluentd — это популярный проект с открытым исходным кодом,
предназначенный для агрегации логов из разных источников. Он эффективно
собирает, фильтрует и преобразует сообщения журналов перед их передачей
в другие системы для последующего анализа и хранения.

Для получения доступа к конечным точкам DaemonSet создадим headless-
сервис, как делали это в главе 12. В реальных сценариях применения объекты
DaemonSet, как правило, имеют более сложную конфигурацию и требуют мон-
тирования различных системных ресурсов в поды. В нашем примере мы сохра-
ним конфигурацию максимально простой, чтобы сосредоточиться на ключевых
принципах работы DaemonSet.

        Для читателей, желающих поработать над другим примером, мы подготовили
         рабочую версию экспортера Prometheus node-exporter, развернутого в виде
         DaemonSet и доступного через headless-сервис (см. файл node-exporter.yaml).
        Для этого при выполнении описанных далее шагов используйте имя сервиса
          node-exporter, порт 9100, а для запросов, отправляемых с помощью wget,
         добавьте путь /metrics. Данный объект DaemonSet публикует метрики узлов
          в формате Prometheus data model (модель данных Prometheus) на порте 9100
         по пути /metrics.

Далее мы рассмотрим все YAML-манифесты, необходимые для создания объ-
екта DaemonSet, и применим их к кластеру.
