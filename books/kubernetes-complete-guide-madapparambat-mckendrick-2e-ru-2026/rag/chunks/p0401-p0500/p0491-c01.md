    $ kubectl apply -f dashboard-sa.yaml

3. Подготовьте YAML-файл с описанием объекта ClusterRoleBinding, который
   позволит пользователю получить доступ к веб-интерфейсу:
   # dashboard-rbac.yml
   apiVersion: rbac.authorization.k8s.io/v1
   kind: ClusterRoleBinding
   metadata:
     name: admin-user
   roleRef:
     apiGroup: rbac.authorization.k8s.io
     kind: ClusterRole
     name: cluster-admin
   subjects:
     - kind: ServiceAccount
       name: admin-user
       namespace: kubernetes-dashboard
4. Создайте объект ClusterRoleBinding, применив YAML-манифест:

    $ kubectl apply -f dashboard-rbac.yml
    clusterrolebinding.rbac.authorization.k8s.io/admin-user created

5. Создайте токен:

    $ kubectl -n kubernetes-dashboard create token admin-user

Скопируйте сгенерированный токен, он понадобится вам в следующем подраз-
деле для авторизации в веб-интерфейсе.

Получение доступа к веб-интерфейсу Dashboard
Получить доступ к веб-интерфейсу Kubernetes Dashboard можно несколькими
способами. В этом разделе мы рассмотрим стандартный способ, предполагаю-
щий, что вы не изменяли конфигурацию чарта при установке. Если вы вносили
правки, отдельные шаги могут отличаться.

Запустите показанную ниже команду (скопированную из вывода helm install),
чтобы получить доступ к Dashboard. Эта команда активизирует режим проброса
портов (port-forward) — не завершайте ее выполнение:
