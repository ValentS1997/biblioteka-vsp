450     Глава 12   •  Объект StatefulSet: развертывание приложений

   случае обновится только под mysql-stateful-2, а все остальные останутся
   без изменений:

   ...
   spec:
     serviceName: mysql-headless
     podManagementPolicy: OrderedReady
     updateStrategy:
       type: RollingUpdate
       rollingUpdate:
         partition: 2
     replicas: 3
   ...

4. Снова примените манифест к кластеру:

    $ kubectl apply -f mysql-statefulset-rolling-update.yaml
    statefulset.apps/mysql-stateful configured

5. Используйте команду kubectl rollout status для отслеживания процесса.
  Как и ожидалось, будет пересоздан только один под:

    $ kubectl rollout status statefulset -n mysql
    Waiting for partitioned roll out to finish: 0 out of 1 new pods have been
    updated...
    Waiting for 1 pods to be ready...
    Waiting for 1 pods to be ready...
    Waiting for 1 pods to be ready...
    partitioned roll out complete: 1 new pods have been updated...

6. Если вы отобразите подробные сведения о подах mysql-stateful-0 и mysql-
   stateful-2, то увидите, что первый под использует старую версию образа,
   а второй — новую:

    $ kubectl describe pod -n mysql mysql-stateful-0 | grep Image
        Image:          mysql:8.3.0
        Image ID:       docker-pullable://mysql@sha256:9de9d54fecee6253130e6515
                        4b930978b1fcc336bcc86dfd06e89b72a2588ebe

    $ kubectl describe pod -n mysql mysql-stateful-2 | grep Image
        Image:          mysql:8.4.0
        Image ID:       docker-pullable://mysql@sha256:4a4e5e2a19aab7a678705889
                        52e8f401e17a330466ecfc55c9acf51196da5bd0
