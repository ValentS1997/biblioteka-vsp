58     Глава 1   •  Основы Kubernetes

Теперь проблема связана с необходимостью управлять установками Docker
на каждой из этих виртуальных машин в облаке. Представьте, что у вас
есть 10 (100 или 1000) машин, запущенных в облаке, и вам нужно выполнить
простую задачу — развернуть контейнеризованное Docker-приложение на
каждой из них.

Это можно сделать, выполнив команду docker run на каждой машине. Однако
существует и более эффективный способ — использовать оркестратор контейне-
ров, например Kubernetes. В двух словах Kubernetes можно описать как REST API,
который ведет учет всех машин с запущенным демоном Docker.

Однако это определение является слишком упрощенным. На самом деле
Kubernetes представляет собой не один централизованный REST API, а набор
микросервисов.

Стоит также отметить, что, хотя система Kubernetes отлично управляет контей-
неризованными рабочими нагрузками, она не может полностью заменить вир-
туальные машины (ВМ). ВМ по-прежнему полезны для решения определенных
задач, например для запуска устаревших приложений или ПО со сложными
зависимостями, которые трудно контейнеризовать. Тем не менее Kubernetes
продолжает развиваться в сторону устранения разрыва между контейнерами
и виртуальными машинами.

KubeVirt — мост между контейнерами
и виртуальными машинами
KubeVirt — это проект, расширяющий возможности Kubernetes за счет управле-
ния виртуальными машинами через привычный API Kubernetes. Такой подход
позволяет пользователям задействовать всю мощь и гибкость Kubernetes для
развертывания ВМ наряду с контейнеризованными приложениями. KubeVirt
следует принципам IaC (Infrastructure as Code — инфраструктура как код), что
дает пользователям возможность определять и управлять ВМ декларативно,
прямо в манифестах Kubernetes. Это упрощает администрирование ВМ и орга-
нично интегрирует их в существующие рабочие процессы Kubernetes.

Включая виртуальные машины в зону ответственности Kubernetes, KubeVirt
обеспечивает эффективный способ организации гибридной среды, в которой
могут сосуществовать контейнеры и ВМ. Этот проект демонстрирует продолжа-
ющуюся эволюцию Kubernetes как платформы для управления разнородными
рабочими нагрузками, открывая путь к разработке более унифицированного
подхода к развертыванию и сопровождению приложений.

Итак, мы обсудили работу с контейнерами и сложности их оркестрации в мас-
штабах крупной инфраструктуры. В следующем разделе вы познакомитесь
с историей развития системы Kubernetes.
