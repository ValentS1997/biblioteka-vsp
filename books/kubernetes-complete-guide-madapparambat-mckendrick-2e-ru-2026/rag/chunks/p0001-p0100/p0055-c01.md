Контейнеры     55

COPY . .
RUN yarn install --production
CMD ["node", "src/index.js"]
EXPOSE 3000

Разберем его построчно.
1. Строка #syntax=docker/dockerfile:1 определяет версию синтаксиса Docker
    file, используемую для сборки образа. В данном случае указана версия 1
   стандартного синтаксиса Dockerfile.
2. Строка FROM node:18-alpine определяет базовый образ контейнера. Здесь
   используется официальный образ Node.js 18 на базе Alpine Linux, который
   служит легковесной и достаточной основой для приложения.
3. Строка WORKDIR /app задает рабочий каталог внутри контейнера. В данном
   случае это /app. Все последующие команды Dockerfile будут выполняться
   относительно этого каталога.
4. Строка COPY . . копирует все файлы и каталоги из текущего контекста (ка-
   талога, в котором находится Dockerfile) в рабочий каталог (/app), указанный
   на предыдущем шаге. Таким образом, в контейнер помещается весь код
   приложения1.
5. Строка RUN yarn install --production приказывает контейнерному движ-
   ку выполнить команду внутри контейнера. В данном случае выполняется
   команда yarn install --production, которая устанавливает все рабочие
   зависимости, перечисленные в файле package.json, с помощью пакетного
   менеджера yarn. Флаг --production гарантирует установку только тех за-
   висимостей, которые необходимы в рабочей среде, при этом зависимости,
   используемые при разработке, игнорируются.
6. Строка CMD ["node", "src/index.js"] задает команду по умолчанию, вы-
  полняемую при запуске контейнера. Здесь указаны два элемента: node
  и src/index.js. Это означает, что при запуске контейнера будет запущен
   интерпретатор Node.js (node), который выполнит основной сценарий при-
   ложения (src/index.js).
7. Строка EXPOSE 3000 открывает порт внутри контейнера. В данном случае бу-
   дет открыт порт 3000. По умолчанию эта инструкция не сопоставляет порт
   контейнера с портом хостовой машины, однако вы можете сделать это позже
  при запуске контейнера с флагом -p (например, docker run -p 3000:3000
   my-image). Открытие порта 3000 предполагает, что ваше приложение ожидает
   входящие подключения именно на этом порте.

1  Главное не забывать держать рядом подходящую конфигурацию .dockerignore, ко-
   торая исключит из копирования такие очевидно ненужные в образе файлы, как сам
    Dockerfile и, к примеру, node_modules для данного примера, так как образ не должен
   содержать лишнего.
