Компоненты вычислительных узлов     93

Kubernetes и Docker. Выпуски Kubernetes до версии 1.24 предусматривали
прямую интеграцию с Docker Engine, реализуемую с помощью компонента
dockershim. Однако эта интеграция была признана устаревшей, и в релизе вер-
сии 1.20 было объявлено о ее удалении. В настоящее время осуществляется по-
степенный отказ от использования Docker в качестве базовой среды выполнения
контейнеров, и теперь пользователям Kubernetes рекомендуется выбирать среды
выполнения, совместимые со стандартом CRI, разработанным специально для
этой платформы.

Несмотря на эти изменения, образы, созданные с помощью Docker, по-прежнему
будут работать в вашем кластере с любой средой выполнения контейнеров.
Подробнее об этом можно узнать здесь: https://kubernetes.io/blog/2020/12/02/
dont-panic-kubernetes-and-docker/.
Таким образом, любая машина под управлением Linux, на которой работает
среда containerd, может использоваться в качестве базы для построения вы-
числительного узла Kubernetes. (О вычислительных узлах на машинах под
управлением Windows мы поговорим в следующих главах.)
Проект Open Container Initiative. Open Container Initiative (OCI) — это проект
с открытым исходным кодом, определяющий стандарты для контейнеров, их
образов, сред выполнения и контейнерных реестров. Его цель — обеспечить
совместимость и взаимную интеграцию контейнерных систем и гарантировать
единообразное выполнение контейнеров в различных средах. Система CRI
взаимодействует с OCI, предоставляя стандартизированный интерфейс для об-
мена данными между компонентом kubelet и средой выполнения контейнеров.
OCI определяет стандарты для образов и сред выполнения контейнеров, под-
держиваемых интерфейсом CRI, что способствует эффективному управлению
контейнерами и их развертыванию в системе Kubernetes.
Класс среды выполнения контейнеров. Ресурс RuntimeClass (класс среды вы-
полнения) системы Kubernetes позволяет определять и назначать подам раз-
личные конфигурации среды выполнения контейнеров. Это дает возможность
обеспечивать нужный баланс между производительностью и безопасностью
приложений. Например, рабочие нагрузки, предъявляющие повышенные тре-
бования к безопасности, можно запускать в среде выполнения с аппаратной
виртуализацией для обеспечения более строгой изоляции, даже если это при-
ведет к некоторому снижению производительности. RuntimeClass также по-
зволяет использовать одну и ту же среду выполнения с разными настройками
для отдельных подов. Для этого необходимо настроить интерфейс CRI на узлах
(способ установки зависит от среды) и создать в Kubernetes соответствующие
ресурсы типа RuntimeClass.
В следующем подразделе вы познакомитесь с агентом kubelet — еще одним
важным компонентом узла кластера Kubernetes.
