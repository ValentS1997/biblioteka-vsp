Прямого взаимодействия со средой выполнения контейнеров рекомендуется из-
бегать (за исключением тех случаев, когда речь идет об устранении неполадок).
Компонент kube-apiserver реализован в соответствии со стандартом REST.
Данный архитектурный стиль позволяет эффективно предоставлять функцио
нальные возможности через конечные точки HTTP, доступ к которым осу-
ществляется с использованием таких методов, как GET, POST, PUT, PATCH и DELETE.
Комбинируя HTTP-методы и пути, можно выполнять различные операции
(определяемые методом) над ресурсами (доступными по указанному пути).

Стандарт REST обеспечивает значительную гибкость, позволяющую расширять
любой REST API за счет добавления новых ресурсов через создание новых
путей. Обычно для управления состоянием объектов или ресурсов REST API
использует хранилище данных.

Хранение данных в таком API может быть реализовано несколькими способами,
включая следующие.

Хранение данных REST API в памяти:

z данные хранятся в собственной памяти API;
z однако это делает API сохраняющим состояние (stateful), что исключает
   возможность масштабирования.

        Для хранения состояния в системе Kubernetes используется компонент etcd —
         открытое распределенное хранилище данных в формате «ключ — значение»,
         предназначенное для хранения критически важной информации, необходимой
         для работы распределенных систем.

Использование движка базы данных:
z могут применяться полнофункциональные СУБД, такие как MariaDB или
   PostgreSQL;
z делегирование функции хранения данных внешнему движку делает API
   не сохраняющим состояние (stateless) и пригодным для горизонтального
   масштабирования.

Любой REST API можно легко обновить или расширить, добавив функции, вы-
