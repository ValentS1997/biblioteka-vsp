Компоненты Kubernetes     73

Контейнеры Linux и Windows
Система Kubernetes позволяет использовать узлы на базе Windows для запуска
контейнеров, предназначенных для этой операционной системы. Кластер мо-
жет содержать как Linux-, так и Windows-машины, однако запуск контейнера
Windows на вычислительном узле под управлением Linux (и наоборот) невоз-
можен. Правильное соотношение Linux- и Windows-машин в кластере позволяет
достичь оптимальной производительности.
В следующих разделах этой главы мы рассмотрим различные компоненты
Kubernetes и их назначение.

Компоненты Kubernetes
Kubernetes функционирует как распределенное приложение. Это не единый
монолитный программный продукт, выпускаемый в виде одной сборки для
установки на выделенную машину, а совокупность небольших проектов, на-
писанных на языке Go, которые образуют целостную систему.
Чтобы развернуть полностью работоспособный кластер Kubernetes, необходимо
установить и настроить каждый из этих компонентов по отдельности, обеспечив
их беспрепятственное взаимодействие. После выполнения этих шагов можно
приступать к запуску контейнеров с помощью оркестратора Kubernetes.
Для целей разработки и локального тестирования ПО все компоненты Kuber
netes можно установить на одну машину. Однако в рабочей среде для обеспече-
ния высокой доступности, балансировки нагрузки, организации распределен-
ных вычислений и масштабирования компоненты следует распределять между
разными хостами. Такой подход дает два преимущества.

z Кластер становится высокодоступным и устойчивым к сбоям.
z Кластер легче масштабировать, поскольку каждый компонент имеет собствен-
  ный жизненный цикл и может масштабироваться независимо от остальных.

В итоге отказ одного из серверов приведет к недоступности лишь небольшой части
кластера, а добавление новых серверов не будет вызывать никаких затруднений.
Каждый компонент Kubernetes выполняет строго определенную функцию. Что-
бы понять принцип работы системы в целом, важно знать назначение каждого
компонента и то, как он взаимодействует с другими.
В зависимости от своей роли компонент развертывается либо на управляющем,
либо на вычислительном узле. Одни компоненты отвечают за поддержание
состояния всего кластера и управление им, а другие — за запуск контейнеров
