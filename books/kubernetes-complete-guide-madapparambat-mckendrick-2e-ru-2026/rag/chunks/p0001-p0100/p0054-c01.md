Контейнер
Контейнер можно рассматривать как запущенный экземпляр образа. Подобно
морским грузовым контейнерам, они служат упаковкой для кода приложения,
его зависимостей и среды выполнения, объединяя их в один легковесный па-
кет. Благодаря тому что контейнер включает все необходимое, он одинаково
работает в разных средах. Каждый контейнер выполняется изолированно, что
предотвращает конфликты с другими приложениями, работающими в той же
системе. Контейнеры совместно используют ядро хостовой операционной систе-
мы, благодаря чему они запускаются и останавливаются значительно быстрее,
чем виртуальные машины.

Реестр контейнеров
Реестр контейнеров представляет собой централизованный репозиторий для
хранения и обмена образами контейнеров. Он играет роль механизма распро-
странения, позволяя пользователям отправлять образы в реестр и загружать
их оттуда. Среди популярных публичных реестров можно выделить Docker
Hub, Red Hat Quay, Elastic Container Registry (ECR) от Amazon, Azure Container
Registry, Google Container Registry и GitHub Container Registry. Многие ор-
ганизации используют частные реестры для безопасного хранения и обмена
пользовательскими образами. Реестры играют ключевую роль в экосистеме
Docker, способствуя совместной работе и эффективному управлению контей-
неризованными приложениями.

Файлы Dockerfile и Containerfile
Dockerfile или Containerfile — это текстовый файл, содержащий набор инструк-
ций для сборки образа контейнера. Он определяет базовый образ, настраивает
окружение, копирует код приложения, устанавливает зависимости и задает
параметры среды выполнения. Эти файлы автоматизируют процесс создания
полноценных образов, позволяя разработчикам версионировать и распростра-
нять конфигурации их приложений.

Пример файла Dockerfile приведен в следующем фрагменте кода:
# syntax=docker/dockerfile:1

FROM node:18-alpine
WORKDIR /app
