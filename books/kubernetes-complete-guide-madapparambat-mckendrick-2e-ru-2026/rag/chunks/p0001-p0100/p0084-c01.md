84     Глава 2   •  Архитектура Kubernetes

Теперь рассмотрим содержимое управляющего узла (рис. 2.5).

    Рис. 2.5. Компонент kube-apiserver располагается перед хранилищем etcd
   и выполняет роль прокси; только kube-apiserver может читать данные из etcd
                         и записывать их в него

Компонент etcd можно назвать «сердцем» кластера. Если данные в etcd будут
потеряны, кластер Kubernetes перестанет работать. Этот компонент даже
важнее kube-apiserver: если kube-apiserver выйдет из строя, его можно пере-
запустить, но если данные etcd будут повреждены или безвозвратно удалены,
кластер будет полностью утрачен.

К счастью, для использования Kubernetes вам не требуется глубокое знание
etcd. Более того, настоятельно не рекомендуется изменять его содержимое
без четкого понимания последствий: некорректная операция может повредить
данные в etcd и, как следствие, нарушить состояние кластера.
Помните, что согласно принципам архитектуры Kubernetes для чтения или за-
писи данных в etcd каждый компонент должен обращаться к kube-apiserver.
Это связано с тем, что с технической точки зрения утилита kubectl прохо-
дит аутентификацию в kube-apiserver с использованием клиентского TLS-
сертификата, который есть только у kube-apiserver. Таким образом, это един-
ственный компонент Kubernetes, имеющий право читать и записывать данные
в etcd. Это принципиально важный момент в архитектуре Kubernetes: осталь-
ные компоненты не могут напрямую читать или записывать данные в etcd,
не обращаясь к конечным точкам kube-apiserver по протоколу HTTP.
