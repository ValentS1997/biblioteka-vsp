Чтобы решить эту проблему, можно создать образ машины для каждого микро-
сервиса и запустить каждый из них на отдельной виртуальной машине, то есть
отказаться от развертывания нескольких микросервисов на одном сервере.
Однако в этом случае потребуется по одной машине на каждый микросервис.
Разумеется, с помощью AWS или GCP можно без труда развернуть десятки сер-
веров, каждый из которых будет обслуживать только один микросервис, но это
приведет к лишним расходам, поскольку при таком подходе вычислительные
ресурсы хоста не используются совместно.

В мире контейнеров существуют аналогичные решения, однако стандартные
среды выполнения контейнеров не обеспечивают полной изоляции микросерви-
сов. Именно здесь в игру вступают среда выполнения Kata и проект Confidential
Containers. Эти технологии обеспечивают более высокий уровень безопасности
и улучшенную изоляцию контейнеризованных приложений. Более подробно
мы поговорим о них далее в книге.

В следующем подразделе вы узнаете о том, как контейнеры обеспечивают изо-
ляцию приложений.

Преимущества изоляции с помощью контейнеров
Такие контейнерные движки, как Docker и Podman, играют ключевую роль
в управлении микросервисами. В отличие от виртуальных машин (ВМ), ко-
торым требуется полноценная гостевая операционная система, контейнеры
представляют собой легковесные модули, использующие ядро Linux хостовой
системы. Благодаря этому они запускаются и останавливаются значительно
быстрее, чем виртуальные машины.

Контейнерные движки предоставляют удобный API для сборки, развертывания
и управления контейнерами. Они не создают дополнительный слой виртуали-
зации, а используют встроенные возможности ядра Linux для изоляции процес-
сов, обеспечения безопасности и распределения ресурсов. Столь эффективный
подход делает контейнеризацию оптимальным решением для развертывания
микросервисов.
