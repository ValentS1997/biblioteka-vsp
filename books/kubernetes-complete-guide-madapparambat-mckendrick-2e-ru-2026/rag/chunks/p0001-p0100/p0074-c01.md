вычислительных узлов.
Вы не запускаете контейнеры самостоятельно, поэтому не взаимодействуете
непосредственно с вычислительными узлами. Вместо этого ваши инструкции
отправляются в управляющий слой, который делегирует задачу создания и об-
служивания контейнеров вычислительным узлам от вашего имени (рис. 2.1).

                Рис. 2.1. Типовой рабочий процесс Kubernetes

Благодаря распределенной архитектуре Kubernetes компоненты управляющего
слоя могут располагаться на нескольких машинах. Существует два подхода к их
развертыванию.

z Все компоненты управляющего слоя можно запустить на одной машине либо
   распределить по разным. Для обеспечения максимальной отказоустойчивости
   рекомендуется размещать их на отдельных машинах. При этом компоненты
   Kubernetes должны иметь возможность взаимодействовать между собой, и их
   установка на разных хостах вполне допускает такое взаимодействие.
z С вычислительными (или рабочими) узлами все намного проще. Их компо-
   ненты устанавливаются на стандартную машину с поддерживаемой средой
   выполнения контейнеров. Эти компоненты взаимодействуют с локальным
   контейнерным движком, установленным на данной машине, и запускают
   контейнеры на основе инструкций, поступающих от компонентов управля-
  ющего слоя. Для увеличения вычислительных ресурсов кластера достаточно
   добавить новые вычислительные узлы и присоединить их к кластеру, создав
   место для дополнительных контейнеров.

         Распределение компонентов управляющего слоя и вычислительных узлов по
         разным машинам делает кластер высокодоступным и масштабируемым. Систе
        ма Kubernetes изначально проектировалась с учетом принципов облачных
          технологий: ее компоненты не используют локальные хранилища данных, легко
         масштабируются и могут быть распределены по разным хостам. Основная идея
         заключается в том, чтобы избежать появления единой точки отказа, которая
          возникает при размещении всех компонентов на одном хосте.
