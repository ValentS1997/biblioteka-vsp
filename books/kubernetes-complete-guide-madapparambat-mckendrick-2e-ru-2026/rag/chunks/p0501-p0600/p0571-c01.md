Запуск кластера AKS     571

После запуска кластера вы увидите примерно следующее (рис. 17.7).

                    Рис. 17.7. Результат запуска кластера

Как видите, вывод содержит множество данных, однако анализировать их вруч-
ную не придется, так как мы будем взаимодействовать с кластером через Azure
CLI и портал Azure, а не путем отправки запросов к API Azure Resource Manager.
Теперь, когда кластер создан, необходимо настроить локальный клиент kubectl
для взаимодействия с ним.

Для этого выполните команду:

 $ az aks get-credentials --resource-group rg-myfirstakscluster-eus \
     --name aksmyfirstakscluster-eus

Появится сообщение о загрузке учетных данных и настройке kubectl (рис. 17.8).

  Рис. 17.8. Загрузка учетных данных для доступа к кластеру и настройка kubectl

Затем, когда кластер запущен и клиент kubectl настроен, можно вывести список
узлов кластера с помощью уже знакомой вам команды:

 $ kubectl get nodes

Результат ее выполнения показан на рис. 17.9.

Теперь можно развернуть тестовую рабочую нагрузку Guestbook, которую мы
уже использовали в предыдущих двух главах для проверки работоспособности
кластеров.
