В целом этот метод подходит для среды разработки и знакомства с основами
аутентификации в Kubernetes, но не рекомендуется для использования в рабо-
чей среде. Далее мы рассмотрим процесс аутентификации пользователей с по-
мощью токенов ServiceAccount.
Токены ServiceAccount. Хотя объекты ServiceAccount (учетные записи серви-
сов) предназначены для идентификации процессов, выполняющихся внутри
подов, или компонентов кластера, их можно использовать и для аутентифика-
ции внешних запросов.

ServiceAccount — это объект Kubernetes, которым можно управлять так же,
как и другими ресурсами кластера, — с помощью kubectl или прямых HTTP-
запросов к API-серверу. Токены ServiceAccount представляют собой объекты
JSON Web Token (JWT) и генерируются по запросу или с помощью команды
kubectl create token.

         Каждое пространство имен Kubernetes содержит предварительно созданную
         учетную запись сервиса default. Поды, для которых явно не указана учетная
          запись сервиса, автоматически наследуют эту учетную запись по умолчанию
         для авторизации внутри кластера. Вы можете выяснить, какая учетная запись
          сервиса используется подом, выполнив команду kubectl get pods/ <имя_пода>
           -o yaml и просмотрев значение поля spec.serviceAccountName.

Обычно при определении пода можно указать учетную запись сервиса, которая
должна использоваться для процессов внутри контейнера. Это делается через
поле .spec.serviceAccountName в спецификации пода. JWT-токен внедряется
в контейнер, после чего выполняющийся внутри процесс может использовать
его для аутентификации на API-сервере Kubernetes по схеме Bearer. Это требу-
ется только в том случае, если контейнеру необходимо взаимодействовать с API
Kubernetes, например, для обнаружения других подов в кластере. Принцип ра-
боты этого метода аутентификации представлен на следующей схеме (рис. 18.3).

Эта схема также объясняет, почему токены ServiceAccount могут применяться
для аутентификации внешних запросов: API-сервер Kubernetes не анализиру-
ет источник запроса, его интересует лишь токен, переданный в его заголовке.
Этот токен можно использовать как в командах kubectl, так и в прямых HTTP-
запросах к API-серверу. Тем не менее использование токенов ServiceAccount
для аутентификации внешних запросов не является рекомендуемой практикой.
