558     Глава 16   •  Запуск кластера на платформе Amazon Web Services

На первом этапе обновляется локальный файл конфигурации kubectl:

[✔] kubeconfig has been updated

Затем завершается работа всех ресурсов, созданных в процессе развертывания
рабочих нагрузок:

 [i] cleaning up AWS load balancers created by Kubernetes objects of Kind
 Service or Ingress

После этого удаляются два стека AWS CloudFormation, что влечет за собой
автоматическое удаление всех созданных ими ресурсов и настроек:

 11c87ff4"

 11c87ff4" to get deleted
 [i] waiting for CloudFormation stack "eksctl-hilarious-wardrobe-1717847351-
 nodegroup-ng-11c87ff4"
 [i] will delete stack "eksctl-hilarious-wardrobe-1717847351-cluster"
[✔] all cluster resources were deleted

На этом процесс удаления кластера завершается.

         После удаления кластера обязательно проверьте разделы EC2, EKS и Cloud
          Formation консоли AWS, чтобы убедиться, что все ресурсы действительно
         удалены. За оставшиеся «осиротевшие» или неактивные ресурсы может про-
         должать взиматься плата. Хотя подобные ситуации случаются редко, лучше
          убедиться в полном удалении ресурсов заранее, чем получить неожиданный
          счет в конце месяца.

Amazon EKS в течение месяца.
