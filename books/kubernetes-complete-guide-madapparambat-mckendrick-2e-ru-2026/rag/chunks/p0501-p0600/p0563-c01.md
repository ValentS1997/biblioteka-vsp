Знакомство с Microsoft Azure и Azure Kubernetes Service     563

Microsoft Сатья Наделла представил ставший знаменитым (или печально из-
вестным, в зависимости от точки зрения) слайд с надписью «Microsoft ♥ Linux».
Мы говорим «знаменитый» или «печально известный», потому что бывший
генеральный директор компании Стив Балмер однажды заявил:

   «Linux — это рак, который пожирает все, чего касается, в смысле интеллек-
   туальной собственности».

Поэтому данный шаг Microsoft стал разворотом на 180 градусов и многих удивил.
В 2020 году стало известно, что более 50 % всех виртуальных ядер в Azure
выполняют Linux-нагрузки, а около 60 % образов в Azure Marketplace осно-
ваны на этой ОС. Такой результат оказался следствием открытой политики
Microsoft в отношении Linux и проектов с открытым исходным кодом, таких как
Kubernetes, что в итоге привело к появлению ее собственного нативного сервиса
Azure Kubernetes Service (AKS).

Сервис Azure Kubernetes Service
Изначально компания Microsoft запустила сервис контейнеризации под назва-
нием Azure Container Service (ACS). Он позволял пользователям развертывать
контейнерные рабочие нагрузки, выбирая один из трех доступных оркестрато-
ров: Docker Swarm, DC/OS или Kubernetes, каждый из которых предоставлял
собственное решение для управления кластером контейнеров.
Вскоре стало очевидно, что среди этих оркестраторов самым популярным
является Kubernetes, и ACS был постепенно заменен AKS (Azure Kubernetes
Service) — сервисом, полностью основанным на Kubernetes и соответствующим
стандартам CNCF. Этот переход занял около двух лет: сервис AKS стал общедо-
ступным в 2018 году, а ACS окончательно прекратил работу в начале 2020 года.
Сервис AKS тесно интегрирован с другими ключевыми компонентами Microsoft
Azure, включая Azure Active Directory и Policies. Помимо AKS, Microsoft раз-
вивает и другие решения для работы с контейнерами. Одним из новейших
является Azure Container Apps.
Azure Container Apps — это бессерверная платформа, которая позволяет поль-
зователям запускать контейнеризованные приложения, избавляя их от не-
обходимости управлять инфраструктурой. Среди ее возможностей можно
выделить: динамическое масштабирование в зависимости от трафика, событий,
загрузки процессора или памяти; поддержку входящего трафика, передаваемого
по протоколам HTTPS и TCP; интеграцию с Dapr; автоматическое масшта-
бирование; возможность использования встроенных инструментов Azure для
управления, безопасного хранения секретов, внутреннего обнаружения серви-
сов и разделения трафика между версиями приложения при внедрении новых
