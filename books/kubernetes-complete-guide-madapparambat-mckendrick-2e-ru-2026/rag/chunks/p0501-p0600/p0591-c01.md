В следующем подразделе мы рассмотрим механизм аутентификации более
подробно.

Аутентификация в API Kubernetes
Аутентификация в API Kubernetes гарантирует то, что только авторизованные
пользователи и сервисы смогут взаимодействовать с ресурсами кластера. Каж-
дый входящий запрос проходит через цепочку настроенных модулей аутенти-
фикации.

Все запросы к API делятся на две категории:

z запросы от обычного внешнего пользователя или учетной записи сервиса
   (ServiceAccount), определенной в кластере Kubernetes;
z анонимные запросы, если конфигурация кластера их допускает.

Тип запроса определяется на этапе аутентификации. В качестве входных
данных процесса проверки используется весь HTTP-запрос, однако обычно
анализу подвергаются только заголовки запроса или клиентский сертификат.
Аутентификация выполняется с помощью специальных модулей, активизиро-
ванных в конфигурации кластера. Если активизировано несколько модулей,
они выполняются поочередно, пока один из них не подтвердит запрос. В случае
непрохождения аутентификации API-сервер возвращает код HTTP-ответа 401
(Unauthorized) или обрабатывает запрос как анонимный, если такие запросы
являются допустимыми.

         Анонимные запросы автоматически сопоставляются со специальным именем
          пользователя system:anonymous и группой system:unauthenticated. Это позволяет
          настраивать правила авторизации для таких запросов точно так же, как для
         обычных пользователей или учетных записей сервисов.

Все внутренние и внешние операции с кластером осуществляются через API-
сервер Kubernetes и, следовательно, требуют аутентификации. Это правило
распространяется на действия внутренних компонентов кластера и подов, об-
ращающиеся к API-серверу. Запросы, которые вы, как внешний пользователь,
отправляете через kubectl или напрямую в API, тоже проходят эту процедуру.
