550     Глава 16   •  Запуск кластера на платформе Amazon Web Services

Развертывание рабочей нагрузки
Хотя наш кластер запущен на платформе AWS с помощью сервиса EKS, для раз-
вертывания рабочей нагрузки мы будем использовать те же YAML-манифесты,
что и в случае с GKE, применив локальную утилиту kubectl. Для этого выпол-
ните следующие шаги.

1. Сначала создайте объекты Deployment и Service для Redis Leader, выполнив
   две команды:

    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/redis-leader-
    deployment.yaml
    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/redis-leader-service.
    yaml

2. Затем создайте объекты Deployment и Service для Redis Follower:

    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/redis-follower-
    deployment.yaml
    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/redis-follower-service.
    yaml

3. После запуска Redis Leader и Follower создайте развертывание и сервис
   frontend, выполнив следующие команды:

    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/frontend-deployment.
    yaml
    $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
    kubernetes-engine-samples/main/quickstarts/guestbook/frontend-service.yaml

4. Через несколько минут можно будет выполнить следующую команду для
   получения сведений о запущенном сервисе. Ее вывод должен содержать
  информацию о способе получения доступа к рабочей нагрузке:

    $ kubectl get service frontend

На этот раз результат немного отличается от вывода, который мы получили при
запуске рабочей нагрузки в GKE (рис. 16.6).

Как видите, вместо IP-адреса мы получаем URL-адрес. Скопируйте его в адрес-
ную строку браузера.

Поскольку мы использовали те же команды и конфигурационные файлы, вы
увидите уже знакомое веб-приложение Guestbook, изображенное на рис. 16.7.
