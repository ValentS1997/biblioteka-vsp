Аутентификация и авторизация: управление пользовательским доступом     593

для определенных сценариев и уровней безопасности. Эти стратегии опира-
ются на токены и сертификаты, подтверждающие подлинность пользователей
и приложений, взаимодействующих с кластером. Преимущество API-сервера
Kubernetes заключается в поддержке нескольких механизмов аутентифика-
ции, что позволяет комбинировать различные подходы в рамках одного кла-
стера. В следующих разделах мы рассмотрим наиболее распространенные
методы аутентификации, включая статические файлы с токенами, токены
ServiceAccount, клиентские сертификаты X.509 и токены OpenID Connect.
Статические файлы с токенами. Это самый простой метод аутентификации,
предусмотренный в Kubernetes для управления обычными пользователями.
По своей сути он напоминает использование файлов /etc/shadow и /etc/passwd
в системах Unix/Linux. Однако следует подчеркнуть, что этот метод не реко-
мендуется использовать, так как он считается небезопасным для кластеров,
развернутых в рабочей среде.

Такой подход предполагает создание CSV-файла, в котором каждая строка
имеет следующий формат:

 token,user,uid,"group1,group2,group3"

При запуске API-сервера Kubernetes этот файл передается ему через параметр
--token-auth-file, указанный в статическом манифесте пода /etc/kubernetes/
manifests/kube-apiserver.yaml на узлах управляющего слоя (или на мастер-
узлах):

# /etc/kubernetes/manifests/kube-apiserver.yaml
... <фрагмент опущен для краткости> ...
spec:
  containers:
  - command:
    - kube-apiserver
    - --advertise-address=192.168.59.154
    - --allow-privileged=true
    - --authorization-mode=Node,RBAC
    - --token-auth-file=/etc/kubernetes/user-tokens.csv
    - --client-ca-file=/var/lib/minikube/certs/ca.crt
... <фрагмент опущен для краткости> ...

Для аутентификации на API-сервере необходимо использовать стандартную
схему HTTP-аутентификации Bearer, добавив в запрос следующий заголовок:

 Authorization: Bearer <токен>

Получив запрос, API-сервер Kubernetes сопоставит указанный токен с содер-
жимым статического файла и присвоит пользователю атрибуты из соответству-
ющей записи.
