Аутентификация и авторизация: управление пользовательским доступом     599

    Рис. 18.4. Проверка содержимого JWT-токена для объекта ServiceAccount

  Как видите, JWT-токен соответствует объекту example-sa в пространстве
  имен example-ns. Кроме того, в поле sub раздела PAYLOAD указано фак-
   тическое имя пользователя, которое будет использоваться в Kubernetes:
   system:serviceaccount:example-ns:example-sa.
6. Теперь настройте kubeconfig для использования этого токена. Сначала соз-
   дайте нового пользователя с помощью команды:

    $ kubectl config set-credentials example-sa --token=<ваш_токен>
    User "example-sa" set.

   где example-sa — это имя созданного объекта ServiceAccount, а <ваш_токен> —
   скопированное ранее значение токена.
7. Создайте новый контекст для этого пользователя в файле kubeconfig. Снача-
   ла узнайте имя текущего кластера с помощью команды kubectl config view,
   а затем создайте контекст, выполнив команду kubectl config set-context:

    $ kubectl config set-context <имя_нового_контекста> --user=<новый_
    пользователь> --cluster=<имя_кластера>
