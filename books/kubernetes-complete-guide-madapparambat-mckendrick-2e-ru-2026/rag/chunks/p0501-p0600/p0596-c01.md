    Рис. 18.3. Аутентификация в Kubernetes с помощью токенов ServiceAccount

До выхода версии 1.22 система Kubernetes автоматически создавала учетные
данные API для объектов ServiceAccount с использованием объектов Secret. Эти
объекты содержали токены, которые поды могли монтировать для получения
доступа. Однако такой подход имел ряд ограничений.

z Статические токены. Токены хранились в объекте Secret в виде открытого
   текста, что представляло угрозу безопасности в случае компрометации.
z Ограниченная степень контроля. Срок действия и разрешения токенов было
   сложно контролировать.

Начиная с версии 1.22, в Kubernetes используется более безопасный механизм.
Теперь поды получают токены напрямую с помощью API TokenRequest. Эти
токены:

z являются короткоживущими. Токены имеют ограниченный срок жизни, что
   уменьшает последствия возможной утечки;
z автоматически монтируются в поды. Токены автоматически монтируются
   в виде томов, что устраняет потребность в заранее созданных объектах Secret.
