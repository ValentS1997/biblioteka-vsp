594     Глава 18   •  Безопасность в системе Kubernetes

При работе с kubectl необходимо внести изменения в файл конфигурации
kubeconfig, выполнив команду:

 $ kubectl config set-credentials <контекстный_пользователь> --token=<токен>

После этого нужно создать контекст с этим пользователем и активизировать его
для отправки запросов с помощью команды kubectl config use-context.

        До выхода версии 1.19 в Kubernetes существовал механизм, позволяющий ис-
          пользовать схему HTTP-аутентификации Basic и файл, передаваемый API-серверу
          через параметр --basic-auth-file. Однако по соображениям безопасности этот
         метод больше не поддерживается.

Принцип работы этого метода аутентификации представлен на следующей
схеме (рис. 18.2).

     Рис. 18.2. Аутентификация в Kubernetes с помощью статического файла
                                     с токенами

Теперь перечислим преимущества и недостатки метода аутентификации на
основе статического файла с токенами.

Преимущества:

z простая настройка;
z понятный принцип работы.

Недостатки:

z низкий уровень безопасности, поскольку компрометация файла с токенами
   приводит к утечке данных всех пользователей кластера;
z необходимость в ручном управлении пользователями;
