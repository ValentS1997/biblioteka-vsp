534     Глава 15   •  Запуск кластера на платформе Google Cloud Platform (GCP)

Однако рабочие нагрузки можно распределить и между несколькими регионами,
используя механизм Multi Cluster Ingress. В этом случае нужно учесть увеличение
задержки при взаимодействии между регионами, особенно для таких общих сер-
висов, как базы данных. Ссылка на источник, посвященный Multi Cluster Ingress,
приведена в разделе «Дополнительные источники информации» в конце главы.

Теперь вернемся к примеру, рассмотренному в начале главы:

 $ gcloud container clusters create myfirstgkecluster --num-nodes=2 --zone=us-
 central1-a

Команда создает два узла в одной зоне региона us-central1, а именно в зоне a,
которую мы указали с помощью флага --zone.
Заменим его на флаг --region:

 $ gcloud container clusters create myfirstgkecluster --num-nodes=2 --region=us-
 central1

После запуска кластера выполните команду:

 $ kubectl get nodes

Вывод будет примерно таким, как показано на рис. 15.14.

              Рис. 15.14. Просмотр узлов, работающих в регионе

Как видите, в каждой зоне региона размещено по два узла, а значит, кластер
содержит шесть узлов. Это объясняется тем, что при указании региона по умол-
чанию кластер распределяется по трем зонам. Такое поведение можно изменить,
указав конкретные зоны с помощью параметра --node-locations.
Команда для создания такого кластера с нуля будет выглядеть следующим об-
разом — обратите внимание на список зон, разделенных запятыми:

 $ gcloud container clusters create myfirstgkecluster \
   --num-nodes=2 \
   --region=us-central1 \
   --node-locations us-central1-a,us-central1-b,us-central1-c,us-central1-f
