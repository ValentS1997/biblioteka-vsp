Подготовка локальной среды     543

  AWS используется для личных проектов, поэтому после нажатия кнопки
   Enable (Включить) он выбрал вариант Enable in only this AWS account (Включить
   только в этой учетной записи AWS) вместо рекомендуемого Enable with AWS
    Organizations (Включить с AWS Organizations). Он сделал это, потому что ему
   не нужно управлять несколькими учетными записями AWS в рамках одной
   организации. Следуйте инструкциям на экране, чтобы активизировать сервис.
2. После активизации сервиса IAM Identity Center (Центр идентификации IAM)
   необходимо создать пользователя, имеющего только программный доступ.
  Для этого вернитесь к строке поиска в верхнем меню, снова введите IAM, но
   на этот раз выберите пункт Manage access to AWS resources (Управление до-
   ступом к ресурсам AWS). После загрузки страницы выберите пункт Users
   (Пользователи) в разделе Access Management (Управление доступом) меню
   слева и нажмите кнопку Create user (Создать пользователя).
3. Введите имя пользователя ekscluster и убедитесь, что флажок Provide user
   access to the AWS Management Console — optional (Предоставить пользователю
   доступ к консоли управления AWS — не обязательно) снят. Затем нажмите
   кнопку Next (Далее) (рис. 16.2). Мы обсудим данную опцию после запуска
   кластера.

                    Рис. 16.2. Добавление пользователя

4. Вместо создания новой группы мы предоставим пользователю доступ на ос-
   нове существующей политики. Для этого выберите Attach existing policies directly
   (Присоединить существующие политики напрямую), отметьте политику
    AdministratorAccess и нажмите кнопку Next (Далее) (рис. 16.3).
