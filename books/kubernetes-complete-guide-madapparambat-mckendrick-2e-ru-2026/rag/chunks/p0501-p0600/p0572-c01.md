572     Глава 17   •  Запуск кластера на платформе Microsoft Azure

               Рис. 17.9. Проверка доступности узлов кластера

Развертывание рабочей нагрузки
и взаимодействие с кластером
Здесь мы воспользуемся той же рабочей нагрузкой, что и в главах 15 и 16, по-
этому приведем только сами команды без их детального разбора.

Развертывание рабочей нагрузки
Начнем с создания объектов Deployment и Service для Redis Leader:

 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/redis-leader
 -deployment.yaml
 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/redis-leader-service.yaml

Затем создадим те же объекты для Redis Follower:

 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/redis-follower
 -deployment.yaml
 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/redis-follower
 -service.yaml

Наконец, развернем фронтенд с помощью следующих команд:

 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/frontend
 -deployment.yaml
 $ kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/
 kubernetes-engine-samples/main/quickstarts/guestbook/frontend-service.yaml

Через несколько минут можно получить информацию о сервисе frontend, вы-
полнив команду:

 $ kubectl get service frontend
