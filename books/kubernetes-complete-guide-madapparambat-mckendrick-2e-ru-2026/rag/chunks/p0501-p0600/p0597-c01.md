Аутентификация и авторизация: управление пользовательским доступом     597

Хотя автоматическое монтирование является предпочтительным вариантом,
при необходимости вы можете вручную создавать объекты Secret для токенов
учетных записей сервисов. Это может быть полезно в тех случаях, когда токену
требуется более длительный срок действия, однако в большинстве ситуаций
для повышения уровня безопасности рекомендуется выбирать автоматическое
монтирование токенов.

         Как мы уже выяснили, Kubernetes автоматически монтирует учетные данные
          API объекта ServiceAccount в поды для упрощения доступа к кластеру. Чтобы
         отключить это поведение и управлять токенами другим способом, задайте
         параметр automountServiceAccountToken: false в манифесте ServiceAccount или
          в спецификации пода. Это значение применяется ко всем подам, использу-
       ющим данную учетную запись сервиса, если только оно не переопределено
          в конфигурации конкретного пода. При одновременном указании параметра
          в обоих местах приоритет имеет настройка пода. Подробнее об этом параметре
        можно узнать в официальной документации по адресу https://kubernetes.io/docs/
           tasks/configure-pod-container/configure-service-account/#opt-out-of-api-credential-
          automounting.

Далее мы покажем, как создавать и управлять объектами ServiceAccount, а так-
же продемонстрируем способ применения JWT-токенов для аутентификации
при работе с kubectl. Это даст вам некоторое представление о механизме RBAC,
с которым вы познакомитесь чуть позже. А пока выполните следующие шаги.

1. Создайте YAML-манифест для нового пространства имен и объекта Ser
   viceAccount. Мы настроим механизм RBAC таким образом, чтобы эта учет-
   ная запись могла просматривать поды только в данном пространстве имен:
   # 01_serviceaccount/example-sa-ns.yaml
   ---
   apiVersion: v1
   kind: Namespace
   metadata:
     name: example-ns

   ---
   apiVersion: v1
   kind: ServiceAccount
   metadata:
     name: example-sa
     namespace: example-ns
   Учтите, что те же ресурсы можно создать и императивным способом с по-
  мощью команды kubectl create serviceaccount example-sa.
2. Создайте YAML-манифест для объекта Role с именем pod-reader в про-
   странстве имен example-ns. Эта роль предоставит вам права на получение
