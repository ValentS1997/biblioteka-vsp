556     Глава 16   •  Запуск кластера на платформе Amazon Web Services

          Рис. 16.15. Просмотр созданного балансировщика нагрузки

На ней вы увидите два стека: один — для узлов EKS (двух экземпляров EC2),
второй — для самого кластера EKS, то есть управляющего слоя Kubernetes
(рис. 16.16).

                 Рис. 16.16. Два стека, составляющих кластер

При выборе любого стека отобразятся подробности о процессе его запуска,
включая полный список ресурсов, созданных при развертывании кластера
Amazon EKS с помощью eksctl.

Выбранный шаблон можно просмотреть в визуальном редакторе. Там же до-
ступен исходный шаблон CloudFormation, сгенерированный eksctl, который
представляет собой довольно сложный JSON-файл. Если нажать кнопку View
in Application Composer (Посмотреть в Application Composer), откроется более на-
глядное визуальное представление стека, как показано на рис. 16.17.

На этом обзор возможностей консоли AWS можно завершить. Несмотря на то
что запуск кластера EKS через eksctl относительно прост, уровень его инте-
грации с консолью AWS оставляет желать лучшего — особенно по сравнению
с тем, что мы видели в предыдущей главе при работе с GKE.
