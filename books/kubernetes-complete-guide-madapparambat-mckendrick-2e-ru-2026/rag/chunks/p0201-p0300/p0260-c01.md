260     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Как видите, в кластере появился новый объект ConfigMap, содержащий четыре
параметра, которые были указаны в ENV-файле. Теперь вы знаете, как можно
импортировать содержимое ENV-файлов в объекты Kubernetes ConfigMap.

         Помните, что объекты ConfigMap не предназначены для хранения конфиден-
         циальных данных. Информация в них не закодирована, поэтому ее можно
         просмотреть с помощью команды kubectl describe cm. Для хранения конфиден-
         циальных данных следует использовать объект Secret. Хотя объекты Secret по
         умолчанию не шифруются, они хранятся в формате base64, что обеспечивает
         базовый уровень обфускации. Начиная с версии Kubernetes 1.27, для шифро-
         вания содержимого объектов Secret и ConfigMap можно использовать плагины
        KMS (Key Management System — система управления ключами), обеспечивающие
         дополнительную защиту конфиденциальной информации.

В следующем подразделе мы обсудим способ чтения содержимого объекта Con
figMap.

Чтение значений, содержащихся
в объекте ConfigMap
До сих пор мы выводили список объектов ConfigMap, просто чтобы увидеть
количество содержащихся в них ключей. Однако, помимо перечисления таких
объектов, мы также можем просматривать хранящиеся в них данные. Это бывает
полезно при отладке и в тех случаях, когда вы не уверены в их содержимом.

Поскольку данные в ConfigMap не являются конфиденциальными, их можно
легко прочитать с помощью утилиты kubectl, которая выводит их прямо в тер-
минал.
Для этого используется команда kubectl describe. Мы применим ее к объекту
my-fourth-configmap, содержащему наибольшее количество данных. Вывод
команды получается довольно объемным, но при этом все конфигурационные
значения отображаются в удобочитаемом формате:

 $ kubectl describe cm my-fourth-configmap
 Name:         my-fourth-configmap
 Namespace:    default
 Labels:       <none>
 Annotations:  <none>
