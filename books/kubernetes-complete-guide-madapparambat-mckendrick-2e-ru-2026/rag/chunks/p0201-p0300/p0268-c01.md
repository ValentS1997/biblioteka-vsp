268     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Чтобы сделать объект ConfigMap неизменяемым, достаточно задать значение
true для поля immutable в его определении:

# immutable-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: immutable-configmap
data:
  color: "blue"
  version: "1.0"
  environment: "prod"
immutable: true

После этого изменить его данные будет невозможно. Для обновления ConfigMap
вам придется удалить существующий объект и создать новый. Чтобы сохранить
корректную конфигурацию, вам также потребуется пересоздать все поды,
ссылающиеся на удаленный объект.

В следующем разделе мы поговорим об объекте Secret.

Управление конфиденциальной конфигурацией
с помощью объекта Secret
Secret (секрет) — это ресурс, который позволяет настраивать приложения, ра-
ботающие в Kubernetes. Секреты очень похожи на объекты ConfigMap и могут
использоваться совместно с ними. Главное отличие заключается в том, что
объекты Secret кодируются и предназначены для хранения конфиденциальной
информации — паролей, токенов, секретных ключей API, а объекты ConfigMap
предназначены для хранения неконфиденциальных данных. В остальном эти
объекты ведут себя практически одинаково.

Чтобы обеспечить защиту чувствительных данных, хранящихся в объектах
Secret, рекомендуется придерживаться следующих практик.

z Ограничение доступа. Используйте механизм управления доступом на основе
   ролей (RBAC), предоставляя пользователям и сервисам только необходимые
   привилегии.
z Избегайте жесткого кодирования. Никогда не встраивайте секреты напря-
  мую в код приложения или конфигурационные файлы.
z Регулярная ротация. Обеспечьте регулярную ротацию секретов, чтобы сни-
