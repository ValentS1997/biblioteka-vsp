Влияние пространств имен на ресурсы и сервисы     225

 $ kubectl apply -f custom-ns-2.yaml
 namespace/custom-ns-2 created

Итак, мы создали два пользовательских пространства имен. Первое, custom-ns,
было создано императивным способом, а второе, custom-ns-2, — декларативным.
Теперь рассмотрим процедуру удаления этих двух пространств имен с по-
мощью kubectl.

Удаление пространства имен
Удалить пространство имен можно с помощью команды kubectl delete:

 $ kubectl delete namespaces custom-ns
 namespace "custom-ns" deleted

То же самое можно сделать и декларативным способом. Например, удалим про-
странство custom-ns-2, созданное в предыдущем YAML-файле:

 $ kubectl delete -f custom-ns-2.yaml
 namespace "custom-ns-2" deleted

В результате выполнения этой команды пространство имен перейдет из со-
стояния Active в состояние Terminating. После запуска команды в этом про-
странстве нельзя будет размещать новые объекты, а через некоторое время оно
будет полностью удалено из кластера.

         Имейте в виду, что команда kubectl delete namespace крайне опасна. Удаление
          пространства имен является необратимой операцией. Все ресурсы, созданные
          в этом пространстве, будут уничтожены. Перед тем как использовать эту коман-
           ду, убедитесь в наличии YAML-файлов для восстановления удаленных ресурсов
         и самого пространства имен.

Теперь рассмотрим процесс создания ресурсов внутри заданного пространства
имен.

Создание ресурса внутри пространства имен
Следующий фрагмент кода показывает, как можно создать под nginx с указани-
ем пользовательского пространства имен. В этом примере мы заново создадим
пространство custom-ns и запустим в нем под nginx:

 $ kubectl create ns custom-ns
 $ kubectl run nginx --image nginx:latest -n custom-ns
 pod/nginx created
