Настройка подов с помощью ConfigMap     255

После выполнения этой команды можно снова ввести команду kubectl get cm,
чтобы увидеть созданный объект:

 $ kubectl get cm
 NAME                 DATA   AGE
 my-first-configmap   0      42s

Теперь создадим пустой объект ConfigMap декларативным способом. Для этого
необходимо подготовить YAML-файл и применить его с помощью утили-
ты kubectl.

Приведенный ниже код необходимо поместить в файл ~/my-second-configmap.yaml:
# my-second-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-second-configmap

После создания файла примените его к вашему кластеру Kubernetes с помощью
команды kubectl apply -f:

 $ kubectl apply -f my-second-configmap.yaml
 configmap/my-second-configmap created

Затем снова выполните команду kubectl get cm, чтобы убедиться в том, что
новый объект ConfigMap появился рядом с созданным ранее:

 $ kubectl get cm
 NAME                  DATA   AGE
 kube-root-ca.crt      1      23d
 my-first-configmap    0      5s
 my-second-configmap   0      2s

Обратите внимание, что в выводе команды kubectl get cm в столбце DATA отобра-
жается количество ключей, содержащихся в каждом объекте ConfigMap. Сейчас
оно равно нулю, но в следующих примерах мы обсудим способ заполнения этого
объекта при его создании, и тогда столбец DATA будет отражать количество клю-
чей, добавленных в ConfigMap.

Создание объекта ConfigMap
на основе литеральных значений
Поскольку пустой объект ConfigMap практически бесполезен, создадим такой
объект с изначально заданными значениями. Это можно сделать императивным
способом, добавив флаг --from-literal к команде kubectl create cm.
