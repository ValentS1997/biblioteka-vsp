230     Глава 6   •  Пространства имен, квоты и лимиты

Попробуем создать два пода с именем nginx в пространстве default. Для этого
можно два раза подряд выполнить одну и ту же команду:

 $ kubectl run nginx --image nginx:latest
 pod/nginx created
 $ kubectl run nginx --image nginx:latest
 Error from server (AlreadyExists): pods "nginx" already exists

Вторая команда завершится с ошибкой, и система Kubernetes сообщит, что
под с таким именем уже существует. Выполнив команду kubectl get pods, мы
увидим, что в пространстве имен по умолчанию был создан только один под:

 $ kubectl get pods
 NAME    READY   STATUS    RESTARTS   AGE
 nginx   1/1     Running   0          64s

Теперь попробуем снова вывести список подов, но на этот раз в пространстве
имен custom-ns:

 $ kubectl get pods --namespace custom-ns
 NAME    READY   STATUS    RESTARTS   AGE
 nginx   1/1     Running   0          89m
 nginx2  1/1     Running   0          23m

Как видим, в этом пространстве тоже есть под nginx, и это не тот же самый под,
что находится в пространстве default. В этом и заключается одно из главных
преимуществ пространств имен: они позволяют определить несколько одно-
именных ресурсов в кластере Kubernetes, распределив их по разным простран-
ствам. С их помощью мы можем легко создавать независимые копии микро-
сервисов или приложений.
Мы также можем переопределить пространство имен для ресурсов, создаваемых
декларативным способом. Если при выполнении команды kubectl apply добавить
параметр -n, то утилита kubectl выполнит операцию в отношении пространства,
заданного с помощью переданного параметра, а не того, которое указано в YAML-
файле. Такой подход упрощает дублирование ресурсов между разными простран-
ствами имен, например между рабочей (production) и тестовой (test) средами.

Не все ресурсы принадлежат пространству имен
В Kubernetes не все объекты принадлежат пространству имен. Например, узлы,
представленные на уровне кластера объектами типа Node, не относятся ни к ка-
кому конкретному пространству имен. Вывести список ресурсов, не принадле-
жащих никакому пространству имен, можно с помощью следующей команды:

 $ kubectl api-resources --namespaced=false
 NAME                SHORTNAMES   APIVERSION   NAMESPACED   KIND
 componentstatuses   cs           v1           false        ComponentStatus
