Настройка подов с помощью ConfigMap     259

Теперь снова перечислим объекты ConfigMap с помощью команды kubectl get cm,
чтобы убедиться в том, что объект my-seventh-configmap создан и содержит два
значения:

 $ kubectl get configmap/my-seventh-configmap
 NAME                   DATA   AGE
 my-seventh-configmap   2      36s

В следующем разделе мы рассмотрим способ создания ConfigMap на основе
ENV-файла.

Создание объекта ConfigMap на основе env-файла
Объект ConfigMap также можно создать императивным способом на основе
ENV-файла, используя флаг --from-env-file.
Файл .env содержит пары «ключ — значение», каждая из которых располага-
ется на отдельной строке. Такой формат конфигурации используется рядом
приложений, поэтому в Kubernetes предусмотрен способ создания объекта
ConfigMap из существующего ENV-файла. Это особенно удобно, если у вас
уже есть работающее приложение, которое вы хотите перенести в Kubernetes.

Вот как выглядит типичный ENV-файл:
# my-env-file.env
hello=world
color=blue
release=1.0
production=true

Как правило, такие файлы называют .env, но это не обязательно. Если файл име-
ет корректный формат, система Kubernetes сможет создать объект ConfigMap
на основе его содержимого.

Импортировать конфигурацию из ENV-файла в кластер Kubernetes можно
с помощью следующей команды:

 $ kubectl create cm my-eight-configmap --from-env-file=my-env-file.env
 configmap/my-eight-configmap created

Выведем список объектов ConfigMap в кластере, чтобы убедиться в том, что
новый объект был успешно создан и содержит четыре конфигурационных
значения:

 $ kubectl get cm my-eight-configmap
 NAME                 DATA   AGE
 my-eight-configmap   4      7s
