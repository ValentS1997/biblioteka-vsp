246     Глава 6   •  Пространства имен, квоты и лимиты

Задание диапазона ограничений служит страховкой на тот случай, если вы
забудете указать значения requests и limits для подов. Благодаря объекту
LimitRange у них всегда будут значения по умолчанию.

 $ kubectl apply -f limitrange.yaml

Теперь посмотрим, как можно вывести список объектов LimitRange.

Вывод списка объектов LimitRange
Вывести список объектов LimitRange можно с помощью утилиты kubectl.
Не забудьте добавить флаг -n, чтобы ограничить запрос определенным про-
странством имен:

 $ kubectl get limitranges -n quota-ns
 NAME           CREATED AT
 my-limitrange  2024-03-10T16:13:00Z

 $ kubectl describe limitranges my-limitrange -n quota-ns
 Name:       my-limitrange
 Namespace:  quota-ns
 Type        Resource  Min    Max     Default Request  Default Limit  Max Limit/
 Request Ratio
 ----        --------  ---    ---     ---------------  -------------  ----------
 -------------
 Container   memory    128Mi  1000Mi  128Mi            256Mi          -
 Container   cpu       100m   1       500m             500m           -

А теперь удалим объект LimitRange из пространства имен.

Удаление объекта LimitRange
Удалить объект LimitRange также можно с помощью утилиты kubectl:

 $ kubectl delete limitranges my-limitrange -n quota-ns
 limitrange "my-limitrange" deleted

Как и всегда, не забывайте добавлять флаг -n, чтобы указать конкретное про-
странство имен, иначе вы рискуете затронуть не то, которое вам нужно!

Резюме
В этой главе вы познакомились с таким важным механизмом системы Kuber
netes, как пространства имен. Они обеспечивают логическую изоляцию ресур-
сов, поэтому необходимы для эффективного управления кластером. Чаще всего
пространства имен создаются для отдельных сред или приложений. Нередко
в кластерах создаются сотни таких пространств.
