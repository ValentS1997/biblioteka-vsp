254     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Перечисление объектов ConfigMap
Как и в случае с любыми другими объектами Kubernetes, просмотреть все объ-
екты ConfigMap, созданные в кластере, можно с помощью утилиты kubectl. Для
этого укажите полное имя ресурса configmaps:

 $ kubectl get configmaps

Или воспользуйтесь сокращенным псевдонимом cm:

 $ kubectl get cm

Обе команды решают одну задачу. В результате их выполнения kubectl выводит
список предустановленных объектов ConfigMap или сообщение о том, что они
не найдены. Эта разница объясняется тем, что одни облачные сервисы создают
объекты ConfigMap по умолчанию для внутренних процессов, а другие — нет.
Наличие или отсутствие таких предустановленных объектов зависит от среды,
в которой развернут кластер Kubernetes.

 $ kubectl get configmaps -A
 NAMESPACE         NAME               DATA   AGE
 default           kube-root-ca.crt   1      23d
 kube-node-lease   kube-root-ca.crt   1      23d
 kube-public       cluster-info       1      23d
 kube-public       kube-root-ca.crt   1      23d
 ...               ...                ...    ...
 ... <фрагмент опущен для краткости>...

Как видите, в пространстве имен default и в служебных пространствах, управ-
ляемых Kubernetes, присутствует несколько объектов ConfigMap, созданных
в процессе развертывания кластера. Теперь обсудим процесс создания таких
объектов.

Создание объекта ConfigMap
Как и другие объекты Kubernetes, объект ConfigMap можно создать импера-
тивным или декларативным способом. Иначе говоря, вы можете либо создать
пустой объект ConfigMap и затем добавить в него значения, либо задать на-
чальные значения непосредственно при его создании. Следующая команда
создает пустой объект ConfigMap с именем my-first-configmap императивным
способом:

 $ kubectl create configmap my-first-configmap
 configmap/my-first-configmap created
