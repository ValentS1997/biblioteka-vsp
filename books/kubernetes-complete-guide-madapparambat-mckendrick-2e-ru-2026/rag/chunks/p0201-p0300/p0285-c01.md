Причины для публикации подов     285

Назначение IP-адреса поду
Чтобы разобраться в том, что такое сервисы, нужно снова вернуться к подам.
В Kubernetes все строится вокруг подов: они запускают ваши приложения и об-
ладают особым свойством. При создании пода в кластере система Kubernetes
назначает ему приватный IP-адрес. Это крайне важно запомнить: каждый под
в вашем кластере получает уникальный IP-адрес, выделенный Kubernetes.
В качестве иллюстрации создадим под nginx. В этом примере используется
контейнерный образ nginx, однако результат будет тем же самым при исполь-
зовании любого другого образа.

Мы создадим под декларативным способом с помощью следующего YAML-
манифеста:

# new-nginx-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: new-nginx-pod
spec:
  containers:
    - image: nginx:1.17
      name: new-nginx-container
      ports:
        - containerPort: 80

Под new-nginx-pod не содержит ничего особенного: он просто запускает контей-
нер new-nginx-container на основе образа nginx:1.17.
После сохранения этого YAML-файла мы можем применить его с помощью
команды:

 $ kubectl apply -f new-nginx-pod.yaml
 pod/new-nginx-pod created

В результате ее выполнения в кластере появится под, которому Kubernetes на-
значит уникальный IP-адрес.

Чтобы просмотреть назначенный поду IP-адрес, мы используем команду
kubectl get pods с параметром -o wide, который выводит дополнительную ин-
формацию о поде:

 $ kubectl get po new-nginx-pod -o wide
 NAME           READY   STATUS    RESTARTS   AGE   IP            NODE
 NOMINATED NODE   READINESS GATES
 new-nginx-pod  1/1     Running   0          99s   10.244.0.109  minikube
 <none>           <none>
