226     Глава 6   •  Пространства имен, квоты и лимиты

Обратите внимание на параметр -n, полной формой которого является --namespace.
Он используется для указания имени пространства имен, в котором требуется
создать ресурс (или из которого нужно получить информацию). Этот параметр
поддерживается всеми видами ресурсов, область видимости которых может
быть ограничена пространством имен.

В качестве еще одного примера рассмотрим следующую команду для создания
configmap в пространстве имен custom-ns:

 $ kubectl create configmap configmap-custom-ns --from-literal=Lorem=Ipsum -n
 custom-ns
 configmap/configmap-custom-ns created

Пространство имен также можно указать при использовании декларативного
синтаксиса. Вот пример создания пода в конкретном пространстве имен декла-
ративным способом:

# pod-in-namespace.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx2
  namespace: custom-ns
spec:
  containers:
    - name: nginx
      image: nginx:latest

Обратите внимание на ключ namespace в разделе metadata, расположенный
сразу под именем пода. Он указывает на то, что под нужно создать в простран-
стве custom-ns. Теперь мы можем применить этот файл с помощью следующей
команды kubectl:

 $ kubectl apply -f pod-in-namespace.yaml
 pod/nginx2 created

На этом этапе у нас должно быть пространство custom-ns, содержащее два пода
nginx и один объект ConfigMap с именем configmap-custom-ns.

        При работе с пространствами имен всегда используйте флаг -n, чтобы указать
         нужное пространство. В противном случае есть риск выполнения операций
         не с тем пространством имен.

Теперь выведем список ресурсов, находящихся внутри конкретных пространств
имен.
