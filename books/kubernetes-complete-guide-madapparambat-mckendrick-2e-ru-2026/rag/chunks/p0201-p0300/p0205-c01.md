Совместное использование томов контейнерами одного пода     205

# multi-container-with-hostpath.yaml
---
apiVersion: v1
kind: Pod
metadata:
  name: multi-container-with-hostpath
spec:
  containers:
    - name: nginx-container
      image: nginx:latest
      volumeMounts:
      - mountPath: /foo
        name: my-host-path-volume
    - name: debian-container
      image: debian
      command: ["/bin/sh"]
      args: ["-c", "while true; do sleep 30; done"]  # Предотвращает завершение
                                                     # работы контейнера
  volumes:
    - name: my-host-path-volume
      hostPath:
        path: /tmp   # путь на рабочем узле
        type: Directory

Как видите, том hostPath монтируется так же, как и том emptyDir, рассмотрен-
ный ранее. Этот процесс состоит из двух этапов: объявления тома на уровне
пода и его подключения через volumeMounts на уровне контейнера.

        В предыдущем фрагменте YAML-манифеста мы использовали параметр type:
            Directory, который означает, что каталог уже существует на хостовой машине.
         Если вам требуется создать каталог или файл на хосте, используйте параметры
           DirectoryOrCreate и FileOrCreate соответственно.

Мы также можем смонтировать каталог в контейнер Debian, чтобы предоставить
ему доступ к данным, хранящимся на хостовой машине.

Перед запуском YAML-манифеста необходимо создать путь и сам файл на
хосте:

 $ echo "Hello World" >> /tmp/hello-world.txt

При использовании кластера minikube это действие нужно выполнить внутри
соответствующей виртуальной машины:

 $ minikube ssh
 docker@minikube:~$ echo "Hello World" > /tmp/hello-world.txt
 docker@minikube:~$ exit
 Logout
