296     Глава 8   •  Публикация подов с помощью сервисов

В выводе приведены следующие сведения:

z  Server: 10.96.0.10 — это IP-адрес сервиса kube-dns (kubectl get svc kube-dns
   -n kube-system -o wide). Если вы используете другой DNS-сервис, проверьте
   его параметры;
z  nginx.default.svc.cluster.local — DNS-запись, разрешающаяся в IP-адрес
   сервиса nginx (kubectl get svc nginx -o wide), например 10.106.124.xxx.

Теперь запустим команду curl, чтобы проверить возможность получения глав-
ной страницы nginx:

 $ kubectl exec -it k8sutils -- curl nginx.default.svc.cluster.local
 ... <фрагмент опущен для краткости>...
 <body>
 <h1>Welcome to nginx!</h1>
 <p>If you see this page, the nginx web server is successfully installed and
 working. Further configuration is required.</p>

 ... <фрагмент опущен для краткости>...

Как видите, нам удалось обратиться к сервису nginx с помощью отладочного
пода k8sutils, как показано на рис. 8.5.

   Рис. 8.5. Под k8sutils используется для отправки curl-запроса к сервису nginx,
               предоставляющему доступ к одноименному поду

Помните, что для отладки сервиса под k8sutils необходимо развернуть именно
внутри кластера, так как DNS-имя nginx.default.svc.cluster.local не явля-
ется публичным и доступно только в кластере.
