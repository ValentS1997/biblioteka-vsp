Причины для публикации подов     289

Фактически сервисы создаются в Kubernetes как отдельный тип ресурсов. Как
и большинство других объектов этой системы, их можно развернуть в кластере
либо с помощью интерактивных команд, либо декларативным способом с ис-
пользованием YAML-манифестов.

Как и в случае с другими ресурсами Kubernetes, при создании сервиса необхо-
димо присвоить ему имя. Это имя система использует для формирования DNS-
записи, к которой смогут обращаться все поды в кластере. Данная DNS-запись
будет указывать на ваш сервис, который должен оставаться внутри кластера.
От вас требуется лишь указать список подов, которые необходимо опублико-
вать через сервис. Как будет показано далее, это делается с помощью простой
конфигурации на основе меток и селекторов.

После завершения настройки доступ к подам можно будет получить путем
простого обращения к сервису, который принимает запросы и перенаправляет
их в поды.

Циклический алгоритм балансировки нагрузки
в Kubernetes
При условии корректной настройки сервисы Kubernetes могут предоставлять
доступ к одному или нескольким подам. Когда один сервис обслуживает не-
сколько подов, входящие запросы равномерно распределяются между ними
с помощью циклического алгоритма (round-robin), как показано на рис. 8.2.
