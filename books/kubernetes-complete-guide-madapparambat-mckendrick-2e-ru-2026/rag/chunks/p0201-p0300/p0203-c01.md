Как видите, команда ls /var выводит имя каталога в обоих контейнерах! Это
подтверждает, что том emptyDir был инициализирован и успешно смонтирован
в оба контейнера.

Теперь создадим файл в одном из контейнеров. Если этот файл мгновенно
станет видимым во втором контейнере, это подтвердит корректность монти-
рования тома.
Следующая команда создает текстовый файл hello-world.txt в смонтирован-
ном каталоге:

 $ kubectl exec multi-container-with-emptydir-pod \
   -c debian-container -- /bin/sh -c \
   "echo 'hello world' >> /var/i-am-empty-dir-volume/hello-world.txt"
 $ kubectl exec multi-container-with-emptydir-pod \
   -c nginx-container -- cat \
   /var/i-am-empty-dir-volume/hello-world.txt
 hello world
 $ kubectl exec multi-container-with-emptydir-pod \
   -c debian-container -- cat \
   /var/i-am-empty-dir-volume/hello-world.txt
 hello world

Здесь мы использовали контейнер debian-container для создания файла
/var/i-am-empty-dir-volume/hello-world.txt, содержащего строку hello-world.
Затем с помощью команды cat мы получили доступ к его содержимому из обоих
контейнеров и убедились в том, что файл доступен каждому из них. Напомним,
что тома emptyDir связаны с жизненным циклом пода. Если под будет удален, том
и все его данные также будут уничтожены и восстановить их будет невозможно.
Теперь рассмотрим другой тип тома — hostPath. Как подсказывает название, он
представляет собой каталог на хостовой машине (узле Kubernetes, на котором
запущен под), который можно смонтировать в контейнеры.
