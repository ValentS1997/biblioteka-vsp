Объекты ConfigMap и Secret     251

Вот несколько типичных примеров конфигурационных параметров, которые
следует отделять от кода приложения.

z Ключи API для доступа к хранилищу Amazon S3.
z Пароль от сервера MySQL, используемый приложением.
z Адрес конечной точки кластера Redis, используемый приложением.
z Заранее вычисленные значения, например закрытые ключи для подписи
   JWT-токенов.

Все эти значения, как правило, меняются в зависимости от среды. Прило-
жения, запускаемые в подах, должны иметь возможность загружать разные
конфигурации в зависимости от окружения, в котором они выполняются.
Поэтому мы стремимся систематически поддерживать границу между при-
ложениями и используемыми ими конфигурациями. Это позволяет нам рас-
сматривать их в качестве двух совершенно разных сущностей в кластере
Kubernetes.

Для хранения конфигурационных данных в этой системе предусмотрены
объекты ConfigMap и Secret, которые необходимо подключать при создании
подов.

        Не включайте конфигурационные параметры в контейнерные образы (напри-
          мер, в Docker-образы). Ваш файл Dockerfile (или Containerfile в случае Podman)
         должен собирать приложение, но не конфигурировать его. Задействуя конфи-
         гурацию контейнера на этапе сборки, вы создаете жесткую зависимость между
         приложением и его настройками, что снижает переносимость контейнера между
         разными средами.

Объект ConfigMap предназначен для хранения неконфиденциальных конфи-
гурационных параметров, а объект Secret, по сути, выполняет ту же роль, но
используется для хранения конфиденциальных данных, таких как пароли баз
данных, ключи API и т. п.

Таким образом, для каждой среды и для каждого приложения можно создать
собственные объекты ConfigMap и Secret, которые будут содержать параметры,
необходимые приложению для работы в конкретном контексте и окружении.
Важный момент заключается в том, что эти объекты служат механизмами хра-
нения данных конфигурации в формате пар «ключ — значение» внутри кластера
Kubernetes. Эти пары могут содержать как простые значения (литералы), так
и целые конфигурационные файлы, например, в формате YAML, TOML и т. д.
При создании пода можно указать имя объекта ConfigMap или Secret и связать
его с подом, чтобы сделать конфигурационные значения доступными контей-
нерам, работающим внутри него.
