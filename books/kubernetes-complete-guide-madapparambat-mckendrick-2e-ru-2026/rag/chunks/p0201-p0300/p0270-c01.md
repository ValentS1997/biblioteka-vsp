270     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Перечисление объектов Secret
Как и любые другие объекты Kubernetes, секреты можно перечислить с помощью
команды kubectl get. В данном случае идентификатором ресурса будет secret:

 $ kubectl get secret -A

В столбце DATA содержится количество конфиденциальных параметров, которые
были хешированы и сохранены в объекте Secret. При выполнении команды ути-
лита kubectl выводит список предустановленных объектов Secret или сообще-
ние о том, что они не найдены. Эта разница объясняется тем, что одни облачные
сервисы создают объекты Secret по умолчанию для внутренних процессов,
а другие — нет. Наличие или отсутствие таких предустановленных объектов
зависит от среды, в которой развернут кластер Kubernetes.

Создание объекта Secret императивным способом
Система Kubernetes позволяет создавать объекты Secret как императивным, так
и декларативным способом. Начнем с рассмотрения императивного подхода.
В этом примере мы сохраним пароль от базы данных my-db-password в объекте
Secret в нашем кластере. Это можно сделать с помощью команды kubectl create
secret с флагом --from-literal:

 $ kubectl create secret generic my-first-secret \
     --from-literal='db_password=my-db-password'

Теперь выведем список секретов в кластере, выполнив команду kubectl get
secrets. В выводе должен отобразиться новый объект Secret:

 $ kubectl get secrets
 NAME              TYPE     DATA   AGE
 my-first-secret   Opaque   1      37s

Выведем его содержимое в формате YAML:

 $ kubectl get secret my-first-secret -o yaml
 apiVersion: v1
 data:
   db_password: bXktZGItcGFzc3dvcmQ=
 kind: Secret
 metadata:
   creationTimestamp: "2024-08-10T13:13:32Z"
   name: my-first-secret
   namespace: default
   resourceVersion: "36719"
   uid: 7ccf5120-d1c5-4874-ba4b-894274fd27e6
 type: Opaque
