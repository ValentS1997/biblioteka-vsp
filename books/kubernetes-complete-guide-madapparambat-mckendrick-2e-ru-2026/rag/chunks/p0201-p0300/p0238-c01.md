238     Глава 6   •  Пространства имен, квоты и лимиты

В данном случае в нашем кластере Kubernetes используется примерно 800 МиБ
памяти и 180 миллиядер ЦП.

        При использовании minikube с драйвером Podman или Docker будут отобра-
        жены доступные ресурсы (ЦП и память) хостовой машины, а не узла кластера
          Kubernetes. В этом случае для использования ресурсов ВМ minikube рекомен-
          дуется развернуть дополнительный кластер с помощью драйвера VirtualBox:
          minikube start --profile cluster2-vb --driver=virtualbox.

Создадим новое пространство имен для демонстрации принципа работы с за-
просами и лимитами ресурсов:

 $ kubectl create ns quota-ns
 namespace/quota-ns created

Теперь создадим YAML-файл с нереалистичным запросом на выделение памя-
ти, например, в объеме 100 ГиБ:

# pod-with-request-and-limit-1.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-with-request-and-limit-1
  namespace: quota-ns
spec:
  containers:
    - name: nginx
      image: nginx:latest
      resources:
        requests:
          memory: "100Gi"
          cpu: "100m"
        limits:
          memory: "100Gi"
          cpu: "500m"

Создайте под с помощью команды kubectl apply:

 $ kubectl apply -f pod-with-request-and-limit-1.yaml
 pod/nginx-with-request-and-limit-1 created

Проверьте статус пода:

 $ kubectl get pod -n quota-ns
 NAME                             READY   STATUS    RESTARTS   AGE
 nginx-with-request-and-limit-1   0/1     Pending   0          45s
