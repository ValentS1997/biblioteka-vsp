286     Глава 8   •  Публикация подов с помощью сервисов

В этом примере под получил IP-адрес 10.244.0.109. Этот адрес уникален внутри
данного кластера Kubernetes и принадлежит только этому поду.

Если вы повторите эти шаги в своем кластере, то получите другой результат.
Этот IP-адрес является приватным адресом версии IPv4 и существует только
внутри кластера Kubernetes. То есть он недоступен во внешней сети Интернет,
поэтому если ввести его в браузере, страница не откроется.

Независимо от того, какую облачную платформу вы используете — Amazon Web
Services (AWS), Google Cloud Platform (GCP) или Azure, кластер Kubernetes задей-
ствует сетевой сегмент, предоставляемый облачным провайдером. Этот сегмент,
обычно называемый виртуальным частным облаком (VPC, virtual private cloud),
представляет собой приватную и изолированную сеть, аналогичную приватному
диапазону IP-адресов локальной сети частного дата-центра. Во всех случаях
CNI-плагин, используемый Kubernetes, гарантирует назначение уникального
IP-адреса каждому поду, обеспечивая их изоляцию. Это справедливо и для об-
лачных, и для локальных сред.

Далее вы узнаете о том, что назначение IP-адресов подам является динамиче-
ским процессом и может создавать проблемы при масштабировании.

Динамическое назначение IP-адресов подам
в Kubernetes
IP-адреса, назначаемые подам, не являются статичными. Если удалить под
и создать его заново, он получит совершенно другой IP-адрес, даже если для
создания используется тот же самый YAML-манифест. Чтобы продемонстри-
ровать это, удалим под и создадим его заново, используя тот же YAML-файл:

 $ kubectl delete -f new-nginx-pod.yaml
 pod "new-nginx-pod" deleted
 $ kubectl apply -f new-nginx-pod.yaml
 pod/new-nginx-pod created

Теперь снова выполним команду kubectl get pods -o wide, чтобы убедиться
в отличии нового IP-адреса от предыдущего:

 $ kubectl get po new-nginx-pod -o wide
 NAME            READY   STATUS    RESTARTS   AGE   IP            NODE
 NOMINATED NODE   READINESS GATES
 new-nginx-pod   1/1     Running   0          97s   10.244.0.110  minikube
 <none>           <none>

Как видите, адрес изменился с 10.244.0.109 на 10.244.0.110.
Итак, при удалении и повторном создании пода, даже с тем же именем и кон-
фигурацией, он получает новый IP-адрес.
