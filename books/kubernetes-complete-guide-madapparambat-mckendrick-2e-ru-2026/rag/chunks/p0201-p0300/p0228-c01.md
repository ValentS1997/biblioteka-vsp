228     Глава 6   •  Пространства имен, квоты и лимиты

Задание текущего пространства имен
с помощью kubectl config set-context
В некоторых случаях можно задать текущее пространство имен для работы.
Например, если в рамках проекта вы используете определенное пространство
имен для приложения и связанных с ним ресурсов, то можете указать его в ка-
честве текущего контекста:

 $ kubectl config set-context --current --namespace=custom-ns
 Context "minikube" modified.

Чтобы проверить, какое пространство имен задано в качестве контекста, можно
использовать команду:

 $ kubectl config view --minify --output 'jsonpath={..namespace}'
 custom-ns

Теперь можно получать информацию о приложении или применять конфигу-
рацию без указания параметра -n <пространство_имен>:

 $ kubectl get pods
 NAME     READY   STATUS    RESTARTS   AGE
 nginx    1/1     Running   0          79m
 nginx2   1/1     Running   0          71m

         Команда kubectl config и ее подкоманды выполняют только операции чтения или из-
         менения конфигурационного файла ~/.kube/config, используемого утилитой kubectl.
         Выполняя команду kubectl config set-context, вы фактически обновляете этот
         файл, задавая в нем другое пространство имен.

Умение переключаться между пространствами имен с помощью kubectl весьма
полезно, однако перед выполнением таких операций записи, как kubectl delete
или kubectl create, следует убедиться в том, что вы находитесь в правильном
пространстве. В противном случае рекомендуется продолжать использовать
параметр -n. Поскольку операция переключения контекста может выполняться
довольно часто, для упрощения работы пользователи Kubernetes обычно соз-
дают псевдонимы в Linux. Вы тоже можете определить такой псевдоним, если
считаете, что так вам будет удобнее.

Например, если вы используете Linux или macOS, то можете задать псевдоним
в файле ~/.bashrc следующим образом:

 alias kubens='kubectl config set-context --current --namespace'
