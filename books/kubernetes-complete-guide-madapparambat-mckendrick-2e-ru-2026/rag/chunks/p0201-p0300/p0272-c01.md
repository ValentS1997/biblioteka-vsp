272     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Чтобы убедиться в успешном создании секрета, выведите список соответству-
ющих объектов в кластере:

 $ kubectl get secret my-second-secret -o yaml
 apiVersion: v1
 kind: Secret
 metadata:
   name: my-second-secret
   namespace: default
 ... <фрагмент опущен для краткости>...
 data:
   db_password: bXktZGItcGFzc3dvcmQ=
 type: Opaque

Теперь создадим тот же секрет, но с использованием поля stringData, чтобы
не кодировать значение вручную. Новый YAML-файл будет выглядеть так:

# secret-from-file-stringData.yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-secret-stringdata
type: Opaque
stringData:
  db_password: my-db-password

Обратите внимание на то, что пароль записан в виде открытого текста, а не за-
кодированного значения.

Создадим объект Secret на основе этого файла:

 $ kubectl apply -f secret-from-file-stringData.yaml
 secret/my-secret-stringdata created

Выведите содержимое объекта Secret, чтобы просмотреть закодированные
данные:

 $ kubectl get secret my-secret-stringdata -o yaml
 apiVersion: v1
 kind: Secret
 metadata:
   name: my-secret-stringdata
   namespace: default
   resourceVersion: "37229"
   uid: 5078124b-7318-44df-a2da-a30ea5088e3f
 ... <фрагмент опущен для краткости>...
 data:
   db_password: bXktZGItcGFzc3dvcmQ=
 type: Opaque
