Управление конфиденциальной конфигурацией с помощью объекта Secret     273

Как видите, значение, указанное в поле stringData в виде открытого текста,
было автоматически закодировано и сохранено в разделе data.
В следующем подразделе вы научитесь создавать объекты Secret на основе зна-
чений из файла.

Создание объекта Secret
на основе содержимого файла
Как и в случае с ConfigMap, объект Secret можно создать на основе хранящихся
в файле значений. Начнем с создания файла, предназначенного для хранения
пароля, который нам предстоит импортировать в систему Kubernetes в качестве
секрета:

 $ echo -n 'mypassword' > ./password.txt

После выполнения этой команды у нас появится файл password.txt, содержа-
щий строку mypassword, которая и будет секретным значением. Флаг -n предот-
вращает появление в конце файла лишней пустой строки.

Далее выполним команду kubectl create secret, передав путь к файлу pass
word.txt через флаг --from-file. В результате будет создан новый объект Secret
со строкой mypassword, преобразованной в формат base64:

 $ kubectl create secret generic mypassword \
     --from-file=./password.txt
 secret/mypassword created

Теперь этот новый объект доступен в вашем кластере Kubernetes! Далее мы
обсудим способ чтения данных, содержащихся в объекте Secret.

Чтение значений, содержащихся в объекте Secret
Как мы уже отметили, объекты Secret предназначены для хранения конфиден-
циальных данных, и поэтому вывод утилиты kubectl не отображает их в рас-
шифрованном виде. Чтобы просмотреть секретное содержимое, вам необходимо
декодировать его самостоятельно. Такая конфиденциальность сохраняется для
того, чтобы:

z предотвратить случайное раскрытие секрета тем, кто не имеет соответству-
  ющих прав доступа;
z исключить отображение секрета в выводе терминала, который может быть
   записан в лог.
