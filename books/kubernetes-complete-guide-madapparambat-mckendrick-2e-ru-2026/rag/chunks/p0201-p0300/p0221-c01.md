Пространства имен в Kubernetes     221

z изоляция ресурсов;
z ограничение области видимости имен ресурсов;
z распределение и ограничение использования аппаратных ресурсов;
z управление правами доступа с помощью механизма RBAC (Role-Based
   Access Control — управление доступом на основе ролей).

Мы рекомендуем создавать отдельное пространство имен для каждого микро-
сервиса или приложения и развертывать в нем все связанные с ним ресурсы.
Однако учтите, что система Kubernetes не предусматривает жестких правил.
Пространства имен можно использовать и другими способами.

z  Разделение по средам — одно пространство можно использовать для рабочей
   среды, а другое — для среды разработки.
z  Разделение по уровням — одно пространство можно использовать для баз дан-
   ных, другое — для подов приложений, а третье — для промежуточного ПО.
z Использование пространства по умолчанию — для создания кластеров с не-
  большим количеством ресурсов можно использовать одно общее простран-
   ство по умолчанию, помещая в него все компоненты.

При этом важно помнить, что, даже если два пода развернуты в разных простран-
ствах имен и опубликованы через сервисы, они все равно могут взаимодейство-
вать и обмениваться данными. Хотя сервис Kubernetes создается в конкретном
пространстве имен, он получает полное доменное имя (FQDN), доступное во
всем кластере. Таким образом, если приложению из пространства A необходимо
взаимодействовать с приложением из пространства Б, оно будет обращаться
к сервису, публикующему приложение Б, по его FQDN. Взаимодействие между
пространствами имен разрешено по умолчанию и может контролироваться с по-
мощью сетевых политик.

Теперь перейдем к рассмотрению стандартных пространств имен.

Пространства имен по умолчанию
Большинство кластеров Kubernetes создаются с несколькими пространствами
имен по умолчанию. Просмотреть их можно с помощью команды kubectl get
namespaces (или ее сокращенной формы kubectl get ns), как показано ниже:

 $ kubectl get namespaces
 NAME              STATUS   AGE
 default           Active   8d
 kube-node-lease   Active   8d
 kube-public       Active   8d
 kube-system       Active   8d
