Настройка квот и лимитов на уровне пространства имен     245

потребить все доступные ресурсы. Объект LimitRange как раз и предотвращает
создание слишком маленьких или чрезмерно больших контейнеров в простран-
стве имен.

Ниже приведен YAML-файл для создания объекта LimitRange:
# limitrange.yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: my-limitrange
  namespace: quota-ns
spec:
  limits:
    - default:             # задает значение лимитов по умолчанию
        cpu: 500m
        memory: 256Mi
      defaultRequest:      # задает значение запросов по умолчанию
        cpu: 500m
        memory: 128Mi
      max:                 # значения max и min определяют диапазоны ограничений
        cpu: "1"
        memory: 1000Mi
      min:
        cpu: 100m
        memory: 128Mi
      type: Container

Как видите, YAML-файл для создания объекта LimitRange содержит четыре
ключевых раздела, в каждом из которых задается объем памяти и ресурсов ЦП.

z  default — задает лимиты памяти и ресурсов ЦП по умолчанию для контейне-
   ров, если они не указаны на уровне пода. Все контейнеры без явно заданных
   лимитов наследуют эти значения объекта LimitRange.
z  defaultRequest — задает запросы ресурсов ЦП и памяти по умолчанию. Если
   для контейнера в поде не указан параметр requests, то к нему автоматически
   применяются значения из этого раздела.
z  max — данное значение определяет максимальный лимит (не запрос), кото-
  рый может быть установлен для контейнера в поде. Нельзя настроить под
   со значением лимита, превышающим этот. Как и значение default, данный
  лимит не может превысить указанный здесь предел.
z  min — это значение аналогично max, но применяется к запросам (requests).
  Это минимальный объем ресурсов, который может запросить под; параметр
   defaultRequest не может быть ниже этого значения.

Учтите, что если ключи default и defaultRequest не заданы, то ключ max ис-
пользуется как значение по умолчанию для default, а ключ min — как значение
по умолчанию для defaultRequest.
