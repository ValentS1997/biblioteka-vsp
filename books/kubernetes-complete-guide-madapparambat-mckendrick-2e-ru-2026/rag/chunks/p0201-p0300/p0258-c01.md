258     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Сначала создадим файл configfile.txt с произвольным содержимым по адресу
$HOME/configfile.txt:

 $ echo "I'm just a dummy config file" >> $HOME/configfile.txt

Файл имеет расширение .txt, однако конфигурационные данные могут хра-
ниться в любом формате, поддерживаемом приложением, включая .yaml, .toml,
.rb и т. д.
Теперь необходимо импортировать этот файл в ConfigMap. Для этого создадим
новый объект с помощью флага --from-file, который можно комбинировать
с флагом --from-literal в одной команде:

 $ kubectl create cm my-sixth-configmap \
     --from-literal=color=yellow \
     --from-file=$HOME/configfile.txt
 configmap/my-sixth-configmap created

Выполнив команду kubectl get cm, мы можем убедиться, что объект my-sixth-
configmap успешно создан и содержит два значения:

 $ kubectl get cm my-sixth-configmap
 NAME                  DATA   AGE
 my-sixth-configmap    2      38s

Таким образом, объект my-sixth-configmap включает в себя два элемента дан-
ных: литеральное значение и файл.

Теперь создадим еще один объект ConfigMap, содержащий литерал и файл, но
на этот раз декларативным способом.

Формат YAML позволяет записывать многострочные значения с помощью
символа |. Мы воспользуемся этой возможностью при создании декларатив-
ного файла:

# my-seventh-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-seventh-configmap
data:
  color: "green"
  configfile.txt: |
    I'm another configuration file.

После создания файла применим его с помощью команды kubectl apply -f:

 $ kubectl apply -f my-seventh-configmap.yaml
 configmap/my-seventh-configmap created
