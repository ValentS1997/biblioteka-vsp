Влияние пространств имен на ресурсы и сервисы     229

А затем воспользоваться им:

 $ kubens custom-ns
 Context "minikube" modified.
 $ kubectl config view --minify --output 'jsonpath={..namespace}'
 custom-ns
 # Переключение на другое пространство имен
 $ kubens default
 Context "minikube" modified.
 $ kubectl config view --minify --output 'jsonpath={..namespace}'
 default

Тем не менее во избежание ошибок при выполнении операций в Kubernetes
настоятельно рекомендуется использовать параметр -n <пространство_имен>.
Прежде чем двигаться дальше, восстановим исходный контекст, выполнив
команду:

 $ kubectl config set-context --current --namespace=default
 Context "minikube" modified.

А теперь посмотрим, как можно перечислить все ресурсы, находящиеся внутри
конкретного пространства имен.

Перечисление ресурсов, находящихся
в конкретном пространстве имен
Для вывода списка всех ресурсов, находящихся в определенном пространстве
имен, можно воспользоваться командой kubectl get all -n custom-ns:

 $ kubectl get all -n custom-ns

Она перечисляет все ресурсы, созданные в пространстве имен, указанном с по-
мощью флага -n.

Область видимости и пространство имен
Еще одно преимущество пространств имен заключается в том, что они опреде-
ляют область видимости для имен ресурсов, которые в них находятся.

Возьмем, к примеру, имена подов. Если вы не указываете конкретное про-
странство имен, то взаимодействуете с пространством по умолчанию. В этом
случае при создании двух одноименных подов вы столкнетесь с ошибкой, так
как система Kubernetes использует имя пода в качестве его уникального иден-
тификатора.
