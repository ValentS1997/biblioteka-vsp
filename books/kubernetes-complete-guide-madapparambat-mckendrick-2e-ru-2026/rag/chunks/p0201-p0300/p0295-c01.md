Причины для публикации подов     295

виса является nginx. Поэтому нам нет необходимости использовать его полное
DNS-имя nginx.default.svc.cluster.local, назначенное Kubernetes.

При обращении к этому URL-адресу (Uniform Resource Locator — унифици-
рованный указатель ресурса) из любого пода в кластере1 вы должны получить
доступ к стартовой странице nginx.

Ниже показан YAML-файл, позволяющий создать отладочный под с образом
k8sutils:

# k8sutils.yaml
apiVersion: v1
kind: Pod
metadata:
  name: k8sutils
  namespace: default
spec:
  containers:
    - name: k8sutils
      image: quay.io/iamgini/k8sutils:debian12
      command:
        - sleep
        - "infinity"
  restartPolicy: Always

Выполним следующую команду для запуска пода k8sutils:

 $ kubectl apply -f k8sutils.yaml
 pod/k8sutils created

И удостоверимся в том, что под был успешно создан:

 $ kubectl get po k8sutils
 NAME       READY   STATUS    RESTARTS   AGE
 k8sutils   1/1     Running   0          13m

Отлично! Теперь выполним команду nslookup внутри пода k8sutils для про-
верки DNS-записи сервиса:

 $ kubectl exec -it k8sutils -- nslookup nginx.default.svc.cluster.local
 Server:         10.96.0.10
 Address:        10.96.0.10#53
 Name:  nginx.default.svc.cluster.local
 Address: 10.106.124.200

1  В пределах одного пространства имен.
