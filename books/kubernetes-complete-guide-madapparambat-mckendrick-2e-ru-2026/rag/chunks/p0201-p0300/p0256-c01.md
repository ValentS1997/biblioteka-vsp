256     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

В следующем примере мы создаем ConfigMap с именем my-third-configmap,
в котором ключу color присвоено значение blue:

 $ kubectl create cm my-third-configmap --from-literal=color=blue
 configmap/my-third-configmap created

Мы также можем создать ConfigMap сразу с несколькими параметрами, добавив
в команду нужное количество флагов --from-literal и значений:

 $ kubectl create cm my-fourth-configmap \
     --from-literal=color=blue \
     --from-literal=version=1 \
     --from-literal=environment=prod
 configmap/my-fourth-configmap created

В данном примере создается объект ConfigMap, содержащий три конфигураци-
онных параметра. Теперь, если вы выполните команду kubectl get cm, увидите
в списке вновь созданные объекты.
Обратите внимание, что в столбце DATA теперь отражается количество конфи-
гурационных значений, содержащихся в каждом объекте ConfigMap:

 $ kubectl get cm
 NAME                  DATA   AGE
 my-first-configmap    0      9m30s
 my-fourth-configmap   3      6m23s
 my-second-configmap   0      8m2s
 my-third-configmap    1      7m9s

Чтобы просмотреть подробные сведения о ConfigMap (или любом другом объ-
екте), их можно вывести в удобном для восприятия формате YAML или JSON:

 $ kubectl get cm my-fourth-configmap -o yaml
 apiVersion: v1
 data:
   color: blue
   environment: prod
   version: "1"
 kind: ConfigMap
 metadata:
   creationTimestamp: "2024-08-10T06:20:49Z"
   name: my-fourth-configmap
   namespace: default
   resourceVersion: "25647"
   uid: 3c8477dc-f3fe-4d69-b66a-403679a88450

Данный подход также упрощает резервное копирование объектов в формате YAML
или JSON, что соответствует лучшим практикам CaC (Configuration as Code —
конфигурация как код) и IaC (Infrastructure as Code — инфраструктура как код).
