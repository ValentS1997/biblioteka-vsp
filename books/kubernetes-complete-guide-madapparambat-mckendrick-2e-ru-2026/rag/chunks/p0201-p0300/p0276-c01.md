276     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

Создадим под с помощью команды kubectl apply -f:

 $ kubectl apply -f flask-pod-with-secret.yaml

Теперь выполним команду env внутри контейнера, чтобы вывести список пере-
менных окружения:

 $ kubectl exec pod/flask-pod-with-secret -- env
 PATH=/usr/local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
 HOSTNAME=flask-pod-with-secret
 PASSWORD_ENV_VAR=my-db-password
 KUBERNETES_SERVICE_PORT=443
 ... <фрагмент опущен для краткости>...

Как видите, строка my-db-password доступна в качестве переменной окружения
PASSWORD_ENV_VAR.

Альтернативный способ получения значений из объекта Secret сводится к ис-
пользованию ключа envFrom в YAML-манифесте. В этом случае в под будут
внедрены все значения из объекта Secret в качестве переменных окружения.
Этот механизм работает так же, как и в случае с ConfigMap.

         Чтобы под успешно запустился, объект Secret, на который он ссылается, дол-
        жен существовать, если только в определении пода явно не указано, что он
          является необязательным. Убедитесь в существовании объекта Secret перед
         развертыванием подов, которые от него зависят.

Сначала создадим объект Secret с помощью YAML-файла:

# secret-from-file-database.yaml
apiVersion: v1
kind: Secret
metadata:
  name: appdb-secret
type: Opaque
stringData:
  db_user: appadmin
  db_password: appdbpassword

Обратите внимание на пароль в открытом виде, а не в закодированном.

Создайте Secret из файла следующим образом:

 $ kubectl apply -f secret-from-file-database.yaml
 secret/appdb-secret created
