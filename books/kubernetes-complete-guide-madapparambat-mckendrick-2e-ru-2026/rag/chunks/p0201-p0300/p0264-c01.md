264     Глава 7   •  Настройка подов с помощью объектов ConfigMap и Secret

приведен обновленный YAML-манифест с описанием пода. Теперь в специфи-
кации контейнера вместо отдельных ключей env используется ключ envFrom:

# flask-pod-with-configmap-all.yaml
apiVersion: v1
kind: Pod
metadata:
  name: flask-pod-with-configmap-all
spec:
  containers:
    - name: flask-with-configmap
      image: quay.io/iamgini/my-flask-app:1.0
      envFrom:
        - configMapRef:
            name: my-fourth-configmap

После подготовки манифеста создадим под для Flask-приложения:

 $ kubectl apply -f flask-pod-with-configmap-all.yaml
 pod/flask-pod-with-configmap-all created

Теперь снова выполним команду env внутри Flask-контейнера с помощью
kubectl exec, чтобы отобразить все переменные окружения:

 $ kubectl exec pod/flask-pod-with-configmap-all -- env
 PATH=/usr/local/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
 HOSTNAME=flask-pod-with-configmap-all
 environment=prod
 version=1
 color=blue
 KUBERNETES_PORT_443_TCP_PORT=443
 KUBERNETES_PORT_443_TCP_ADDR=10.96.0.1
 ... <фрагмент опущен для краткости>...

Как видите, три параметра (color, version и environment), объявленные в объ-
екте my-fourth-configmap, были установлены в контейнере в качестве перемен-
ных окружения. Только теперь вы не контролируете их имена, поскольку они
наследуются от названий ключей в ConfigMap.
Далее мы обсудим способ монтирования объекта ConfigMap в контейнер в виде
тома.

Монтирование объекта ConfigMap в виде тома
Ранее в этой главе мы создали два объекта ConfigMap с фиктивными конфи-
гурационными файлами. Утилита kubectl позволяет смонтировать ConfigMap
в под в качестве тома. Это особенно полезно, если вам необходимо внедрить
в файловую систему контейнера содержимое файла, хранящегося в ConfigMap.
