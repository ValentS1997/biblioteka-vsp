202     Глава 5   •  Использование многоконтейнерных подов

      volumeMounts:
        - mountPath: /var/i-am-empty-dir-volume
          name: empty-dir-volume
    - name: debian-container
      image: debian
      command: ["/bin/sh"]
      args: ["-c", "while true; do sleep 30; done;"]  # Предотвращает завершение
                                                      # работы контейнера
      volumeMounts:
      - mountPath: /var/i-am-empty-dir-volume
        name: empty-dir-volume
  volumes:
  - name: empty-dir-volume # имя тома
    emptyDir: {}           # создает временный каталог на узле,
                           # общий для всех контейнеров пода

По мере продвижения наш кластер Kubernetes будет усложняться. Как вы
понимаете, большинство сложных сценариев невозможно реализовать с по-
мощью одних лишь императивных команд. Мы все чаще будем использовать
YAML-манифесты, поэтому вам стоит научиться их читать и разбираться в их
содержимом.
Применим приведенный выше манифест с помощью команды kubectl apply -f:

 $ kubectl apply -f multi-container-with-emptydir-pod.yaml
 pod/multi-container-with-emptydir-pod created

А теперь проверим результат запуска пода, выполнив команду kubectl get Pods:

 $ kubectl get po
 NAME                                READY   STATUS    RESTARTS   AGE
 multi-container-with-emptydir-pod   2/2     Running   0          25s

Убедившись, что под работает, а контейнеры Nginx и Debian запущены, мы
можем проверить доступность общего каталога для обоих контейнеров с по-
мощью команды ls.
Эту команду можно выполнить внутри контейнеров через команду kubectl exec,
которая, как вы помните, принимает в качестве аргументов имя пода и имя кон-
тейнера. Мы запустим ее дважды, чтобы убедиться, что наш том смонтирован
в оба контейнера:

 $ kubectl exec multi-container-with-emptydir-pod -c debian-container -- ls /var
 backups
 cache
 i-am-empty-dir-volume
 lib
 local
 lock
 log
 mail
