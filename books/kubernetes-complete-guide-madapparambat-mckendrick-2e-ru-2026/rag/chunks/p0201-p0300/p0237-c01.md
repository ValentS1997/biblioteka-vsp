Настройка квот и лимитов на уровне пространства имен     237

так же, как ресурсы ЦП, а система Kubernetes должна обеспечивать стабиль-
ность работы остальных приложений. Поэтому это важно учитывать.

Без задания лимитов под может потребить все ресурсы вычислительного узла.
Ниже приведен обновленный YAML-файл для пода nginx, в который были до-
бавлены ограничения на использование памяти и ресурсов ЦП.

Данный под сможет потреблять до 1 ГиБ памяти и до одного полного процес-
сорного ядра вычислительного узла:

# pod-in-namespace-with-request-and-limit.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-with-request-and-limit
  namespace: quota-ns
spec:
  containers:
    - name: nginx
      image: nginx:latest
      resources:
        requests:
          memory: "512Mi"
          cpu: "250m"
        limits:
          memory: "1Gi"
          cpu: "1000m"

Таким образом, при задании запроса всегда следует указывать и лимит. В сле-
дующем примере мы сделаем и то и другое.

Для начала проверим доступность системных ресурсов. Поскольку для демон-
страции используется кластер minikube, активизируем компонент metrics-
server для сбора подробной информации о потреблении ресурсов. Подробнее
об использовании метрик мы поговорим в главе 10.

 $ minikube addons enable metrics-server

Дождитесь перехода подов сервера метрик в состояние Running, прежде чем
продолжить:

 $ kubectl get po -n kube-system | grep metrics
 metrics-server-7c66d45ddc-82ngt   1/1     Running   0   113m

Теперь выведите информацию об использовании ресурсов кластера:

 $ kubectl top node
 NAME       CPU(cores)   CPU%   MEMORY(bytes)   MEMORY%
 minikube   181m         1%     806Mi           2%
