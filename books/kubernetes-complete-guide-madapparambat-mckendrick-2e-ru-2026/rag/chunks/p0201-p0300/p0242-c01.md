242     Глава 6   •  Пространства имен, квоты и лимиты

Для создания объекта ResourceQuota достаточно применить YAML-конфигу
рацию:

 $ kubectl apply -f resourcequota.yaml
 resourcequota/resourcequota created

 $ kubectl get quota -n quota-ns
 NAME           AGE   REQUEST                                          LIMIT
 resourcequota  4s    requests.cpu: 100m/1, requests.memory: 1Gi/1Gi   limits.
 cpu: 500m/2, limits.memory: 2Gi/2Gi

Теперь проверим ресурсы, доступные в пространстве имен quota-ns:

 $ kubectl get po -n quota-ns
 NAME                           READY   STATUS    RESTARTS         AGE
 nginx-with-request-and-limit-2 1/1     Running   1 (5h41m ago)    7h18m

 $ kubectl top pod -n quota-ns
 NAME                           CPU(cores)   MEMORY
 nginx-with-request-and-limit-2 50m          120Mi

Если вы не удалили предыдущий демонстрационный под, то в пространстве бу-
дет находиться под nginx, а уровень потребления ресурсов будет очень низким.
Теперь у нас есть новый YAML-файл пода, в котором мы запрашиваем 3 ГиБ
памяти:

# pod-with-request-and-limit-3.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-with-request-and-limit-3
  namespace: quota-ns
spec:
  containers:
    - name: nginx
      image: nginx:latest
      resources:
        requests:
          memory: "3Gi"
          cpu: "100m"
        limits:
          memory: "4Gi"
          cpu: "500m"

Создадим этот под и посмотрим на результат:

 $ kubectl apply -f pod-with-request-and-limit-3.yaml
 Error from server (Forbidden): error when creating "pod-with-request-andlimit-3.
 yaml": pods "nginx-with-request-and-limit-3" is forbidden: exceeded quota:
 resourcequota, requested: limits.memory=4Gi,requests.memory=3Gi, used: limits.
 memory=2Gi,requests.memory=1Gi, limited: limits.memory=2Gi,requests.memory=1Gi
