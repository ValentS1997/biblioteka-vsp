Управление конфиденциальной конфигурацией с помощью объекта Secret     271

В выводе будет присутствовать строка bXktZGItcGFzc3dvcmQ=, содержащая па-
роль в закодированном виде.
Далее мы обсудим декларативный способ создания объекта Secret.

Создание объекта Secret декларативным способом
Секреты также можно создавать декларативно с помощью YAML-файлов. Хотя
значения для поля data можно вручную закодировать в формат base64, система
Kubernetes предусматривает более удобный способ. Поле stringData позво-
ляет указать секретные значения в виде обычных текстовых строк, которые
Kubernetes автоматически преобразует в формат base64 при создании объекта
Secret. Этот метод упрощает рабочий процесс и предотвращает случайное
раскрытие конфиденциальных данных, содержащихся в конфигурационных
файлах с открытым текстом.

         Преобразование данных в формат base64 обеспечивает лишь базовую обфу-
         скацию и не является надежным методом шифрования. Для обеспечения до-
         полнительной защиты рекомендуется использовать плагины KMS или внешние
         системы управления секретами.

При использовании флага --from-literal система Kubernetes сама преобра-
зует строки в формат base64. Однако при создании секрета на основе YAML-
манифеста этот шаг придется выполнить вам.
Для начала преобразуем строку my-db-password в формат base64:

 $ echo -n 'my-db-password' | base64
 bXktZGItcGFzc3dvcmQ=

Поскольку bXktZGItcGFzc3dvcmQ= — это представление строки my-db-password
в кодировке base64, именно это значение следует записать в YAML-файл. Вот
как выглядит содержимое файла, предназначенного для создания объекта Secret:

# secret-from-file.yaml
apiVersion: v1
kind: Secret
metadata:
  name: my-second-secret
type: Opaque
data:
    db_password: bXktZGItcGFzc3dvcmQ=

После сохранения этого файла в системе мы можем создать секрет с помощью
команды kubectl apply -f:

 $ kubectl apply -f secret-from-file.yaml
