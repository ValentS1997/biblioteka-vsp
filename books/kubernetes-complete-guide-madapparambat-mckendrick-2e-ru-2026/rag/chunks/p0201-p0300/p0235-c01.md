Настройка квот и лимитов на уровне пространства имен     235

Как поды могут запрашивать вычислительные ресурсы
Запросы и лимиты задаются в YAML-файле с определением пода. Кроме того,
их можно применить и к работающему развертыванию с помощью команды
kubectl set resource. В этом подразделе мы сосредоточимся на запросах.
Запрос определяет минимальное количество вычислительных ресурсов, кото-
рое необходимо поду для корректной работы. Хорошей практикой считается
задание параметра requests для подов, особенно для тех, которые запускаются
в рабочей среде.
Предположим, вы хотите запустить под nginx в кластере Kubernetes. Заполнив
поле requests, вы можете сообщить системе, что для корректной работы этому
поду потребуется как минимум 512 МиБ памяти и 25 % ресурсов одного про-
цессорного ядра.

Ниже приведен YAML-файл для создания такого пода:
# pod-in-namespace-with-request.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-with-request
  namespace: custom-ns
spec:
  containers:
    - name: nginx
      image: nginx:latest
      resources:
        requests:
          memory: "512Mi"
          cpu: "250m"

Как видите, запросы можно делать на уровне контейнеров, задавая разные зна-
чения для каждого из них.

В данном случае под:
z  создается в пространстве имен custom-ns;
z  требует 512 Mi памяти;
z  требует 250m, то есть 1/4 процессорного ядра.

Что означают эти метрики
Объем памяти выражается в байтах (один МиБ равен 1 048 576 байтам), а объем
ресурсов ЦП — в миллиядрах и может задаваться дробными значениями. Если
вы хотите, чтобы под потреблял ресурсы всего процессорного ядра, задайте для
ключа cpu значение 1000m. Два ядра соответствуют 2000m, половина ядра — 500m,
