Сервис типа NodePort     299

Теперь подробно рассмотрим первый тип сервисов — NodePort.
Как уже упоминалось, такой сервис особенно полезен для предоставления до-
ступа к подам извне кластера в средах разработки, так как он привязывает поды
к портам узлов Kubernetes.

Сервис типа NodePort
NodePort — это тип сервиса Kubernetes, делающий поды доступными через порт
хост-машины (рабочего узла). В этом разделе мы сосредоточимся исключитель-
но на сервисах этого типа.

Назначение сервисов типа NodePort
Прежде всего важно понимать, что сервисы NodePort позволяют обращаться
к поду, работающему на узле Kubernetes, через порт самого узла. После пу-
бликации подов с помощью сервиса типа NodePort доступ к ним можно будет
получить по схеме <ip-адрес_узла>:<порт_узла>.
Порт может быть явно указан в YAML-манифесте или назначен автоматически
системой Kubernetes. Проиллюстрируем это на конкретном примере.
Чаще всего сервисы NodePort используются в качестве входной точки в кластер
Kubernetes. В следующем примере мы создадим два пода на основе контейнер-
ного образа containous/whoami, доступного в реестре Docker Hub и выводящего
имя хоста контейнера.

Мы создадим два пода, чтобы получить два контейнера с разными именами
хостов, а затем опубликуем их с помощью сервиса типа NodePort.

Создание двух подов
на основе образа containous/whoami
Начнем с создания двух подов с одной или несколькими метками. Эти метки
позволят сервису «понять», к каким подам он должен предоставить доступ.

Нам также нужно открыть порт на стороне пода. Само по себе это не сделает
под доступным извне, но позволит сервису обращаться к этому порту. Код для
решения этой задачи приведен ниже:

 $ kubectl run whoami1 --image=containous/whoami --port 80 --labels="app=whoami"
 pod/whoami1 created
 $ kubectl run whoami2 --image=containous/whoami --port 80 --labels="app=whoami"
 pod/whoami2 created
