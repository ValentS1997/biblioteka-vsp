300     Глава 8   •  Публикация подов с помощью сервисов

Теперь выполним команду kubectl get pods, чтобы убедиться в успешном запуске
обоих подов. Для отображения меток можно добавить параметр --show-labels:

 $ kubectl get pods --show-labels
 NAME      READY   STATUS    RESTARTS   AGE     LABELS
 whoami1   1/1     Running   0          3m5s    app=whoami
 whoami2   1/1     Running   0          3m      app=whoami

Как видите, все в порядке. Теперь у нас есть два пода с назначенной меткой
и мы можем опубликовать их с помощью сервиса типа NodePort. Далее мы рас-
смотрим YAML-манифест для создания такого сервиса.

YAML-манифест для создания сервиса NodePort
Поскольку сервисы являются достаточно сложными объектами, их лучше соз-
давать с помощью YAML-манифеста, а не команд.
Ниже приведен YAML-файл для публикации подов whoami1 и whoami2 с по
мощью сервиса типа NodePort:

# nodeport-whoami.yaml
apiVersion: v1
kind: Service
metadata:
  name: nodeport-whoami
spec:
  type: NodePort
  selector:
    app: whoami
  ports:
    - nodePort: 30001
      port: 80
      targetPort: 80

На первый взгляд этот YAML-манифест может показаться непростым, так как
он ссылается на три разных порта и содержит блок selector.
Прежде чем подробно его разбирать, применим манифест и удостоверимся
в создании сервиса:

 $ kubectl apply -f nodeport-whoami.yaml
 service/nodeport-whoami created

 $ kubectl get service nodeport-whoami
 NAME              TYPE       CLUSTER-IP     EXTERNAL-IP   PORT(S)        AGE
 nodeport-whoami   NodePort   10.98.160.98   <none>        80:30001/TCP   14s

Вывод команды kubectl get services подтверждает, что сервис был успешно создан.
Блок selector имеет ключевое значение для сервисов NodePort. Он выполняет
фильтрацию по меткам, определяя поды, к которым сервис будет открывать
