206     Глава 5   •  Использование многоконтейнерных подов

Если кластер minikube создан с использованием контейнеров Podman (на-
пример, с помощью команды minikube start --profile cluster2-podman
--driver=podman), нужно войти в под minikube и создать файл там:

 $ sudo podman exec -it minikube /bin/bash
 root@minikube:/# cat /tmp/hello-world.txt

После создания пути на хосте можно применить YAML-манифест к кластеру
Kubernetes, а затем выполнить команду kubectl get pod, чтобы убедиться в том,
что под был успешно создан:

 $ kubectl apply -f multi-container-with-hostpath.yaml
 pod/multi-container-with-hostpath created
 $ kubectl get pod
 NAME                             READY   STATUS    RESTARTS   AGE
 multi-container-with-hostpath    2/2     Running   0          11s

Кажется, все в порядке! Теперь выведем содержимое файла, который должен
быть смонтирован по пути /foo/hello-world.txt:

 $ kubectl exec multi-container-with-hostpath -c nginx-container -- cat /foo/
 hello-world.txt
 Hello World

Как видите, локальный файл (на узле Kubernetes) стал доступен внутри кон-
тейнера благодаря монтированию тома hostPath.
В начале этой главы мы рассмотрели основы работы с многоконтейнерными по-
дами: как создавать, обновлять и удалять такие поды, использовать контейнеры
инициализации, просматривать логи, переопределять команды контейнеров
непосредственно в конфигурации пода, а также организовывать совместное
использование каталогов несколькими контейнерами с помощью двух базовых
типов томов.

Далее обсудим несколько паттернов проектирования, которые можно исполь-
зовать при создании многоконтейнерных подов.

Паттерн проектирования Ambassador
При проектировании многоконтейнерного пода можно опираться на архитек-
турные принципы, помогающие решать типовые задачи. Одним из таких прин-
ципов является использование паттерна Ambassador (Посредник).

В этом разделе мы разберем суть этого паттерна, обсудим способ создания
контейнера-посредника в подах Kubernetes и рассмотрим конкретный пример
его применения.
