134     Глава 3   •  Установка первого кластера Kubernetes

Судя по всему, кластер kind работает как надо.
Как и в случае с minikube, вы можете проверить состояние компонентов управ-
ляющего слоя с помощью следующей команды:

 $ kubectl cluster-info
 Kubernetes control plane is running at https://127.0.0.1:42547
 CoreDNS is running at https://127.0.0.1:42547/api/v1/namespaces/kube-system/
 services/kube-dns:dns/proxy

Для дополнительной отладки и диагностики проблем в кластере используйте
команду kubectl cluster-info dump:

 $ kubectl get --raw='/readyz?verbose'
 [+]ping ok
 [+]log ok
 [+]etcd ok
 ... <фрагмент опущен для краткости>...
 [+]poststarthook/apiservice-openapiv3-controller ok
 [+]shutdown ok
 readyz check passed

В следующем подразделе мы рассмотрим способы остановки и удаления кла-
стеров Kubernetes, созданных с помощью инструмента kind.

Остановка и удаление локального кластера kind
Иногда вам может потребоваться остановить или удалить все, что было создано
в вашей локальной системе с помощью инструмента kind. Для этого можно ис-
пользовать следующую команду:

 $ kind stop

Эта команда остановит контейнеры Docker, управляемые инструментом kind.
Того же результата можно добиться, применив команду Docker stop к этим
контейнерам вручную. В этом случае контейнеры будут остановлены, но состо-
яние кластера сохранится. Это означает, что кластер не будет уничтожен и при
повторном запуске вернется в то состояние, в котором находился до остановки.

Чтобы полностью удалить кластер из системы, используйте следующую коман-
ду. После ее выполнения кластер и его состояние будут удалены из системы без
возможности восстановления:

 $ kind delete cluster
 Deleting cluster "kind" ...
