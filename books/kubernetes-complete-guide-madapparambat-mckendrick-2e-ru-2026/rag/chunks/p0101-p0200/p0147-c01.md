Понятие пода     147

Благодаря этим возможностям Kubernetes развернуть блог WordPress оказыва-
ется очень просто. Для этого достаточно создать под, который будет запускать
два контейнера — Nginx и PHP-FPM. Поскольку они могут взаимодействовать
друг с другом через локальный хост, настройка обмена данными между ними
не составляет труда. Затем с помощью тома мы можем предоставить обоим
контейнерам доступ к коду WordPress.
Наиболее сложные приложения неизбежно требуют использования нескольких
контейнеров, которые имеет смысл сгруппировать в один под, чтобы система
Kubernetes запускала их вместе. Помните о том, что под призван упростить
межконтейнерное (или межпроцессное) взаимодействие в условиях масштаб-
ной рабочей среды.

         Тем не менее под нередко состоит всего из одного контейнера. Так или иначе,
         под представляет собой самый низкий уровень абстракции, предоставляемый
          API Kubernetes, и именно с ним вам предстоит взаимодействовать.

Наконец, учтите, что контейнер, запущенный вручную на машине, входящей
в кластер Kubernetes, не будет рассматриваться системой как управляемый ею
контейнер. Такой контейнер становится «осиротевшим», то есть находящимся
вне зоны контроля оркестратора. Система Kubernetes управляет только теми
контейнерами, которые она сама запустила через API подов.

Каждый под получает IP-адрес
Контейнеры внутри одного пода могут обмениваться данными через локаль-
ный хост, но и поды способны взаимодействовать друг с другом. При запуске
каждому поду назначается частный IP-адрес. Каждый под может связываться
с любым другим подом в кластере, используя его IP-адрес.
Система Kubernetes использует модель плоской сети, реализованную с помо-
щью компонента CNI (Container Network Interface, сетевой интерфейс контей-
нера). CNI выступает в качестве стандартизированного моста между контейне-
ризованными приложениями и сетевой инфраструктурой, лежащей в основе
кластеров Kubernetes. Это устраняет необходимость в создании отдельной
сетевой конфигурации для каждого контейнера и упрощает процесс коммуни-
кации и передачи данных.
Компонент CNI построен на основе гибкой архитектуры с плагинами. Эти пла-
гины, написанные на разных языках программирования, взаимодействуют со
средой выполнения контейнеров через стандартные механизмы ввода-вывода.
Спецификация плагинов определяет четкий интерфейс для настройки сети,
выделения IP-адресов и поддержания соединений между узлами. Среда вы-
полнения контейнеров вызывает эти плагины, что обеспечивает динамическое
