Установка кластера Kubernetes с помощью minikube     125

Используйте следующую команду, чтобы отобразить текущий файл kubeconfig.
Вы увидите кластер с именем minikube, который указывает на локальный
IP-адрес:

 $ kubectl config view

Затем выполните следующую команду, чтобы увидеть кластер Kubernetes, на
работу с которым настроена ваша утилита kubectl:

 $ kubectl config current-context
 minikube

Теперь попробуем выполнить настоящую команду kubectl, чтобы вывести спи-
сок узлов, входящих в кластер minikube. Если все пройдет успешно, эта команда
обратится к компоненту kube-apiserver, запущенному инструментом minikube,
и возвратит единственный узел, поскольку по умолчанию minikube создает одно-
узловой кластер. Список узлов можно получить с помощью следующей команды:

 $ kubectl get nodes
 NAME       STATUS   ROLES           AGE     VERSION
 minikube   Ready    control-plane   3m52s   v1.29.0

Если при выполнении этой команды вы не увидите сообщений об ошибках,
значит, ваш кластер minikube готов к работе и функционирует корректно!
Итак, вы выполнили свою первую настоящую команду kubectl. В данном слу-
чае реальный компонент kube-apiserver получил ваш API-запрос и прислал
HTTP-ответ с данными из реального хранилища etcd. В нашем примере это
был список узлов кластера.

          Поскольку minikube по умолчанию создает одноузловой кластер Kubernetes, эта
         команда возвратит данные только об одном узле, который одновременно является
         и управляющим, и вычислительным. Такая конфигурация подходит для локаль-
          ного тестирования, но не рекомендуется для развертывания в рабочей среде.

Теперь посмотрим статусы компонентов управляющего слоя, чтобы лучше по-
знакомиться с утилитой kubectl:

 $ kubectl get componentstatuses
 Warning: v1 ComponentStatus is deprecated in v1.19+
 NAME                 STATUS    MESSAGE   ERROR
 controller-manager   Healthy   ok
 scheduler            Healthy   ok
 etcd-0               Healthy   ok
