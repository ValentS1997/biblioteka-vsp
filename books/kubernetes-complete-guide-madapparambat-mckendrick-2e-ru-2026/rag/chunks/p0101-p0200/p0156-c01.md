156     Глава 4   •  Запуск контейнеров в Kubernetes

         Существуют инструменты, позволяющие получить «чистый» YAML-файл, при-
         годный для использования в качестве декларации. Например, для удаления
        лишней информации можно использовать утилиту kube-neat. Подробнее о ней
        можно узнать здесь: https://github.com/itaysk/kubectl-neat.

Если что-то пойдет не так, вы сможете без труда воссоздать свой под. Обра
тите внимание на фрагмент команды с nginx-pod: чтобы получить YAML-
декларацию, необходимо явно указать целевой ресурс. Перенаправление вывода
этой команды в файл позволяет извлекать и сохранять конфигурацию объекта,
входящего в состав кластера Kubernetes.

Получение дополнительных сведений
с помощью операции перечисления
Нам также стоит упомянуть весьма полезный параметр -o wide, который рас-
ширяет стандартный вывод, включая в него дополнительные данные. Например,
при применении этого параметра к объекту pods вы получите имя рабочего узла,
на котором запущен данный под:

 $ kubectl get pods -o wide
 NAME       READY   STATUS    RESTARTS   AGE   IP          NODE      NOMINATED
 NODE   READINESS GATES
 nginx-pod  1/1     Running   0          15m   10.244.0.4  minikube  <none>
 <none>

Учтите, что параметр -o принимает множество различных аргументов, в том
числе весьма продвинутых. Например, jsonpath позволяет выполнять сорти-
ровку и выборку прямо из JSON-документа, благодаря чему можно извлечь
только нужную информацию. Это похоже на работу с библиотекой jq, которая
используется в Bash-сценариях для обработки данных JSON.

Получение доступа к поду из внешнего мира
К этому моменту в вашем кластере Kubernetes уже должен быть запущен под
с HTTP-сервером Nginx. Теперь вам нужно получить к нему доступ из браузера.
Однако сделать это не так просто.
По умолчанию кластер Kubernetes не позволяет получать доступ к подам извне.
Для этого используется отдельный ресурс — Service (сервис), о котором мы
подробно поговорим в главе 8. Тем не менее утилита kubectl предусматривает
команду kubectl port-forward для быстрого доступа к запущенному в кластере
контейнеру. Вот как ее можно использовать:

 $ kubectl port-forward pod/nginx-pod 8080:80
 Forwarding from 127.0.0.1:8080 -> 80
 Forwarding from [::1]:8080 -> 80
