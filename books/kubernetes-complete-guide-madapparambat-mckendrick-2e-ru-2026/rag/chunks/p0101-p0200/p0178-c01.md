178     Глава 4   •  Запуск контейнеров в Kubernetes

После этого вновь созданный объект CronJob будет запускать под по расписа-
нию, указанному в YAML-файле, — в данном случае каждую минуту:

 $ kubectl get cronjobs

 hello-world-cronjob  */1 * * * *  <none>   False    0       37s            11m

 $ kubectl get jobs
 NAME                           COMPLETIONS   DURATION   AGE
 hello-world-cronjob-28390196   1/1           3s         4m47s
 hello-world-cronjob-28390197   1/1           3s         3m47s
 hello-world-cronjob-28390198   1/1           3s         2m47s
 hello-world-cronjob-28390199   1/1           3s         107s
 hello-world-cronjob-28390200   1/1           4s         47s

 $ kubectl get pods
 NAME                                 READY   STATUS      RESTARTS   AGE
 hello-world-cronjob-28390196-fpmc6   0/1     Completed   0          4m52s
 hello-world-cronjob-28390197-vkzw2   0/1     Completed   0          3m52s
 hello-world-cronjob-28390198-tj6qv   0/1     Completed   0          2m52s
 hello-world-cronjob-28390199-dd666   0/1     Completed   0          112s
 hello-world-cronjob-28390200-kn89r   0/1     Completed   0          52s

Поскольку мы задали значение successfulJobsHistoryLimit: 5, нам будут видны
только последние пять заданий или запущенных подов.

Удаление объекта CronJob
Как и любой другой ресурс Kubernetes, объект CronJob можно удалить с по-
мощью команды kubectl delete. При наличии YAML-манифеста это делается
очень просто:

 $ kubectl delete -f hello-world-cronjob.yaml
 cronjob/hello-world-cronjob deleted

После выполнения этой команды объект CronJob будет удален из вашего кла-
стера Kubernetes и задания больше не будут запускаться по расписанию.
