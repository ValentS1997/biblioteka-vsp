188     Глава 5   •  Использование многоконтейнерных подов

Здесь есть два варианта.
z Указать путь к YAML-манифесту с помощью параметра –f.
z Удалить под по его имени, не используя путь к YAML-файлу.

Путь к YAML-манифесту указывается так:

 $ kubectl delete -f multi-container-pod.yaml

А если вы знаете имя пода, то можете сделать следующее:

 $ kubectl delete pods/multi-container-pod
 # или эквивалент
 $ kubectl delete pods multi-container-pod

Чтобы определить имя пода, можно воспользоваться командой kubectl get:

 $ kubectl get pod
 NAME                         READY   STATUS             RESTARTS   AGE
 failed-multi-container-pod   1/2     ImagePullBackOff   0          13m

В нашем случае в кластере был создан только под failed-multi-container-pod,
поэтому в выводе отображается лишь одна строка.

Удалить его можно императивным способом, без указания пути к YAML-файлу:

 $ kubectl delete -f failed-multi-container-pod.yaml
 pod "failed-multi-container-pod" deleted

Через несколько секунд под будет удален из кластера Kubernetes, а все его кон-
тейнеры — из контейнерного демона и узла кластера.

Временной интервал между запуском команды и фактическим удалением пода
называется периодом корректного завершения работы (grace period). О том, как
с ним работать, мы поговорим далее.

Период корректного завершения работы пода
Одним из ключевых понятий, связанных с удалением подов, является так на-
зываемый период корректного завершения работы, который предусмотрен
как для одноконтейнерных, так и для многоконтейнерных подов. Этот период
можно проигнорировать, передав параметр --grace-period=0 --force команде
kubectl delete.
