Запуск объекта CronJob     175

 # ┌───────────── минута (0–59)
 # │ ┌───────────── час (0–23)
 # │ │ ┌───────────── день месяца (1–31)
 # │ │ │ ┌───────────── месяц (1–12)
 # │ │ │ │ ┌───────────── день недели (0–6) (воскресенье — суббота;
 # │ │ │ │ │                в некоторых системах 7 может означать воскресенье)
 # │ │ │ │ │                ИЛИ sun, mon, tue, wed, thu, fri, sat
 # │ │ │ │ │
 # * * * * *

Cron-выражение состоит из пяти полей, разделенных пробелами. Слева направо
эти поля означают:

z минуты;
z  часы;
z день месяца;
z  месяц;
z день недели.

Любое поле может быть заполнено символом *, который означает «каждый».
В одном поле можно указать несколько значений, разделив их запятыми. Мож-
но также указать диапазоны значений с помощью дефиса (-). Вот несколько
примеров.

z  "10 11 * * *" означает «в 11:10 каждый день каждого месяца».
z  "10 11 * 12 *" означает «в 11:10 каждый день декабря».
z  "10 11 * 12 1" означает «в 11:10 каждый понедельник декабря».
z "10 11 * * 1,2" означает «в 11:10 каждый понедельник и вторник каждого
   месяца».
z  "10 11 * 2-5 *" означает «в 11:10 каждый день с февраля по май».

Эти примеры помогут вам лучше понять принцип работы cron-выражений.
Разумеется, запоминать синтаксис не обязательно: большинство пользователей
опираются на документацию или специальные генераторы cron-выражений, та-
кие как crontab.cronhub.io или crontab.guru. Если синтаксис кажется слишком
сложным, смело используйте такие инструменты, чтобы проверить правиль-
ность выражения перед развертыванием объекта в Kubernetes.

Роль раздела jobTemplate
Если вы внимательно следили за структурой YAML-файла, то, вероятно, за-
метили, что раздел jobTemplate содержит определение объекта Job. Используя
объект CronJob, мы просто делегируем ему создание объекта Job (рис. 4.6).
