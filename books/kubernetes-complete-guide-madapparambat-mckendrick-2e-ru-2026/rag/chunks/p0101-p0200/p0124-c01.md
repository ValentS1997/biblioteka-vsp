🔎 Verifying Kubernetes components...

🏄 Done! kubectl is now configured to use "minikube" cluster and "default"
 namespace by default

Мы также можем использовать Podman в качестве контейнерного движка
и создать кластер Kubernetes с помощью minikube, выполнив следующую
команду:

 $ minikube start --driver=podman

Теперь у нас есть кластер Kubernetes, созданный с использованием minikube.
В следующем подразделе вы узнаете, как получать к нему доступ и управлять
им с помощью утилиты kubectl.

Получение доступа к кластеру Kubernetes,
созданному с помощью minikube
Теперь нам необходимо создать файл kubeconfig, чтобы локальная утилита
kubectl могла взаимодействовать с новой установкой Kubernetes. Хорошая но-
вость в том, что minikube сгенерировал его автоматически при выполнении ко-
манды minikube start. Этот файл kubeconfig указывает на локальную конечную
точку kube-apiserver, и ваша локальная утилита kubectl настроена на работу
с этим кластером по умолчанию. Иными словами, никаких дополнительных
действий выполнять не нужно: файл kubeconfig уже имеет правильный формат
и находится в нужном месте.

По умолчанию эта конфигурация хранится в файле ~/.kube/config, и вы можете
увидеть, что теперь там присутствует контекст minikube:

 $ cat ~/.kube/config
 ...<фрагмент опущен для краткости>..
 - context:
     cluster: minikube
     extensions:
       - extension:
           last-update: Mon, 03 Jun 2024 13:06:44 +08
           provider: minikube.sigs.k8s.io
           version: v1.33.1
         name: context_info
     namespace: default
     user: minikube
   name: minikube
 ... <фрагмент опущен для краткости>...
