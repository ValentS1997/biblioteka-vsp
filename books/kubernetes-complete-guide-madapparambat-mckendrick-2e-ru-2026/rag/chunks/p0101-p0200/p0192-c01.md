192     Глава 5   •  Использование многоконтейнерных подов

Для выполнения команды в контейнере, как и раньше, используется kubectl exec.
Но на этот раз параметр -it нужно опустить, чтобы утилита kubectl не привя-
зывалась к текущему терминальному сеансу.
В следующем примере запускается команда ls, которая выводит список файлов
в контейнере nginx-container, работающем внутри пода multi-container-pod:

 $ kubectl exec pods/multi-container-pod -c nginx-container -- ls
 bin
 boot
 dev
 docker-entrypoint.d
 docker-entrypoint.sh
 ...<фрагмент опущен для краткости>...

Если не указать имя контейнера, утилита kubectl по умолчанию выберет пер-
вый контейнер из списка.

Далее мы обсудим способ переопределения команд, выполняемых контейне-
рами.

Переопределение команд, выполняемых
контейнерами по умолчанию
Переопределение команд по умолчанию позволяет управлять поведением
каждого отдельного контейнера внутри многоконтейнерных подов. Напри-
мер, контейнер с веб-сервером обычно запускает команду start server, но
вы можете переопределить его поведение, чтобы он отвечал за логирование.
Этот подход также помогает в управлении ресурсами: если контейнер по
умолчанию запускает ресурсоемкий процесс, вы можете заменить его более
легковесным, чтобы остальные контейнеры в поде имели достаточно ресур-
сов. Наконец, это упрощает управление зависимостями: например, контейнер
приложения может запуститься быстро, но вы можете переопределить его
поведение так, чтобы он дожидался готовности связанного с ним контейнера
базы данных.

В Docker для сборки образа контейнера используются специальные файлы
Dockerfile, в которых есть два ключевых параметра, ENTRYPOINT и CMD, опреде-
ляющие то, какие команды и аргументы будут выполняться контейнером при
его запуске с помощью команды docker run:

z  ENTRYPOINT определяет основную команду, которая будет запущена внутри
   контейнера;
z  CMD задает параметры по умолчанию для команды ENTRYPOINT, которые поль-
   зователь может переопределить при запуске контейнера.
