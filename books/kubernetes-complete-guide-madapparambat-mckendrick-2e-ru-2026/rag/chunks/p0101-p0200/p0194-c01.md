194     Глава 5   •  Использование многоконтейнерных подов

spec:
  restartPolicy: Never
  containers:
    - name: nginx-container
      image: nginx:latest
    - name: debian-container
      image: debian
      command: ["sleep"]  # соответствует ENTRYPOINT
      args: ["60"]        # соответствует CMD

Здесь есть небольшой нюанс: то, что в Dockerfile называется ENTRYPOINT,
в YAML-манифесте соответствует ключу command, а то, что в Dockerfile называ-
ется CMD, соответствует ключу args.
Если мы опустим один из этих параметров, система Kubernetes использует
настройки по умолчанию из образа контейнера. То есть при отсутствии ключа
args в YAML-файле Kubernetes возьмет значение CMD из Dockerfile, а при от-
сутствии ключа command будет использовано значение ENTRYPOINT из Dockerfile.
В большинстве случаев (если вас устраивает значение ENTRYPOINT контейнера)
вы будете переопределять только ключ args (CMD в Dockerfile).
После создания пода мы можем проверить результат следующим образом:

 $ kubectl apply -f nginx-debian-with-custom-command-and-args.yaml
 pod/nginx-debian-with-custom-command-and-args created

 $ kubectl get po -w
 NAME                                       READY STATUS             RESTARTS  AGE
 nginx-debian-with-custom-command-and-args  0/2   ContainerCreating  0         2s
 nginx-debian-with-custom-command-and-args  2/2   Running            0         6s
 nginx-debian-with-custom-command-and-args  1/2   NotReady           0         66s

Итак, переопределение команд по умолчанию позволяет контролировать пове-
дение отдельных контейнеров в многоконтейнерных подах, а также оптимизи-
ровать использование ресурсов и управлять зависимостями. Как было показано
в этом разделе, Kubernetes позволяет переопределять настройки контейнеров
с помощью ключей command и args в YAML-манифестах пода.
В следующем подразделе вы познакомитесь с контейнерами инициализации.

Контейнеры инициализации
Контейнеры инициализации, или init-контейнеры (initContainers), позволяют
выполнять подготовительные действия перед запуском основных контейнеров
пода. Их можно рассматривать как дополнительные контейнеры, которые зада-
ются в YAML-манифесте пода и выполняются первыми при его создании. После
завершения их работы система Kubernetes запускает основные контейнеры.
