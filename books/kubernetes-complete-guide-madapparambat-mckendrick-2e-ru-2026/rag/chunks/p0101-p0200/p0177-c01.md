последующие запланированные запуски.

Управление историей выполнения заданий
Кластер Kubernetes сохраняет историю выполнения всех заданий CronJob
независимо от их результата. Политику хранения этой истории можно на-
строить индивидуально для каждого объекта CronJob, указав количество
сохраняемых записей об успешных и неуспешных запусках. Для этого ис-
пользуются необязательные параметры .spec.successfulJobsHistoryLimit
и .spec.failedJobsHistoryLimit.

Создание объекта CronJob
При наличии YAML-манифеста создание объекта CronJob осуществляется
очень просто:

# hello-world-cronjob.yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: hello-world-cronjob
spec:
  schedule: "*/1 * * * *"   # запуск каждую минуту
  successfulJobsHistoryLimit: 5
  startingDeadlineSeconds: 30
  jobTemplate:
    spec:
      template:
        metadata:
          name: hello-world-cronjob
        spec:
          restartPolicy: OnFailure
          containers:
            - name: hello-world-container
              image: busybox
              imagePullPolicy: IfNotPresent
              command: ["/bin/sh", "-c"]
              args: ["echo 'Hello world'"]

В данном случае параметр successfulJobsHistoryLimit: 5 указывает контрол-
леру CronJob хранить сведения о последних пяти успешных запусках задания.
История более ранних успешных заданий будет удаляться автоматически.
Объект CronJob можно создать с помощью команды kubectl apply -f:

 $ kubectl apply -f hello-world-cronjob.yaml
 cronjob.batch/hello-world-cronjob created
