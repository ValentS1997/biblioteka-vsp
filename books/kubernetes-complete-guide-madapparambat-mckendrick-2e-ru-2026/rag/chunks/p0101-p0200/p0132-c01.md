132     Глава 3   •  Установка первого кластера Kubernetes

управляющего слоя. В результате будет создан одноузловой кластер Kubernetes,
в котором роль управляющего узла играет контейнер Docker.
При желании в качестве провайдера для кластера kind можно использовать
Podman:

 $ KIND_EXPERIMENTAL_PROVIDER=podman kind create cluster

Однако такой вариант нам неинтересен, так как мы можем достичь нужного
результата и с помощью minikube. В данном случае нужно создать многоузловой
кластер на базе kind, узлы которого можно настраивать. Для этого необходи-
мо написать небольшой конфигурационный файл и приказать инструменту
kind использовать его в качестве шаблона при сборке локального кластера
Kubernetes. Итак, удалим только что созданный одноузловой кластер kind
и пересоберем его в виде многоузлового кластера.

1. Чтобы удалить кластер, выполните команду:

    $ kind delete cluster
    Deleting cluster "kind" ...

2. Создайте конфигурационный файл, который будет служить шаблоном для
   сборки кластера kind. Для этого скопируйте следующий фрагмент кода в ло-
   кальный файл текущего каталога, например ~/.kube/kind_cluster:

    kind: Cluster
    apiVersion: kind.x-k8s.io/v1alpha4
    nodes:
      - role: control-plane
      - role: worker
      - role: worker
      - role: worker

   Учтите, что данный файл имеет формат YAML. Важнейшей частью это-
   го файла является массив nodes, где указывается нужное количество уз-
   лов в кластере. Ключ role может принимать два значения: control-plane
  и worker.
  В зависимости от выбранной роли будет создан управляющий или вычис-
   лительный узел.
3. Теперь снова выполните команду kind create с использованием этого конфи-
   гурационного файла, чтобы собрать многоузловой кластер. В данном случае
   результатом будет кластер, состоящий из одного управляющего и трех вы-
   числительных узлов:

    $ kind create cluster --config ~/.kube/kind_cluster
