параметров --grace-period=0 и --force имя пода немедленно освобождается
и становится доступным для создания нового пода. При обычном удалении
система учитывает период корректного завершения работы, и имя пода осво-
бождается только после фактического завершения этой операции.

 $ kubectl delete pod failed-multi-container-pod --grace-period=0 --force
 Warning: Immediate deletion does not wait for confirmation that the running
 resource has been terminated. The resource may continue to run on the cluster
 indefinitely.
 pod "failed-multi-container-pod" force deleted

          Эту команду следует применять с осторожностью. Принудительное удаление
         пода не является нормальной практикой, поскольку, как указано в выводе коман-
          ды, мы не можем удостовериться в фактическом удалении пода. Если по какой-то
         причине это не удастся сделать, он может продолжать работу неопределенно
          долго. Поэтому не запускайте эту команду, если не уверены в своих действиях.

Теперь рассмотрим, как получать доступ к конкретному контейнеру, работа
ющему внутри многоконтейнерного пода.

Доступ к конкретному контейнеру внутри
многоконтейнерного пода
Когда в одном поде работает несколько контейнеров, мы можем получать до-
ступ к каждому из них по отдельности. В этом примере мы обратимся к кон-
тейнеру Nginx внутри многоконтейнерного пода. Поскольку в предыдущем
примере мы его удалили, сначала воссоздадим этот под:

 $ kubectl apply -f multi-container-pod.yaml
 pod/multi-container-pod created

Для получения доступа к работающему контейнеру используется коман-
да kubectl exec. Это аналогично использованию docker exec для выполнения
команд в уже созданном контейнере при работе с Docker напрямую (то есть без
Kubernetes).

Эта команда принимает два параметра:

z имя пода, в котором находится нужный контейнер;
z имя контейнера, заданное в YAML-манифесте.

Имя пода мы уже знаем: его легко получить с помощью команды kubectl get.
В нашем случае под называется multi-container-pod.
