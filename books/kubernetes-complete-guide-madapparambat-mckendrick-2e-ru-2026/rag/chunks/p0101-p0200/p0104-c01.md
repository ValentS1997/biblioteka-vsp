104     Глава 2   •  Архитектура Kubernetes

Например, чтобы активизировать функцию автодополнения в Linux Bash, вы-
полните команду:

 # Установка пакета Bash Completion (если нужно)
 $ sudo yum install bash-completion   # Для систем на основе RPM
 $ sudo apt install bash-completion   # Для систем Debian/Ubuntu

 # Добавьте строку source в конфигурацию вашей оболочки
 $ echo 'source <(kubectl completion bash)' >> ~/.bashrc

Теперь при вводе команды утилита kubectl будет предлагать варианты авто-
дополнения на основе доступных ресурсов и параметров. Чтобы принять пред-
ложение, нажмите клавишу Tab или продолжайте ввод, чтобы сократить список
доступных вариантов.

         Процесс активизации функции автодополнения в других оболочках, таких как Zsh
         или Fish, может быть немного иным. Подробные инструкции приведены в офи-
         циальной документации по kubectl, доступной по адресу https://kubernetes.io/
           docs/reference/kubectl/generated/kubectl_completion/.

Такая настройка гарантирует активизацию функции автодополнения при каж-
дом запуске нового сеанса терминала.

В следующем разделе мы поговорим об использовании императивного и декла-
ративного синтаксиса при выполнении команд kubectl.

Императивный синтаксис
Практически любую инструкцию, передаваемую компоненту kube-apiserver
через утилиту kubectl, можно записать в императивном или декларативном
стиле. Императивный синтаксис позволяет непосредственно изменять со-
стояние кластера в соответствии с аргументами и параметрами, переданными
в команду kubectl.
Рассмотрим несколько команд, написанных в императивном стиле:

 # Создает под с именем my-pod на основе образа контейнера busybox:latest:
 $ kubectl run my-pod --restart Never --image busybox:latest
 # Показывает все ресурсы ReplicaSet в пространстве имен my-namespace,
 # созданные в кластере Kubernetes:
 $ kubectl get rs -n my-namespace
 # Удаляет под с именем my-pod в пространстве имен default:
 $ kubectl delete pods my-pod
