Создание многоузлового кластера Kubernetes с помощью kind     133

  Мы также можем использовать определенную версию Kubernetes, указав
   соответствующие параметры образа при создании кластера kind:

    $ kind create cluster \
      --name=my-kind-cluster \
      --config=~/.kube/kind_cluster \
      --image=kindest/node:v1.29.0\
    @sha256:eaa1450915475849a73a9227b8f201df25e55e268e5d619312131292e324d570

После выполнения всех этих шагов инструмент kind развернет и сконфигури-
рует новый кластер Kubernetes, а в конце вы получите сообщение о том, как
к нему можно подключиться:

 Creating cluster "my-kind-cluster" ...
✓ Ensuring node image (kindest/node:v1.29.0) 🖼
✓ Preparing nodes 📦 📦 📦
✓ Writing configuration 📜
✓ Starting control-plane 🕹
✓ Installing CNI 🔌
✓ Installing StorageClass 💾
✓ Joining worker nodes 🚜

 Set kubectl context to "kind-my-kind-cluster"

 You can now use your cluster with:
 kubectl cluster-info --context kind-my-kind-cluster

 Thanks for using kind! 😊

В итоге у вас появится четыре новых контейнера Docker: один будет выступать
в роли управляющего узла кластера Kubernetes, а три других — в роли вычис-
лительных узлов.
Теперь нам следовало бы создать файл kubeconfig, чтобы утилита kubectl могла
взаимодействовать с новым кластером. Однако инструмент kind уже сгенери-
ровал корректную конфигурацию и добавил ее в файл ~/.kube/config, а также
задал новый кластер в качестве текущего контекста. Таким образом, дополни-
тельных действий от нас не требуется и мы можем сразу приступить к работе.
Выведем список узлов кластера, выполнив команду kubectl get nodes. Если все
в порядке, вы должны увидеть четыре узла:

 $ kubectl get nodes
 NAME                          STATUS   ROLES           AGE     VERSION
 my-kind-cluster-control-plane Ready    control-plane   4m      v1.29.0
 my-kind-cluster-worker        Ready    <none>          3m43s   v1.29.0
 my-kind-cluster-worker2       Ready    <none>          3m42s   v1.29.0
 my-kind-cluster-worker3       Ready    <none>          3m41s   v1.29.0
