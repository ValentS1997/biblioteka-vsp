Проанализировав этот лог, можно сделать вывод о том, что с контейнером
debian-container все в порядке — агент kubelet успешно создал его, на что
указывает последняя строка предыдущего вывода. Однако с контейнером nginx-
container возникла проблема.
Указанная в выводе ошибка ErrImagePull говорит о невозможности запуска
контейнера из-за неудачной попытки загрузки образа nginx:i-do-not-exist.

Итак, система Kubernetes делает следующее.
1. Создает запись в хранилище etcd, если YAML-файл с описанием пода яв-
   ляется действительным.
2. Пытается запустить контейнер.
3. При возникновении ошибки многократно повторяет попытку запуска проб
   лемного контейнера.

Даже если остальные контейнеры работают корректно, под не перейдет в со-
стояние выполнения (Running) до тех пор, пока хотя бы один из них продолжает
сбоить. И это логично: ваше приложение наверняка нуждается в этом контей-
нере для полноценной работы, иначе его просто не следовало включать в под.

Теперь обсудим способ удаления многоконтейнерного пода.

Удаление многоконтейнерного пода
Для удаления пода с несколькими контейнерами используется та же команда
kubectl delete, что и для удаления одноконтейнерного пода.
