Обзор утилиты командной строки kubectl и синтаксиса YAML     103

После этого HTTP-запрос отправляется компоненту kube-apiserver, который
формирует HTTP-ответ. Утилита kubectl преобразует этот ответ в удобочитае
мый формат и выводит его в терминал.
Ниже приведена команда, которая очень часто используется при работе
с Kubernetes:

 $ kubectl get pods

Эта команда выводит список подов. По сути, она отправляет GET-запрос ком-
поненту kube-apiserver для получения списка контейнеров (подов) в вашем
кластере. Внутренне kubectl сопоставляет переданный в команду параметр
Pods с URL-путем /api/v1/pods, через который kube-apiserver предоставляет
доступ к ресурсу Pod.

Рассмотрим еще одну команду:

 $ kubectl run nginx --restart Never --image nginx

Эта команда чуть сложнее, так как run не является HTTP-методом. Она от-
правляет POST-запрос компоненту kube-apiserver, в результате чего создается
контейнер nginx на основе одноименного образа, размещенного в контейнерном
реестре (например, Docker Hub или quay.io).

        На самом деле эта команда создает не контейнер, а под. Данный ресурс будет
         подробно описан в главе 4. А сейчас давайте перейдем от обсуждения кон-
         тейнеров к изучению терминологии и концепций Kubernetes. С этого момента,
          если вы встретите слово «контейнер», оно будет означать реальный контейнер
          в контексте технологий контейнеризации. Соответственно, под словом «под»
        мы будем подразумевать ресурс Kubernetes.

В следующем разделе вы узнаете, как активизировать функцию автодополнения
команд kubectl.

Автодополнение команд kubectl
Утилита kubectl имеет встроенную функцию автодополнения команд, которая
экономит время и снижает количество ошибок. Данная функция поддерживает
следующие популярные оболочки:

z  Bash;
z  Zsh;
z  Fish;
z  PowerShell.
