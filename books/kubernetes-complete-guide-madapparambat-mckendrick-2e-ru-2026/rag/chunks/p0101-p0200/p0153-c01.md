Запуск подов     153

Ниже приведено содержимое файла nginx-pod.yaml, который вы можете создать
на своей локальной машине:

# nginx-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
    - name: nginx-container
      image: nginx:latest

Попробуйте внимательно прочитать этот файл и разобраться в его содержании.
YAML-файлы представляют собой набор пар «ключ — значение». В данном слу-
чае именем (name) пода является nginx-pod, а в разделе spec: содержится массив
контейнеров, включающий только один контейнер nginx-container, созданный
на основе образа nginx:latest.
После сохранения файла nginx-pod.yaml вы можете создать под, выполнив
команду:

 $ kubectl apply -f nginx-pod.yaml
 pod/nginx-pod created

Если в кластере уже существует под с именем nginx-pod, эта команда завершит-
ся с ошибкой. В этом случае измените имя пода в YAML-файле и повторите
попытку.

Пространства имен в Kubernetes
Если не указать пространство имен при создании ресурса, по умолчанию будет
использоваться default. Подробно о пространствах имен мы поговорим в главе 6.

Чтение информации и метаданных пода
На данном этапе у вас уже должен быть запущен под в кластере Kubernetes.
Теперь попробуем получить информацию о нем. В любой момент времени нам
необходимо иметь возможность извлекать и просматривать сведения о создан-
ных ресурсах кластера Kubernetes, в том числе о подах. Чтение информации
о кластере выполняется с помощью двух команд утилиты kubectl: kubectl get
и kubectl describe.
