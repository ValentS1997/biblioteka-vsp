Обзор утилиты командной строки kubectl и синтаксиса YAML     107

Вы сможете прочитать этот файл и без труда понять его содержимое. Как ви-
дите, он просто создает два пода. Первый использует образ busybox, а второй —
nginx.
Разумеется, запоминать весь синтаксис и значения для каждого ключа нет не-
обходимости. Вы всегда можете найти примеры декларативных YAML-файлов
в официальной документации Kubernetes. Если ее окажется недостаточно, вы
можете воспользоваться командой kubectl explain, чтобы получить подробное
описание ресурса, например:

 $ kubectl explain pod.spec.containers.image
 KIND:       Pod
 VERSION:    v1

 FIELD: image <string>
 DESCRIPTION:
     Container image name. More info:
     https://kubernetes.io/docs/concepts/containers/images

         Вывод команды kubectl explain содержит подробное описание всех полей кон-
         фигурационного файла.

Несмотря на то что написание YAML-файлов занимает больше времени, чем
выполнение императивной команды, декларативный синтаксис имеет два су-
щественных преимущества.

z Управление инфраструктурой как кодом (IaC) — вы можете хранить конфи-
   гурацию в отдельном репозитории Git и версионировать ресурсы Kuber
   netes. В случае утраты состояния кластера наличие версионированных
  YAML-файлов в репозитории Git позволит быстро и корректно его вос-
   становить.
z Создание нескольких ресурсов одновременно — поскольку в одном YAML-
   файле можно объявить несколько ресурсов, вы можете хранить в нем полное
   описание приложения и всех его зависимостей. Это позволяет создавать
  и воссоздавать сложные приложения одной командой. Позднее вы познако-
   митесь с инструментом Helm, который реализует механизм шаблонизации
  YAML-файлов Kubernetes.

Ни один из описанных выше способов использования утилиты kubectl не явля-
ется лучшим. Это два разных подхода к взаимодействию с ним, которые следует
освоить. Дело в том, что одни функции недоступны при работе в императивном
стиле, а другие — в декларативном. В конечном счете оба подхода предполагают
взаимодействие с компонентом kube-apiserver через протокол HTTP.
