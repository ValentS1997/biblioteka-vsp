158     Глава 4   •  Запуск контейнеров в Kubernetes

В результате вы окажетесь внутри контейнера Nginx и сможете выполнять в нем
любые действия. Приведенная выше команда предполагает, что в контейнере
установлен интерпретатор bash. При его отсутствии в контейнерах обычно до-
ступен интерпретатор sh, который можно использовать для получения доступа
к ним. При необходимости вы можете указать полный путь к двоичному файлу,
например, так:

 $ kubectl exec -it nginx-pod -- /bin/bash

По окончании тестирования выйдите из оболочки контейнера с помощью
команды exit:

 root@nginx-pod:/# exit
 exit

        Безопасность и работа в контейнерах от имени непривилегированных
        пользователей
         Чтобы ограничить потенциальный ущерб от эксплуатации уязвимостей, ре-
         комендуется не запускать контейнеры от имени пользователя root. Неприви
         легированный пользователь имеет меньше прав доступа к системе, что сни-
         жает последствия в случае атаки. Кроме того, для минимизации поверхности
         атаки следует придерживаться принципа наименьших привилегий, то есть
         предоставлять контейнеру только те разрешения, которые необходимы для
          его работы. В главе 18 мы подробно обсудим такое понятие, как контекст
          безопасности.

Теперь посмотрим, как можно удалить под из кластера Kubernetes.

Удаление пода
Удалить под очень просто. Для этого достаточно использовать команду kubectl
delete и указать имя пода, который требуется удалить. В нашем случае это
nginx-pod:

 $ kubectl delete pods nginx-pod
 # или...
 $ kubectl delete pods/nginx-pod

Если вы не знаете имя пода, сначала используйте команду kubectl get pods,
чтобы вывести список подов и найти нужный.
