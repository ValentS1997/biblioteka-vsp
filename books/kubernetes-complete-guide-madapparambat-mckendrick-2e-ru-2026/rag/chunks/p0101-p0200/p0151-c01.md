Запуск подов     151

YAML-файла с конфигурацией пода и его дальнейшего применения с помощью
команды kubectl apply -f.
Для создания пода в кластере Kubernetes используется команда kubectl run.
Это самый простой и быстрый способ запуска пода. Команда вызывается так:

 $ kubectl run nginx-pod --image=nginx:latest

Здесь в качестве имени пода задается nginx-pod. Имя имеет большое значение,
так как служит идентификатором пода: при обновлении (update) или удалении
(delete) пода необходимо указывать именно его, чтобы система Kubernetes
знала, над каким именно объектом должна быть выполнена указанная опера-
ция. Флаг --image указывает, какой контейнерный образ будет использован
для запуска контейнера в этом поде. После создания пода его состояние можно
проверить следующим образом:

 $ kubectl get pods
 NAME       READY   STATUS    RESTARTS   AGE
 nginx-pod  1/1     Running   0          79s

          Учтите, что под не запускается мгновенно. Системе Kubernetes может потребо-
          ваться время, чтобы загрузить образ контейнера из реестра (если он отсутствует
          в локальном хранилище) и настроить окружение пода. Чтобы отслеживать этот
          процесс в реальном времени, используйте команду kubectl get po -w, которая
         выводит информацию о подах и автоматически обновляет ее1.

В данном примере мы создаем под на основе образа контейнера nginx:latest
из реестра Docker Hub. Под nginx-pod будет содержать только один контейнер,
собранный из этого образа. Указать несколько образов здесь невозможно из-за
ограничений императивного синтаксиса.
Если вам требуется создать под, содержащий несколько контейнеров, собран-
ных на основе разных образов, то вам придется использовать декларативный
синтаксис и описать конфигурацию в YAML-файле.

Теги и дайджесты: обеспечение согласованности образов
При создании подов вы можете столкнуться с такими понятиями, как теги
и дайджесты. И те и другие используются для идентификации контейнерных
образов, но между ними есть важное различие.

z  Теги — это человекочитаемые имена версий образов. Они могут указывать
   на разные версии одного и того же образа, что способно вызвать непредска-
   зуемое поведение.

1  В книге встречаются сокращенные имена ресурсов, как в этом примере po (pods). Их пол-
   ный список можно посмотреть, введя команду kubectl api-resources.
