184     Глава 5   •  Использование многоконтейнерных подов

Итак, если несколько контейнеров должны работать совместно и быть тесно
связаны между собой, то их следует объединять в многоконтейнерный под.
Теперь обсудим процесс создания таких подов.

Создание пода, состоящего из двух контейнеров
В предыдущей главе мы выяснили, что для управления объектами в Kubernetes
можно использовать:

z императивный синтаксис;
z декларативный синтаксис.

Большинство объектов Kubernetes, с которыми мы будем работать в этой книге,
можно создавать и обновлять обоими способами. Однако многоконтейнерные
поды являются исключением.
Для их создания необходимо использовать декларативный синтаксис. Это озна-
чает, что вы должны создать YAML-файл с описанием пода и всех контейнеров,
которые он будет содержать, а затем применить его с помощью команды kubectl
apply -f file.yaml.
Рассмотрим следующий YAML-манифест, сохраненный по адресу ~/multi-
container-pod.yaml:

# multi-container-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-container-pod
spec:
  restartPolicy: Never
  containers:
    - name: nginx-container
      image: nginx:latest
    - name: debian-container
      image: debian
      command: ["/bin/sh"]
      args: ["-c", "while true; do date; echo debian-container; sleep 5; done"]

Этот файл предназначен для создания пода Kubernetes, который содержит два кон-
тейнера: один на основе образа nginx:latest, а другой — на основе образа debian.
Для его создания используйте команду:

 $ kubectl apply -f multi-container-pod.yaml
 pod/multi-container-pod created

В результате будет создан под. Агент kubelet на выбранном узле поручит среде
выполнения контейнеров (например, containerd, CRI-O или демону Docker)
скачать оба образа и создать на их основе два контейнера.
