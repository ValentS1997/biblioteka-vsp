162     Глава 4   •  Запуск контейнеров в Kubernetes

metadata:
  name: nginx-pod
  labels:
    environment: prod
    tier: frontend
spec:
  containers:
    - name: nginx-container
      image: nginx:latest

Если этот файл сохранен по адресу ~/labeled_pod.yaml, то мы можем создать
под с помощью следующей команды:

 $ kubectl apply -f ~/labeled_pod.yaml

Теперь при выполнении фильтрации по метке мы получим как минимум один
под — тот, который только что был создан:

 $ kubectl get pod -l environment=prod
 NAME        READY   STATUS    RESTARTS   AGE
 nginx-pod   1/1     Running   0          31m

Далее выведем список меток, назначенных поду.

Вывод списка меток, присвоенных поду
В Kubernetes нет отдельной команды для отображения меток, присвоенных
поду, но вы можете сделать вывод команды kubectl get pods более подробным.
Если добавить параметр --show-labels, то в результате выполнения этой коман-
ды будут показаны все метки, назначенные подам:

 $ kubectl get pods --show-labels
 NAME       READY   STATUS    RESTARTS   AGE   LABELS
 nginx-pod  1/1     Running   0          56s   environment=prod,tier=frontend

Эта команда не выполняет никаких запросов на основе меток, а просто выводит
список меток.

Добавление или обновление метки запущенного пода
Теперь, когда вы научились создавать поды с метками, рассмотрим способ при-
своения метки уже запущенному поду. Мы можем в любой момент добавить
или изменить метку ресурса с помощью команды kubectl label. Например,
присвоим поду nginx новую метку stack со значением blue:

 $ kubectl label pod nginx-pod stack=blue
 pod/nginx-pod labeled
