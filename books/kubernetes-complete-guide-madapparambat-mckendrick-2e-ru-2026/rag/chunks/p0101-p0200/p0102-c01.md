z Пользователи (users) — этот раздел хранит учетные данные для получения
   доступа к кластерам Kubernetes. Обычно он включает имя пользователя
  и секрет (например, токен или клиентский сертификат), используемые для
   аутентификации на API-сервере. Файлы kubeconfig также могут ссылаться
   на сертификаты, указанные в разделе user, для безопасной аутентификации
   пользователей на API-сервере Kubernetes. Такая двусторонняя проверка
   гарантирует получение доступа к кластеру только авторизованными поль-
   зователями с действительными сертификатами и устраняет потенциальные
   угрозы безопасности.
z Контексты (contexts) — этот раздел связывает кластеры с пользователями.
  Каждый контекст ссылается на конкретный кластер и конкретного пользо-
   вателя в этом кластере. Выбирая контекст, вы определяете, какой кластер
  и какие учетные данные утилита kubectl будет использовать при выполне-
  нии последующих команд.

Наличие в файле kubeconfig нескольких настроенных кластеров, пользовате-
лей и контекстов позволяет легко переключаться между разными кластерами
Kubernetes, используя различные учетные данные.

Путь к файлу kubeconfig можно переопределить в системе, установив пере-
менную окружения KUBECONFIG или передав параметр --kubeconfig при вы-
зове kubectl:

 $ export KUBECONFIG="/custom/path/.kube/config"
 $ kubectl --kubeconfig="/custom/path/.kube/config"

Каждый раз при запуске команды kubectl одноименная утилита командной
строки ищет файл kubeconfig, из которого нужно загрузить конфигурацию,
выполняя следующие шаги.

1. Сначала утилита проверяет, был ли передан параметр --kubeconfig, и при
   его наличии загружает указанный файл конфигурации.
2. Если файл конфигурации не найден, kubectl проверяет наличие переменной
   окружения KUBECONFIG.
3. В итоге она использует файл по умолчанию, расположенный по адресу
   $HOME/.kube/config.

Чтобы просмотреть файл конфигурации, который в данный момент использу-
ется локальной установкой kubectl, выполните команду:

 $ kubectl config view
