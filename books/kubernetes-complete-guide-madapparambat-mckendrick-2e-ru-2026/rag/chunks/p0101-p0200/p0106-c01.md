106     Глава 2   •  Архитектура Kubernetes

Предположим, что мы сохранили файл с конфигурацией пода под именем
pod.yaml. Для создания самого пода необходимо выполнить следующую
команду:

 $ kubectl create -f pod.yaml

Результат будет эквивалентен результату выполнения императивной команды.

Каждый YAML-файл, созданный для системы Kubernetes, должен содержать
четыре обязательных ключа.

z  apiVersion — указывает версию API, в которой описан ресурс. Для каждого
   типа ресурса задается свой ключ apiVersion. Например, ресурс типа Pod
   относится к версии API v1.
z  kind — определяет тип ресурса, создаваемого с помощью YAML-файла. В на-
  шем случае это Pod.
z  metadata — содержит сведения о самом ресурсе, включая его имя. В данном
   случае под называется my-pod. Эти метаданные предназначены для систе-
  мы Kubernetes, а не для контейнерных движков вроде Docker Engine или
   Podman.
z spec — описывает состав объекта. В приведенном примере под состоит
   из одного контейнера busybox-container, созданного на основе образа
   busybox:latest. Именно эти контейнеры будут запущены в среде выполне-
   ния контейнеров на вычислительном узле.

Еще одна важная особенность декларативного синтаксиса состоит в том, что
в одном YAML-файле можно описать несколько ресурсов, разделяя их тремя
дефисами (---). Вот обновленная версия файла, определяющая сразу два пода:

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
    -  name: busybox-container
       image: busybox:latest
---
apiVersion: v1
kind: Pod
metadata:
  name: my-second-pod
spec:
  containers:
    - name: nginx-container
      image: nginx:latest
