# Source findings — глава 14, Helm и операторы

**Source policy:** RAG-only, PDF 474–514. Каждая находка опирается на текст книги, без проверки внешних URL. Неустановленное обозначено [Needs confirmation].

1. **F-01 — NodePort mismatch (p484–485).** WordPress Service и итоговый URL дают HTTP-порт 30509, а пояснение страницы 484 указывает 31979. Реальный порт конкретного кластера [Needs confirmation].
2. **F-02 — Helm uninstall (p487).** Сначала говорится об удалении всех объектов релиза, затем — что PV/PVC автоматически не удаляются. Судьба данных зависит от ресурсов и reclaim policy; rollback [Needs confirmation].
3. **F-03 — Несоответствие dry-run (p483–484).** Реальная установка использует namespace wordpress и wp-values.yaml; предлагаемый dry-run не передаёт эти параметры, поэтому конфигурации отличаются.
4. **F-04 — WordPress values (p482, p485).** В источнике пароль находится в values.yaml, затем извлекается из Secret. Не использовать демонстрационные credentials в репозитории и журналах; безопасность хранения [Needs confirmation].
5. **F-05 — Dashboard RBAC (p490–493).** Учебный ServiceAccount получает ClusterRoleBinding на cluster-admin. Это не модель минимальных привилегий; управление выданным токеном [Needs confirmation].
6. **F-06 — Dashboard TLS/репозиторий (p489–492).** Источник использует исторический адрес чарта и предлагает пропустить предупреждение о самоподписанном сертификате. Актуальность пакета и безопасная проверка TLS [Needs confirmation].
7. **F-07 — OLM readiness (p503).** Один из catalog Pod имеет 0/1 Ready при статусе Running, однако packageserver CSV имеет Succeeded. Успех CSV не доказывает готовность всех Pod.
8. **F-08 — Удалённый установщик OLM (p502).** Используется получение и непосредственный запуск install.sh. Код, контроль целостности и способ удаления не проверены [Needs confirmation].
9. **F-09 — OperatorHub manifests (p503–504).** Подписки Prometheus/Grafana создаются из удалённых YAML URL без приведённой проверки фактического содержимого; полномочия и совместимость [Needs confirmation].
10. **F-10 — CSV table extraction (p504).** Строки Prometheus Operator v0.70.0/v0.65.1 и столбцы REPLACES/PHASE извлечены с переносами; значения нельзя надёжно назначить версиям без проверки.
11. **F-11 — CRD vs custom resource (p498–499, p505).** Текст иногда приписывает desired state самому определению типа (CRD), тогда как настройки экземпляра содержатся в custom resource.
12. **F-12 — ServiceMonitor (p505–508).** Selector в Prometheus CR дан, но полный манифест ServiceMonitor не приведён. Соответствие меток не доказано [Needs confirmation].
13. **F-13 — Порядок Node Exporter (p506–507).** В выводе мониторинга Pod Node Exporter уже запущен до шага, создающего DaemonSet. Непоказанный промежуточный шаг [Needs confirmation].
14. **F-14 — Grafana конфигурация (p506).** Учебный custom resource задаёт администраторские credentials открытым текстом, сам источник советует Secrets. Безопасный вариант не реализован.
15. **F-15 — Граница namespace (p491, p494, p504).** Рекомендация изоляции по пространствам имён не покрывает ClusterRoleBinding и CRD, действующие в масштабе кластера.
16. **F-16 — Способ установки мониторинга (p502, p505–508, p514).** Резюме описывает Helm и операторов, однако последовательность установки Prometheus/Grafana выполнена через OLM/операторы; Helm-чарт стека приведён только как альтернатива.
17. **F-17 — Data recovery (p483–487).** Демонстрация WordPress не проверяет резервное копирование, восстановление MariaDB или безопасное удаление PVC [Needs confirmation].
18. **F-18 — Историчность (p478–479, p503–506).** Приведённые версии Helm/OLM/операторов и URL не являются подтверждением их нынешней доступности, безопасности или совместимости [Needs confirmation].

**Scope:** никакие команды не выполнялись; source PDF/LFS, RAG, registry и статус чтения не менялись.
