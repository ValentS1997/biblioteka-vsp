# Резюме главы 18 — по заключительному разделу книги

**Source:** `kubernetes-complete-guide-madapparambat-mckendrick-2e-ru-2026:p0639:c01`–`…:p0640:c01`, PDF/печатные страницы 639–640, раздел «Резюме». Ниже — **краткий пересказ**, не дословная перепечатка; последовательность и смысл заключительного источника сохранены.

Авторы завершают главу итогами по управлению доступом к API Kubernetes. Рассмотрены различия аутентификации и авторизации, способы проверки пользователей и сервисов, в том числе токены ServiceAccount и сертификаты. Механизм RBAC продемонстрирован на объектах `Role`, `ClusterRole`, `RoleBinding` и `ClusterRoleBinding`. Учебный Pod с выделенной ServiceAccount получает строго ограниченные права читать сведения о Pod; без соответствующего RoleBinding API возвращает запрет.

Вторая часть главы посвящена контроллерам допуска, применяющим политики к изменяющим запросам, а также `securityContext` для ограничения прав процесса внутри контейнера. Рассмотрены NetworkPolicy для управления взаимодействием Pod, TLS для защищённых соединений, изолирующие среды выполнения gVisor и Kata Containers и credentials для приватных реестров через Kubernetes Secret и `imagePullSecrets`.

В следующей главе — **продвинутые методы планирования Pod**.

**Evidence boundary:** источник не доказывает действительную production-защиту кластера, конфигурацию шифрования Secret at rest, безопасность всех политик и runtime handlers. Это граница приведённых в тексте опытов; дополнительные замечания сохранены отдельно в `source-findings.md`.
