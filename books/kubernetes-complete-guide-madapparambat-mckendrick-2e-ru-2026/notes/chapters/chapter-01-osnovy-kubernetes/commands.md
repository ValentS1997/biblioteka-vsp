### Dockerfile (учебный пример из стр. 54–55)

```dockerfile
# syntax=docker/dockerfile:1
FROM node:18-alpine
WORKDIR /app
COPY . .
RUN yarn install --production
CMD ["node", "src/index.js"]
EXPOSE 3000
```

Это **описание сборки образа**, а не read-only команда. `RUN yarn install --production` выполняется при сборке; `CMD` задает команду запуска; `EXPOSE` не публикует порт хоста самостоятельно (стр. 55). Глава отдельно отмечает потребность в подходящем `.dockerignore`. Безопасность и актуальность базового образа, зависимости и проверка скрипта не установлены: **[Needs confirmation]**.

### Compose (стр. 56)

Источник приводит демонстрационный `compose.yaml` с сервисами MariaDB и WordPress, томом `db_data`, сетью `wordpress`, публикацией `8081:80`. В оригинале присутствуют учебные литеральные пароли: в любых перенесенных примерах их следует заменять плейсхолдерами `<DB_ROOT_PASSWORD>`, `<DB_PASSWORD>` и не помещать реальные секреты в документацию. Глава не приводит точной команды выполнения и не описывает схему хранения production-секретов.

## Границы безопасности для изменения Deployment

**Эффект:** изменится образ в `deploy/myapp` для контейнера `myapp_container` (p0065:c01).

**Риск:** возможные нарушения доступности при обновлении в рабочей среде (p0064:c01).

**Проверка:** глава формулирует целевую непрерывность сервиса, но конкретные read-only команды и success thresholds отсутствуют — **[Needs confirmation]**.

**Rollback:** возможность отката ревизии описана концептуально (p0066:c01), однако буквальной команды rollback нет — **[Needs confirmation]**.
