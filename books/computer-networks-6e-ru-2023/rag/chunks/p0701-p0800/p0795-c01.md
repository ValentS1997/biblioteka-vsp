Им. 7.45. Дерево распределения CDN


  С ростом применения шифрования в интернете, в частности, использования
протокола HTTPS для распространения веб-контента, доставка контента из CDN
приобрела более сложный характер. Допустим, вам нужно загрузить главную
страницу сайта https://nytimes.com/. DNS-поиск для этого домена выдает ссылку
на сервер имен компании Dуп, например nsl.p24.dynect.net, который, в свою
очередь, перенаправляет вас на IР-адрес, размещенный в CDN этой компании.
Но теперь этот сервер должен доставить вам контент, аутентифицированный
New York Times. Для этого он, вероятно, должен располагать закрытыми ключа
ми шифрования для сайта New York Тimes или сертификатом для сайта nytimes.
сот (или и тем и другим). Таким образом, CDN придется доверить конфиден
циальную информацию провайдера контента, а сервер потребуется настроить
так, чтобы он фактически выступал в роли агента сайта nytimes.com. Альтерна
тивный подход состоит в том, чтобы направлять вес запросы клиента обратно
на исходный сервер, который сможет доставлять сертификаты и контент по
протоколу HTTPS, но это сведет на нет практически все преимущества CDN
в плане производительности. Решение обычно представля ет собой компро
