Илл. 8.5. Проблемы, с которыми столкнулся Кевин Митник при атаке на Суnеркомnьютерный центр
Сан-Диего

   Тот факт, что Митник не видел сегмент SYN/ АСК и поэтому не мог получить
ISN, не стало бы проблемой, если бы этот ном~р был предсказуемым (нанример,
начинался с О для каждого нового соединения). Но посколL>ку ISN выбирался
достаточно случайно для каждого соединения, нужно было выяснить, как он
генерировался, чтобы предсказать, какой номер использует Х-терминал в не
видимом сегменте SYN/ АСК, который он отправит серверу.
   Чтобы решить все эти проблемы, Митник провел свою атаку в несколько
этапов. Он начал с активного взаимодействия с Х-термина.тюм с использованием
неподдельных сообщений SYN (шаг 1 на илл. 8.6 (а)). Хотя эти попытки не при
вели к установлению ТСР-соединения с Х-терминалом, они позволили получить
некоторую последовательность ISN. К счастью для Кевина, номера выбирались
не таким уж случайным образом. Понаблюдав за ними некоторое время, он
смог выявить закономерность. Теперь он был уверен, что, получив один ISN, он
сможет предсказать следующий. Затем он позаботился о том, чтобы доверенный
сервер не мог сбросить его попытки подключения. Для этого он запустил DоS
атаку, которая сделала сервер недоступным (шаг 2 на илл. 8.6 (б)). После этого
уже можно было приступить к проведению реа.т1ьной атаки.
   После отправки поддельного пакета SYN (шаг 3 на илл. 8.6 (б)) он определил,
какой ISN будет использован Х-терминалом в отсылаемом на сервер ответе
SYN/ACK (шаг 4 на илл. 8.6 (б)). Он указал этот номер на третьем и последнем
шаге, где отправил команду echo «+ +» >>  • rhosts в качестве данных на порт,
используемый демоном удаленной оболочки (шаг 5 на илл. 8.6 (в)). После этого
он мог войти в систему с любого компьютера без пароля.
   Поскольку атака Митника стала возможной главным образом иэ-за пред
сказуемости номеров ISN протокола ТСР, впоследствии разработчики сетевых
стеков приложили немало усилий к тому, чтобы повысить степень случайности
при выборе протоколом ТСР этих важных для безопасности номеров. Поэтому
теперь реализовать такую атаку уже невозможно. Сегодня злоумышленники
должны подбирать ISN иначе, например так, как это делается в случае захвата
соединения. Обсудим эту разновидность атак более подробно.
