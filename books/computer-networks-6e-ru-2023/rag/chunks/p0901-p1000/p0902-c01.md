  Для начала Алиса отправляет Бобу случайно выбранное число Rл ( сообще
ние 1). Такие случайно выбранные числа, которые применяются в протоко
лах безопасности только один раз, принято называть нонсами (nonce); это
сокращение от английского выражения «number used once• -  «однократно
используемое число•. Боб при ответе выбирает собственный ноне R8 и вы
сылает его вместе с кодом НМАС. Этот код формируется путем построения
структуры данных, состоящей из нонсов Алисы и Боба, их идентификаторов,
а также общего секретного ключа Клв· Затем вся эта структура с помощью
хеш-функции (например, SHA-2) помещается в НМАС. После приема со
общения 2 у Алисы имеется значение Rл (она сама его выбрала), значение R8 ,
полученное в виде открытого текста, два идентификатора и секретный ключ
Клв• который она и так знала. С помощью этих данных она может вычислить
НМАС самостоятельно. Если он совпадает с кодом НМАС в сообщении, она
убеждается, что говорит с Бобом. Ведь Труди не знает Клв и, следовательно,
не может угадать НМАС, который следует отослать. Алиса отправляет Бобу
НМАС, содержащий только два нонса.
   Вопрос: может ли Труди взломать такой протокол? Нет, поскольку она не
может заставить ни одну из сторон зашифровать или хешировать выбранное
ею значение, как было показано на илл. 8.31и8.32. Оба кода НМАС содержат
значения, выбранные отправителем, и Труди не способна их контролировать.
   Коды НМАС - далеко не единственный вариант применения этой идеи.
Довольно распространенная альтернативная схема заключается в шифровании
элементов данных последовательно, с помощью сцепления блоков шифра.
