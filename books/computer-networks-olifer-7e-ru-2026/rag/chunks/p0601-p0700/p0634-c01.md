боте маршрутизатора по продвижению пакетов. Поэтому эту работу поручают внешним
серверам, которые называются SR-МРLS-контроллерами. SR-МРLS-контроллер может
работать на основе различных протоколов, связывающих его с узлами SR-MPLS-ceти.
Наиболее популярными являются протоколы РСЕР (Path Computation Element Protocol)
и расширения BGP.
На рис. 20.14 показана сеть SR-MPLS с контроллером на основе протокола РСЕР. Каждый
маршрутизатор сети SR-MPLS передает контроллеру топологическую информацию по
протоколу РСЕР, работающему поверх соединений ТСР. Для этого каждый маршрутизатор
имеет в своем составе специальный программный блок, называемый клиентом РСС ( Path
Computation Client). Клиент собирает всю топологическую информацию, необходимую
для построения базы данных TED, - идентификаторы узлов Node-SID, идентификаторы
связей Adj-SID, ШЗ-адреса узлов подсетей, состояние связей, метрики связей, включая
ТЕ-метрики. Эту информацию он в компактном виде передает в контроллер, но не пери
одически, а только при изменении топологической информации, например, изменении
состояния связи или метрики лини связи. Контроллер на основании этой информации
создает базу топологических данных сети SR-MPLS TED и с помощью алгоритма CSPF
находит ТЕ-пути в форме списков SR-Policy. Затем контроллер передает каждый список
соответствующему пограничному узлу, который должен использовать этот список для
сегментной маршрутизации, с помощью протокола РСЕР.
