Глава 20. MPLS -  транспортная технология глобальных сетей                    627

Существуют два основных варианта технологии MPLS ТЕ, поддерживающей инжиниринг
трафика:
•  на основе протокола RSVP;
•  на основе сегментной маршрутизации SR-MPLS (Segment Routing MPLS).
Оба эти варианта используют нахождение пути на rрафе сети протоколом маршрутизации
состояния связей - OSPF или IS-IS. Для решения задачи инжиниринга трафика необхо
димы специальные версии этих протоколов, называемые версиями OSPF ТЕ или IS-IS ТЕ,
то есть версиями с ТЕ-расширениями. Эти версии делают объявления о состоянии связи
с дополнительными параметрами, необходимыми для принятия решения об инжиниринrе
маршрута. В дополнение к обычной метрике - количеству хопов -  в состояние связи могут

включаться следующие метрики:
•  максимальная пропускная способность линии;
•  зарезервированная пропускная способность линии;
•  свободная ( оставшаяся, незарезервированная пропускная способность) линии;
•  •цвет• линии - принадлежность к одной из групп, задаваемых администратором;
•  величина задержки линии.
В результате обмена объявлениями состояния связей каждый маршрутизатор знает точ
ный граф сети с ребрами, помеченными (нагруженными) одной или несколькими такими
дополнительными метриками. Эти метрики являются ограничениями при поиске крат
чайшего пути на rрафе. Результатом работы протокола с расширением ТЕ является граф
с ребрами, нагруженными дополнительными параметрами. Такой граф составляет базу
данных инжиннринrа трафика (Traffic Engineering Database, ТЕD).

Для нахождения ТЕ-пути (называемого также ТЕ-туннелем) используется специальный
алгоритм поиска кратчайшего пути на графе. На первом этапе этот алгоритм просто от
брасывает линии связи, которые не удовлетворяют заданному администратором сети оrра
ничениям, - например, отбрасываются линии связи, у которых максимальная пропускная
способность меньше заданного порогового значения, или же задержки, вносимые линией,
слишком велики. А затем работает стандартный алгоритм нахождения кратчайшего пути
на rрафе (алгоритм Дейкстры), но уже на графе, у которого имеются только линии связи,
удовлетворяющие заданным ограничениям. Такой алгоритм нахождения кратчайшего пути
называется алrоритмом нахождеНИJI кратчайшеrо пути с оrраничеНИJ1МИ ( constrains ), CSPF.
Алгоритм CSPF не должен работать на каждом маршрутизаторе сети. Достаточно его
применить на одном из узлов сети. Обычно этим узлом является пограничный узел LER,
который находит ТЕ-путь с помощью алгоритма CSPF, а затем устанавливает найденный
путь в каждом промежуточном узле сети. Возможен вариант, когда для нахождения ТЕ
пути исnользуется внешний по отношению к сети узел, называемый узлом РСЕ (Path
Computation Element). Этот внешний узел должен получать маршрутные объявления
протокола OSPF ТЕ (или протокола IS-IS ТЕ).
Теперь рассмотрим оба варианта технологии MPLS ТЕ, которые используют описанную
процедуру нахождения ТЕ-пути и устанавливают его в сети MPLS. Эти варианты отлича
ются именно способом установки ТЕ-пути.
