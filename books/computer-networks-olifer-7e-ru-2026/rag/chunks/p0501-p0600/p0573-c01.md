572                                  Часть V. Глобальные проводные коммуникационные сети

Версия НТГР /1.0. Установление одного ТСР-соединения для передачи одного запроса и от

вета на него.
В версии НТТР 1.0 поддерживается только режим кратковременных соединений, когда
после передачи одного запроса и получения ответа, то есть передачи только одного объ
екта веб-страницы, ТСР-соединение закрывается. Такой режим полностью соответствует
концепции сервера без сохранения состояния, а это, как уже отмечалось, приводит к за
медлению работы браузера и увеличению трафика из-за частого выполнения процедуры
трехэтапного установления ТСР-соединения.
Версия НТГР /1.1. Установление одного ТСР-соединения для передачи последовательности

пар •запрос-ответ•.

В каждый момент времени в рамках одного ТСР-соединения НТГР/1.1 обрабатывает
только один запрос. Для обработки следующего запроса может устанавливаться новое
ТСР-соединение, но может использоваться и уже существующее. В этом случае оно назы
вается долговременным (keep-alive) и по нему последовательно передаются несколько пар
•запрос-ответ•. Долговременное соединение, в свою очередь, может быть использовано
двумя способами:
•  Последовательная передача запросов с простоями - это способ, посредством которого
   новый запрос посылается только после получения ответа от сервера.
•  Конвейерная передача - это более эффективный способ, в котором следующий запрос
   посылается до прибытия ответа на один или несколько предыдущих запросов (напо
   минает метод скользящего окна). Обычно по умолчанию степень параллелизма уста
   навливается на уровне 5-10 запросов, но у пользователя имеется возможность изменять
   этот параметр при конфигурировании клиента. Большинство браузеров не используют
   конвейеризацию, поскольку она вызывает проблемы на практике.
Этот способ передачи имеет серьезный дефект -  блоIСИровку начала очереди (head-of-
line, HoL). Поскольку ответы должны отправляться в том же порядке, в котором были
отправлены запросы, медленный ответ на очередной запрос может задержать все по
следующие ответы по тому же соединению. Например, объемный объект, состоящий из
многих байтов, такой, например, как видеоклип, может выкачиваться долго и тем самым
вызвать •затор• - блокировать следующие за ним запросы на другие более мелкие объ
екты (рисунки, тексты, заголовки). Из-за этого пользователь браузера может испытывать

регулярные раздражающие паузы.

Для того чтобы повысить скорость выполнения запросов к веб-серверам и для избежания
блокировок производители браузеров при использовании протокола НТТР / 1.1 стали
поддерживать открытие нескольких (обычно до шести) ТСР-соединений с одним и тем
же сервером для параллельной загрузки ресурсов. Несколько соединений используются
для параллельного извлечения нескольких различных объектов одной и той же страницы
( объекты передаются только целиком). Поскольку как большие, так и маленькие объекты
отображаются на экране браузера параллельно, передача объемного видеоклипа не при

водит к •замораживанию• экрана дисплея.
