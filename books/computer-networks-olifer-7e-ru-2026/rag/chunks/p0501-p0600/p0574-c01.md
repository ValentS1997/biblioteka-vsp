Версия НТТР /2. Установление одноzо ТСР-соединения, поддерживающего мультиплекси

рование потоков.

Прежде всего давайте еще раз определим, что понимается под термином •поток• в данном
контексте. Поток (stream) -  это независимая последовательность байтов, которая пере

носит одну пару •запрос-ответ•, а иноrда и несколько последовательных пар •запрос-от
вет•. Поток может быть однонаправленным или двунаправленным, может создаваться
и закрываться независимо от друrих. Например, в НТТР/1.1 через одно ТСР-соединение
проходит один поток.
В НТТР /2 ТСР-соединение передает сразу несколько потоков, каждый из которых несет
одну пару •запрос-ответ•. На рис. 19.З показана схема преобразования данных, передава
емых между браузером и веб-сервером. Несколько запросов, сгенерированных браузером,
образуют потоки А, В и С, которые обрабатываются протоколом НТТР /2. Эти несколько
потоков мультиплексируются, то есть каждый поток разделяется на кадры (фреймы),
которые чередуются и в •перемешанном• виде передаются на уровень ТСР для передачи
через одно ТСР-соединение. Работа по разделению НТТР-сообщений на части (кадрирова
ние) и формирование из этих частей общеrо мультиплексированного потока выполняется
протоколом НТТР.

Когда данные приходят на другую сторону соединения, они передаются в неизменном
виде протоколу НТТР, который разделяет мультиплексированный (смешанный) поток на
исходные подпотоки. Восстановленные сообщения передаются для обработки обычным
образом либо веб-серверу, либо веб-браузеру. По дороге данные шифруются/дешифриру
ются протоколом TLS.
Версия НТТР/2 ускорила процесс построения веб-браузером веб-страницы за счет сле
дующих усовершенствований:
•  Возможность разбивать НТТР-сообщение на независимые кадры, чередовать их и за
   тем собирать их заново на другом конце - самое важное улучшение НТТР /2. Вместо
   использования отдельных ТСР-соединений для передачи каждого запроса и ответа,
   приводившего к простоям из-за того, что новый запрос не может быть послан без по
   лучения ответа, теперь используется одно ТСР-соединение для мультиплексирования
   нескольких запросов, которые могут быть посланы практически одновременно.
 •  Введена приоритизация запросов к веб-серверу, благодаря которой сервер знает, какой
   запрос более важен веб-браузеру для построения страницы.
 •  Поддерживается режим Server Push, при котором веб-сервер может передать веб
   браузеру не только запрашиваемые ресурсы, но и те, которые, по мнению веб-сервера,
   скоро понадобятся веб-браузеру.
 •  Используется компрессия заголовков сообщений НТТР, значительно сокращающая
