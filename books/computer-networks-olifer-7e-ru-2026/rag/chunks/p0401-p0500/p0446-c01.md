Глава 15. Протоколы транспортного уровня ТСР и UDP                        445

буфер UDP переполняется, то сообщение приложения отбрасывается.
Заголовок UDP состоит из четырех двухбайтных полей:
•  номер UDР-порта отправителя;
•  номер UDР-порта получателя;
•  контрольная сумма;
•  длина дейтаграммы.
Приведем пример заголовка UDP с заполненными полями:
  Source Port = 0х0035
  Destination Port = 0х0411
  Total length = 132 (0х84) bytes
  Checksum = 0х5333

В этой UDР-дейтаграмме в поле данных, длина которого, как следует из заголовка, равна
(132 - 8) байт, помещено сообщение DNS-cepвepa, что можно видеть по номеру порта
источника (Source Port = 0х00ЗS). В шестнадцатеричном формате это значение равно
стандартному номеру порта DNS-cepвepa -  53.
Судя по простоте заголовка, протокол UDP несложен. Действительно, его функции
сводятся к простой передаче данных между прикладным и сетевым уровнями, а также
примитивному контролю искажений в передаваемых данных. При контроле искажений
протокол UDP только диагностирует, но не исправляет ошибку. Если контрольная сумма
показывает, что в поле данных UDР-дейтаграммы произошла ошибка, то протокол UDP
просто отбрасывает поврежденную дейтаграмму.
Работая на хосте-получателе, протокол UDP принимает от протокола IP извлеченные
из пакетов UDР-дейтаграммы. Полученные из IР-заголовка IР-адрес назначения и из
UDР-заголовка номер порта используются для формирования UDР-сокета, однозначно
идентифицирующего приложение, которому направлены данные. Протокол UDP осво
бождает дейтаграмму от UDР-заголовка. Полученное в результате сообщение он передает
приложению на соответствующий UDР-сокет. Таким образом, протокол UDP выполняет
демультиплексирование на основе сокетов.

Протокол ТСР и ТСР-сегменты

  Протокол ТСР предназначен для надежной передачи данных меJ1Щу приложениями. Этот прото

  кол основан на логическом соединении, что позволяет ему, используя в качестве инструмента не
  надежный дейтаграммный сервис протокола IP, обеспечивать гарантированную доставку данных.

При работе на хосте-отправителе протокол ТСР рассматривает информацию, поступаю
щую к нему от прикладных процессов, как неструктурированный поток байтов (рис. 15.4).
Поступающие данные буферизуются средствами ТСР. Для передачи на сетевой уровень из
буфера •вырезается• некоторая непрерывная часть данных, которая называется сегмешом 1
и снабжается заголовком.
