Маршрутизация в сети 802.11s нужна, потому что это не одношаговая сеть, как BSS, и не
сеть с топологией •звезда•, как сеть ESS, а сеть с ячеистой топологией. Маршрутизация
в сети 802.11s осуществляется на канальном уровне с использованием МАС-адресов с по
мощью протокола Hybrid Wireless Mesh Protocol (HWMP) - гибридного беспроводного
mеsh-протокола.

Определение •гибридный• появилось в названии протокола потому, что он состоит из
двух протоколов - проактивноzо и реактивного, которые применяются независимо друг
от друга для решения различных задач. Проактивный протокол маршрутизации, Р-HWMP,
применяется для нахождения кратчайших путей от mesh-yзлa до портала. Реактивный
протокол R-HWMP служит для нахождения кратчайших путей между произвольными
mеsh-узлами сети. Два протокола маршрутизации служат двум разным целям: протокол
P-HWMP предназначен для работы в устойчивой конфигурации инфраструктурной ячеи
стой сети, когда в сети есть портал и основной трафик посылается через портал в интернет
или корпоративную сеть. Протокол R-HWMP находит кратчайший путь между любыми
двумя mеsh-узлами сети по запросу, когда одному mesh-yзлy нужно послать кадр другому
mesh-yзлy, и адреса назначения нет в таблице маршрутизации узла-источника.
С помощью протокола P-HWMP в сети строится древовидная структура маршрутов к кор
ню дерева - порталу. Для этого портал периодически рассылает маршрутные объявления

своим соседям, а те распространяют их дальше по сети, наращивая при этом метрику
расстояния от себя до корня дерева. Каждый узел выбирает в качестве следующего хопа
узел, от которого он получил маршрутное объявление корня с наименьшей метрикой,
и помещает его в таблицу маршрутизации. Протокол P-HWMP использует механизм по
следовательных номеров своих маршрутных объявлений для предотвращения маршрутных
петель. Этот протокол в некоторых отношениях похож на протокол Spanning Tree: они оба
строят дерево маршрутов на основе объявлений узла - корня дерева. Но есть и отличия:
если протокол Spanning Tree работает в сети узлов-коммутаторов, то здесь каждый узел -
это маршрутизатор, и порты узлов не блокируются для создания древовидной топологии,

а остаются активными и могут передавать кадры, предназначенные для узлов сети, не

являющихся порталом.
На рис. 25.13 маршруты, созданные протоколом P-HWMP, показаны пунктирными
линиями. Маршруты, созданные протоколом P-HWMP, соединяют все mеsh-узлы сети
и являются оптимальными для трафика между порталом и mеsh-узлами, но они не всегда
оптимальны для обмена данными между самими mеsh-узлами. Например, mesh-yзeл STA6
должен обмениваться данными с mеsh-узлом STA7 через обходной маршрут P-HWMP
через mesh-yзeл Portal1. Эту проблему решает реактивный протокол маршрутизации
R-HWMP. В этом протоколе все mеsh-узлы рассматриваются как равные. В исходном со
стоянии их таблицы маршрутизации пусты, а в том случае, когда некоторому узлу нужно
послать кадр другому узлу, он посылает широковещательный запрос своим соседям - не

знают ли они пути к узлу назначения.
