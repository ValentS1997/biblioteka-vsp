    Рис. 23. 19. Распределение подканалов OFDM между подпотоками одного пользователя

При применении техники О FD М мультиплексирование данных различных пользователей
(в тех сетях, которые работают в многопользовательском режиме) может осуществляться
на основе техники ТОМ за счет выделения каждому пользователю определенного тайм

слота.
Разработчики многопользовательского режима OFDMA (OFDM Access) пошли по дру
гому пути: они решили разделять между различными пользователями не тайм-слоты,
а подканалы OFDM.
Идея мультиплексирования на основе частотных подканалов иллюстрируется рис. 23.20.
В соответствии с ней на вход системы OFDMA параллельно поступают несколько потоков
данных от разных пользователей, в данном случае - от трех .
В нашем примере система О FD МА состоит из восьми частотных подканалов С1 -С8 . В на
чальный момент времени подканалы С1, С2 и С3 выделены для передачи данных первого
пользователя U1, подканалы С4, С5 и С6 - для передачи данных пользователя U2, а под
каналы С7 и С8 - для передачи данных пользователя UЗ.

Для передачи потока данных отдельного пользователя по нескольким выделенным ему
подканалам применяется техника OFDM. Это означает, что поток распараллеливается на
несколько подпотоков и каждый из них передается по отдельному подканалу. Например,
в нашем примере поток данных пользователя U1 распараллелен на три подпотока, которые
передаются в подканалах С1, С2 и СЗ.
Таким образом, в OFDMA сочетаются две техники - техника частотного мультиплекси
рования FDM между потоками различных пользователей и техника OFDM при передаче

потока отдельного пользователя параллельными потоками по нескольким частотным

подканалам.

Распределение подканалов между пользователями происходит динамически . Подканалы

выделяются потоку пользователя на какое-то определенное время, например, для передачи
определенного количества символов. Назовем это время периодом планирования. После
завершения передачи такой порции данных распределение подканалов происходит заново,
в зависимости от потребностей в передаче данных каждого пользователя ( способы, каким
образом эта потребность оценивается, мы сейчас не рассматриваем, потому что они могут
быть разными).                           Книги для программистов: https://t.me/free_books_for_it
