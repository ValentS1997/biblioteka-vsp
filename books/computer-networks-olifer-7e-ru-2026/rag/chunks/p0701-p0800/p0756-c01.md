Наличие сервера третьего типа, так называемого запрашивающего сервера 1-CSCF
(Interrogating-CSCF), объясняется тем, что в крупном домене IMS обычно применяется
несколько серверов S-CSCF для баланса их загрузки, так как поток сообщений INVITE
на установление соединений между телефонами может быть очень интенсивным и один
сервисный сервер может с ним не справиться. Запрашивающий сервер участвует в про
цессе регистрации пользователя и совместно с базой данных HSS принимает решение,
какой сервисный сервер S-CSCF нужно выделить этому пользователю для регистрации.
Упрощенно процедура регистрации пользователя в системе IMS может быть представлена
в виде следующей последовательности шагов:
•  SIР-агент пользователя подключается к назначенному ему прокси-серверу P-CSCF.
•  SIР-агент отправляет прокси-серверу сообщение REGISTER user@domain.com.
•  Прокси-сервер P-CSCF обращается с этим сообщением к запрашивающему серверу
   1-CSCF.
•  Сервер 1-CSCF обращается к базе данных HSS и получает от нее список серверов
  S-CSCF данного домена. База данных HSS вместе с именами серверов S-CSCF пере
   дает список предоставляемых этими серверами дополнительных функций по обработке
   соединений (перенаправление звонка, автоответчик и т. п.) и поддерживаемые типы
   аутентификации. Сервер 1-CSCF на основе этих характеристик, а также информации
   о загруженности серверов S-CSCF назначает пользователю user@domain.com один из

   них для регистрации.
•  Назначенный сервер S-CSCF совместно с базой данных проводит аутентификацию
   пользователя user@domain.com.
•  В случае успешной аутентификации сервер S-CSCF отправляет прокси-серверу
   P-CSCF, который обращался к запрашивающему серверу, сообщение 200 ОК как сви
   детельство успешной регистрации. При этом сервер S-CSCF запоминает тот факт, что
   пользователь user@domain.com зарегистрирован, а также запоминает имя прокси-серве
    ра, которому надо передавать сообщения, адресованные пользователю user@domain.com.
•  Прокси-сервер P-CSCF передает сообщение 200 ОК SIР-агенту пользователя user@
   domain.com, и на этом процесс регистрации заканчивается.
В дальнейшем мы будем называть сервисный сервер сервером регистрации домена, учи

тывая его основную роль в этом процессе.
В том случае, когда прокси-серверу необходимо обслужить запрос INVITE user@domain.
com, он обращается к запрашивающему серверу 1-CSCF с просьбой указать, к какому кон
кретно серверу регистрации ему нужно обратиться, чтобы получить маршрут, по которому
можно передать сообщения INVITE этому пользователю. Напомним, что маршрут в данном
случае означает имя прокси-сервера, обслуживающего пользователя user@domain.com. По
сле получения ответа от запрашивающего сервера взаимодействие между прокси-сервером

и сервером регистрации идет уже непосредственно.
