738                                                Часть VI. Беспроводная передача данных

Шлюз PGW сообщает серверу ММЕ значение назначенного телефону IР-адреса, и сервер
ММЕ передает его через сигнальный протокол телефону Т1 (транзитом через базовую
станцию). Теперь у телефона есть /Р-адрес, и он может использовать его для обмена дан
ными с любым узлом интернета - но только после завершения создания туннелей.
Шлюз PGW передает шлюзу SGW1 значение идентификатора TEID-S для направления
S-+ Р, шлюз SGW1 будет его использовать при отправке пакетов телефона Т1 шлюзу
PGW, то есть в обратном направлении туннеля P-S. На этом создание туннеля P-S за
вершено, и оба шлюза создали для него таблицы отображения трафика (на рисунке
показаны таблицы только для направления «шлюз PGW -+ устройство пользовате
ля тt. ).
Похожим образом создается туннель S-B. Этот процесс также координирует сервер ММЕ.
В результате согласованной работы трех транспортных узлов сети -  пакетного шлюза
PGW, сервисного шлюза SGW1 и базовой станции 1 - при координации всех операций
севером управления мобильностью ММЕ создан составной туннель, обеспечивающий
обмен трафиком устройства Т1 и шлюза PGW через магистральную сеть без использо
вания IР-адреса устройства. Этот адрес учитывается только при приходе IР-пакетов для
устройства Т1 из интернета на входной интерфейс пакетного шлюза PGW

Продвижение пакета через сеть

Посмотрим по шагам, как работает созданный составной туннель, когда по нему передается
пакет, поступивший из интернета. Назовем его пакетом Р.
1. Шлюз PGW сравнивает IР-адрес пришедшего пакета с записями своей таблицы про
   движения. Он находит запись для адреса IP-Т1, которая показывает, что пакет нужно
   направить в туннель {IP-S, 256}. Шлюз PGW инкапсулирует пришедший пакет в со
   общение IP /UDP/GTP (в соответствии с правилами, приведенными выше) и помещает
    в соответствующие поля заголовков адрес IP-S1 и идентификатор TEID-P, равный 256,
    а пакет Р - в поле данных протокола GРТ.
2. Новый пакет, назовем его РР, направляется в магистральную сеть, маршрутизаторы
   которой доставляют его шлюзу SGW1, так как его адрес IP-S1 указан в качестве IР
   адреса назначения нового пакета. Внутрь пакета промежуточные маршрутизаторы не
   заглядывают - для них это обычная процедура маршрутизации.
3. Шлюз SGW1 получает пакет РР в качестве хоста, а не маршрутизатора, потому что
   пакет адресован ему. По номеру UDР-порта 2151 шлюз вызывает протокол прикладного
   уровня, закрепленный за этим портом, которым является протокол GTP. Этот про

   токол распознает, по какому туннелю пришел к нему пакет, читая адрес отправителя
   из заголовка внешнего пакета (это IP-P) и идентификатор TEID-P=256 из поля TEID
   протокола GTP. Далее протокол GTP находит запись в своей таблице продвижения,
   содержащую пару {IP-P, TEID- Р=256}, и узнает из этой записи, что пакет Р нужно
   передать в туннель S-B идентифицируемой парой {IP-B 1, TEID-S=788}. Для этого про
   токол формирует новый внешний пакет PS и инкапсулирует в него пакет Р, указывая
    в качестве внешнего IР-адреса назначения IР-адрес базовой станции IP-В 1 и в качестве
   идентификатора туннеля идентификатор TEID-S, равный 788.
4. Новый пакет PS направляется шлюзом SGW1 в сеть. Промежуточные маршрутизаторы
