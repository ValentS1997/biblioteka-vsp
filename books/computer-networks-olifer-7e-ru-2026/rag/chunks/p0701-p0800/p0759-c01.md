758                                                Часть VI. Беспроводная передача данных

предпочитают обходиться без использования техники ENUM из-за ее плохой масштаби
руемости (нужно хранить таблицы отображения для всех имеющихся номеров, которых
может насчитываться сотни тысяч), а также по соображениями безопасности пользова
телей (система DNS не контролируется оператором связи, и он не может предотвратить
утечку из нее данных). В крупных корпоративных сетях отображение с помощью ENUM
используется, так как оба ее недостатка здесь не проявляются - масштаб не такой и безо
пасность можно обеспечить своими силами.
Вместо обращения к системе ENUM операторы применяют традиционную практику связи
первых цифр телефонного номера с определенным оператором связи, например, если номер
начинается с цифр +7 903, то всем операторам мобильной связи известно, что этот номер
принадлежит компании Билайн. Соответствие старших цифр номеров телефонов опера
торам связи и, следовательно, их именам доменов в системе DNS хранится в домашних
базах HSS операторов и доступно серверам регистрации системы IMS.
Вторая задача всегда решается с помощью обращения к DNS. Поиск сервера нужного типа
в определенном домене включает три последовательных запроса к DNS. Рассмотрим эту
процедуру на примере поиска запрашивающего типа в домене operator2.net. В исходном
состоянии известны только тип сервера - запрашивающий - и имя домена.
Первым посылается запрос типа NAPTR (Name Authority Pointer) с аргументом operator2.
net. По этому запросу система DNS возвращает список сервисов, которые поддержива
ются серверами домена operator2.net, например sip, h.323, email. Запись NAPTR в свое
время создал администратор домена operator2.net. Но одного такого запроса недостаточно,
теперь нужно найти имя сервера, который в домене operator2.net отвечает за сервис sip.
Поэтому сервер регистрации делает новый запрос к DNS другого типа - SRV (Service),
с аргументами sip и operator2.net, и этот запрос возвращает имя i-cscf2.operator2.net. И на
конец, стандартный запрос А (1Pv4) или ЛАЛА (1Pv6) с этим именем возвращает IР-адрес
запрашивающего сервера i-cscf2.operator2.net домена operator2.net. Обратите внимание, что
в запросе SRV не указывался тип сервера, и интерпретация ответа SRV как имя запраши
вающего сервера полностью полагается на тот факт, что оператор при формировании за
писи SRV поместил туда имя запрашивающего сервера. Формат записи типа SRV не дает
возможности определить тип сервера, а только то, что сервер участвует в предоставлении
определенного сервиса, например сервиса sip. Обычно операторы помещают в записи
SRV для сервиса sip имя запрашивающего сервера, так как сервер этого типа нужен для

нахождения сервера регистрации определенного домена.

Установление соединения
На примере двух доменов, изображенных на рис. 24.13, рассмотрим, каким образом
системы IMS этих доменов устанавливают соединение между двумя телефонами, ког
да пользователь +733333333@operator1.net инициирует соединение с пользователем
+711111111@operator2.net, набирая на своем телефоне номер +711111111.
Будем считать, что оба телефона прошли регистрацию в своих домашних доменах, то
есть пользователь +711111111@operator2.net с помощью своего прокси-сервера P-CSCF2
зарегистрирован в одном из серверов регистрации домена operator2.net, а пользователь
+733333333@operator1.net с помощью своего прокси-сервера P-CSCF1 зарегистрирован
в единственном сервере регистрации домена operator2.net ( оператор этого домена решил
обойтись одним сервером регистрации). Книги для программистов: https://t.me/free_books_for_it
