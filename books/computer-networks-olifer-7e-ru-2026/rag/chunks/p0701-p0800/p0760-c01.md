Глава 24. Сотовые и спутниковые сети                                  759

После того как пользователь набрал номер + 711111111, его телефон посылает запрос
INVIТE + 711111111 через свой прокси-сервер своему домашнему серверу регистрации
s-cscf.operator1 .net. Сервер регистрации дополняет телефонный номер именем домена
вызываемого абонента, найдя это имя по отображению первых нескольких цифр телефон
ного номера на доменное имя в своей домашней базе HSS или воспользовавшись услугой
ENUM DNS, в результате чего запрос теперь стал выглядеть как INVITE 711111111@
operator2.net.
Сервер регистрации s-cscf.operator1 .net теперь знает полное имя вызываемого поль
зователя, но оно ничего не говорит о его текущей точке присоединения, то есть какой
прокси-сервер его в данный момент обслуживает. Он может находиться в любом домене,
и об этом знает только сервер регистрации домашнего домена operator2.net вызываемого
пользователя. Так как в домене operator2.net может быть несколько серверов регистра
ции, то нужно сначала найти запрашивающий сервер этого домена, который должен
знать, какой из серверов регистрации домена отслеживает перемещения пользователя
+711111111@operator2.net.
Поиск запрашивающего сервера происходит с помощью системы DNS и включает запросы
NAPTR/SRV / А, описанные выше. Результатом запросов является IР-адрес запрашиваю
щего сервера i-cscf2.operator2.net домена operator2.net, и по нему сервер регистрации s-cscf.
operator1 .net обращается к запрашивающему серверу i-cscf2.operator2.net.
Запрашивающий сервер i-cscf2.operator2.net знает, какой сервер регистрации закреплен
за пользователем +711111111@operator2.net, поэтому он возвращает имя этого серве
ра, например s-cscf21.operator2.net. Получив ответ, сервер регистрации пользователя
733333333+@operator1.net переправляет запрос INVIТE +711111111@operator2.net серверу
регистрации пользователя +711111111@operator2.net, -  а тот знает текущее положение
в сети своего пользователя, то есть его прокси-сервер p-cscf2@operator2.net.
В результате домашний сервер регистрации пользователя+ 711111111@operator2.net пере
сылает этому прокси-серверу приглашение INVITE +711111111@operator2.net, после чего
прокси-сервер пересылает его телефону +711111111. Дальнейшее развитие событий за
висит от вызываемого пользователя. Если он, услышав звонок, решит на него ответить, то
его согласие в виде ответа ОК пойдет назад по цепочке, но уже без обращения к системе
DNS, так как последовательность посещенных узлов при передаче сообщения INVITE
была записана в заголовок этого сообщения, так что обратный путь для сообщения ОК

известен.
Из ответа ОК телефон пользователя +7ЗЗЗЗЗЗЗЗ@ореrаtог1.net узнает IР-адрес, который
ему нужно использовать в прямой передаче голосовых данных в сообщениях протокола
RTP телефону 711111111@operator2.net. В системе SIP этим адресом является IР-адрес
вызываемого телефона, но операторы сетей LТЕ обычно избегают прямого общения
телефонов пользователей между собой. Они соединяют телефоны пользователей через
промежуточный узел системы IMS, который называется медиашлюзом, и это его IР-адрес
возвращает сообщение ОК. Этот промежуточный медиашлюз является единственным уз
лом, принадлежащим слою пользовательских данных системы IMS. Все остальные ее узлы
работают только с протоколом сигнализации SIP, то есть принадлежат слою управления.
Необходимость прохождения пользовательского голосового трафика через медиа-шлюз
вызвана несколькими причинами: требованиями учета проходящего трафика для его
оплаты, требованиями безопасности, а также управлением сессиями - переадресацией
