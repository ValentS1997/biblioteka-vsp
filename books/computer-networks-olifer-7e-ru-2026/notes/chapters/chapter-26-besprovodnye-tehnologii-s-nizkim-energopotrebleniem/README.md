## Главный принцип

**Технологии LP (НЭ) минимизируют затраты батареи не просто понижением мощности или скорости, а согласованием профиля трафика, duty cycle, покрытия, топологии и стека протоколов.** IEEE 802.15.4 служит общим PHY/MAC конструктором локальных/mesh сетей, в то время как LoRaWAN — низкоскоростной дальнобойный доступ конечных узлов через шлюзы и серверы, с энергоклассами приёма и chirp-модуляцией.

## Выводы, подтверждённые источником

1. Применимые сценарии: малые и редкие пакеты телеметрии, преимущественно по событию. Радио TX расходует больше энергии, чем многие операции MCU; после передачи узел уходит в sleep. Обещания «5–15 лет» являются исходными иллюстрациями требований, не прогнозом батареи конкретного устройства. [p0821](../../../rag/chunks/p0801-p0900/p0821-c01.md)–[p0822](../../../rag/chunks/p0801-p0900/p0822-c01.md).
2. ZigBee/Thread в книге представлены как ближние LP сети умного дома/здания, Wi-SUN FAN и LoRaWAN — для протяжённого мониторинга. Величины дальности, битрейта, числа устройств издания — **контекст источника**, не универсальные производственные характеристики. [p0823](../../../rag/chunks/p0801-p0900/p0823-c01.md)–[p0824](../../../rag/chunks/p0801-p0900/p0824-c01.md).
3. IEEE 802.15.4 определяет PHY/MAC и варианты работы сети, но **не** завершённый верхнеуровневый стек. MAC frame до 127 байт, EUI-64 и короткий 16-битный локальный адрес, роли FFD/RFD, PAN coordinator/координатор/end device; древовидная и mesh топология. В тексте о числе EUI-64 адресов есть противоречие — source-findings.md. [p0824](../../../rag/chunks/p0801-p0900/p0824-c01.md)–[p0826](../../../rag/chunks/p0801-p0900/p0826-c01.md).
4. Для 802.15.4 описаны распределённый CSMA/CA и централизованный beacon-based режим: суперкадр 16 тайм-слотов с конкурирующим и гарантированным доступом. Детали конкретного PHY/регуляторного домена не подтверждены источником как настройки реального оборудования. [p0827](../../../rag/chunks/p0801-p0900/p0827-c01.md).
5. ZigBee строит собственные NWK/APS/app layers: в tree сетях распределённые диапазоны адресов помогают выбирать next hop вверх/вниз без отдельной таблицы, в mesh для маршрутов применяются таблицы/модель, сравниваемая автором с AODV. APS обеспечивает multiplexing/доставку и абстракцию «переключатель → лампа». [p0828](../../../rag/chunks/p0801-p0900/p0828-c01.md)–[p0829](../../../rag/chunks/p0801-p0900/p0829-c01.md).
6. Thread и Wi-SUN FAN **в изложении главы** используют IPv6 + 6LoWPAN для заголовков и fragmentation/reassembly внутри короткого MAC frame, а RPL — для маршрутов маломощных сетей. Thread дополнен UDP/CoAP/Matter в авторской схеме. Не экстраполировать это описание на все версии стандартов. [p0830](../../../rag/chunks/p0801-p0900/p0830-c01.md).
7. Пример ZigBee smart home включает питаемые от электросети координаторы и батарейные end devices; автоматизация управляется заранее настроенными сценариями. Это пример автора, не готовая конфигурация. [p0831](../../../rag/chunks/p0801-p0900/p0831-c01.md)–[p0832](../../../rag/chunks/p0801-p0900/p0832-c01.md).
8. В LoRaWAN в модели главы конечное устройство **не закреплено за конкретным gateway**. Один uplink могут принять разные шлюзы, отправив копии по UDP/IP network server; тот дедуплицирует их и выбирает путь ответа по радиопараметрам. Gateway передаёт, но не управляет радиосредой по модели AP. Среда использует ALOHA, поэтому эффективность и коллизии — компромисс энергопотребления. [p0832](../../../rag/chunks/p0801-p0900/p0832-c01.md)–[p0834](../../../rag/chunks/p0801-p0900/p0834-c01.md).
9. Join server управляет присоединением и аутентификацией, network server — обменом, дедупликацией и адаптацией скорости, application server — полезной нагрузкой. Источник описывает MIC и разделение сетевого и прикладного ключа. Схему нельзя считать доказательством настроенной безопасности реальной инсталляции. [p0834](../../../rag/chunks/p0801-p0900/p0834-c01.md)–[p0835](../../../rag/chunks/p0801-p0900/p0835-c01.md).
10. LoRaWAN Class A после uplink открывает два окна приёма (RX1/RX2), Class B имеет периодические receive windows, Class C слушает значительно дольше/практически постоянно и расходует больше энергии. Показатели задержек/интервалов и батарей зависят от версии/конфигурации. [p0835](../../../rag/chunks/p0801-p0900/p0835-c01.md)–[p0836](../../../rag/chunks/p0801-p0900/p0836-c01.md).
11. CSS LoRa: линейный up-chirp заполняет полосу частот; код символа зависит от начального циклического сдвига частоты. Автор описывает `M=2^SF` и `T_sym=M/B`, а приём через перемножение с down-chirp и дискретное преобразование Фурье. У численного примера SF=9 и записей для сдвига есть **несколько ошибок**, см. source-findings.md. [p0837](../../../rag/chunks/p0801-p0900/p0837-c01.md)–[p0842](../../../rag/chunks/p0801-p0900/p0842-c01.md).
12. Источник заявляет большой link budget и устойчивое распознавание LoRa на отрицательных SNR, а сигналы с разным SF описывает как независимые. Эти заявления **не** гарантируют бесколлизионность, линк-бюджет, дальность или пропускную способность реальной сети. [p0842](../../../rag/chunks/p0801-p0900/p0842-c01.md)–[p0843](../../../rag/chunks/p0801-p0900/p0843-c01.md).
