# Source findings — глава 30

Источник: `computer-networks-olifer-7e-ru-2026`, PDF 955–990, RAG p0955:c01–p0990:c01 и p0978:c02. **rag_only**: ошибки и ограничения фиксируются, исходные чанки не исправляются; PDF напрямую и внешние vendor manuals не читались.

## 1. [Source CLI syntax/meaning] Применение ACL к Cisco interface

- [p0957:c01](../../../rag/chunks/p0901-p1000/p0957-c01.md) объясняет формат `access-list ... permit|deny ...`; [p0958:c01](../../../rag/chunks/p0901-p1000/p0958-c01.md) утверждает, что применение на входящем интерфейсе выражается командой `access-list 1 in`.
- Эта строка **не отличена** от создания ACL и не содержит привязки к конкретному interface. Разрешённость такой формы для какого-либо Cisco IOS/версии **[Needs confirmation]**. В commands.md она цитируется как проблемный source fragment, не инструкция.
- [p0958:c01](../../../rag/chunks/p0901-p1000/p0958-c01.md): в расширенном примере `апу` смешано с латинским `any`, а `estaЫished` с кириллическими символами; [p0959:c01](../../../rag/chunks/p0901-p1000/p0959-c01.md) содержит `ТСР` кириллицей и адрес-портную строку со спорными позиционными полями.
- **Policy:** реальный синтаксис, интерфейсный контекст, implicit-deny/порядок и примеры адресов требуют versioned vendor verification.

## 2. [Source overclaim] `established` как проверка TCP session state

- [p0958:c01](../../../rag/chunks/p0901-p1000/p0958-c01.md) говорит, что слово `established` позволяет понять, что TCP connection уже установлено, потому что маршрутизатор ищет **ACK flag**.
- [p0959:c01](../../../rag/chunks/p0901-p1000/p0959-c01.md) и [p0963:c01](../../../rag/chunks/p0901-p1000/p0963-c01.md) противопоставляют ACL-маршрутизаторы stateful firewalls, которые поддерживают таблицу состояний.
- Факт ACK **не тождествен** проверке таблицы реально установленного соединения; это внутреннее несовпадение в объяснении автора. Не выдавать ACL `established` за stateful validation.

## 3. [Source contradiction] Linux host firewall «без состояния» и stateful fields в примере

- [p0966:c01](../../../rag/chunks/p0901-p1000/p0966-c01.md): сказано, что host firewall **как правило stateless**, затем демонстрируется `iptables -L` с явно напечатанными условиями `state RELATED,ESTABLISHED` и `state NEW`.
- Тот же текст отождествляет `state NEW` с наличием SYN, не определяя условия для UDP/других протоколов из таблицы.
- Из этого не следует, что Linux host firewalls в общем не могут быть stateful. В учебных артефактах различие фиксируется без реконструкции современных iptables/nftables versions и без автоматического исполнения.

## 4. [Source example complexity] Cisco ACL номера, logging и адреса

- [p0957:c01](../../../rag/chunks/p0901-p1000/p0957-c01.md) задаёт диапазоны standard 1–99, extended 100–199; это форма исторического numbered ACL и **не исчерпывающая классификация** современных ACL.
- [p0958:c01](../../../rag/chunks/p0901-p1000/p0958-c01.md) применяет `permit tcp any eq 80 any gt 1023 established` в логике старой модели client source/destination port; одновременно утверждает, что клиенты «всегда» используют порт более 1023. Такое правило не универсально для всех TCP application flows.
- [p0959:c01](../../../rag/chunks/p0901-p1000/p0959-c01.md) пример `log` не определяет logging rate/operational overhead. Source-specific ACL entries могут прервать удалённое управление при буквальном копировании.
- В README/commands они не названы проверенными командными рецептами.

## 5. [Source simplification] Классификация firewall по уровню и state

- [p0962:c01](../../../rag/chunks/p0901-p1000/p0962-c01.md)–[p0964:c01](../../../rag/chunks/p0901-p1000/p0964-c01.md) описывает типичные соответствия network-level = stateless, session/app = stateful, но сам автор упоминает исключения (например, Juniper SRX в [p0963:c01](../../../rag/chunks/p0901-p1000/p0963-c01.md)).
- [p0964:c01](../../../rag/chunks/p0901-p1000/p0964-c01.md) говорит о сетевых firewalls с «минимальным» влиянием на производительность, хотя [p0955:c01](../../../rag/chunks/p0901-p1000/p0955-c01.md) и [p0963:c01](../../../rag/chunks/p0901-p1000/p0963-c01.md) предупреждают о нагрузке/переполнении.
- Использовать классификацию **как учебную типологию**, не как vendor feature matrix.

## 6. [Source overclaim] Proxy/NAT как сокрытие и контроль

- [p0969:c01](../../../rag/chunks/p0901-p1000/p0969-c01.md) приписывает proxy скрытие внутреннего адреса и делает далеко идущее предположение, что целый класс атак становится «нереализуемым».
- [p0971:c01](../../../rag/chunks/p0901-p1000/p0971-c01.md) говорит о NAT как средстве сокрытия структуры сети; [p0972:c01](../../../rag/chunks/p0901-p1000/p0972-c01.md) Basic NAT называет в первую очередь мерой безопасности.
- Эти эффекты не подтверждают ни segment isolation, ни application authentication, ни полноту threat controls. **NAT ≠ firewall policy**, proxy ≠ универсальная проверка всех протоколов, обход proxy должен быть закрыт отдельно ([p0967:c01](../../../rag/chunks/p0901-p1000/p0967-c01.md)).

## 7. [Source internal ambiguity] Таблица Basic NAT и диапазоны сетей A/B

- [p0973:c01](../../../rag/chunks/p0901-p1000/p0973-c01.md) говорит, что обе внутренние сети A/B используют одинаковый `10.0.1.0/24`, но в extracted **рис. 30.6** адреса в сети A представлены в основном как `10.0.2.x` и `10.0.2.0/24`, тогда как в таблице для сети A есть `10.0.1.4`.
- [p0974:c01](../../../rag/chunks/p0901-p1000/p0974-c01.md) далее исходящий host `10.0.1.4` относится к сети A. Нельзя уверенно восстановить согласованную topology рисунка по распознанному тексту; возможно ошибка подписи/извлечения или сама исходная несогласованность.
- Численные адресные пары не используются как работающая схема настройки NAT.

## 8. [Source oversimplification] Basic NAT/NAPT inbound policy

- [p0971:c01](../../../rag/chunks/p0901-p1000/p0971-c01.md) и [p0976:c01](../../../rag/chunks/p0901-p1000/p0976-c01.md) формулируют традиционный NAT как предназначенный для **исходящих** сеансов, с оговоркой о статической трансляции и publish по port.
- Наличие NAPT table само по себе не доказывает application-level security, защиту от всех unsolicited packets, порядок NAT и firewall stages, соответствие современным implementation modes.
- [p0975:c01](../../../rag/chunks/p0901-p1000/p0975-c01.md) на рисунке присутствуют пересекающиеся подсети и искажённые линии; таблица port mappings нужна для понимания **идеи** разрешения одинаковых внутренних source ports, не для production.

## 9. [Source versioning / indicators] NetFlow v5 и устаревающие IOC

- [p0979:c01](../../../rag/chunks/p0901-p1000/p0979-c01.md): параметры flow явно указаны в примечании **для NetFlow версии 5**, названной наиболее распространённой во время написания книги. Нельзя переносить этот набор в каждую версию/IPFIX.
- [p0981:c01](../../../rag/chunks/p0901-p1000/p0981-c01.md): `SQL Slammer` указан с `TCP 1434` в качестве признака; принадлежность transport port к конкретному историческому червю **[Needs confirmation]**. В RAG нет достаточной проверки, и фрагмент не превращён в production detection rule.
- Top N Sessions/Data, SYN/ICMP spikes и сигнатуры — **условные индикаторы для investigation**, не доказательство компрометации.

## 10. [Source security/privacy] Сбор packet payload и аудита

- [p0977:c01](../../../rag/chunks/p0901-p1000/p0977-c01.md)–[p0979:c01](../../../rag/chunks/p0901-p1000/p0979-c01.md): port mirroring, promiscuous mode и PCAP могут создавать копии пользовательского трафика, включая чувствительные payload; глава не задаёт разрешённые границы наблюдения, retention и шифрование хранилищ.
- [p0984:c01](../../../rag/chunks/p0901-p1000/p0984-c01.md)–[p0986:c01](../../../rag/chunks/p0901-p1000/p0986-c01.md): audit требует событий, actor identity, защиты журналов и синхронизации, но недостаточно дано для стандартизованного доказательства невмешательства/целостности каждого события.
- Требуются authorization, minimization и отдельно подтверждённые privacy controls.

## 11. [Source architectural generalization] IDS/IPS и DMZ

- [p0982:c01](../../../rag/chunks/p0901-p1000/p0982-c01.md) говорит, что «IDS только alerts, not block»; [p0983:c01](../../../rag/chunks/p0901-p1000/p0983-c01.md)–[p0984:c01](../../../rag/chunks/p0901-p1000/p0984-c01.md) отдельно описывает IDS, дополненную **IPS functions**, которая автоматически блокирует через другие устройства. В notes они не смешиваются.
- [p0987:c01](../../../rag/chunks/p0901-p1000/p0987-c01.md) говорит, что после взлома внешнего периметра злоумышленник сможет прослушать «только публичный несекретный traffic DMZ». Это верно лишь при дополнительных условиях сегментации/маршрутов/шифрования, которых фрагмент не доказывает.
- [p0988:c01](../../../rag/chunks/p0901-p1000/p0988-c01.md) применяет ACL `established` для охраны internal return traffic; вопрос из finding 2 сохраняется.
- [p0989:c01](../../../rag/chunks/p0901-p1000/p0989-c01.md) заявляет HA failover «без разрыва» существующих flows. Реальная совместимость и state synchronization требуют проверки устройства/версии.
