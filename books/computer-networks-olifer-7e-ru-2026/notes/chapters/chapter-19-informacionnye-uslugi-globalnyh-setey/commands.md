# Команды, методы и протокольные операции — глава 19

Источник: RAG PDF 565–607, p0565:c01–p0607:c01. **В книге нет универсальных команд Linux/Windows CLI для этих сервисов.** Ниже — только методы и управляющие PDU, прямо названные в источнике, а не инструкции к запуску.

## HTTP/1.x (p0579:c01–p0581:c01)

| Метод | Значение по главе | Класс | Границы |
|---|---|---|---|
| GET | запрос объекта | read-only по модели главы; network workload | запрос может нагружать веб-службу |
| HEAD | запрос метаданных | read-only; network workload | только заголовки в описании |
| POST | передача данных серверу | potentially state-changing / workload-generating | бизнес-эффект определяется приложением |
| PUT | размещение объекта | state-changing | риск замены/изменения данных |
| DELETE | удаление объекта | state-changing, potentially destructive | риск потери данных |

Пример учебного запроса: GET /books/books.html HTTP/1.1, Host: www.olifer.co.uk. Учебный ответ: HTTP/1.1 200 OK. Классы кодов: 1xx информационный, 2xx успешный, 3xx переход, 4xx ошибка клиента, 5xx ошибка сервера; упомянуты 200, 401, 404, 505. Это описание синтаксиса **HTTP/1.x** по исходнику, не универсальный wire format HTTP/2/3.

Для PUT/DELETE: эффект — изменение/удаление объекта. Реальные endpoint, authorization, precheck, verification и rollback: **[Needs confirmation]**. Ничего не отправлять на производственный сервер без утверждённого изменения.

## Почта (p0585:c01–p0591:c01)

| Протокол/объект | Что делает по тексту | Класс |
|---|---|---|
| SMTP, TCP порт 25 | передача письма клиент → сервер и между серверами | workload-generating/state-changing |
| POP3, TCP порт 110 | доступ клиента к почтовому ящику | read-only запрос либо state-changing в сценарии удаления |
| IMAP, TCP порт 143 | доступ к серверным копиям и управление письмами | чтение/потенциально изменение состояния |
| DNS MX | DNS-имена почтовых серверов домена | read-only concept/lookup |

SMTP ack от промежуточного сервера — **принятие ответственности**, а не доказательство конечной доставки. Примеры портов — исходное описание, не руководство по безопасной настройке или совет использовать незашифрованный транспорт.

## SNMP (p0603:c01–p0605:c01)

| PDU/операция | Значение | Класс |
|---|---|---|
| GetRequest | запрос значения переменной MIB | read-only, polling/network workload |
| GetNextRequest | запрос следующей переменной | read-only, polling/network workload |
| GetBulk | запрос нескольких переменных | read-only, polling/network workload |
| Response | ответ агента | response, no direct change |
| Trap | уведомление агента по событию | agent-initiated notification |
| SetRequest | изменение переменной управляемого объекта, например порт/VLAN | **state-changing**; риск отключения/нарушения связи |

**SetRequest** может вызывать реальные изменения конфигурации; источник не предоставляет верифицируемых параметров конкретного устройства, резервной копии, проверки результата и отката. Они остаются **[Needs confirmation]**. SNMP community-string в тексте — слабый механизм распознавания/доступа, не основание передавать реальные community значения в артефактах.

## Администрирование и телеметрия (p0605:c01–p0607:c01)

- Telnet: удалённый терминал; в источнике прямо сказано об открытой передаче пароля. **Не рекомендовать как безопасный способ production-администрирования.**
- SSH: описанная защищённая альтернатива терминального доступа; никаких конкретных shell-опций в главе не предоставлено.
- MIB/SMIv2: модель переменных устройства, текстовые MIB, вендорские расширения.
- Streaming telemetry: push от устройства к коллектору; YANG-модель; gRPC в изложении главы. Готовые команды/config для collector в RAG отсутствуют.

## Проверки, модификации и rollback

Методы чтения не меняют конфигурацию, но создают трафик. SMTP-передача создаёт сообщения; POST/PUT/DELETE/SetRequest и операции почтового ящика могут изменять состояние. Для всех изменений необходимы собственные precheck, scope, authorization, verification и rollback: **[Needs confirmation]**. Shell-команды на основе памяти модели **не добавлялись**.
