Если вы как-то изменяете правила роутинга для интерфейса в Ipv4, то они ничего
не изменяют и не отображаются в роутинге для IPv6.
Еще больше глубину и гибкость управления роутингом предоставляет уже упоми-
навшаяся команда ip — в новой нотации это выглядит так:

$ ip --help route
Usage: ip [ OPTIONS ] OBJECT { COMMAND | help }
       ip [ -force ] -batch filename
where  OBJECT := { address | addrlabel | fou | help | ila | ioam | l2tp |
                   link | macsec | maddress | monitor | mptcp | mroute |
                   mrule | neighbor | neighbour | netconf | netns |
                   nexthop | ntable | ntbl | route | rule | sr | tap |
                   tcpmetrics | token | tunnel | tuntap | vrf | xfrm }
       OPTIONS := { -V[ersion] | -s[tatistics] | -d[etails] |
                    -r[esolve] | -h[uman-readable] | -iec | -j[son] |
                    -p[retty] | -f[amily] { inet | inet6 | mpls |
                    bridge | link } | -4 | -6 | -M | -B | -0 |
                    -l[oops] { maximum-addr-flush-attempts } | -br[ief] |
