Вот как будет выглядеть работа модуля для протокола IPPROTO_RAW:

$ sudo insmod trn_proto.ko
$ lsmod | head  -n2
Module                 Size  Used by
trn_proto               780  0
$ cat /proc/modules | grep proto
trn_proto 780 0 - Live 0xf9a26000
$ ls -R /sys/module/trn_proto
/sys/module/trn_proto:
holders  initstate  notes  refcnt  sections  srcversion
$ sudo rmmod trn_proto
$ dmesg | tail -n60 | grep -v ^audit
proto module loaded
proto module unloaded

Но если вы попытаетесь установить (добавить!) обработчик для уже обрабатывае-
мого (установленного) протокола (например, IPPROTO_TСP), то получите ошибку:

$ sudo insmod trn_proto.ko
insmod: error inserting 'trn_proto.ko': -1 Operation not permitted
$ dmesg | tail -n60 | grep -v ^audit
proto init: can't add protocol
$ lsmod | grep proto
$

Здесь возникает уже названная ранее сложность:
   если вы планируете отрабатывать новый (или не использующийся в системе)
   протокол, то для его тестирования в системе нет инструментов, и прежде нужно
   подумать о том, чтобы создать тестовые приложения прикладного уровня;
   если пытаться моделировать работу нового протокола под видом уже сущест-
  вующего (например, IPPROTO_UDP), то вам прежде понадобится удалить сущест-
  вующий обработчик, чем можно радикально нарушить работоспособность сис-
  темы (например, для IPPROTO_UDP разрушить систему разрешения доменных имен
  DNS).
