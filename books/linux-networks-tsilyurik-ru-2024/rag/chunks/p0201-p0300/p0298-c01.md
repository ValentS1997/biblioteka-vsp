За границами традиций Интернета                                            297

Как легко заметить, у этого компьютера есть только два IPv4-интерфейса частной
сети 192.168.1.0/24, которые во внешней интернет-сети (куда этот хост не имеет
прямого доступа) стараниями моего провайдера (его NAT) видятся под таким вот
IP-адресом:

$ curl ifconfig.co
193.28.177.123

Это исходные условия экспериментов, которые воспроизводят и ситуацию у 99%
читателей этого раздела, и обеспечивают адекватность таких экспериментов.
  Первым вариантом достижимости этого хоста извне будет сеть Yggdrasil. На
  интересующем меня (локальном) хосте:

   $ ip a s dev tun0
   4: tun0: <POINTOPOINT,MULTICAST,NOARP,UP,LOWER_UP> mtu 53049 qdisc fq_codel state UNKNOWN group
    default qlen 500
        link/none
       inet6 21d:8a7c:aafa:f346:8115:14aa:9ca4:cd7f/7 scope global
          valid_lft forever preferred_lft forever
       inet6 fe80::255b:2ca5:b8ca:5c2a/64 scope link stable-privacy
          valid_lft forever preferred_lft forever

   организуем доступ из сервера с «белым» IPv4-адресом, удаленного от тестируе-
   мого хоста на 4000 километров:

   $ hostname
    277938.local
   $ ip a s | grep "inet "
       inet 127.0.0.1/8 scope host lo
       inet 90.156.230.27/24 brd 90.156.230.255 scope global dynamic eth0

  Следующим, вторым вариантом достижимости этого хоста извне будет исполь-
   зование onion-адресации проекта Tor. На тестируемом хосте выполним:

   $ sudo cat /var/lib/tor/onion.service/hostname
    jfdbieogcloucaypr6o4twh337fryoc6phg5yzpuv6phontov6ijm7id.onion

  и подключимся к нему с того же удаленного сервера:
