# Шпаргалка: часть I — Сетевой стек: архитектура

**Область:** только первая часть книги; PDF стр. 11–61. Часть I в первоисточнике не называется главой 1. Ссылки ведут на проверенные RAG-чанки.

## 1. Symptom / problem framing — что именно не работает?

Для сетевой проблемы разграничьте уровни, которые часть I рассматривает раздельно: наличие интерфейса и MAC; назначение IP и префикса; сопоставление адреса соседа; достижимость сети по маршруту; адрес сервиса и его порт. Особенно важно не путать адрес интерфейса и таблицу маршрутизации **хоста**, которую ведёт ядро. [PDF p. 20](../../../rag/chunks/p0001-p0100/p0020-c01.md), [PDF p. 38](../../../rag/chunks/p0001-p0100/p0038-c01.md), [PDF p. 46](../../../rag/chunks/p0001-p0100/p0046-c01.md), [PDF p. 59](../../../rag/chunks/p0001-p0100/p0059-c01.md).

## 2. Baseline / context — понятийный минимум

- **Архитектура:** физический/канальный уровень → IP → транспортный протокол → приложение. Сетевые пакеты вложены друг в друга (инкапсуляция); таблицы/схемы первоисточника частично представлены только подписями. [PDF p. 11](../../../rag/chunks/p0001-p0100/p0011-c01.md), [PDF p. 13](../../../rag/chunks/p0001-p0100/p0013-c01.md), [PDF p. 14](../../../rag/chunks/p0001-p0100/p0014-c01.md)
- **MAC и соседи:** в LAN взаимодействие ведётся на канальном уровне; в IPv4 соответствия IP↔MAC обслуживает ARP, в IPv6 — NDP/ICMPv6. [PDF p. 19](../../../rag/chunks/p0001-p0100/p0019-c01.md), [PDF p. 20](../../../rag/chunks/p0001-p0100/p0020-c01.md)
- **IPv4:** 32-битный адрес; маска/префикс определяют сеть и узел, `192.168.1.5/28` сопоставляется автором с маской `255.255.255.240`. Private диапазоны перечислены в RFC 1918; NAT используется для выхода за пределы локальных private-сетей. Таблица примеров масок в источнике содержит расхождения — не копировать её как эталон. [PDF p. 21](../../../rag/chunks/p0001-p0100/p0021-c01.md), [PDF p. 22](../../../rag/chunks/p0001-p0100/p0022-c01.md), [PDF p. 24](../../../rag/chunks/p0001-p0100/p0024-c01.md), [PDF p. 25](../../../rag/chunks/p0001-p0100/p0025-c01.md)
- **IPv6:** 128 бит; сокращение нулевых хекстетов; разделение глобальных, unique-local и link-local адресов; для link-local `fe80::` важен интерфейс/зона (например, `%eno1`). [PDF p. 26](../../../rag/chunks/p0001-p0100/p0026-c01.md), [PDF p. 28](../../../rag/chunks/p0001-p0100/p0028-c01.md), [PDF p. 29](../../../rag/chunks/p0001-p0100/p0029-c01.md), [PDF p. 30](../../../rag/chunks/p0001-p0100/p0030-c01.md)
- **DNS:** имена хостов разрешаются через DNS и локальные настройки; в коде обсуждаются `gethostbyname`, `gethostbyaddr`, `getaddrinfo`/`freeaddrinfo`, `inet_pton`/`inet_ntop`. [PDF p. 33](../../../rag/chunks/p0001-p0100/p0033-c01.md), [PDF p. 34](../../../rag/chunks/p0001-p0100/p0034-c01.md), [PDF p. 35](../../../rag/chunks/p0001-p0100/p0035-c01.md), [PDF p. 36](../../../rag/chunks/p0001-p0100/p0036-c01.md), [PDF p. 37](../../../rag/chunks/p0001-p0100/p0037-c01.md)
- **Маршруты:** записи IPv4 и IPv6 хранятся/наблюдаются отдельно. Маршрут по умолчанию важен для пакетов за пределами более конкретных записей. [PDF p. 46](../../../rag/chunks/p0001-p0100/p0046-c01.md), [PDF p. 47](../../../rag/chunks/p0001-p0100/p0047-c01.md)
- **Интерфейсы:** бывают аппаратными и логическими; `lo` нужен для локального сетевого обмена без физической среды. IP-алиас добавляет адрес существующему интерфейсу; `altname` не тождественен переименованию основного интерфейса. [PDF p. 38](../../../rag/chunks/p0001-p0100/p0038-c01.md), [PDF p. 50](../../../rag/chunks/p0001-p0100/p0050-c01.md), [PDF p. 54](../../../rag/chunks/p0001-p0100/p0054-c01.md), [PDF p. 58](../../../rag/chunks/p0001-p0100/p0058-c01.md)
- **Порты:** номер порта 16-битен; порты TCP и UDP — разные пространства; категории 0–1023, 1024–49151, 49152–65535. [PDF p. 59](../../../rag/chunks/p0001-p0100/p0059-c01.md)

## 3. Read-only checks — сначала без конфигурирования

```sh
ip link
ip addr show
ip -4 neigh show
ip -6 neigh show
ip route show
ip -6 route show
route -n
cat /etc/services
```

Первые две команды описывают интерфейсы и назначенные адреса; две `neigh` — соседей; две `route` — направления для IPv4 и IPv6; `/etc/services` — рекомендованные номера портов, не подтверждение работы службы. Команды приведены в [PDF p. 20](../../../rag/chunks/p0001-p0100/p0020-c01.md), [PDF p. 41](../../../rag/chunks/p0001-p0100/p0041-c01.md), [PDF p. 46](../../../rag/chunks/p0001-p0100/p0046-c01.md), [PDF p. 47](../../../rag/chunks/p0001-p0100/p0047-c01.md), [PDF p. 59](../../../rag/chunks/p0001-p0100/p0059-c01.md).

Для адресов имён используются `host`, `dig`, `nslookup` — они могут отправлять DNS-запросы и потому отнесены в `commands.md` к workload-generating, а не к чистому read-only. [PDF p. 36](../../../rag/chunks/p0001-p0100/p0036-c01.md).

## 4. Interpretation — читать результаты слоями

1. **Интерфейс:** интерфейс существует? установлен ли адрес? совпадает ли предполагаемое имя с выводом `ip link`? [PDF p. 38](../../../rag/chunks/p0001-p0100/p0038-c01.md), [PDF p. 41](../../../rag/chunks/p0001-p0100/p0041-c01.md)
2. **L2/L3 сосед:** у IPv4 есть запись ARP/neighbor? У IPv6 нужный NDP-запрос идёт через корректный интерфейс? Состояния `REACHABLE`, `STALE`, `FAILED` показаны в исходнике. [PDF p. 19](../../../rag/chunks/p0001-p0100/p0019-c01.md), [PDF p. 20](../../../rag/chunks/p0001-p0100/p0020-c01.md)
3. **Адрес и префикс:** соответствует ли фактическая запись `ip addr` нужной подсети? Особо проверять алиасы — в RAG есть расхождение `/24` ↔ `/8`. [PDF p. 22](../../../rag/chunks/p0001-p0100/p0022-c01.md), [PDF p. 50](../../../rag/chunks/p0001-p0100/p0050-c01.md), [PDF p. 52](../../../rag/chunks/p0001-p0100/p0052-c01.md)
4. **Маршрут:** записан ли нужный маршрут в **нужной адресной семье**? Есть ли запись по умолчанию? [PDF p. 46](../../../rag/chunks/p0001-p0100/p0046-c01.md), [PDF p. 47](../../../rag/chunks/p0001-p0100/p0047-c01.md), [PDF p. 56](../../../rag/chunks/p0001-p0100/p0056-c01.md)
5. **Сервис:** порт конкретного TCP/UDP-приложения проверяется отдельно от самого IP-маршрута. Возможна фильтрация брандмауэром; открытый TCP-сеанс сам по себе не подтверждает корректность прикладного протокола. [PDF p. 59](../../../rag/chunks/p0001-p0100/p0059-c01.md), [PDF p. 60](../../../rag/chunks/p0001-p0100/p0060-c01.md)

## 5. Next action — ограниченная диагностика

По подтверждённой конфигурации переходите от локального теста `lo` к тесту соседнего адреса (`ping`), затем к проверке маршрута/порта; IPv6 link-local следует проверять с указанием исходящего интерфейса. `ping`, `telnet` и `nmap` генерируют трафик и выполняются только на разрешённых адресах. Примеры: [PDF p. 30](../../../rag/chunks/p0001-p0100/p0030-c01.md), [PDF p. 32](../../../rag/chunks/p0001-p0100/p0032-c01.md), [PDF p. 54](../../../rag/chunks/p0001-p0100/p0054-c01.md), [PDF p. 56](../../../rag/chunks/p0001-p0100/p0056-c01.md), [PDF p. 60](../../../rag/chunks/p0001-p0100/p0060-c01.md).

## 6. Modifying action — только контролируемое изменение

В части I продемонстрированы: изменение MAC (`macchanger -m`), добавление IPv6-адреса (`ip address add`), добавление маршрута (`ip -6 route add`), IP-алиас (`ifconfig IFACE:1 ADDRESS up`), остановка/переименование/восстановление интерфейса, управление `altname`. Все изменяют состояние; на действующем удалённом интерфейсе могут потерять сетевой доступ. Выбирайте **только один** мотивированный эксперимент, предварительно фиксируя `ip addr` и обе таблицы маршрутов. [PDF p. 18](../../../rag/chunks/p0001-p0100/p0018-c01.md), [PDF p. 48](../../../rag/chunks/p0001-p0100/p0048-c01.md), [PDF p. 50](../../../rag/chunks/p0001-p0100/p0050-c01.md), [PDF p. 55](../../../rag/chunks/p0001-p0100/p0055-c01.md), [PDF p. 56](../../../rag/chunks/p0001-p0100/p0056-c01.md), [PDF p. 58](../../../rag/chunks/p0001-p0100/p0058-c01.md).

## 7. Verification / acceptance checks

После адресного изменения перепроверьте `ip addr` и соответствующую таблицу маршрутизации; после изменения IPv6-маршрута — `ip -6 route show`; после переименования — имя, IP, маршрут по умолчанию и достижимость соседнего узла, затем внешнего адреса. Для тестов источника требуются контекст, разрешённая сеть и фактические ожидания, а не копирование тестовых IP. [PDF p. 48](../../../rag/chunks/p0001-p0100/p0048-c01.md), [PDF p. 56](../../../rag/chunks/p0001-p0100/p0056-c01.md), [PDF p. 57](../../../rag/chunks/p0001-p0100/p0057-c01.md).

## 8. Rollback — обратимость

- Для переименования источник показывает восстановление **IP и маршрута по умолчанию** после изменения имени, но **проверенная полная обратная процедура переименования не приведена**: **[Needs confirmation]**. [PDF p. 56](../../../rag/chunks/p0001-p0100/p0056-c01.md), [PDF p. 57](../../../rag/chunks/p0001-p0100/p0057-c01.md)
- Для изменения MAC, IP-алиаса и добавления IPv6-маршрута конкретные команды полного отката вместе с процедурой проверки в этой части **[Needs confirmation]**.
- Удалять интерфейс `lo` не следует: источник отдельно предупреждает о влиянии на работоспособность системы. [PDF p. 54](../../../rag/chunks/p0001-p0100/p0054-c01.md), [PDF p. 55](../../../rag/chunks/p0001-p0100/p0055-c01.md)

**Вывод:** сравнивайте не «есть ли сеть», а последовательно *интерфейс → адрес/сосед → маршрут IPv4/IPv6 → сервисный порт*. Источник не даёт универсальной безопасной команды для исправления произвольной сетевой проблемы.
