# Source findings — ЧАСТЬ IV. Драйверы сетевых устройств

Режим `rag_only`. Проблемы зафиксированы с текстовыми локаторами; исходные варианты не переписываются и не чинятся по памяти. Это не подтверждение компиляции или возможности эксплуатации.

## SF-01 — `irq` / `byte` в примере IRQ

**[Source code mismatch]** — [PDF 202](../../../rag/chunks/p0201-p0300/p0202-c01.md) (PDF 202, печатная 201).

Сначала объявляется `char irq;`, но следующий код использует `pci_read_config_byte(pdev, PCI_INTERRUPT_LINE, &byte);`; далее показан `request_irq((int)irq, ...)`. В видимом фрагменте **`byte` не объявлен**, а значение предполагаемого `irq` не заполняется. Исходное решение компиляции или точное имя параметра **[Needs confirmation]**.

## SF-02 — обращение к `skb` после `kfree_skb(skb)`

**[Source code mismatch]** — [PDF 220](../../../rag/chunks/p0201-p0300/p0220-c01.md), [PDF 222](../../../rag/chunks/p0201-p0300/p0222-c01.md), [PDF 227](../../../rag/chunks/p0201-p0300/p0227-c01.md).

Текстовые листинги `test_pack_rcv`, `test_pack_rcv_1/2`, `pack_parent` вызывают `kfree_skb(skb)`, но следом обращаются к `skb->len` и, в двух обработчиках, `atomic_read(&skb->users)`. На [PDF 223](../../../rag/chunks/p0201-p0300/p0223-c01.md) поясняется, что `kfree_skb` **освобождает память при достижении счётчика ссылок 1**. Поэтому последующее чтение полей может оказаться обращением к освобождённой памяти; доказательства безопасности для всех путей в RAG нет. **Оригинал сохранён**, копирование в новые шаблоны запрещено до проверки владения.

## SF-03 — доступ к переданному `skb` после `dev_queue_xmit`

**[Source code mismatch]** — [PDF 215](../../../rag/chunks/p0201-p0300/p0215-c01.md), [PDF 227](../../../rag/chunks/p0201-p0300/p0227-c01.md).

В реализации `start_xmit()` выполняется `dev_queue_xmit(skb);` и **после** этого `LOG/DBG(..., skb->dev->name, ... skb->len)`. Из текста не следует, что указатель `skb` остаётся действительным после передачи буфера дальше (исходник также описывает освобождение TX по окончании обработки: [PDF 206](../../../rag/chunks/p0201-p0300/p0206-c01.md)). Следовательно, это риск жизненного цикла, а не подтверждённо безопасный отладочный приём. Корректные варианты — **[Needs confirmation]**.

## SF-04 — обозначение «сетевого уровня» как L2 и L3

**[Source contradiction]** — [PDF 219](../../../rag/chunks/p0201-p0300/p0219-c01.md) (PDF 219, печатная 218) и [PDF 225](../../../rag/chunks/p0201-p0300/p0225-c01.md) (PDF 225, печатная 224).

Заголовок «Протокол сетевого уровня» на PDF 219 сопровождается описанием **«На этом уровне (L2)»** для IP/ARP и регистрации `packet_type` через `dev_add_pack`. Позднее та же схема фильтрации в абзаце «Еще раз о виртуальном интерфейсе» описывается как **«протокольные механизмы сетевого уровня (L3)»**. Сохранены обе исходные формулировки, без решения, какой слой обозначался автором.

## SF-05 — сценарий длительной нагрузки/проверки утечки

**[Source extraction issue]**, **[Needs confirmation]** — [PDF 224](../../../rag/chunks/p0201-p0300/p0224-c01.md), [PDF 225](../../../rag/chunks/p0201-p0300/p0225-c01.md).

Скрипты автора для испытания утечки памяти устанавливают `LIMIT=1000000`, выполняют `nc` и манипуляции с `z.txt`; строка `rm -а z.txt` содержит знак, визуально похожий на латинское `a`, но в извлечённом RAG его корректная природа не доказана. Тест генерирует нагрузку и изменяет файлы, а **не** является безопасной проверкой по умолчанию. Без доступа к сопроводительному архиву или прямому PDF установить точный синтаксис и безопасную длительность нельзя.

## SF-06 — оговорка о влиянии на работающий интерфейс

**[Needs confirmation]** — [PDF 225](../../../rag/chunks/p0201-p0300/p0225-c01.md), [PDF 230](../../../rag/chunks/p0201-p0300/p0230-c01.md), [PDF 231](../../../rag/chunks/p0201-p0300/p0231-c01.md).

Автор прямо различает `virtl.ko`, при котором деятельность родительского интерфейса прекращается, и полный `virt.ko`, где трафик родителя и дочернего интерфейса должен сосуществовать. Но в RAG **не содержится проверенной для текущей среды** схемы аварийного возврата сети, предотвращения потери удалённой консоли или результативной приёмки современного ядра. Этот пробел не дополняется модельной памятью.

## Область безопасности

Проблемы `skb`, регистрации обработчиков, API NAPI и нагрузочного цикла означают, что текстовый пример **не тождествен** исполнимому production-решению. В частности, модуль, перехватывающий `ETH_P_ALL`, может воздействовать на весь входящий поток, а удаление существующего транспортного обработчика прямо названо разрушительным действием в [PDF 233](../../../rag/chunks/p0201-p0300/p0233-c01.md). **Статус исходного RAG не изменяется.**
