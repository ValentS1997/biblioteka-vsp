# Схемы части II (Mermaid)

Концептуальное представление по RAG-тексту, а не реконструкция изображений 2.1–2.17.

## Жизненный цикл сетевого сервиса

~~~mermaid
flowchart TD
    A["Базовая диагностика: ip link; route -n"]
    B["Сервис: клиент + сервер + протокол"]
    C["Установка пакета"]
    D["Конфигурация + ограничение доступа"]
    E["Проверка конфигурации, если есть: dhcpd -t"]
    F["systemctl start SERVICE"]
    G["systemctl status SERVICE"]
    H{"Служба активна и нет ошибок?"}
    I["Контроль слушателя и тест клиента"]
    J{"Прикладная функция работает?"}
    K["Автозапуск, если нужен"]
    L["Локализация: DNS / firewall / маршрут / proxy"]
    M["Вернуть baseline; точный rollback: Needs confirmation"]
    A --> B --> C --> D --> E --> F --> G --> H
    H -->|да| I --> J
    H -->|нет| D
    J -->|да| K
    J -->|нет| L --> M
~~~

## Постоянный сервер, суперсервер, сокетная активация и прокси

~~~mermaid
flowchart LR
    A["Клиент"] --> B["Сетевой порт / протокол"]
    B --> C["Постоянно работающий демон: sshd / danted"]
    B --> D["inetd запускает дочерний сервер по запросу"]
    B --> E["systemd.socket запускает экземпляр service"]
    A --> F["SOCKS/HTTP proxy"]
    F --> G["Целевой ресурс"]
    A --> H["Локальный SOCKS: ssh -N -D"]
    H --> G
~~~

## Классификация воздействий

Наблюдение: `ip link`, `netstat`, `systemctl status`, `ufw status`. Сетевая проба: `ping`, `nc`, `host`, `curl`, `tcpdump`. Модификация: `apt install`, `systemctl start`, `ufw enable/allow`, редактирование конфигураций, создание socket units. Проверка и откат должны соответствовать изменённому слою.
