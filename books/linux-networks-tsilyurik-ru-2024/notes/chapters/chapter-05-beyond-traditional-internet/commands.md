# Часть V — команды и инструменты по RAG

Режим `rag_only`, PDF 235–302. **RO** = чтение/инвентаризация; **WG** = сетевой запрос, нагрузка или работа с файлами; **SC** = установка/изменение сервиса, конфигурации, интерфейса, маршрутов, DNS либо публикация. Одна команда может относиться сразу к нескольким категориям. `HOST`, `IFACE`, `TEST_URL`, `PEER`, `USER`, `PORT` — **placeholder'ы только для собственного стенда**, а не реальные адреса из старого примера. Не выводить и не копировать `PrivateKey`, ключи, коды доступа, конфигурационные secrets.

## Не исполнять без отдельной проверки

1. В исходнике приводятся **ключи PrivateKey/PublicKey** и peer URI (PDF 246, 249, 260). Эти данные могут раскрывать идентичность сетевого хоста; ни один приватный ключ или endpoint из них здесь не повторён. [PDF 246](../../../rag/chunks/p0201-p0300/p0246-c01.md), [PDF 249](../../../rag/chunks/p0201-p0300/p0249-c01.md), [PDF 260](../../../rag/chunks/p0201-p0300/p0260-c01.md).
2. Учебные URL, IP, имена onion, адреса `.i2p`, `.lib`, `.ygg` и `check-host.net/ip` относятся к времени написания книги, а их доступность и назначение **[Needs confirmation]**.
3. `iperf`, `peer_checker`, компиляторы и `git clone` работают только в контролируемом контуре: нагрузка, установка исполнимых файлов и права могут изменить состояние стенда.
4. Конкретный rollback полной сетевой/именной конфигурации источником **не подтверждён**. Для примеров ошибки извлечения и внутренние расхождения — [source-findings.md](source-findings.md).
